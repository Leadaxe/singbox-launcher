# tools/l10n — гард-рейлы локализации (SPEC 111)

Локализация на естественных ключах: **английский текст в коде и есть ключ
перевода**. `locale.T("Save")` → «Сохранить» из `bin/locale/ru.json`; промах
любого уровня деградирует в сам ключ (корректный английский) с подстановкой
аргументов. Отдельного английского каталога нет — английский живёт в коде.

Схему держат два чекера. CI гоняет оба с `--strict` на каждом push/PR
(`.github/workflows/ci.yml`, job `Test`, шаг «L10n checks»). Запуск из корня:

```
go run ./tools/l10n/l10n_check   [--strict]
go run ./tools/l10n/hardcoded_check [--strict] [--write-baseline]
```

## l10n_check — код ↔ каталог

AST-скан вызовов `locale.T/Tf/TN/TfN/Plural/PluralN` по всем пакетам
(кроме `tools/`, тестов) и сверка с `bin/locale/ru.json`.

| Находка | Что значит | Режим |
|---|---|---|
| `missing` | ключ из кода отсутствует в каталоге | warn, `--strict` → fail |
| `orphan` | запись каталога не используется в коде | warn, `--strict` → fail |
| `orphan-special` | `special["N"]` не вызывается с формой N | warn, `--strict` → fail |
| `usage-conflict` | ключ зовут и `T`-, и `Plural`-семейством | fail всегда |
| `shape` | `T` на plural-записи; `Plural` без полного набора форм резолвера; использованная форма N отсутствует | fail всегда |
| `arity` | наборы printf-плейсхолдеров ключа и перевода расходятся (включая `%[1]s`; `%%` — литерал) | fail всегда |

Что сканер умеет сверх литералов:

- **Константы файла**: `locale.T(longHintText)` резолвится по `const` того же
  файла — длинные тексты выносятся в const рядом с использованием.
- **`// l10n-key`** на строке литерала: строка считается использованным
  ключом. Для ключей, уходящих в `locale.T` через переменные и функции,
  которые сканер не резолвит (`locale.T(pickHint(x))`).
- **Реестр хелперов** `l10n_helpers.json` (`{"CommandRow": [1]}` — функция →
  позиции аргументов-ключей): литеральный аргумент такого хелпера — ключ.
- Прочие нелитеральные ключи только считаются (`dynamic: N` в сводке).

## hardcoded_check — ratchet на хардкод

Строковый литерал **с буквами** в display-позиции (`display_positions.json`:
конструкторы и сеттеры Fyne, диалоговые хелперы), не обёрнутый в `locale.*`,
— находка. Литералы без букв (глифы `?`, `→`) не считаются. Легально:
`widget.NewLabel(locale.T("…"))` — литерал аргумент локализатора.

- **Baseline** `hardcoded_baseline.json` (`{файл: число сайтов}`) — пуст:
  любой новый хардкод роняет CI. Правило: счётчик файла не растёт, новый
  файл не появляется. `--write-baseline` фиксирует текущее состояние.
- **`// l10n-exempt: <причина>`** на строке литерала или строкой выше —
  точечное исключение. Легитимно: wire-теги, образцы URL/URI, единицы,
  эндонимы, имена продуктов. Нелегитимно: «переведём потом».
- Пакеты `internal/debuglog`, `core/debugapi` не сканируются (логи и debug
  API не переводятся, SPEC 111 §8).
- Аргументы функций из `l10n_helpers.json` ratchet не смотрит — по контракту
  это ключи, их валидирует `l10n_check`.
- Осознанный зазор: поток переменных не отслеживается (в Go нет тернарного
  оператора; ветка `if`, кладущая литерал в переменную перед display-вызовом,
  не ловится).

## Как добавить строку

1. В коде: `locale.T("English text")` (плейсхолдеры — `Tf`, формы
   множественного — `Plural`).
2. В `bin/locale/ru.json`: `"English text": { "value": "перевод" }` с тем же
   набором плейсхолдеров.
3. Коллизия (тот же английский, другой перевод): на отличающемся сайте
   `locale.TN(1, "Text")`, в записи `"special": {"1": {"value": "…"}}`.
4. Правка английского текста = смена ключа: старая запись станет `orphan`,
   новая — `missing`; переименуй ключ в каталоге и перечитай перевод.

Оба чекера — только stdlib и синтаксис ≤ go1.20: легаси-джоба Win7 гоняет
`go get ./...` тулчейном go 1.20.14 по всем пакетам модуля, включая `tools/`.
