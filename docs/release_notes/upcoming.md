# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **SRS rules with many links: dead links are named, not hidden.** The real cause of "more than 7 SRS links fail" was a link that returns HTTP 404, not the group deadline: the download stopped at the first broken file and the dialog only said "see the log". Now every file of the rule is downloaded, and if some links do not exist the dialog lists them by file name so they can be removed from the rule.
- **Troubleshooting: Linux `system` TUN stack blocked by firewalld.** When the VPN is up but nothing loads and `gvisor` works, a host firewall drops the local TCP forwarder of the `system` stack. The troubleshooting guide now has the narrow `firewall-cmd` rule (issue #129).
- **Linux: TUN auto redirect.** New setting Wizard → Settings → "TUN auto redirect (Linux)" (sing-box `auto_redirect`): TCP is routed into the core with nftables/iptables rules instead of the `system` stack's local forwarder, so a host firewall like firewalld no longer blocks the VPN. On by default on this computer, off for remote machines; emitted only on Linux with auto-route enabled. Confirmed by the reporter of issue #129 on openSUSE. Contract 1.1.133.
- **DNS: template servers can be deleted.** The template's DNS servers are now a catalog: they are added to your list once, and after that the list is yours — a template server you do not need can be deleted with **Del** and stays deleted after restarts and reopening the Configurator. **Add from template** returns one with the template's defaults, **Add all defaults** returns all of them. A server that something still uses (Final DNS, the default domain resolver, a DNS rule, a rule's DNS option, a DNS group, another server's domain resolver, a preset) cannot be deleted: the tooltip says what uses it; `required` servers stay. Existing setups keep every server they had — the config does not change after the update.
- **Backup: deleted template DNS servers travel between devices.** The backup file now carries the source's template catalog (`dns.template_catalog`) and the full server list. Importing a file removes a template server the source deleted — unless something here still uses it (`backup_dns_entry_kept` names what); Final DNS / default resolver pointing to a server missing here are reset to the template default, and an imported DNS group with no servers here comes in turned off. Older backups without the catalog are merged as before, nothing is removed. Same rules as LxBox (contract 1.1.135–1.1.136).

### Core
- `sing-box-lx 1.14.3-lx.22` (was 1.14.3-lx.21). Fixes: a masque `vhttp: auto` node no longer keeps the previous core instance in memory after every reload (Stop/Start, apply) — on a router the heap grew until the GC ate both CPU cores within days, affected since `v1.14.0-lx.27`; the core no longer waits 10–16 s on start for an unrelated mux handshake. New: `lxd` runs the admin's own scripts at the core's lifecycle boundaries (`pre_start`, `post_start`, `post_reload`, `post_stop` in `<state_dir>/hooks/`, off by default, `hooks.enabled` in `daemon.json`, Unix only); the launcher does not manage them.

## RU
### Основное
- **SRS-правило с множеством ссылок: мёртвые ссылки называются поимённо.** Настоящая причина «больше 7 SRS-ссылок не работает» — ссылка, отвечающая HTTP 404, а не дедлайн группы: загрузка вставала на первом битом файле, а окно писало только «подробности в логе». Теперь качаются все файлы правила, и если каких-то ссылок не существует, окно перечисляет их по имени файла, чтобы их убрали из правила.
- **Troubleshooting: стек `system` на Linux режет firewalld.** Когда VPN поднят, но ничего не грузится, а с `gvisor` работает, хост-файрвол рубит локальный TCP-форвардер стека `system`. В руководстве по диагностике появилось точечное правило `firewall-cmd` (issue #129).
- **Linux: TUN auto redirect.** Новая настройка Wizard → Settings → «TUN auto redirect (Linux)» (sing-box `auto_redirect`): TCP заворачивается в ядро правилами nftables/iptables вместо локального форвардера стека `system`, и хост-файрвол вроде firewalld больше не блокирует VPN. По умолчанию включена на этом компьютере, выключена для удалённых машин; эмитится только на Linux при включённом auto-route. Подтверждено автором issue #129 на openSUSE. Контракт 1.1.133.
- **DNS: шаблонные серверы можно удалять.** DNS-серверы шаблона теперь каталог: в ваш список они попадают один раз, дальше список ваш — ненужный шаблонный сервер удаляется кнопкой **Del** и не возвращается ни перезапуском, ни повторным открытием Конфигуратора. **Добавить из шаблона** возвращает один с настройками шаблона, **Вернуть все шаблонные** — все сразу. Сервер, который что-то использует (Final DNS, резолвер доменов по умолчанию, DNS-правило, DNS-опция правила, DNS-группа, резолвер другого сервера, пресет), удалить нельзя — подсказка называет, кто его держит; обязательные (`required`) серверы остаются. У существующих настроек все серверы на месте — конфиг после обновления тот же.
- **Бэкап: удалённые шаблонные DNS-серверы переносятся между устройствами.** Файл бэкапа несёт каталог шаблона источника (`dns.template_catalog`) и полный список серверов. Импорт снимает шаблонный сервер, удалённый источником, — если здесь его ничего не держит (иначе `backup_dns_entry_kept` называет, что держит); Final DNS и резолвер по умолчанию на сервер, которого здесь нет, сбрасываются на умолчание шаблона, а ввезённая DNS-группа без серверов приезжает выключенной. Старые бэкапы без каталога сливаются как раньше, ничего не снимается. Правила те же, что у LxBox (контракт 1.1.135–1.1.136).

### Ядро
- `sing-box-lx 1.14.3-lx.22` (было 1.14.3-lx.21). Исправлено: узел masque `vhttp: auto` больше не держит в памяти предыдущий экземпляр ядра после каждой пересборки (Stop/Start, apply) — на роутере куча росла, пока GC за несколько дней не съедал оба ядра CPU, затронуты версии с `v1.14.0-lx.27`; старт ядра больше не ждёт 10–16 с чужой mux-handshake. Новое: `lxd` запускает скрипты администратора на границах жизненного цикла ядра (`pre_start`, `post_start`, `post_reload`, `post_stop` в `<state_dir>/hooks/`, по умолчанию выключено, `hooks.enabled` в `daemon.json`, только Unix); лаунчер ими не управляет.
