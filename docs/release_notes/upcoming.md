# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **Hop chains for core 1.14.4-lx.37-rc.2 (core SPEC 165).** The core no longer makes copies of chain nodes: a node at position 2 or later dials through the position below as itself, everywhere, so a chain group measures the path traffic takes. The chain editor loses **Link idle timeout** and the strip filters — the core removed them (filters now apply to any node under a detour by default); saved values are dropped on load and import. A node or a group used after the first position may stand in one place only — two chains sharing such a node or group, a ring such as "A, then a group that contains A", a fixed local port of a node inside a chain, a node named like a chain hop or a rewrite of `detour`: the chain editor does not save such a chain and says what to copy (a group without A, a copy of the group for one of the chains), and the build leaves it out with a warning instead of a config the core would refuse. Two chains may share their first hop. The node **Info** window shows the node's JSON as the core runs it, with a switch to the config form and the list of what the core changed; **Core runtime** gets an **Effective config** tab. A remote machine on an older core keeps working with its old config form; its chain section in Info is not shown until its core is updated.
- **Remote machine: its config is built from the machine's own inputs.** Three inputs of a remote machine's config were taken from the computer running the launcher. Node fields were gated by the launcher's OS and core: `tls.kernel_tx` / `tls.kernel_rx` (kTLS, Linux only) were silently stripped from a Linux router's config built on macOS or Windows, and version-gated fields (REALITY `key_share`, XHTTP) followed the launcher's core version instead of the machine's. URLTest URL / interval / tolerance of auto groups came from this computer's Settings, not the machine's. Template presets were filtered by the launcher's OS. All three now follow the target: its OS, the core version its daemon reported, its own Settings. The local config is built as before.
- **macOS: notifications come from the launcher, with its icon.** macOS no longer let the launcher's old bundle id `com.singbox.launcher` into the notification center, so every notification was shown as coming from Script Editor. The app's bundle id is now `com.leadaxe.singbox-launcher`. To macOS this is a new app: on the first notification it asks for permission once, and it asks again for **Local Network** access — allow it, or machines on the local network are unreachable. Data, settings and the core are not affected.
- **Remote Linux machine: "TUN auto redirect" no longer blocks Save** (issue #161). A Windows or macOS launcher checked the config of a remote Linux machine with its own core, which rejects `auto_redirect` as Linux-only. The check now ignores this host-only key; the machine still gets it.
- **TUN: "LAN interfaces" apply only in gateway mode** (issue #160). The `include_interface` list of the TUN inbound was written into the config even with **Gateway mode** off — a value left in the greyed-out field (for example an IP address instead of an interface name) broke TUN on the machine. The list is now emitted only when gateway mode is on.
- **Rule-sets (.srs) update themselves** (issue #157). A downloaded `.srs` file was never refreshed: block and bypass lists went stale for months while the rule showed ✔️. Rule-sets are now refreshed by the same hourly loop that updates subscriptions — a file older than its interval (a week by default) is downloaded again, checked, and swapped in; the running core picks it up without a restart. A missing file is downloaded when the config is built and before the core starts; if that fails, the rule is left out and the core still starts instead of failing with `FATAL initialize rule_set`. A remote machine gets fresh files on Deploy.
- **Rules with similar names no longer share one rule-set.** A rule's internal id was its name with everything but Latin letters, digits, `-` and `_` dropped, so two rules named in Cyrillic (or `Ads` and `Ads!`) got the same id: both used the rule-set of one of them, and the other list was silently ignored. A name that loses characters now gets a short hash added to its id, and the rule window refuses a name that still conflicts with another rule. References to the old rule-set tags saved in DNS rules are rewritten on load.
- **DNS rule: the rule-set list no longer offers your own SRS rules.** DNS for an SRS rule of yours is set in the rule itself (Rules → edit the rule → **DNS** tab): that setting belongs to the rule and survives a rename, while a `user:<name>` tag picked in a DNS rule was stored as text and broke when the rule was renamed. This reverses the picker change from issue #140. DNS rules that already reference `user:…` tags keep working and keep their tags when edited; the JSON tab still accepts any tag.
- **Rule-set settings: Local / Remote, interval, download route.** Settings has a new **Rule-sets** group, and the window of an SRS rule or of a preset with rule-sets has a **Rule-set updates** block that overrides it for that rule. **Remote** hands the download to the core (`type: remote` with `update_interval` and `download_detour`); note that the core will not start if its first download fails and it has no cached copy. The srs button tooltip shows when the files were last downloaded.
- **Rule sets from a file, and in JSON** (issue #153). The **Rule sets** field of a rule (in the Destination / Rule sets condition): besides `.srs` links it takes `.json` (source-format) rule sets and files from your disk. Press **Add file…** or paste a path — it becomes a `file://` line in the same list, next to URLs. The launcher keeps a copy of the file, so the core and remote machines (on Deploy) read the copy; an edited file is picked up within the hourly update loop or on **⬇ upd** without restarting the core. If the source file disappears, the rule keeps working on the last copy. The row button is now **upd** instead of **srs**.
- **Rules are built from conditions.** The rule window no longer makes you pick one type (IP, Domains, Processes, Rule set, Custom JSON). A rule is a stack of conditions joined by AND; inside a condition its fields mean "any of". **+ Condition** adds Destination / Rule sets, Port, Source, Source port, Process, Protocol, Network, Inbound and Wi-Fi — so "domains AND port 443", "a rule set AND only this LAN client" or "bittorrent goes direct" no longer need hand-written JSON. Rule sets and your own domains or addresses sit in one Destination condition and match as "any of". **Rule group** adds a nested group with **all of / any of** and **Not**, as deep as needed. Existing rules open in the form; a rule with a key the form does not know opens on the JSON tab, as before. Wi-Fi works on Windows and Linux; on macOS the condition is marked as having no effect.
- **Rule-set tags are the rule name.** The sets of your rules are now tagged by the rule name and the set's file name instead of `user:<id>` — a rule "Ai" with two downloaded sets and its own domains gets `Ai:geosite-category-ai-!cn`, `Ai:geosite-google` and `Ai` for its own domains; readable in core logs and usable from a hand-written `rule_set`. References to the old tags inside rule bodies and your own DNS rules are rewritten automatically; in a template update them by hand. Downloaded set files are not fetched again. A hand-written `rule_set` that names a set which is not emitted now drops that rule instead of making the core fail to start.
- **DNS options follow the rule's conditions.** A rule's DNS mirror repeats its tree of conditions and groups, keeping only what DNS can see. When the mirror ends up empty (for example a rule matching only "not port 443"), the DNS tab and the rule row show ⚠ "DNS options have no effect: the rule has no condition DNS can see"; the rule is saved and routing works. Fixed: `invert` of a rule was not carried into its DNS mirror, so DNS options acted on the opposite set of names.
- **State and backup format bumped.** `state.json` is now version 9 and the backup file `lx_backup: 3`. Older launcher versions refuse these files instead of reading them with rules lost. On the first save in the new format the previous state is kept next to it as `state.json.v8.bak` (the same for each remote machine's state): to go back to an older version, put it in place of `state.json`.
- **LxBox compatibility:** a backup in the new format is read only by an LxBox version that supports contract 1.1.181.
- **Preset window names the nodes it applies to.** The window of a preset that walks nodes (Tunnel ingress, Tunnel routes, Tailscale) now starts with **Applies to nodes**: one node per line, followed by the node switches the preset reads that are turned on (for Tunnel ingress — access to this device, local network, gateway).
- **Deploy no longer fails when a rule-set the machine's config references was updated.** The machine's daemon refuses to overwrite a file its active or last-good config points to (also with the core stopped), and Deploy used to stop there with advice to stop the core. Now such a rule-set is skipped: it stays at its previous version on the machine until it is delivered another way, the other files are uploaded and the config is applied; the result names the kept rule-sets (up to 5, then "and N more"). Debug API `…/deploy` answers them in `resources_kept`, `…/resources/sync` in `kept`. The machine's resources window says "≠ content differs" with the date of the local copy and, for a file the running config references, that the previous version stays there.
- **Deploy skips a rule-set the machine refuses.** A daemon that can replace a rule-set in use checks the new content first and answers 422 when the core cannot load it or the running core refuses to reload it. Deploy used to stop on that; now the rule-set is skipped with the daemon's reason in the result, the previous file stays on the machine, the rest is uploaded and the config applied. Debug API: `resources_rejected` (`…/deploy`) and `rejected` (`…/resources/sync`), entries `name: reason`.
- **Core sing-box-lx 1.14.4-lx.37-rc.2 (pre-release).** Hop chains are rebuilt as a rewrite of `detour` (see the chains item below). A `round_robin` load-balancing group heals itself: a connection that fails through a node is retried once through another slot, a dead node is replaced in its slot at once, a node that keeps breaking connections is quarantined. A TLS handshake with `tls.fragment` to a server that never acknowledges data no longer hangs past the timeout. A new test outbound `impair` (for checking balancing and chains under a bad line) is in the release builds and does nothing unless a config uses it. From lx.36: WireGuard and AmneziaWG tunnels without a detour are faster (download +15 %, upload +10 % on a Cortex-A55 board) and hold less memory under load; DNS over a proxied stream no longer loses queries in bursts; an HTTP proxy that never answers no longer piles up goroutines and sockets.
- **WARP: the generator no longer writes `reserved`.** The WARP node generator put the registration's `client_id` into the peer as `reserved`; from Russian networks DPI recognises WARP by it and cuts an AmneziaWG tunnel after about 20 packets. The node is now built without `reserved` and the **Bind to this device (reserved)** checkbox is removed. A node you already have keeps its `reserved` until you recreate it with Get WARP; links imported from elsewhere are read as before.
- **Settings → WireGuard.** Two new settings for Linux, where they take effect — routers and remote Linux machines: **Datagrams per read** (8 by default on a remote Linux machine such as a router — about 1 MiB per tunnel instead of 16; 128 elsewhere; 1–2 suit tens and hundreds of tunnels) and **Connected socket** (more upload on a tunnel with one server, off by default). **Send buffers by MTU** is a diagnostic switch, on by default. A key is written into the config only when it differs from the core default; a remote machine with an older core gets the config without them.
- **Daemon mode: traffic of a connection keeps counting.** With the core run by the launcher's own daemon, the traffic profiler took a connection's upload and download from the first event only: the totals stayed at what the connection had when it appeared, so long-lived connections looked silent. The daemon stream reports growth as deltas, and they are now added up — the same way as for a remote machine. The connection list also gets the source address and the detour chain, as on a remote machine. Connections that had already closed when the stream (re)connected are no longer shown as open until the next core restart — in daemon mode and for a remote machine.
- **Balancer pool shows how it heals itself.** In the Info window of a load-balancing group (`round_robin`), the **Live balancer pool** section now shows what the core does about failing nodes: a line with shifted keys, address problems and a freeze (with the time left), and under a slot — **quarantine** in red and the slot's connections and failures. A healthy pool and other group types look as before. The ↻ button re-reads the pool without reopening the window. Needs a core with self-healing `round_robin`; with an older core the section is unchanged. Debug API `…/remote/machines/{id}/pool` returns the same fields.
- **Configurator window opens at its final size.** The window used to open narrower than its tab bar needs and widen on the first frame, slightly off center; it now opens at its final size, centered.

## RU
### Основное
- **Цепочки для ядра 1.14.4-lx.37-rc.2 (SPEC 165 ядра).** Ядро больше не делает копий узлов цепочки: узел на позиции 2 и дальше везде ходит через позицию ниже как сам узел, и группа в цепочке меряет тот путь, по которому идёт трафик. Из редактора цепочки ушли **Link idle timeout** и фильтры strip — ядро их убрало (фильтры теперь по умолчанию действуют на любой узел под detour); сохранённые значения отбрасываются при загрузке и импорте. Узел или группа, используемые не на первой позиции, могут стоять только в одном месте — общий такой узел или группа двух цепочек, кольцо вида «A, затем группа, в которой есть A», фиксированный локальный порт у узла внутри цепочки, узел с именем как у хопа цепочки или rewrite с `detour`: редактор цепочки не сохраняет такую цепочку и подсказывает, что скопировать (группу без A, копию группы для одной из цепочек), а сборка исключает её с предупреждением вместо конфига, который ядро не примет. Общий первый хоп двух цепочек допустим. Окно **Info** узла показывает JSON узла, как его исполняет ядро, с переключателем на форму конфига и списком изменений ядра; в окне **Core runtime** появилась вкладка **Effective config**. Удалённая машина на старом ядре работает со своей прежней формой конфига; секция цепочки в Info у неё не показывается, пока ядро машины не обновлено.
- **Удалённая машина: её конфиг собирается из её собственных входов.** Три входа конфига удалённой машины брались с компьютера, на котором запущен лаунчер. Поля узлов проверялись по ОС и ядру лаунчера: `tls.kernel_tx` / `tls.kernel_rx` (kTLS, только Linux) молча срезались из конфига Linux-роутера при сборке на macOS или Windows, а поля с порогом версии ядра (REALITY `key_share`, XHTTP) шли по версии ядра лаунчера, а не машины. URL / интервал / допуск URLTest у auto-групп брались из Settings этого компьютера, а не машины. Пресеты шаблона отбирались по ОС лаунчера. Теперь все три — от цели: её ОС, версия ядра из паспорта её демона, её Settings. Локальный конфиг собирается как раньше.
- **macOS: уведомления приходят от лаунчера, с его иконкой.** macOS больше не пускала прежний bundle id лаунчера `com.singbox.launcher` к центру уведомлений, и каждое уведомление показывалось от имени «Редактора скриптов». Теперь bundle id приложения — `com.leadaxe.singbox-launcher`. Для macOS это новое приложение: при первом уведомлении она один раз спросит разрешение и заново спросит доступ к **Локальной сети** — его нужно разрешить, иначе машины в локальной сети будут недоступны. Данные, настройки и ядро не затронуты.
- **Удалённая Linux-машина: «TUN auto redirect» больше не ломает Save** (issue #161). Лаунчер на Windows и macOS проверял конфиг удалённой Linux-машины своим ядром, а оно отвергает `auto_redirect` как ключ только для Linux. Проверка теперь этот ключ хоста не учитывает; на машину он уходит как был.
- **TUN: «LAN interfaces» действуют только в режиме шлюза** (issue #160). Список `include_interface` у TUN-инбаунда попадал в конфиг и при выключенном **Gateway mode** — значение, оставшееся в погашенном поле (например IP-адрес вместо имени интерфейса), ломало TUN на машине. Теперь список пишется только при включённом режиме шлюза.
- **Наборы правил (.srs) обновляются сами** (issue #157). Скачанный `.srs` не обновлялся никогда: списки блокировок и обхода устаревали на месяцы, а у правила горело ✔️. Теперь наборы обновляет тот же ежечасный цикл, что и подписки: файл старше своего периода (по умолчанию неделя) скачивается заново, проверяется и подменяется; работающее ядро подхватывает его без перезапуска. Отсутствующий файл докачивается при сборке конфига и перед стартом ядра; если не вышло — правило не попадает в конфиг, а ядро стартует, вместо `FATAL initialize rule_set`. Удалённая машина получает свежие файлы при Deploy.
- **Правила с похожими именами больше не делят один набор.** Внутренний идентификатор правила получался из имени, из которого выбрасывалось всё, кроме латиницы, цифр, `-` и `_`. Поэтому два правила с именами на кириллице (или `Ads` и `Ads!`) получали один идентификатор: оба работали по набору одного из них, а второй список молча не использовался. Теперь к идентификатору имени, потерявшего символы, добавляется короткий хэш, а окно правила не даёт сохранить имя, которое всё же конфликтует с другим правилом. Ссылки на старые теги наборов, сохранённые в DNS-правилах, переписываются при загрузке.
- **DNS-правило: в списке наборов больше нет своих SRS-правил.** DNS для своего SRS-правила задаётся в самом правиле (Rules → изменить правило → вкладка **DNS**): эта настройка принадлежит правилу и переживает переименование, а тег `user:<имя>`, выбранный в DNS-правиле, хранился текстом и рвался при смене имени. Это отменяет правку списка из issue #140. DNS-правила, которые уже ссылаются на теги `user:…`, продолжают работать и при редактировании теги сохраняют; вкладка JSON по-прежнему принимает любой тег.
- **Настройки наборов: Local / Remote, период, маршрут загрузки.** В Settings — новая группа **Rule-sets**, а в окне правила SRS и пресета с наборами — блок **Rule-set updates**, который переопределяет её для этого правила. **Remote** отдаёт загрузку ядру (`type: remote` с `update_interval` и `download_detour`); учтите: ядро не запустится, если первая загрузка не удалась и сохранённой копии нет. Подсказка кнопки srs показывает, когда файлы скачаны в последний раз.
- **Наборы правил из файла и в формате JSON** (issue #153). Поле **Rule sets** правила (в условии Destination / Rule sets): кроме ссылок на `.srs` оно принимает наборы `.json` (исходный формат) и файлы с диска. Нажмите **Add file…** или вставьте путь — он станет строкой `file://` в том же списке, рядом с URL. Лаунчер держит копию файла: ядро и удалённые машины (при Deploy) читают копию; правка файла подхватывается часовым циклом обновления или кнопкой **⬇ upd**, без перезапуска ядра. Если исходный файл пропал, правило работает на последней копии. Кнопка в строке правила теперь **upd**, а не **srs**.
- **Правило собирается из условий.** Окно правила больше не заставляет выбирать один тип (IP, Domains, Processes, Rule set, Custom JSON). Правило — стопка условий, связанных «И»; внутри условия поля значат «любое из». **+ Condition** добавляет Destination / Rule sets, Port, Source, Source port, Process, Protocol, Network, Inbound и Wi-Fi — «домены И порт 443», «набор И только этот клиент LAN», «bittorrent напрямую» больше не требуют JSON руками. Наборы и свои домены или адреса стоят в одном условии Destination и срабатывают как «любое из». **Rule group** добавляет вложенную группу с **all of / any of** и **Not**, любой глубины. Существующие правила открываются формой; правило с ключом, которого форма не знает, открывается на вкладке JSON, как раньше. Wi-Fi действует на Windows и Linux; на macOS условие помечено как не действующее.
- **Теги наборов — имя правила.** Наборы своих правил теперь называются по имени правила и имени файла набора, а не `user:<id>` — у правила «Ai» с двумя скачанными наборами и своими доменами: `Ai:geosite-category-ai-!cn`, `Ai:geosite-google` и `Ai` для своих доменов; читаются в логах ядра, на них можно сослаться рукописным `rule_set`. Ссылки на старые теги внутри тел правил и своих DNS-правил переписываются сами; в шаблоне — поправьте вручную. Скачанные файлы наборов заново не качаются. Рукописный `rule_set` на невыпущенный набор теперь снимает это правило, а не роняет старт ядра.
- **DNS-опции идут по условиям правила.** DNS-зеркало правила повторяет его дерево условий и групп, оставляя только то, что видит DNS. Если зеркало вышло пустым (например, правило только «не порт 443»), на вкладке DNS и в строке правила ⚠ «DNS options have no effect: the rule has no condition DNS can see»; правило сохраняется, маршрут работает. Исправлено: `invert` правила не переносился в его DNS-зеркало, и DNS-опции действовали на обратное множество имён.
- **Версия состояния и бэкапа поднята.** `state.json` теперь версии 9, файл бэкапа — `lx_backup: 3`. Старые версии лаунчера такие файлы отвергают, а не читают с потерей правил. При первом сохранении в новом формате прежнее состояние остаётся рядом как `state.json.v8.bak` (так же у состояния каждой удалённой машины): чтобы вернуться на старую версию, положите его на место `state.json`.
- **Совместимость с LxBox:** бэкап нового формата читает только версия LxBox с поддержкой контракта 1.1.181.
- **Окно пресета называет узлы, на которых он сработает.** Окно пресета с обходом узлов (Tunnel ingress, Tunnel routes, Tailscale) начинается с блока **Applies to nodes**: по узлу на строку, за тегом — включённые у узла переключатели, которые пресет читает (у Tunnel ingress — доступ к устройству, локальная сеть, шлюз).
- **Deploy больше не падает, когда обновился набор, на который ссылается конфиг машины.** Демон машины не даёт перезаписать файл, на который указывает её активный или last-good конфиг (и при остановленном ядре тоже), и Deploy обрывался на этом с советом остановить ядро. Теперь такой набор пропускается: на машине он остаётся прежней версии до доставки новым способом, остальные файлы заливаются, конфиг применяется; итог перечисляет оставленные наборы (до 5, дальше «and N more»). Debug API `…/deploy` отдаёт их в `resources_kept`, `…/resources/sync` — в `kept`. Окно ресурсов машины пишет «≠ content differs» с датой локальной копии, а для файла, на который ссылается работающий конфиг, — что там остаётся прежняя версия.
- **Deploy пропускает набор, который машина не приняла.** Демон, умеющий заменять занятый набор, сначала проверяет новое содержимое и отвечает 422, если ядро не может его загрузить или работающее ядро отказалось его перечитать. Раньше Deploy на этом обрывался; теперь набор пропускается с причиной от демона в итоге, на машине остаётся прежний файл, остальное заливается, конфиг применяется. Debug API: `resources_rejected` (`…/deploy`) и `rejected` (`…/resources/sync`), записи «имя: причина».
- **Ядро sing-box-lx 1.14.4-lx.37-rc.2 (пре-релиз).** Цепочки перестроены как перезапись `detour` (см. пункт про цепочки ниже). Группа с балансировкой `round_robin` восстанавливается сама: соединение, не открывшееся через узел, один раз повторяется через другой слот, мёртвый узел сразу заменяется в слоте, узел, который рвёт соединения, уходит в карантин. Рукопожатие TLS с `tls.fragment` к серверу, не подтверждающему данные, больше не висит дольше таймаута. Новый тестовый outbound `impair` (проверка балансировки и цепочек под плохой линией) есть в релизных сборках и ничего не делает, пока его нет в конфиге. Из lx.36: Туннели WireGuard и AmneziaWG без detour быстрее (скачивание +15 %, отдача +10 % на плате с Cortex-A55) и держат меньше памяти под нагрузкой; DNS через потоковое прокси-соединение больше не теряет запросы пачками; HTTP-прокси, который молчит, больше не копит горутины и сокеты.
- **WARP: генератор больше не пишет `reserved`.** Генератор узлов WARP клал `client_id` регистрации в пира как `reserved`; из российских сетей DPI узнаёт WARP по нему и рвёт туннель AmneziaWG примерно после 20 пакетов. Теперь узел строится без `reserved`, а галка **Bind to this device (reserved)** убрана. Уже созданный узел сохраняет `reserved`, пока вы не создадите его заново через Get WARP; ссылки, импортированные из других источников, читаются как раньше.
- **Settings → WireGuard.** Две новые настройки для Linux, где они действуют, — роутеры и удалённые Linux-машины: **Datagrams per read** (на удалённой Linux-машине, например роутере, по умолчанию 8 — около 1 МБ на туннель вместо 16; в остальных случаях 128; 1–2 — для десятков и сотен туннелей) и **Connected socket** (больше отдачи у туннеля с одним сервером, по умолчанию выключен). **Send buffers by MTU** — диагностический переключатель, по умолчанию включён. Ключ попадает в конфиг, только если отличается от дефолта ядра; удалённой машине со старым ядром конфиг уходит без них.
- **Режим демона: трафик соединения продолжает считаться.** Когда ядро ведёт собственный демон лаунчера, профайлер трафика брал отдачу и загрузку соединения только из первого события: суммы застывали на том, что было у соединения в момент появления, и долгие соединения выглядели молчащими. Поток демона сообщает рост приращениями — теперь они складываются, так же как у удалённой машины. В списке соединений появились адрес источника и цепочка detour, как у удалённой машины. Соединения, закрытые к моменту (пере)подключения потока, больше не числятся открытыми до следующего перезапуска ядра — в режиме демона и у удалённой машины.
- **Пул балансировщика показывает самовосстановление.** В окне Info группы с балансировкой (`round_robin`) секция **Живой пул балансировщика** показывает, что ядро делает с отказывающими узлами: строку со сдвинутыми ключами, проблемами с адресом и заморозкой (с остатком времени), а под слотом — **карантин** красным и счётчики соединений и отказов слота. Здоровый пул и группы других типов выглядят как раньше. Кнопка ↻ перечитывает пул без переоткрытия окна. Нужно ядро с самовосстановлением `round_robin`; со старым ядром секция прежняя. Debug API `…/remote/machines/{id}/pool` отдаёт те же поля.
- **Окно Конфигуратора открывается сразу в итоговом размере.** Раньше оно открывалось уже, чем нужно полосе вкладок, и на первом кадре расширялось, съезжая с центра; теперь открывается в итоговом размере и по центру.
