# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **Remote machines: is my config on the machine?** The machine row now shows it at a glance. An orange dot on **Deploy** (renamed from "Deploy config") means the config saved here differs from the one running on the machine (sha256 of the built `config.json` vs the daemon's active SHA, checked on every 5-second poll). A red dot on **Configure** means the last deploy did not start and the core rolled back to the last-good config. The ⓘ window also lists the local built-config sha256 next to the machine's active and last-good hashes.
- **Service window: keeping the daemon running, here and on every machine.** A new ⚙ next to ⓘ in a machine's row (and Servers → ⚙ → Local for this computer) opens one runbook with four tabs — **Not running** (status → restart → log → boot the last working config once → reinstall), **Core** (running vs required version; for a Linux machine: download the core for *its* platform into `~/Downloads`, checked against `SHA256SUMS`, stream it over ssh — `scp` does not work on OpenWrt — check it with the new binary, back up, swap, restart, roll back), **Pairing** (mint an invite on the machine, paste, Pair; who is trusted, revoke) and **Reference** (binary, service, state dir, `daemon.json`, last-good and log paths as the daemon reported them, or marked `default`; the `daemon.json` keys; a live log window). Every command uses the machine's own paths; ⧉ copies it, ▶ opens Terminal with `ssh <target> '…'`. The window opens on the tab that needs attention and its header turns green by itself once the daemon answers. The machine row gets a yellow dot on ⚙ and a `⚠ Core lx.11 is older than required (lx.14)` line when its core is too old, a red dot and a `✖ …` line when the daemon does not answer. Deploy to an older core now warns first (**How to update** / **Deploy anyway**, with "Don't ask again for this version"). The machine's Edit window has an **SSH** field (`root@<host>` by default); the init system (procd/systemd) is picked in the Service header. Locally the Status/Install tabs became the same view plus **Uninstall**, and the service can now be restarted from the launcher. New guide: [TROUBLESHOOTING → Daemon](../TROUBLESHOOTING.md#daemon).
- **macOS install script:** the core download now shows a progress bar, like the launcher download (it used to run silently).
- **macOS app icon:** transparent rounded corners on macOS 11–15 (it showed white corners there; macOS 26 was unaffected).

### Technical / Internal
- Debug API (SPEC 161): `/daemon/status` += `log_path`, `executable`, `listen`, `tls`, `uptime_seconds`, `passport_seen_at`, `passport_cached`, `reach_error`; `/daemon/commands` += `restart`, `client_list`; a machine entry += `ssh`, `init_system`, `core_warn_ack`, `passport` (`ssh` and `init_system` writable via `PATCH /remote/machines/{id}`); `/remote/machines/{id}/health` += `executable`, `log_path`, `listen`, `tls`, `uptime_seconds`, `core_required`, `core_outdated`.
- Core-version comparison and the service recipes (procd/systemd/launchd/SCM, ssh wrapping, error classification) are untagged pure functions in `core` (`core_build.go`, `service_recipes.go`), covered by one table test; the machine registry gains `ssh`, `init_system`, `core_warn_ack` and a cached `passport` (no migration, not part of LX Backup or the contract).

## RU
### Основное
- **Удалённые машины: доехал ли конфиг.** Строка машины теперь показывает это сразу. Оранжевая точка на **Отправить** (бывшее «Отправить конфиг»): сохранённый здесь конфиг не тот, что работает на машине (sha256 собранного `config.json` против active SHA демона, сверка на каждом опросе раз в 5 с). Красная точка на **Настроить**: последняя отправка не завелась, ядро откатилось на прежний удачный конфиг. В окне ⓘ рядом с хешами машины добавлен sha256 собранного здесь конфига.
- **Окно Service: обслуживание демона здесь и на каждой машине.** Новая ⚙ рядом с ⓘ в строке машины (и Servers → ⚙ → Local для этого компьютера) открывает один раннбук с четырьмя вкладками — **Not running** (статус → перезапуск → лог → один раз загрузить последний рабочий конфиг → переустановка), **Core** (работающая версия против требуемой; для Linux-машины: скачать ядро под *её* платформу в `~/Downloads` со сверкой с `SHA256SUMS`, залить потоком через ssh — `scp` на OpenWrt не работает, — проверить новым бинарём, бэкап, замена, перезапуск, откат), **Pairing** (выпустить приглашение на машине, вставить, Pair; кому доверяет демон, отзыв) и **Reference** (пути бинаря, службы, state dir, `daemon.json`, last-good и лога — как их сообщил демон или с пометкой `default`; ключи `daemon.json`; окно живого лога). Все команды — с путями самой машины; ⧉ копирует, ▶ открывает Терминал с `ssh <цель> '…'`. Окно открывается на вкладке, где есть что чинить, а шапка сама зеленеет, когда демон снова отвечает. В строке машины — жёлтая точка на ⚙ и строка `⚠ Core lx.11 is older than required (lx.14)`, когда ядро старее нужного, красная точка и строка `✖ …`, когда демон не отвечает. Deploy на старое ядро теперь сначала предупреждает (**How to update** / **Deploy anyway**, с «больше не спрашивать для этой версии»). В окне Edit машины — поле **SSH** (по умолчанию `root@<хост>`); init-система (procd/systemd) выбирается в шапке Service. Локально вкладки Status/Install стали тем же видом плюс **Uninstall**, а службу теперь можно перезапустить из лаунчера. Новый раздел: [TROUBLESHOOTING → Демон](../TROUBLESHOOTING.ru.md#демон).
- **Скрипт установки на macOS:** скачивание ядра теперь показывает прогресс, как и скачивание лаунчера (раньше шло молча).
- **Иконка приложения на macOS:** прозрачные скруглённые углы на macOS 11–15 (там были видны белые углы; на macOS 26 проблемы не было).

### Техническое / Внутреннее
- Debug API (SPEC 161): `/daemon/status` += `log_path`, `executable`, `listen`, `tls`, `uptime_seconds`, `passport_seen_at`, `passport_cached`, `reach_error`; `/daemon/commands` += `restart`, `client_list`; запись машины += `ssh`, `init_system`, `core_warn_ack`, `passport` (`ssh` и `init_system` пишутся через `PATCH /remote/machines/{id}`); `/remote/machines/{id}/health` += `executable`, `log_path`, `listen`, `tls`, `uptime_seconds`, `core_required`, `core_outdated`.
- Сравнение версий ядра и рецепты службы (procd/systemd/launchd/SCM, ssh-обёртка, классификация ошибок связи) — нетегированные чистые функции в `core` (`core_build.go`, `service_recipes.go`) под одним табличным тестом; в реестре машин — `ssh`, `init_system`, `core_warn_ack` и кэш `passport` (без миграции, не входят ни в LX Backup, ни в контракт).
