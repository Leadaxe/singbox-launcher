# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- Tailscale: removed the "Keep local network reachable while using the exit node" checkbox from Add server and from the node's Settings block. It had no effect: the core's Tailscale stack installs no LAN-bypass routes because sing-box does all routing. LAN traffic bypasses the exit node through the "Private IPs" rule preset. `exit_node_allow_lan_access` is still accepted from JSON.
- DNS rules: the "SRS (existing rule_set)" picker now lists the rule sets of your own SRS rules (`user:<name>`, plus `user:<name>:2`, … for rules with several URLs), not only those of enabled library presets ([#140](https://github.com/Leadaxe/singbox-launcher/issues/140)).
- DNS servers: the server form now covers DoQ (`quic`, port 853) and DoH3 (`h3`, port 443, with path) alongside UDP/TCP/DoT/DoH, same as LxBox. Before, these types could only be edited on the JSON tab.
- OpenConnect (AnyConnect, GlobalProtect, Fortinet, F5, Pulse) nodes added as sing-box JSON (`"type": "openconnect"`) now land in `endpoints[]`, where the core expects them. Before, the launcher wrote them to `outbounds[]` and the core rejected the whole config with `unknown outbound type: openconnect`. The body is passed through as written; on a core built without `with_openconnect` the node is dropped with a build-report warning instead of breaking the config. Contract 1.1.120.
- A node whose body the core cannot even decode (for example an old MASQUE body with `network`: `decode config: outbounds[12].network: json: unknown field "network"`) is now turned off automatically like any other node the core rejects, and the config is rebuilt. Before, this error named no tag, so the safety net stayed silent and the VPN did not start. Contract 1.1.121.
- Detour picker and rule/DNS target lists no longer offer template Direction stubs you deleted (`vpn ①`, `vpn ②`): they are not in the config, so picking one pointed to nothing. `block-out` is no longer offered as a detour either — chaining through a block makes no sense.
- OpenConnect: the Add server dialog and the node editor now have a form for OpenConnect gateways (FortiGate, Cisco AnyConnect, GlobalProtect, F5, Pulse, Juniper NC): gateway type, server, username and password, server certificate check with three choices (system CAs / pinned fingerprint / do not verify), SNI and group, and an Advanced block (TCP only, User-Agent, Hostcheck for FortiGate, MTU, DPD interval, reconnect timeout, disable IPv6, legacy crypto). An empty field writes no key, so the gateway or core default stays. In the server list the node is labelled like `openconnect·fortinet`.
- OpenConnect: second factor and browser (SAML) sign-in, daemon mode (lxd) and remote machines only. When the gateway asks for a code, a dialog shows the gateway's own form fields; "Not now" closes it and sends nothing, "Request a new code" asks the gateway again (a new e-mail with a code). FortiGate browser sign-in works through a link and a temporary local callback on 127.0.0.1 (port from the gateway's answer, or 8020). In classic mode the node shows a hint that code prompts are unavailable. SSO that returns a cookie (AnyConnect) is not supported yet.
- Detour picker is now a two-level tree: the button opens a popup with "(none — direct)" on top and expandable Directions and Nodes branches; the branch with the current choice opens by itself. A chosen target that is no longer in the config stays visible with a ⚠ (missing) mark.
- Add server: forms for VLESS (None / TLS / Reality, uTLS fingerprint, transports ws, gRPC, HTTP, HTTPUpgrade, XHTTP), Hysteria2 (obfuscation, port hopping), Trojan, WireGuard (AWG) with a collapsed AmneziaWG block (`jc`…`i5`), naive and masque. SOCKS5, HTTP and WireGuard moved to the same registry-driven form; the type list is VLESS · Hysteria2 · Trojan · WireGuard (AWG) · naive · masque · SOCKS5 · HTTP · OpenConnect (SSL VPN) · Tailscale · Source. The same form edits an existing node of these types in the node window. The WireGuard form no longer has a DNS field: tunnel DNS was never applied (the launcher's DNS is global).
- Sources: Add with an empty field opens the Add server form.

### Technical / Internal
- Fyne 2.8.1 → 2.8.2 ([#142](https://github.com/Leadaxe/singbox-launcher/pull/142)); GLFW 3.4 moves to the tagged `pre.2`.
- golangci-lint CI takes Go from `go.mod` (it was pinned to 1.25 and failed `go mod tidy` on every PR), golangci-lint 2.14.0, action v9; the 36 errcheck/unused/bodyclose findings it reported are fixed. The stale Dependabot ignore for `golang.org/x/sys` ≥ 0.48 is removed (the toolchain is already Go 1.26).
- Contract 1.1.122: wildcard `*` in the registry (a described subset of fields plus pass-through of the rest; not inherited into nested objects), the `form` attribute (visibility, required, ranges, blocks, choice groups; read by forms only), and the `variant` field role for the node label. `fields_unchecked` is removed (openvpn-client moved to `*`). The build writes `server`/`server_port` only into fields the scheme describes. New codes `openconnect_flavor_invalid`, `openconnect_fingerprint_invalid`, `openconnect_mtu_invalid`, `openconnect_insecure_crypto`. Corpus `body/singbox/openconnect_*` and `corpus/form`.
- Contract 1.1.123: `form` on scheme ref fields and on shared `tls`/`transports` fields, `form.fixed`, `form.implies`, `exclude_fields`/`exclude_variants`, array element `[0]` in form paths, active choice by the longest match; forms for vless, hysteria2, trojan, wireguard, naive, masque, socks, http; `transports` ws/httpupgrade describe `headers.Host` plus `*`. Corpus `corpus/form/*_form.json`.

## RU
### Основное
- Tailscale: из «Add server» и блока узла в Settings убрана галка «Keep local network reachable while using the exit node». Она ничего не делала: стек Tailscale в ядре маршрутов LAN-защиты не ставит, маршрутизацию ведёт sing-box. Локальную сеть мимо exit node пускает пресет «Private IPs». Поле `exit_node_allow_lan_access` по-прежнему принимается из JSON.
- DNS-правила: в выборе «SRS (existing rule_set)» теперь есть наборы ваших собственных SRS-правил (`user:<имя>`, а у правил с несколькими URL ещё `user:<имя>:2`, …), а не только наборы включённых пресетов библиотеки ([#140](https://github.com/Leadaxe/singbox-launcher/issues/140)).
- DNS-серверы: форма сервера теперь умеет DoQ (`quic`, порт 853) и DoH3 (`h3`, порт 443, с путём) наряду с UDP/TCP/DoT/DoH — как в LxBox. Раньше эти типы правились только на вкладке JSON.
- Узлы OpenConnect (AnyConnect, GlobalProtect, Fortinet, F5, Pulse), добавленные как sing-box JSON (`"type": "openconnect"`), теперь попадают в `endpoints[]`, где их ждёт ядро. Раньше лаунчер писал их в `outbounds[]`, и ядро отвергало весь конфиг с `unknown outbound type: openconnect`. Тело уходит как написано; на ядре без `with_openconnect` узел снимается с предупреждением в отчёте сборки, а не ломает конфиг. Контракт 1.1.120.
- Узел, тело которого ядро не может даже декодировать (например, старое тело MASQUE с `network`: `decode config: outbounds[12].network: json: unknown field "network"`), теперь выключается автоматически, как любой узел, отвергнутый ядром, и конфиг пересобирается. Раньше в такой ошибке не было тега, страховка молчала, и VPN не поднимался. Контракт 1.1.121.
- Выбор detour и списки целей правил/DNS больше не предлагают удалённые вами заготовки Направлений шаблона (`vpn ①`, `vpn ②`): в конфиге их нет, и выбор указывал в пустоту. `block-out` из detour тоже убран — цепочки через блокировку не бывает.
- OpenConnect: в «Add server» и в правке узла появилась форма для шлюзов OpenConnect (FortiGate, Cisco AnyConnect, GlobalProtect, F5, Pulse, Juniper NC): тип шлюза, сервер, логин и пароль, проверка сертификата сервера тремя вариантами (системные CA / отпечаток / без проверки), SNI и группа, блок Advanced (TCP only, User-Agent, Hostcheck для FortiGate, MTU, DPD, reconnect timeout, отключение IPv6, legacy crypto). Пустое поле ключ не пишет, поэтому дефолт шлюза или ядра остаётся. В списке серверов узел подписан как `openconnect·fortinet`.
- OpenConnect: второй фактор и вход через браузер (SAML) — только в daemon-режиме (lxd) и на удалённых машинах. Если шлюз просит код, открывается диалог с полями формы, которые отдал сам шлюз; «Not now» закрывает его и ничего не шлёт, «Request a new code» запрашивает код заново (придёт новое письмо). Браузерный вход для FortiGate идёт через ссылку и временный локальный callback на 127.0.0.1 (порт из ответа шлюза или 8020). В классическом режиме на узле подсказка, что запрос кода недоступен. SSO через cookie (AnyConnect) пока не поддерживается.
- Выбор detour теперь двухуровневое дерево: кнопка открывает попап, где сверху «(нет — напрямую)», а под ним раскрываемые ветки «Направления» и «Узлы»; ветка с текущим выбором раскрыта сразу. Выбранная цель, которой больше нет в конфиге, остаётся видна с пометкой ⚠ (нет в конфиге).
- «Add server»: формы для VLESS (None / TLS / Reality, отпечаток uTLS, транспорты ws, gRPC, HTTP, HTTPUpgrade, XHTTP), Hysteria2 (обфускация, port hopping), Trojan, WireGuard (AWG) со свёрнутым блоком AmneziaWG (`jc`…`i5`), naive и masque. SOCKS5, HTTP и WireGuard переведены на ту же форму по реестру; список типов: VLESS · Hysteria2 · Trojan · WireGuard (AWG) · naive · masque · SOCKS5 · HTTP · OpenConnect (SSL VPN) · Tailscale · Source. Та же форма правит готовый узел этих типов в окне узла. В форме WireGuard больше нет поля DNS: DNS туннеля и раньше не применялся (DNS у лаунчера общий).
- Sources: Add при пустом поле открывает форму «Add server».
