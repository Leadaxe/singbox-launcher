# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **SRS rules with many links: dead links are named, not hidden.** The real cause of "more than 7 SRS links fail" was a link that returns HTTP 404, not the group deadline: the download stopped at the first broken file and the dialog only said "see the log". Now every file of the rule is downloaded, and if some links do not exist the dialog lists them by file name so they can be removed from the rule.
- **Troubleshooting: Linux `system` TUN stack blocked by firewalld.** When the VPN is up but nothing loads and `gvisor` works, a host firewall drops the local TCP forwarder of the `system` stack. The troubleshooting guide now has the narrow `firewall-cmd` rule (issue #129).
- **Linux: TUN auto redirect.** New setting Wizard → Settings → "TUN auto redirect (Linux)" (sing-box `auto_redirect`): TCP is routed into the core with nftables/iptables rules instead of the `system` stack's local forwarder, so a host firewall like firewalld no longer blocks the VPN. On by default on this computer, off for remote machines; emitted only on Linux with auto-route enabled. Confirmed by the reporter of issue #129 on openSUSE. Contract 1.1.133.
- **DNS: template servers can be deleted.** The template's DNS servers are now a catalog: they are added to your list once, and after that the list is yours — a template server you do not need can be deleted with **Del** and stays deleted after restarts and reopening the Configurator. **Add from template** opens the whole catalog: a deleted server comes back with the template's defaults, a server already in the list is added as your own copy (its current settings, a new tag) and opens in the editor; **Add all defaults** returns all deleted ones. A server that something still uses (Final DNS, the default domain resolver, a DNS rule, a rule's DNS option, a DNS group, another server's domain resolver, a preset) cannot be deleted: the tooltip says what uses it; `required` servers stay. Existing setups keep every server they had — the config does not change after the update.
- **Backup: deleted template DNS servers travel between devices.** The backup file now carries the source's template catalog (`dns.template_catalog`) and the full server list. Importing a file removes a template server the source deleted — unless something here still uses it (`backup_dns_entry_kept` names what); Final DNS / default resolver pointing to a server missing here are reset to the template default, and an imported DNS group with no servers here comes in turned off. Older backups without the catalog are merged as before, nothing is removed. Same rules as LxBox (contract 1.1.135–1.1.136).
- **Rules: answer DNS with a fixed IP (hosts-style).** The rule window's DNS tab now has **Answer**: Default (DNS Final), Dedicated server, or **Fixed IP** — one address per line, IPv4 or IPv6. Domains matched by the rule get these addresses straight from the core (`predefined` answers `*. 300 IN A|AAAA <ip>`; a family without addresses gets an empty answer), and traffic to them follows the rule's action. Same as LxBox; contract 1.1.139 (`rules[].dns.fixedIps`) with a shared corpus `rule_dns`.
- **WireGuard: configurations with several peers keep all of them.** A wg-quick `.conf` (also `vpn://` and `awg://` base64) with several `[Peer]` sections now becomes one node with all peers in file order — the core routes between them by `AllowedIPs`. Before, only the first peer was kept. A `[Peer]` without `PublicKey` or `Endpoint` is skipped on its own (`wgconf_peer_dropped`), and a peer with a broken key no longer drops the whole node — only that peer (`wg_peer_dropped`). Same as LxBox; contract 1.1.140.
- **macOS: windows no longer freeze after sleep.** After the Mac woke up, the launcher's windows kept reacting to clicks but showed the pre-sleep picture until the window was resized. Now every window is resized by one pixel and back shortly after wake, which makes macOS give it a fresh drawing surface.
- **macOS: notifications come from the launcher.** Notifications (auto-deploy, short info messages) were shown as coming from Script Editor with its icon, and the launcher had no entry in Notifications settings: macOS refuses the modern notification API to an ad-hoc signed app, and the fallback was `osascript`. Now the launcher falls back to the older notification center first — notifications carry the launcher's icon, and on the first one macOS asks for permission once; it can then be turned on or off in System Settings → Notifications.
- **TrustTunnel nodes are known to the launcher.** A sing-box JSON node of type `trusttunnel` (AdGuard TrustTunnel, core `lx.21+`) is now parsed by the registry like any other outbound: credentials and `tls` are required, `quic` together with uTLS is resolved the way the core demands (`quic` is dropped, the node runs over HTTP/2), unknown keys are reported. No share link and no Add server form yet — the node comes in as JSON. Contract 1.1.141.
- **Fixed: saving a machine config with a TrustTunnel node showed "the machine will refuse it on Deploy".** The candidate config is checked by the launcher's own bundled core; when that core is older than lx.21 it does not know `trusttunnel` and rejected the whole file, although the machine's newer core accepts it. With the registry entry the launcher no longer feeds the node to a core that cannot run it blindly; the check itself still uses the bundled core — update it to lx.21 or newer to get a clean Save.
- **Debug API: folders, node detour, and a machine's config built without the wizard (issue #152).** `GET/POST/DELETE /state/folders` lists, creates and deletes folders (a folder with nodes only with `with_nodes=1`; links to its nodes are removed); `POST /state/servers` takes an optional `detour` (a root name or a node of a folder/subscription) for the nodes it adds; `POST /remote/machines/{id}/config/rebuild` builds a machine's config from its profile the way the wizard's Save does, and `?deploy=1` deploys it — profile edits made through the API no longer wait for Save in the UI. All of it is mirrored for remote machines. `API.md` also notes that `URLTestOutbound.timeout` is in milliseconds.
- **Backup import: an edited template DNS server stays one server.** LxBox now lets you edit a template DNS server; the edit is saved as your own server under the same tag. Importing such a backup no longer lists the server twice, and no longer removes the template server as "deleted by the source". When both sides have the tag, the receiving side keeps its own record, whether it is the template one or the edited one. Contract 1.1.142.
- **TUN MTU defaults to 9000, as in sing-box.** The template default for TUN MTU was 1492; it is now 9000, the core's own default, same as LxBox. A value you set yourself in Settings stays as it is. If UDP through a WireGuard/AmneziaWG node misbehaves, set TUN MTU back to 1492 or lower. Contract 1.1.143.

### Core
- `sing-box-lx 1.14.4-lx.25` (was 1.14.3-lx.21), base upstream sing-box 1.14.4. Fixes: a masque `vhttp: auto` node no longer keeps the previous core instance in memory after every reload (Stop/Start, apply) — on a router the heap grew until the GC ate both CPU cores within days, affected since `v1.14.0-lx.27`; the core no longer waits 10–16 s on start for an unrelated mux handshake. New: `lxd` runs the admin's own scripts at the core's lifecycle boundaries (`pre_start`, `post_start`, `post_reload`, `post_stop` in `<state_dir>/hooks/`, off by default, `hooks.enabled` in `daemon.json`, Unix only); the launcher does not manage them. lx.23: a `round_robin` pool no longer sends new connections to a node that failed its last probe; stopping the core with many WireGuard/AmneziaWG endpoints is fast again; a stop hanging over 20 s writes a goroutine dump to the core log. lx.24: connection test through the core (a tree of stages with the root cause; the launcher does not show it yet). lx.25: XHTTP `packet-up` upload no longer waits for each POST's reply (single-stream upload is no longer capped by the round trip), six smaller XHTTP gaps against Xray closed (a `stream-up` write hanging after the server refused the upload, path slash, HTTP/2 pool and keep-alive, default Chrome headers, literal `%` in `path`).

### Technical / Internal
- Contract 1.1.141: `registry/protocols/trusttunnel.json` (outbound, singbox source only, no core gate), three `body/singbox` corpus cases, LxBox §137.
- Contract 1.1.144: the build cleans a DNS group's `hosts` key (core `1.14.4-lx.26`, SPEC 143 of the core) after its members — only emitted servers of type `hosts`, no repeats, not the group itself and not its members stay, an empty list drops the key; a `hosts` link holds a server like a member does in backup import (`used_by` `group:<tag>`). Corpus `dns/group_prunes_hosts`, `dns/group_hosts_all_dropped`, LxBox §140. The pinned core is still lx.25.

## RU
### Основное
- **SRS-правило с множеством ссылок: мёртвые ссылки называются поимённо.** Настоящая причина «больше 7 SRS-ссылок не работает» — ссылка, отвечающая HTTP 404, а не дедлайн группы: загрузка вставала на первом битом файле, а окно писало только «подробности в логе». Теперь качаются все файлы правила, и если каких-то ссылок не существует, окно перечисляет их по имени файла, чтобы их убрали из правила.
- **Troubleshooting: стек `system` на Linux режет firewalld.** Когда VPN поднят, но ничего не грузится, а с `gvisor` работает, хост-файрвол рубит локальный TCP-форвардер стека `system`. В руководстве по диагностике появилось точечное правило `firewall-cmd` (issue #129).
- **Linux: TUN auto redirect.** Новая настройка Wizard → Settings → «TUN auto redirect (Linux)» (sing-box `auto_redirect`): TCP заворачивается в ядро правилами nftables/iptables вместо локального форвардера стека `system`, и хост-файрвол вроде firewalld больше не блокирует VPN. По умолчанию включена на этом компьютере, выключена для удалённых машин; эмитится только на Linux при включённом auto-route. Подтверждено автором issue #129 на openSUSE. Контракт 1.1.133.
- **DNS: шаблонные серверы можно удалять.** DNS-серверы шаблона теперь каталог: в ваш список они попадают один раз, дальше список ваш — ненужный шаблонный сервер удаляется кнопкой **Del** и не возвращается ни перезапуском, ни повторным открытием Конфигуратора. **Добавить из шаблона** открывает весь каталог: удалённый сервер возвращается с настройками шаблона, уже добавленный — появляется вашей копией (текущие настройки, новый тег) и сразу открывается в редакторе; **Вернуть все шаблонные** — все удалённые сразу. Сервер, который что-то использует (Final DNS, резолвер доменов по умолчанию, DNS-правило, DNS-опция правила, DNS-группа, резолвер другого сервера, пресет), удалить нельзя — подсказка называет, кто его держит; обязательные (`required`) серверы остаются. У существующих настроек все серверы на месте — конфиг после обновления тот же.
- **Бэкап: удалённые шаблонные DNS-серверы переносятся между устройствами.** Файл бэкапа несёт каталог шаблона источника (`dns.template_catalog`) и полный список серверов. Импорт снимает шаблонный сервер, удалённый источником, — если здесь его ничего не держит (иначе `backup_dns_entry_kept` называет, что держит); Final DNS и резолвер по умолчанию на сервер, которого здесь нет, сбрасываются на умолчание шаблона, а ввезённая DNS-группа без серверов приезжает выключенной. Старые бэкапы без каталога сливаются как раньше, ничего не снимается. Правила те же, что у LxBox (контракт 1.1.135–1.1.136).
- **Правила: ответ DNS фиксированным IP (как hosts).** На вкладке DNS окна правила появился **Ответ**: По умолчанию (DNS Final), Отдельный сервер или **Фиксированный IP** — по одному адресу в строке, IPv4 или IPv6. Домены правила получают эти адреса прямо от ядра (`predefined`, записи `*. 300 IN A|AAAA <ip>`; семейство без адресов — пустой ответ), а трафик к ним идёт по действию правила. Как у LxBox; контракт 1.1.139 (`rules[].dns.fixedIps`), общий корпус `rule_dns`.
- **WireGuard: конфигурация с несколькими пирами сохраняет их все.** `.conf` wg-quick (а также `vpn://` и `awg://` base64) с несколькими секциями `[Peer]` теперь становится одним узлом со всеми пирами в порядке файла — трафик между ними ядро разводит по `AllowedIPs`. Раньше оставался только первый пир. `[Peer]` без `PublicKey` или `Endpoint` пропускается одна (`wgconf_peer_dropped`), а пир с битым ключом больше не роняет весь узел — снимается только он (`wg_peer_dropped`). Как у LxBox; контракт 1.1.140.
- **macOS: окна больше не замирают после сна.** После пробуждения Мака окна лаунчера реагировали на клики, но показывали картинку до сна, пока окно не потянешь за край. Теперь вскоре после пробуждения каждое окно на мгновение увеличивается на пиксель и возвращается обратно — macOS выдаёт ему новую поверхность для рисования.
- **macOS: уведомления приходят от лаунчера.** Уведомления (автодеплой, короткие информационные сообщения) показывались от имени «Редактора скриптов» с его иконкой, а в настройках уведомлений лаунчера не было: ad-hoc подписанному приложению macOS не даёт новый API уведомлений, и запасным путём был `osascript`. Теперь лаунчер сначала переходит на прежний центр уведомлений — уведомления идут с иконкой лаунчера, при первом macOS один раз спрашивает разрешение, дальше их можно включать и выключать в «Системные настройки → Уведомления».
- **Узлы TrustTunnel известны лаунчеру.** Узел sing-box JSON типа `trusttunnel` (AdGuard TrustTunnel, ядро `lx.21+`) теперь разбирается реестром как любой другой outbound: учётные данные и `tls` обязательны, `quic` вместе с uTLS разрешается так, как требует ядро (`quic` снимается, узел идёт по HTTP/2), незнакомые ключи называются. Ссылки для обмена и формы Add server пока нет — узел приходит JSON'ом. Контракт 1.1.141.
- **Исправлено: сохранение конфига машины с узлом TrustTunnel показывало «машина откажет на Deploy».** Кандидат конфига проверяет ядро из бандла лаунчера; если оно старше lx.21, оно не знает `trusttunnel` и отвергало весь файл, хотя более новое ядро на машине его принимает. С записью в реестре лаунчер больше не отдаёт узел ядру вслепую; сама проверка по-прежнему идёт ядром бандла — обновите его до lx.21 или новее, чтобы Save проходил чисто.
- **Debug API: папки, detour узла и сборка конфига машины без Мастера (issue #152).** `GET/POST/DELETE /state/folders` показывает, заводит и удаляет папки (непустую — только с `with_nodes=1`, ссылки на её узлы снимаются); `POST /state/servers` принимает необязательный `detour` (корневое имя или узел папки/подписки) для добавляемых узлов; `POST /remote/machines/{id}/config/rebuild` собирает конфиг машины из её профиля так же, как Save Мастера, а `?deploy=1` сразу его деплоит — правки профиля через API больше не ждут Save в интерфейсе. Всё зеркалировано для удалённых машин. В `API.md` добавлено, что `URLTestOutbound.timeout` — в миллисекундах.
- **Импорт бэкапа: правленый шаблонный DNS-сервер остаётся одним сервером.** В LxBox шаблонный DNS-сервер теперь можно править; правка сохраняется своим сервером под тем же тегом. Импорт такого бэкапа больше не показывает сервер дважды и не снимает шаблонный сервер как «удалённый источником». Когда тег есть у обеих сторон, остаётся запись приёмника — шаблонная или правленая. Контракт 1.1.142.
- **TUN MTU по умолчанию 9000, как в sing-box.** Дефолт TUN MTU в шаблоне был 1492, теперь 9000 — собственный дефолт ядра, как у LxBox. Значение, заданное вами в Settings, остаётся как есть. Если UDP через узел WireGuard/AmneziaWG ведёт себя плохо, верните TUN MTU 1492 или меньше. Контракт 1.1.143.

### Ядро
- `sing-box-lx 1.14.4-lx.25` (было 1.14.3-lx.21), база — апстримный sing-box 1.14.4. Исправлено: узел masque `vhttp: auto` больше не держит в памяти предыдущий экземпляр ядра после каждой пересборки (Stop/Start, apply) — на роутере куча росла, пока GC за несколько дней не съедал оба ядра CPU, затронуты версии с `v1.14.0-lx.27`; старт ядра больше не ждёт 10–16 с чужой mux-handshake. Новое: `lxd` запускает скрипты администратора на границах жизненного цикла ядра (`pre_start`, `post_start`, `post_reload`, `post_stop` в `<state_dir>/hooks/`, по умолчанию выключено, `hooks.enabled` в `daemon.json`, только Unix); лаунчер ими не управляет. lx.23: пул `round_robin` больше не отправляет новые соединения узлу, провалившему последнюю пробу; остановка ядра с многими WireGuard/AmneziaWG-endpoint'ами снова быстрая; остановка, зависшая дольше 20 с, пишет дамп горутин в лог ядра. lx.24: проверка соединения силами ядра (дерево стадий с корневой причиной; лаунчер её пока не показывает). lx.25: аплинк XHTTP `packet-up` больше не ждёт ответа на каждый POST (скорость выгрузки одного потока не привязана к RTT), закрыты шесть мелких расхождений XHTTP с Xray (зависавшая запись `stream-up` после отказа сервера, слэш в пути, пул и keep-alive HTTP/2, заголовки Chrome по умолчанию, `%` в `path` буквально).
