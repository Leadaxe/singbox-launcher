# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- **Service window: the daemon updates itself, and tells the launcher what it runs on.** With a core that has `/admin/commands` (sing-box-lx with SPEC 127–129, after lx.15), the Service header gets a **Daemon command** row: pick a named command from the daemon's `daemon.json` (`update`, `check-update`, `restart`, …), see its text and last outcome, press **Run**, watch its log. `update` runs `sing-box lxd update` on the machine itself — download, checksum, swap, restart, rollback if the new core does not come up — and the window waits through the restart and reports `Updated lx.15 → lx.16`, `Already up to date`, or `rolled back`. The launcher never passes anything to a command: no arguments, no body. Without the key the row says `not available` and the new **Suggested commands** section gives a ready `"commands": {…}` fragment to paste into `daemon.json`. The daemon's passport now carries the machine's platform (`linux/arm64`, the release asset suffix) and init system (`procd`/`systemd`/…): the machine record is corrected from it (a wrong `amd64` picked by hand becomes `arm64`), **Download core** fetches the right asset, and the init selector disappears once the daemon names it. The former tabs became a **Troubleshooting** accordion under the header — one section open, the one the diagnosis picked (`✖ Not running — connection refused`, `⚠ Core — lx.15 is older than required lx.16`); a healthy daemon shows a short window with everything folded. A core version with an unknown suffix (`1.14.3-lx.15-test128`) is now "cannot compare" instead of a false "older than required".
- **Remote machines: is my config on the machine?** The machine row now shows it at a glance. An orange dot on **Deploy** (renamed from "Deploy config") means the config saved here differs from the one running on the machine (sha256 of the built `config.json` vs the daemon's active SHA, checked on every 5-second poll). A red dot on **Configure** means the last deploy did not start and the core rolled back to the last-good config. The ⓘ window also lists the local built-config sha256 next to the machine's active and last-good hashes.
- **Service window: keeping the daemon running, here and on every machine.** A new ⚙ next to ⓘ in a machine's row (and Servers → ⚙ → Local for this computer) opens one runbook with four tabs — **Not running** (status → restart → log → boot the last working config once → reinstall), **Core** (running vs required version; for a Linux machine: download the core for *its* platform into `~/Downloads`, checked against `SHA256SUMS`, stream it over ssh — `scp` does not work on OpenWrt — check it with the new binary, back up, swap, restart, roll back), **Pairing** (mint an invite on the machine, paste, Pair; who is trusted, revoke) and **Reference** (binary, service, state dir, `daemon.json`, last-good and log paths as the daemon reported them, or marked `default`; the `daemon.json` keys; a live log window). Every command uses the machine's own paths; ⧉ copies it, ▶ opens Terminal with `ssh <target> '…'`. The window opens on the tab that needs attention and its header turns green by itself once the daemon answers. The machine row gets a yellow dot on ⚙ and a `⚠ Core lx.11 is older than required (lx.14)` line (full versions such as `1.14.0-lx.30` vs `1.14.3-lx.15` when the upstream base differs) when its core is too old, a red dot and a `✖ …` line when the daemon does not answer. Deploy to an older core now warns first (**How to update** / **Deploy anyway**, with "Don't ask again for this version"). The machine's Edit window has an **SSH** field (`root@<host>` by default); the init system (procd/systemd) is picked in the Service header. Locally the Status/Install tabs became the same view plus **Uninstall**, and the service can now be restarted from the launcher. New guide: [TROUBLESHOOTING → Daemon](../TROUBLESHOOTING.md#daemon).
- **Remote nodes no longer show up on the Local tab.** After a Deploy (or any restart of a machine's core) while Local was open, the machine's node list landed in the Local list and stayed there under "core stopped". Each tab's list now writes only its own state and widgets. A stopped local core also no longer clears the node list of a connected machine on the Remote tab.
- **macOS install script:** the core download now shows a progress bar, like the launcher download (it used to run silently).
- **macOS app icon:** transparent rounded corners on macOS 11–15 (it showed white corners there; macOS 26 was unaffected).

### Technical / Internal
- SPEC 162: `lxdclient.InfoData` += `goos`, `goarch`, `platform`, `init_system`, `service`; new `lxdclient/commands.go` (`CommandsCtx`/`CommandCtx`/`RunCommandCtx`, 404 → `ErrCommandsUnsupported`, 409 → `ErrCommandRunning`); the machine registry caches the five passport fields and rewrites `goos`/`goarch`/`init_system` from them; `core.CommandsRecipe` builds the `daemon.json` fragment; the release asset is named by the passport's `platform` with the goos/goarch table as the fallback; `parseCoreBuild` accepts only `-rc<K>` after `lx.N`. The Service window is a `widget.Accordion` (`ui/service_commands.go` holds the command bar and the `update` state machine). Feature gating is by the daemon's answer, not by version; `RequiredCoreVersion` unchanged.
- **Core pinned to sing-box-lx 1.14.3-lx.15** (was 1.14.3-lx.14; base sing-box v1.14.3 unchanged). In the core: `urltest` probes every `interval` instead of every 2×`interval`; `failover` also leaves a node that answers but is more than 2× slower than the others; `fingerprint: random` / `randomized` no longer leave REALITY nodes on Xray ≥ v26.9.8 dead until a restart; each uTLS/REALITY connection holds 18–25 KB less memory after the handshake; `lxd --service=install` / `copy` no longer fail on a clean macOS where `/Library/PrivilegedHelperTools` is missing; gRPC updated for a critical advisory. Daemon stubs unchanged (`SYNC_REV` → tag commit 5195eb80).
- Debug API (SPEC 161): `/daemon/status` += `log_path`, `executable`, `listen`, `tls`, `uptime_seconds`, `passport_seen_at`, `passport_cached`, `reach_error`; `/daemon/commands` += `restart`, `client_list`; a machine entry += `ssh`, `init_system`, `core_warn_ack`, `passport` (`ssh` and `init_system` writable via `PATCH /remote/machines/{id}`); `/remote/machines/{id}/health` += `executable`, `log_path`, `listen`, `tls`, `uptime_seconds`, `core_required`, `core_outdated`.
- Core-version comparison and the service recipes (procd/systemd/launchd/SCM, ssh wrapping, error classification) are untagged pure functions in `core` (`core_build.go`, `service_recipes.go`), covered by one table test; the machine registry gains `ssh`, `init_system`, `core_warn_ack` and a cached `passport` (no migration, not part of LX Backup or the contract).

## RU
### Основное
- **Окно Service: демон обновляется сам и сообщает, на чём работает.** С ядром, у которого есть `/admin/commands` (sing-box-lx со SPEC 127–129, после lx.15), в шапке Service появляется строка **Daemon command**: выбрать именованную команду из `daemon.json` демона (`update`, `check-update`, `restart`, …), увидеть её текст и последний исход, нажать **Run**, смотреть лог. `update` выполняет `sing-box lxd update` на самой машине — скачивание, контрольная сумма, замена, перезапуск, откат, если новое ядро не поднялось, — а окно пережидает перезапуск и пишет `Updated lx.15 → lx.16`, `Already up to date` или `rolled back`. Лаунчер ничего не передаёт команде: ни аргументов, ни тела. Без ключа строка показывает `not available`, а новый раздел **Suggested commands** даёт готовый фрагмент `"commands": {…}` для вставки в `daemon.json`. Паспорт демона теперь несёт платформу машины (`linux/arm64`, суффикс релизного ассета) и init-систему (`procd`/`systemd`/…): запись машины исправляется по нему (выбранный руками `amd64` становится `arm64`), **Download core** качает нужный ассет, а селектор init исчезает, как только демон его назвал. Прежние вкладки стали аккордеоном **Troubleshooting** под шапкой — раскрыта одна секция, та, что выбрал диагноз (`✖ Not running — connection refused`, `⚠ Core — lx.15 is older than required lx.16`); у здорового демона окно короткое, всё свёрнуто. Версия ядра с неизвестным суффиксом (`1.14.3-lx.15-test128`) теперь «cannot compare», а не ложное «older than required».
- **Удалённые машины: доехал ли конфиг.** Строка машины теперь показывает это сразу. Оранжевая точка на **Отправить** (бывшее «Отправить конфиг»): сохранённый здесь конфиг не тот, что работает на машине (sha256 собранного `config.json` против active SHA демона, сверка на каждом опросе раз в 5 с). Красная точка на **Настроить**: последняя отправка не завелась, ядро откатилось на прежний удачный конфиг. В окне ⓘ рядом с хешами машины добавлен sha256 собранного здесь конфига.
- **Окно Service: обслуживание демона здесь и на каждой машине.** Новая ⚙ рядом с ⓘ в строке машины (и Servers → ⚙ → Local для этого компьютера) открывает один раннбук с четырьмя вкладками — **Not running** (статус → перезапуск → лог → один раз загрузить последний рабочий конфиг → переустановка), **Core** (работающая версия против требуемой; для Linux-машины: скачать ядро под *её* платформу в `~/Downloads` со сверкой с `SHA256SUMS`, залить потоком через ssh — `scp` на OpenWrt не работает, — проверить новым бинарём, бэкап, замена, перезапуск, откат), **Pairing** (выпустить приглашение на машине, вставить, Pair; кому доверяет демон, отзыв) и **Reference** (пути бинаря, службы, state dir, `daemon.json`, last-good и лога — как их сообщил демон или с пометкой `default`; ключи `daemon.json`; окно живого лога). Все команды — с путями самой машины; ⧉ копирует, ▶ открывает Терминал с `ssh <цель> '…'`. Окно открывается на вкладке, где есть что чинить, а шапка сама зеленеет, когда демон снова отвечает. В строке машины — жёлтая точка на ⚙ и строка `⚠ Core lx.11 is older than required (lx.14)` (при разной базе апстрима — полные версии, например `1.14.0-lx.30` против `1.14.3-lx.15`), когда ядро старее нужного, красная точка и строка `✖ …`, когда демон не отвечает. Deploy на старое ядро теперь сначала предупреждает (**How to update** / **Deploy anyway**, с «больше не спрашивать для этой версии»). В окне Edit машины — поле **SSH** (по умолчанию `root@<хост>`); init-система (procd/systemd) выбирается в шапке Service. Локально вкладки Status/Install стали тем же видом плюс **Uninstall**, а службу теперь можно перезапустить из лаунчера. Новый раздел: [TROUBLESHOOTING → Демон](../TROUBLESHOOTING.ru.md#демон).
- **Узлы удалённой машины больше не попадают на вкладку Local.** После Deploy (или любого перезапуска ядра машины) при открытой Local список узлов машины ложился в список своего ядра и висел там под «ядро остановлено». Теперь список каждой вкладки пишет только в своё состояние и свои виджеты. И остановленное своё ядро больше не чистит список подключённой машины на Remote.
- **Скрипт установки на macOS:** скачивание ядра теперь показывает прогресс, как и скачивание лаунчера (раньше шло молча).
- **Иконка приложения на macOS:** прозрачные скруглённые углы на macOS 11–15 (там были видны белые углы; на macOS 26 проблемы не было).

### Техническое / Внутреннее
- SPEC 162: `lxdclient.InfoData` += `goos`, `goarch`, `platform`, `init_system`, `service`; новый `lxdclient/commands.go` (`CommandsCtx`/`CommandCtx`/`RunCommandCtx`, 404 → `ErrCommandsUnsupported`, 409 → `ErrCommandRunning`); реестр машин кэширует пять полей паспорта и переписывает по ним `goos`/`goarch`/`init_system`; `core.CommandsRecipe` собирает фрагмент `daemon.json`; релизный ассет именуется по `platform` из паспорта, таблица goos/goarch — запасной путь; `parseCoreBuild` после `lx.N` принимает только `-rc<K>`. Окно Service — `widget.Accordion` (`ui/service_commands.go` — строка команд и машина состояний `update`). Фичи включаются по ответу демона, не по версии; `RequiredCoreVersion` не менялась.
- **Ядро — sing-box-lx 1.14.3-lx.15** (было 1.14.3-lx.14; база sing-box v1.14.3 та же). В ядре: `urltest` пробует каждый `interval`, а не раз в 2×`interval`; `failover` вдобавок уходит с узла, который отвечает, но больше чем вдвое медленнее остальных; `fingerprint: random` / `randomized` больше не оставляют узлы REALITY к Xray ≥ v26.9.8 мёртвыми до рестарта; каждое uTLS/REALITY-соединение держит после рукопожатия на 18–25 КБ меньше памяти; `lxd --service=install` / `copy` больше не падают на чистой macOS без `/Library/PrivilegedHelperTools`; gRPC обновлён по критической уязвимости. Стабы демона без изменений (`SYNC_REV` → коммит тега 5195eb80).
- Debug API (SPEC 161): `/daemon/status` += `log_path`, `executable`, `listen`, `tls`, `uptime_seconds`, `passport_seen_at`, `passport_cached`, `reach_error`; `/daemon/commands` += `restart`, `client_list`; запись машины += `ssh`, `init_system`, `core_warn_ack`, `passport` (`ssh` и `init_system` пишутся через `PATCH /remote/machines/{id}`); `/remote/machines/{id}/health` += `executable`, `log_path`, `listen`, `tls`, `uptime_seconds`, `core_required`, `core_outdated`.
- Сравнение версий ядра и рецепты службы (procd/systemd/launchd/SCM, ssh-обёртка, классификация ошибок связи) — нетегированные чистые функции в `core` (`core_build.go`, `service_recipes.go`) под одним табличным тестом; в реестре машин — `ssh`, `init_system`, `core_warn_ack` и кэш `passport` (без миграции, не входят ни в LX Backup, ни в контракт).
