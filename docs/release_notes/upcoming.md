# Upcoming release — черновик

Сюда складываем пункты, которые войдут в следующий релиз. Перед релизом переносим в `X-Y-Z.md` и очищаем этот файл.

## EN
### Highlights
- Node window: a node pasted or saved as Xray JSON (`protocol`, `settings`, `streamSettings`) is now accepted on the JSON tab and in the Origin field, and the node is rebuilt from it with Regen; before, the save was refused for a missing `type`. The source keeps its dialect: a sing-box document is stored as a document trimmed to its `outbounds`/`endpoints`, an Xray config — to its `outbounds`; everything else (`route`, `dns`, `routing`, `log`) is dropped with one message. Pasting the other dialect over a node switches the node's source kind instead of being rejected.
- Configurator and Traffic Profiler for Local and for a machine can be open side by side: one Configurator window per target (`Configure` on a machine no longer just raises the local window), and both window titles name the target — `Config Wizard — Local` / `— <machine>`, `Traffic Profiler — <target>`, which stays in the title while recording.
- Fix: the tailnet state directory of a machine no longer leaks into the local `config.json` after the machine's Configurator was opened — the path is now applied only to that machine's build.
- The JSON tab of a Tailscale node has a read-only field below the editor with what the build adds to the stored body, real values included: `disable_taildrop`, `state_directory`, `taildrop_directory`. The tab used to claim it showed exactly what reaches `config.json`.
- Taildrop settings now belong to the node and travel with its backup. If Taildrop is allowed on a node, clipboard and links from your own devices are accepted and received files go to Downloads by default; both can be turned off on the Settings tab of the node. Per-device permissions are gone, old settings are not migrated. Nodes of remote machines do not have these settings: their files are saved with the Save button in the node window.
- Double copy goes to one device chosen on the Settings tab of the node; nothing is sent until you choose it.
- A clipboard text or a link sent while acceptance is off no longer disappears silently: a notification names the device and where to turn it on.
- Renaming a Tailscale node no longer registers a new device: the state directory name is now a parameter of the node, and new nodes get a random one.
- Several tunnels, each for its own networks: a WireGuard, AWG, OpenVPN or OpenConnect node has a new switch **Only its own networks** on its Settings tab. With it on, only the networks the tunnel announces go into it — WireGuard allowed IPs, routes and domains pushed by an OpenVPN or OpenConnect server — and everything else follows your rules; the tunnel does not have to be chosen as a direction. The new preset **Tunnel routes** on the Rules tab does the work and can be dragged to set its priority. Nothing changes until the switch is turned on. A tunnel that announces the default route takes all traffic.
- Fix: a daemon service or a remote machine running a core older than the launcher's no longer rejects the whole config with `unknown field "quic_sniff_decoy"`. Settings the core does not know yet are left out of the config sent to it (the log names them), and **QUIC sniff decoy** now defaults to Off, as in the core: until you change a tunnel option in Settings, nothing about it is written to the config. If you relied on the decoy for MASQUE, Hysteria2 or TUIC behind a relay, turn it on in Wizard → Settings.

### Technical / Internal
- Contract 1.1.165: `origin.kind` is the dialect of the stored source — `singbox | xray | uri | wg_ini` (was `uri | wg_ini | json`), decided once by the registry (`source_kinds.json`) when the text comes in; stored text is never re-sniffed. The 1.1.87 rule «a node's source is only a sing-box body» is withdrawn: the source is kept whole in its dialect, documents trimmed to node arrays on save, arrays cut into records on input. Old `json` kinds are migrated on load by the registry (unrecognized → `singbox`), the source text is left as is. Corpus: `node_edit/*` (kinds, documents kept, two Xray cases), `backup/legacy_origin_kind_json` with the new `origin_kind` expectation.
- Contract 1.1.164: core `lx.33` turned `lx.quic_sniff_decoy` into an object and removed `lx.awg_masquerade`. Registry: `awg_masquerade` variable removed, new mobile-only `quic_sniff_decoy_send` / `quic_sniff_decoy_outbounds` / `quic_sniff_decoy_detours`; the launcher (core pin lx.30) keeps writing the mode as a string. `core_config.json` gains `forbidden: true`: such a key is dropped from the config for any core version, unknown included — set for `lx.awg_masquerade`.
- Contract 1.1.163: new `registry/core_config.json` (config keys outside node bodies with `min_core`: root `lx`, `lx.mtu_align`, `lx.quic_sniff_decoy`, `lx.awg_masquerade`); the build applies it for the target's core (installed core for Local, the machine's passport version for a remote), the daemon apply — for the service core. `quic_sniff_decoy` default is `off`; an empty root `lx` block is no longer emitted.

## RU
### Основное
- Окно узла: узел, вставленный или сохранённый как Xray JSON (`protocol`, `settings`, `streamSettings`), теперь принимается на вкладке JSON и в поле Origin и пересобирается из него по Regen; раньше сохранение отклонялось из-за отсутствия `type`. Источник хранится в своём диалекте: документ sing-box — документом, обрезанным до `outbounds`/`endpoints`, конфиг Xray — до `outbounds`; остальное (`route`, `dns`, `routing`, `log`) не сохраняется, об этом одно сообщение. Вставка другого диалекта поверх узла меняет вид его источника, а не отвергается.
- Конфигуратор и Профайлер трафика для Local и для машины можно держать открытыми одновременно: у каждой цели своё окно Конфигуратора (`Configure` у машины больше не поднимает локальное окно), а заголовки обоих окон называют цель — «Мастер конфигурации — Локально» / «— <машина>», «Профайлер трафика — <цель>», и во время записи тоже.
- Исправлено: каталог состояния tailnet машины больше не попадает в локальный `config.json` после открытия Конфигуратора машины — путь действует только в сборке этой машины.
- На вкладке JSON узла Tailscale под редактором появилось поле только для чтения: что сборка добавит к хранимому телу, с настоящими значениями — `disable_taildrop`, `state_directory`, `taildrop_directory`. Раньше вкладка утверждала, что показывает ровно то, что попадёт в `config.json`.
- Настройки Taildrop теперь принадлежат узлу и переносятся с его бэкапом. Если на узле разрешён Taildrop, буфер и ссылки от своих устройств принимаются, а файлы сохраняются в Downloads; обе настройки можно выключить на вкладке Settings узла. Разрешений по устройствам больше нет, старые настройки не переносятся. У узлов удалённых машин этих настроек нет: их файлы сохраняются кнопкой Save в окне узла.
- Двойное копирование уходит на одно устройство, выбранное на вкладке Settings узла; пока устройство не выбрано, ничего не отправляется.
- Текст для буфера или ссылка при выключенном приёме больше не пропадают молча: уведомление называет устройство и место, где включить приём.
- Переименование узла Tailscale больше не регистрирует новое устройство: имя каталога состояния стало параметром узла, у новых узлов оно случайное.
- Несколько туннелей, каждый для своих сетей: у узла WireGuard, AWG, OpenVPN и OpenConnect на вкладке Settings появился переключатель **Only its own networks**. С ним в туннель идут только сети, которые он объявляет, — allowed IPs у WireGuard, маршруты и домены, присланные сервером OpenVPN или OpenConnect, — а остальное идёт по вашим правилам; выбирать туннель Направлением не нужно. Работу делает новый пресет **Tunnel routes** на вкладке Rules, его приоритет задаётся перетаскиванием. Пока переключатель не включён, ничего не меняется. Туннель, объявляющий маршрут по умолчанию, забирает весь трафик.
- Исправлено: служба или удалённая машина с ядром старше ядра лаунчера больше не отвергает весь конфиг с ошибкой `unknown field "quic_sniff_decoy"`. Настройки, которых ядро ещё не знает, в отправляемый ему конфиг не попадают (лог называет их), а **QUIC sniff decoy** по умолчанию теперь Off, как в ядре: пока вы не меняли настройки туннелей в Settings, в конфиг о них ничего не пишется. Если обманка была нужна для MASQUE, Hysteria2 или TUIC за реле — включите её в Мастере → Settings.

### Техническое / Внутреннее
- Контракт 1.1.165: `origin.kind` — диалект хранимого источника, `singbox | xray | uri | wg_ini` (было `uri | wg_ini | json`); определяется один раз реестром (`source_kinds.json`) при входе текста, хранимый текст заново не нюхается. Норма 1.1.87 «источник узла — только sing-box тело» отменена: источник хранится целиком в своём диалекте, документы при сохранении обрезаются до узловых массивов, массивы на входе режутся на записи. Старый вид `json` мигрирует при загрузке по реестру (не опознано → `singbox`), текст источника не меняется. Корпус: `node_edit/*` (виды, документы целиком, два кейса Xray), `backup/legacy_origin_kind_json` с новым ожиданием `origin_kind`.
- Контракт 1.1.164: ядро `lx.33` сделало `lx.quic_sniff_decoy` объектом и удалило `lx.awg_masquerade`. Реестр: переменная `awg_masquerade` снята, новые только-mobile `quic_sniff_decoy_send` / `quic_sniff_decoy_outbounds` / `quic_sniff_decoy_detours`; лаунчер (пин ядра lx.30) пишет режим строкой, как прежде. В `core_config.json` появилось `forbidden: true`: такой ключ снимается из конфига при любой версии ядра, включая неизвестную — поставлено у `lx.awg_masquerade`.
- Контракт 1.1.163: новый `registry/core_config.json` (ключи конфига вне тел узлов с `min_core`: корневой `lx`, `lx.mtu_align`, `lx.quic_sniff_decoy`, `lx.awg_masquerade`); сборка применяет его под ядро цели (установленное ядро у Local, версия из паспорта у машины), apply службы — под ядро службы. Дефолт `quic_sniff_decoy` — `off`; пустой корневой блок `lx` в конфиг не пишется.
