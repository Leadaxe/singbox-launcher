# Release notes — v1.6.2

## EN
### Fixes
- **Core `sing-box-lx 1.14.1-lx.3`: REALITY nodes with the `firefox` and `safari` fingerprints connect to Xray 26.9.8+ servers.** Since v1.6.1 the launcher keeps the fingerprint the provider chose, and for `fp=firefox` that exposed a core limitation: such servers accept only a ClientHello carrying the post-quantum `X25519MLKEM768` key share, and the core's uTLS library had it only in the Chrome presets, so a `firefox` node was silently forwarded to the camouflage site (`reality verification failed`). The core's `firefox` fingerprint is now Firefox 148 and `safari` is Safari 26.3, both with that key share; verified on a provider node that failed before. The launcher no longer shows the "try `chrome`" hint on `firefox` and `safari` nodes; it stays on `ios`, `android`, `edge`, `360` and `qq`, whose presets still lack the key share. The core also stops a VLESS `encryption` handshake from hanging forever against a node that accepts the connection and then goes silent.

- **`awg://` links that wrap a whole `.conf` now import.** Some panels hand out AmneziaWG 3.x as `awg://<base64 of the whole [Interface]/[Peer] file>#name` instead of `key@host:port?…`. The launcher read the base64 as a host without a key and dropped the node, leaving an empty source. Such a link is now recognised (no `@` or `:` in the authority), decoded and converted the same way as a pasted `.conf`, so every AWG 2/3 field, the MTU clamp and key validation apply; the fragment becomes the node name.

- **The Traffic Profiler no longer floods the log while the core is stopped.** In classic mode its connection poller kept hitting the Clash API once a second from launcher start until the core came up, and after every stop, writing a `connection refused` warning each time. The poller now waits for a running core, warns once per outage and once more when the API is reachable again.

### Technical / Internal
- Contract: `reality_fp_not_chrome` is no longer raised for `firefox` and `safari` (registries `warnings.json`, `tls.json`; corpus `uri/vless/reality_fp_firefox_kept`, `reality_tcp_no_flow`, `grpc_reality_no_flow`); `protocols/wireguard.json` describes the base64 `.conf` form of `awg://` with corpus cases `uri/wireguard/awg_conf_base64*`; TASKS_LXBOX §20 for the phone side.

## RU
### Исправления
- **Ядро `sing-box-lx 1.14.1-lx.3`: REALITY-узлы с отпечатками `firefox` и `safari` подключаются к серверам Xray 26.9.8+.** С v1.6.1 лаунчер сохраняет отпечаток, который выбрал провайдер, и для `fp=firefox` это вскрыло ограничение ядра: такие серверы принимают только ClientHello с постквантовым key share `X25519MLKEM768`, а в uTLS-библиотеке ядра он был только у chrome-пресетов — узел с `firefox` молча уходил на камуфляжный сайт (`reality verification failed`). Теперь `firefox` в ядре — Firefox 148, `safari` — Safari 26.3, оба с этим key share; проверено на узле провайдера, который раньше не подключался. Подсказка «попробуйте `chrome`» на узлах `firefox` и `safari` больше не показывается; она остаётся у `ios`, `android`, `edge`, `360` и `qq`, чьи пресеты key share по-прежнему не несут. Заодно в ядре хендшейк `encryption` у VLESS больше не виснет бесконечно на узле, который принимает соединение и молчит.

- **Ссылки `awg://` с целым `.conf` внутри теперь импортируются.** Часть панелей раздаёт AmneziaWG 3.x как `awg://<base64 всего файла [Interface]/[Peer]>#имя` вместо `key@host:port?…`. Лаунчер видел в base64 хост без ключа и выбрасывал узел, источник оставался пустым. Такая ссылка распознаётся (в авторитете нет `@` и `:`), декодируется и конвертируется тем же путём, что вставленный `.conf`: все поля AWG 2/3, клэмп MTU и проверка ключей работают, фрагмент становится именем узла.

- **Traffic Profiler больше не засоряет лог при остановленном ядре.** В classic-режиме его опрос соединений стучался в Clash API раз в секунду с запуска лаунчера до старта ядра и после каждой остановки, каждый раз записывая предупреждение `connection refused`. Теперь опрос ждёт запущенное ядро, пишет одно предупреждение на сбой и одно при восстановлении.

### Техническое / Внутреннее
- Контракт: `reality_fp_not_chrome` больше не ставится на `firefox` и `safari` (реестры `warnings.json`, `tls.json`; корпус `uri/vless/reality_fp_firefox_kept`, `reality_tcp_no_flow`, `grpc_reality_no_flow`); `protocols/wireguard.json` описывает base64-форму `.conf` у `awg://` с кейсами `uri/wireguard/awg_conf_base64*`; TASKS_LXBOX §20 для телефона.
