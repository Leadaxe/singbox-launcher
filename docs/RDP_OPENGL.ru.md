# RDP / сервер без GPU — окно не появляется (OpenGL)

**🌐 Язык**: [English](RDP_OPENGL.md) | Русский

## Симптом

На Windows Server (или ВМ/сервере без GPU), обычно при работе через RDP:

- процесс запускается, иконка в трее появляется
- главное окно не открывается, «Открыть» из трея не помогает
- воспроизводится и в `mstsc.exe`, и в Windows App (issue [#105](https://github.com/Leadaxe/singbox-launcher/issues/105))

## Причина

UI лаунчера построен на Fyne (GLFW + OpenGL), которому нужен **OpenGL 2.1+**.
В RDP-сессии на машине без GPU (или без драйвера, отдающего GL в сессию)
Windows предоставляет только software-реализацию «GDI Generic» **OpenGL 1.1** —
контекст не создаётся, и окно молча не отрисовывается.

## Решение — автоматическое (с версии 1.4.2, переработано в 1.5.6)

До старта UI лаунчер проходит **гейт OpenGL**. Правило у него одно: *прошлый
старт дошёл до первого кадра — пробу не делаем; иначе — делаем.* Этот факт
хранится в `bin/gl-state.json`: `phase: starting` пишется перед инициализацией
GL, `phase: rendered` — через несколько секунд после того, как окно ожило.
Удаление этого файла — полный сброс всех решений гейта.

Mesa3D **никогда не ставится без явного «Yes»** — в том числе в архиве
`win64-full`, где DLL лежат в папке `mesa3d/` рядом с exe. В зависимости от
того, что увидел пробник, гейт показывает один из нативных диалогов (GDI —
они работают без OpenGL):

| Ситуация | Диалог | Что делает ответ |
|---|---|---|
| Проба не уложилась в 10 секунд | Retry / Ignore / Abort | Retry — проверить ещё раз; Ignore — стартовать на системном OpenGL, ничего не трогая; Abort — считать, что аппаратного OpenGL нет |
| Аппаратного OpenGL 2.1 нет, Mesa рядом нет | Yes / No | Yes ставит Mesa3D (из `mesa3d/`, либо скачивает ~24 МБ, если папки нет) |
| Рисуем через Mesa, прошлый старт умер, железо работает | Yes / No | Yes переименовывает DLL Mesa в `.off` и стартует на видеокарте |
| Прошлый старт умер под Mesa, и железо тоже не работает | OK | Только предупреждение: лаунчер стартует, но окно может остаться пустым |
| Mesa поставилась, но не прошла проверочную пробу | OK | Mesa отключается обратно, лаунчер стартует на системном OpenGL |

На машине без аппаратного OpenGL с исправной Mesa рядом с exe — то есть в
обычном случае RDP/ВМ без GPU, ради которого Mesa и существует, — гейт не
показывает ничего: отмечает в логе, что железа нет, оставляет Mesa и стартует.
Диалог «не работает ничего» появляется, только если старт под Mesa
действительно не дошёл до кадра.

Таймаут **не** трактуется как «OpenGL больше нет»: зависшая проба — обычно
временная икота драйвера, и именно приговор по таймауту ставил Mesa на машины
с исправной видеокартой.

С флагом `-tray` (старт в трей) гейт **не показывает ни одного диалога** и не
меняет ни одного файла — все решения уходят в лог.

### Проверка и пин драйвера

В ассете Mesa лежат все драйверы Gallium, и на машине с видеокартой Mesa по
умолчанию уходит в `d3d12` — то есть в тот самый GPU-стек, который только что
не ответил. Поэтому перед загрузкой Mesa лаунчер выставляет
`GALLIUM_DRIVER=llvmpipe` (только если вы не задали переменную сами) и
проверяет свежепоставленные DLL второй пробой, которая грузит `opengl32.dll` из
папки лаунчера по полному пути. Установка принимается, только если эта проба
вернула renderer с `llvmpipe`; иначе всё откатывается автоматически.

### Переключение потом

Каждый старт через Mesa пишет об этом строку уровня `WARN`. Если аппаратный
OpenGL появился позже, лаунчер один раз на каждый renderer предложит вернуться
на него (ответ «Позже» — и он молчит, пока строка renderer не изменится).

На вкладке **Диагностика** есть одна кнопка переключения рендерера при живом
UI: *Отключить Mesa3D (аппаратный OpenGL)* или *Включить Mesa3D (программный
рендеринг)* — в зависимости от того, что лежит рядом с exe. В обоих случаях
изменение применяется после перезапуска. Если переключать нечего, кнопки нет.

Скачивание идёт с релиза
[`mesa3d-26.2.0`](https://github.com/Leadaxe/singbox-launcher/releases/tag/mesa3d-26.2.0)
этого репозитория (зеркало [mesa-dist-win](https://github.com/pal1000/mesa-dist-win)),
при недоступности GitHub — через ghproxy-зеркало.

## Решение — вручную

Если автоустановка недоступна (нет интернета на сервере) — перенесите файлы сами:

1. Скачайте `mesa3d-26.2.0-win64.zip` из релиза
   [`mesa3d-26.2.0`](https://github.com/Leadaxe/singbox-launcher/releases/tag/mesa3d-26.2.0)
   (либо возьмите `x64/opengl32.dll`, `x64/libgallium_wgl.dll`, `x64/dxil.dll`
   из `mesa3d-<version>-release-msvc.7z` с
   [mesa-dist-win](https://github.com/pal1000/mesa-dist-win/releases)).
2. Распакуйте все DLL в папку рядом с `singbox-launcher.exe`.
3. Запустите лаунчер.

Порядок поиска DLL в Windows подхватит локальный `opengl32.dll` раньше
системного — Fyne увидит OpenGL 4.x (llvmpipe) и окно отрендерится.

## Откат / служебные переменные

- Штатно: кнопка на вкладке **Диагностика** или ответ «Yes» на предложение
  гейта вернуться на железо. И то, и другое переименовывает DLL Mesa в
  `opengl32.dll.off`, `libgallium_wgl.dll.off`, `dxil.dll.off` — переименование
  обратно включает Mesa снова, без скачивания.
- Вручную: удалить или переименовать эти DLL в папке лаунчера. Папку `mesa3d/`
  всё это не трогает.
- Удалить `bin/gl-state.json`, чтобы гейт забыл все решения (включая renderer,
  от которого вы отказались) и переспросил на следующем старте.
- `SINGBOX_LAUNCHER_NO_MESA=1` — полностью пропустить гейт.
- `GALLIUM_DRIVER=<драйвер>` — переопределить пин `llvmpipe` (например, `zink`
  или `d3d12`). Лаунчер выставляет переменную, только если она пустая.

Диагностика:

- строки с префиксом `gl:` в `logs/singbox-launcher.log` — что увидел пробник
  и какие решения принял гейт;
- `logs/native-stderr.log` — вывод самого нативного кода: Mesa, драйверов GPU,
  GLFW. Windows-сборка слинкована с `-H windowsgui`, у процесса нет stderr, и
  этот вывод раньше пропадал бесследно; теперь лаунчер уводит хендл в этот
  файл. `MESA_DEBUG=1` делает Mesa в нём многословной.

## Производительность

llvmpipe рендерит на CPU. Для UI лаунчера этого достаточно (кадр < 10 мс),
но CPU-нагрузка при открытом окне выше, чем с аппаратным GL. В трее
(окно скрыто) разницы нет.
