# Traffic Profiler — руководство пользователя

**🌐 Язык**: [English](TRAFFIC_PROFILER.md) | Русский

SPEC: [SPECS/059-F-N-TRAFFIC_PROFILER/SPEC.md](../SPECS/059-F-N-TRAFFIC_PROFILER/SPEC.md) ·
удалённые машины: [SPECS/099-F-C-REMOTE_TRAFFIC_PROFILER/SPEC.md](../SPECS/099-F-C-REMOTE_TRAFFIC_PROFILER/SPEC.md)

Traffic Profiler — живой диагностический инструмент: показывает, что ваши приложения на самом деле делают в сети, с кем разговаривают, через какой outbound и удалось ли соединение. Пригождается в ситуациях вроде «Slack работает, а Telegram мимо VPN» и для privacy-аудита закрытого приложения.

Это **отдельное окно**, открывается со вкладки Диагностика — не вкладка визарда, — чтобы держать его рядом с исследуемым приложением.

## Когда пригождается

- **«Почему X идёт мимо VPN?»** — открыть профайлер, начать запись по X, смотреть, какой outbound стоит рядом с каждым соединением.
- **«Почему Y не загружается?»** — включить Verbose logs, открыть Y в приложении, искать маркеры ⚠ DnsTimeout / ⚠ TcpRstEarly в соответствующих строках.
- **Privacy-аудит** — открыть вкладку Live без записи и смотреть, куда подключается каждый процесс на машине.
- **Выяснить, что приложению нужно в allow-list** — записать короткую сессию, посмотреть подвкладку Domains, скопировать список.

## Как открыть окно

Вкладка Диагностика → кнопка **Traffic Profiler**. На кнопке горит значок ⚡, пока активна сессия записи, даже если само окно закрыто (запись идёт в фоне, окно можно переоткрыть в любой момент).

Повторный клик фокусирует существующее окно, а не плодит дубликат.

## Откуда берутся данные

Профайлер сшивает два потока по connection ID. Какие именно — зависит от движка, которым управляется ядро:

| Движок | Соединения | DNS |
|---|---|---|
| **Classic** (по умолчанию) | поллер Clash API `/connections` | разбор хвоста лога sing-box — единственный доступный источник DNS, отсюда и тумблер Verbose ниже |
| **Daemon** (macOS, `sing-box lxd`) | gRPC `SubscribeConnections` | gRPC `SubscribeDNSQueries` — **структурный** стрим, DNS приходит полным без перевода ядра в debug |

Переключение автоматическое: при смене движка источники профайлера переустанавливаются, а прежняя подписка снимается. В daemon-режиме в конфиге нет Clash API вовсе, поэтому Clash-поллер не просто простаивает — он выключается, а не долбится в отсутствующий порт.

## Вкладка Live

Общесистемный поток всех DNS / TCP / UDP событий, которые видит sing-box. Новые события появляются сверху.

- Фильтр-чипы (DNS / DNS× / TCP / TCP· / UDP) прячут и показывают виды событий.
- Поиск ищет по домену, IP, пути процесса и имени процесса.
- В строке есть имя процесса, если sing-box смог его атрибутировать (`route.find_process: true` включён по умолчанию во встроенном шаблоне).

Если большинство строк без процесса — скорее всего, в вашем шаблоне детект процессов выключен; об этом говорит баннер внутри окна. Пройдите визард заново и сохраните: в новом шаблоне `route.find_process: true`.

## Запись по процессу

1. Перейдите на вкладку **Per-process** внутри окна.
2. Нажмите **Pick process & START** — диалог покажет запущенные процессы (те, что уже дают трафик, всплывают наверх).
3. Выберите цель; диалог закроется и начнётся запись. Кнопка сменится на **STOP**.

Подвкладки, появляющиеся во время записи:

| Подвкладка | Назначение |
|---|---|
| **Live** | Поток событий цели, новые сверху. События за 60 секунд до старта подтягиваются и помечаются 〽 («backfilled»). |
| **Domains** | Уникальные домены, отсортированные по суммарным байтам. В строке — число соединений, число IP, суммарные байты вверх/вниз. |
| **IPs** | Агрегированные IP назначения — полезно для «голых» TCP-соединений без SNI. |
| **Connections** | Таймлайн по соединениям с правилом и outbound'ом. |

Значок ⚠ означает, что хотя бы у одного соединения была диагностическая проблема (DnsTimeout или TcpRstEarly).

Нажатие **STOP** финализирует сессию. Она уезжает в кольцо «Saved sessions» (хранится последних 5, FIFO). Сохранённые сессии можно переоткрыть только на чтение или удалить.

## Тумблер Verbose logs

Слева вверху окна — чекбокс **Verbose logs (debug)**.

- ВКЛ: переводит `log.level` sing-box в `debug`, благодаря чему реконструкция DNS-цепочки (CNAME → A) становится полной. Расход батареи и CPU небольшой, но ненулевой — в тулбаре висит предупреждение.
- ВЫКЛ: возвращает `warn`.

**ВНИМАНИЕ**: смена уровня логов перезагружает sing-box. **Активные TCP/UDP-соединения рвутся** — открытые звонки, загрузки и выгрузки файлов сломаются. Тулбар показывает подтверждение перед применением.

Запись переживает перезагрузку — активная сессия продолжает захват в новом пространстве conn-id.

## Меню ⋮

- **Copy session JSON** — копирует текущую (или последнюю завершённую) сессию как JSON в буфер. Удобно вставить в bug-report.
- **Export session JSON…** — сохраняет в файл. Предлагаемое имя: `traffic-<process>-<timestamp>.json`.
- **Clear completed sessions** — стирает кольцо сохранённых сессий. Активная сохраняется.
- **Help / about** — короткая справка.

## Профайлер удалённой машины

У сопряжённой машины (роутер, VPS, другой Mac) **свой** профайлер: своё окно, свои стримы, свой кольцевой буфер. Открывается из блока **«Ещё»** в строке машины на вкладке **Удалённые** (**Ещё → Профайлер трафика**) и требует живого соединения — источник это её gRPC-стрим.

Повторное открытие фокусирует существующее окно, а не поднимает второй стрим; экземпляр гаснет вместе с каналом — при Disconnect и при удалении машины. Локальный профайлер при этом не трогается, поэтому роутер и свою машину можно смотреть рядом.

Два отличия от локального вида:

- **Нет разбивки по процессам.** Ось «процессы» заменена осью **клиентов сети** — трафик на роутере идёт от устройств, а не от процессов этого компьютера. `find_process` в конфиге роутера выключен по той же причине: атрибутировать нечего. Имена клиентов приходят из `GET /admin/clients-info` машины.
- **Нет фоллбэка на хвост лога.** Всё приходит по gRPC (соединения, DNS, статус плюс `GetRules` / `GetOutbounds` для расшифровки) — `sing-box.log` машины лежит на её файловой системе, а Clash API у её конфига нет by design.

> Медленный роутер поднимает не только вопрос о трафике. Окно **телеметрии хоста** (та же строка: CPU / память / хранилище / сеть самой машины) отвечает на вопрос «не задыхается ли коробка» — профайлер описывает ядро, телеметрия описывает машину. См. [DAEMON_AND_REMOTE.ru.md](DAEMON_AND_REMOTE.ru.md).

## Лимиты и жизнь только в памяти

- Одна активная запись за раз.
- До 5 завершённых сессий в FIFO-кольце.
- Каждая сессия ограничена 50 000 событиями или скользящим окном в 3 часа — что наступит раньше. Счётчик отброшенных событий виден в статус-строке.
- Сессии стираются при выходе из приложения — **персистентности нет**. Хотите сохранить сессию — экспортируйте её.

## Устранение проблем

| Симптом | Причина / что делать |
|---|---|
| Баннер «Sing-box is not running» | Сначала запустите sing-box со вкладки Локально. Профайлер продолжает захватывать то немногое, что приходит, но картина неполная. |
| У большинства событий нет процесса | В вашем конфиге выключен `route.find_process`. Пройдите визард заново и сохраните — в дефолтном шаблоне он включён. |
| Нет DNS-событий | Включите Verbose logs — в classic-режиме sing-box пишет DNS только на уровне debug. В daemon-режиме DNS приходит структурным gRPC-стримом, и тумблер не нужен. |
| Таймер в заголовке окна не тикает | Переоткройте окно. Горутина таймера останавливается при закрытии и запускается заново на Show. |
| «TCP RST early» на каждом соединении к домену | Скорее всего, файрвол или обрыв TLS-хендшейка на стороне назначения. Сравните с другим outbound'ом или прямым соединением. |
