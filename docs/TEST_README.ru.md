# Тесты singbox-launcher

**🌐 Язык**: [English](TEST_README.md) | Русский

Как устроен и как запускается тестовый набор проекта: около **1130 тестов в 197
файлах**. Перечислять их поимённо здесь бессмысленно — список устаревает быстрее,
чем документ; вместо этого описано, где что лежит и как запускать.

## Как запускать

### Централизованные скрипты (рекомендуется)

```bash
./build/test_linux.sh      # Linux
./build/test_darwin.sh     # macOS
build\test_windows.bat     # Windows
```

Скрипты **исключают GUI-пакеты** (`/ui/`, `fyne.io`), которым на headless-раннере
нужен OpenGL, настраивают окружение (CGO, PATH, GCC на Windows), пишут полный лог в
`temp/<platform>/` и печатают список пакетов перед запуском.

Параметры (одинаковы у всех трёх):

| Параметр | Действие |
|---|---|
| `nopause` / `silent` | не ждать нажатия клавиши в конце |
| `short` | только короткие тесты |
| `run TestName` | конкретный тест по имени |
| последний аргумент | путь к пакету (по умолчанию `./...`) |

```bash
./build/test_darwin.sh nopause ./core/config/subscription
./build/test_darwin.sh nopause run TestParseNode_VLESS ./core/config/subscription
```

### Напрямую через `go test`

```bash
go test ./core/... ./internal/... ./api/...     # без GUI-пакетов
go test ./core/config/subscription -v -run TestParseNode_VLESS
```

GUI-пакеты (`ui/...`) требуют `CGO_ENABLED=1` и компилятор C; на headless-машине они
падают на инициализации OpenGL — именно поэтому скрипты их исключают. Запускать их
локально имеет смысл только на машине с графическим окружением.

## Где что лежит

| Область | Файлов | Тестов | Что покрывает |
|---|---:|---:|---|
| `core/config/subscription` | 34 | ~240 | парсеры URI по протоколам, share-URI round-trip, классификация тела подписки, Xray JSON, sing-box JSON-импорт, дедупликация |
| `core/config` (весь, включая `subscription`) | 53 | ~335 | плюс генерация outbound'ов, идентичность узлов, контракт групп, эмиссия по схемам |
| `core/build` | 20 | ~141 | сборка конфига: резолверы DNS/route, раскрытие пресетов, sync outbound'ов, имена SRS |
| `core/state` | 13 | ~72 | схема состояния, загрузка v2–v6 и миграции, атомарное сохранение, адаптеры legacy↔canonical |
| `core/services` | 9 | ~48 | реестр удалённых машин, ресурсы для Deploy, транспорт прокси-операций, SRS-загрузчик |
| `core` (корень) | — | — | движки ядра (`CoreBackend`), даунлоадеры, rebuild из raw-кеша, refresh метаданных, интеграционные тесты |
| `internal` | 23 | ~79 | листовые утилиты: локали, профайлер трафика, платформенные хелперы, `wizardsync` |
| `ui` | 40 | ~181 | **исключены из скриптов** — бизнес-логика визарда, модели, форматирование строк машин |
| `api` | 3 | 4 | клиент Clash API |

Ключевые инварианты, за которыми следят тесты:

- **Эмиттер и парсер ходят парой.** Новая схема без ветки эмиссии молча урезает
  узел до `{tag,type,server,server_port}` — на каждую схему есть эмиссионный тест.
- **Round-trip share-URI.** Узел → `config.json` → share-URI → узел не должен
  терять поля; `ErrShareURINotSupported` для того, что в один URI не кодируется
  (селекторы, WireGuard с несколькими peer'ами, цепочки через `detour`).
- **Конфиг проходит `sing-box check`.** Там, где ядро доступно, сгенерированный
  конфиг валидируется настоящим ядром, а не только сравнением с эталоном.
- **Полнота локалей.** `TestAllKeysPresent` падает, если ключ есть в одном языке и
  отсутствует в другом.

## Требования

- **Go 1.25** или новее (`go.mod`). Legacy-сборка под Win7 отдельно пинит Go 1.20
  через `go.win7.mod` — её зависимости резолвятся иначе, см. `docs/BUILD_WINDOWS.ru.md`.
- Зависимости загружены (`go mod download`).
- Для GUI-пакетов — `CGO_ENABLED=1` и GCC (MinGW-w64 / TDM-GCC на Windows). Скрипт
  для Windows сам ищет GCC в стандартных местах (`C:\msys64\mingw64\bin`) и
  добавляет его в PATH.

## Примечания

- Тесты изолированы: временные файлы и каталоги создаются под `t.TempDir()`, общий
  временный каталог прогонов — `temp/<platform>/`, он чистится в начале запуска.
- Флаг `-count=1` в скриптах гарантирует запуск без кеша результатов.
- Сеть не нужна: интеграционные тесты (`core/integration_test.go`) работают на
  встроенных в код образцах подписок, а не на живых URL.
