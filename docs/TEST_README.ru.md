# Тесты singbox-launcher

**🌐 Язык**: [English](TEST_README.md) | Русский

Как устроен и как запускается тестовый набор проекта. Ни тесты, ни их количество
здесь не перечисляются: такой список устаревает быстрее самого документа — это
вступление само утверждало «около 1130 тестов в 197 файлах» и занизило цифру на
четверть за один цикл. Актуальное число считается на месте:

```sh
find . -name '*_test.go' | wc -l          # файлов с тестами
grep -rho '^func Test[A-Za-z0-9_]*' --include='*_test.go' . | wc -l   # тест-функций
```

Ниже — где что лежит и как запускать.

## Как запускать

### Централизованные скрипты (рекомендуется)

```bash
./build/test_linux.sh      # Linux
./build/test_darwin.sh     # macOS
build\test_windows.bat     # Windows
```

Скрипты **исключают GUI-пакеты** (`/ui/`, `fyne.io`), которым на headless-раннере
нужен OpenGL, настраивают окружение (CGO, PATH, GCC на Windows), пишут полный лог в
`temp/<platform>/` и печатают список пакетов перед запуском.

Параметры (одинаковы у всех трёх):

| Параметр | Действие |
|---|---|
| `nopause` / `silent` | не ждать нажатия клавиши в конце |
| `short` | только короткие тесты |
| `run TestName` | конкретный тест по имени |
| последний аргумент | путь к пакету (по умолчанию `./...`) |

```bash
./build/test_darwin.sh nopause ./core/config/subscription
./build/test_darwin.sh nopause run TestParseNode_VLESS ./core/config/subscription
```

### Напрямую через `go test`

```bash
go test ./core/... ./internal/... ./api/...     # без GUI-пакетов
go test ./core/config/subscription -v -run TestParseNode_VLESS
```

GUI-пакеты (`ui/...`) требуют `CGO_ENABLED=1` и компилятор C; на headless-машине они
падают на инициализации OpenGL — именно поэтому скрипты их исключают. Запускать их
локально имеет смысл только на машине с графическим окружением.

## Контрактный корпус (общий с LxBox)

В `contract/corpus/` лежат golden-фикстуры, которые гоняют **оба** приложения —
десктопный лаунчер (Go) и LxBox (Dart). Расхождение там означает ошибку движка, а
не разницу платформ: одна и та же подписка обязана давать одинаковые узлы с обеих
сторон. Состав и текущие размеры:

| Корпус | Фикстур | Что фиксирует |
|---|---:|---|
| `uri/` | 282 | share-URI → канонический узел, по протоколам |
| `template/` | 94 | язык шаблонов: `#if` / `#enable`, подстановка, `#on_change` |
| `direction/` | — | материализация Направлений (SPEC 104) |
| `dns/` | — | материализация DNS-сервера (SPEC 109) |
| `body/` | — | классификация тела подписки |
| `backup/` | — | roundtrip LX Backup |

Раннеры: `core/config/contract_test.go`, `core/config/contract_body_test.go`,
`core/config/contract_direction_test.go`, `core/template/contract_template_test.go`,
`core/build/contract_dns_test.go`, `core/backup/corpus_test.go`.

> **`-update` — это ревью диффа, а не рутина.** У каждого раннера есть флаг
> `-update`, перегенерирующий `expected` из текущего поведения. Перегенерация
> превращает изменение поведения в «тесты проходят» — поэтому артефакт ревью
> именно дифф: он показывает, что теперь обещает контракт. Не перегенерируйте,
> чтобы позеленить красный тест, не прочитав, что сдвинулось.

## Тесты-стражи

Три теста существуют, чтобы известный класс дрейфа не копился молча:

- `core/config/subscription/registry_sync_test.go` — каждый Go-код деградации
  обязан быть объявлен в `contract/registry/warnings.json`, а код, который нигде
  не ставится на узел, обязан быть `severity: error` (то есть узел отбрасывается,
  и помечать нечего).
- `core/template/walker_parity_test.go` — боевой обходчик собирает `config.json`,
  а корпусом проверяется канонический. Тест держит измеренный список расхождений и
  падает **в обе стороны**: появилось новое — движки разъехались дальше; исчезло
  старое — список протух.
- `core/build/outbound_graph_sanitize_test.go` — финальный проход по графу
  зависимостей. Новый вид ребра между outbound'ами добавляется в этот общий
  проход, а не четвёртой частной проверкой.

Ключевые инварианты, за которыми следят тесты:

- **Эмиттер и парсер ходят парой.** Новая схема без ветки эмиссии молча урезает
  узел до `{tag,type,server,server_port}` — на каждую схему есть эмиссионный тест.
- **Round-trip share-URI.** Узел → `config.json` → share-URI → узел не должен
  терять поля; `ErrShareURINotSupported` для того, что в один URI не кодируется
  (селекторы, WireGuard с несколькими peer'ами, цепочки через `detour`).
- **Конфиг проходит `sing-box check`.** Там, где ядро доступно, сгенерированный
  конфиг валидируется настоящим ядром, а не только сравнением с эталоном.
- **Полнота локалей.** `TestAllKeysPresent` падает, если ключ есть в одном языке и
  отсутствует в другом.
- **Один битый элемент деградирует в одиночку.** Висячая ссылка или кольцо
  зависимостей заставляют ядро отвергнуть *весь* конфиг, поэтому санитайзер сборки
  выбрасывает один элемент с warning — за этим следит
  `outbound_graph_sanitize_test.go`.

## Требования

- **Go 1.25** или новее (`go.mod`). Legacy-сборка под Win7 отдельно пинит Go 1.20
  через `go.win7.mod` — её зависимости резолвятся иначе, см. `docs/BUILD_WINDOWS.ru.md`.
- Зависимости загружены (`go mod download`).
- Для GUI-пакетов — `CGO_ENABLED=1` и GCC (MinGW-w64 / TDM-GCC на Windows). Скрипт
  для Windows сам ищет GCC в стандартных местах (`C:\msys64\mingw64\bin`) и
  добавляет его в PATH.

## Примечания

- Тесты изолированы: временные файлы и каталоги создаются под `t.TempDir()`, общий
  временный каталог прогонов — `temp/<platform>/`, он чистится в начале запуска.
- Флаг `-count=1` в скриптах гарантирует запуск без кеша результатов.
- Сеть не нужна: интеграционные тесты (`core/integration_test.go`) работают на
  встроенных в код образцах подписок, а не на живых URL.
