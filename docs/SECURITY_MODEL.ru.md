# Модель безопасности

English version: [SECURITY_MODEL.md](SECURITY_MODEL.md). Как сообщить об
уязвимости: [SECURITY.md](../SECURITY.md).

Документ описывает текущее состояние: что лаунчер защищает, от кого и по каким
правилам. История каждого решения лежит в спеках из [§12](#12-связанные-спеки).

## 1. Что защищаем и от кого

**Атакующий** — программа, которая работает под учётной записью пользователя с
обычными правами: вредоносное приложение, скрипт, скомпрометированная
зависимость. Она может писать во все файлы, доступные пользователю на запись, и
задавать окружение процессов, которые пользователь запускает.

**Граница** — переход от прав пользователя к более высоким: `root` на macOS и
Linux, администратор или `SYSTEM` на Windows. Такие права нужны лаунчеру для
одной задачи, интерфейса TUN, и для службы демона.

**Цель**: программа с правами пользователя не должна получить более высокие
права через лаунчер. Всё, что исполняется с высокими правами, не должно быть
файлом, путём или окружением, которые учётная запись пользователя может
изменить.

**Вне модели:**

- Атакующий, у которого уже есть `root` или права администратора.
- Атакующий с правами пользователя, которому нужны только данные самого
  пользователя: подписки, ключи узлов и `config.json` принадлежат этой учётной
  записи и читаются её программами.
- Физический доступ к машине.
- Анализ трафика и блокировка самих протоколов: это область ядра, см.
  [sing-box-lx](https://github.com/Leadaxe/sing-box-lx).

## 2. Где используются высокие права

| Платформа и режим | Кто запускает ядро | Что исполняется |
|---|---|---|
| Любая платформа, режим прокси без TUN | пользователь | ядро лаунчера из папки данных |
| macOS, classic с TUN | `root`, через системный запрос пароля | защищённая копия `/Library/PrivilegedHelperTools/sing-box-lxd` |
| macOS, служба демона | `root`, через launchd | та же защищённая копия |
| Windows x64/arm64, classic с TUN | администратор, через UAC | защищённая копия `<ProgramFiles>\sing-box-lxd\sing-box-lxd.exe` |
| Windows x64/arm64, служба демона | `LocalSystem` | та же защищённая копия |
| Windows 7 (`win7-32`) | администратор, всегда | ядро лаунчера из папки данных; защищённой копии в этой сборке нет |
| Linux с TUN | пользователь | ядро лаунчера с файловыми capabilities, выставленными через `setcap` |

Ядро лаунчера лежит в папке данных и принадлежит пользователю. Защищённую
копию делает само ядро (`lxd --service=copy` или `lxd --service=install`) в
месте, куда писать может только `root` или администратор.

## 3. Правила для привилегированного кода

Правила действуют на всех платформах. Правка, которая нарушает одно из них,
требует решения владельца, записанного в спеке.

1. **С высокими правами исполняются только защищённые файлы по абсолютным
   путям**: защищённая копия ядра и системные утилиты. Ничего из папки данных,
   бандла приложения или `PATH`.
2. **Окружение не наследуется.** Привилегированный процесс получает
   фиксированное окружение, а не окружение лаунчера.
3. **Текст для шелла из данных не собирается.** Команды передаются как argv.
   Там, где нужен шелл, его тело — константа в бинаре лаунчера, а пути приходят
   позиционными аргументами.
4. **Копия проверяется перед каждым привилегированным стартом**: цепочка
   владения пути и sha256 копии против ядра лаунчера. Если хэш не посчитался,
   старта нет.
5. **Привилегированный процесс не пишет по путям пользователя.** Его вывод
   идёт в защищённый каталог, лаунчер его только читает.
6. **По символическим ссылкам переход не выполняется.** Ссылка, другой тип
   файла или чужой владелец на месте ожидаемого файла или каталога — отказ.
7. **Привилегированный процесс проверяет свои права** до любых действий и
   отказывает с сообщением, которое их называет.
8. **Отказ называет причину**: звено цепочки, системную ошибку, команду
   исправления.
9. **Команды с `sudo` показываются, а не исполняются.** Пользователь запускает
   их в своём терминале и вводит пароль там.

### Правила для правки привилегированного кода

- Изменение того, что исполняется с высокими правами (argv, тело шелла,
  окружение, список утилит), принимается после живого старта с настоящими
  высокими правами на целевой платформе. Тесты без таких прав потерю прав не
  показывают: эффективный и реальный uid там равны
  ([#138](https://github.com/Leadaxe/singbox-launcher/issues/138), SPEC 151).
- Отчёт о реализации перечисляет, что запускалось вживую, а что нет.
- Новое место, где лаунчер собирает или исполняет команду, добавляется в
  таблицу аудита SPEC 137 §12.

## 4. macOS

### 4.1 Защищённая копия

| Что | Где | Владелец и права |
|---|---|---|
| Копия ядра | `/Library/PrivilegedHelperTools/sing-box-lxd` | `root:wheel 0755` |
| Запись установки | `/Library/PrivilegedHelperTools/sing-box-lxd.install.json` | `root:wheel 0644` |
| plist службы | `/Library/LaunchDaemons/com.leadaxe.sing-box-lxd.plist` | пишет команда установки ядра |
| Лог classic-ядра под `root` | `/Library/Logs/sing-box-lxd/classic.log` | каталог `root:wheel 0755`, файл принадлежит пользователю, `0600` |

**Цепочка владения**: `/Library` → `/Library/PrivilegedHelperTools` → копия.
Каждое звено читается через `Lstat` и должно быть: не символической ссылкой,
ожидаемого типа, с владельцем uid 0, без записи для группы и остальных.

### 4.2 Старт classic с TUN

Лаунчер спрашивает пароль через системный запрос, раз за сессию, и запускает:

```text
/usr/bin/env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin /bin/bash -p -c '<постоянное тело>'
  start-singbox-privileged <data>/bin <копия> config.json
  /Library/Logs/sing-box-lxd 0 <uid пользователя> 2097152 0
```

- `env -i` отрезает окружение лаунчера, включая `PATH` и функции bash,
  экспортированные через `BASH_FUNC_<имя>%%`.
- `-p` сохраняет эффективный uid. Системный запрос запускает инструмент с
  эффективным uid 0 и реальным uid пользователя; bash без `-p` сбросил бы
  права. Флаг также отключает импорт функций из окружения.
- Тело сначала проверяет, что работает под `root`, затем проверяет uid
  пользователя (цифры, не меньше 501, учётная запись существует), готовит лог
  и запускает копию.

Stop и Kill запускают `/bin/kill` и `/usr/bin/pkill` напрямую, без шелла.
Снятие TUN высоких прав не требует: остатки лаунчер удаляет своим uid.

Гейт перед запросом пароля выносит один из вердиктов: no core, missing,
unsafe, outdated, ok. При отказе гейта показывается диалог с командой
(`lxd --service=copy`, а при установленной службе `--service=install`), пароль
не запрашивается.

### 4.3 Служба демона

launchd запускает защищённую копию от `root`. Лаунчер проверяет службу без
`sudo` и показывает её состояние: не установлена, небезопасна, устарела, не
запущена, процесс устарел, в порядке. Небезопасная служба — громкое
предупреждение, а не блокировка: VPN работает, пока пользователь не выполнит
показанную команду.

## 5. Windows

### 5.1 Права

Сборка Windows x64/arm64 стартует с правами пользователя (`asInvoker`).
Высокие права запрашиваются через UAC для TUN и для команд службы. Сборка для
Windows 7 всегда работает от администратора.

### 5.2 Защищённые пути

| Что | Где |
|---|---|
| Копия ядра | `<ProgramFiles>\sing-box-lxd\sing-box-lxd.exe` с `libcronet.dll` и записью установки |
| Данные службы | `<ProgramData>\sing-box-lxd\state\` |
| Логи | `<ProgramData>\sing-box-lxd\logs\` (`lxd.log`, `classic.log`) |

**Проверка защиты пути:**

- Владелец — `SYSTEM` или `Administrators`; у родительских каталогов допустим
  ещё `TrustedInstaller`.
- Ни у какой другой учётной записи нет права записи, удаления или смены списка
  доступа.
- Reparse point и пустой список доступа — отказ.
- У копии проверяется каждый родительский каталог от корня тома, а том должен
  быть фиксированным диском NTFS. У лога проверяются только
  `<ProgramData>\sing-box-lxd` и `logs\`.

Копия также сверяется с ядром лаунчера по sha256, вместе с `libcronet.dll`.

### 5.3 Предупреждение вместо отказа

На Windows непройденная проверка защиты не оставляет пользователя без запуска.
Диалог показывает причину, риск, команду `icacls` и кнопку **Run anyway**. С
ней, до закрытия лаунчера:

- при непройденной проверке копии с правами администратора запускается ядро
  лаунчера из папки данных;
- при непройденной проверке лога вывод ядра идёт в собственный лог лаунчера.

Выбор хранится только в памяти. Принятые риски — в [§10](#10-принятые-риски).

## 6. Linux

Лаунчер ничего не запускает от `root`. Ядро работает от пользователя с
файловыми capabilities `cap_net_admin` и `cap_net_bind_service`. Лаунчер
проверяет их через `getcap` и, если их нет, показывает команду `sudo setcap`,
которую выполняет пользователь. Запись в файл снимает его capabilities, поэтому
подмена ядра высоких прав не даёт.

## 7. Канал демона и удалённые машины

| Предмет | Состояние |
|---|---|
| Локальный адрес | loopback, порт выбирает команда установки (19091 и выше) |
| Подлинность сервера | клиент сверяет SHA-256 сертификата сервера с закреплённым |
| Подлинность клиента | собственные ключ и сертификат ECDSA P-256; файл ключа `0600`, его каталог `0700` |
| Сопряжение | одноразовое приглашение `адрес#отпечаток#код`; код сгорает при первой регистрации |
| Права сопряжённого клиента | полное управление демоном: конфиг, старт и стоп, ресурсы |
| Отзыв | на самой машине: `sing-box lxd client remove`. Удаление машины в лаунчере стирает локальные ключи и доступ не отзывает |

Канал без TLS существует для демона на loopback; сетевой канал лаунчер сам до
него не понижает.

Подробности: [DAEMON_AND_REMOTE.ru.md](DAEMON_AND_REMOTE.ru.md).

## 8. Debug API

- По умолчанию выключен; запускается, только если включён в настройках и задан
  токен.
- Слушает только `127.0.0.1`. TLS и доступа из локальной сети нет; для
  удалённого доступа — SSH-туннель.
- Каждый запрос, кроме `GET /ping`, требует `Authorization: Bearer <токен>`.
  Токен — 32 случайных байта, сравнение за постоянное время.
- Токен даёт полное управление лаунчером: состояние, конфиг, старт и стоп,
  сопряжённые машины. Обращайтесь с ним как с паролем.

Подробности: [API.ru.md](API.ru.md).

## 9. Недоверенный ввод и скачивание

### 9.1 Подписки

Подписка — недоверенный ввод.

- Ответ ограничен 10 МБ и, по умолчанию, 3000 узлов.
- Поля узла проходят через реестр контракта: ключи вне схемы снимаются, `tag`
  и `type` задаёт сборка.
- Узел, чей `detour` сломал бы конфиг, выбрасывается.
- Тег становится именем каталога только после приведения к `[A-Za-z0-9._-]`.
- Ответ без единого годного узла не заменяет уже сохранённые узлы.

### 9.2 Скачивание

| Что | Источник | Проверка |
|---|---|---|
| Ядро | релиз GitHub `Leadaxe/sing-box-lx`, версия закреплена в лаунчере; при неудаче — зеркала `ghfast.top` и `gh-proxy.com` | HTTPS, статус, не HTML-страница, размер до 100 МБ; имена файлов из архива сводятся к базовому имени. Контрольной суммы и подписи нет |
| `wizard_template.json` | `raw.githubusercontent.com`, в релизной сборке закреплённый коммит | HTTPS, разбор и валидация шаблона |
| Наборы правил (SRS) | URL из шаблона или правил пользователя | только статус HTTPS |
| Локали | `raw.githubusercontent.com`, ветка | HTTPS, валидный JSON |
| `wintun.dll` | `www.wintun.net` | HTTPS |

Сам себя лаунчер не обновляет. Он проверяет последнюю версию и открывает
страницу релиза в браузере. У каждого релиза есть `checksums.txt`.

### 9.3 Что лаунчер отправляет

- Серверу подписки: `User-Agent` и, если не отключено, `X-Hwid`,
  `X-Device-OS`, `X-Ver-OS`, `X-Device-Model`. HWID — случайный UUID, из
  железа не выводится. Отправка отключается в настройках, для всех подписок
  или для одной.
- Телеметрии и аналитики нет.

### 9.4 Файлы пользователя

| Файл | Права |
|---|---|
| Ключи mTLS клиента демона | `0600`, каталог `0700` |
| Файл LX Backup | `0600` |
| `settings.json` (хранит токен Debug API), `state.json`, `config.json`, реестр удалённых машин | `0644` |

## 10. Принятые риски

Каждый пункт — записанное решение, а не недосмотр.

| Риск | Где записан |
|---|---|
| Ядро с высокими правами читает `config.json` пользователя и пишет по путям из него (кэш, `log.output`) | SPEC 137 §8 |
| Команды `copy` и `install` исполняют под `sudo` или UAC ядро лаунчера, файл пользователя. Пароль пользователь вводит в своём терминале, диалог показывает оба хэша | SPEC 137 §8, SPEC 136 |
| **Run anyway** на Windows исполняет файл или пишет в каталог, которые может подменить программа пользователя | SPEC 150 §4 |
| Скачанное ядро не сверяется с контрольной суммой | SPEC 072 |
| У Debug API нет TLS | [API.ru.md](API.ru.md) |
| Удаление машины в лаунчере не отзывает её доступ | [DAEMON_AND_REMOTE.ru.md](DAEMON_AND_REMOTE.ru.md) |
| В лог ядра под `root` попадает stderr ядра, включая фрагменты ошибок конфига. Файл `0600`, владелец — пользователь | SPEC 137 §8 |
