# Словарь терминов контракта

Одна строка на термин: что это и где раскрыто подробно. Общая картина —
`ARCHITECTURE.md`; словарь читать перед любым другим документом каталога; если слово из документов здесь не найдено —
это ошибка словаря, дописать.

## Стороны и артефакты

| Термин | Что это | Где подробно |
|---|---|---|
| **Контракт** | Этот каталог: данные и документы, общие для лаунчера (Go) и LxBox (Dart). Кода в нём нет, только правила и проверки к ним | `README.md` |
| **Лаунчер** | Десктопное приложение singbox-launcher (macOS, Windows, Linux) | — |
| **LxBox** | Мобильное приложение на Flutter/Dart, вторая сторона контракта | — |
| **Ядро** | sing-box в форке `sing-box-lx`, которому приложение отдаёт собранный `config.json`. Версия ядра, под которую написаны правила, — «пин» (`body.core` в реестре, `RequiredCoreVersion` в лаунчере) | `README.md` §Правила изменения |
| **Реестр** | Таблицы правил в `registry/*.json`: как читать ссылку или JSON каждой схемы, какие поля бывают в теле, что делать с мусором, какой код выдать. Исполняется движками обеих сторон | `README.md` §Структура файлов реестра |
| **Схема** | Протокол узла как он назван в ссылке: `vless`, `ss`, `wireguard`. У каждой схемы свой файл `registry/protocols/<схема>.json` («секция реестра»). Не путать с типом ядра: у shadowsocks схема `ss`, тип `shadowsocks` | `PARSING_PRINCIPLES.md` §1 |
| **Секция реестра** | Содержимое одного файла протокола; «секция схему опознала» = файл этого протокола взялся читать элемент | `MAPPER_ENGINE.md` §2 |
| **Корпус** | `corpus/`: набор кейсов «вход + ожидаемый результат», по которым раннеры обеих сторон проверяют, что дают одно и то же | `corpus/README.md` |
| **Кейс, фикстура** | Один файл входа корпуса (`.uri`, `.body`, `.backup.json`) плюс его `expected.json`. «Golden» — то же: эталон, с которым сравнивают | `corpus/README.md` |
| **Раннер** | Тест приложения, который прогоняет свой движок по корпусу и сравнивает с ожиданием. Живёт в приложении, не в контракте | `corpus/README.md`, `PARSING_PRINCIPLES.md` §7 |
| **Override** | Файл `<кейс>.expected.launcher.json` / `.expected.lxbox.json`: ожидание одной стороны там, где расхождение признано намеренным (by design) | `IDENTITY.md` §4a |
| **D-NNN** | Номер решения в `SPECS/103-F-O-LX_SHARED_CONTRACT/DECISIONS.md`. Ссылка на «почему», а не на норму | `README.md` §Правила изменения |
| **SPEC NNN** | Папка задачи лаунчера в `SPECS/`. В документах контракта — ссылка на историю, откуда норма пришла | `SPECS/README.md` |
| **TASKS_LXBOX** | Файл `TASKS_LXBOX.md`: параграфы-задания и уведомления для LxBox по каждой версии контракта | `TASKS_LXBOX.md` |

## Разбор источника

| Термин | Что это | Где подробно |
|---|---|---|
| **Источник** | Любой текст, из которого приложение достаёт узлы: ссылка, тело подписки, файл `.conf`, Xray-массив, `vpn://`-профиль, бэкап | `PARSING_PRINCIPLES.md` §0 |
| **Вид источника** | Чем оказался текст целиком: список ссылок, base64-обёртка, sing-box-конфиг, Xray-массив, INI, `vpn://`. Таблица — `registry/source_kinds.json`; вид говорит, как резать текст на элементы | `MAPPER_ENGINE.md` §1–§2 |
| **Элемент** | Один кусок источника, из которого получается один узел: строка списка, объект `outbounds[]`, секция INI | `MAPPER_ENGINE.md` §1 |
| **Оболочка, распаковщик (unwrap)** | Слой поверх текста, который надо снять до разбора: base64, `vpn://` (qCompress+base64). Распаковщик — код, вызываемый по имени из таблицы (`unwrap`), потому что формат предикатами не выразить | `registry/source_kinds.json`, `registry/containers.json` |
| **Контейнер** | Источник, несущий несколько узлов и общие для них данные (профиль `vpn://` с `dns1/dns2`, папка, подписка) | `registry/containers.json`, `BACKUP.md` §2 |
| **Движок (маппер-движок)** | Общий код, который исполняет реестр: читает элемент по таблице и собирает тело узла. Имён схем в нём нет, только примитивы таблиц | `MAPPER_ENGINE.md` |
| **Маппер** | Первая ступень конвейера: перевод диалекта источника (параметры ссылки, поля Xray) в канонические пути тела. Значения не проверяет | `PARSING_PRINCIPLES.md` §8, `MAPPER_ENGINE.md` |
| **Форма (form)** | Вариант записи одной схемы в одном виде источника: у vmess это JSON-в-base64 (`v2rayn`) и старая ссылка с userinfo (`legacy`). Форма выбирается предикатом `detect`; «ни одна форма не прочитала пейлоад» = `form_unrecognized` | `MAPPER_ENGINE.md` §2 |
| **Предикат detect** | Условие из таблицы, по которому выбирают вид источника, секцию и форму: префикс, регекс, наличие ключа JSON, первая секция INI | `MAPPER_ENGINE.md` §2, `schema/registry_mapper.schema.json` |
| **Пространство источников** | Все места, откуда запись таблицы может взять значение: `query.sni`, `userinfo`, `json.$base.users.0.id`, `ini.Interface.MTU`, `context.profile.dns1`. Запись говорит `source`, движок читает | `MAPPER_ENGINE.md` §4 |
| **Запись (маппера)** | Одна строка таблицы `mappers.<вид>.params`: откуда взять (`source`), куда положить (`maps_to`), как привести и что делать с негодным | `MAPPER_ENGINE.md` §7 |
| **context.\*** | Значения, которые распаковщик контейнера знает о тексте, но которых в самом тексте нет (`last_config.mtu` рядом с `.conf` Amnezia). Применяются один раз при распаковке к тексту | `MAPPER_ENGINE.md` §4, `BACKUP.md` §Происхождение из контейнера |
| **Санитайзер** | Вторая ступень конвейера: проверка тела по секции `body` реестра (тип, формат, связи полей), каждое снятие или приведение — с кодом | `PARSING_PRINCIPLES.md` §8, `README.md` §Атрибуты поля |
| **Эмиттер, эмит** | Обратный ход: из тела узла собрать share-ссылку или JSON для ядра. Идёт по тем же записям маппера | `MAPPER_ENGINE.md` §9 |
| **Конвейер** | Маппер → санитайзер → эмиттер, одинаково для любого входа | `PARSING_PRINCIPLES.md` §8 |

## Результат разбора и узел

| Термин | Что это | Где подробно |
|---|---|---|
| **Результат разбора** | Выход разбора одного источника: `nodes[]`, `dropped[]`, `meta`. Форма нормативна, корпус сверяет побайтно. Прежнее имя в старых текстах — «конверт» | `PARSING_PRINCIPLES.md` §0–§1 |
| **Узел** | Одна запись `nodes[]`: `{kind, scheme, label, entry, chain?, warnings?}` | `PARSING_PRINCIPLES.md` §0 |
| **Тело, entry, body** | Объект outbound/endpoint sing-box без тега — то, что уедет в конфиг ядра. «Тело» и `body` в состоянии, `entry` в результате разбора — одно и то же | `PARSING_PRINCIPLES.md` §2, `ONE_NAMESPACE.md` |
| **Канонизация, канонический узел** | Приведение тела к единственной записи (ключи отсортированы, числа числами, дефолты выброшены, тег и detour вынесены). Без неё два одинаковых сервера были бы разными байтами | `PARSING_PRINCIPLES.md` §0, §2 |
| **Метка (label)** | Имя узла, как его дал автор источника, до префиксов и уникализации приложения | `PARSING_PRINCIPLES.md` §0 |
| **Тег** | Имя узла внутри приложения и в конфиге ядра. Сырой тег = метка; финальный тег = после политики контейнера и уникализации. Идентичность узла — сырой тег в рамках источника | `IDENTITY.md` §1, `NODE_LINK.md` §3 |
| **Идентичность (identity)** | То, по чему узел считается «тем же» при обновлении подписки и слиянии бэкапа: сырой тег, уникализированный внутри источника. Содержимое узла в неё не входит | `IDENTITY.md` |
| **NodeLink** | Ссылка на узел в форме `{folder_id, tag}`: id контейнера плюс сырой тег. Единственная допустимая форма ссылки «через кого» во всех проектах | `NODE_LINK.md` |
| **Деградация** | Что делать с мусором: битое значение чинится или снимается с кодом, узел живёт; битый узел уходит в `dropped[]`, подписка живёт | `PARSING_PRINCIPLES.md` §4 |
| **Код (warning)** | Машинное имя события из `registry/warnings.json`: `wgconf_dns_ignored`, `form_unrecognized`. Тексты на двух языках лежат там же, приложения своих не держат | `PARSING_PRINCIPLES.md` §6 |
| **Отбраковка (dropped)** | Запись `{ref, index, code, reason}` об элементе, который распознали и отвергли целиком. `reason` — свободный текст стороны, не сравнивается | `PARSING_PRINCIPLES.md` §4.1 |
| **Origin (происхождение)** | `{kind, raw}` у узла в состоянии и бэкапе: чем узел был до разбора, байт в байт. Из него узел пересобирается (Regen). Виды: `uri`, `wg_ini`, `json` | `BACKUP.md` §2 |
| **Regen** | Пересборка тела узла из `origin.raw` по текущим правилам реестра. Требует, чтобы origin был самодостаточен | `BACKUP.md` §Происхождение из контейнера |
| **Секции узла (sections)** | Правила маршрута и DNS, которые узел носит с собой и которые сборка дописывает к общим спискам (Tailscale, WireGuard с подсетями) | `NODE_SECTIONS.md` |
| **Группа** | Узел вида `selector`/`urltest`, члены — другие узлы. В результате разбора `kind: group`, в состоянии `kind: auto` | `PARSING_PRINCIPLES.md` §5 |
| **Цепочка (chain), detour** | Через какие узлы ходит узел: ближний хоп первым. В теле не живёт, вынесена в `chain[]` | `PARSING_PRINCIPLES.md` §2, `BACKUP.md` §4 |
| **Core-rejected** | Узел, который ядро отвергло при старте конфига: приложение выключает его и записывает причину кодом `core_rejected` | `PARSING_PRINCIPLES.md` §9 |
| **Гейт** | Проверка при сборке конфига, а не при разборе: годно ли поле или узел для текущего ядра и платформы (`min_core`, `platform`, `build_tag`) | `README.md` §Атрибуты поля |

## Состояние, бэкап, шаблон

| Термин | Что это | Где подробно |
|---|---|---|
| **Состояние (state)** | Всё, что приложение хранит: источники, узлы, правила, DNS, переменные. У лаунчера `state.json` | `ONE_NAMESPACE.md` |
| **Бэкап (LX Backup)** | Файл переноса настроек между приложениями = сериализация состояния в общей схеме. Импорт — слияние по идентичности, не замена | `BACKUP_PRINCIPLES.md`, `BACKUP.md` |
| **Одно пространство имён** | Правило: запись любой сущности = метаданные приложения + `body` (объект sing-box как есть), одинаково в состоянии обеих сторон и в бэкапе | `ONE_NAMESPACE.md` |
| **Направление** | Сущность LxBox: куда ходит трафик приложения или канала. В бэкапе едет своей формой | `BACKUP.md` §2, `NODE_LINK.md` §8 |
| **Свёртка (replace)** | Настройка папки или подписки `replace {mode, tag, auto?}`: источник отдаёт Направлениям одну группу-замену (`manual` — selector, `auto` — urltest, `both` — selector с двойником `<tag>-auto`) вместо своих узлов. Прежняя форма `fold` + `fold_tag` с контракта 1.1.79 не читается (неизвестные ключи) | `BACKUP.md` §2 «`replace` — свёртка источника» |
| **Шаблон** | JSON с плейсхолдерами `"@var"` и условиями `#if`, из которого сборка делает `config.json` | `TEMPLATE_LANG.md` |
| **Переменная (var)** | Объявленная в шаблоне настройка с типом и значением по умолчанию; подставляется вместо `"@имя"` | `TEMPLATE_LANG.md` §2–§3 |
| **Пресет** | Набор правил, DNS-серверов и (на десктопе) outbound'ов, включаемый одной галочкой; теги пресета живут в своём пространстве `<preset_id>:<tag>` | `TEMPLATE_LANG.md` §6 |
| **Dropped-каскад** | Правило шаблона: пустая переменная убирает ключ, пустой объект убирает родителя, и так до уровня, где что-то осталось | `TEMPLATE_LANG.md` §5 |
| **Расширение (extension)** | Пометка, что схема, поле или конструкция есть только у одной стороны (`desktop`/`mobile`). Вторая сторона обязана молча пропускать | `README.md` §Правила изменения п.3, `TEMPLATE_LANG.md` |
