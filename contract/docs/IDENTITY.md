# IDENTITY — идентичность нод

Нормативно. **SPEC 112 (контракт 0.10.0) сменил модель идентичности.**
Прежний identity-хеш (sha256 от эмитированного JSON, SPEC 094 D / SPEC 101)
упразднён; идентичность узла — его **тег**.

> **Зеркальная правка LxBox выполнена 02.09.2026** (device-verified, см.
> «Статус зеркала»). Процесс был как у chains/0.7.1: сторона Dart реализовала
> ту же модель и то же правило миграции. Перенос disabled-отметок между
> приложениями работает — с оговоркой про безымянные узлы (§4).

## 1. Идентичность = тег в рамках источника

```
identity = uniquify_within_source( raw_provider_tag )
```

- `raw_provider_tag` — тег, как его отдал провайдер (remarks / `#`-фрагмент
  URI / `tag` импортированного sing-box-объекта), **до** применения
  tag_prefix / tag_postfix / tag_mask источника;
- `uniquify_within_source` — тот же алгоритм, что для конфиговых тегов:
  первый `X`, следующий `X-2`, затем `X-3`; порядок — порядок разбора;
  счётчик **свой на источник** (конфиговые теги уникальны глобально,
  идентичность — только внутри источника);
- узлы-группы (`selector` / `urltest`, `kind: group`) идентичности **не
  имеют**: цепляться через группу — задача detour-по-тегу, а отметок
  выключения у групп нет;
- узел без имени идентичности не имеет — пустая строка = «идентичности нет».
  Пустую строку нельзя трактовать как общий ключ: иначе все безымянные ноды
  схлопнулись бы в одну отметку.

**Содержимое узла в идентичность не входит.** Server, port, credential, SNI,
транспорт, reality, mtu — ничто из этого её не меняет.

Реализация Go: `core/config/node_hash.go` (`NodeIdentity`),
стемпинг — `core/config/subscription/source_loader.go` (`StampNodeIdentity`).
Реализация Dart: **выполнена 02.09.2026** (см. «Статус зеркала»).

### 1.1 Почему тег, а не содержимое

- **Тег — имя, которым провайдер управляет узлом.** Провайдер вправе поменять
  сервер под тем же именем: ротация IP, смена группы, обход белых списков.
  Это ТОТ ЖЕ узел, и пользовательская отметка обязана за ним следовать.
  Контент-хеш считал такую ротацию появлением нового узла и молча снимал
  отметку.
- **Контент-хеш зависел от эмиттера и от формы хранения.** Один и тот же узел,
  записанный как `uri` и как `config_json`, давал разные хеши. Из-за этого
  detour-ссылка на узел протухала сама собой, и зависимый источник fail-closed
  выпадал из конфига целиком. Класс багов снимается только сносом хеша.
- **Правка эмиттера меняла все хеши разом.** Каждое расхождение из §3
  приходилось закрывать как инцидент миграции отметок; с тегом эмиттер и
  идентичность развязаны.

### 1.2 Что модель НЕ даёт (честные ограничения)

- **Переименование узла провайдером отметку теряет** — имя и есть
  идентичность. Отметка не переезжает молча на чужой узел: она остаётся в
  карте и исчезает по штатному TTL (§5). Прежняя модель это переживала, но
  ценой ложных срабатываний при ротации сервера — обмен сознательный.
- **Дедуп идентичностью не занимается.** Контент-хеш упразднён из
  ИДЕНТИЧНОСТИ, но дедуп записей есть — как **parse-слой** (амендмент
  0.10.0, SPEC 112-B — версия не поднимается: 0.10.0 ещё не выпущен).
  Подпись — полная эмиссия записи без tag/detour (тот же алгоритм, что
  упразднённый identity-хеш; в Go живёт как `LegacyNodeIdentityHash`):
  схлопывается только байтовый повтор, различающийся подписью после `#`.

  Вердикт пользователя (уточнение 26.08): **разные SNI или транспорты
  одного сервера с одним креденшлом — разные записи** (разные соединения и
  разные схемы обхода блокировок). Первая редакция амендмента дедупила по
  ключу подключения `scheme|server|port|credential` и склеивала такие
  пары — отменено, семантика возвращена к v1.5.1.

  Уточнение D-086 (02.09.2026, обе стороны): подпись — эмиссия узла без тега
  и без detour **плюс идентичность пути дозвона** (подпись релея, рекурсивно
  по хопам). Схлопываются только байтовые дубли с ОДИНАКОВЫМ путём дозвона:
  BYPASS-запись — другой маршрут, а не резерв, и её потеря молчалива именно
  там, где прямой путь зарезан (кейс Liberty, хотфикс v1.5.3). LxBox
  расширяет до этого правила свой ключ P4 (`protocol|server|port|credential`).

  Подпись живёт ОДИН разбор источника, в состояние не пишется, на отметки,
  ссылки и идентичность не влияет; выживает ПЕРВАЯ запись. Запись без
  подписи (группа, несостоявшаяся эмиссия) не схлопывается никогда.
  Зависимость от эмиттера здесь безвредна: обе копии эмитятся одним кодом
  из одной формы в пределах одного тела.

  Реализация Go: `core/config/subscription/server_conn_key.go`
  (`dedupSignature`), точка применения — `LoadNodesFromSource`, **до**
  простановки тегов; тот же дедуп у превью источника
  (`DedupParsedNodes`).

- **Уникализация остаётся единственным механизмом для ИМЁН.** «Тот же сервер
  под двумя именами, но с разными кредами» — это два узла, у каждого своя
  отметка.

## 2. Использования

Отметки выключения (§5), принадлежность узла источнику, ссылка detour на
конкретный узел (объект «источник + identity-тег» — см. §2.1).

Разбор источника держит два внутренних механизма: дедуп записей — по подписи
содержимого (§1.2), и «кто из элементов Xray-массива вправе выпустить этот
сервер» — по ключу подключения `scheme|server|port|credential`. Оба решают
задачу ВНУТРИ разбора, к идентичности отношения не имеют и в состояние не
выходят.

### 2.1 Ссылка detour на узел

Ссылка на конкретный узел — **объект из двух частей** (амендмент 0.10.0,
SPEC 112-A):

| Поле | Значение |
|---|---|
| `detour_node_source_id` | id источника-цели (в бэкапе — `subscriptions[].id` / `servers[].id` / `chains[].id`, контракт 0.11.0) |
| `detour_node_tag` | **identity-тег** узла ВНУТРИ этого источника (§1) |
| `detour_node_label` | подпись для UI, в резолве не участвует |

Финальный конфиговый тег в состоянии **не хранится**: он производная от
`tag_prefix` / `tag_postfix` / `tag_mask` источника-цели и от глобальной
уникализации, то есть меняется от правок, к самому узлу отношения не имеющих.
Хранимый тег был бы кэшем, протухающим от смены префикса или переименования
источника — ровно тем же классом багов, из-за которого до 0.10.0 протухал
контент-хеш. Финальный тег **вычисляется на каждой сборке**.

**Двухпроходность — инвариант сборки.** Проход 1: все узлы всех источников
получают финальный тег (prefix/mask/uniquify); ни одна ссылка не резолвится
(источник-цель вправе стоять в списке ниже ссылающегося). Проход 2: строится
единая карта «источник + identity-тег → узел», и только по ней материализуются
ссылки. Любой новый вид ссылки на узел обязан ходить через ту же карту.

**Резолв строгий.** Ссылка жива, только если сошлись ОБЕ части: источник
найден по id И узел с таким identity-тегом в нём есть. Расхождение не лечится
подстановкой узла с другим именем — узел под другим именем это другой узел, а
подставить его значило бы пустить трафик источника через хоп, которого
пользователь не выбирал. Смену идентичности (переименование тега узла у
сервера/цепочки) отрабатывает UI: операция сбрасывает все ссылки на прежнее имя
и сообщает пользователю список затронутых источников.

Пустой `detour_node_source_id` при непустом `detour_node_tag` — переходная
форма (состояния между 0.10.0-dev и амендментом, плюс результат
label-fallback §5.2): тег трактуется как ФИНАЛЬНЫЙ и ищется глобально.

Семантика fail-closed сохраняется: ссылка не разрешилась → зависимый источник
выбрасывается из конфига с warning (не direct). Текст предупреждения обязан
называть обе стороны человеческими именами — источник-цель и зависимый
источник по подписи (при её отсутствии — по тегу узла или URL), узел по тегу.
Хеши и id в текст не выносятся, кроме случая, когда другого имени нет
(источник удалён — от него остался только id).

## 3. Каноническая эмиссия (было §3 «расхождения хеша»)

Расхождения, закрытые в фазе 1, остаются нормативными — но теперь как
требования к **эмиссии**, а не к хешу: на побайтовой эмиссии держится общий
корпус `corpus/uri/**`.

| Класс | Причина | Решение |
|---|---|---|
| строки с `<>&` (и ` /29`) | Go HTML/юникод-escaping | Go → без escaping (D-007) ✅ |
| ws `?ed=N` без `eh` | Dart не эмитил `early_data_header_name` | Dart добавил дефолт `Sec-WebSocket-Protocol` (D-008) ✅ |
| anytls без `fp=` | Go не эмитил utls | Go добавил дефолт `random` по vless-конвенции (D-009) ✅ |
| wireguard | Go эмитил `name`/`system` | Go убрал дефолтные поля (D-010) ✅ |

### 3.1 Защита от возврата

- Go: `core/config/identity_contract_test.go` — `TestIdentityNoHTMLEscaping`,
  `TestIdentityWSEarlyDataHeaderPresent`, `TestIdentityWireGuardNoDefaultFields`,
  плюс инварианты §1 (идентичность = тег, содержимое её не меняет, разные
  имена различимы, уникализация внутри источника).
- Общий корпус `corpus/uri/**` прогоняется обеими сторонами: расхождение
  эмиссии проявится как разъехавшийся `expected`.

## 4. By-design различие: nodeIdentityKey (только LxBox)

Dart использует строковый ключ `protocol|server|port|credential` (без
транспорта и TLS) для СВОЕГО дедупа: ноды одного сервера с разными SNI
схлопываются на мобиле и НЕ схлопываются на десктопе. Различие
**сохраняется** (вердикт пользователя 26.08: разные SNI/транспорты = разные
схемы обхода, launcher их держит раздельно; подпись дедупа — полная
эмиссия, §1.2). Промежуточная редакция амендмента 0.10.0, объявлявшая
различие схлопнувшимся, отменена в тот же день — per-app override'ы корпуса,
поставленные из-за разного дедупа, остаются в силе.

На переносимость disabled-отметок дедуп не влиял и не влияет — они по
идентичности (§1), а дедуп её не трогает.

Второе by-design различие (зафиксировано 02.09.2026, класс A — расхождение
СОХРАНЯЕТСЯ): **у LxBox безымянных узлов не бывает.** Его парсер синтезирует
тег `<scheme>-<host>-<port>` — и для URI без `#`-фрагмента, и для пустого `tag`
в JSON-теле; такие узлы имеют идентичность и выключаются поштучно. У лаунчера
безымянный узел подписки получает тег по СВОЕМУ правилу, поэтому отметки
выключения безымянных узлов между сторонами не переносятся. Именованных узлов
различие не касается: там идентичность — сырой тег провайдера (§1), одинаковый
у обеих сторон.

## 4a. Законные per-app override'ы корпуса

`corpus/README.md` требует, чтобы каждый `<case>.expected.lxbox.json` ссылался
на задокументированное различие. Аудит 25.08 (контракт 0.8.0) оставил три
класса.

**A. Warning есть у Dart, у Go запланирован** — `tls_insecure` (10 кейсов),
`ech_ignored` (3), `utls_fp_unknown` (1), `vision_with_transport` (2).

**B. Desktop-only поля entry** — `ssh` `client_version` и `private_key_path`
(2 кейса), `"ext": "desktop"` в `registry/protocols/ssh.json`.

**C. Алиас схемы `socks5` у Go** — `socks` (6 кейсов). Канон требует `socks`;
Go сохраняет алиас, которым пришла ссылка, потому что дефолтный тег узла
строится из схемы (`node_parser_core.go`), и канонизация переименовала бы
`socks5-host-1080` → `socks-host-1080`. С SPEC 112 цена такого переименования
ВЫРОСЛА: тег теперь и есть идентичность, так что канонизация сбросила бы
отметки выключения и порвала ссылки detour у всех безымянных socks-узлов.
Override остаётся, причина — та же, аргумент стал сильнее.

## 5. Disabled-отметки

- Ключ — идентичность (§1); значение — lastSeen.
- Форматы значений в хранилищах приложений различны (Go unix int64,
  Dart ISO-8601) — **в обменном формате бэкапа всегда unix seconds** (D-014).
- TTL общий: `clamp(3 × interval_hours, 24h, 720h)`; interval ≤ 0 → 24h.
- lastSeen продлевается, когда идентичность встречена в свежем теле;
  GC — только после успешного сетевого обновления.

### 5.1 Миграция ключей (SPEC 112)

Обязательна для обеих сторон.

1. Ключ формы **64 lowercase hex** считается legacy-хешем.
2. При первом разборе источника прогнать по ЕГО узлам упразднённый алгоритм
   (Go: `config.LegacyNodeIdentityHash`) — по ПОЛНОМУ списку, до фильтра
   выключенных: legacy-ключ опознаётся именно по выключенному узлу.
3. Совпало → отметка переезжает на идентичность найденного узла (при
   коллизии побеждает более свежий lastSeen).
4. Не совпало → ключ выбрасывается: узла с таким содержимым в источнике нет,
   отметка и так мертва.
5. Результат **сохраняется**: иначе legacy-хеши прогоняются заново на каждом
   запуске, а файл состояния не чистится.

Реализация алгоритма шага 2 обязана остаться воспроизводимой, пока в природе
есть непереехавшие состояния. В Go он оставлен как `LegacyNodeIdentityHash`
и покрыт тестом `TestLegacyNodeIdentityHashStillReproducible`.

### 5.2 Миграция ссылки detour (SPEC 112 → 112-A)

Поле `detour_node_hash` читается только ради миграции:

1. Прогнать legacy-алгоритм по всем узлам конфига; хеш совпал → записать
   **полную ссылку**: id источника найденного узла в `detour_node_source_id`
   и его identity-тег в `detour_node_tag`. Источник без id (конфиг собран не
   из состояния) → tag-only ссылка с ФИНАЛЬНЫМ тегом узла.
2. Не совпал → **fallback: взять `detour_node_label` как тег**, но БЕЗ
   `detour_node_source_id`: узел под хешем не опознан, и приписывать ссылке
   чужой источник нельзя. Пикер писал в label тег узла в момент выбора,
   поэтому для узла, живого под тем же именем, глобальный поиск даст верную
   цель. Именно этот путь лечит состояния, где хеш протух из-за смены формы
   хранения узла (`uri` ↔ `config_json`).
3. Ни то ни другое → ссылка потеряна, источник падает fail-closed (§2.1).

`detour_node_hash` после миграции не пишется. Исключение — экспорт бэкапа с
источника, ещё не прошедшего миграцию: там хеш и подпись едут как есть и
мигрируют уже на приёмнике (BACKUP.md §4).
