# CANON — правила канонизации канонического узла

Нормативно. Версия контракта: см. `../VERSION`. Решения: DECISIONS.md (SPEC 103).

## 1. Конверт

Форма — `schema/node.schema.json`: `{v, nodes[], dropped[], meta?}`. Узел:
`{kind, scheme, label, entry, chain?, warnings?}`.

**`scheme` — имя схемы URI, не тип sing-box.** Канон берётся из
`registry/protocols/<scheme>.json` → поле `scheme`; тип ядра лежит рядом в
`singbox_type`. Разница видна ровно на shadowsocks: схема `ss`, тип
`shadowsocks`. Лаунчер пишет в конверт схему, LxBox — тип, поэтому раннер
LxBox приводит имя (`_canonScheme`). Расхождение косметическое (поведение
одинаково), но без приведения составы узлов не сходятся.

## 2. Канонизация `entry` (sing-box map)

1. **Без `tag`.** Tag-политика (prefix/mask/uniquify) — постобработка приложений,
   вне контракта. Человекочитаемое имя — в `label` конверта.
2. **Без `detour`.** Цепочка — в `chain[]` (ближний хоп первым, cap 8).
3. **Ключи отсортированы** рекурсивно (byte-order UTF-8), **порядок элементов
   списков сохраняется** (alpn, allowed_ips — значимы).
4. **Дефолтные поля не пишутся.** Поле, значение которого совпадает с дефолтом
   ядра или «пустым» смыслом, опускается (D-010: WG `name`/`system` не эмитятся).
5. **Числа — числами** (`server_port: 443`, не `"443"`); bool — bool.
6. **Компактный JSON без пробелов** при сериализации для хеша (identity —
   `IDENTITY.md`); в фикстурах — pretty-print для читаемости, сравнение — по
   разобранным значениям, не по байтам файла.
7. **Escaping: нет** (D-007). Строки — сырой UTF-8: без HTML-escaping
   (`<`, `>`, `&`), без ` `/` `-эскейпов. Go: `SetEscapeHTML(false)`
   и выравнивание юникод-эскейпов.

## 3. Порядок `nodes`

Порядок появления во входе. Для Xray-массивов — после нормативных проходов
владения идентичностью (ownership); фикстуры `corpus/body/` фиксируют результат.
Для sing-box-конфигов — порядок `outbounds[]`, затем `endpoints[]`, группы — на
месте появления.

## 4. Деградация

Философия обоих проектов, теперь нормативно:

- битое **значение** → чинится/выкидывается с warning-кодом
  (`registry/warnings.json`), нода живёт;
- битая **нода** → в `dropped[{ref, reason}]`, подписка живёт;
- битый **контейнер/элемент** → try/catch на гранулярности узла; потерянный
  протокол виден через warning `unsupported_protocol`;
- значение, которое ядро отвергнет fatal'ом на весь конфиг, в `entry` попадать
  **не имеет права** (пример: `tls.ech` — вычищается с `ech_ignored`, D-006).

## 5. Группы

`kind:"group"`: `entry.type` = `selector`|`urltest`; члены группы — по `label`
исходных узлов (теги в контракте не существуют). Синтетические группы приложений
(autogroup LxBox) — вне контракта, в фикстурах не появляются.

## 6. Warnings

`warnings[]` — список `{code, path?, value?, params?}` (контракт 1.1.0, SPEC 131;
до 1.1.0 — список строк-кодов, читается по-прежнему):

- `code` — из `registry/warnings.json`;
- `path` — путь поля в `entry` (`tls.reality.short_id`), обязателен для кодов
  уровня поля, отсутствует у кодов уровня узла (`field_missing` на узле в
  `dropped`, `protocol_unsupported`);
- `value` — исходное значение до деградации, обрезано до 64 символов; у полей
  с `secret: true` в реестре — `"***"`;
- `params` — подстановки шаблона `text_*` кода (имена — `params` записи кода).

Порядок: коды уровня узла — в порядке появления при разборе; коды уровня
поля — в порядке `body.order` реестра (обход санитайзера), дубли по
`(code, path)` снимаются. Текст рисуют приложения по `title_*`/`text_*` из
реестра; контракт сам переводит коды (оба языка в реестре), приложения не
держат собственных таблиц.

Warnings — производные данные: пересчитываются из исходника узла при любом
повторном разборе и не являются авторитетными при переносе (бэкап, обмен).

## 7. Сравнение в раннерах

Раннер разбирает вход → строит конверт → сравнивает с `expected.json`
**по значению** (после канонизации), не по байтам. Per-app override
(`<case>.expected.launcher.json` / `<case>.expected.lxbox.json`) допустим только
со ссылкой на задокументированное by-design различие (см. `IDENTITY.md` §4);
бесхозный override — ошибка линтера корпуса.

## 8. Конвейер (SPEC 131)

Любой вход — share-URI, sing-box/Xray JSON, wg-conf, ручное тело — проходит
три ступени, одинаковые для обеих сторон:

1. **маппер** — перевод диалекта в канонический путь `entry` по
   `uri.*.maps_to` и `body.*.aliases` реестра; значений не проверяет, дефолтов
   не ставит, незнакомое кладёт как есть;
2. **санитайзер** — по `body`-секциям реестра (`registry/protocols/<scheme>.json`,
   `tls.json`, `transports.json`, `multiplex.json`, `dialer.json`): тип, enum,
   формат, алиасы, `allowed_for`/`forbidden_for`, `conflicts`/`requires`,
   `unknown_key`; каждое снятие/приведение — запись в `warnings[]`;
3. **эмиттер** — сериализация в порядке `body.order`; схемных ветвлений в коде
   нет.

Инвариант, проверяемый корпусом: значение, которое ядро пина отвергает
фатально на весь конфиг (`sing-box check` = B по `DRIFT.md` SPEC 131), после
санитайзера в `entry` остаться не может. Гейты по версии ядра (`min_core`,
`platform`) — не при разборе, а при сборке конфига: `entry` от ядра не
зависит.
