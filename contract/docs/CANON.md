# CANON — правила канонизации канонического узла

Нормативно. Версия контракта: см. `../VERSION`. Решения: DECISIONS.md (SPEC 103).

## 1. Конверт

Форма — `schema/node.schema.json`: `{v, nodes[], dropped[], meta?}`. Узел:
`{kind, scheme, label, entry, chain?, warnings?}`.

## 2. Канонизация `entry` (sing-box map)

1. **Без `tag`.** Tag-политика (prefix/mask/uniquify) — постобработка приложений,
   вне контракта. Человекочитаемое имя — в `label` конверта.
2. **Без `detour`.** Цепочка — в `chain[]` (ближний хоп первым, cap 8).
3. **Ключи отсортированы** рекурсивно (byte-order UTF-8), **порядок элементов
   списков сохраняется** (alpn, allowed_ips — значимы).
4. **Дефолтные поля не пишутся.** Поле, значение которого совпадает с дефолтом
   ядра или «пустым» смыслом, опускается (D-010: WG `name`/`system` не эмитятся).
5. **Числа — числами** (`server_port: 443`, не `"443"`); bool — bool.
6. **Компактный JSON без пробелов** при сериализации для хеша (identity —
   `IDENTITY.md`); в фикстурах — pretty-print для читаемости, сравнение — по
   разобранным значениям, не по байтам файла.
7. **Escaping: нет** (D-007). Строки — сырой UTF-8: без HTML-escaping
   (`<`, `>`, `&`), без ` `/` `-эскейпов. Go: `SetEscapeHTML(false)`
   и выравнивание юникод-эскейпов.

## 3. Порядок `nodes`

Порядок появления во входе. Для Xray-массивов — после нормативных проходов
владения идентичностью (ownership); фикстуры `corpus/body/` фиксируют результат.
Для sing-box-конфигов — порядок `outbounds[]`, затем `endpoints[]`, группы — на
месте появления.

## 4. Деградация

Философия обоих проектов, теперь нормативно:

- битое **значение** → чинится/выкидывается с warning-кодом
  (`registry/warnings.json`), нода живёт;
- битая **нода** → в `dropped[{ref, reason}]`, подписка живёт;
- битый **контейнер/элемент** → try/catch на гранулярности узла; потерянный
  протокол виден через warning `unsupported_protocol`;
- значение, которое ядро отвергнет fatal'ом на весь конфиг, в `entry` попадать
  **не имеет права** (пример: `tls.ech` — вычищается с `ech_ignored`, D-006).

## 5. Группы

`kind:"group"`: `entry.type` = `selector`|`urltest`; члены группы — по `label`
исходных узлов (теги в контракте не существуют). Синтетические группы приложений
(autogroup LxBox) — вне контракта, в фикстурах не появляются.

## 6. Warnings

Коды из `registry/warnings.json`, в порядке появления при разборе. Локализация —
на стороне приложений; контракт кодов не переводит.

## 7. Сравнение в раннерах

Раннер разбирает вход → строит конверт → сравнивает с `expected.json`
**по значению** (после канонизации), не по байтам. Per-app override
(`<case>.expected.launcher.json` / `<case>.expected.lxbox.json`) допустим только
со ссылкой на задокументированное by-design различие (см. `IDENTITY.md` §4);
бесхозный override — ошибка линтера корпуса.
