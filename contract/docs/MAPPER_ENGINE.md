# MAPPER_ENGINE — архитектура движка маппера

Общий документ контракта (SPEC 133). Рядом с `CANON.md`; к LxBox едет синком.

Грамматика (имена атрибутов, FROZEN/DRAFT) —
`SPECS/133-F-N-REGISTRY_DRIVEN_LINK_MAPPER/PRIMITIVES.md` §0, машиночитаемая
форма — `contract/schema/registry_mapper.schema.json`.

Структура документа:

- **Норма** — влияет на результат. Обе стороны обязаны соблюдать одинаково;
  расхождение здесь = расхождение тел узлов.
- **Рекомендации** — не влияет на результат, но проверено на практике.
- **Приложение «Трасса»** — общий формат для механической сверки Go↔Dart.
- **Приложение «Go»** и **«Dart»** — устройство конкретной реализации.

Пометка «план» = в реализации лаунчера ещё нет, норма объявлена заранее.

# НОРМА

## 1. Стадии конвейера

Порядок нормативен. Между стадиями передаётся ровно то, что названо; стадия
не имеет доступа к тому, что ей не передали.

```
0. сырой ТЕКСТ документа
   ↓  document.sources[] — detect по priority (§2)
1. вид источника + оболочка
   ↓  unwrap → redetect (рекурсия, предел max_unwrap_depth)
2. элементы документа (строки списка / элементы массива / секции ini)
   ↓  mappers.<kind>.detect — какому протоколу и диалекту принадлежит элемент
3. секция-маппер + форма (forms[].detect)
   ↓  decode формы: percent ОДИН РАЗ, base64/json/ini/reparse
4. ПРОСТРАНСТВО ИСТОЧНИКОВ (§4)
   ↓  проход A: записи с selector: true
   ↓  проход B: остальные записи
5. тело узла (карта sing-box) + label + body_source
   ↓
6. nodeflow.Sanitize   ← значения судит ТОЛЬКО он
7. nodeflow.Emit       ← порядок ключей тела = body.order
```

**Движок принимает ТЕКСТ, а не разобранный URL-объект.** Причина —
норма §3: платформенный парсер URL отвергает то, что движок обязан принять.

**Маппер не судит значения.** Он переводит диалект; годность значения —
дело санитайзера по `body`-схеме. Граница нужна, чтобы вход из ссылки и
вход из JSON судились ОДНИМ набором правил, а не двумя.

**Отказы движка — ровно два:** «форма не распознана» и «синтаксис не
разобрать». Оба дают узел в `dropped` с кодом. Молча ронять узел движок не
может; всё прочее — деградация поля санитайзером с кодом.

## 2. Выбор: detect на двух уровнях

Предикаты `detect` **одни и те же** на уровне документа
(`registry/source_kinds.json`) и на уровне элемента
(`mappers.<kind>.detect`, `forms[].detect`). Отдельного «документного» языка
нет — иначе сниффер формата вернулся бы в код.

**Разрешение неоднозначности:**

1. совпало несколько — побеждает меньший `priority` (у форм — позиция в
   массиве);
2. не совпало ничего — берётся ветка `default: true`;
3. нет и её — код `source_unrecognized` (`severity: warning`, с фрагментом
   текста).

**Ветка `default` НИКОГДА не конкурирует с настоящим предикатом**, даже
если её `priority` меньше. Иначе «всё остальное» выигрывало бы у точного
признака, и порядок в файле стал бы ловушкой.

**Ровно одна ветка `default` на уровень** — проверяет линтер.

**Инвариант, проверяемый на корпусе:** каждый кейс опознаётся **ровно
одной** секцией. Ноль или два — красное.

## 3. Лексер authority и query

**Authority разбирает лексер ДВИЖКА, а не платформенный парсер URL.**
Причина конкретная: `host:443,20000-30000` (multi-port hysteria) —
валидный вход, который `Uri.tryParse` у Dart отвергает целиком.

Правила:

- `port_raw` — **сырая строка** порта до приведения к числу; multi-port
  читается из неё, а `port` для такого входа равен нулю;
- IPv6 в скобках: `[…]` — хост, порт после скобки;
- **голый IPv6 без скобок** несёт несколько `:` — портом это не является;
  порт берётся, только когда двоеточие ОДНО;
- userinfo отделяется по ПОСЛЕДНЕМУ `@`.

**Query разбирается с сохранением ПОРЯДКА появления.** Это не удобство, а
требование §5.

## 4. Пространство источников

Форма распаковывает текст в одно плоское пространство. Запись адресует
значение строкой `source` — и **это единственный способ получить значение**.
Сырых `url.Values`/карты JSON у исполнителя записи нет.

```
scheme   authority   userinfo[.user|.pass]   host   port   port_raw
path     fragment    query.<name>            json.<path>   ini.<S>.<K>
ini.$comment.<S>
```

- `json.<path>` — точечный путь; числовой сегмент индексирует массив.
  **Массив НЕ приводится к строке**: запись, которой нужен не скаляр, берёт
  значение как есть (`list`, `coerce`, `flatten`). Склейка массива в строку —
  источник живого дефекта (приложение «Go», Q133-16);
- `ini.<S>.<K>` — имена секций и ключей регистронезависимы;
- `$base` формы подставляется в `source` вместо префикса пути: одна таблица
  обслуживает `settings.vnext[0]`, `settings.servers[0]` и плоскую форму.

## 5. Имена параметров и приоритет написаний

Имена читаются **регистронезависимо** — на это опирается живой корпус
(`AllowInsecure=1`, `SNI=`, `Fp=`).

При **двух написаниях одного имени в одной ссылке** (`?sni=a&SNI=b`):

1. побеждает **точное совпадение с каноном**;
2. иначе — **первое по порядку появления**.

Правило требует сохранения порядка query (§3). Без него победитель
определяется порядком обхода хеш-таблицы, то есть меняется между запусками.

**Дубли одного написания** (`?fp=a&fp=b`) — берётся первый.

## 6. Политика декодирования

**Percent-декод — один раз, до всего**, силами декодера формы.
`decode_extra` — дополнительный проход ПОВЕРХ, объявляемый у записи.

| | Режим | Проходы |
|---|---|---|
| `alpn` | `query` | `until_stable`, `max: 16` |
| `path` | `path` | `2`, **path-семантика на ОБОИХ проходах** |

`alpn` не может быть «2 прохода»: живая фикстура несёт ТРИ уровня
кодирования (`http%2525252F1.1` → `http/1.1`). Предел 16 — страховка от
неограниченного цикла, на корпусе не достигается.

`path` не может быть query-семантикой на первом проходе: `+` в пути
литерален, и `/ws+v2%2Fdata` превратилось бы в `/ws v2/data` — сервер
отвечает 404, узел «жив» и молча не работает.

**`+` в query = пробел** (form-encoding; так же пишет эмит).
**Исключение — поля `format: base64*`**: `decode_extra.plus_literal`,
**по умолчанию выводимый из формата**, с возможностью явного указания.
Одно правило вместо точечных заплат у каждого ключа.

Следствие для реализации: `+` обязан доезжать до записи **сырым**.
Форм-семантику применяет запись, а не разбор — иначе решение о `+`
принималось бы до того, как известно, какое это поле.

## 7. Порядок исполнения записей и разрешение конфликтов

**Два прохода**, потому что `when` зависимой записи ссылается на тело,
построенное селектором (`transport.type`, `tls.enabled`):

- **проход A** — записи с `selector: true`, в порядке объявления;
- **проход B** — остальные, в порядке объявления.

**Порядок объявления в реестре НОРМАТИВЕН.** Реализация, исполняющая записи
в порядке обхода хеш-таблицы, обязана привести их к порядку объявления.
`aliases` — тоже в порядке объявления.

**Конфликт двух записей, пишущих в один путь:**

1. `priority` (меньше = раньше);
2. при равном `priority` — порядок объявления;
3. `merge` решает, что делать с занятым путём: `keep_first` (по умолчанию),
   `overwrite`, `prepend`, `append`.

Правило **«`sets` побеждает» — неверно**: побеждает не источник значения, а
объявленный порядок. Пример, на котором это видно: `flow=…-udp443` через
`sets` пишет `packet_encoding: xudp`, а `packetEncoding=` пишет своё
значение. Корпус требует, чтобы при `packetEncoding=none` уцелел `xudp` — и
это работает не потому, что `sets` сильнее, а потому что `none`
отображается в `null` и записи не делает. Явное значение перебивает.

**`sets` со значением `null` СНИМАЕТ путь** — это отличается от «не
писать»: `disable_sni=1` убирает уже записанный `tls.server_name`.

**`when` различает тело и источник:**

- ключ-путь тела (`transport.type`) — условие по УЖЕ ПОСТРОЕННОМУ телу;
- ключ-источник (`query.security`, `json.…`, `ini.…`) — условие по ВХОДУ;
- `$type` — тип тела, `$form` — id сработавшей формы.

Условие по источнику необходимо: род узла AWG объявляет **вход**, а не
тело — при негодных значениях в теле не остаётся ни одного awg-ключа, но
правило (потолок MTU) обязано примениться.

**Детерминированность.** При одинаковом входе и одинаковом реестре результат
и трасса совпадают побайтово. Источники недетерминизма, которые обязаны
быть исключены: обход хеш-таблиц, порядок ключей при сериализации, порядок
`aliases`.

### 7.1. Коллизия имени записи блока и записи секции

`include`-блоки разворачиваются ДО записей секции. Одноимённые записи **не
сливаются**: обе попадают в план, блок — раньше.

**Переопределением считается совпадение имени И ПОЛНОГО НАБОРА `source`**
(набор сравнивается с учётом порядка: `["query.sni","query.peer"]` и
`["query.peer","query.sni"]` — разные цепочки фолбэка). В этом случае запись
блока **изымается** из плана, и исполняется только запись секции.

Изъятие, а не «обе по порядку», выбрано потому, что переопределяющая запись
обычно ведёт в ДРУГОЙ путь тела: при исполнении обеих в теле остаются оба
пути, и лишний доезжает до ядра. `merge` разрешает спор за ОДИН путь, а не
за два разных, и проигравший по позиции путь никто не снимает.

Совпало имя, но источник другой — обе записи живут, и порядок их записи в
тело решают `priority`/`merge`, а не позиция.

**Запись под условием (`when`) переопределением НЕ считается.** Это не
послабление, а другая вещь: условная запись исполняется лишь в части
случаев, и изъять за неё запись блока значит оставить остальные случаи без
правила вовсе. Живой пример — `http.security`: она гейтится
`when.scheme.not_in: [proxy-https]` и на http-суффиксе снимает блок TLS, а
на https-суффиксе молчит, потому что там истину ведёт запись блока.

Имя записи уточняется именем блока (`ws.path`, `http.path`) **только у
склейки группы блоков** (`include: ["transports#uri"]`), где одно имя
принадлежит нескольким подблокам. Одиночный блок (`tls#uri`) имена не
префиксует. Объявленность параметра источника (`uri_param_unknown`)
считается по `source`, а не по ключу плана: `ws.path` и `http.path` — один
объявленный параметр `path`.

## 8. Множество «объявленных» параметров (`uri_param_unknown`)

Параметр считается **объявленным**, если он есть:

1. в `params` секции протокола;
2. в любом блоке, подключённом через `include` (`tls#uri`,
   `transports#uri`, `dialer`) — **включая блоки, не применившиеся** по
   `when`. Иначе `tcp_keep_alive*` давали бы по три info на каждый узел;
3. среди `aliases` любого из них.

**Не считается параметром ссылки** содержимое вложенного слоя чужого
диалекта (`extra` у xhttp): он адресуется `source`-ом, а не перечисляется.

Код ставится **только при загруженном реестре**: без реестра «неизвестно
всё», и молчание правильнее шума.

Для JSON-входов парный код — `json_field_unknown`; действие объявляется
секцией (`keep` у `singbox`, потому что чужой ключ может быть расширением
форка; `drop` у `xray`).

**`unknown_key.ignore[]` — ключи УРОВНЯ ДОКУМЕНТА.** Элемент объектного
входа несёт служебные ключи, полем узла не являющиеся: у Xray-outbound'а это
`protocol` (его читает выбор секции), `tag` и `remarks` (их читает обход
документа). Они перечисляются в `ignore` и не дают кода.

Это отличается от записи со значением `null` («параметр знаем, читать
нечего») ровно тем, что ключ **не принадлежит этому уровню**: объявить его
записью значило бы сказать, что секция его читает.

### 8a. Норма пустой `singbox`-секции

**Секция `singbox` у схемы без диалектных отличий — пустая форма, и это
не заготовка, а нормальное конечное состояние.** Канонический вид (образец
`trojan.json`):

```json
"singbox": {
  "detect": { "json": { "value_in": { "type": ["<тип>"] } } },
  "body_source": "singbox",
  "forms": [{ "id": "outbound", "detect": {"default": true},
              "space": "json", "level": "outbound" }],
  "params": {},
  "unknown_key": { "action": "keep", "code": "json_field_unknown" }
}
```

Почему `params` пуст, а секция всё же нужна. Вход `singbox` — тело **уже
в каноне ядра**: имена полей те же, что в теле узла, и переводить нечего.
Записи в `params` у такой секции появляются **только** там, где диалект
всё-таки есть: синоним типа (`type_synonyms`), разъезд уровней
`outbound`/`endpoint` (`lift`), legacy-написание поля (`since`).
Перечислять совпадающие имена значило бы держать вторую копию `body.fields`
и ловить её расхождение с первой.

При этом секция обязана существовать: она несёт `detect` (по нему элемент
достаётся протоколу), `body_source` (на него опирается `except_sources` в
правилах реестра) и `unknown_key` — то самое место, где неизвестный ключ
перестаёт уезжать в тело слепой копией.

`unknown_key.action` у `singbox` — **`keep`**, в отличие от `xray`: чужой
ключ может быть расширением форка, выбрасывать его нельзя; но и молчать
нельзя, поэтому `keep` идёт с кодом.

## Контекст санитайзера: `body_source` + `kind`

Санитайзер судит ЗНАЧЕНИЯ по телу, но часть правил зависит не от тела, а от
того, **откуда** оно взялось. Таких сведений два, и они разные:

- **`body_source`** — ВИД входа (`uri` / `singbox` / `xray` / `wgconf` /
  `amnezia`). Его читает `except_sources`: тело в собственной форме ядра
  человек написал сам, и лаунчер его не переписывает, а предупреждает.
- **`kind`** — РОД узла внутри одной схемы (`wg` / `awg` / `awg3`).
  Объявляет его секция-маппер атрибутом **`kind_when`** по условию на ВХОД
  (написание схемы, форма, наличие источников); в тело `kind` не пишется.
  Правила реестра читают его оператором **`when.source_kind`**, общим для
  `max_when` / `min_when` / `default_when`.

**Почему род нельзя вывести из тела.** Потолок MTU у AmneziaWG сегодня
объявлен условием `any_set` по awg-ключам тела. Но если ссылка принесла
ЭТИ ЖЕ ключи негодными, поле снимает правило значения — и к моменту
проверки потолка в теле не остаётся ни одного awg-ключа. Узел при этом
AmneziaWG и остаётся: род ему дало НАПИСАНИЕ `awg://`, а не содержимое.
Кейсы корпуса `awg_bad_numeric_skipped` и `awg_jc_invalid_dropped` ждут
`mtu: 1280` при пустом наборе awg-ключей — выразить это `any_set` нельзя
по построению.

**Род обязан переживать сохранение.** Правило общее:

> род — часть сохраняемого контекста узла ТАМ, ГДЕ ИСТОЧНИК НЕ ХРАНИТСЯ.

У LxBox узел хранится источником (`rawSource`), тело — кеш, и род
восстанавливается перепарсом всегда; сохранять его им не нужно. Лаунчер
хранит `Body` + `Origin`, а пересчёт кодов идёт по СОХРАНЁННОМУ ТЕЛУ, без
повторного разбора ссылки (`SanitizeBodyRequest`, `recountOneNode`). Значит
род обязан лежать рядом с телом: иначе первый же пересчёт увидит «род
неизвестен» и снимет кламп задним числом — настройка пользователя исчезала
бы от перезапуска. Ровно эту мину уже обезвредили для `body_source`,
положив `Origin.Kind` в запрос пересчёта.

Порядок восстановления рода у лаунчера:

1. сохранённое поле рода в `Origin` (launcher-only расширение: у LxBox его
   нет и быть не должно, они хранят источник);
2. у старых узлов без него — вывести перепарсом `Origin.Raw`, если он есть
   (ссылка хранится байт в байт);
3. иначе — прежнее ИЛИ-условие `any_set` по телу. Оно остаётся в правиле
   навсегда: у входа `singbox` рода от входа нет вовсе, и судить можно
   только по телу.

**Критерий для эмиссии** (следствие, проверять при обратном направлении):
эмит AWG-узла, у которого в теле не осталось awg-полей, обязан выбрать
написание `awg://` — иначе род теряется на круге. Проверка:
`parse(emit(node))` у `awg_bad_numeric_skipped` и `awg_jc_invalid_dropped`
обязан дать `mtu: 1280`.

Секция такого вида **порождается механически** и ревью по существу не
требует — проверяется линтером формы
(`TestContractMapperSectionsMatchSchema`), а не глазами. Ответ на находку 7
LxBox: да, генерируйте.

## 9. Обратный ход (эмит)

**Одна таблица в обе стороны**, а не два плана. Обратные операции:
`maps_to⁻¹`, `value_map⁻¹`, `sets` сопоставлением, `compose` (обратный
`extract`), `into⁻¹` у userinfo, `emit_form`/`form_from`.

Нормы выхода:

- `param_order` — **правило «алфавит»**, а не перечень имён; явный перечень
  только там, где порядок обязан отличаться;
- каноническое имя параметра — **первое в `aliases`**;
- пробел на выходе — **`%20`**;
- `emit_when` / `omit_default` — явные атрибуты, не умолчания реализации;
- `implicit: true` — значение подставлено конвенцией, а не источником: в
  ссылку не пишется, хотя в теле присутствует;
- `max_uri_length` применяется и на выходе (сегодня — только на входе).

**Не-round-trip случаи — данные, а не исключения кода**:
`round_trip: false` с причиной (DRAFT).

**Критерий приёмки эмита:** `parse(emit(node))` даёт то же тело на всех
identity-фикстурах, и старые сохранённые ссылки читаются в то же тело.

## 10. Дописано по сведению с Dart (19.09.2026)

Норма молчала о трёх вещах, на которых реализации разошлись бы. Формулируем
однозначно.

### 10.1. `defaults` секции — слабее любой записи

`defaults` применяются **после обоих проходов** и пишут **только в путь,
который никто не занял**. Ни `priority`, ни `merge` к ним не применяются:
они не участвуют в конкуренции, а заполняют оставшееся.

Иначе дефолтный `port: 443` побеждал бы явный порт из ссылки — он пишется
раньше. Формулировка «после проходов, только в пустое» предпочтительнее
«с очень большим `priority`»: она не зависит от выбора магического числа и
не ломается, если запись объявит `merge: overwrite`.

Трасса: `stage: "default"`, `entry: "$defaults"`, `why: "default"`.

### 10.2. `when` ЧИТАЕТ источник, но НЕ отмечает его прочитанным

Условие `when` по ключу-источнику (`query.security`, `json.…`, `ini.…`)
**не делает параметр объявленным-прочитанным** для §8. Спрашивать о
параметре и потреблять его — разные вещи.

Иначе параметр, который только проверяется условием и никуда не пишется,
переставал бы давать `uri_param_unknown` — код замолкал бы там, где он
единственный признак непонятого входа.

### 10.3. Имя из `source` объявлено наравне с именем записи

Имя записи в таблице и имя параметра в ссылке могут отличаться: запись
читает `query.<name>`, и **объявленным считается `<name>` из `source`**, а
не только имя записи. Множество §8 пополняется из трёх мест: имя записи,
её `aliases`, имена вида `query.*` из её `source`.

# РЕКОМЕНДАЦИИ

Не влияет на результат, но проверено.

1. **Предкомпиляция плана при загрузке реестра, а не интерпретация на лету.**
   Разворачивание `include`, разрешение `$ref`, компиляция регулярок и
   раскладка записей на проход A/проход B делаются один раз. Реестр вшит в
   бинарь и не меняется в рантайме, поэтому кэш — на процесс.
2. **Валидация при загрузке, а не при первом применении.** Битая секция
   должна ломать сборку/старт, а не один узел посреди разбора подписки.
3. **Кэш скомпилированных регулярок — общий**, ключ = текст выражения.
   Одно и то же выражение встречается в нескольких секциях.
4. **Трасса — опциональна и выключена по умолчанию.** Коллектор не должен
   стоить ничего, когда не собирается.
5. **Ожидания фикстур снимаются прогоном, а не пишутся руками** (практика
   LxBox). Снимок описывает поведение; вписанное руками описывает намерение
   и расходится с кодом молча.
6. **Пометка дельты — двусторонняя** (практика LxBox). Кейс, у которого
   поведение сознательно изменено, несёт и новое ожидание, и прежнее; тест
   требует совпадения с новым И отличия от прежнего. Односторонняя пометка
   протухает и с этого момента прикрывает регрессию.
7. **Гейт тестов вешать на то зеркало реестра, которое есть на CI.** Гейт
   на копию, которой в CI нет, молча пропускает тесты именно там, где они
   нужны.
8. **Регулярки реестра — в одном написании для обеих сторон** (Go-форма
   `(?P<name>)`), перевод делает читающая сторона при компиляции. Правка
   данных под язык = расхождение: запись читают оба движка.
9. **Цену мерить, а не оценивать**, и повторять на каждой волне: лучший из
   трёх прогонов, разнородный набор форм, отдельно слой и полная воронка.

# ПРИЛОЖЕНИЕ «ТРАССА»

Общий формат для **механической сверки Go↔Dart диффом**. Согласован обеими
сторонами.

## Формат

JSON Lines: одна строка = одно событие. Ключи в **фиксированном порядке**,
без времени и адресов памяти.

```
{"n":1,"stage":"field","mapper":"trojan.uri.url","entry":"sni","src":"query.sni",
 "raw":"x.com","val":"x.com","path":"tls.server_name","act":"write","why":"-"}
```

| Ключ | Значение |
|---|---|
| `n` | номер события, с 1 |
| `stage` | `doc_detect`, `unwrap`, `elem_detect`, `lex`, `field`, `sets`, `default`, `label`, `unknown`, `result` |
| `mapper` | `<protocol>.<секция>[.<form/dialect>]` |
| `entry` | имя записи таблицы или `$служебная` |
| `src` | `query.sni` \| `userinfo.user` \| `json.…` \| `ini.S.K` \| `-` |
| `raw` | значение до декодирования, либо `null` |
| `val` | значение после `decode`/`value_map`/`coerce` |
| `path` | путь в теле, либо `null` |
| `act` | `write`, `skip`, `remove`, `override`, `keep` |
| `why` | `when_false`, `empty`, `lower_priority:<entry>`, `not_declared`, `default`, `materialize_default`, `alias_of:<canon>`, `-` |

## Порядок событий НОРМАТИВЕН

Порядок событий = порядок исполнения: записи в порядке объявления в
реестре, `aliases` в порядке объявления. `unknown` — по строке на каждый
необъявленный параметр, в порядке появления во входе.

**Последняя строка — `stage: "result"`**: итоговое тело (ключи по
`body.order`), `label`, `body_source`.

## Каноническая сериализация

Без неё сверка даёт ложные расхождения.

1. JSON **без пробелов** (никаких отступов и пробелов после `:` и `,`);
2. ключи объектов тела и `val` — **в порядке `body.order`**; вложенные — в
   порядке своей секции; свободные объекты (например `headers`) —
   **лексикографически**;
3. числа **без экспоненты**;
4. не-ASCII **как есть** (UTF-8); `\u`-экранирование только для
   управляющих символов;
5. **БЕЗ HTML-экранирования** `<`, `>`, `&`.

Для Go пункты 4–5 означают `json.Encoder` с `SetEscapeHTML(false)`, а
пункт 2 — собственный упорядоченный вывод вместо сортировки ключей карты.

**Golden-трассы живут в `contract/corpus`** (генерирует Go, сверяет Dart) —
подключаются к раннеру корпуса после вливания обоих движков.

# ПРИЛОЖЕНИЕ «Go» (лаунчер)

Пакет `core/config/linkmap`, модель — `core/config/registry/mapper.go`.
go1.20-совместимо (Win7-джоба собирает весь модуль тулчейном go1.20).

## Что реализовано

| Часть | Статус |
|---|---|
| предикаты `detect` обоих уровней, ленивый разбор контента | есть |
| выбор по `priority`, неконкурирующий `default` | есть |
| пространство источников, `source` как единственный доступ | есть |
| лексер authority (multi-port, голый IPv6) | есть |
| порядок query с приоритетом точного совпадения | есть |
| кэш регулярок | есть |
| проходы A/B, `sets`/`implies`/`extract`, `defaults` | есть |
| трасса (`trace.go`) | есть |
| `compose` / эмит | **план** |
| кэш `Plan` между узлами, `implicit` до результата | **план** |

## Решения реализации

**Лексер.** `SplitAuthority` режет по последнему `@`, затем различает три
случая: скобочный IPv6, ровно одно двоеточие (хост:порт), несколько
двоеточий без скобок (голый IPv6 — порта нет). `PortOf` возвращает 0 на
всём, что не число целиком: multi-port читается из `port_raw`.

**Порядок query.** Собственный `ParseQueryOrdered` вместо `url.ParseQuery`:
нужен порядок (§5) и сырой `+` (§6). Значение percent-декодируется
`PathUnescape` — он не трогает `+`.

**JSON-скаляр.** `jsonScalar` возвращает «нет значения» для массива и
объекта. Это отличается от сегодняшнего `xrayMapString`, который делает
`fmt.Sprint` и превращает `["a.com","b.com"]` в `"[a.com b.com]"` —
типовой реальный Xray-конфиг даёт мусорный `host` (QUIRKS Q133-16).

**Кэш регулярок** — общий, под мьютексом, ключ = текст выражения.

**Предкомпиляция плана** — план: сейчас секции читаются в модель при
`LoadMappers()`, разворачивание `include` и раскладка на проходы ещё не
сделаны.

## Цена

Разбор реестра — один раз на процесс (`sync.Once`, как у существующего
`registry.Get`). На узел приходится: выбор формы (несколько предикатов по
уже разобранному контенту), обход записей таблицы, поиск по
`source`. Тяжёлых операций на узел нет: регулярки скомпилированы заранее,
JSON элемента разбирается один раз на элемент, ini — один раз на документ.

Ориентир масштаба — подписки на 500+ узлов (память
`subscription_scale_fanout`), реальное состояние владельца — 186 узлов.
На 2000 узлов узкое место — не движок, а сборка документа (дедуп,
владение, цепочки), которая в маппер не входит.

## Что спорно

1. **`priority` у записей против чистого порядка объявления.** Порядок
   объявления уже нормативен, и `priority` его дублирует. Оставлен потому,
   что запись может приезжать из `include`-блока, где её позиция
   относительно записей протокола не определена.
2. **`default` не конкурирует с предикатами.** Удобно и предсказуемо, но
   означает, что `priority` у `default`-ветки не значит ничего. Альтернатива
   (честная конкуренция) делала бы порядок в файле ловушкой.
3. **`$`-префикс служебных записей** — соглашение, а не механизм: движок
   отличает их только по отсутствию `maps_to`. DRAFT.
4. **Два прохода, а не топологическая сортировка зависимостей.** Проходов
   хватает на весь сегодняшний реестр, но `when`, ссылающийся на путь,
   который пишет НЕ селектор, работать не будет. Сознательное ограничение:
   топологическая сортировка сделала бы порядок неочевидным для человека,
   читающего таблицу.

# ПРИЛОЖЕНИЕ «Dart» (LxBox)

Пакет `app/lib/services/parser/engine/`. Состояние — волна W1: движок и
пилот trojan в `develop`. Ниже только то, что **реально отличается** от Go;
совпадающее (лексер, проходы A/B, `sets: null`, `when` по телу и источнику,
формат трассы) не повторяется.

## Что реализовано

| Часть | Статус |
|---|---|
| стадии 4–7 (форма → пространство → таблица → label) | есть |
| стадии 1–3 (уровень документа) | **план**, волны W5–W6; сегодня формат опознаёт рукописный `body_decoder.dart` |
| `extract` | есть (`_applyExtract`) |
| `compose` / эмит | **план**, волна W7; ссылку собирает прежний `toUri*` |
| трасса | **план**, следующим блоком |
| предкомпиляция плана | **план** |

## Решения реализации

**Границы слоёв.** Между стадиями едут ровно две структуры: `SourceSpace`
(`source_space.dart`) и `EngineResult`. Наружу движок отдаёт `UriMapping` —
ту же запись, что отдавали рукописные мапперы, поэтому санитайзер,
`parseSingboxEntry` и модель не изменились. Побочное следствие: `body_source`
секции до санитайзера пока не доезжает, он получает `BodySource.other`.

**Порядок записей достаётся бесплатно.** Dart сохраняет порядок вставки в
`Map`, поэтому «порядок объявления» (норма §7) не требует приведения, как в
Go. `_orderedParams` — стабильная сортировка по `priority` с индексом
объявления как тай-брейком.

**Регулярки реестра — в Go-написании.** `(?P<name>)` переводится в
`(?<name>)` внутри `_regex` при компиляции, один раз на выражение. Правка
данных под Dart была бы расхождением: одну и ту же запись читают обе стороны.

**`aliases` берутся из описательной части реестра** (`_withAliases`):
исполняемая запись `insecure` их не дублирует, словарь из девяти написаний
объявлен один раз в `tls.params.insecure`.

**`include` разворачивается при сборке секции** (`_withIncludes`): записи
блока становятся обычными записями таблицы, и норма §8 получается сама —
отдельного списка исключений нет. Имена блока разводятся по группе
(`ws.path` против `http.path`).

**Чтение без отметки.** `_readSourceBare` — чтение источника для `when` без
пометки «прочитано»: условие о параметре спрашивает, а не читает его.

## Цена

Замер на 2000 ссылок trojan (лучший из трёх, пять разнородных форм):

| Слой | Рукописный | Движок | Отношение |
|---|---|---|---|
| маппер | 18 мс | 75 мс | ×4,06 |
| полная воронка | 201 мс | 201 мс | +28% |

Маппер — 37% воронки; за ним санитайзер по реестру и постройка модели,
и они дороже перевода диалекта. На 2000 узлов это +55 мс разово при
открытии подписки. Четырёхкратность слоя держится на `_orderedParams` на
каждом узле, чтении `source` разбором строки-имени (`startsWith('query.')`)
и обходе всех записей секции вместо заранее разложенных проходов — всё
снимается предкомпиляцией.

## Обвязка

- `before_480_identity_snapshot_test.dart` — снимок «до» (88 кейсов, 13
  схем), плюс `engine_trojan_pilot_test.dart` (35 кейсов). Сравнение —

  И отличается от прежнего — иначе пометка протухла и прикрывает регрессию.
  Новые ожидания снимаются прогоном (`engine_delta_dump_test.dart`).

- `engine_no_scheme_names_test.dart` — в `engine/` нет ни одного имени

## Спорное, где обе стороны могут ошибаться

- **`priority` у записей дублирует порядок объявления** (наш «Что спорно» §1).
  LxBox возражений не прислала и использует `priority` активно (`flow` 10 /
  `packetEncoding` 20). Удалять нельзя: запись из `include`-блока не имеет
  определённой позиции относительно записей протокола. Оставляем, но это
  **два способа сказать одно** — кандидат на ревизию после эмита.
- **`default`-ветка не конкурирует.** Обе реализации так и делают, возражений
  нет; цена — `priority` у `default` не значит ничего. Линтер обязан это
  проверять, иначе поле молча игнорируется.
- **Порог ×1,5 на воронке** держится сегодня при ОДНОЙ схеме на движке. На 13
  схемах доля маппера вырастет; ни одна сторона не знает, где порог порвётся.
  Мерить обеим при каждой волне, а не один раз.

## В Dart-движке (LxBox)

1. **Стадии 1–3 и `body_source` до санитайзера** (волны W5–W6). Пока
   санитайзер получает `BodySource.other`, правило реестра с

   записью с искусственным `priority: 1<<20`. Норма §10.1 дописана по вашей

   имя записи и имя в `query.<name>` различаются — иначе лишний
   `uri_param_unknown`.

   применяет `+`→пробел по умолчанию (`exec.go:546` `decodeValue` →

   каждом узле — ваша же главная статья цены. У нас раскладка уже в `Plan`,
