# TEMPLATE_LANG v1 — язык шаблонов LX (нормативная спека)

Статус: **черновик фазы 0** программы SPEC 103. Источник фактов — сверка
`SPECS/103-F-O-LX_SHARED_CONTRACT/research/CHECK_TEMPLATE_ENGINE.md`, решения —
`PLAN.md §9.C` и `DECISIONS.md` (D-011, D-012). Референсные реализации:

- Go (desktop, singbox-launcher): `core/template/substitute.go`,
  `core/template/vars_resolve.go`, `core/template/vars_default.go`,
  `core/template/preset_types.go`, `core/template/loader.go`
- Dart (mobile, LxBox): `app/lib/services/builder/if_engine.dart`,
  `app/lib/services/builder/preset_expand.dart`, `app/lib/models/parser_config.dart`

Документ описывает **целевое состояние**. Там, где реализация сегодня
отличается, стоит пометка «разрыв CN» — сводная таблица в §9.

Терминология: **ядро** — обязаны оба движка; **desktop-расширение** /
**mobile-расширение** — задекларированная односторонняя возможность; второй
движок обязан такие конструкции *толерантно игнорировать*, а не падать.

## 1. Структура шаблона

Шаблон — один JSON-объект. Top-level секции:

| Секция | Статус | Примечание |
|---|---|---|
| `parser_config` | ядро | настройки парсера подписок и (desktop) заготовки групп-outbound'ов |
| `config` | ядро | базовый sing-box-конфиг с `"@var"`-плейсхолдерами и `#if` |
| объявления переменных | ядро | **представление расходится**: desktop — плоский `vars[]` (+ `{"separator": true}`-записи), mobile — `sections[].vars[]` c `id/name/chapter/description`. Ядро контракта — *набор объявлений var*, контейнер — расширение каждой стороны (разрыв C9) |
| `dns_options` | ядро | форма записей серверов расходится (desktop — плоские объекты, mobile — `{description, enabled, vars[], server{}}`); выравнивание — тема SPEC 105, здесь не нормируется |
| пресеты | ядро | **имя секции расходится**: desktop `presets[]`, mobile `selectable_rules[]` (разрыв N4, §9). Схема пресета — §6 |
| `params[]` | desktop | dot-notation патчи конфига, §7.1 |
| `group_templates`, `default_channels` | mobile | magic-ноды и каналы, §8.5 |
| `ping_options`, `speed_test_options` | mobile | конфигурация приложения, движком шаблонов не интерпретируется |

**Правило толерантности (нормативно).** Неизвестная top-level секция,
неизвестное поле объявления переменной и неизвестное поле пресета обязаны
молча игнорироваться (допустим debug-warning). Это правило делает шаблоны и
их фрагменты переносимыми между проектами и версиями. Падение загрузки на
неизвестном поле — нарушение контракта.

## 2. Объявление переменных

### 2.1 Поля ядра

```json
{
  "name": "tun_mtu",
  "type": "int",
  "default_value": "1492",
  "options": ["1280", "1400", "1492"],
  "title": "MTU",
  "tooltip": "…",
  "wizard_ui": "edit"
}
```

| Поле | Обязательность | Семантика |
|---|---|---|
| `name` | обязательно | идентификатор; подстановка — `"@<name>"` |
| `type` | обязательно | один из типов §2.2; неизвестный тип трактуется как `text` |
| `default_value` | опционально | строка; сложные формы (per-platform объект, `#if`-дерево) — desktop-расширение §7.4 |
| `options` | опционально | список строк ИЛИ список `{"title": "...", "value": "..."}`. Для `enum` — множество допустимых значений; для остальных типов — UI-подсказки (suggestions). Объектная форма **не меняет** `type` (сегодня Go форсит `type→enum` — разрыв N5) |
| `title`, `tooltip` | опционально | UI-строки |
| `wizard_ui` | опционально | `edit` \| `fix` \| `hidden` — ядро; `target` — desktop-расширение |

Все прочие поля объявления — расширения (§7/§8) под правилом толерантности.

### 2.2 Типы и приведение (coercion)

Канонический набор типов — **8**:
`bool`, `int`, `text`, `text_list`, `enum`, `secret`, `outbound`, `dns_servers`.

Канон имени последнего — **`dns_servers`**; `dns_server` (Go PresetVar,
`preset_types.go:179-186`) — допустимый алиас чтения. `number` (Go PresetVar) —
алиас `int`. Эмитить при записи шаблонов следует только канонические имена.

Значение переменной хранится строкой; в JSON оно попадает **строго по
объявленному `type`** — никакого угадывания по содержимому и никаких
хардкод-списков имён (сегодняшний Go `isIntCastVar`, `substitute.go:15-21` —
разрыв C5; список имён остаётся временным fallback на миграцию).

Таблица приведения (нормативно):

| type | Приведение строки `raw` | Невалидное значение |
|---|---|---|
| `bool` | `TrimSpace` + case-insensitive сравнение с `"true"` → JSON `true`/`false`; всё прочее (включая пустую строку) → `false` | не бывает |
| `int` | `TrimSpace` + целочисленный парс → JSON number; затем **clamp в [0, 65535]** (uint16-backstop: порт/tolerance/MTU вне диапазона роняют ядро на decode) | не число → значение уезжает **строкой как есть** (advisory: опечатка видна в конфиге/валидаторе, а не маскируется нулём; сегодняшний Go `warn + 0` уходит вместе с C5) |
| `text` | строка как есть | — |
| `text_list` | построчный сплит (`\n`), trim строк, пустые строки выбрасываются → JSON-массив строк; пустое значение → `[]` | — |
| `enum` | строка как есть; принадлежность `options` — забота UI, движок не enforce'ит | — |
| `secret` | строка как есть | — |
| `outbound` | строка как есть (тег outbound-цели) | — |
| `dns_servers` | строка как есть (тег DNS-сервера) | — |

Разрыв C6: в Dart типа `text_list` нет вообще (`parser_config.dart:509`) —
добавляет. Go сегодня допускает `outbound`/`dns_server` только в preset-vars —
в ядре типы разрешены в любом контексте объявления.

Разрыв N12: Dart сегодня коэрсит значение `bool` строго — `raw == 'true'`
без trim и case-insensitive (`if_engine.dart:40`); это сайт коэрции значения,
отдельный от bare-предиката C1.

## 3. Подстановка `"@var"`

- Распознаётся **строка, целиком** равная `"@<name>"` в любой позиции JSON
  (значение ключа, элемент массива). Интерполяция в середине строки
  (`"prefix @var"`) в ядро v1 не входит.
- Подставляется **типизированное** значение по таблице §2.2: `bool` → JSON
  bool, `int` → JSON number, `text_list` → JSON-массив, остальное — строка.
- `"@runtime.*"` — desktop-расширение (§7.2), не переменные шаблона.
- Legacy-форма «одноэлементный массив `["@text_list_var"]` коллапсирует в
  массив значений» (Go `substitute.go:166-177`) — desktop-legacy, в ядро не
  входит; канонический способ — значение `"@list"` прямо в позиции массива.

Политика неразрешённых имён — §5.2.

## 4. Конструкция `#if`

### 4.1 Грамматика

```json
{"#if": {"and": [ <pred>, … ], "value": <JSON>, "else": <JSON>}}
{"#if": {"or":  [ <pred>, … ], "value": <JSON>, "else": <JSON>}}
```

- Обязан присутствовать **ровно один** из ключей `and` / `or`, и его значение —
  **непустой список** предикатов. Оба ключа, ни одного, или пустой список —
  **ошибка загрузки шаблона** (load-валидация, модель Dart
  `if_engine.dart:392-402`); если невалидный узел всё же дошёл до рантайма
  (толерантный режим) — условие вычисляется в `false` + warning. Разрыв C3:
  Go сегодня «neither → warn + true» (`substitute.go:310-313`) и валидации
  загрузки не имеет.
- `value` обязателен (load-валидация; Dart `if_engine.dart:403-405`).
  `else` опционален.
- `and` — истинно, когда истинны все предикаты; `or` — когда хотя бы один.
- Вычисление ленивое: обходится (и подставляется) только выбранная ветка.
  Вложенные `#if` любой формы в ветках разрешены.
- Неизвестные ключи, начинающиеся с `#`, выбрасываются с warning
  (forward-compat). Сегодня warning даёт только Go (`substitute.go:127`);
  Dart удаляет их молча (`if_engine.dart:121-133`) — разрыв N10 (ход Dart).

### 4.2 Таблица предикатов (полная, ядро)

`scalar(v)` ниже — строковое значение переменной `v` до типизации.

| # | Форма | Семантика (нормативно) | Разрыв |
|---|---|---|---|
| P1 | `"@boolvar"` (bare-строка) | истинен ⇔ `EqualFold(TrimSpace(scalar), "true")` — **trim + case-insensitive** | C1: Dart сегодня строгое `== 'true'` (`if_engine.dart:265`) — добавляет trim+casefold |
| P2 | `{"@var": "<строка>"}` | равенство: `TrimSpace(scalar(var)) == subst(RHS)`, где `subst` — @var-подстановка в RHS: `{"@a": "@b"}` сравнивает две переменные | C8: в Dart RHS всегда литерал (`if_engine.dart:287`) — добавляет подстановку |
| P3 | `{"@var": "#notEmpty"}` / `{"@var": "#isEmpty"}` | **семантика по объявленному типу** (модель Go `substitute.go:469-480`): `bool` → notEmpty ⇔ значение `true`; `text_list` → notEmpty ⇔ список непуст; остальные типы → notEmpty ⇔ `len(TrimSpace(scalar)) > 0`. `#isEmpty` — отрицание | C2: Dart сегодня чисто строковая проверка — на bool-var `#notEmpty` всегда true; переходит на типовую семантику |
| P4 | `{"@var": {"#in": <arg>}}` / `{"#notIn": <arg>}` | принадлежность `TrimSpace(scalar)` множеству. `<arg>` — массив строк (каждый элемент проходит @var-подстановку) **или строка `"@text_list_var"`** — сравнение с элементами списка | C6+C8: у Dart аргумент только литеральный List (`if_engine.dart:293-296`) — добавляет обе формы |
| P5 | `{"@var": {"#matches": "<re>"}}` | поиск регэкспа (unanchored) в `scalar`; паттерн проходит @var-подстановку. Кэш компиляции — деталь реализации (Dart `_matchCache`), не семантика | C8: @var в паттерне — добавляет Dart |
| P6 | `{"#not": <pred>}` | отрицание вложенного предиката; объект-предикат обязан иметь ровно один ключ (load-валидация) | — |

**Вложенные `#and`/`#or` разрешены на любую глубину** (SPEC 107, D-066 —
снимает прежний запрет D-018). Элемент списка `#and`/`#or` — предикат ИЛИ
вложенный cond-obj:

```json
{"#or": ["@tun", {"#and": [{"@runtime.platform": "windows"}, "@enable_proxy_in"]}]}
```

`#not` (P6) отрицает **любое** условие, включая `#and`/`#or`, а не только
предикат.

Ссылка на **неизвестную** переменную в любом предикате → предикат `false` +
warning. Сегодня warning даёт только Go (`substitute.go:367-370`); Dart молчит —
resolve → null → `''` → `false` (`if_engine.dart:265, 281, 310-315`), а
необъявленное в `vars` имя в предикате у Dart вообще ошибка загрузки
(`_requireVar`, `if_engine.dart:435, 461, 508`) — разрыв N9 (ход Dart:
warning в толерантном рантайме).

`{"@runtime.platform": …}` и прочие `@runtime.*` в предикатах —
desktop-расширение (§7.2). Движок без поддержки `@runtime.*` обязан вычислить
такой предикат в `false` (Dart это уже делает через resolve→null). Bare-форма
`"@runtime.x"` запрещена и на desktop (`substitute.go:362-365`).

### 4.3 map-spread (условные поля объекта)

**Именованные условные ключи (D-045).** Условным считается любой ключ,
начинающийся с `#if`: `"#if"`, `"#if1"`, `"#if 2"`, `"#if tun-only"`. Суффикс
произволен и на семантику не влияет — он нужен, чтобы повесить на один объект
несколько независимых условий (JSON не допускает двух одинаковых ключей: при
разборе в map выживает последний, а первое условие молча теряется), и заодно
даёт условию человекочитаемое имя. Несколько `#if…` одного объекта применяются
последовательно в порядке сортировки ключей — порядок обязан быть
детерминированным в обеих реализациях (`ifKeysSorted` в `substitute.go` и
`if_engine.dart`). В условном элементе массива (§4.4) и в скалярном `#if`
(§4.5) ключ по-прежнему должен быть ровно один — с любым суффиксом.

Объект, содержащий ключ `"#if"` **среди других ключей**:

```json
{"type": "tun", "#if": {"and": ["@a"], "value": {"x": 1}, "else": {"x": 2}}}
```

> **Нельзя** ставить `#if` значением скалярного поля:
> `"strategy": {"#if": {…, "value": "@a", "else": "b"}}` даёт на выходе пустой
> объект `{}`, а не выбранную строку — ветка мержится в родителя (см. ниже), и
> подставлять её вместо самого поля движку некуда. Значение скалярного поля,
> зависящее от условия, ведётся через `on_change` (§4.6) — переменная получает
> нужное значение, а поле ссылается на неё обычным `"@var"`. Ограничение
> грамматики, одинаково в обоих движках (D-044). Не путать с §4.5: там тот же
> `#if` вычисляется до скаляра **вне дерева конфига** (движком `on_change`) —
> внутри конфига такой формы нет.

- Ветки `value`/`else` — объекты. Выбранная ветка **мержится в родителя**;
  при конфликте ключей побеждает ветка (перетирает сиблингов, last-wins).
  Порядок обхода — деталь реализации (Go — pre-pass до полей,
  `substitute.go:114-133`; Dart — ветка последней, `if_engine.dart:137-160`);
  наблюдаемый результат обязан совпадать.
- Условие `false` без `else` → no-merge (родитель остаётся как есть).
- Defensive-путь «условие true, а `value` отсутствует» до рантайма не доходит
  (load-валидация §4.1); толерантный рантайм — skip + warning.

### 4.4 array-element (условный элемент массива)

Элемент массива распознаётся как условный, когда он — объект **ровно с одним
ключом** `"#if"` (`substitute.go:141-152`, `if_engine.dart:169-172`):

```json
"address": ["@tun_address", {"#if": {"and": ["@ipv6_enabled"], "value": "@tun_address6"}}]
```

- Условие `true` → элемент заменяется веткой `value` (после подстановки).
- Условие `false` → ветка `else`, а при её отсутствии элемент **выпадает из
  массива** (Dropped, §5.1) — массив укорачивается, `null` не остаётся.

### 4.5 Скалярный `#if`

Вычисление одиночного `{"#if": …}` до скаляра вне дерева конфига —
`evalIfScalar` (`if_engine.dart:224-229` на mobile, `EvalIfScalar`
(`substitute.go`) на desktop, SPEC 103) — переиспользует тот же движок
предикатов, что и подстановка внутри конфига (§4.1-4.4): один парсер языка
`#if` на оба контекста. Используется механизмом `on_change.set` (§4.6, ядро).

Возвращает скаляр-строку, если ветка выбрана (`value`/`else`) и её значение —
строка; в остальных случаях (ветка не выбрана, значение — массив/объект) —
«не вычислено», вызывающий (on_change) обязан оставить цель нетронутой.

### 4.5.1 Пометка ключевых слов (D-073)

Правило языка: **`#` — ключевое слово движка, `@` — ссылка на переменную, всё
остальное — данные.** Канонические формы:

```json
{"#if": {"#or": ["@tun", {"#and": [{"@runtime.platform": "windows"}, "@proxy"]}],
         "#value": {…}, "#else": {…}}}
{"#enable": {"#not": "@gateway_mode"}}
{"#on_change": {"#set": {"@target": {"#if": {…}}}}}
```

Непомеченные `and`, `or`, `value`, `else`, `on_change`, `set` — **легаси-алиасы
чтения, поддерживаются бессрочно**; ни один существующий шаблон не ломается.
Смешанная запись (канон снаружи, легаси внутри) валидна — читает один движок.

Зачем: до D-073 правило выполнялось наполовину (`#not`/`#in`/`#matches`
помечены, `and`/`or`/`value`/`else` — нет), и в одной позиции списка
предикатов встречались три разные конвенции. Помеченная форма делает первый
символ ключа самодостаточным: разборщику не нужен контекст, а человеку —
помнить, в каком контексте он находится.

### 4.6 `#enable` — гейт существования/активности (ядро, D-065)

Плоский ключ среди полей носителя — в отличие от `#if`, ничего не подставляет,
а решает, «жив» ли носитель:

```json
{"tag": "geoip-ru", "type": "remote", "#enable": ["@geoip_enabled"], "url": "…"}
```

- Значение — всегда список; оператор, если нужен, — первый элемент:
  `["@a", "@b"]` (все истинны, and по умолчанию), `["or", "@a", "@b"]`
  (хотя бы одно), `["and", ...]` — явная форма. Оператор — голое слово,
  ссылки в каноне всегда с `@`, поэтому двусмысленности нет. Объектная форма
  `{"and": [...]}` / `{"or": [...]}` — алиас чтения. Пусто/нет → true.
- Носители и эффект: фрагмент пресета (rule_set / rules[] / dns_servers /
  dns_rule(s) / outbounds) — не эмитится; объявление переменной — строка
  Settings/поле диалога неактивны; `params[]` — блок не применяется.
- Движок обязан вырезать ключ перед эмиссией (как `#if`).
- Легаси-алиасы чтения, бессрочно: `if` (= and-список), `if_or` (= or-список),
  mobile `enabled: "@var"` (= список из одного).
- Отличие от `#if` (§4.1–4.5): `#if` — тернарная подстановка со `value`/`else`
  и merge; `#enable` — булев гейт без веток. Полная `#if`-обёртка для гейта
  отвергнута как тяжеловесная (D-065).

### 4.7 `on_change` — side-effects при изменении переменной (ядро, SPEC 103)

До SPEC 103 — mobile-расширение (§232); перенесено в ядро: у Go-лаунчера
своя реализация (`core/template/on_change.go`, `EvalIfScalar` в
`substitute.go`), семантика идентична mobile-эталону
(`_applyOnChange`, `settings_screen.dart:258-277`).

Поле объявления var:

```json
{"name": "ipv6_enabled", "type": "bool", "on_change": {"set": {
  "@dns_strategy":     {"#if": {"and": ["@ipv6_enabled"], "value": "prefer_ipv4", "else": "ipv4_only"}},
  "@resolve_strategy": {"#if": {"and": ["@ipv6_enabled"], "value": "prefer_ipv4", "else": "ipv4_only"}}
}}}
```

Семантика:

- `on_change.set` — единственная форма сегодня: `{"@target": <#if-дерево>}`
  для одной или нескольких целевых var;
- когда пользователь МЕНЯЕТ значение var (edit-time, в UI визарда/settings —
  НЕ при каждой пересборке конфига), для каждого target его `#if`-дерево
  вычисляется до скаляра (`EvalIfScalar`/`evalIfScalar`, §4.5) **в контексте
  уже НОВОГО значения** изменённой var; результат пишется в целевую var;
- если `#if` не вычисляется (ветка не выбрана, значение — не скаляр), цель
  НЕ трогается;
- рекурсия: после записи цели её собственный `on_change` (если есть)
  применяется тем же ходом — цепочка;
- **fixpoint-guard**: если новое значение цели совпало с уже записанным —
  запись не производится и рекурсия по этой ветке обрывается (защита от
  циклов вида A→B→A, а не только от A→A);
- реализация обязана иметь дополнительный жёсткий предохранитель (лимит
  глубины и/или число посещений одной var в цепочке) на случай топологии,
  которую fixpoint не ловит (например значения, чередующиеся по кругу).

`on_change` — декларативный, разовый эффект переключения: пользователь
может вручную переопределить целевую var после срабатывания, это не
принудительный форс на каждую сборку (в отличие от `#if` внутри `config`,
который пересчитывается при каждой генерации).

## 5. Dropped-каскад и политика unresolved (D-011)

Принята **модель Dart** целиком; Go мигрирует в фазе 3 (разрыв C4).

### 5.1 Dropped-каскад

Sentinel `Dropped` (`if_engine.dart:21-24`) — «этого значения быть не должно»:

- источники: (а) объявленная переменная со значением `null` (optional-var);
  (б) array-element `#if` со значением `false` без `else`;
- распространение: значение ключа → **ключ удаляется из объекта**; элемент
  массива → **элемент удаляется из массива** (`if_engine.dart:140-148,
  179-186`); каскад идёт снизу вверх без остановки сборки;
- гейты валидности фрагментов пресета (после каскада): rule без
  `outbound`/`action` → фрагмент выпадает (`preset_expand.dart:296-301`);
  dns_rule без `server` и без serverless-`action` → выпадает
  (`preset_expand.dart:234-241`); `required`-переменная пустая → весь пресет
  не собирается и попадает в warnings (`preset_expand.dart:121-144`).

Итог: деградация **пофрагментная** — битая часть пресета выпадает с warning,
остальное живёт. Строгий режим Go (`SubstituteVarsInJSONStrict` →
`UnresolvedVarError` → пресет выбрасывается целиком) упраздняется.

### 5.2 Unresolved var

| Ситуация | Нормативное поведение |
|---|---|
| Имя **не объявлено** в `vars` | плейсхолдер `"@name"` остаётся в выводе **как есть** — опечатка видна в итоговом конфиге и ловится валидатором, а не маскируется пустой строкой |
| Имя объявлено, значение `null` | `Dropped`-каскад §5.1 |
| Имя не объявлено — в `#if`-предикате | предикат `false` + warning |

Разрыв C4: Go сегодня подставляет `""` + WarnLog
(`substitute.go:196-202`) — мигрирует.

## 6. Пресеты

### 6.1 Единая схема (ядро)

```json
{
  "id": "block-ads",
  "label": "Block Ads",
  "description": "…",
  "default_enabled": true,
  "vars":        [ { "name": "out", "type": "outbound", "default_value": "reject", "title": "…" } ],
  "rule_set":    [ { "tag": "ads", "type": "remote", "format": "binary", "url": "…" } ],
  "rules":       [ { "rule_set": "ads", "outbound": "@out" } ],
  "dns_rules":   [ { "…": "…" } ],
  "dns_servers": [ { "tag": "…", "type": "udp", "…": "…" } ]
}
```

- `rules[]` / `dns_rules[]` — канонические списки; сингулярные формы `rule` /
  `dns_rule` — синонимы «список из одного». Обе формы сегодня читает только
  Dart (`parser_config.dart:779, 788`); Go читает сингулярный `dns_rule`
  (`preset_types.go:66`), но не `rule` (`preset_types.go:63` — только `rules`),
  а mobile-шаблон `rule` реально пишет — на desktop такой пресет молча теряет
  правило. Разрыв N11 (ход Go: добавить чтение `rule`).
- Объявления `vars` пресета — та же грамматика §2 (включая толерантность);
  поле дефолта — каноническое `default_value` (сегодня Go-пресеты пишут
  `default` — разрыв N3).
- Каноническое поле идентификатора — `id`, UI-поля (`label`, `description`,
  `default_enabled`) — плоские. Mobile-представление `preset_id` + обёртка
  `ui{}` — текущий разрыв представления (N4); при чтении оба движка обязаны
  принимать обе формы до выравнивания.
- Переносимость: тело пресета живёт в шаблоне каждого приложения; бэкап несёт
  только ссылку `{kind: "preset", ref: "<id>", vars: {…}}` — поэтому общие id
  регистрируются в `contract/registry/presets.json`, а неизвестный id при
  импорте даёт «правило выключено + warning», не потерю.

### 6.2 Неймспейс тегов: префикс `<preset_id>:<tag>` (D-012)

Принята **модель Go** (`preset_types.go:7-8, 47-52, 240-241, 269-271`):

- локальные теги пресета (`rule_set[].tag`, `dns_servers[].tag`) при сборке
  получают автопрефикс `<preset_id>:<tag>` — например `block-ads:ads`;
- внутренние ссылки пресета на локальный тег (`rules[].rule_set`,
  `dns_rule.server`, `detour` и т.п.) резолвятся с тем же префиксом;
- ссылки на глобальные теги шаблона (`direct-out`, `proxy-out`, …) префикса
  не получают;
- цель — детерминированные теги: два включённых пресета не коллидируют, а
  ссылка из бэкапа значит одно и то же на обоих устройствах.

Разрыв C7: Dart сегодня не префиксует, коллизии решает дедупом first-wins +
warning (`preset_expand.dart:473-526`). Миграция LxBox меняет теги собранного
конфига — обязательны heal-редиректы существующих ссылок (route.final, detour,
отметки) и обычный релизный цикл (PLAN §11.6).

### 6.3 `outbounds[]` пресета — desktop-расширение

Блок `outbounds` с `mode: "add" | "update"`, `filters`, `addOutbounds`
(`preset_types.go:98-167`) — модификация глобальных групп из пресета
(пример — `!RU`-фильтры пресетов `russian`/`ru-inside`/`ru-blocked`).
В Dart отсутствует и в ядро не входит; переносимость preset-ссылок не
страдает (§6.1). Прочие односторонние поля пресетов: `platforms`,
`if`/`if_or` на фрагментах, `select: local|global` у var — desktop (§7);
`locked`, `num`, `isSortable`, `enabled: "@var"` на фрагментах, `required`
у var — mobile (§8). Условность фрагментов (`if` vs `enabled`) — открытый
разрыв N6.

## 7. Расширения desktop (каждое — вне ядра)

### 7.1 `params[]`

Dot-notation патчи конфига до var-подстановки
(`loader.go:192-200`, `substitute.go` applyParam/applyValue):
`{"name": "route.rules", "mode": "replace|prepend|append", "value": …,
"if"/"if_or": […], "platforms": […]}`. Предикаты `if`/`if_or` — та же
грамматика §4.2.

### 7.2 `@runtime.*`

Глобальные значения окружения сборки: `@runtime.platform`, `@runtime.arch`,
`@runtime.target` (TargetSpec; `substitute.go:28-51, 443-455`). Допустимы в
предикатах и в `#if`-деревьях `default_value`; bare-форма запрещена. На
mobile отсутствуют by design (одна платформа) — предикаты с ними обязаны
вычисляться в `false` (§4.2).

### 7.3 Секретные переменные: автогенерация

`MaybeGenerateSecrets` (`vars_resolve.go:19-27, 288-309`): переменной
`type: "secret"` с пустым значением или значением с префиксом `CHANGE_THIS_`
генерируется случайное значение.

### 7.4 Per-platform `default_value`

`default_value` — объект `{"windows"|"linux"|"darwin"|"win7"|"default":
<строка | #if-дерево>}` (`vars_default.go:15-21, 45-61, 95-107`); значения
могут быть `#if`-деревьями с `@runtime.*`. Dart сегодня схлопывает объект в
ключ `default` (`parser_config.dart:570-576`) — допустимое поведение
«не-поддерживающей» стороны.

### 7.5 Прочее

`separator`-записи в `vars[]` (визуальные разделители), `default_node`
(фолбэк из JSON-пути шаблона, `vars_resolve.go:331-339`), `platforms` и
`if`/`if_or` на объявлении var («скрыть vs погасить»,
`vars_resolve.go:483-509`), `wizard_ui: "target"`.

## 8. Расширения mobile (каждое — вне ядра)

### 8.1 `sections[]`

Контейнер объявлений: `{"id", "name", "chapter", "description", "vars": […]}`
вместо плоского `vars[]`; поле `section`/`chapter` у var
(`parser_config.dart:515-516, 601-616`).

### 8.2 `ref`

Запись `{"ref": "<global_var_name>"}` в списке vars пресета — ссылка на
глобальную переменную вместо локального объявления (§265,
`preset_expand.dart:110-117, 152-156`).

### 8.3 `required`

Флаг на объявлении var (§033, `parser_config.dart:521`); пустое значение
required-переменной — гейт §5.1.

### 8.4 `group_templates` / `default_channels`

Шаблоны magic-нод и каналов (`selector`/`urltest`), список каналов по
умолчанию `vpn-1..N`. Модель каналов переезжает на desktop отдельной
программой (SPEC 104), до того — mobile-расширение.

### 8.5 Прочее

`enabled: "@var"` на фрагментах пресета (§045), `locked`/`num`/`isSortable`
в `ui{}` (§264/§370; `num` — общая ось порядка правил в бэкапе, PLAN §7),
`ping_options`/`speed_test_options`, локализационный overlay шаблона.
