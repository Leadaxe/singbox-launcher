# TEMPLATE_LANG v1 — язык шаблонов LX (нормативная спека)

> **О чём этот документ.** Язык шаблона конфига: JSON с плейсхолдерами
> `"@имя"` вместо значений и условиями `#if` вместо ветвлений, из которого
> сборка делает `config.json` для ядра. Здесь объявление переменных и их
> типы, правила подстановки, грамматика `#if`, что происходит с пустым
> значением (dropped-каскад), устройство пресетов и какие конструкции есть
> только у одной стороны.
>
> **Кому читать.** Автору своего шаблона (§1–§6 достаточно) и тому, кто
> правит обходчик шаблона в любом из приложений (всё, включая §9 —
> расхождения сторон).
>
> **Что знать заранее.** Штатный шаблон лаунчера — `bin/wizard_template.json`,
> его описание для пользователя — `docs/TEMPLATE_REFERENCE.md` репозитория.
> Термины «ядро» и «расширение» в этом документе означают не sing-box, а
> «обязаны оба движка» и «умеет одна сторона» (см. абзац «Терминология» ниже).

Статус: **черновик фазы 0** программы SPEC 103. Источник фактов — сверка
`SPECS/103-F-O-LX_SHARED_CONTRACT/research/CHECK_TEMPLATE_ENGINE.md`, решения —
`PLAN.md §9.C` и `DECISIONS.md` (D-011, D-012). Референсные реализации:

- Go (desktop, singbox-launcher): `core/template/substitute.go`,
  `core/template/vars_resolve.go`, `core/template/vars_default.go`,
  `core/template/preset_types.go`, `core/template/loader.go`
- Dart (mobile, LxBox): `app/lib/services/builder/if_engine.dart`,
  `app/lib/services/builder/preset_expand.dart`, `app/lib/models/parser_config.dart`

Документ описывает **целевое состояние**. Там, где реализация сегодня
отличается, стоит пометка «разрыв CN» — сводная таблица в §9.

Терминология: **ядро** — обязаны оба движка; **desktop-расширение** /
**mobile-расширение** — задекларированная односторонняя возможность; второй
движок обязан такие конструкции *толерантно игнорировать*, а не падать.

## 1. Структура шаблона

Шаблон — один JSON-объект. Top-level секции:

| Секция | Статус | Примечание |
|---|---|---|
| `parser_config` | ядро | настройки парсера подписок и (desktop) заготовки групп-outbound'ов |
| `config` | ядро | базовый sing-box-конфиг с `"@var"`-плейсхолдерами и `#if` |
| объявления переменных | ядро | **представление расходится**: desktop — плоский `vars[]` (+ `{"separator": true}`-записи), mobile — `sections[].vars[]` c `id/name/chapter/description`. Ядро контракта — *набор объявлений var*, контейнер — расширение каждой стороны (разрыв C9) |
| `dns_options` | ядро | форма записей серверов расходится (desktop — плоские объекты, mobile — `{description, enabled, vars[], server{}}`); выравнивание — тема SPEC 105, здесь не нормируется |
| пресеты | ядро | **имя секции расходится**: desktop `presets[]`, mobile `selectable_rules[]` (разрыв N4, §9). Схема пресета — §6 |
| `params[]` | desktop | dot-notation патчи конфига, §7.1 |
| `group_templates` | обе | magic-ноды и форма групп Направления, §8.4 |
| `default_channels` | mobile | стартовый набор каналов телефона, §8.4 |
| `ping_options`, `speed_test_options` | mobile | конфигурация приложения, движком шаблонов не интерпретируется |

**Правило толерантности (нормативно).** Неизвестная top-level секция,
неизвестное поле объявления переменной и неизвестное поле пресета обязаны
молча игнорироваться (допустим debug-warning). Это правило делает шаблоны и
их фрагменты переносимыми между проектами и версиями. Падение загрузки на
неизвестном поле — нарушение контракта.

## 2. Объявление переменных

### 2.1 Поля ядра

```json
{
  "name": "tun_mtu",
  "type": "int",
  "default_value": "1492",
  "options": ["1280", "1400", "1492"],
  "title": "MTU",
  "tooltip": "…",
  "wizard_ui": "edit"
}
```

| Поле | Обязательность | Семантика |
|---|---|---|
| `name` | обязательно | идентификатор; подстановка — `"@<name>"` |
| `type` | обязательно | один из типов §2.2; неизвестный тип трактуется как `text` |
| `default_value` | опционально | строка; сложные формы (per-platform объект, `#if`-дерево) — desktop-расширение §7.4 |
| `options` | опционально | список строк ИЛИ список `{"title": "...", "value": "..."}`; формы равноправны (`title` — только подпись в UI, подставляется `value`). Допустимы при **любом** типе §2.2, **кроме `bool`** — валидатор загрузки отвергает `options` у `bool`. Семантика — **закрытое множество** допустимых значений. Объектная форма **не меняет** `type` (N5 закрыт, SPEC 143, D-125) |
| `options_open` | опционально | `true` разрешает значение вне `options` (свободный ввод рядом со списком); введённое значение проходит приведение по `type` (§2.2: у `int` — парс и clamp, у `text_list` — построчный сплит). Без флага своё значение UI не даёт ввести; состояние с чужим значением движок не enforce'ит (как у `enum`). Без `options` флаг ничего не значит |
| `title`, `tooltip` | опционально | UI-строки |
| `wizard_ui` | опционально | `edit` \| `fix` \| `hidden` \| `internal` — ядро (`internal` — контракт 1.1.119, D-132, ниже); `target` — desktop-расширение |
| `unique` | опционально | bool, **только у `text_list`** (у другого типа — ошибка загрузки); контракт 1.1.119, D-132. Значение переменной всегда без дубликатов, порядок первого появления. Применяется к вводу пользователя (UI убирает дубли при сохранении, хранимое значение с дублями нормализуется при чтении), к `default_value` и к результату `#append` (§6.7.3, шаг 5). С `#final.#unique` совместимо — идемпотентно |

`type` и `options` ортогональны (SPEC 143, D-125): `type` говорит, что уедет
в JSON, `options` — какие значения допустимы. `text_list` + `options` —
множественный выбор: значение — выбранные строки по одной на строку, движок
подставляет их JSON-массивом (§2.2); рендер множественного выбора — забота UI
каждой стороны.

```json
{"name": "urltest_tolerance", "type": "int", "default_value": "100",
 "options": [{"title": "Low", "value": "50"}, {"title": "Medium", "value": "100"}]}
{"name": "tun_mtu", "type": "int", "default_value": "1492",
 "options": ["1280", "1400", "1492"], "options_open": true}
```

**`wizard_ui: "internal"` — переменная только для сборки** (контракт 1.1.119,
D-132). Единственный, кто её пишет, — `#do` обхода узлов (§6.7):

- в формах не показывается — ни строки, ни подсказки;
- значение из состояния и из файла бэкапа сборка **игнорирует**: база —
  `default_value` (нет — пусто), дальше пишет только `#do`;
- в состояние не пишется (писатель снимает ключ молча), в LX Backup не
  экспортируется;
- импорт значение снимает и называет:
  `backup_var_skipped {name, record, reason: internal}` (`record` — носитель,
  как у прочих причин; у пресета — `preset:<ref>`).

Отличие от `hidden`: `hidden` прячет строку, но значение остаётся данными
пользователя — хранится, экспортируется, переносится. `internal` — не данные
пользователя вовсе. У переменной верхнего уровня `#do` нет — `internal` там
означает константу `default_value` без строки в форме.

Все прочие поля объявления — расширения (§7/§8) под правилом толерантности.

### 2.2 Типы и приведение (coercion)

Канонический набор типов — **8**:
`bool`, `int`, `text`, `text_list`, `enum`, `secret`, `outbound`, `dns_server`.

Канон имени последнего — **`dns_server`** (единственное число, как соседний
`outbound`); `dns_servers` — допустимый алиас чтения, нормализуется при
загрузке (`canonicalVarType`, `core/template/preset_types.go`). `number` —
алиас `int`. Эмитить при записи шаблонов следует только канонические имена.

> Решение зафиксировано в §9, строка N9. Раньше этот абзац называл каноном
> множественное число, противореча и §9, и обеим реализациям — шаблон с
> чужой стороны при этом молча терял переменную: неизвестный тип
> отбрасывает весь пресет целиком.

`enum` — синоним `text` + закрытые `options` (§2.1): читается бессрочно,
но в новых объявлениях эмитить следует `text` с `options` (SPEC 143, D-125).

Значение переменной хранится строкой; в JSON оно попадает **строго по
объявленному `type`** — никакого угадывания по содержимому и никаких
хардкод-списков имён (C5 закрыт полностью, SPEC 143: каст только по `type`).

Таблица приведения (нормативно):

| type | Приведение строки `raw` | Невалидное значение |
|---|---|---|
| `bool` | `TrimSpace` + case-insensitive сравнение с `"true"` → JSON `true`/`false`; всё прочее (включая пустую строку) → `false` | не бывает |
| `int` | `TrimSpace` + целочисленный парс → JSON number; затем **clamp в [0, 65535]** (uint16-backstop: порт/tolerance/MTU вне диапазона роняют ядро на decode) | не число → значение уезжает **строкой как есть** (advisory: опечатка видна в конфиге/валидаторе, а не маскируется нулём; код `template_int_invalid`) |
| `text` | строка как есть | — |
| `text_list` | построчный сплит (`\n`), trim строк, пустые строки выбрасываются → JSON-массив строк; пустое значение → `[]` | — |
| `enum` | = `text` с закрытыми `options`: строка как есть; принадлежность `options` — забота UI, движок не enforce'ит | — |
| `secret` | строка как есть | — |
| `outbound` | строка как есть (тег outbound-цели) | — |
| `dns_servers` | строка как есть (тег DNS-сервера) | — |

Разрыв C6: в Dart типа `text_list` нет вообще (`parser_config.dart:509`) —
добавляет. Go сегодня допускает `outbound`/`dns_server` только в preset-vars —
в ядре типы разрешены в любом контексте объявления.

Разрыв N12: Dart сегодня коэрсит значение `bool` строго — `raw == 'true'`
без trim и case-insensitive (`if_engine.dart:40`); это сайт коэрции значения,
отдельный от bare-предиката C1.

## 3. Подстановка `"@var"`

- Распознаётся **строка, целиком** равная `"@<name>"` в любой позиции JSON
  (значение ключа, элемент массива). Интерполяция в середине строки
  (`"prefix @var"`) в ядро v1 не входит.
- Подставляется **типизированное** значение по таблице §2.2: `bool` → JSON
  bool, `int` → JSON number, `text_list` → JSON-массив, остальное — строка.
- `"@runtime.*"` — desktop-расширение (§7.2), не переменные шаблона.
- **Коллапса нет** (SPEC 143, D-124). Одноэлементный массив `["@name"]` не
  сворачивается в скаляр: скобки автора сохраняются, а что встанет на место
  ссылки, решает только объявленный `type`. `"address": ["@tun_address"]` при
  `tun_address: text = "172.16.0.1/30"` даёт `["172.16.0.1/30"]`. Ссылка
  всегда в кавычках — шаблон это JSON.
- Голая ссылка на `text_list` в позиции значения ключа (`"k": "@list"`) даёт
  массив; в позиции элемента массива (`["@list", …]`) — вливается в
  родительский массив (§4.4).

Политика неразрешённых имён — §5.2.

## 4. Конструкция `#if`

### 4.1 Грамматика

```json
{"#if": {"and": [ <pred>, … ], "value": <JSON>, "else": <JSON>}}
{"#if": {"or":  [ <pred>, … ], "value": <JSON>, "else": <JSON>}}
```

- Обязан присутствовать **ровно один** из ключей `and` / `or`, и его значение —
  **непустой список** предикатов. Оба ключа, ни одного, или пустой список —
  **ошибка загрузки шаблона** (load-валидация, модель Dart
  `if_engine.dart:392-402`); если невалидный узел всё же дошёл до рантайма
  (толерантный режим) — условие вычисляется в `false` + warning.
  Разрыв C3 **закрыт с обеих сторон** (см. §9): Go валидирует на загрузке
  секции `config`, `params[].value`, `vars[].default_value` и тела `#enable`
  одним обходом (`ValidateWizardTemplate` → `walkValidateIf`,
  `core/template/template_validate.go`). Рантайм остаётся толерантным:
  боевой обходчик на невалидном условии даёт `true` (канонический — `false`,
  см. §9.1), но такой шаблон до рантайма не доходит — он не загружается.
- `value` обязателен (load-валидация; Dart `if_engine.dart:403-405`).
  `else` опционален.
- `and` — истинно, когда истинны все предикаты; `or` — когда хотя бы один.
- Вычисление ленивое: обходится (и подставляется) только выбранная ветка.
  Вложенные `#if` любой формы в ветках разрешены.
- Неизвестные ключи, начинающиеся с `#`, выбрасываются с warning
  (forward-compat). Сегодня warning даёт только Go (`substitute.go:127`);
  Dart удаляет их молча (`if_engine.dart:121-133`) — разрыв N10 (ход Dart).

### 4.2 Таблица предикатов (полная, ядро)

`scalar(v)` ниже — строковое значение переменной `v` до типизации.

| # | Форма | Семантика (нормативно) | Разрыв |
|---|---|---|---|
| P1 | `"@boolvar"` (bare-строка) | истинен ⇔ `EqualFold(TrimSpace(scalar), "true")` — **trim + case-insensitive** | C1: Dart сегодня строгое `== 'true'` (`if_engine.dart:265`) — добавляет trim+casefold |
| P2 | `{"@var": "<строка>"}` | равенство: `TrimSpace(scalar(var)) == subst(RHS)`, где `subst` — @var-подстановка в RHS: `{"@a": "@b"}` сравнивает две переменные | C8: в Dart RHS всегда литерал (`if_engine.dart:287`) — добавляет подстановку |
| P3 | `{"@var": "#notEmpty"}` / `{"@var": "#isEmpty"}` | **семантика по объявленному типу** (модель Go `substitute.go:469-480`): `bool` → notEmpty ⇔ значение `true`; `text_list` → notEmpty ⇔ список непуст; остальные типы → notEmpty ⇔ `len(TrimSpace(scalar)) > 0`. `#isEmpty` — отрицание | C2: Dart сегодня чисто строковая проверка — на bool-var `#notEmpty` всегда true; переходит на типовую семантику |
| P4 | `{"@var": {"#in": <arg>}}` / `{"#notIn": <arg>}` | принадлежность `TrimSpace(scalar)` множеству. `<arg>` — массив строк (каждый элемент проходит @var-подстановку) **или строка `"@text_list_var"`** — сравнение с элементами списка | C6+C8: у Dart аргумент только литеральный List (`if_engine.dart:293-296`) — добавляет обе формы |
| P5 | `{"@var": {"#matches": "<re>"}}` | поиск регэкспа (unanchored) в `scalar`; паттерн проходит @var-подстановку. Кэш компиляции — деталь реализации (Dart `_matchCache`), не семантика | C8: @var в паттерне — добавляет Dart |
| P6 | `{"#not": <pred>}` | отрицание вложенного предиката; объект-предикат обязан иметь ровно один ключ (load-валидация) | — |

**Вложенные `#and`/`#or` разрешены на любую глубину** (SPEC 107, D-066 —
снимает прежний запрет D-018). Элемент списка `#and`/`#or` — предикат ИЛИ
вложенный cond-obj:

```json
{"#or": ["@tun", {"#and": [{"@runtime.platform": "windows"}, "@enable_proxy_in"]}]}
```

`#not` (P6) отрицает **любое** условие, включая `#and`/`#or`, а не только
предикат.

Ссылка на **неизвестную** переменную в любом предикате → предикат `false` +
warning. Сегодня warning даёт только Go (`substitute.go:367-370`); Dart молчит —
resolve → null → `''` → `false` (`if_engine.dart:265, 281, 310-315`), а
необъявленное в `vars` имя в предикате у Dart вообще ошибка загрузки
(`_requireVar`, `if_engine.dart:435, 461, 508`) — разрыв N9 (ход Dart:
warning в толерантном рантайме).

`{"@runtime.platform": …}` и прочие `@runtime.*` в предикатах —
desktop-расширение (§7.2). Движок без поддержки `@runtime.*` обязан вычислить
такой предикат в `false` (Dart это уже делает через resolve→null). Bare-форма
`"@runtime.x"` запрещена и на desktop (`substitute.go:362-365`).

### 4.3 map-spread (условные поля объекта)

**Именованные условные ключи (D-045).** Условным считается любой ключ,
начинающийся с `#if`: `"#if"`, `"#if1"`, `"#if 2"`, `"#if tun-only"`. Суффикс
произволен и на семантику не влияет — он нужен, чтобы повесить на один объект
несколько независимых условий (JSON не допускает двух одинаковых ключей: при
разборе в map выживает последний, а первое условие молча теряется), и заодно
даёт условию человекочитаемое имя. Несколько `#if…` одного объекта применяются
последовательно в порядке сортировки ключей — порядок обязан быть
детерминированным в обеих реализациях (`ifKeysSorted` в `substitute.go` и
`if_engine.dart`). В условном элементе массива (§4.4) и в скалярном `#if`
(§4.5) ключ по-прежнему должен быть ровно один — с любым суффиксом.

Объект, содержащий ключ `"#if"` **среди других ключей**:

```json
{"type": "tun", "#if": {"and": ["@a"], "value": {"x": 1}, "else": {"x": 2}}}
```

> **Нельзя** ставить `#if` значением скалярного поля:
> `"strategy": {"#if": {…, "value": "@a", "else": "b"}}` даёт на выходе пустой
> объект `{}`, а не выбранную строку — ветка мержится в родителя (см. ниже), и
> подставлять её вместо самого поля движку некуда. Значение скалярного поля,
> зависящее от условия, ведётся через `on_change` (§4.6) — переменная получает
> нужное значение, а поле ссылается на неё обычным `"@var"`. Ограничение
> грамматики, одинаково в обоих движках (D-044). Не путать с §4.5: там тот же
> `#if` вычисляется до скаляра **вне дерева конфига** (движком `on_change`) —
> внутри конфига такой формы нет.

- Ветки `value`/`else` — объекты. Выбранная ветка **мержится в родителя**;
  при конфликте ключей побеждает ветка (перетирает сиблингов, last-wins).
  Порядок обхода — деталь реализации (Go — pre-pass до полей,
  `substitute.go:114-133`; Dart — ветка последней, `if_engine.dart:137-160`);
  наблюдаемый результат обязан совпадать.
- Условие `false` без `else` → no-merge (родитель остаётся как есть).
- Defensive-путь «условие true, а `value` отсутствует» до рантайма не доходит
  (load-валидация §4.1); толерантный рантайм — skip + warning.

### 4.4 array-element (условный элемент массива)

Элемент массива распознаётся как условный, когда он — объект **ровно с одним
ключом** `"#if"` (`substitute.go:141-152`, `if_engine.dart:169-172`):

```json
"address": ["@tun_address", {"#if": {"and": ["@ipv6_enabled"], "value": "@tun_address6"}}]
```

- Условие `true` → элемент заменяется веткой `value` (после подстановки).
- Условие `false` → ветка `else`, а при её отсутствии элемент **выпадает из
  массива** (Dropped, §5.1) — массив укорачивается, `null` не остаётся.
- **Сплайс на один уровень** (SPEC 143, D-123). Если выбранная ветка после
  подстановки — массив, его элементы вливаются в родительский массив (ровно
  один уровень). Ветка не-массив встаёт одним элементом. Литеральный массив и
  ссылка на `text_list` не различаются. Вложенный массив пишется двойными
  скобками: `[[…]]` после сплайса одного уровня даёт один элемент-массив.

```json
"servers": ["1.1.1.1", {"#if": {"and": ["@ipv6"], "value": ["2606:4700::1111", "2606:4700::1001"]}}]
→ ["1.1.1.1", "2606:4700::1111", "2606:4700::1001"]

"servers": ["1.1.1.1", {"#if": {"and": ["@ipv6"], "value": [["2606:4700::1111", "2606:4700::1001"]]}}]
→ ["1.1.1.1", ["2606:4700::1111", "2606:4700::1001"]]

"address": ["@tun_address"]            // tun_address: text = "172.16.0.1/30"
→ ["172.16.0.1/30"]

"address": ["@tun_address", {"#if": {"and": ["@ipv6_enabled"], "value": "@tun_address6"}}]
                                        // tun_address6: text_list = ["fd00::1/126"]
→ ["172.16.0.1/30", "fd00::1/126"]
```

### 4.5 Скалярный `#if`

Вычисление одиночного `{"#if": …}` до скаляра вне дерева конфига —
`evalIfScalar` (`if_engine.dart:224-229` на mobile, `EvalIfScalar`
(`substitute.go`) на desktop, SPEC 103) — переиспользует тот же движок
предикатов, что и подстановка внутри конфига (§4.1-4.4): один парсер языка
`#if` на оба контекста. Используется механизмом `on_change.set` (§4.6, ядро).

Возвращает скаляр-строку, если ветка выбрана (`value`/`else`) и её значение —
строка; в остальных случаях (ветка не выбрана, значение — массив/объект) —
«не вычислено», вызывающий (on_change) обязан оставить цель нетронутой.

### 4.5.1 Пометка ключевых слов (D-073)

Правило языка: **`#` — ключевое слово движка, `@` — ссылка на переменную, всё
остальное — данные.** Канонические формы:

```json
{"#if": {"#or": ["@tun", {"#and": [{"@runtime.platform": "windows"}, "@proxy"]}],
         "#value": {…}, "#else": {…}}}
{"#enable": {"#not": "@gateway_mode"}}
{"#on_change": {"#set": {"@target": {"#if": {…}}}}}
```

Непомеченные `and`, `or`, `value`, `else`, `on_change`, `set` — **легаси-алиасы
чтения, поддерживаются бессрочно**; ни один существующий шаблон не ломается.
Смешанная запись (канон снаружи, легаси внутри) валидна — читает один движок.

**Слова обхода узлов** (контракт 1.1.119, D-130, D-131, §6.5–§6.7): `#filter`,
`#do`, `#append`, `#final`, `#unique`, `#sort`, `#limit`.

```json
{"for_each_node_do": {"#filter": {"@node.body.server": "#notEmpty"},
                      "#do":     {"@list": {"#append": "@node.body.server"}},
                      "#final":  {"@list": {"#unique": true, "#sort": true, "#limit": 200}}}}
```

У них **непомеченных алиасов нет** — строго, слова новые в 1.1.119, и
легаси-текстов с ними не существует (`filter` прежнего `for_each` снят вместе
с ним). `filter`, `do`, `append`, `final`, `unique`, `sort`, `limit` внутри
`for_each_node*`, операции `#do` или `#final` — ошибка загрузки. Сами
`for_each_node` / `for_each_node_do` — поля пресета, как `vars` и `rules`, а
не слова движка: `#` у них нет. Поле объявления `unique` (§2.1) — тоже поле
данных, не слово движка. Внутри `#filter` действует обычная грамматика
условия §4.1–4.2, включая легаси-алиасы `and`/`or`.

Зачем: до D-073 правило выполнялось наполовину (`#not`/`#in`/`#matches`
помечены, `and`/`or`/`value`/`else` — нет), и в одной позиции списка
предикатов встречались три разные конвенции. Помеченная форма делает первый
символ ключа самодостаточным: разборщику не нужен контекст, а человеку —
помнить, в каком контексте он находится.

### 4.6 `#enable` — гейт существования/активности (ядро, D-065)

Плоский ключ среди полей носителя — в отличие от `#if`, ничего не подставляет,
а решает, «жив» ли носитель:

```json
{"tag": "geoip-ru", "type": "remote", "#enable": ["@geoip_enabled"], "url": "…"}
```

- Значение — всегда список; оператор, если нужен, — первый элемент:
  `["@a", "@b"]` (все истинны, and по умолчанию), `["or", "@a", "@b"]`
  (хотя бы одно), `["and", ...]` — явная форма. Оператор — голое слово,
  ссылки в каноне всегда с `@`, поэтому двусмысленности нет. Объектная форма
  `{"and": [...]}` / `{"or": [...]}` — алиас чтения. Пусто/нет → true.
- Носители и эффект: фрагмент пресета (rule_set / rules[] / dns_servers /
  dns_rule(s) / outbounds) — не эмитится; объявление переменной — строка
  Settings/поле диалога неактивны; `params[]` — блок не применяется.
- Движок обязан вырезать ключ перед эмиссией (как `#if`).
- Легаси-алиасы чтения, бессрочно: `if` (= and-список), `if_or` (= or-список),
  mobile `enabled: "@var"` (= список из одного).
- Отличие от `#if` (§4.1–4.5): `#if` — тернарная подстановка со `value`/`else`
  и merge; `#enable` — булев гейт без веток. Полная `#if`-обёртка для гейта
  отвергнута как тяжеловесная (D-065).

### 4.7 `on_change` — side-effects при изменении переменной (ядро, SPEC 103)

До SPEC 103 — mobile-расширение (§232); перенесено в ядро: у Go-лаунчера
своя реализация (`core/template/on_change.go`, `EvalIfScalar` в
`substitute.go`), семантика идентична mobile-эталону
(`_applyOnChange`, `settings_screen.dart:258-277`).

Поле объявления var:

```json
{"name": "ipv6_enabled", "type": "bool", "on_change": {"set": {
  "@dns_strategy":     {"#if": {"and": ["@ipv6_enabled"], "value": "prefer_ipv4", "else": "ipv4_only"}},
  "@resolve_strategy": {"#if": {"and": ["@ipv6_enabled"], "value": "prefer_ipv4", "else": "ipv4_only"}}
}}}
```

Семантика:

- `on_change.set` — единственная форма сегодня: `{"@target": <#if-дерево>}`
  для одной или нескольких целевых var;
- когда пользователь МЕНЯЕТ значение var (edit-time, в UI визарда/settings —
  НЕ при каждой пересборке конфига), для каждого target его `#if`-дерево
  вычисляется до скаляра (`EvalIfScalar`/`evalIfScalar`, §4.5) **в контексте
  уже НОВОГО значения** изменённой var; результат пишется в целевую var;
- если `#if` не вычисляется (ветка не выбрана, значение — не скаляр), цель
  НЕ трогается;
- рекурсия: после записи цели её собственный `on_change` (если есть)
  применяется тем же ходом — цепочка;
- **fixpoint-guard**: если новое значение цели совпало с уже записанным —
  запись не производится и рекурсия по этой ветке обрывается (защита от
  циклов вида A→B→A, а не только от A→A);
- реализация обязана иметь дополнительный жёсткий предохранитель (лимит
  глубины и/или число посещений одной var в цепочке) на случай топологии,
  которую fixpoint не ловит (например значения, чередующиеся по кругу).

`on_change` — декларативный, разовый эффект переключения: пользователь
может вручную переопределить целевую var после срабатывания, это не
принудительный форс на каждую сборку (в отличие от `#if` внутри `config`,
который пересчитывается при каждой генерации).

### 4.8 `#tpl` — составная строка (ядро, контракт 1.1.86, LxBox §578)

Обычная строка `"@имя"` подставляется только целиком (§3): склеить значение
с литералом нельзя. Для составной строки служит объект с единственным ключом
`#tpl`:

```json
{ "#tpl": "@{node}-dns" }
```

Грамматика:

```
tpl      := { "#tpl": <string> }           — объект РОВНО с одним ключом
<string> := ( литерал | вставка )*
вставка  := "@{" имя "}"                    — имя: как у "@имя", допускает путь через точку
```

| Вопрос | Правило |
|---|---|
| где допустима | на месте значения: поле объекта, элемент массива, в том числе внутри `#value`/`#else` ветки `#if` |
| где недопустима | в ключах объекта; в `default_value` переменной |
| вставка | `@{имя}` и `@{имя.путь}`, любое число раз; пробелы внутри скобок обрезаются |
| `@имя` без скобок внутри строки | литерал, не подстановка |
| значение вставки | скаляр (строка, число, bool) текстом; `@runtime.*` допустим |
| результат | строка |
| имя неизвестно или значение пусто (нет значения, пустая строка, объект, список) | значение снимается ЦЕЛИКОМ: ключ объекта или элемент массива исчезает (Dropped §5.1); у необъявленного имени — ещё `template_var_undeclared {name}` |
| объект с `#tpl` и другими ключами; значение `#tpl` не строка | ошибка шаблона: загрузка отвергает (load `reject`); толерантный рантайм снимает значение с `template_unknown_directive {key: "#tpl"}` |

Обычные строки вне `#tpl` ведут себя как раньше: `"x-@name"` — литерал
(§3, `subst/no_mid_string_interpolation`).

Примеры (корпус `corpus/template/tpl/`):

| Шаблон | Значения | Результат |
|---|---|---|
| `{"server": {"#tpl": "@{name}-dns"}}` | `name=home` | `{"server": "home-dns"}` |
| `{"host": {"#tpl": "@{name}.@{zone}.example"}}` | `name=home, zone=lan` | `{"host": "home.lan.example"}` |
| `{"x": {"#tpl": "@name and @{name}"}}` | `name=home` | `{"x": "@name and home"}` |
| `{"server": {"#tpl": "@{name}-dns"}, "list": ["a", {"#tpl": "@{name}-b"}]}` | `name` без значения | `{"list": ["a"]}` |

## 5. Dropped-каскад и политика unresolved (D-011)

Принята **модель Dart** целиком; Go перешёл на неё полностью (разрыв C4 закрыт, SPEC 143).

### 5.1 Dropped-каскад

Sentinel `Dropped` (`if_engine.dart:21-24`) — «этого значения быть не должно»:

- источники: (а) объявленная переменная со значением `null` (optional-var);
  (б) array-element `#if` со значением `false` без `else`;
- распространение: значение ключа → **ключ удаляется из объекта**; элемент
  массива → **элемент удаляется из массива** (`if_engine.dart:140-148,
  179-186`); каскад идёт снизу вверх без остановки сборки;
- гейты валидности фрагментов пресета (после каскада): rule без
  `outbound`/`action` → фрагмент выпадает (`preset_expand.dart:296-301`);
  dns_rule без `server` и без serverless-`action` → выпадает
  (`preset_expand.dart:234-241`); rule / dns_rule, в котором не осталось ни
  одного поля-условия, матчит весь трафик или все запросы — судьба зависит от
  того, почему условий нет (контракт 1.1.100):
  - **условия снял сбой** → правило выпадает с `template_fragment_dropped`:
    все ссылки `rule_set` висячие (ниже) либо хоть одна ссылка на переменную
    в теле правила (`"@имя"`, вставка `#tpl`) дала Dropped или нулевое
    значение JSON (список ниже). Признак — на всё правило, а не на ключ:
    пустая переменная в поле-не-условии тоже снимает правило без условий
    (сторона осторожности — прежнее поведение). Имена в предикатах `#if` /
    `#enable` не считаются (это выбор ветки, а не значение). Ссылка на
    **необъявленное** имя — тоже сбой (контракт 1.1.103): плейсхолдер
    `"@имя"` остаётся в выводе по §5.2, но правило без условий с
    `"outbound": "@опечатка"` иначе перехватило бы весь трафик в
    несуществующий outbound;
  - **так написал автор** → правило идёт в конфиг как есть с
    `template_rule_unconditional`: условий в теле нет (голый
    `{"action": "sniff"}`, action-правило DNS), литерал без значения
    (`"domain_suffix": []`), условия только в ветках `#if`, которые ложны.
  Правило, целиком снятое ложным `#if`/`#enable`, кода не даёт.
  **Логическое правило** (`"type": "logical"`, контракт 1.1.107): под-правила
  из `rules` судятся тем же гейтом рекурсивно, на любой глубине, при `and` и
  `or` одинаково. Под-правило без условий делает «без условий» всё правило:
  если причина — сбой (признак на всё правило, как выше), всё логическое
  правило выпадает с `template_fragment_dropped`; если так написал автор —
  правило идёт в конфиг с `template_rule_unconditional`. Под-правило, у
  которого висячими оказались все ссылки `rule_set` (при раскрытии или при
  сборке, когда `.srs` не скачан), снимает всё правило; висячее имя рядом с
  живыми убирается. Для `or` пустое под-правило расширило бы совпадение до
  всего трафика, для `and` — молча ослабило бы условие. Кейс —
  `for_each_node/logical_sub_rule_conditions_lost_dropped`. Тело
  `for_each_node_do` судится тем же гейтом: пустой собранный список —
  нулевое значение (§6.7.3, кейс `for_each_node_do/empty_result_rule_dropped`).
  Поля-условия — данные реестра, списки `route_rule_conditions` и
  `dns_rule_conditions` в `registry/allowlists.json` (зеркало полей правила
  ядра; `action`, `outbound` маршрута, опции действий и `invert` условиями
  не считаются, `outbound` DNS-правила — условие). Контракт 1.1.81.
  Ключ-условие с нулевым значением JSON (`null`, `""`, `[]`, `{}`, `false`,
  `0`) условием не считается: ядро по пустому полю сопоставление не строит.
  Висячая ссылка `rule_set` (набора нет после `#if` и Dropped): имя рядом с
  живыми убирается, список сужается; если висячими оказались ВСЕ ссылки,
  правило выпадает целиком с `template_fragment_dropped`, даже когда у него
  остались другие условия, — снятое условие расширило бы совпадение.
  Контракт 1.1.82. То же правило действует при сборке, когда набор не попал
  в `route.rule_set` по другой причине — файл remote `.srs` не скачан: имя
  рядом с живыми убирается, правило маршрута или DNS-правило, у которого не
  осталось ни одной ссылки, выпадает целиком с `template_fragment_dropped`
  (`reason` — `rule_set`), что бы в нём ни осталось (`network`, `port`,
  `server` сужением до набора не являются). Касается правил пресетов и
  пользовательских DNS-правил (у них `owner` — `name` правила или
  `dns_options`). Контракт 1.1.101;
  `required`-переменная пустая → весь пресет
  не собирается и попадает в warnings (`preset_expand.dart:121-144`).

Итог: деградация **пофрагментная** — битая часть пресета выпадает с warning,
остальное живёт. Строгий режим Go (`SubstituteVarsInJSONStrict` →
`UnresolvedVarError` → пресет выбрасывается целиком) упразднён (SPEC 143):
на desktop выпавший фрагмент даёт код `template_fragment_dropped`.

### 5.2 Unresolved var

| Ситуация | Нормативное поведение |
|---|---|
| Имя **не объявлено** в `vars` | плейсхолдер `"@name"` остаётся в выводе **как есть** — опечатка видна в итоговом конфиге и ловится валидатором, а не маскируется пустой строкой |
| Имя объявлено, значение `null` | `Dropped`-каскад §5.1 |
| Имя не объявлено — в `#if`-предикате | предикат `false` + warning |

Разрыв C4 закрыт (SPEC 143): Go во всех путях сборки (главный конфиг,
`on_change.set`, тела пресетов, шаблонные DNS-серверы) идёт каноническим
обходчиком — плейсхолдер остаётся, код `template_var_undeclared`.

## 6. Пресеты

### 6.1 Единая схема (ядро)

```json
{
  "id": "block-ads",
  "label": "Block Ads",
  "description": "…",
  "default_enabled": true,
  "vars":        [ { "name": "out", "type": "outbound", "default_value": "reject", "title": "…" } ],
  "rule_set":    [ { "tag": "ads", "type": "remote", "format": "binary", "url": "…" } ],
  "rules":       [ { "rule_set": "ads", "outbound": "@out" } ],
  "dns_rules":   [ { "…": "…" } ],
  "dns_servers": [ { "tag": "…", "type": "udp", "…": "…" } ]
}
```

- `rules[]` / `dns_rules[]` — канонические списки; сингулярные формы `rule` /
  `dns_rule` — синонимы «список из одного». Обе формы сегодня читает только
  Dart (`parser_config.dart:779, 788`); Go читает сингулярный `dns_rule`
  (`preset_types.go:66`), но не `rule` (`preset_types.go:63` — только `rules`),
  а mobile-шаблон `rule` реально пишет — на desktop такой пресет молча теряет
  правило. Разрыв N11 (ход Go: добавить чтение `rule`).
- Объявления `vars` пресета — та же грамматика §2 (включая толерантность);
  поле дефолта — каноническое `default_value` (сегодня Go-пресеты пишут
  `default` — разрыв N3).
- Каноническое поле идентификатора — `id`, UI-поля (`label`, `description`,
  `default_enabled`) — плоские. Mobile-представление `preset_id` + обёртка
  `ui{}` — текущий разрыв представления (N4); при чтении оба движка обязаны
  принимать обе формы до выравнивания.
- Переносимость: тело пресета живёт в шаблоне каждого приложения; бэкап несёт
  только ссылку `{kind: "preset", ref: "<id>", vars: {…}}` — поэтому общие id
  регистрируются в `contract/registry/presets.json`, а неизвестный id при
  импорте даёт «правило выключено + warning», не потерю.

### 6.2 Неймспейс тегов: префикс `<preset_id>:<tag>` (D-012)

Принята **модель Go** (`preset_types.go:7-8, 47-52, 240-241, 269-271`):

- локальные теги пресета (`rule_set[].tag`, `dns_servers[].tag`) при сборке
  получают автопрефикс `<preset_id>:<tag>` — например `block-ads:ads`;
- внутренние ссылки пресета на локальный тег (`rules[].rule_set`,
  `dns_rule.server`, `detour` и т.п.) резолвятся с тем же префиксом;
- ссылки на глобальные теги шаблона (`direct-out`, `proxy-out`, …) префикса
  не получают;
- цель — детерминированные теги: два включённых пресета не коллидируют, а
  ссылка из бэкапа значит одно и то же на обоих устройствах.

Разрыв C7 ЗАКРЫТ (SPEC 106): Dart префиксует теги пресета так же, как Go.
Историческая справка — до закрытия Dart не префиксовал и решал коллизии
дедупом first-wins +
warning (`preset_expand.dart:473-526`). Миграция LxBox меняет теги собранного
конфига — обязательны heal-редиректы существующих ссылок (route.final, detour,
отметки) и обычный релизный цикл (PLAN §11.6).

### 6.3 `outbounds[]` пресета — desktop-расширение

Блок `outbounds` с `mode: "add" | "update"`, `filters`, `addOutbounds`
(`preset_types.go:98-167`) — модификация глобальных групп из пресета
(пример — `!RU`-фильтры пресетов `russian`/`ru-inside`/`ru-blocked`).
В Dart отсутствует и в ядро не входит; переносимость preset-ссылок не
страдает (§6.1). Прочие односторонние поля пресетов: `platforms`,
`if`/`if_or` на фрагментах, `select: local|global` у var — desktop (§7);
`locked`, `num`, `isSortable`, `enabled: "@var"` на фрагментах, `required`
у var — mobile (§8). Условность фрагментов (`if` vs `enabled`) — открытый
разрыв N6.

### 6.4 Значения переменных записи (D-118)

Два носителя хранят значения переменных, объявленных шаблоном, **в своей
записи состояния и бэкапа**: шаблонный DNS-сервер
(`dns.servers[kind=template].vars`, объявления — `dns_options.servers[].vars`
записи с тем же тегом) и пресет правила (`rules[kind=preset].vars`,
объявления — `presets[].vars` пресета с `id` = `ref`). Нормы одни на оба
носителя и на обе стороны:

- **Н1. Форма.** Объект `string → string`, необязательный; отсутствие ключа и
  пустой объект равнозначны («всё следует шаблону»), пустой объект не
  пишется. У записей других видов `vars` нет.
- **Н2. Имена.** Законны только имена, объявленные носителем в шаблоне
  **своей** стороны. Импорт необъявленное имя выкидывает и называет
  (`backup_var_skipped {reason: undeclared}`), своё хранение снимает молча при
  следующей записи, сборка его не использует никогда. Запись шаблонного
  сервера с тегом, которого шаблон не объявил, — сирота: не эмитится, при
  записи снимается. Нет объявления — нет нормализации (пресет, отфильтрованный
  платформой хоста, `ref`-переменная пресета). Имя с `wizard_ui: "internal"`
  (§2.1) законным для хранения не бывает: импорт снимает его с
  `backup_var_skipped {reason: internal}`, своё хранение — молча, сборка
  значение записи не читает (контракт 1.1.119).
- **Н3. Значения.** Хранятся подрезанными (`TrimSpace`); пустое после подрезки
  значение равно отсутствию ключа.
- **Н4. Умолчание не пишется.** Писатель — UI, импорт, миграция, экспорт —
  снимает ключ, значение которого совпадает с `default_value` объявления в
  шаблоне своей стороны (для цели состояния, §7.4). Выбор умолчания в UI —
  сброс к нему. Читатель значение, равное умолчанию, принимает и снимает при
  следующей записи. Следствие: шаблоны у сторон разные, поэтому незаданное
  значение на другом устройстве берёт умолчание ЕГО шаблона; смена умолчания
  в новой версии шаблона меняет поведение у всех, кто значение не трогал.
- **Н5. Полнота.** Писатель кладёт в `vars` все выбранные значения, не только
  маршрут.
- **Разрешение `@name` в теле шаблонного сервера.** Имя, объявленное сервером:
  значение записи → `default_value` для цели → «не задано», и ключ с этим
  плейсхолдером выпадает. Имя, не объявленное сервером, — у desktop
  расширением переменная шаблона верхнего уровня (локальное имя затеняет
  глобальное); mobile подставляет только объявленные сервером имена.
- **Н11. Необъявленный `@name` — ошибка шаблона.** Плейсхолдер в теле
  шаблонного сервера, не объявленный ни сервером, ни (у desktop) шаблоном, —
  ошибка ШАБЛОНА стороны, а не данных пользователя: валидатор шаблона такой
  шаблон не пропускает.
- **Терпимое чтение.** Корневые `vars.dns_<tag>_<var>` (форма D-117) читатель
  переносит в запись сервера (кандидаты — объявленные пары `(tag, var)`,
  выигрывает самый длинный тег); писатель их не пишет.

Нормы в коде: лаунчер — `core/state/record_vars.go`
(`state.ApplyRecordVars`), мост из шаблона — `core/template/record_var_decls.go`.

### 6.5 `for_each_node` и `for_each_node_do` — пресет по узлам конфига (ядро, контракт 1.1.119, D-130)

Пресет обходит узлы конфига одним из двух ключей:

| Ключ | Тело пресета (`rule_set`, `rules`, `dns_servers`, `dns_rule`, `dns_rules`) | Назначение |
|---|---|---|
| `for_each_node` | повторяется для каждого прошедшего узла, `@node` в scope (§6.6) | фрагменты на каждый узел: маршрут в узел, его DNS-сервер |
| `for_each_node_do` | раскрывается **один раз после обхода**, без `@node` | обход ради сбора значений в переменные пресета (§6.7), одно правило на все узлы |

```json
"for_each_node":    { "#filter": { "#and": [ { "@node.body.type": "tailscale" },
                                             { "#not": "@node.skip_presets" } ] } }

"for_each_node_do": { "#filter": { "@node.body.server": "#notEmpty" },
                      "#do":     { "@domains": { "#append": "@node.body.server" } },
                      "#final":  { "@domains": { "#unique": true, "#sort": true } } }
```

**Допустимые ключи** — закрытый список:

| Ключ | `for_each_node` | `for_each_node_do` | Значение |
|---|---|---|---|
| `#filter` | необязателен | необязателен | условие отбора узла: `cond` языка `#if` (§4.1–4.2) целиком, без обёртки `#if`/`#value` — предикат P1–P6 или список `#and`/`#or`, вложение любой глубины. Нет ключа — истина |
| `#do` | **ошибка загрузки** (тело видит `@node` напрямую) | **обязателен** | сбор значений по узлам, §6.7.1 |
| `#final` | **ошибка загрузки** | необязателен | преобразование собранного после обхода, §6.7.2 |

Ошибка загрузки (пресет отвергается целиком, корпус `load: reject`):

- `for_each` — ключ снят (D-130). Легаси-чтения нет: клиент получает шаблон
  по пину своей версии (`RequiredTemplateRef`), LxBox везёт свой шаблон в
  сборке приложения — шаблона с `for_each` у клиента 1.1.119 не бывает.
  Снятый ключ назван нормой, поэтому правило толерантности §1 (неизвестное
  поле пресета игнорируется) на него не распространяется;
- `node_type` и `as` внутри `for_each_node*` — сняты вместе с `for_each`:
  тип узла выражает `#filter` (`{"@node.body.type": "tailscale"}`, `#in`),
  имя узла фиксировано (§6.6);
- любой иной ключ внутри `for_each_node` / `for_each_node_do`, в том числе
  непомеченный `filter`, `do`, `final` (§4.5.1: алиасов нет);
- оба ключа в одном пресете — допустим ровно один;
- переменная с именем `node` или `node.<…>` — глобальная или пресета (имена
  зарезервированы за узлом, §6.6).

Внутри `for_each_node*` набор ключей закрыт, как у `#tpl` (§4.8): это слова
движка, а не данные, и молча проигнорированный ключ значил бы молча
пропущенный фильтр или сбор.

**Какие узлы обходятся** — те же, что у прежнего `for_each`, по каждому
условию:

1. узел включён;
2. узел попал в конфиг: не снят гейтом реестра, гейтом ядра, деградацией,
   граф-санитайзером;
3. `#filter` истинен. В нём видны имена узла (§6.6), переменные пресета,
   глобальные переменные, `@runtime.*` (desktop, §7.2). Отсутствующее
   значение — ложь, без предупреждения.

`"for_each_node": {}` и `for_each_node_do` без `#filter` обходят все узлы.
Тип узла фильтром не задан — пресет видит узлы любого типа; у кого нет
нужного поля тела, тот отпадает сам (у Tailscale и пиров WireGuard нет
`server`).

- Контейнер значения не имеет: свой сервер, член папки, узел подписки.
- Порядок обхода — порядок узлов в конфиге. У `for_each_node` фрагменты
  повторов идут подряд (все фрагменты первого узла, затем второго).
- Узлов нет — `for_each_node` ничего не выдаёт, конфиг байт в байт прежний;
  у `for_each_node_do` тело раскрывается с несобранными значениями (§6.7.3).
- Переменные пресета (`vars`) общие для всех повторов и для всего обхода.
- **Пространство тегов** (§6.2): у `for_each_node` не действует —
  уникальность даёт тег узла (`{"#tpl": "@{node}-dns"}` → `home-ts-dns`),
  совпадение с тегом пользователя решает общее правило дедупа DNS-тегов
  (первый побеждает). У `for_each_node_do` тело раскрывается один раз без
  узла — действует, как у обычного пресета.
- Раскрытие — в сборке, когда состав узлов окончателен и финальные теги
  назначены. **Проба** (тестовый конфиг узла) не раскрывает ни
  `for_each_node`, ни `for_each_node_do`: пресет с обходом в пробу не идёт.
- Пресет без обхода работает как раньше.

Корпус — два раздела в формате прежнего `for_each/`
(`corpus/template/README.md`: `preset.json` с `preset` и `nodes`,
`vars.json` — значения переменных пресета, `expected.json` с `load?`,
`rules`, `dns_servers`, `dns_rules`, `warnings`):

- `corpus/template/for_each_node/` — переименованный `for_each/`: прежние
  кейсы с теми же именами, переписанные на `#filter` (`node_type` → условие
  на `@node.body.type`, `as: n` → `node`); кейс `missing_as_rejected` снят
  вместе с полем. Отказы загрузки: `load_reject_for_each`,
  `load_reject_node_type`, `load_reject_as`,
  `load_reject_do_in_for_each_node`, `load_reject_unknown_verb`,
  `load_reject_final_without_do`, `load_reject_append_non_list`,
  `load_reject_var_named_node`, `load_reject_unique_non_list`,
  `load_reject_both_loops`.
- `corpus/template/for_each_node_do/`: `collect_domains_filter_ip`,
  `duplicates_without_final`, `final_unique_sort_limit`,
  `final_key_order_irrelevant`, `append_tpl`, `empty_result_rule_dropped`,
  `internal_ignores_state`, `user_value_plus_collected`,
  `unique_declaration`.

Корпус обязателен для обеих сторон.

#### 6.5.1 Пресет `tailscale` (обе стороны, контракт 1.1.86, обход — 1.1.119)

Связку узла Tailscale (маршрут в tailnet и MagicDNS) даёт пресет шаблона, а
не секции узла (упразднены, 1.1.85). Тело одинаковое на обеих сторонах;
оболочка — в диалекте шаблона стороны (лаунчер: `id`, `label`,
`default_enabled`, `num`, `vars[].default`; LxBox: `preset_id`, `ui{}`,
`vars[].default_value`), D-046.

```json
"for_each_node": { "#filter": { "#and": [
  { "@node.body.type": "tailscale" },
  { "#not": "@node.skip_presets" }
] } },
"vars": [ { "name": "dns_enable", "type": "bool", "default": "true" } ],
"rules": [
  { "#if": { "#and": ["@dns_enable"], "#value": {
      "preferred_by": ["@node"], "action": "resolve",
      "server": { "#tpl": "@{node}-dns" } } } },
  { "preferred_by": ["@node"], "outbound": "@node" }
],
"dns_servers": [
  { "#if": { "#and": ["@dns_enable"], "#value": {
      "type": "tailscale", "tag": { "#tpl": "@{node}-dns" },
      "endpoint": "@node", "description": "MagicDNS of the tailnet" } } }
],
"dns_rules": [
  { "#if": { "#and": ["@dns_enable"], "#value": {
      "preferred_by": [ { "#tpl": "@{node}-dns" } ],
      "server": { "#tpl": "@{node}-dns" } } } }
]
```

До 1.1.119 тот же отбор писался `"for_each": {"node_type": "tailscale",
"as": "node", "filter": {"#not": "@node.skip_presets"}}`; результат сборки
не изменился.

Позиция на оси правил — `num: 945` (раньше `private-ips` 950), включён по
умолчанию. Что попадает в конфиг для узлов `home-ts`, `work-ts`:

| Куда | Запись |
|---|---|
| `route.rules` | `{preferred_by: [home-ts], action: resolve, server: home-ts-dns}` |
| `route.rules` | `{preferred_by: [home-ts], outbound: home-ts}` |
| `route.rules` | то же для `work-ts` |
| `dns.servers` | `{type: tailscale, tag: home-ts-dns, endpoint: home-ts}`, то же для `work-ts` |
| `dns.rules` | `{preferred_by: [home-ts-dns], server: home-ts-dns}`, то же для `work-ts` |

`dns_enable = false` снимает DNS-сервер, DNS-правило и правило `resolve`;
правило маршрута остаётся. Условие `preferred_by` — живой ответ узла (имена и
адреса машин tailnet, принятые подсети); постоянных подсетей
`100.64.0.0/10`, `fd7a:115c:a1e0::/48` и суффикса `.ts.net` нет (D-120,
подтверждено LxBox; `preferred_by` в DNS-правиле — новое относительно D-120).

**`preferred_by` в DNS-правиле называет сервер, в правиле маршрута — узел**
(контракт 1.1.90). Ядро разбирает поле по-разному: в правиле маршрута ищет тег
через менеджер outbound/endpoint (`route/rule/rule_item_preferred_by.go`), в
DNS-правиле — через менеджер DNS-серверов (`rule_item_preferred_by_dns.go`,
отказ `DNS server not found: <тег>`). Тег узла в DNS-правиле валит старт ядра,
поэтому там стоит `<тег>-dns` — тот же сервер, что в `server`.

### 6.6 Доступ к узлу `@node` (ядро, контракт 1.1.86; имя фиксировано — 1.1.119)

В `#filter` обоих ключей, в правых частях `#do` и в теле пресета с
`for_each_node`:

| Запись | Значение | Источник |
|---|---|---|
| `@node` | финальный тег узла в конфиге | сборка |
| `@node.<поле>` | поле ЗАПИСИ узла из закрытого перечня | запись |
| `@node.body.<путь>` | поле тела узла (в форме конфига), путь через точку | тело |

- Имя `node` фиксировано (до 1.1.119 его задавал ключ `as`). Имена `node` и
  `node.*` зарезервированы: переменная с таким именем — глобальная или
  пресета — ошибка загрузки (§6.5). Вложенных обходов нет, второе имя не
  нужно.
- Поля записи, видимые пресету: **`skip_presets`** (bool, BACKUP.md
  «Поддержка»). Перечень закрытый, расширяется контрактом.
- У узла подписки записи нет: `@node.skip_presets` всегда ложь.
- Значение поля тела — любого JSON-типа: строка, число и bool подставляются
  как есть, объект и массив — копией.
- **Отсутствующее поле** (нет пути, null, пустая строка, поле записи вне
  перечня) — пустое значение: в условии ложь, в теле пресета ключ или элемент
  снимается (Dropped §5.1), как у необязательной переменной. Предупреждения
  нет: имена `@node.…` объявлены все.
- Вставка `#tpl` читает те же имена: `{"#tpl": "@{node.body.hostname}"}`.
- Тело пресета с `for_each_node_do` и `#final` узла не видят: тело
  раскрывается после обхода. `@node…` там — необъявленное имя (§5.2:
  плейсхолдер остаётся, `template_var_undeclared {name}`; в правиле — сбой,
  правило без условий выпадает, §5.1).

### 6.7 `#do` и `#final` — сбор значений по узлам (ядро, контракт 1.1.119, D-131)

Только в `for_each_node_do`. `#do` говорит, **что** собрать с каждого
прошедшего узла, `#filter` — **с каких** узлов; `#final` — одно чистое
преобразование собранного. Язык декларативный: шагов «до» и «после»,
выражений внутри ссылок (`@nodes.filter(…)`), `#set`, `#init` нет —
объявление переменной живёт в `vars`, второго места для него нет.

#### 6.7.1 `#do`

```json
"#do": {
  "@domains": { "#append": "@node.body.server" },
  "@tags":    { "#append": { "#tpl": "@{node}-out" } }
}
```

- Объект «`"@имя"` → операция». Ключ без `@` — ошибка загрузки.
- Имя обязано быть объявлено в `vars` **этого** пресета. Глобальная
  переменная, переменная другого пресета, необъявленное имя — ошибка
  загрузки: обход пишет только в своё.
- Операция — объект **ровно с одним глаголом**. Список глаголов закрыт;
  в 1.1.119 он один:

| Глагол | Тип переменной | Действие |
|---|---|---|
| `#append` | только `text_list`; иной тип — ошибка загрузки | добавить значение правой части в конец списка, для каждого прошедшего узла в порядке обхода |

- Неизвестный глагол, второй глагол в операции, операция не-объект —
  ошибка загрузки. Одна операция на переменную в одном `#do` (повтор ключа
  JSON невалиден и так).
- Правая часть `#append` — строка-ссылка (`"@node"`, `"@node.<поле>"`,
  `"@node.body.<путь>"`, `"@имя"`) или вставка `{"#tpl": "…"}` (§4.8).
  Объект (кроме `#tpl`) и массив в правой части — ошибка загрузки.
- Значение правой части на узле вычисляется как вставка `#tpl` (§4.8):
  скаляр (строка, число, bool) идёт текстом. Пустое значение — нет пути,
  null, `""`, объект, список — **узел пропускается молча**, как Dropped в
  теле: ни элемента, ни предупреждения.
- `#append` — чистое добавление, **без дедупа**: два узла с одним сервером
  дают два элемента. Уникальность — явное решение автора: `#final` (§6.7.2)
  или `unique` в объявлении (§2.1).
- `#do` в `for_each_node` — ошибка загрузки.

#### 6.7.2 `#final`

```json
"#final": { "@domains": { "#unique": true, "#sort": true, "#limit": 200 } }
```

- Объект «`"@имя"` → набор глаголов», применяется **один раз после
  обхода** к собранному списку. Имя обязано присутствовать в `#do` этого
  пресета, иначе ошибка загрузки. `@node` не виден, условий нет.
- Глаголы — закрытый список чистых преобразований `text_list`:

| Глагол | Значение | Действие |
|---|---|---|
| `#unique` | bool | `true` — дубли сняты, порядок первого появления |
| `#sort` | bool | `true` — сортировка по строке, байтовый порядок по возрастанию |
| `#limit` | int > 0 | первые N элементов |

- Другой ключ или не тот тип значения (`#limit: 0`, `#limit: "200"`,
  `#sort: "yes"`) — ошибка загрузки.
- **Порядок применения фиксирован нормой, а не порядком ключей JSON:**
  `#unique` → `#sort` → `#limit`. `{"#limit": 2, "#sort": true}` и
  `{"#sort": true, "#limit": 2}` дают одно и то же (кейс
  `final_key_order_irrelevant`): порядок ключей объекта JSON не значим, и
  разборщик стороны не обязан его сохранять.
- `#final` в `for_each_node` — ошибка загрузки.

#### 6.7.3 Сборка `for_each_node_do`

Шаги, в этом порядке:

1. **Переменные пресета поверх глобалей** — как у любого пресета. База
   переменной, в которую пишет `#do`: у пользовательской — ввод
   пользователя (значение записи `vars`, при его отсутствии `default_value`);
   у `wizard_ui: "internal"` — только `default_value` (значение из состояния
   и бэкапа игнорируется, §2.1). При `unique` база уже без дублей.
2. **Обход** узлов (§6.5) с `#filter`.
3. **`#do`** — на каждом прошедшем узле, в порядке обхода, добавляет к базе.
4. **`#final`** — один раз, `#unique` → `#sort` → `#limit`.
5. **`unique` объявления** (§2.1) — к итогу; с `#final.#unique` совместимо
   (идемпотентно).
6. **Тело раскрывается один раз** с итоговыми значениями, без `@node`.

- **Собранное не персистится.** Сбор идёт в копию значения на время
  сборки; в состояние и в LX Backup уходит только ввод пользователя (норма
  `vars` записи `kind: preset` — BACKUP.md, §6.4 этой спеки, без изменений).
  Пользователь видит в форме свои строки, а не собранные; следующая сборка
  собирает заново из текущего состава узлов.
- **Пустой итог.** Пустой собранный список подставляется как любой
  `text_list` (§2.2) — `[]`; ключ не снимается (кейс
  `types/text_list_empty_becomes_empty_array`). Дальше решает гейт
  фрагментов §5.1: `[]` — нулевое значение JSON, условием не считается.
  - Правило маршрута или DNS-правило, у которого **каждое** условие
    оказалось пустым или отсутствующим, снимается целиком («условия снял
    сбой») с кодом `template_fragment_dropped` — как в теле `for_each_node`
    (кейсы `for_each_node/rule_conditions_lost_var_dropped`,
    `for_each_node/logical_sub_rule_conditions_lost_dropped`); для тела
    `for_each_node_do` — кейс `empty_result_rule_dropped`. Правило без
    условий перехватило бы весь трафик или все запросы.
  - Правило, у которого осталось другое условие, идёт в конфиг как есть,
    с `"domain": []`: ядро пустое поле условием не считает, правило матчит
    по оставшимся.
- Предупреждения тела — как у обычного пресета: тело раскрывается один раз,
  дублей по узлам не бывает.

#### 6.7.4 Пример `for_each_node_do` (в шаблон не входит)

Одно DNS-правило со всеми доменными серверами узлов. Пример показывает
язык, а не рецепт: в шаблоны сторон пресет не входит — для имён серверов
узлов DNS-правила не действуют. У исходящего с `domain_resolver` (а
`route.default_domain_resolver` в обоих шаблонах задан всегда) ядро резолвит
адрес сервера прямо этим DNS-сервером и DNS-правила не смотрит. Свежие имена
узлов дают поля объектной формы резолвера (§6.9).
Оболочка — диалект лаунчера (`id`, `label`, `num`, `vars[].default`).

```json
{
  "id": "node-domains-fresh-dns",
  "label": "Node hostnames: fresh DNS",
  "description": "Resolve the hostnames of your nodes through a chosen resolver and never serve a stale answer for them.",
  "default_enabled": true,
  "vars": [
    { "name": "resolver", "type": "dns_server", "default": "direct_dns_resolver", "title": "Resolver",
      "tooltip": "Which DNS server resolves node hostnames. Must not go through the proxy itself." },
    { "name": "domains", "type": "text_list", "unique": true, "title": "Extra domains",
      "tooltip": "Hostnames of every node are collected automatically; add your own here." }
  ],
  "for_each_node_do": {
    "#filter": { "#and": [
      { "@node.body.server": "#notEmpty" },
      { "#not": { "@node.body.server": { "#matches": "^[0-9.]+$" } } },
      { "#not": { "@node.body.server": { "#matches": ":" } } }
    ] },
    "#do": { "@domains": { "#append": "@node.body.server" } }
  },
  "dns_rules": [
    { "domain": "@domains", "server": "@resolver", "disable_optimistic_cache": true }
  ],
  "num": 10
}
```

- `#filter` отсекает узлы без `server` и с адресом вместо имени (IPv4 —
  только цифры и точки, IPv6 — есть `:`). Фильтра по типу нет.
- `domains` — пользовательская переменная: строки пользователя — база,
  собранные имена добавляются на время сборки; `unique` снимает дубли (два
  узла на одном сервере, имя и у пользователя, и у узла).
- Узлов с доменным сервером нет и пользователь ничего не ввёл →
  `"domain": []`, других условий у правила нет — правило снято целиком с
  `template_fragment_dropped`.
- Пример с переменной только для сборки: объявить
  `{"name": "node_hosts", "type": "text_list", "wizard_ui": "internal"}` и
  писать `#do` в неё — строки в форме не будет, ввод пользователя не
  смешивается с собранным.

Для узлов `a` (`server: "a.example"`), `b` (`server: "1.2.3.4"`),
`c` (`server: "a.example"`), `ts` (Tailscale, без `server`) и ввода
пользователя `extra.example`:

| Куда | Запись |
|---|---|
| `dns.rules` | `{domain: [extra.example, a.example], server: <resolver>, disable_optimistic_cache: true}` |

#### 6.7.5 Появление у существующих пользователей

Пресет, включённый по умолчанию и добавленный в шаблон позже (например `tailscale`,
§6.5.1), появляется в состоянии сам, один
раз; удалённый пользователем — не возвращается. Механизм у каждой стороны
свой (LxBox — `seedLateDefaultPresets`, ключ `late_presets_seeded`; лаунчер —
`state.SeedLateDefaultRules`, отметка `meta.late_presets_seeded` в
`state.json`); список поздних дефолтов только растёт.

### 6.8 Кэш DNS: три переменные (обе стороны, контракт 1.1.93, LxBox §580)

Оба шаблона объявляют три переменные с одинаковыми именами, типами и
значениями по умолчанию (одно значение для всех платформ) и подставляют их в
одни и те же поля конфига:

| Переменная | Тип | По умолчанию | Допустимо | Поле конфига |
|---|---|---|---|---|
| `dns_cache_capacity` | `int` | `4000` | 1024..65535 | `dns.cache_capacity` |
| `dns_optimistic` | `bool` | `true` | | `dns.optimistic` |
| `dns_store_cache` | `bool` | `true` | | `experimental.cache_file.store_dns` |

Верхняя граница 65535 совпадает с отсечкой int-подстановки (§2.2); исключений
из отсечки нет (решение владельца 27.09.2026, контракт 1.1.94).

- `cache_capacity` — число записей, не байты; ниже 1024 ядро само поднимает
  значение до 1024. Значение вне границ интерфейс не сохраняет; сохранённое
  вне границ (правка файла руками) сборка не подставляет — действует
  значение по умолчанию.
- `optimistic` подставляется только как bool; объектная форма ядра
  (`{enabled, timeout}`) не используется, срок годности устаревшего ответа —
  срок ядра (3 суток после истечения TTL).
- `store_dns` — соседнее поле `cache_file` (`enabled`, `path`,
  `store_fakeip`), путь к файлу не меняется.
- Переменные новые: у состояния без них действуют значения по умолчанию,
  отдельного переноса нет. Все три — на экране настроек DNS, изменение
  помечает конфиг как требующий пересборки.

### 6.9 Резолвер по умолчанию — объект (обе стороны, контракт 1.1.119)

`route.default_domain_resolver` в обоих шаблонах — объектная форма ядра
(`DomainResolveOptions`):

```json
"default_domain_resolver": {
  "server": "@dns_default_domain_resolver",
  "disable_optimistic_cache": "@dns_resolver_no_stale"
}
```

| Переменная | Тип | По умолчанию | `wizard_ui` | Поле конфига |
|---|---|---|---|---|
| `dns_default_domain_resolver` | `text` | `direct_dns_resolver` | `fix` | `route.default_domain_resolver.server` |
| `dns_resolver_no_stale` | `bool` | `true` | `fix` | `route.default_domain_resolver.disable_optimistic_cache` |

- Резолвер по умолчанию резолвит имена, к которым ядро подключается само:
  серверы узлов и прочие адреса исходящих без своего `domain_resolver`. С
  `disable_optimistic_cache: true` ответ с истёкшим TTL не отдаётся из
  оптимистичного кэша (`dns.optimistic`, §6.8) — имя резолвится заново, и
  узел провайдера, сменившего адрес, не остаётся на старом. На DNS-запросы
  приложений поле не влияет: их ведут `dns.rules` и `dns.optimistic`.
- `bool` подставляется JSON-литералом (§2.2): выключено — `false`, ключ
  остаётся. Ядро принимает `{"server": …}` с `false` и без поля; одно
  `server` оно само сериализует обратно строкой.
- Подпись и подсказка — на экране настроек DNS, под выбором резолвера по
  умолчанию; изменение помечает конфиг как требующий пересборки. Переменная
  переносимая (`registry/vars.json`), в бэкапе — как `dns_optimistic`.
- Читатель ключа понимает обе формы — строку (тег) и объект с `server`;
  кто подменяет резолвер (выбор на экране DNS, замена выпавшего сервера при
  сборке), меняет только `server`, остальные поля объекта остаются.
- Кейсы корпуса: `subst/default_resolver_object_defaults`,
  `subst/default_resolver_object_off`.

## 7. Расширения desktop (каждое — вне ядра)

### 7.1 `params[]`

Dot-notation патчи конфига до var-подстановки
(`loader.go:192-200`, `substitute.go` applyParam/applyValue):
`{"name": "route.rules", "mode": "replace|prepend|append", "value": …,
"if"/"if_or": […], "platforms": […]}`. Предикаты `if`/`if_or` — та же
грамматика §4.2.

### 7.2 `@runtime.*`

Глобальные значения окружения сборки: `@runtime.platform`, `@runtime.arch`,
`@runtime.target` (TargetSpec; `substitute.go:runtimeGlobalFields`). Допустимы в
предикатах и в `#if`-деревьях `default_value`; bare-форма в предикатах
запрещена. На mobile отсутствуют by design (одна платформа) — предикаты с
ними обязаны вычисляться в `false` (§4.2).

**В позиции значения** (SPEC 143, D-127): `"@runtime.platform"`,
`"@runtime.arch"`, `"@runtime.target"` допустимы как значение ключа объекта и
элемент массива в любой секции — `config`, `params[].value`, тела пресетов и
шаблонных DNS-серверов, `on_change.set`. Desktop подставляет строку.

- **Mobile:** имена `runtime.platform`, `runtime.arch`, `runtime.target`
  считаются **ОБЪЯВЛЕННЫМИ со значением `null`** — ключ или элемент выпадает
  (Dropped, §5.1), а **не** остаётся плейсхолдером как необъявленное имя
  (§5.2).
- **Неизвестное поле** после `@runtime.` (`"@runtime.foo"`) на обеих сторонах
  даёт `template_var_undeclared {name}` и остаётся плейсхолдером (§5.2).
- Bare-форма `"@runtime.x"` в предикатах по-прежнему запрещена (§4.2).

### 7.3 Секретные переменные: автогенерация

`MaybeGenerateSecrets` (`vars_resolve.go:19-27, 288-309`): переменной
`type: "secret"` с пустым значением или значением с префиксом `CHANGE_THIS_`
генерируется случайное значение.

### 7.4 Per-platform `default_value`

`default_value` — объект `{"windows"|"linux"|"darwin"|"win7"|"default":
<строка | #if-дерево>}` (`vars_default.go:15-21, 45-61, 95-107`); значения
могут быть `#if`-деревьями с `@runtime.*`. Dart сегодня схлопывает объект в
ключ `default` (`parser_config.dart:570-576`) — допустимое поведение
«не-поддерживающей» стороны.

### 7.5 Прочее

`separator`-записи в `vars[]` (визуальные разделители), `default_node`
(фолбэк из JSON-пути шаблона, `vars_resolve.go:331-339`), `platforms` и
`if`/`if_or` на объявлении var («скрыть vs погасить»,
`vars_resolve.go:483-509`), `wizard_ui: "target"`.

набор. Лаунчер засевается из `parser_config.outbounds` и эту секцию не
читает.
