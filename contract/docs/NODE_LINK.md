# Ссылка на узел: NodeLink — норма для всех проектов (контракт 1.0.x)

> **О чём этот документ.** Единственная допустимая форма ссылки на узел во
> всех проектах: `{folder_id, tag}` — id контейнера и сырой тег узла в нём.
> Почему не финальный тег из конфига (он производный и меняется от правок,
> к узлу не относящихся), где ссылка обязательна, где запрещена, как
> резолвится при сборке и как переживает экспорт и импорт.
>
> **Кому читать.** Тому, кто хранит указатель на узел: detour, цепочки,
> члены групп, Направления, `@self` в секциях узла.
>
> **Что знать заранее.** Сырой тег против финального — `IDENTITY.md` §1 и
> §3 этого документа; контейнер — `GLOSSARY.md`.

Статус: **норма** (D-112, решение владельца 14.09.2026; группы, `default` и
Направления без узлов — D-115, 15.09.2026). Действует у лаунчера
(singbox-launcher), у LxBox, в контракте (схема и корпус бэкапа) и в API обеих
сторон. Контракт 1.0.1 (`contract/VERSION`): форма согласована с LxBox
(`TASKS_LXBOX.md` §17.8).

Формулировка владельца: «ссылки на ноды в формате {folder_id, tag} должны
стать форматом по всем проектам нашим».

Смежные нормы: `IDENTITY.md` §1–§2 (идентичность узла = тег), `BACKUP.md`
§4/§6/§9 (перенос), `NODE_SECTIONS.md` (`@self`), `ONE_NAMESPACE.md` §1.
Адреса кода лаунчера (`файл:строка`) даны по ветке `develop` на момент влития
документа — это справка для сверки, а не норма: сдвинулся код — правится
адрес. Поведение сборки, описанное в §5, проверено прогоном конвейера
лаунчера на синтетических источниках, а не только чтением.

## 1. Зачем

Финальный тег узла в `config.json` — производная, а не имя. У члена папки или
подписки он складывается из политики контейнера, сырого тега и глобальной
уникализации (§3) и потому меняется от правок, к самому узлу не относящихся:
префикс подписки, перенос узла в другую папку, одноимённый сосед в соседнем
источнике. Ссылка, хранящая финальный тег, — кэш, который протухает молча:
тот же класс багов, из-за которого SPEC 112 снёс контент-хэш (`IDENTITY.md`
§2.1).

NodeLink хранит то, что от этих правок не зависит, — **id контейнера и сырой
тег узла в нём**. Отсюда:

- **переименование папки или подписки** (`name`) ссылок не касается: адрес —
  `id`, а не имя;
- **смена `tag_policy`** (префикс, суффикс) меняет только финальные теги, ни
  одна ссылка не переписывается — главное преимущество модели (лаунчер:
  `core/config/canonical_emit.go:28-29`, тест
  `core/config/canonical_emit_test.go:151-170`);
- **обновление подписки** сливает узлы по сырому тегу и переносит `enabled` и
  `detour` совпавших, поэтому ссылки на них живут
  (`core/state/subscription_merge.go:8-10`, `49-75`, `110-131`);
- **перенос на другую машину**: id контейнеров переписываются по карте (§7.2),
  сырые теги у обеих сторон одинаковы (`IDENTITY.md` §1).

Финальный тег вычисляется каждой сборкой и не лежит ни в хранении, ни в
бэкапе, ни в API (`BACKUP.md` §2, П5).

## 2. Форма

```json
{ "folder_id": "<ULID папки или подписки>", "tag": "<сырой тег узла внутри неё>" }
```

| Поле | Тип | Обязательность | Смысл |
|---|---|---|---|
| `tag` | string, непустой | всегда | член контейнера — СЫРОЙ тег узла; корневая цель — тег корневого узла или корневое имя (§5.2) |
| `folder_id` | string | у члена контейнера ОБЯЗАТЕЛЕН; у корневой цели отсутствует | `id` записи `sources[]` вида `folder` или `subscription` — единственная идентификация контейнера |

Правила записи — у обеих сторон одинаковые:

1. Член контейнера адресуется ТОЛЬКО парой. Ссылку `{tag}` на члена папки или
   подписки писатель не создаёт; читатель её терпит (§7.3).
2. Корневая ссылка — объект без ключа `folder_id`, пустой строкой он не
   пишется (лаунчер: `omitempty`, `core/state/sources_v7.go:41-42`). Читатель
   трактует отсутствие ключа и пустую строку одинаково.
3. При заданном `folder_id` в `tag` лежит сырой тег, никогда не финальный:
   `"US-1"`, а не `"nl:US-1"`.
4. Других ключей у ссылки нет. Подпись для UI (`detour_node_label` формата
   0.12) снята: имя узла и есть его тег (SPEC 112).
5. `id` КОРНЕВОГО узла (`sources[].id` у `server` и `chain`) адресом не
   является: корневой узел адресуется `{tag}`, у члена папки своего `id` нет
   вовсе (`BACKUP.md` §2).

Лаунчер: `state.NodeLink` — `core/state/sources_v7.go:39-45`; сборочное
зеркало — `core/config/configtypes/types.go` (`NodeLink`, те же json-имена).
Схема — `schema/backup.schema.json` `$defs/nodeLink`: пара обязательна у члена
папки и подписки, `tag` сырой, «Поддержка: обе» (контракт 1.0.1); у `detour`
в `BACKUP.md` §2 — тоже «обе».

### 2.1 Примеры

Корневой узел:

```json
"detour": { "tag": "relay-root" }
```

Член папки: папка «Work» с `tag_policy.prefix = "[W] "`, в конфиге узел
зовётся `[W] de-1`:

```json
"detour": { "folder_id": "01FLDWORK00000000000000000", "tag": "de-1" }
```

Член подписки: подписка с `tag_policy.prefix = "nl:"`, в конфиге узел зовётся
`nl:US-1`. Позиции цепочки вперемешку:

```json
"hops": [
  { "tag": "relay-root" },
  { "folder_id": "01FLDWORK00000000000000000", "tag": "de-1" },
  { "folder_id": "01SUBNL0000000000000000000", "tag": "US-1" }
]
```

Члены и умолчание провайдерской группы той же подписки — ссылки одной формы
(`default` объектом с контракта 1.0.1; строка — dev-форма, §7.3):

```json
"group": {
  "group_type": "selector",
  "default": { "folder_id": "01SUBNL0000000000000000000", "tag": "US-1" },
  "members": [
    { "folder_id": "01SUBNL0000000000000000000", "tag": "US-1" },
    { "folder_id": "01SUBNL0000000000000000000", "tag": "US-2" }
  ]
}
```

Позиция на саму провайдерскую группу `Best` этой подписки (в конфиге она
зовётся `nl:Best`) — пара с СЫРЫМ тегом группы; на свёртку папки — корневое
имя `replace.tag`:

```json
"hops": [
  { "folder_id": "01SUBNL0000000000000000000", "tag": "Best" },
  { "tag": "Work-pick" }
]
```

Сырой тег группы уникализируется в подписке ТЕМ ЖЕ счётчиком, что и узлы
(`X`, `X-2`), до всякой `tag_policy`, и ПОСЛЕ всех узлов: группа-тёзка узла
получает `X-2`, где бы ни стояла в теле (`IDENTITY.md` §1.3; лаунчер —
`core/config/subscription/parse_body.go`, `finish`; LxBox — ответ на вопрос 2,
§9.4).

### 2.2 Узел подписки: что лежит в `folder_id` и `tag`

**`folder_id` — `id` самой подписки**, записи `sources[]` вида
`subscription`. Подписка — такой же контейнер, как папка, и другого адреса у
её узлов нет.

- Лаунчер: проекция подписки отдаёт `ProxySource.ID = s.ID` и
  `CanonicalSource.FolderID = s.ID` (`core/state/adapter_source.go:33-50`,
  `100-110`); словарь целей сборки кладёт узлы ЛЮБОГО контейнера в
  `byFolder[FolderID]` (`core/config/nodelink_resolve.go:82-110`). Ссылки
  внутри подписки fetch материализует её же id: члены провайдерской группы —
  `core/config/migrate_materialize.go:138-142`, detour владельца на релей
  BYPASS — `core/config/relay_materialize.go:118-133`; `subID` там —
  `src.ID` (`core/config_service_subscriptions.go:164`).
- Это **не** id папки, в которую подписку «заливают». Заливка создаёт в папке
  КОПИИ узлов с собственным адресом `{id папки, тег копии}`
  (`core/state/subscription_merge.go:172-286`): ссылка на копию и ссылка на
  оригинал в подписке — разные ссылки.
- Это **не** свёртка. Свёртка (`replace`) — группа с корневым именем, её
  адресуют корневой ссылкой `{tag: "<replace.tag>"}` (§5.2).

**`tag` — сырой тег узла в подписке**: имя от провайдера (фрагмент ссылки,
`tag` / `ps` / `remarks` записи тела), уникализированное В ПРЕДЕЛАХ подписки
(`X`, `X-2`, `X-3`) до всякой `tag_policy` (`IDENTITY.md` §1;
`core/state/sources_v7.go:201-204`). Служебный релей BYPASS получает тег
`<тег владельца> · relay` (`core/config/relay_materialize.go:48`).

Обновление подписки и ссылка на её узел (`core/state/subscription_merge.go:77-170`):

| У провайдера | Узел в `nodes[]` | Ссылка на узел |
|---|---|---|
| узел остался под тем же именем | тело освежено, `enabled` и `detour` перенесены (`49-75`, `124-129`) | жива |
| узел исчез | удалён (`133-142`) | висячая: detour и позиция — fail-closed, член группы — prune (§5) |
| узел переименован | прежний удалён, новый добавлен включённым | висячая: за переименованием у провайдера ссылка НЕ следует (`IDENTITY.md` §1.2) |
| ответ обрезан капом | исчезнувшие не удаляются (`134-140`) | жива |
| ответ недостоверный | `nodes[]` не трогаются (`103-105`) | жива |
| подписка выключена | узлы не собираются | не разрешается на этой сборке (`it has no node`), оживает с включением |

Узлы подписки в бэкап не едут (`BACKUP.md` §2): до первого обновления на
приёмнике ссылка на член подписки не разрешается, и это не потеря.

## 3. Сырой тег против финального

**Сырой тег** (`sources[].tag`, `nodes[].tag`) — имя узла и его идентичность
в контейнере (SPEC 112). На нём живут merge-ключ обновления, `enabled`,
отметки `disabled{}` и ссылки NodeLink.

**Финальный тег** — имя outbound'а в `config.json`. Формула сборки лаунчера
(`core/config/canonical_emit.go:413-465`):

```
член контейнера:  final = uniq( norm( expand(prefix) + tag + expand(postfix) ) )
корневой узел:    final = uniq( norm( tag ) )
```

- `expand` — переменные `{$tag} {$scheme} {$protocol} {$server} {$port}
  {$label} {$comment} {$num}` (`canonical_emit.go:448-465`); `{$tag}` — сырой
  тег, `{$num}` — порядковый номер узла в контейнере, выключенные считаются
  (`canonical_emit.go:83-106`);
- `norm` — ремонт UTF-8, `❯ » ›` → ` > `, цветные геометрические эмодзи →
  `*`, схлопывание пробелов, обрезка краёв
  (`internal/textnorm/proxy_display.go:12-32`);
- `uniq` — ГЛОБАЛЬНАЯ уникализация на всю сборку (`X`, `X-2`) в порядке
  `sources[]`: выключенный узел включённого контейнера слот потребляет
  (`canonical_emit.go:66-75`), неразобранная запись — нет
  (`core/state/adapter_source.go:117-127`), выключенный источник целиком — нет
  (`core/config/outbound_generator.go:1282-1286`).

Уникальность:

- сырой тег уникален В КОНТЕЙНЕРЕ; правка, дающая дубль, отвергается
  (лаунчер: `ui/configurator/tabs/source_edit_window.go:2362-2366`,
  `ui/configurator/tabs/preview_node_ops.go:434-439`);
- тег корневого узла уникален в КОРНЕВОМ пространстве — среди корневых узлов,
  цепочек, Направлений и их `-auto`, тегов свёрток и их `-auto`, системных
  тегов шаблона (гард — `SPECS/features/directions.md` §8);
- корневая ссылка адресует ФИНАЛЬНЫЙ тег корневого узла
  (`core/config/nodelink_resolve.go:112-120`). Он равен хранимому, пока тег
  нормализован и не столкнулся на `uniq` с финальным тегом члена контейнера,
  стоящего в `sources[]` выше: такое столкновение даёт корневому узлу суффикс
  `-2`, и корневая ссылка на него перестаёт разрешаться. Держать тег корня
  нормализованным и уникальным — обязанность писателя.

## 4. Где NodeLink обязателен и где запрещён

### 4.1 Обязателен: всякая ссылка «через кого»

| Место | Хранение (лаунчер, state v8) | Бэкап 1.0 | Сборка |
|---|---|---|---|
| личный detour узла `server` (в корне и в контейнере) | `Node.Detour` (`sources_v7.go:219-222`) | `sources[].detour`, `nodes[].detour` | fail-closed |
| общий detour контейнера (папка, подписка) | `detour` записи контейнера | `detour` у `folder` / `subscription` | fail-closed; действует на `server` без личного, `chain` и `auto` пропускает (`canonical_emit.go:132-148`) |
| позиции цепочки, ближний хоп первым | `Node.Hops` (`sources_v7.go:223-224`) | `hops[]` | fail-closed, цепочка целиком |
| члены провайдерской группы `auto` | `AutoGroup.Members` (`sources_v7.go:102-119`) | `group.members[]` | prune |
| умолчание селектора `auto` | `AutoGroup.Default` — `*NodeLink` (`sources_v7.go:102-119`; чтение строки — `UnmarshalJSON`, `121-177`) | `group.default` | снимается с ⚠, группа живёт (`nodelink_resolve.go:508-528`) |

У `chain` и `auto` detour не существует типом (`sources_v7.go:603-622`).

**API.** Ручка, адресующая узел хранения (прочитать, изменить, удалить по
адресу), принимает и отдаёт NodeLink. Лаунчер сегодня отдаёт ссылки как лежат
в `GET /state/full` (форма state v8, `core/debugapi/state_endpoints.go:133-138`)
и в `GET /backup/export`; ручек, адресующих узел хранения для правки, у него
нет. Рантайм-ручки говорят финальным тегом — это не хранение (§4.3).

**UI.** Окно, открытое на узле, держит его адрес NodeLink, а не индекс в
списке: индекс протухает от перетаскивания и удаления соседей (лаунчер:
`ui/configurator/business/node_address.go:1-8`, `70-102`).

### 4.2 Запрещён: внутри `body`

`body` — объект sing-box как есть (`ONE_NAMESPACE.md`, `BACKUP.md` §2). Внутри
него живут только ФИНАЛЬНЫЕ теги, и вписывает их сборка:

- `tag` и `detour` из тела outbound'а сняты при материализации
  (`core/config/migrate_materialize.go:274-290`); «через кого» — поле записи,
  сборка подставляет его резолвом (`core/config/nodelink_resolve.go:396-399`);
- цель правила маршрута (`rules[].body.outbound`) и `route.final`;
- `detour` DNS-сервера (`dns.servers[].body.detour`) и `server` DNS-правила;
- `@self` / `@{self}` в секциях узла — финальный тег ЭТОГО узла, подставляет
  сборка (`NODE_SECTIONS.md`); сам узел для подстановки находится по паре
  `{id контейнера, сырой тег}` (`core/config/canonical_emit.go:212-218`).

Объект NodeLink внутри `body` не пишется никогда: ядро его не понимает, а
сборка тело не разбирает.

### 4.3 Не ссылки на узел

| Что | Чем адресует | Почему не NodeLink |
|---|---|---|
| отбор Направления (`filter`, `invert`) и его умолчание (`default`) | регулярка по финальному тегу | отбор множества, а не ссылка |
| `directions[].include` (addOutbounds) | ОБЪЯВЛЕННЫЕ корневые имена строками; в файле — только теги Направлений | Направление на узлы не ссылается — §8 |
| `disabled{}` подписки | сырой тег | отметка на узле, а не ссылка на него (`IDENTITY.md` §5) |
| `origin.sub_url` | URL подписки | связь копии с подпиской, переживает перенос машин (`SPECS/features/sources.md` §Происхождение) |
| выбор в селекторе (cache.db, Clash API), проба цепочки `/chains/{tag}/probe` | финальный тег | рантайм ядра, в хранении не лежит (`SPECS/features/directions.md` §10) |

## 5. Резолв

Резолв один на все виды ссылок и выполняется ПОСЛЕ того, как финальные теги
получили все узлы всех источников — цель вправе стоять в `sources[]` ниже
ссылающегося (двухпроходность, `IDENTITY.md` §2.1). Лаунчер: словарь целей —
`core/config/outbound_generator.go:1475`, позиции цепочек — `:1481`, detour и
члены групп — `:1521`; финальный рубеж — санитайзер графа
`core/build/outbound_graph_sanitize.go:19-42`.

## 6. Операции и ссылки

Правила для обеих сторон:

1. Операция, меняющая АДРЕС узла (переименование, перенос между
   контейнерами), переписывает ссылки на новый адрес во всех видах ссылок:
   detour узлов и контейнеров, позиции цепочек, члены и `default` групп
   (`SPECS/features/directions.md` §9).
2. Операция, меняющая только ФИНАЛЬНЫЙ тег (`tag_policy`, имя контейнера),
   ссылки не трогает.
3. Ссылка никогда не переуказывается на ДРУГОЙ узел — тёзку, соседа, узел под
   похожим именем. Узел удалён операцией — ссылки, которые его использовали,
   гаснут вместе с ним, задетые называются (D-114, решение владельца
   15.09.2026);
   цель пропала без операции (провайдер убрал узел, удалён контейнер) —
   ссылка висит до сборки и разбирается fail-closed / prune (`IDENTITY.md`
   §2.1).
4. Выбор в селекторах ядра (cache.db) адресован финальными тегами и протухает
   при любой смене финального тега; переписать его сторона не может и обязана
   предупредить (`SPECS/features/directions.md` §10).

## 7. Импорт и экспорт

### 7.1 Экспорт

Ссылки пишутся ровно так, как лежат в хранении: файл — сериализация
состояния (`BACKUP.md` §1). `folder_id` — id контейнера на машине-экспортёре,
финальных тегов в файле нет. Лаунчер: `Source10.Detour / Hops / Group` —
`core/backup/backup10.go:92-94`.

### 7.2 Перепись id контейнеров

Карта «id контейнера в файле → id здесь» строится слиянием `sources[]`
(`BACKUP.md` §9): совпавший контейнер отдаёт ЛОКАЛЬНЫЙ id, новый — id из файла
(свежий ULID, если id занят). Через карту проходят:

- контейнеры обоих видов: папки (совпадение по `id`, затем по имени) и
  подписки (совпадение по `url`);
- ссылки всех видов в записях, приехавших файлом: detour узлов, общий detour
  контейнеров, `hops[]`, `group.members[]` и `group.default` (одним правилом,
  `core/backup/merge.go:614-641`, `rewriteGroup`).

Ссылка следует и за переименованием, которое делает само слияние. Член
контейнера файла, легший в совпавшую папку под другим тегом (уникализация
`X` → `X-2`) или узнанный по телу в уже стоящем узле с другим тегом, получает
ссылки файла по паре `(локальный id, локальный тег)`. Оставить тег файла
значит молча увести ссылку на тёзку или повесить её — подстановка узла с
другим именем запрещена (`IDENTITY.md` §2.1).

Ссылка на контейнер, которого в файле нет, ввозится КАК ЕСТЬ, без
предупреждения; разбирает её сборка (`BACKUP.md` §6). Лаунчер на сборке
называет её `the referenced source is gone` и выбрасывает носителя detour,
цепочку или члена группы (§5.1 № 2). Кейс — `v10_node_links` (`orphan`).

Лаунчер: перепись — `core/backup/merge.go:569-641` (`rewriteLinks`,
`fileLinkHere`, `rewriteGroup`: detour, `hops[]`, `group.members[]` и
`default`), вызов после слияния — `core/backup/import.go:429`; где легли узлы
файла — `merge.go:441-541` (`mergedInfo`, `landings`); подписка в карте id —
`merge.go:809`, `835-838`, папка — `merge.go:956-958`; корневой узел,
уникализированный или узнанный по телу, — `merge.go:850-898`, `906-914`; член
папки — `merge.go:959-969`, `1007-1026`. Кейс — Go-тест
`core/backup/merge_test.go` `TestImportLinksFollowMergeAddresses` (импорт и
сборка результата); кейсом корпуса не закреплено (§10).

### 7.3 Терпимость читателя: `{tag}` на члена контейнера и dev-формы

Старые и чужие файлы несут `{tag}` там, где цель — член папки или подписки
(`BACKUP.md` §4, §6). Это правило ЧТЕНИЯ: форма записи остаётся парой (§2), и
писатель после чтения пишет уже пару.

- **Файл 1.0.** В такой ссылке лежит ФИНАЛЬНЫЙ тег члена. После слияния и
  переписи id (§7.2) читатель поднимает её до пары `{id контейнера здесь,
  сырой тег}`, если тег (а) не занят корнем результата — корневой узел,
  Направление, тег свёртки, известная цель приёмника, зарезервированный
  литерал: корень сильнее члена папки, как и в резолве; (б) совпал с
  `prefix + сырой тег + postfix` РОВНО ОДНОГО члена папки или подписки
  результата — без раскрытия переменных и суффикса уникализации. Совпало
  несколько или ни одного — ссылка остаётся как есть и без предупреждения;
  разбирает её сборка (§5.1 № 6). Поднимаются приехавшие этим файлом `detour`
  узлов, общий `detour` контейнеров и `hops[]`.
- **Файл 0.x.** Позиции корневых цепочек приходят строками и сопоставляются
  с СЫРЫМ тегом члена контейнера: тег не корневое имя и найден ровно в одном
  контейнере; неразобранные записи не адресуются.

Совпадение ищется сперва в пространстве ФАЙЛА — члены папок файла под теми
именами, которые они носили в файле, и узлы подписок, приехавших файлом, — и
только если там такого имени нет, среди членов результата. Иначе член,

поднятая ссылка под него больше не подпадает, поэтому перезаписи файла на
загрузке нет, а мигрированное состояние сохраняется сразу.

| Правило | Что | Во что |
|---|---|---|
| S1 | член группы ВНУТРИ контейнера C без `folder_id` | `{C, tag}` — сборка так его и трактовала (§5.1 № 8) |
| S2 | `default` группы строкой (читается как `{tag}`) | ровно один член с этим тегом → копия его ссылки; иначе `{контейнер первого члена, tag}`; членов нет → `{C, tag}` / в корне `{tag}`. У корневой группы умолчание, совпавшее с корневым членом `{tag}`, уже в норме |

уникализации `-2` S3 не поднимет: после 1.0.1 они не разрешаются, и сборка

## 8. Направления: узлы не хранятся (решение — вариант А)

**Решение владельца 15.09.2026 (D-115), вариант А: Направление на узлы не
ссылается, нового поля нет.** Узлы в Направление набирает отбор (`filter` /
`invert`), умолчание — регулярка `default` (§4.3). Опции (`addOutbounds` ↔
`directions[].include`) — только ОБЪЯВЛЕННЫЕ корневые имена:

- теги Направлений и их парные `-auto`;
- `replace.tag` свёрток и их `-auto`;
- системные и шаблонные теги: `direct-out`, тег блокировки шаблона
  (`magic_nodes.block`), outbound'ы и endpoint'ы самого шаблона, теги
  пресетов.

Предложенные раньше `include_nodes: [NodeLink]` (А прежней редакции) и union
`include: [string | NodeLink]` (Б) отклонены: узел в опциях протухал бы от
правки `tag_policy`, переноса и переименования, а перепись ссылок узла (§6) за
опциями не ходит. Узел, которому нужно стоять в Направлении, попадает туда
отбором.

### 9.4 Ответы LxBox (15.09.2026)

1. **Выпущенный читатель или писатель 1.0 с `kind: auto` в папке и

   dev-формой лаунчера.
2. **Уникализация сырого тега провайдерской группы.** Сейчас у LxBox группы
   подписки вне уникализации; меняют на общий счётчик с узлами (`X`, `X-2`), до

   (`IDENTITY.md` §1.3): лаунчер до 1.6.0 давал теги в порядке тела и
   приведён к ней (§2.1).
3. **Позиция `{tag: replace.tag}` из файла лаунчера на стороне без свёрток.**
   Ввозится корневым тегом; на сборке — `chain_hop_missing`, цепочка
   деградирует fail-closed с предупреждением.
4. **«Группа подписки» в позициях** — провайдерская группа внутри подписки:
   пара `{id подписки, сырой тег группы}`; свёртка — `{tag: replace.tag}` (§2.1,
   §5.2).
5. **Неизвестная строка `include`.** Хранят; сборка её не эмитит и
   предупреждает. Просят не класть туда свёртки — отсюда норма §8: `include`
   только теги Направлений.
6. **Как autogroup LxBox едет в 1.0.** До релиза: экспорт `kind: auto` в
   `nodes[]` папки (`group_type: urltest`, `members` — NodeLink, `strategy` по

   `default` читают как urltest с предупреждением.
7. **`disabled_hashes`, Debug API `/folders/{id}/members/{index}`,
   цепочки в папках** — без изменений против §9.1 (D-112 их не меняет).
8. **Подъём dev-форм (S1–S3).** Делают в кодеке и импорте.
9. **«Поддержка: обе» у `detour`** server / folder / subscription — да, до
