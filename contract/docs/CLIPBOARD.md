# Буфер обмена поверх Taildrop

Нормативно. Константы — `registry/clipboard.json`; в тексте они названы именами
ключей (`name_prefix`, `max_bytes`, `ttl_seconds`). Контракт 1.1.146, TASKS_LXBOX §142.

## 1. Что это

LxBox и лаунчер передают друг другу текст буфера обмена обычным файлом
Taildrop. Получатель-наш-продукт кладёт текст в буфер и удаляет файл; во
входящие клип не попадает. Официальный клиент Tailscale видит обычный файл
`.txt` — синхронизация буфера есть только между нашими продуктами.

Транспорт — Taildrop ядра sing-box-lx (gRPC `StartedService`:
`SubscribeTaildropInbox`, `SendTaildropFiles`, `DownloadTaildropFile`,
`DeleteTaildropFile`). Своего канала, порта или формата сообщения нет.

## 2. Клип

- Имя: `name_prefix` + unix-ms отправителя + `name_suffix`
  (`lxclip-1793548800123.txt`). Получатель опознаёт клип по префиксу и
  суффиксу: при совпадении имён ядро может переименовать файл.
- Тело: текст в UTF-8 без BOM, не больше `max_bytes` байт, не пустой.
  Переводы строк — как в буфере отправителя, никто их не нормализует.
- Маркера источника в имени и теле нет: источник — `senderName` записи
  `TaildropFile` (`ComputedName` пира в ядре).

## 3. Отправитель

1. Цель — пир с `CanReceiveFiles`; выбирается человеком, не угадывается.
2. Не отправляет, а называет причину человеку: пустая строка; больше
   `max_bytes` байт; не валидный UTF-8.
3. Клип, помеченный системой как чувствительный, не отправляется (Android:
   `ClipDescription.EXTRA_IS_SENSITIVE`). У десктопа такого флага нет.
4. Отправка — только явным действием человека. Полученный клип никогда не
   отправляется дальше автоматически: петли нет.

## 4. Получатель

Обработка — по кадру входящих (`TaildropInbox`), для файлов с `name_prefix` и
`name_suffix`, по порядку:

1. **Разрешение.** Приём клипов включается у получателя явно — «Accept
   clipboard from <устройство>», по умолчанию выключено, ключ разрешения —
   `senderName`. Если разрешения нет или `senderName` пуст, файл остаётся
   ОБЫЧНЫМ файлом входящих: не удаляется и в буфер не идёт — как у
   официальных клиентов. Человек видит, что ему прислали, и может включить
   приём. (`senderName` ядро держит в памяти: после перезапуска ядра у
   лежащих файлов он пуст, и они остаются обычными файлами.)
2. **Возраст.** Возраст = часы получателя минус `modifiedAt`. `modifiedAt` —
   mtime файла на диске получателя после приёма, секунды (ядро не переносит
   время отправителя). Клип старше `ttl_seconds` удаляется без применения,
   запись в журнал уровня info.
3. **Пачка.** Из годных по п.1–2 применяется один — с наибольшим
   `modifiedAt`; при равенстве — с наибольшим unix-ms в имени. Остальные
   удаляются без применения.
4. **Тело.** Скачивается; больше `max_bytes` или не валидный UTF-8 —
   удаляется, warning в журнал, в буфер не идёт. Один ведущий U+FEFF
   снимается.
5. **Применение.** Текст кладётся в буфер, файл удаляется
   (`DeleteTaildropFile`).

Если приложение получателя не подключено к ядру, файлы лежат во входящих
ядра; при подключении обработка идёт по тем же пунктам, и п.2 отсекает
залежавшееся.

## 5. Что не входит

Не-текстовые клипы (картинки, файлы), история буфера, шифрование поверх
Taildrop (кого пускать, решает политика tailnet: по умолчанию — устройства
того же пользователя), подтверждение доставки.
