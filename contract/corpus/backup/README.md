# corpus/backup — фикстуры LX Backup v1

Кейсы переноса настроек между приложениями (SPEC 103, фаза 4).
Семантика — `contract/docs/BACKUP.md`, схема — `contract/schema/backup.schema.json`.

## Формат

```
<case>.backup.json     входной файл бэкапа
<case>.expected.json   что обязано получиться после импорта:
                       {"rules": [...], "vars": {...}, "warnings": ["код", …]}
```

Раннеры: Go — `core/backup/corpus_test.go`, Dart — `test/contract/backup_contract_test.dart`.

## Что фиксируют кейсы

Не «happy path», а именно те решения, которые легко нарушить:

- **битая символическая ссылка** — правило с несуществующим `outbound`
  импортируется ВЫКЛЮЧЕННЫМ, а не теряется и не включается (включённое
  правило с мёртвой целью роняет конфиг ядра целиком);
- **`route.final` в никуда** — не применяется: иначе весь трафик уходит в
  несуществующий outbound;
- **непереносимая переменная** — не применяется, факт назван (на другой
  машине то же имя значит другое: путь, интерфейс, платформенный флаг);
- **чужой `extensions`** — переживает импорт нетронутым и возвращается в
  следующий экспорт: бэкап, побывавший на десктопе, не должен вернуться на
  телефон обеднённым;
- **чужой `kind` правила** — пропускается с warning, остальные правила
  приезжают: одно чужое правило не роняет весь файл;
- **ось порядка** — перенумеровывается, относительный порядок сохраняется.

Данные синтетические: хосты `example-N.com`, UUID из единиц, identity-хеши —
64 hex-символа (короткий ключ не сопоставится ни с одной нодой).
