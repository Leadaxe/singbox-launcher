# Корпус формы узла

> **О чём.** Кейсы «тело узла → что делает с ним форма по реестру» (контракт
> 1.1.122, атрибут `form` поля и секция `body.form`; норма —
> `SPECS/167-F-C-OPENCONNECT_FORM/REGISTRY_DESIGN.md` §3 лаунчера; общие
> секции, варианты, `fixed`, массив `[0]`, `implies` и норма активного варианта — 1.1.123,
> `SPECS/168-F-O-NODE_FORMS/SPEC.md` §2.4). Обе стороны
> читают один файл и обязаны получить одно и то же: какие поля форма рисует,
> какие требует, какой вариант групп выбора активен, где значение вне
> диапазона формы.

## Файл

Один файл на схему: `<scheme>_form.json`.

```json
{
  "v": 1,
  "scheme": "openconnect",
  "cases": [
    {
      "name": "fortinet_basic",
      "comment": "что проверяет кейс",
      "body": { "server": "…", "flavor": "fortinet" },
      "expect": {
        "visible": ["server", "flavor", "…"],
        "required": ["server", "flavor", "username"],
        "missing": ["username"],
        "choices": { "server_cert_check": "system" },
        "out_of_range": [{ "path": "mtu", "value": 1600 }]
      }
    }
  ]
}
```

- `body` — тело узла в форме ядра (без `type` и `tag`), как его видит форма.
  Значения `body.form.fixed` схемы перед вычислением кладутся поверх тела
  (форма пишет их всегда), сами пути `fixed` в списки не попадают.
- Пути — от корня тела через точку (`tls.peer_fingerprint`), списки — в
  порядке `order` реестра (обход вглубь: поле, затем его вложенные поля).
  Элемент массива объектов с `form` — числовой сегмент: форма правит только
  элемент `0` (`peers.0.address`), он виден и при пустом теле; остальные
  элементы форма не видит. Поле варианта — путь без имени варианта
  (`transport.path`).
- **Общие секции** (`tls`, `transport`, `server`/`server_port` из
  `dialer.common`) входят в форму схемы только через `form` ref-поля схемы;
  поле секции отпадает, если схема в его `forbidden_for` (с поддеревом) или
  путь снят `form.exclude_fields` ref-поля. Варианты транспорта: виден
  дискриминатор (`transport.type`, сразу за ref-полем), затем поля варианта,
  равного текущему значению дискриминатора, если он не в
  `form.exclude_variants`.
- Контейнеры с `form` — объект, массив, ref-поле общей секции — входят в
  `visible` своим путём (`tls`, `transport`, `peers`), как любое поле с `form`;
  рисует форма их поля.
- `visible` — поля с атрибутом `form`, которые форма рисует: `visible_when`
  истинно на `body` и ни один предок не скрыт (скрытый объект скрывает всё
  поддерево). Поле без `form` в списки не попадает. `default` поля в условие не
  подставляется: отсутствующий `flavor` не равен `fortinet`, а `not_in`
  на отсутствующем пути истинно.
- `required` — видимые поля с `form.required`, обязательность которых не снята
  `form.required_unless` (задан любой путь из `set`, в том числе неописанный;
  либо в том же объекте не задан сосед из `absent`). «Задан» — ключ есть, не
  `null` и не пустая строка.
- `missing` — поля из `required`, которых в `body` нет: форма не сохранит.
- `choices` — id группы `body.form.choices` → id активного варианта по
  самому длинному совпадению: среди вариантов, у которых задан хоть один путь
  из `paths`, побеждает тот, у кого задано больше путей из `paths` ∪ ключей
  `set`; при равенстве — первый; если не задан ни один — вариант с пустыми
  `paths`.
- `out_of_range` — видимые заданные числовые поля вне `form.min`/`form.max`.
  Пустое поле границей не судится (ключ не пишется).
- Пустой список и отсутствие ключа равнозначны; сравнение по значению.

Скрытое поле из тела не снимается — форма тело не меняет, корпус проверяет
только вычисление.

### Запись формы (`write`, контракт 1.1.123)

Кейс может нести `write` — что форма пишет в `body` перед вычислением:

```json
"write": { "set": { "tls.utls.fingerprint": "firefox" }, "clear": ["…"] },
"expect": { "body": { "…": "тело после записи" }, "visible": ["…"] }
```

- `set` — путь поля формы → значение: значение пишется по пути (недостающие
  объекты создаются, числовой сегмент — элемент массива), затем пути
  `form.implies` поля — своими значениями.
- `clear` — пути очищенных полей: ключ снимается, затем снимаются пути
  `form.implies` поля; опустевшие объекты-предки снимаются.
- `expect.body` — тело после записи (сравнение по значению); списки
  `visible`/`required`/… считаются уже по нему. Без `write` `expect.body` не
  пишется.
