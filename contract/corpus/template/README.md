# Корпус шаблонов (фаза 3)

Общие конформанс-фикстуры **движка шаблонов** (SPEC 103, D-047). Сами шаблоны
двух приложений остаются разными (D-046) — унифицируется только движок,
поэтому корпус проверяет **язык**, а не содержимое шаблонов.

## Формат кейса

Тройка файлов с общим префиксом `<case>`:

```
<case>.template.json   # фрагмент шаблона: {"vars": [...], "config": {...}}
<case>.vars.json       # значения переменных: {"имя": "строка", ...}
<case>.expected.json   # {"config": {...}, "warnings": [...]}
```

- `template.json` — минимальный фрагмент, а НЕ полный шаблон приложения:
  секция `vars` с объявлениями (грамматика TEMPLATE_LANG §2) и секция
  `config` — то дерево, которое прогоняется через подстановку.
- `vars.json` — значения **строками**, как их хранит состояние обоих
  приложений; отсутствующий ключ = значение не задано (берётся
  `default_value`), значение `null` = optional-var (Dropped-каскад §5.1).
- `expected.json` — результат подстановки (`config`) и отсортированный
  список кодов предупреждений (`warnings`, коды из
  `registry/warnings.json`). Пустой список — поле обязательно присутствует.

### Поле `load` — рубеж загрузки (0.7.2, D-077)

Необязательное поле `expected.json`, нормирующее вердикт **load-валидации**
шаблона (TEMPLATE_LANG §4.1: «ошибка загрузки шаблона»). До него корпус
проверял только рантайм, и load-поведение сторон расходилось молча.

```
"load": "accept"   валидатор обязан принять шаблон (дефолт при отсутствии
                   поля — миграция существующих кейсов нулевая)
"load": "reject"   валидатор обязан отвергнуть шаблон на загрузке.
                   Рантайм-ожидания кейса (config/warnings) при этом
                   ПРОДОЛЖАЮТ проверяться толерантным прогоном — поле
                   нормирует рубеж загрузки, а не выключает рантайм
"load": "either"   вердикт намеренно не нормирован — кандидаты, по которым
                   решение о load-политике ещё не принято
```

Классификация текущего корпуса: `reject` — невалидная форма условия
(§4.1: оба/ни одного из `#and`/`#or`, пустой список предикатов,
отсутствующий `#value`; D-058); `either` — класс «необъявленное имя»
целиком (`unresolved/*` и enable-кейсы с undeclared-переменной): рантайм
нормирован §5.2, но load-политика undeclared-имён — открытый вопрос, и
нормировать её через отдельные кейсы класса нельзя. `-update`-регенерация
поле не трогает — оно нормируется руками.

Комментарий к кейсу — поле `"_comment"` в `template.json` (JSON не имеет
комментариев; ключ игнорируется обоими движками по правилу толерантности
TEMPLATE_LANG §1).

## Разделы

| Каталог | Что проверяет | Спека |
|---|---|---|
| `subst/` | подстановка `"@var"`, позиции, типизация значения | §3 |
| `types/` | приведение по объявленному `type`, clamp, невалидные значения | §2.2 |
| `predicates/` | предикаты P1–P6 | §4.2 |
| `map_spread/` | `#if` среди полей объекта, именованные `#if…`, merge/last-wins | §4.3 |
| `array_element/` | условный элемент массива, выпадение элемента | §4.4 |
| `unresolved/` | необъявленные имена, `null`-значения, Dropped-каскад | §5 |
| `on_change/` | `on_change.set`, цепочки, fixpoint-guard | §4.7 |
| `enable/` | гейт `#enable`: порядок, Dropped, сахар, fail-closed | §4.6 |
| `grammar/` | валидность формы `#if`, толерантность к неизвестным полям | §4.1 |
| `deps/` | извлечение зависимостей условия (**иной формат**, см. ниже) | §8.1 |

`presets/` добавляется отдельно (D-049, миграция модели пресетов LxBox).

## Раздел `deps/` — отдельный формат

Проверяет статическое извлечение зависимостей (SPEC 107 §8.1): на нём стоит
реактивный пересчёт UI, и расхождение означало бы, что на одной платформе
строка обновляется при изменении переменной, а на другой — нет.

```
<case>.cond.json      условие языка (§5.1) в любой форме — БЕЗ обёртки
<case>.expected.json  {"deps": ["a", "b", "runtime.platform"]}  — отсортированные
```

Имена без ведущего `@`; `@runtime.*` — полными именами (это зависимости, а не
константы: платформу удалённой машины меняют селектором). Собираются имена
всего дерева, включая ветки, до которых вычисление не дойдёт из-за
short-circuit.

## Нормативность и `-update`

Правила те же, что у корпуса URI (`corpus/README.md`): expected нормативны,
расхождение = баг движка или осознанное изменение контракта; регенерация —
отдельный PR с ревью диффа, не рутина.

## Синтетичность

Имена переменных — по сути кейса (`flag_a`, `port_num`), не из реальных
шаблонов: корпус не должен зависеть от словаря ни одного приложения (D-046).
