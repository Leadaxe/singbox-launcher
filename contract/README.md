# LX Shared Contract

Единый контракт данных между десктопным лаунчером (Go) и LxBox (Flutter/Dart).
Программа и решения: `SPECS/103-F-O-LX_SHARED_CONTRACT/` (SPEC, PLAN, DECISIONS).

**Контракт — это данные и документы, ни строки исполняемого кода.** Раннеры живут
в проектах и читают этот каталог.

## Состав

| Путь | Что это |
|------|---------|
| `VERSION` | semver контракта: major — изменение правил канонизации, minor — новые конструкции/разделы, patch — уточнения |
| `docs/CANON.md` | правила канонизации канонического узла (нормативно) |
| `docs/IDENTITY.md` | алгоритм identity-хеша и ключа (нормативно) |
| `docs/TEMPLATE_LANG.md` | язык шаблонов v1 (нормативно) |
| `docs/BACKUP.md` | семантика LX Backup v1 (нормативно) |
| `registry/protocols/<scheme>.json` | реестр протоколов: по файлу на схему |
| `registry/transports.json`, `registry/tls.json` | общие суб-схемы транспортов и TLS |
| `registry/allowlists.json` | канонические allowlist'ы (uTLS fp, ss-методы, …) |
| `registry/warnings.json` | коды warning'ов РАЗБОРА источников (локализация — на стороне приложений) |
| `registry/backup_warnings.json` | коды warning'ов БЭКАПА: экспорт/импорт состояния, с указанием стороны эмиссии (`export`/`import`/`both`). Отдельный словарь — граница другая, и общий файл смешал бы два несвязанных набора |
| `registry/limits.json` | лимиты (URI, нод, тело, цепочки) |
| `registry/vars.json`, `registry/presets.json` | переносимые имена переменных и preset id |
| `registry/containers.json` | контейнеры тел (`vpn://`, wgconf INI, base64) |
| `schema/*.schema.json` | JSON Schema узла, Направления, свёртки и цепочки источника, бэкапа, реестра |
| `diagrams/*.mmd` | нормативные mermaid-блок-схемы пайплайна |
| `docs/generated/**` | **генерируется из реестра**, руками не править (см. абзац ниже) |
| `tools/gendocs/` | генератор этих страниц (`go generate ./contract/...`) |
| `corpus/` | golden-фикстуры (фаза 1+) |
| `embed.go`, `doc.go` | **единственный код в каталоге** (см. абзац ниже) |

`embed.go` (`package contract`) — исключение из правила «контракт это только
данные», и оно намеренно узкое: файл не содержит ни одного решения, ни одной
проверки и ни одной таблицы, он лишь объявляет `//go:embed registry/*.json`,
чтобы реестр уезжал внутрь бинаря лаунчера и санитайзер с эмиттером
(`core/config/registry`, `core/config/nodeflow`, SPEC 131) читали те же самые
байты, что лежат в репозитории, — без копии реестра в `assets/` и без чтения с
диска в рантайме. Правила по-прежнему живут только в JSON. LxBox этот файл
игнорирует: Dart-сторона берёт те же файлы своими средствами.

`docs/generated/` — **человекочитаемая документация, собранная из реестра**:
оглавление, страница на каждую схему (параметры ссылки, поля тела, что делаем с
мусором) и словарь кодов с обратным индексом. Эти файлы **руками не правятся**:
их переписывает `go generate ./contract/...` (генератор — `tools/gendocs`,
директива — `doc.go`), а CI-джоба `Contract` на каждом PR перегенерирует их и
падает на `git diff --exit-code contract/docs/generated`. Правка нужного текста
начинается с `desc_en`/`desc_ru` в реестре, а не со страницы. Нормативен
по-прежнему реестр, а не эти страницы: они — его чтение вслух.

## Правила изменения

1. **Контракт раньше кода.** Новый протокол/параметр/приём начинается с PR сюда
   (реестр + фикстуры), реализации — вторым шагом.
2. Golden-файлы `corpus/**/*.expected*` нормативны: перегенерация раннером
   с `-update` — это осознанный PR с ревью диффа, не рутина.
3. Каждое расхождение проектов либо чинится, либо называется явно —
   бесхозных различий не бывает. Для протоколов и кейсов корпуса это маркер
   `"extension": "desktop"|"mobile"` (`registry/protocols/*.json`,
   `meta.extension` — им раннер пропускает чужие кейсы). Для ПОЛЕЙ схемы
   бэкапа маркера нет: поле объявляется в схеме, а кто его применяет,
   говорит колонка «Поддержка» в `docs/BACKUP.md` §2 (D-094).
4. Решения протоколируются в `SPECS/103-F-O-LX_SHARED_CONTRACT/DECISIONS.md`.
5. **Арбитраж неоднозначного парсинга** (D-019): если из кода/тестов обоих
   проектов непонятно, как разбирать параметр подписки — порядок сверки:
   поведение ядра sing-box-lx → как параметр парсит **Happ** → конвенции
   Xray/v2rayN. Вердикт — в note реестра + DECISIONS.md.
