# LX Shared Contract

Единый контракт данных между десктопным лаунчером (Go) и LxBox (Flutter/Dart).
Программа и решения: `SPECS/103-F-O-LX_SHARED_CONTRACT/` (SPEC, PLAN, DECISIONS).

**Контракт — это данные и документы, ни строки исполняемого кода.** Раннеры живут
в проектах и читают этот каталог.

## Правила изменения

1. **Контракт раньше кода.** Новый протокол/параметр/приём начинается с PR сюда
   (реестр + фикстуры), реализации — вторым шагом.
2. Golden-файлы `corpus/**/*.expected*` нормативны: перегенерация раннером
   с `-update` — это осознанный PR с ревью диффа, не рутина.
3. Каждое расхождение проектов либо чинится, либо явно помечается
   `"extension": "desktop"|"mobile"` — бесхозных различий не бывает.
4. Решения протоколируются в `SPECS/103-F-O-LX_SHARED_CONTRACT/DECISIONS.md`.
5. **Арбитраж неоднозначного парсинга** (D-019): если из кода/тестов обоих
   проектов непонятно, как разбирать параметр подписки — порядок сверки:
   поведение ядра sing-box-lx → как параметр парсит **Happ** → конвенции
   Xray/v2rayN. Вердикт — в note реестра + DECISIONS.md.

| 0.10.0 | **Идентичность узла = его тег** (SPEC 112): identity-хеш (sha256 от эмитированного JSON) упразднён. Ключ — сырой провайдерский тег, уникализированный в рамках источника и снятый ДО tag_prefix/tag_mask; содержимое узла (server, port, ключи, SNI, транспорт, mtu) в идентичность не входит. Причина: провайдер вправе поменять сервер под тем же именем — это тот же узел, а хеш зависел ещё и от формы хранения (`uri` и `config_json` одного узла хешировались по-разному), из-за чего detour-ссылка на узел молча протухала и зависимый источник fail-closed выпадал из конфига. Ссылка detour переехала с `detour_node_hash` на ОБЪЕКТ `detour_node_source_id` + `detour_node_tag` (id источника-цели + identity-тег узла внутри него) — **амендмент 0.10.0 (SPEC 112-A), номер версии не поднимается: 0.10.0 ещё не выпущен**. Финальный конфиговый тег в состоянии больше не хранится: он вычисляется на каждой сборке, потому что хранимый протухал от смены `tag_prefix` источника-цели. Сборка строго двухпроходная (сначала все финальные теги, потом резолв ссылок по единой карте), резолв строгий — обе части ссылки обязаны сойтись, иначе fail-closed с сообщением, называющим обе стороны по именам; смену идентичности узла (переименование его тега) UI отрабатывает сбросом ссылок и предупреждением. Контент-дедуп упразднён; вместо него дедуп записей на PARSE-слое по ключу подключения `scheme\|server\|port\|credential` — **амендмент 0.10.0 (SPEC 112-B), версия не поднимается по той же причине**: ключ живёт один разбор источника, в состояние не пишется, на отметки и ссылки не влияет, выживает первая запись, пустой ключ не схлопывает. Ключ жёстче прежнего хеша (один сервер + один креденшл с разными SNI = одна запись), и by-design различие с LxBox `nodeIdentityKey` из-за этого СХЛОПНУЛОСЬ — per-app override'ы корпуса, поставленные ради него, подлежат снятию при ревью (`docs/IDENTITY.md` §1.2, §4). Legacy-ключи (64 lowercase hex) мигрируют при первом разборе источника, для detour — в полную ссылку, а при неопознанном хеше с fallback на `detour_node_label` как tag-only ссылку (`docs/IDENTITY.md` §5.1–5.2). **Требуется зеркальная правка LxBox** (процесс как chains/0.7.1): до неё перенос disabled-отметок между приложениями сломан |
