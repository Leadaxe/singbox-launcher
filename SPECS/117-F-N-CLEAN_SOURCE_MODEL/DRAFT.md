# SPEC 117 — черновик: чистая модель источников

> Рабочий черновик обсуждения. НЕ спека. Правится по ходу разговора.

## Дерево классов

```dart
class NodeLink {
  String? folderId;            // null → корневое пространство тегов:
                               //   верхний узел, Направление, системный тег
  String tag;                  // иначе → узел папки folderId
}

class Origin {
  OriginKind kind;             // uri | wgIni | json | warp — чем парсить raw
  String     raw;              // исходник байт в байт, НИКОГДА не правится
  String?    subUrl;           // URL родной подписки; null = не из подписки.
                               // URL, а не ULID: самодостаточен, переживает
                               // перенос на другую машину. «Разыменовать» =
                               // обнулить subUrl.
}

abstract class Source {        // всё, что лежит в sources[]
  bool enabled;
}

abstract class Node extends Source {
  String    tag;
  Origin?   origin;            // null = создан руками; в Node, не в Server:
                               // происхождение есть у любого узла
                               // (провайдерский Auto тоже помнит subUrl)
  NodeLink? detour;            // null = напрямую

  JSON emitJSON();
}

class Server extends Node {
  JSON body;

  JSON emitJSON();             // отдаёт body
}

class Chain extends Node {
  List<NodeLink> hops;         // ближний первым

  JSON emitJSON();             // строит по hops
}

// Группы — тоже узлы. Два РАЗНЫХ зверя (расцепил Саша):
// Auto — узел со своим явным составом; FolderReplace — замена всей папки.

class Auto extends Node {      // провайдерская группа из подписки
  List<NodeLink> members;      // явный состав; фильтров нет
  AutoStrategy   strategy;     // url, interval, tolerance, … — набор
                               // полей возьмём из фактического кода групп.
                               // Пользовательские Auto — потом (галками);
                               // управление фильтрацией — потом, не сейчас

  JSON emitJSON();             // строит urltest/selector по members
}

class TagPolicy {
  String prefix;               // приставка: "proton-" → proton-NL
  String postfix;              // хвост: "-eu" → NL-eu
}                              // mask (шаблон {$server}…) ВЫКИНУТ —
                               // решение Саши; миграция: state с mask
                               // теряет его с warning

class FolderReplace {          // ОБЪЕКТ внутри Folder, НЕ Node:
                               // инвариант «только в папке» — типом;
                               // origin/detour ей не нужны (были бы трупами)
  ReplaceMode   mode;          // auto | manual | both
  String        tag;           // тег замены в конфиге; ЯВНЫЙ, не из имени
                               // папки (ловушка #91 tag-vs-label). При both
                               // авто-двойник деривативный: "<tag>-auto"
                               // (паттерн твинов Направлений)
  AutoStrategy? strategy;      // null при mode=manual
}
// Пул замены = ВСЯ папка, фильтров нет. Узлы папки при этом ГЕНЕРИРУЮТСЯ
// в outbounds как обычно (члены группы, легальные цели цепочек и detour) —
// прячутся они только из пула Направлений. Это смерть fold-флага.
// Резолв NodeLink обязан видеть replace-теги наравне с nodes[].
// Выбор в manual-селекторе НЕ хранится в модели — его помнит кэш ядра
// (cache.db), как сегодня. UI: строка в блоке Directions с кнопкой выбора.

class Folder extends Source {
  String     id;               // ЕДИНСТВЕННАЯ идентификация, отличная
                               // от тега: на папку ссылаются как на
                               // контейнер (NodeLink.folderId)
  String     name;
  TagPolicy  tagPolicy;
  NodeLink?  detour;           // общий, детям без личного
  List<Node> nodes;            // Server, Chain, Auto

  FolderReplace? replace;      // null = свёртки нет; убрал = выключил
}

class Subscription extends Folder {
  String     url;
  SubMeta    meta;
  UpdateSpec update;           // fetch перезаписывает nodes
}
```

## Принятое по ходу

- Диск v6 уже хранит каноническую модель; проблема — рантайм: рабочая
  модель UI = legacy ParserConfig, две конвертации на каждый Load/Save.
- Направление удара: canonical становится рабочей моделью, legacy —
  одноразовая проекция перед сборкой, обратного синка нет (сценарий А —
  ещё не утверждён, Саша думает).
- `connections` как обёртка умирает: корень плоский —
  `sources[] / directions[] / rules[] / dns_options / vars / warp_accounts / meta`.
- `defaults {reload, max_nodes}` уходят ИЗ состояния в настройки
  приложения (не state, не vars): умолчание описывает поведение
  лаунчера, не конфигурацию; одно место на все wizard-состояния.
  Резолв остаётся: своя настройка подписки → заголовок провайдера →
  дефолт из настроек.
- Направления и источники разнесены (directions в корень).
- Узлу не нужен name/label — только `tag`, он же тег в конфиге.
- Идентификация: узел — тегом (в папке или в корневом пространстве),
  папка — id; id есть ТОЛЬКО у папки. Узел может жить наверху sources[];
  его тег обязан быть уникален в корневом неймспейсе тегов конфига.
  Хранение направлений и источников раздельное (`sources[]` /
  `directions[]`); общий у них только неймспейс тегов готового конфига —
  это свойство sing-box, не модели.
- `Origin {kind, raw, subUrl?}` — происхождение узла, диагностика; raw —
  байт в байт, никогда не правится (кроме явного Regen). Связь с
  подпиской — subUrl (URL, не ULID: самодостаточен, переживает перенос
  на другую машину; «разыменовать» = обнулить).
  Ранняя идея «URL первой строкой raw» отменена: она портила raw и ломала
  валидность kind=json.
- В2 РЕШЁН — копии узлов подписки в папках/корне (появляются двумя
  путями: «copy to..» с узла подписки; заливка подписки в папку целиком).
  Правка внутри самой подписки запрещена моделью (несвободные узлы) —
  конфликт правки с обновлением возможен только у копий. Правила:
  1) любой ручной чих по копии (body ИЛИ тег) = авторазыменование
     с уведомлением — правка не может пропасть молча;
  2) отдельного действия «обновить» нет — повторная заливка той же
     подписки = merge по (subUrl, tag): совпал — body/raw освежаются,
     enabled/detour живут; новый — добавляется; исчезнувший у
     провайдера — НЕ удаляется, а разыменовывается с пометкой
     (папка — собственность пользователя, в отличие от подписки);
  3) списка «подписок папки» нет нигде — вся связь только в узле
     (subUrl); meta.subscriptions отменена окончательно.
- В1 РЕШЁН: источник истины узла — ВСЕГДА body; правка узла = правка body.
  Но в UI raw редактируем с явной кнопкой Regen (удобно для WG-INI):
  нажал — parse(raw) пересоздаёт body и origin.raw обновляется; не
  нажал — правка raw теряется. Regen с неразбираемым raw = ошибка и
  откат (правило битого фрагмента), узел не портится.
- `NodeLink` — единая ссылка «через кого»: заменяет тройню
  detour_tag + detour_node_source_id + detour_node_tag.
- `hops = NodeLink[]` — цепочка симметрична одиночному detour:
  одна механика резолва, один fail-closed.
- Подписка = папка с внешним владельцем состава (fetch перезаписывает
  nodes, пользователю — enable/disable поверх).
- Цепочка — наследник Node → может жить в папке.
- Группы, финальная форма: Auto — узел (провайдерская группа из подписки,
  явный состав members, без фильтров; Origin в Node — Auto тоже помнит
  subUrl). FolderReplace — НЕ узел, а объект-поле Folder.replace:
  {mode: auto|manual|both, tag явный, strategy?}; пул = вся папка;
  both = пара «селектор + авто-двойник <tag>-auto» (паттерн твинов).
  Membership выкинут — фильтры потом, если понадобятся. Выбор в
  manual-селекторе НЕ хранится в модели — кэш ядра (cache.db), как
  сегодня; никакой двусторонней синхронизации state ↔ Clash API.
- Локальных Направлений источника (`sources[].outbounds`) БОЛЬШЕ НЕТ —
  их роль целиком забрал FolderReplace. Направления существуют только
  глобальные, в своей секции `directions[]`. Миграция: старый fold →
  Folder.replace один в один (режимы совпадают); локальные Направления
  в replace не ложатся (у них фильтры) — теряются с warning.
- Семантика replace: узлы папки ГЕНЕРИРУЮТСЯ в outbounds как обычно
  (члены группы, легальные цели цепочек и detour), но НАПРАВЛЕНИЯМ
  вместо папки предлагается только замена. Прятанье — из пула
  Направлений, не из конфига. Fold-флаг умирает. Резолв NodeLink видит
  replace-теги наравне с узлами.
- `excludeFromGlobal` УБРАН совсем: fold-применение закрыл FolderReplace,
  «служебный транспорт» прячется папкой (узел при этом остаётся в
  outbounds и целью ссылок). Названная цена: Направление без фильтра
  («все узлы») видит верхние узлы все до единого — кому мешает, заводит
  фильтр или убирает транспорт в папку.
- **РЕШЕНО: узлы подписки материализуются в состоянии** (аргумент Саши:
  в памяти всё равно распаковываем — диск приводится в консистентность
  с памятью, меньше костылей). Семантика:
  - fetch = скачать → разобрать → слить в nodes[] ПО ТЕГУ:
    совпавший тег — обновить body/origin, СОХРАНИТЬ id/enabled/detour;
    новый тег — новый узел (enabled=true); исчезнувший тег — узел
    удаляется (цена: enable-отметка не переживает временное пропадание
    узла у провайдера; TTL-механика не переносится — костыль).
  - SPEC 113-A теперь охраняет сами узлы: недостоверный ответ
    (ошибка, пусто, обрезано) не трогает nodes[] вообще.
  - Сборка конфига БОЛЬШЕ НЕ ПАРСИТ подписки — body уже лежат готовые;
    парсинг происходит один раз, на fetch.
  - Умирают: .raw-кэш подписок (bin/subscriptions/*.raw — состояние
    само себе кэш; per-node raw живёт в origin), disabled_nodes-карта
    с TTL и GC (SPEC 094 D4 → просто node.enabled), PreviewNodes в meta
    (превью читает nodes[] напрямую), ловушка «ленивый кэш ≠ данных
    нет» (три состояния схлопываются — данные всегда есть).
  - Цена: файл состояния растёт (~1 МБ на CIDR-подписку 500 узлов);
    потолок max_nodes остаётся защитой. Секреты в state — by design.
  - Потеря: цельного тела подписки больше нет — переразобрать ВЕСЬ
    оригинал новым парсером нельзя, только пофрагментно из origin.raw.
