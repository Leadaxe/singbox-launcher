# SPEC 142 — вычистка рукописных правил об узлах вне реестра

Курс владельца (25.09.2026): реестр `contract/registry/**` важнее локальных
правил. Любое правило о полях узла (допустимость, значения, связи, дефолты,
деградации) живёт только в реестре; в Go остаётся общий движок
(`core/config/linkmap`, `core/config/nodeflow`) без имён схем. Рукописные
копии переносятся в примитив реестра (с кодом предупреждения, если узел
меняется) и удаляются вместе с тестами, которые проверяли копию.

Находки и их разбор — [AUDIT.md](AUDIT.md) (группы A–D, номера находок ниже
ссылаются на него).

## Правила для каждой волны

- Работа в git worktree от `develop`; коммиты явным списком путей; в develop —
  только `git merge --ff-only`. Ветки основной копии не переключать.
- Изменение `contract/registry` = бамп `contract/VERSION` + changelog +
  параграф в `contract/TASKS_LXBOX.md` (что меняется для LxBox).
- В движке — ни одного имени схемы/протокола; нужен частный случай — ищи
  общий примитив реестра.
- Поведение для пользователя не ухудшать: узел, который сейчас работает, после
  волны работает так же; любая правка узла — с кодом из `warnings.json`
  (+ `bin/locale/ru.json` для новых ключей).
- Проверки локально: `go build ./...` и только свой новый тест через `-run`;
  раннер корпуса контракта — по имени, если менялись реестр/корпус. Полный
  прогон — CI после волны.
- В конце волны — строка в `docs/release_notes/upcoming.md` при изменении
  поведения и отметка в таблице ниже.
