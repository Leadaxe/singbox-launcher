# SPEC 131 · Единый конвейер добавления узла

Статус: **N — ТЗ**, решения владельца 17.09.2026. Ветка develop от `d0e5aca3`
(после релиза 1.6.3, ядро `1.14.1-lx.4`, контракт `1.0.4`).
Связанные: SPEC 103 (общий контракт), SPEC 112 (идентичность = тег),
SPEC 121/122 (секции узла), SPEC 127 (одно пространство имён),
LxBox #140 (редактор терял `tls.certificate`), TASKS_LXBOX §22–§23.
Карты рядом: `CODEMAP.md` (адреса в лаунчере), `DRIFT.md` (расхождения
Go/Dart с обоснованиями), `CORE_SCHEMA.md` + `core_schema.draft.json`
(поля тел из структур ядра на теге lx.4).

---

## 1. Зачем

Узел попадает в state пятью дорогами (вставка в Add, fetch подписки,
миграция, Regen, импорт бэкапа) плюс ручной JSON-объект, и на каждой дороге
правила «что делать с мусором» свои. Сегодня одни и те же решения живут в
**трёх копиях**: в URI-парсерах (каждая схема — свой набор проверок), в
JSON-санитайзере (`SanitizeSingboxOutboundMap`, только для JSON-входа) и в
эмиттере (allowlist-ы полей, per-scheme switch, naive-фильтр). Копии
расходятся между собой и с LxBox: восемь имён `insecure` с разными наборами,
`short_id` нечётной длины проходит по ссылке и валит ядро, мусорный `fp`
у ссылки исчезает молча, а у JSON становится `chrome` с кодом, `tls.ech`
теряется без следа, `tls.certificate` терялся эмиттером (#140).
Каждый следующий пин ядра (key_share в lx.4) добавляет правку в 3–4 места.

Пользователь при этом ничего не видит: подписка «обновилась», узел в
списке, а поле снято. Владелец отверг попап и naive-костыли: нужен **один
механизм для всех входов**, с правилами в одном месте — реестре контракта,
который читают и лаунчер, и LxBox, и из которого генерируется документация.

## 2. Решения владельца (17.09.2026)

| Вопрос | Решение |
|---|---|
| Где живут правила | В реестре контракта, **привязаны к схеме протокола** (`registry/protocols/<scheme>.json` + `tls.json` + `transports.json`), не в коде |
| Порядок конвейера | текст → парсер ссылки/JSON (тупой маппер) → санитайзер по реестру → тупой эмиттер → тело в state + `warnings` с кодами |
| Область | **Все** входы: Add, fetch, миграция, Regen, импорт бэкапа, ручной JSON-объект; не только вставка |
| Показ вырезанного | Не попап: строка в превью Add + ⚠ на строке узла везде, причина в карточке, ссылка на якорь кода в документации |
| Naive и прочие «особые» | Никаких частных фильтров в эмиттере — то же правило реестра (`allowed_for`/`drop` с кодом) |
| Ключ, неизвестный реестру | Снимается с кодом `unknown_key`; реестр пополняется вместе с пином ядра из структур `option/*.go` |
| Версия контракта | Остаётся **1.x** (аддитивно: `1.1.0`), не 2.0.0 |
| Расхождения Go/Dart | Целевое = вариант LxBox, **с обоснованием каждого пункта** в `DRIFT.md`; там, где вариант LxBox ломает узел, который ядро приняло бы, — отдельное решение владельца |
| Документация | Генерируется из реестра Go-программой (`go generate`), `docs/Protocols*.md` заменяются ссылкой |
| Порядок работ | 1) это ТЗ 2) контракт 3) лаунчер по конвейеру 4) генерация документации; волны релизятся отдельно, старый код живёт до замены |
| Тесты | Минимально и в конце; корпус контракта — главный тест |

## 3. Конвейер

```
      текст (URI / JSON-объект / JSON-массив / base64 / wg .conf)
        │
        ▼
 ┌──────────────┐  карта sing-box (map[string]any) на схему,
 │ 1. маппер    │  ключи канонические, значения как пришли,
 │  (тупой)     │  незнакомое — как есть; ничего не решает
 └──────┬───────┘
        ▼
 ┌──────────────┐  по реестру: тип, enum, диапазон, алиасы,
 │ 2. санитайзер│  запреты по схеме, конфликты, unknown_key;
 │  (правила)   │  мусор → поле снято/приведено + {code,path,value}
 └──────┬───────┘  выход: чистая карта + []Warning (+ dropped)
        ▼
 ┌──────────────┐  сериализация в порядке структур ядра,
 │ 3. эмиттер   │  Listable как пришло (строка/массив),
 │  (тупой)     │  ни одного `if scheme ==`
 └──────┬───────┘
        ▼
   state.Node{Body, Origin{Raw}, Warnings[]}  ──▶  UI: ⚠ + карточка + ссылка
        │
        ▼  (сборка config.json)
   гейт min_core / platform по реестру → ключ опущен, запись в лог сборки
```

### 3.1 Маппер

Вход: одна ссылка / один JSON-объект / одна секция wg-conf. Выход:
`scheme string, m map[string]any, origin Origin`. Обязанности — только
**перевод диалекта в канонический путь**: `sni`→`tls.server_name`,
`pbk`→`tls.reality.public_key`, `allowInsecure`→`tls.insecure`,
`?ed=N`→`transport.max_early_data`+`early_data_header_name`, Xray-JSON
`streamSettings.*`→`transport.*`/`tls.*`, `headerType=http`→`transport.type=http`
и т.д. Таблица переводов **тоже из реестра**: секция `uri.query.<param>.maps_to`
(путь в теле) и `aliases`. Маппер **не** проверяет значения, не ставит дефолты
ядра, не режет поля; единственные его отказы — «не распознан протокол» и
«не разобрать синтаксис» (узел в `dropped` с кодом).

Сегодняшние парсеры схем (`node_parser_*.go`, `shareuri_*.go`,
`xray_outbound_convert.go`) остаются как код перевода, но из них **выносятся
все решения** (перечень — `CODEMAP.md` §2 и `DRIFT.md`); после выноса парсер
схемы должен помещаться в один экран.

Обратное направление (тело → share-URI) в этом ТЗ не меняется, но обязано
брать имена параметров из той же таблицы `maps_to`, чтобы пара парсер/эмиттер
ссылки не расходилась (память: эмиттер и парсер ходят парой).

### 3.2 Санитайзер

Единственная функция: `Sanitize(scheme string, m map[string]any, opts) (clean map[string]any, warns []Warning, drop *Warning)`.
Правила берутся из реестра (см. §4), код не знает ни одной схемы по имени.
Порядок обхода: по списку полей реестра в порядке структур ядра (тот же порядок,
что у эмиттера), поэтому список `warnings` детерминирован и сравним в корпусе.

Проверки на поле (все — по данным реестра):

| Проверка | Данные реестра | Исход при провале |
|---|---|---|
| ключ есть в схеме | `fields` | снять, `unknown_key` |
| ключ разрешён для схемы | `allowed_for` / `forbidden_for` | снять, код из правила (пример: у naive 16 TLS-ключей — `insecure`, `alpn`, `min_version`, `fragment`, `utls.*`, `reality.*`… — ядро отвергает **фатально на старте**, `CORE_SCHEMA.md` §naive; ещё 6 молча игнорирует — те тоже снимаем, один код `tls_field_unsupported_naive`) |
| тип (string/int/bool/duration/listable) | `type` | попытка приведения (`"443"`→443, `"true"`→true, `float64`→int без дробной части); иначе снять, `type_invalid` |
| enum | `values` | снять, либо `coerce` в дефолт, если правило так велит; код из правила |
| формат (hex, uuid, base64, host, port 1–65535, длина) | `format`, `min`, `max`, `len` | снять, код из правила |
| алиасы одного значения | `aliases` (список путей-синонимов с приоритетом) | оставить первый по приоритету, остальные снять с `alias_shadowed` |
| конфликт полей | `conflicts` | снять младший по приоритету, `field_conflict` (пример: `certificate` vs `certificate_public_key_sha256`) |
| требование | `requires` | снять зависимое, код из правила (пример: `reality.short_id` без валидного `public_key`) |
| обязательность | `required` | узел в `dropped`, `field_missing` |
| зависимые дефолты | `default_when` | подставить (пример: `utls.fingerprint` пустой при reality → `chrome`) — **только** если реестр явно велит; иначе дефолты ядра не материализуются |

Значение, которое ядро отвергнет fatal-ом на весь конфиг, после санитайзера
в теле остаться **не может** — это инвариант, его проверяет корпус.

`Warning{Code, Path, Value, Params}`: `Path` — путь в теле (`tls.reality.short_id`),
`Value` — исходное значение (обрезано до 64 символов, секреты не логируются:
поля с `secret:true` в реестре пишутся как `***`). Текст **не хранится**:
UI рисует по коду из реестра (§6).

### 3.3 Эмиттер

`Emit(scheme string, clean map[string]any) json.RawMessage` — обход реестра в
порядке структур ядра, запись только тех ключей, что есть в карте. Ни одного
per-scheme switch: сегодняшний `GenerateNodeJSONBare` со switch-ом и
`emitOutboundTLSJSON` с allowlist-ом заменяются одной табличной функцией.
Listable-поля пишутся в той форме, в какой пришли (строка или массив) —
канонизация формы не задача эмиттера. Неизвестных ключей на входе быть не
может (их снял санитайзер), поэтому «молча урезать» эмиттеру нечего.

### 3.4 Гейт по ядру — на сборке

Тело в state заморожено и не зависит от запущенного ядра. При сборке
`config.json` финальный проход по реестру: ключ с `min_core` выше версии
ядра или с `platform`, не совпадающей с `runtime.GOOS`, опускается, запись
в лог сборки (WARN). Гейты двух классов (`CODEMAP.md` §4.5, Л17): **узловые**
(`Naive`/`Chain`/`Tailscale`/`AWG3`, `outbound_generator.go:1195-1213`) —
узел в `dropped`/`unsupported`, остаются как есть; **полевые**
(`RealityKeyShareSupportProbe` `:284`) — переезжают в реестр (`min_core`,
`platform`) и снимаются одной табличной проверкой. ⚠ на узле от полевого
гейта **не** ставится: тело узла верное, ограничен рантайм.

### 3.5 Входы, которые обязаны идти через конвейер

Весь репозиторий сходится в **две воронки** (`CODEMAP.md` §1.1):
`MaterializeServerNode` (`core/config/migrate_materialize.go:341` — Add,
Regen, правка тела, миграция) и `MaterializeSubscriptionBody`
(`core/config/fetch_materialize.go:51` — fetch). Конвейер встаёт внутрь
обеих, плюс три места рождения тела вне воронок (ниже).

| Вход | Сегодня (адрес) | Целевое |
|---|---|---|
| Add: ссылка / список ссылок | воронка 1 → `ParseNode` `:205` → `emitMigrationBody` `:212`; коды `ParsedNode.Warnings` теряются в `ServerNodeMaterial` `:326-332` (Л1) | маппер → санитайзер → эмиттер; `ServerNodeMaterial.Warnings`; превью показывает warnings |
| Add: ручной JSON-объект | воронка 1, ветка `config_json` `:175-191` — `stripTagAndDetour` без санитайза и эмиттера (Л2) | маппер JSON (identity + алиасы диалекта) → санитайзер → эмиттер |
| Fetch подписки (все форматы) | воронка 2; JSON через `SanitizeSingboxOutboundMap`; `canonicalNodeFromEntry` `:156-166` не копирует `e.Node.Warnings` (Л1) | одинаково для всех форматов; `SubUpdateStatus.Warnings` остаётся сводкой по источнику (Л15), per-узел — в `Node.Warnings` |
| Regen / пересборка из `origin.raw` | `regenServerBodyFromRawText` `ui/…/source_body_edit.go:147` → воронка 1 | заново конвейер; warnings **замещаются**, не дописываются (Л5) |
| Миграция state / загрузка | перепись тела; `EmitBody` при сборке как есть (Л4) | разовая миграция при загрузке: узел с `warnings == nil` → санитайзер по телу; тело перезаписывается **только** если что-то снято/приведено, каждая замена — WARN в лог с тегом и кодами (Л3, решение ТЗ) |
| Импорт бэкапа | 1.0 копирует `body` как есть (`import10.go:116`); 0.x кладёт пустой `Body` до первого Regen (`legacy_read_0x.go:379-384`, Л24) | если есть `origin.raw` — конвейер от raw; иначе санитайзер по телу; `warnings` из бэкапа не авторитетны; пустое тело — конвейер при первой материализации, как сейчас |
| Релеи Xray | `relayNodesFromEntry` `core/config/relay_materialize.go:129` — третье место рождения `Body` (Л25) | тело релея — через санитайзер+эмиттер схемы релея |
| AWG-форма | `applyAWGSettings` `ui/…/source_awg_edit.go:239` правит ключи в готовом теле (Л23) | форма меняет карту → санитайзер → эмиттер; warnings пересчитываются |
| Chain / group / tailscale-форма | свой код | тело формы — тоже через санитайзер соответствующей схемы (chain, group, tailscale в реестре есть) |
| Отдельные парсеры мимо общего switch | `parseHTTPProxyURI`, `parseMasqueURI`, `parseAmneziaVPNLink`, `parseWGConfBase64Link` (`CODEMAP.md` Л27) | все возвращают карту в санитайзер; правило, добавленное в реестр, доезжает до всех |

Warnings — **производные данные**: их можно пересчитать из `origin.raw`
в любой момент; они хранятся в state только чтобы рисовать ⚠ без разбора.

## 4. Реестр — схема тела протокола

Новая секция `body` в каждом `registry/protocols/<scheme>.json`; общие
суб-схемы — `body` в `tls.json`, `transports.json`, новый `multiplex.json`,
`dialer.json`. Поля перечисляются **из структур ядра** (`CORE_SCHEMA.md`,
источник — `option/*.go` на теге пина), не по памяти.

```jsonc
"body": {
  "core": "1.14.1-lx.4",          // тег, по которому сверен список
  "order": ["server","server_port","uuid","flow","network","packet_encoding","tls","transport","multiplex"],
  "fields": {
    "uuid":   { "type": "string", "format": "uuid", "required": true, "secret": true,
                "desc_en": "...", "desc_ru": "...", "impl": "..." },
    "flow":   { "type": "enum", "values": ["", "xtls-rprx-vision"],
                "on_invalid": { "action": "drop", "code": "flow_invalid" },
                "forbidden_when": { "path": "transport", "present": true, "code": "flow_with_transport" } },
    "packet_encoding": { "type": "enum", "values": ["", "xudp", "packetaddr"],
                "on_invalid": { "action": "drop", "code": "packet_encoding_invalid" } },
    "tls":       { "type": "ref", "ref": "tls", "allowed_keys": null },
    "transport": { "type": "ref", "ref": "transports" },
    "multiplex": { "type": "ref", "ref": "multiplex" }
  }
}
```

Атрибуты поля (все опциональны, кроме `type`):

| Атрибут | Смысл |
|---|---|
| `type` | `string` · `int` · `uint16` · `bool` · `duration` · `listable_string` · `string_array` · `object` · `enum` · `ref` |
| `tristate` | `true` для указательных полей ядра (`vless.packet_encoding *string`: нет ключа = `xudp`, явная `""` = без инкапсуляции; `chain.strip_evasion *bool`: nil = true; `udp_fragment`) — санитайзер и эмиттер обязаны различать «ключа нет» и «пустое значение», эмиттер **не** опускает пустое у tristate-полей |
| `all_or_nothing` | `true` у объекта, где задание одного поля обнуляет дефолты соседних (`transport.xmux`: пусто = `1-1`/`600-900`/`1800-3000`, частично = остальные 0 без лимита) — санитайзер при частичном объекте дописывает дефолты ядра явно (`coerce`) с кодом `partial_object_defaulted` |
| `values`, `format`, `min`, `max`, `len`, `len_parity` | ограничения значения |
| `required`, `secret`, `default_when` | обязательность, маскирование в warnings/логах, зависимый дефолт |
| `aliases` | синонимы **в теле** по диалектам: `{"singbox": [], "xray": ["streamSettings.tlsSettings.serverName"], "clash": ["skip-cert-verify"]}` — для JSON-маппера |
| `on_invalid` | `{action: drop|coerce|drop_node, value?, code}` |
| `normalize` | `trim` · `lower` · `trim_lower` — применяется **до** проверки enum, только там, где реестр велит явно (`key_share`: ядро case-sensitive, `"Hybrid"` → `hybrid` с кодом). Без флага регистр не трогается: `x_padding_placement` у xhttp принимает только camelCase `queryInHeader`, lowercase ломает рабочий узел (`DRIFT.md` §9.2) |
| `allowed_for` / `forbidden_for` | список схем (для полей общих суб-схем: `tls.insecure` → `forbidden_for: ["naive"]`, код `tls_field_unsupported_naive`) |
| `conflicts`, `requires`, `forbidden_when` | связи между полями с кодом |
| `min_core`, `platform`, `lx_only` | гейты сборки (§3.4) |
| `desc_en`, `desc_ru`, `impl` | текст для людей (в документацию) и для разработчиков (не в документацию) |

Секция `uri.query.<param>` дополняется атрибутом `maps_to` (путь в теле) —
мост между ссылкой и телом; правила значений из `uri.*` переезжают в
`body.*` (одно правило на поле, а не два), в `uri.*` остаются только
синтаксис параметра и алиасы имён.

`note` разделяется: `desc_en`/`desc_ru` — что поле значит для человека;
`impl` — где в коде, история расхождений. Существующие `note` переносятся в
`impl` без потерь, `desc_*` пишутся заново (короткие).

`warnings.json` — у каждого кода добавляются `title_en/title_ru` (одна
строка для ⚠-подсказки) и `text_en/text_ru` (шаблон с `{path}`, `{value}`,
`{param}`), `doc` (якорь генерируется из кода). Новые коды этого ТЗ:
`unknown_key`, `type_invalid`, `alias_shadowed`, `field_conflict`,
`tls_field_unsupported_naive`, `flow_with_transport`, `partial_object_defaulted` (если нет — сверить с
DRIFT.md, часть уже существует под другими именами: не плодить дублей).

Проверка реестра самим реестром: линтер корпуса (`go test`) сверяет, что
каждый `code` в реестре объявлен в `warnings.json`, каждый `ref` существует,
`order` покрывает все `fields`, и что для каждого поля в `CORE_SCHEMA`
на теге пина есть запись (или явное `"skip": "reason"`).

## 5. Запись узла и контракт

### 5.1 State

`core/state` `Node` (`core/state/sources_v7.go:199`) получает поле
`Warnings []NodeWarning` (`json:"warnings,omitempty"`), рядом с `Reason` `:252`
по тому же образцу; `NodeWarning{Code, Path, Value, Params map[string]string}`.
Поле аддитивное, `SchemaVersion` v8 не бампается. `Reason` (английский текст
отброшенного узла, едет в диагностику) и `Warnings` (коды выжившего узла,
переводятся в UI) — разные поля, не сливать (Л20). `nil` = «не считали»,
`[]` = «чисто»: разовая миграция при загрузке (§3.5) переводит nil в
посчитанное. Порядок кодов = порядок обхода реестра, дубли снимаются (Л14).
`ParsedNode.Warnings`/`AddWarning` (`core/config/configtypes/types.go:765`,
`:769`) остаются накопителем на этапе разбора; расширяются `Path`/`Value`.

### 5.2 Контракт (1.1.0, аддитивно)

- `docs/CANON.md` §6: `warnings[]` конверта = `[{code, path, value?, params?}]`,
  порядок = порядок `body.order` реестра; `path` обязателен для кодов уровня
  поля, отсутствует для кодов уровня узла.
- `docs/CANON.md` новый §8 «Конвейер»: три ступени и инвариант «fatal-значение
  в entry не попадает» — теперь проверяемый по реестру, а не по памяти.
- `schema/backup.schema.json`: у узла `warnings` опционально; импорт их
  **не** доверяет (§3.5).
- `corpus/body/**`, `corpus/uri/**`: `expected.json` дополняются `warnings`
  с `path` там, где сегодня только код; ожидается пересмотр кейсов по
  `DRIFT.md` (сторона Go подтягивается к целевому поведению).
- `TASKS_LXBOX.md` §24: норма, список изменённых правил с обоснованиями,
  вопросы LxBox: (а) переносить ли `warnings` в бэкап; (б) готовы ли
  потреблять `body`-секцию генерацией Dart или руками; (в) согласие по
  каждому пункту DRIFT, где мы отходим от их поведения.

## 7. Генерация документации

`contract/tools/gendocs` (Go, `//go:generate go run ./contract/tools/gendocs`
в `contract/doc.go`) читает реестр и пишет `contract/docs/generated/`:

- `protocols/<scheme>.md` — таблица параметров ссылки (`uri.*` + `maps_to`)
  и таблица полей тела (`body.*`: путь, тип, значения, дефолт, что делаем с
  мусором и код-ссылка, `min_core`); EN и RU колонки `desc_*`; `impl` не
  попадает;
- `warnings.md` — по коду: якорь `<a id="code">`, severity, `title`, `text`,
  где возникает (обратный индекс по реестру: какие поля/схемы ссылаются);
- `index.md` — оглавление и версия контракта/ядра.

CI: в репозитории сегодня **ни одного** `go:generate`, и ни один workflow не
упоминает `contract`/`registry`/`corpus` (`CODEMAP.md` §8.6, Л13) — джоба
заводится с нуля: запускает генератор, падает на
`git diff --exit-code contract/docs/generated`, и там же гоняет линтер реестра.
Сторожевой тест `registry_sync_test.go:170` парсит `parse_warnings.go`
регуляркой по константам `Warn…` (Л12): при переводе кодов на реестр тест
переписывается в том же коммите.
`docs/Protocols*.md` (перечень в `CODEMAP.md` §8) заменяются одним абзацем со
ссылкой на `contract/docs/generated/index.md`. Генератор — на go1.20-совместимом
Go (Win7-джоба собирает весь модуль): без `slices`/`maps`/`min`/`max`.

## 9. Критерии приёмки

1. Ни одного `if scheme == "naive"`/`switch scheme` в санитайзере и эмиттере
   тела; все схемные различия — в реестре.
2. Один и тот же мусорный вход (ссылка и JSON-эквивалент) даёт **одинаковые**
   тело и `warnings` (кейсы-пары в корпусе `uri/` ↔ `body/`).
3. Каждый пункт `DRIFT.md` закрыт: либо целевое поведение реализовано и
   покрыто кейсом корпуса, либо решение владельца записано в DECISIONS.
4. `sing-box check` (ядро пина) проходит на конфиге, собранном из всех
   кейсов корпуса разом.
5. Узел с снятым полем виден: ⚠ в списке, причина в карточке, ссылка ведёт
   на существующий якорь сгенерированной страницы.
6. `go generate ./contract/...` идемпотентен; CI-диф пуст.
7. Сборка Win7 (go1.20) проходит.

## 12. Адреса и ловушки

Полный список — `CODEMAP.md` §10 (Л1–Л28); адреса на `d0e5aca3`. Что ТЗ
обязано пережить (сверх уже упомянутого в §3–§7):

- **Л1/Л2** — шов один на воронку, чинить оба сразу: иначе ⚠ есть у узлов из
  подписки и нет у узлов из Add.
- **Л3** — санитайзер на бывшем «сыром» пути перепишет тела в `state.json`
  на апгрейде; решение §3.5: перезапись только при реальном снятии/приведении,
  с WARN-строкой на узел.
- **Л6/Л7** — эмиттер сегодня цепочка `else if` (`outbound_generator.go:346-638`)
  плюс allowlist-ы (`outbound_jsonbuilder.go:84`, `outbound_tls_emit.go:41`,
  `xhttpV2StringKeys`/`xhttpIntKeys`); все уходят, порядок ключей — из `order`.
- **Л8** — JSON-карта несёт `float64`/`[]interface{}`; типы приводит санитайзер
  по реестру, в эмиттере ни одного `.(int)`/`.([]string)`.
- **Л9/Л10** — санитайзер ставит коды для 2 деградаций из 10, четыре кода
  реестра (`reality_pbk_invalid`, `tls_insecure`, `flow_deprecated`,
  `vision_with_transport`) не ставятся нигде; после W2 каждое правило реестра
  обязано иметь код, и линтер это проверяет.
- **Л11** — `severity: error` = узел отброшен; на выжившем узле только
  `warning`/`info`.
- **Л16/Л26** — коды уровня тела подписки (`clash_yaml_unsupported`) и
  накопитель причин с `MaxParseFailureReasons = 3` — не смешивать с warnings
  узла: у них своя ёмкость и адресат.
- **Л18** — `max_uri_length` 8192 в Go против 65536 канона: расхождение на
  входе, закрывается в W2 (лимит из `limits.json`).
- **Л21** — один `expected.json` на обе стороны: каждое изменение — либо
  встречная задача в TASKS_LXBOX §24, либо обоснованный per-app override.
- **Л22** — Win7 = go1.20: без `slices`/`maps`/`min`/`max`/`clear`.
- Enum-ы ядра case-sensitive (`key_share`, xhttp `mode`/`seq_placement`/
  `x_padding_placement`/`x_padding_method`, masque `vhttp`, ss `method`): все
  дают **B** (фатал на весь конфиг) на мусор и на неверный регистр
  (`DRIFT.md` §9); санитайзер обязан гардить каждый, а нормализовать регистр
  только по флагу `normalize`.
- **Л28** — комментарий в `awg3.go:112-115` про MTU врёт: AWG3 клампится
  до 1280 (решение владельца 05.09.2026), в реестр переносить факт, не коммент.
- Tri-state и all-or-nothing (§4): эмиттер, пишущий `""` вместо пропуска
  ключа или пропускающий пустое у `*string`, молча меняет поведение ядра.
- `lx_only`/`min_core` считать от базы форка (`git merge-base` с upstream),
  не от v1.13.11 из module cache: иначе 30+ ложных lx-полей (настоящих 8,
  `CORE_SCHEMA.md`).
- Дефолты `anytls.idle_session_*`, `tuic.heartbeat` ставят библиотеки
  (sing-anytls, sing-quic), не `option/` — в реестре как `default` с
  `impl`-ссылкой, санитайзер их не материализует.
