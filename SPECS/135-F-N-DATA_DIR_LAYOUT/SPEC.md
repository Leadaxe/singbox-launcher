# 135 · Раскладка данных: AppDir / DataDir / LogDir

Закрывает issue #85 (падение на NixOS, Guix, Flatpak, snap) и поглощает
SPEC 022 (данные macOS в `~/Library`). Статус: **ТЗ утверждается владельцем**,
код не начат.

## 1. Проблема

Единственный корень путей сегодня — `FileService.ExecDir = filepath.Dir(os.Executable())`
(`core/services/file_service.go:82-96`). От него `internal/platform/platform_common.go`
строит 21 категорию файлов: состояние, снапшоты, remote-машины, `config.json`,
шаблон, ядро, логи, `.srs`, кэш подписок, `settings.json`, локали, `gl-state.json`,
`wintun.dll`, каталог tailscale, клиентская пара демона, реестр remote-демонов.

Следствия:

- На read-only установке `EnsureDirectories` падает на первом `MkdirAll`
  (`platform_common.go:205-215`). Это и есть #85.
- На macOS всё лежит **внутри бандла** (`Contents/MacOS/bin`, `logs`). Полная
  замена `.app` стирает данные пользователя; `build/build_darwin.sh:422-500`
  вынужден выносить `bin`/`logs` наружу ради `codesign`, а `codesign --verify`
  признан бесполезным (комментарий на :446-449).
- Литералы `"bin"` и `execDir + "/bin/rule-sets/"` живут мимо хелперов:
  `core/build/preset_merge.go:58,760`, `file_service.go:94`,
  `ui/core_dashboard_tab_status.go:254`, `core/controller.go:306`.

## 2. Что отвергнуто из предложения в #85 и почему

| Предложение | Почему нет |
|---|---|
| `os.UserConfigDir()` как корень | На Windows это roaming `%APPDATA%`: 30 МБ ядра и `state.json` с ключами будут ездить между машинами домена. На Linux это `~/.config`, куда не место бинарям и кэшам `.srs`. |
| Seed копированием шаблона и локалей при первом запуске | Классический баг «старый seed лёг поверх свежего». Поставляемое читается на месте, копия появляется только когда лаунчер реально скачал новое. |
| Без миграции: «state пересоздастся» | В `state.json` подписки, ключи, Направления, remote-машины. Потеря недопустима. |
| `SINGBOX_LAUNCHER_EXEC_DIR` | Подменяет и код, и данные разом. Нужны раздельные override только для данных и логов. |
| Переименовать функции путей в `*FromExec` | Строковые аргументы не защищают от подмены. Защита — именованные типы, которые ловит компилятор. |

## 3. Целевая модель

Три роли вместо одного `ExecDir`:

| Роль | Права | Что лежит |
|---|---|---|
| **AppDir** | только чтение | бинарь, поставляемые шаблон и локали (`bin/wizard_template.json`, `bin/locale/`), поставляемое ядро (если есть), `mesa3d/` |
| **DataDir** | запись | всё состояние и кэши в **прежней внутренней структуре** `bin/…` (состояние, снапшоты, remote, `config.json`, скачанные шаблон и локали, скачанное ядро, `.srs`, подписки, `settings.json`, `gl-state.json`, `wintun.dll`, `tailscale/`, `daemon/`, `remote-daemons/`) |
| **LogDir** | запись | четыре лога и их `.old` |

Внутренняя структура `bin/…` под DataDir сохраняется намеренно: снапшоты,
каталоги remote-машин, документация и sudo-команды демона не меняются.
Переименование `bin` — отдельная косметика, не здесь.

### 3.1 Пути по платформам

| Платформа | AppDir | DataDir | LogDir |
|---|---|---|---|
| Linux | каталог бинаря | `$XDG_DATA_HOME/singbox-launcher` (по умолчанию `~/.local/share/singbox-launcher`) | `$XDG_STATE_HOME/singbox-launcher/logs` (по умолчанию `~/.local/state/…`) |
| macOS из `.app` | `…app/Contents/MacOS` | `~/Library/Application Support/singbox-launcher` | `~/Library/Logs/singbox-launcher` |
| macOS голый бинарь | каталог бинаря | = AppDir (portable, как в SPEC 022) | `AppDir/logs` |
| Windows | каталог exe | `%LOCALAPPDATA%\singbox-launcher` | `%LOCALAPPDATA%\singbox-launcher\logs` |
| Любая, portable | каталог бинаря | = AppDir | `AppDir/logs` |

Один корень данных, без дробления на config/data/cache: `.srs` и подписки
в `XDG_CACHE_HOME` вычищают «чистильщики», после чего `config.json` ссылается
на несуществующие файлы. Логи вынесены отдельно, потому что только они растут
и только их просят приложить к issue.

### 3.2 Порядок определения раскладки

Первое сработавшее правило выигрывает. Решение принимается один раз при
старте и **логируется** одной строкой: `layout: <режим> data=<путь> logs=<путь>`.

1. **Переменные окружения** `SINGBOX_LAUNCHER_DATA_DIR`, `SINGBOX_LAUNCHER_LOG_DIR`
   (каждая независимо). Для Flatpak-обёрток, пакетов, CI, отладки.
2. **Маркер `portable.txt`** рядом с бинарём (Windows, Linux; на macOS
   игнорируется — рядом с `.app` его никто не положит, а карантин Gatekeeper
   переносит бандл). Содержимое не читается, достаточно существования.
3. **Унаследованная раскладка**: рядом с бинарём есть `bin/wizard_states/state.json`
   и каталог бинаря доступен на запись → portable **без записи маркера**.
   Существующие установки Windows и Linux продолжают работать там, где
   работали. Ничего не копируется, ничего не «уезжает». Чтобы перейти на
   системную раскладку, пользователь переносит `bin/` сам или ставит
   переменную окружения; это описывается в документации.
4. **Платформенный дефолт** из таблицы 3.1.

Дистрибуция решает режим: **zip для Windows поставляется с `portable.txt`**,
так что для нынешних пользователей флешек и «папки с программой» ничего не
меняется. Установщик (если появится вместе с #99) маркер не кладёт. Tarball
для Linux маркера не содержит: там ожидают XDG.

### 3.3 Двухуровневое чтение поставляемого

Шаблон, локали и ядро читаются по цепочке **DataDir → AppDir**. Скачанное
перекрывает поставляемое; поставляемое никогда не копируется. Запись
(скачивание шаблона, ядра, локалей) идёт только в DataDir.

Порядок поиска ядра: `SINGBOX_LAUNCHER_CORE` (новая переменная, явный путь) →
`DataDir/bin/sing-box` → `AppDir/bin/sing-box` → `PATH`. Системный `sing-box`
из `PATH` **последний**, а не первый: лаунчер требует форк `lx` (XHTTP, AWG),
дистрибутивный бинарь почти всегда не тот. Выбранный путь и версия
логируются при старте.

### 3.4 Миграция

Единственный случай, когда данные копируются: **macOS из `.app`**, DataDir
пуст, а в бандле есть `Contents/MacOS/bin/wizard_states/state.json`. Тогда
`bin/` копируется целиком (включая ядро: владелец кладёт dev-сборки руками,
их нельзя терять), логи не копируются. В DataDir ставится маркер
`.migrated_from` с путём источника, **последним** шагом. Старое в бандле не
трогается: откат на предыдущую версию остаётся рабочим.

После миграции обязательно выставляется `RebuildConfig`, как это делает
`RefreshTemplateIfStale` (`core/template_migration.go:87`): сохранённый
`config.json` содержит **абсолютные пути** к `.srs` (`preset_merge.go:58`) и к
каталогу tailscale (`controller.go:306`), указывающие на старый корень. Без
пересборки ядро не найдёт rule-set или упадёт.

Честное ограничение: если пользователь macOS обновился, перетащив новый
`.app` поверх старого, данные уже уничтожены до первого запуска новой версии,
и никакой код это не спасёт. Промежуточный «патч-мигратор» не помогает по той
же причине. Поэтому:

- заметки релиза для macOS: **перед обновлением сделать LX Backup** (Settings →
  Backup) или обновляться через `build_darwin.sh -i`, который меняет только
  исполняемый файл;
- при первом запуске без данных и без источника миграции показывается
  одноразовое уведомление «данных предыдущей версии не найдено; если они
  были, импортируйте бэкап» со ссылкой на документацию.

Windows и Linux миграции не требуют благодаря правилу 3 из 3.2.

## 4. Механизм в коде

Новый пакет **`internal/paths`** (не `internal/platform`: тот тянет `exec` и
`syscall`, а резолвер должен импортироваться отовсюду, включая тесты).

```go
type AppDir  string   // только чтение
type DataDir string   // запись
type LogDir  string   // запись

type Layout struct {
    App  AppDir
    Data DataDir
    Logs LogDir
    Mode Mode        // Env, Portable, Legacy, System
}

func Resolve(exe string, env func(string) string, goos string) (Layout, error)
```

Правила:

- `Layout` вычисляется **один раз** в `NewFileService` и прокидывается
  значением. Никаких package-level глобалов и ленивой инициализации: они
  делают невозможной проверку двух раскладок в одном тестовом процессе.
- Каждый хелпер путей принимает **именованный тип**: пишущие только `DataDir`
  или `LogDir`, читающие поставляемое только `AppDir`. Передать `AppDir` в
  пишущий хелпер не даст компилятор. Это главная защита при правке ~190 мест.
- `EnsureDirectories(Layout)` создаёт **только** writable-каталоги.
- `FileService.ExecDir` исчезает как публичное поле; `wizard_model.ExecDir` и
  `debugapi` facade (`GetExecDir()`) разделяются на `App`/`Data`. Это два
  шва, где сейчас легче всего протащить AppDir в пишущий путь.
- Литералы из §1 переводятся на хелперы **до** рефакторинга, отдельным
  коммитом без смены поведения.

### 4.1 Демон (macOS, lxd)

Конфиг доставляется демону по mTLS (`prepareConfigForDaemon`), из каталога
приложения демон ничего не читает. Меняется только клиентская пара
`bin/daemon` → `DataDir/bin/daemon`. Проверить: (а) sudo-команды, которые
пользователь копирует в терминал, не содержат старых путей; (б) уже
установленное сопряжение не отваливается после переезда пары; (в) `.srs`
из `~/Library/Application Support` читаются root-демоном.

### 4.2 Сборка macOS

`build_darwin.sh`: снять перенос `bin`/`logs` ради `codesign`, вернуть
`codesign --verify` в строй, режим `-i` сводится к замене бинаря без
сохранения `bin/`. Поставляемые шаблон, локали и ядро остаются в
`Contents/MacOS/bin` как read-only seed, чтобы не менять раскладку бандла.

## 7. Проверка

Локально только `go build ./...` и именованные `-run`. Полный прогон в CI.

- Резолвер: матрица из этапа 1.
- Миграция: **один** интеграционный тест на волну (по CONSTITUTION): старая
  раскладка в `t.TempDir()` → миграция → state, подписки, `.srs` читаются,
  источник на месте, маркер выставлен, `RebuildConfig == true`.
- Read-only: AppDir с правами `0555`, старт не падает (Linux, macOS).
- Страж «AppDir не пишем»: AST-скан вызовов пишущих хелперов с аргументом
  типа `AppDir` по образцу `tools/l10n/l10n_check/scan.go:131`.
- Legacy-режим: данные рядом с бинарём → тот же путь, ничего не скопировано.
- Ручная проверка владельцем: macOS через `-i`, Windows из zip с маркером,
  daemon-режим после переезда пары.

## 8. Вне рамок

- Относительные пути `.srs` в `config.json` (сделали бы конфиг независимым от
  расположения, но cwd ядра в daemon-режиме не подтверждён).
- Переименование `bin/` внутри DataDir.
- `asInvoker` и elevation по требованию (#99) — следующая спека, опирается на эту.
- Пакеты Linux (#103).

## 9. Риски, по убыванию

1. Абсолютные пути в сохранённом `config.json` после миграции: лечится только
   принудительной пересборкой.
2. `wizard_model.ExecDir` и `debugapi` facade: один недосмотр возвращает
   исходный баг на NixOS. Закрывается именованными типами и стражем.
3. Daemon-режим macOS: пути в sudo-командах и уже установленное сопряжение.
4. macOS drag-replace: данные теряются до старта нового кода. Закрывается
   только заметками релиза и уведомлением при первом запуске.
