# SPEC 138 · Корневой блок `lx` ядра lx.13: ключи сна WG и глобальный простой MASQUE

Статус: **N**, спека и страховочный тест в ветке `spec-138-lx-wg-idle-keys`. Решение
владельца 24.09: «делаем». Пара к SPEC 098 форка `sing-box-lx` (ядро `v1.14.1-lx.13`,
тег ещё не срезан).

Главный вывод разведки: **лаунчер ключи сна WireGuard не писал никогда и писать не
может.** Десктопные сборки ядра их отвергают на старте в любой форме. Поэтому гейт по
версии ядра, перенос ключей из `route` в `lx` в сборщике и разбор running-config здесь
не нужны: для лаунчера переход на lx.13 сводится к бампу пина. Обоснование — §2 и §3.

---

## 1. Интерфейс ядра lx.13 (SPEC 098 форка)

Источник имён: `origin/lx` форка на `7de943642`. Структуры `option/lx.go` (добавлен в
`6e234fb3f`) и `option/route.go`. Между `a514ed0d1` (коммит из постановки) и
`7de943642` в `option/`, `route/`, `protocol/masque/`, `daemon/` изменений нет. Дока:
`docs-lx/lx-config.ru.md` §13, changelog `docs-lx/lx-changelog.md` → `v1.14.1-lx.13`.

Все глобальные ручки форка собраны в одном корневом блоке `lx`. Все подблоки и ключи
опциональны. Пустой блок `lx` равнозначен отсутствующему. Опечатка в имени ключа даёт
ошибку загрузки. Подблок `lx.naive` зарезервирован за SPEC 096 форка и пока
отвергается как неизвестный ключ.

| Было (lx.12) | Стало (lx.13) | Тип | Смысл |
|---|---|---|---|
| `route.lx_idle_suspend` | `lx.wg.idle_suspend` | длительность | порог простоя endpoint'а вне дерева маршрутизации; `0`/нет = выкл |
| `route.lx_idle_suspend_reachable` | `lx.wg.idle_suspend_reachable` | длительность | второй порог для endpoint'ов в дереве; ≥ `idle_suspend`, требует его |
| `route.lx_idle_teardown` | `lx.wg.idle_teardown` | длительность, явный `"0"` допустим | сон до разборки устройства; нет = наследует `idle_suspend_reachable`; `"0"` запрещает разборку |
| — | `lx.wg.lazy_build` | bool | новое; до SPEC 097 форка только разбирается и валидируется |
| — | `lx.wg.build_max` | целое ≥ 0 | новое; до SPEC 097 форка только разбирается и валидируется |
| — | `lx.wg.build_overflow` | `wait` \| `build` | новое; до SPEC 097 форка только разбирается и валидируется |
| — | `lx.masque.idle_timeout` | длительность ≥ 0 | глобальное окно простоя для masque-узлов без своего `idle_timeout` |

Совместимость в ядре:

- **Алиасы.** Старые `route.lx_idle_*` lx.13 принимает с предупреждением
  `route.lx_<key> is deprecated, use lx.wg.<key>` на каждый ключ. Одинаковое значение
  в обоих местах даёт то же предупреждение. Разные значения — ошибка старта
  `route.lx_<key> conflicts with lx.wg.<key>`. Алиасы снимут в релизе после перехода
  LxBox и лаунчера.
- **Сборка без `with_lx_idle_suspend`.** Любой ключ `lx.wg.*` (включая явный
  `idle_teardown: "0"`, `lazy_build`, ненулевой `build_max`, `build_overflow: "build"`)
  отвергается на старте: `lx.wg.* is set but this build lacks idle-suspend support;
  rebuild with -tags with_lx_idle_suspend (mobile-only feature)`. `sing-box check` такие
  ключи пропускает: роутер при проверке не стартует.
- **Приоритет у MASQUE.** `idle_timeout` узла > `lx.masque.idle_timeout` > выкл. В lx.13
  `idle_timeout` узла стал указателем. Явный `"0"` (или отрицательное значение) держит
  туннель поднятым при любом глобальном значении. Отсутствие ключа наследует глобальное.
- **Running-config** (`GetRunningConfig`, SPEC 037 форка) отдаёт блок в канонической
  форме: ключи `lx.wg.*`, без `route.lx_idle_*`.
- **lx.12 и корневой `lx`.** lx.12 блока `lx` не знает, неизвестное поле корня — ошибка
  загрузки.

## 2. Разведка: где лаунчер пишет и читает эти ключи

| Поверхность | Что найдено |
|---|---|
| Сборщик `core/build/*` | `route.lx_idle_*` / `lx.wg.*` нигде нет. Секции без своего обработчика (`buildSection` → `default`) уходят в config.json как есть, после подстановки `@vars`/`#if`. Корневой блок `lx` из шаблона дойдёт до конфига без правок кода. |
| Шаблон `bin/wizard_template.json` (пин `RequiredTemplateRef` `9736db76…`) | Секции `config`: `log, certificate, dns, inbounds, endpoints, outbounds, route, experimental`. В `route`: `default_domain_resolver, rules, final, auto_detect_interface` + `#if`. Среди 43 `vars` нет ни сна WG, ни простоя MASQUE. |
| Состояние, vars, UI-настройки | Ничего. |
| Running-config | Лаунчер `GetRunningConfig` / `GetChainCloneConfig` не вызывает: есть только сгенерированные заглушки в `internal/daemonpb`. Разбирать нечего. |
| Контракт `contract/**` | Ключей сна WG нет. Главная сессия подтвердила: реестр описывает разбор узлов, а не runtime-конфиг. В LxBox это переменные его собственного шаблона в секции `route`. Есть только `idle_timeout` узла masque (`registry/protocols/masque.json`). |
| MASQUE в лаунчере | WARP MASQUE получает собственный `idle_timeout: "5m"` (`core/warp/masque.go`, `ApplyNodeOptions`, зеркало LxBox). Ссылки `masque://` переносят `idle_timeout` как есть. Глобальной настройки нет. |
| Доки | Только исторические release notes 1.2.2 / `RELEASE_NOTES.md` упоминают `route.lx_idle_suspend_reachable` как ручку ядра. Историю не правим. |

**Почему ключей нет.** Десктопный набор тегов форка (`Makefile.lx` → `LX_TAGS`, по
нему собирает `lx-release.yml`) намеренно не включает `with_lx_idle_suspend`. Этот тег
добавляет только `cmd/internal/build_libbox` (мобильный AAR). Уже lx.12 отвергал
`route.lx_idle_*` на старте (`route.lx_idle_suspend is set but this build lacks
idle-suspend support…`, `route/idle_suspend_stub_lx.go`). lx.13 так же отвергает
`lx.wg.*`. Машины remote-таргета (lxd, в том числе musl-сборки для роутеров) собраны из
того же `LX_TAGS`. Сон WG — мобильная функция: экономит ~8 МБ буферов на endpoint там,
где `BatchSize=128`.

## 3. Решение

### 3.1 Ключи сна WG — не пишутся ни в какой форме

Лаунчер не пишет ни `route.lx_idle_*`, ни `lx.wg.*`: ни до бампа пина, ни после.
Гейта по версии ядра и переноса `route` → `lx` в сборщике нет.

Почему не делаем гейт, предложенный в постановке:

- На любом ядре, которое ставит лаунчер, обе формы роняют старт. Перенос ключа из
  `route` в `lx` исход не меняет.
- Гейт без потребителя — мёртвый код, и его пришлось бы снимать отдельной задачей
  после бампа пина.
- Парсер версий `-lx.N` / `-rc.N` (`parseCoreBuild` / `compareCoreBuilds`) живёт в
  `core/daemon_service_state_darwin.go` и собирается только на darwin. Выносить его
  платформенно-нейтрально без потребителя — рефакторинг вне задачи. Если появится
  кроссплатформенный гейт по фиче ядра, вынос делается в той задаче.

Пользовательский шаблон с `route.lx_idle_*` или `lx.wg.*` на десктопе остаётся тем же,
чем был на lx.12: `sing-box check` проходит, ядро не стартует с понятной ошибкой ядра.
Лаунчер такие ключи не вырезает (развилка 2 в §6).

**Для форка:** лаунчер не держит снятие алиасов `route.lx_idle_*`. Его переход
выполнен по факту: этих ключей в нём не было. Ждать остаётся только LxBox.

### 3.2 Running-config

Разбора нет, и он не нужен. Если лаунчер когда-нибудь начнёт читать `GetRunningConfig`,
читать нужно только канон `lx.wg.*`. Старой формы в ответе lx.13 не бывает.

### 3.3 `lx.masque.idle_timeout` — «пишется, если задано», без UI

UI или переменной для простоя MASQUE в лаунчере нет, поэтому новой настройки тоже нет.
Единственный канал — корневой блок `lx` в `config` шаблона. Сборщик пропускает его как
есть, с подстановкой `@vars`. Это закреплено тестом `TestBuildConfigPassesRootLXBlock`:
будущий белый список корневых секций иначе молча выбросил бы блок.

Ограничения канала:

- Шаблон с блоком `lx` допустим только в паре с пином ядра ≥ lx.13. lx.12 падает на
  неизвестном поле корня. Шаблон и пин версионируются вместе (`RequiredTemplateRef` и
  `RequiredCoreVersion` в `internal/constants/constants.go`), так что блок `lx` в
  шаблоне появляется не раньше бампа пина.
- На WARP MASQUE лаунчера глобальное значение не действует: у этих узлов свой
  `idle_timeout: "5m"`, а ключ узла сильнее. Наследовать глобальное будут только
  masque-узлы подписок без своего ключа.

### 3.4 Бамп пина на lx.13 — отдельный шаг после релиза ядра

- `RequiredCoreVersion` → `1.14.1-lx.13` (`internal/constants/constants.go`).
- Миграция config.json и state.json не нужна: лаунчер не пишет ни одного переименованного
  ключа.
- `idle_timeout` узла masque: в lx.12 `"0"` и отсутствие ключа значили одно и то же
  (выкл). В lx.13 `"0"` держит туннель, отсутствие наследует глобальное. Пока шаблон не
  задаёт `lx.masque.idle_timeout`, поведение совпадает.

## 4. Критерии приёмки

1. `go build ./...` зелёный. `TestBuildConfigPassesRootLXBlock` зелёный.
2. Код сборщика и шаблона не менялся. Новых ключей `locale.T` нет.
   `l10n_check --strict`, `hardcoded_check --strict`, `paths_guard`, `win7guard` зелёные.
3. `docs/ARCHITECTURE.md` / `.ru.md` описывают сквозной путь корневого `lx`.
   `docs/release_notes/upcoming.md` содержит строку EN/RU в «Technical / Internal».
   В `SPECS/README.md` есть запись о задаче.

## 5. Вне рамок

- Бамп `RequiredCoreVersion` на lx.13 — по релизу ядра (§3.4).
- UI или переменная шаблона для `lx.masque.idle_timeout`.
- Вырезание ключей сна WG из пользовательских шаблонов.
- Правки контракта. В `contract/registry/protocols/masque.json` `idle_timeout.impl`
  говорит «пусто = дефолт ядра (5m)», а в ядре простой по умолчанию выключен и в lx.12,
  и в lx.13. Это устаревшая формулировка, её правка — через владельца контракта.

## 6. Развилки для владельца

1. **WARP MASQUE и простой 5m.** Форк считает сон MASQUE на десктопах и роутерах
   невыгодным: просыпание стоит полного QUIC-рукопожатия. Поэтому в ядре он выключен
   по умолчанию. Лаунчер ставит WARP MASQUE `idle_timeout: "5m"` вслед за LxBox.
   Варианты:
   - (а) оставить 5m;
   - (б) не писать ключ, узел наследует `lx.masque.idle_timeout` или выключен;
   - (в) явный `"0"`.

   Дефолт — (а), поведение не меняется.
2. **Ключи сна WG в пользовательском шаблоне на десктопе.** Варианты:
   - (а) оставить: ядро не стартует со своей ошибкой;
   - (б) сборщик вырезает их с WARN.

   Дефолт — (а).
