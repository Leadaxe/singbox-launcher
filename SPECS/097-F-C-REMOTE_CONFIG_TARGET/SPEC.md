# SPEC 097 — Remote config target

**Тип:** Feature · **Статус:** Complete · **Платформа:** все

Лаунчер готовит конфиги не только для себя и управляет чужими ядрами. Визард
выбирает, для какой машины собирается config (**local** | **remote**);
remote-конфиг выгружается файлом и доставляется на машину по каналу lxd;
вкладка Servers работает с ядром выбранной машины теми же средствами, что и
с локальным.

**Depends on:** SPEC 067 (template expressions), SPEC 096 (lxd — движок на
remote-машине), SPEC 064 (шов ProxyTransport).

---

## 1. Проблема

Генерация конфига неявно предполагала «машину, на которой запущен лаунчер»:
`runtime.GOOS` был зашит в пайплайне, а в шаблоне литералами сидели локальные
допущения (`clash_api`, `find_process`, `set_system_proxy`, имя TUN только для
win/linux). Конфиг для linux-роутера с mac собрать было нельзя, gateway-кейс
(wifi-с-VPN + обычный wifi) не выражался вовсе, а хранить remote-состояние
было негде: `bin/wizard_states/` — плоский список local-снапшотов.

Отдельно: сопряжённой удалённой машиной нельзя было управлять — у remote-ядра
Clash API нет by design, а gRPC-клиент был привязан к локальному демону.

## 2. Оси: таргет и роль

Две **независимые** оси, их смешение — источник ошибок:

| ось | значения | что определяет |
|-----|----------|----------------|
| **target** | `local` \| `remote` | где машина: файл состояния, канал управления, куда идёт результат |
| **роль** | `gateway_mode` (bool) | форвардит ли машина чужой трафик |

Роль не выводится из таргета: local-gateway легален (mac + Internet Sharing),
а remote-сервер — не gateway. Платформа (GOOS/GOARCH) — третья ось, задаётся
для remote явно.

## 3. Целевая модель

### 3.1 Шаг 0 визарда

Первая вкладка — выбор таргета. Для remote раскрываются ОС и архитектура
целевой машины (подменяют `runtime.GOOS` во всей генерации).

`gateway_mode` и `gateway_include_interface` живут **тоже на шаге 0**
(`wizard_ui: "target"`), а не в Settings: от `gateway_mode` зависит
`default_value` других полей, а дефолты резолвятся однопроходно в порядке
объявления — переключатель обязан стоять выше зависимых и быть виден раньше.

Переключение таргета: флаш текущего состояния → чтение целевого →
перерисовка вкладок.

### 3.2 Хранение

```
bin/wizard_states/state.json          # local — исторический layout, не тронут
bin/wizard_states/<id>.json           # local-снапшоты
bin/wizard_states/remote/state.json   # remote-состояние
bin/wizard_states/remote/<id>.json    # remote-снапшоты
```

`platform.GetWizardStatesDirFor(execDir, target)`; неизвестный таргет →
local (опечатка не должна ронять state туда, где его никто не ищет).
`StateStore` корневится на директории таргета — Save/Load/снапшоты
переключаются вместе с ним.

GC обходит **оба уровня**: `collectAllStageRuleSetTags` и
`collectAllStageSourceIDs` заглядывают в подпапки, иначе rebuild снёс бы
.srs и raw-body подписок, которыми владеет только remote-state.

### 3.3 TargetSpec

```go
type TargetSpec struct { GOOS, GOARCH, Target string }
```

Протаскивается через `LoadTemplateData` / `ApplyTemplateWithVarsFor` /
`ResolveTemplateVarsFor` / `SubstituteVarsInJSON` / `ExpandPreset` /
`ResolveDNS` / `ResolveRoute` / `SyncOutboundsWithActivePresets` /
`MergeOutboundUpdates*`. `runtime.GOOS` остаётся только в `LocalTarget()`.

Zero value нормализуется в «эта машина, local» — вызывающие, не знающие о
таргетах, ведут себя как прежде.

### 3.4 Язык условий — один на весь шаблон

`@runtime.target` = `local` | `remote` — строковый global рядом с
`platform`/`arch`. Bare-форма для globals запрещена (SPEC 067), сравнение
явное: `{"@runtime.target": "remote"}`.

Записи `if`/`if_or` принимают **предикаты того же языка**, что внутри `#if`:
голое `"@tun"` (bool-var) ИЛИ JSON-предикат
`{"@runtime.target": "local"}`, `{"#not": "@gateway_mode"}`. Никаких
параллельных механизмов вроде отдельного поля `targets[]`.

`default_value.#if` видит user-vars, объявленные **выше** по списку
(`ForTargetIn`); forward-ссылка — ошибка загрузки, а не молчаливый false.

Видимость строки в UI различает два случая:
- условие **только от `@runtime.*`** — пользователь его не выполнит → строка
  **скрывается** (`VarConditionIsTargetOnly`);
- условие **ссылается на vars** (`@tun`) — он может включить → строка
  **гасится**.

### 3.5 Шаблон

| поле | правило | ось |
|------|---------|-----|
| `interface_name` | только windows/linux; var `@tun_interface_name`, remote-дефолт `lxd-tun0` | платформа |
| `include_interface` | `@gateway_include_interface` (`text_list`), ключ **постоянный** | роль |
| `clash_api` | только `target=local` | таргет |
| `find_process` | `false` при `gateway_mode` | роль |
| `proxy_in_listen` | `0.0.0.0` при `gateway_mode`, иначе `127.0.0.1` | роль |
| `set_system_proxy` | никогда на remote | таргет |

Два решения, которые легко нарушить:

**`interface_name` не эмитится на macOS.** Система сама выдаёт `utunN` и
отвергает любое другое имя (`bad tun name`). Условие стояло в шаблоне до
SPEC 097; его снятие ломает локальный запуск.

**`include_interface` вынесен из платформенной ветки.** Ключ присутствует
всегда: пустой `text_list` даёт `[]`, а ядро трактует `[]` как отсутствие
поля (везде `len(...)>0`) — фильтр не применяется. Вложить его в
платформенную ветку значило бы потерять gateway на macOS; два `#if` в одном
объекте невозможны (ключ один), поэтому постоянный ключ — единственная форма
без дублей и ложной связи.

### 3.6 Вывод конфига

- **local** → `bin/config.json`, как раньше (Update/Rebuild).
- **remote** → `bin/remote-config.json`. Отдельный файл принципиально:
  `config.json` принадлежит локальному ядру, его перезаписывает Update и с
  него стартует sing-box — чужой конфиг там был бы затёрт либо запущен
  локально.

Превью и деплой берут один и тот же артефакт: `BuildRemoteConfig` — то же
тело, что превью, только без truncation.

**Выключенные пресеты не эмитят свои `rule_set`.** Правило выключено → его
routing-правило не эмитится → ссылаться на набор некому, а требование к
файлу остаётся: на машине, где .srs нет, ядро падает `open …: no such file`.

## 4. Управление удалённой машиной

### 4.1 Реестр

`bin/remote-daemons.json` — несколько машин (роутер, VPS, другой mac),
переживают перезапуск. У **каждой своя** клиентская пара в
`bin/remote-daemons/<id>/`: сертификат = полный мандат, общий ключ означал бы,
что отзыв доступа на одной машине отзывает его везде.

Сопряжение с **не-loopback** адресом уходит в реестр и **не трогает**
`settings.json`: там одно подключение — своего демона, и запись чужого
адреса лишала лаунчер связи с локальным ядром.

Адрес — отдельное поле при добавлении: демон печатает в приглашении свой
listen-адрес, при `0.0.0.0` он нерабочий. Enroll идёт на адрес пользователя.

Удаление забывает ключ у себя; доступ на машине **не отзывается** — диалог
предупреждает и даёт команду `sing-box lxd client remove singbox-launcher`.

### 4.2 Транспорт

`LxdRemoteTransport` — `services.ProxyTransport` поверх gRPC произвольного
демона (`GetGroups` / `SelectOutbound` / `URLTestOutbound`). Отдельно от
`daemonProxyTransport`: тот привязан к жизненному циклу локального
`DaemonBackend`, здесь мы только клиент к чужому процессу.

Транспорт ставится в **`APIService.SetTransport`** — через него ходят ВСЕ
proxy-операции core-слоя (`AutoLoadProxies`, ping, переключение узла).
Подстановки только в `EffectiveProxyTransport` (UI-путь) недостаточно:
список узлов грузится другим путём и остался бы локальным.
Снимается override только если он наш — в daemon-режиме там стоит транспорт
локального демона.

Группы для удалённой машины берутся **у неё** (`GetGroups`), а не из
локального `config.json`. При ошибке — пустой список и причина в логе;
откат на локальные группы запрещён: подстановка чужих данных под именем
выбранной машины хуже пустого экрана.

`internal/lxdclient` и `internal/daemonpb` — без build-тегов: лаунчер на
Windows управляет linux-роутером. Демонный **движок** остаётся macOS-only —
это про запуск своего демона.

### 4.3 UI

- **Дропдаун в шапке Servers** — Local + сохранённые машины, переключение в
  один клик. Единственная точка переключения (кнопки Connect в списке нет).
- **Start/Stop + короткий статус** выбранной машины. Опрос удалённой идёт в
  горутине, кнопка блокируется до ответа; результат проверяется на
  актуальность источника. Останов спрашивает подтверждение — он рвёт VPN у
  всех, кто ходит через машину.
- **Deploy config** — отправляет `bin/remote-config.json` через
  `/admin/apply`. Демон валидирует конфиг до подмены инстанса, поднимает
  ядро сам (`StartOrReloadService`) и откатывается на last-good при провале,
  поэтому неудачный деплой не оставит роутер без VPN.
- **Список машин** (окно подключения): добавить (имя + адрес + приглашение),
  импортировать уже сопряжённую, править, удалить; диагностика **каждой**
  машины отдельной строкой (доступна / статус ядра / версия демона /
  последняя ошибка).

Выбор машины эфемерный: после перезапуска — своё ядро. Иначе Servers на
старте пошёл бы к роутеру вместо локального ядра.

## 5. Из scope

- Транспорт деплоя помимо lxd (ssh/scp) — не нужен: `Apply` покрывает.
- Мониторинг трафика удалённой машины.
- Per-source таргеты (несколько remote-состояний): формат готов —
  `remote/` расширяется до именованных папок.

## 6. Открытые пункты

- **`.srs` включённых пресетов на remote.** Пути указывают на машину, где
  собирали. Для remote-таргета их следует оставлять `type: remote`, чтобы
  целевая машина качала сама. Сейчас не мешает: выключенные пресеты .srs не
  эмитят.
- **Активный узел urltest-группы для удалённой машины.** Живой пул
  (`DaemonPoolAvailable` / `DaemonPoolSlots`) привязан к `ac.Backend()`, то
  есть к локальному демону, хотя канал тот же gRPC. В окне узла удалённой
  машины выбранный участник группы не подсвечивается.
- **Дизайн шапки Servers.** Контролы добавлялись по одному: действия,
  статус и селектор в один ряд без группировки и иерархии.
- **Первое remote-состояние копирует local** вместе с источниками —
  пользователь получает то, чего не добавлял.
- **Пресеты фильтруются по платформе ХОСТА** (`filterPresetsByPlatform`
  на загрузке шаблона). Сегодня не проявляется: единственный платформенный
  preset покрывает все три десктопа.

## 7. Инварианты (что нельзя ломать)

1. **local-путь генерации не изменился** — те же секции, значения и
   поведение, что до SPEC 097. Zero-value таргет = local.
2. **`bin/config.json` принадлежит локальному ядру** — remote-конфиг туда
   не пишется никогда.
3. **`settings.json` держит одно подключение — своего демона.** Чужие
   машины только в реестре.
4. **UI не подменяет данные при ошибке** — пустой список честнее чужого.
5. **`interface_name` не эмитится на macOS.**
6. **Роль и таргет — независимые оси.**
