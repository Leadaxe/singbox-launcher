# SPEC 098 — отчёт о реализации

**Статус:** реализовано. `go build ./...`, `go vet ./...`, `go test ./...` — чисто.

## Что сделано

### 1. Пути на машину (§2.3)

`internal/platform/platform_common.go`:

- `GetWizardStatesDirFor(execDir, target, id)` — третий аргумент; для `local`
  игнорируется, иначе `bin/wizard_states/remote/<id>/`.
- `GetWizardStatePathFor(execDir, target, id)` — то же для `state.json`.
- `GetRemoteMachineDir(execDir, id)` — корень имущества машины.
- `GetRemoteConfigPathFor(execDir, id)` — её `config.json`.
- `GetRuleSetsDirFor(execDir, target, id)` — `bin/rule-sets/` для local,
  `<machine>/srs/` для машины.
- `GetSubscriptionsDirFor(execDir, target, id)` — аналогично для тел подписок.
- `GetRemoteConfigPath` (singleton `bin/remote-config.json`) **удалён**.

`internal/constants`: добавлена `RemoteRuleSetsDirName = "srs"`;
`RemoteConfigFileName` переименована в `LegacyRemoteConfigFileName` — она
осталась только ради миграции, новый код в этот файл не пишет.

Машинный ID переехал в `TargetSpec.MachineID` (`core/template/target.go`), а не
поехал вторым параметром через весь пайплайн: каждый слой, которому нужно
разрешить путь, уже получает `TargetSpec`, и любое забытое место молча писало
бы в singleton-папку, то есть в чужой профиль. Плюс `RemoteTargetFor` и
`MachineIDOrEmpty()` (для local всегда `""`).

### 2. Миграция (§2.3, §3.1.8)

`core/services/lxd_remote_migration.go` + вызов в `main.go` до чтения новых
путей. Переносит `remote/state.json`, плоские снапшоты `remote/*.json` и
`bin/remote-config.json` в папку машины — **только если в реестре ровно одна
запись**. При нуле или нескольких пишет warning и не трогает файлы: угадать
владельца нельзя, а потерять настроенный конфиг недопустимо.

Идемпотентна (зовётся на каждом старте), не перезаписывает существующий
destination, умеет cross-device переносом copy+remove. `.srs` и тела подписок
не мигрируют — пересобираются.

### 3. GC в границах машины (§3.1.10, §5.7)

- `collectAllStageRuleSetTags(execDir, target, machineID, td)` и
  `collectAllStageSourceIDs(execDir, target, machineID)` сканируют **только
  свой уровень**; спуск в подпапки убран.
- `DeleteOrphanRuleSetsFor(execDir, target, machineID, tags)`;
  `DeleteOrphanRuleSets` осталась тонкой local-обёрткой.

Раньше обе функции были **обязаны** обходить все уровни `wizard_states/`,
потому что каталог был общий: пропустив чужое состояние, GC сносил чужой живой
файл. С раздельными каталогами обход чужих состояний стал вредным — он
удерживал бы от удаления файл, в этой машине уже никем не упомянутый.

### 4. Платформа — свойство машины (§2.4, §5.8)

`RemoteDaemon` получил `GOOS`/`GOARCH` + метод `Target()` и
`RemoteRegistry.SetPlatform`. Пустая платформа → **linux/amd64, а не платформа
хоста**: подставить `runtime.GOOS` значило бы на macOS-лаунчере молча собрать
darwin-конфиг для linux-роутера. Правится в диалоге машины; визард читает, но
не редактирует.

### 5. Конфиг и деплой на машину (§2.4)

- `exportRemoteConfig` пишет в `<machine>/config.json` (+ `MkdirAll`).
- Deploy читает путь **от того же ID**, на который уходит `ApplyConfig`.
- `ShowConfigWizardForMachine(parent, machine)` — визард, корневой на профиле
  машины; таргет ставится **до** чтения состояния и восстанавливается после
  `LoadState` (иначе meta файла затирала бы id и платформу из реестра).
- Первое состояние машины — из шаблона, не копия local.
- `RemoteRegistry.Remove` удаляет директорию машины целиком.

### 6. Вкладки Local и Remote (§2.1, §2.5)

- `CreateProxyListPanel` — левая колонка обеих вкладок (один виджет, не копия);
  шапка с питанием и выбором машины из неё убрана.
- `ui/machine_list_panel.go` — правая колонка Remote: строка машины с именем,
  платформой, адресом, статусом (или причиной недоступности) и кнопками
  Configure / Start-Stop / Deploy / ✎ / ✕; health опрашивается в фоне.
- `ui/local_remote_tabs.go` — `CreateLocalTab` (список + блок ядра) и
  `CreateRemoteTab` (список + машины), обе через `HSplit` 0.6.
- `ui/app.go`: вкладки `Local | Remote | 🔍 | ⚙ | ?`; динамический
  ⏸️/▶️-индикатор переехал на Local (показывает локальное ядро).

### 7. Окно 1000×700 (§3.2)

`MinWindowSize` + layout `minSizeBox`, которым обёрнут контент главного окна.
`SetFixedSize` не подошёл — он запрещает и растягивание, а требование
«растянуть можно, сжать нельзя». Нижнюю границу держит `MinSize` контента.
Прежние 350×450 остались от одноколоночной эпохи.

### 8. Удалённый мёртвый код

`ui/endpoint_picker.go` и `ui/endpoint_power.go` удалены целиком — после
переноса управления в правую колонку на них не осталось ни одной ссылки.
Вместе с ними убраны осиротевшие ключи локали: `servers.endpoint.badge_local`,
`servers.endpoint.picker_tooltip`, `servers.power.local`,
`servers.power.deploy_missing`, `app.tab.core`.

## Тесты

- `internal/platform/target_paths_test.go` — local игнорирует id; машина
  получает свою подпапку; пустой id = legacy-раскладка; **машины не делят ни
  одного пути**, всё имущество под её директорией, local-пути наружу.
- `core/services/lxd_remote_migration_test.go` — перенос при одной машине
  (включая снапшоты), сохранение файлов при неоднозначности и пустом реестре,
  идемпотентность, отказ перезаписать существующий файл, удаление директории
  машины без урона соседней, дефолт платформы linux/amd64.
- `core/services/srs_isolation_test.go` — GC одной машины не трогает файлы
  другой и local при **совпадающих тегах**; живой тег сохраняется; отсутствующий
  каталог не ошибка; local-GC работает как раньше.
- `ui/min_window_size_test.go` — пол 1000×700 держится, больший минимум
  контента уважается, layout растягивает контент.

## Отклонения от ТЗ

**Тела подписок добавлены в изоляцию.** ТЗ в §2.3 говорило только про `.srs`,
но `bin/subscriptions/` был ровно той же общей папкой с тем же union-GC по всем
состояниям. Оставить его общим значило сохранить нарушение §5.7 в половине
пайплайна. ТЗ дополнено (§2.3, §3.1.6, §3.1.10, §5.5–5.7).

**Платформа переехала в реестр.** ТЗ рисовало `linux/arm64` в строке машины, но
таких полей в `RemoteDaemon` не было, а `GOOS`/`GOARCH` жили в состоянии
визарда. Без переноса §2.4 не выполняло своего обещания: оставался способ
собрать под архитектуру, отличную от показанной. ТЗ дополнено (§2.4, §3.1.7,
§5.8).

**Снапшоты добавлены в миграцию.** Старые remote-снапшоты лежат плоско в
`remote/*.json`; без них пользователь терял сохранённые варианты конфига.

**Исправлена ошибка в §2.4:** путь `bin/remote-configs/<машины>.json` в ТЗ не
существовал (остаток черновика) — заменён на фактический
`bin/wizard_states/remote/<id>/config.json`.
