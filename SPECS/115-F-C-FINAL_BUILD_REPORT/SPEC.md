# SPEC 115 — вкладка «Итог»: сборка в памяти, отчёт, гейт Save

Решения пользователя 28.08.2026. Продолжение SPEC 113-B (реестр исключений)
и окна отчёта импорта (c1dd99d): предупреждения обязаны доходить до
пользователя, единая точка правды — отчёт попытки сборки.

## 1. Переименование и роль вкладки

- Вкладка конфигуратора Files → **«Итог»** (en: Final). Локаль обновить.
- Вкладка = стадия сборки: вход на неё запускает **сборку в памяти**
  (полный конвейер: парсерный кэш → резолв ссылок/цепочек → граф-санитайзер,
  БЕЗ записи config.json и без перезапуска ядра).
- Пока сборка идёт — прелоадер (ProgressBarInfinite + подпись); сборка в
  горутине, мутации виджетов только fyne.Do (никакой работы на UI-потоке).
- По завершении: отчёт предупреждений; **кнопка Save появляется только
  после показа отчёта** (до того скрыта/disabled). Ошибка сборки — текст
  ошибки вместо отчёта, Save не показывается.

## 2. Типизированный реестр отчёта сборки

Расширение реестра SPEC 113-B (in-memory, per-попытка, не в state.json):

- виды записей: `source_excluded` (источник исключён: хоп не найден,
  источник ссылки удалён), `nodes_dropped` (снятые узлы, ГРУППИРОВАТЬ по
  источнику: «Источник X: снято N узлов — причина»), `chain_failed`
  (цепочка не стала узлом — причины уже есть в WarnLog chain_nodes),
  `naive_degraded` (SkippedNaiveReason), `target_missing` (цель detour
  не существует в сборке);
- каждая запись: субъект, ссылка на источник (source_id, если есть),
  человекочитаемая причина по стандарту SPEC 112-A;
- одна попытка сборки — один реестр; новая попытка перезаписывает;
- **инвалидация**: любое изменение модели Мастера сбрасывает реестр
  (отчёт и раскраска не должны врать после правки).

## 3. Поверхности

- **Итог**: полный отчёт (паттерн окна отчёта импорта: скролл, без
  обрезки, Wrapping, Copy). У записи с source_id — переход «показать
  источник»: переключение на вкладку Sources с выделением строки.
- **Sources**: раскраска строк по итогам ПОСЛЕДНЕЙ попытки сборки —
  исключён целиком → ⚠ + причина (существующий механизм SPEC 112-B),
  сняты узлы → пометка «снято N ⚠». До первой попытки и после
  инвалидации — без раскраски (не врём).
- **Тост на Local** про исключённые источники (SPEC 112-B часть B-2) —
  УБРАТЬ (решение пользователя): роль забирает отчёт «Итога» и стойкие
  пометки Sources. Пометки Wizard-Sources от боевых сборок остаются.

## 4. Запреты и требования

- Превью-слой обязан совпадать с боевой сборкой (память
  lazy-cache-vs-lost-state): сборка в памяти использует ТОТ ЖЕ конвейер
  (BuildConfig-путь с ForPreview-вариантом, не параллельная реализация).
- Никаких тестов на вёрстку/форматирование; тестируется логика: наполнение
  реестра по видам, группировка узлов по источнику, инвалидация при правке
  модели, гейт Save (чистая функция состояния «сборка прошла+отчёт
  показан»).
- Локаль: новые строки в bin/locale/ru.json.
- win7 = go1.20; fyne-ловушки (Wrapping, NewWindow для высокого) учесть.
- Ветки не переключать; git-операции записи агентам запрещены.
