# SPEC 152 — правило пресета без условий по замыслу автора идёт в конфиг

Решение владельца 29.09.2026. Контракт 1.1.100, TASKS_LXBOX §97.

## Проблема

Гейт «правило без условий» (TEMPLATE_LANG §5.1, контракт 1.1.81/1.1.82)
выбрасывал любое правило пресета (`route.rules`, `dns.rules`), в котором после
подстановки не осталось ни одного поля-условия (`route_rule_conditions` /
`dns_rule_conditions` в `contract/registry/allowlists.json`), с кодом
`template_fragment_dropped`. Под него попадали и правила, которые автор
написал без условий намеренно: голый `{"action": "sniff"}`, тестовое правило
на весь трафик.

## Требования

Правило пресета без условий после подстановки обрабатывается по причине:

1. **Условия снял сбой** → выпадает с `template_fragment_dropped` (прежнее
   поведение). Сбой — одно из двух:
   - все ссылки `rule_set` висячие (набор снят `#if`/`#enable`, выпал без
     источника);
   - хоть одна ссылка на переменную в теле правила дала Dropped или нулевое
     значение JSON (`null`, `""`, `[]`, `{}`, `false`, `0`). Ссылка — `"@имя"`
     в позиции значения (с элементом массива и сплайсом `text_list`) и
     вставка `@{имя}` в `#tpl`.
   Пример: `{"rule_set": ["ai"], "outbound": "Ai"}` без набора не становится
   «весь трафик в Ai».
2. **Иначе (так написал автор)** → правило идёт в конфиг как есть с новым
   предупреждением `template_rule_unconditional` (warning; `owner` — id
   пресета, `kind` — `route.rules` / `dns.rules`): условий в теле нет,
   литерал без значения (`"domain_suffix": []`), условия только в ложных
   ветках `#if`.

Не меняются: правило, целиком снятое ложным `#if`/`#enable` (без кода);
гейты «нет `outbound`/`action`» и «нет `server`/`action`».

## Критерий различения и его граница

Признак сбоя по переменной — **на всё правило**, а не на ключ-условие:
пустая переменная в поле-не-условии (`"timeout": "@t"` у sniff без условий)
тоже отправляет правило в случай 1. Ошибка в эту сторону повторяет прежнее
поведение (правило выпадает) и не открывает перехват всего трафика; привязка
к ключу потребовала бы протащить путь ключа через обходчик и `#if`-спред.
Имена в предикатах `#if`/`#enable` не считаются (выбор ветки, а не значение),
необъявленное имя, наоборот, сбой (контракт 1.1.103: без этого
`{"outbound": "@опечатка"}` уходило в конфиг и перехватывало весь трафик;
поймал CI, `TestExpand_UnresolvedVar`), невыбранные
ветки `#if` не обходятся.

Пограничный случай, решённый в пользу п. 2: условный элемент массива, у
которого все `#if` ложны без `else` (`"source_port_range": [{"#if": …}]` →
`[]`), — «выражение автора вычислилось в пустоту», правило остаётся.

## Критерии приёмки

- Пресет с `{"action": "sniff"}` / DNS `{"action": "predefined", …}` — правило
  в конфиге, `template_rule_unconditional`.
- Пресет с висячим `rule_set` или пустой переменной в единственном условии —
  правила нет, `template_fragment_dropped`. Route и DNS.
- Эталоны `core/build/testdata/wizard_template_config` не меняются (в штатном
  шаблоне правил без условий нет).
- Корпус `contract/corpus/template/for_each/` — 4 новых кейса.
