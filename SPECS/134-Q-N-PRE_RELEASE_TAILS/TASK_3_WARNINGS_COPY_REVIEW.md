# ТЗ 3 · Вычитка текстов кодов предупреждений (`warnings.json`, en + ru)

**Цель одной фразой:** пройти 81 код предупреждения в
`contract/registry/warnings.json` и довести их тексты до одного качества —
чтобы человек из каждого понимал **что случилось**, **чем это ему грозит** и
**что делать**, а подстановки соответствовали объявленным параметрам.

---

## 0. Контекст для того, кто репозиторий видит впервые

Приложение — десктопный лаунчер VPN-ядра `sing-box`. Когда узел приезжает из
подписки или ссылки, его поля проверяются по таблицам реестра. Если поле
снято, заменено или узел выброшен — на узел вешается **код предупреждения**.
Человек видит их в списке узлов (значок ⚠/✖ и подстрока) и в карточке узла
(раздел «Предупреждения»: заголовок, текст, «почему так бывает», «что
делать»).

**Тексты живут в одном месте на все приложения** — в реестре контракта. У
лаунчера своих таблиц текстов нет, `bin/locale/ru.json` несёт только обвязку
(слова «Предупреждения», «Подробнее», счётчик «+N»). Тот же реестр читает
мобильное приложение LxBox и генератор документации. Поэтому правка текста —
это правка **контракта**, с ритуалом (см. §6).

## 2. Границы

### Входит

Поля **пользовательских текстов** у кодов в
`contract/registry/warnings.json`:
`title_en`, `title_ru`, `text_en`, `text_ru`,
`cause_en`, `cause_ru`, `fix_en`, `fix_ru`, а также состав `params`, когда он
разошёлся с плейсхолдерами текста.

### НЕ трогать

- `severity` кода — это поведение, а не текст.
- Состав кодов: не добавлять, не удалять, не переименовывать.
- `desc`, `go`, `dart` — служебные заметки для разработчика, **в UI не
  попадают**. Их разбор — смежная находка, см. §7 п. 4, в объём **не входит**.
- `contract/docs/generated/**` — генерируется, руками не править.
- Любой Go-код. Если текст нельзя починить без правки кода — записать в отчёт.
- `core/config/linkmap/**`, `core/config/subscription/shareuri_*.go` — чужая
  работа, только чтение.

## 3. Разведка (проверено, ссылки точные)

### 3.1 Устройство файла

`contract/registry/warnings.json`, **81 код**. Корень:

- `v` — версия словаря;
- `text_params_implicit` (строки 3–6) — **неявные** плейсхолдеры, доступные
  любому коду без объявления: `path` и `value`;
- `warnings` — карта «код → запись».

Запись: `severity`, `params[]`, `title_en/ru`, `text_en/ru`, `cause_en/ru`,
`fix_en/ru[]`, плюс служебные `desc`, `go`, `dart`.

Описание секции — `contract/README.md:75`. Тип в Go —
`core/config/registry/registry.go:382` (`WarningEntry`).

### 3.2 Где какая подстановка работает — **проверено**

| Что | Где |
|-----|-----|
| Заголовок и текст, **с подстановкой** | `core/config/registry/registry.go` — `Registry.WarningText(code, lang, params)`, внутри `substitute()` |
| Причина и советы, **без подстановки** | `Registry.WarningAdvice(code, lang)` — возвращает `cause` и `fixes` **как есть** |
| Слияние неявных `path`/`value` в параметры перед рендером | `internal/nodewarn/nodewarn.go:22–27` (комментарий с нормой), `paramsOf` там же |
| Фильтр параметров при записи кода в состояние — доезжают **только объявленные в `params`** | `core/config/nodeflow/sanitize.go` (`declaredParams`) |

**Норма, подтверждённая фактом:** плейсхолдер в `cause_*`/`fix_*`
**не раскроется** — человек прочитает `{path}` буквально. Автопроверка
показала: сегодня плейсхолдеров в `cause`/`fix` **нет ни у одного из 81
кода**. Норма соблюдена, её надо не сломать.

### 3.3 Где текст видно человеку

- **Подстрока строки узла** — `internal/nodewarn/nodewarn.go:276` (`Subtitle`)
  собирает **только заголовки** кодов уровня error/warning. То есть
  `title_*` часто читается **в отрыве от текста**, и обобщённый заголовок
  вида «параметр не прочитан» в списке не говорит, о каком параметре речь.
- **Карточка узла** — `internal/nodewarn/section.go:116` (`Section`):
  заголовок, текст, причина, советы.
- **Сгенерированная документация** — `contract/docs/generated/warnings.md`,
  **только EN** (`contract/tools/gendocs/warnings.go`).

### 3.4 Машинная сверка `params` ↔ плейсхолдеры — **готовый результат**

Проверка прогнана, вот полный результат по всем 81 коду. Расхождений
ровно **четыре**, все одного рода: параметр объявлен, но в тексте не
используется.

| code | строка | `params` | реально в title/text | замечание |
|------|--------|----------|----------------------|-----------|
| `wg_key_invalid` | **863** | `path`, `value` | `path` | `value` объявлен и не используется. **Возможно намеренно:** в `desc` записи сказано, что значение маскируется (`secret: true` у всех трёх полей ключей) — тогда лишний параметр надо снять, а не вставлять в текст. Решить и записать решение |
| `awg_header_invalid` | **887** | `field`, `path`, `value` | `path`, `value` | `field` — остаток: до контракта 1.1.33 текст был «field {field} removed», потом переписан на `{path}`/`{value}` (история — `contract/README.md:313`), а `field` из `params` не убрали |
| `awg3_field_invalid` | **914** | `field`, `path`, `value` | `path`, `value` | То же самое, тот же заход |
| `ss_method_legacy` | **1876** | `method` | `path`, `value` | Текст пользуется **неявными** `path`/`value`, а объявленный `method` не используется нигде — мёртвое объявление |

Ни одного случая «в тексте плейсхолдер, которого нет ни в `params`, ни в
неявных» — таких нет. Ни одного плейсхолдера в `cause`/`fix` — тоже нет.

Воспроизвести проверку (и прогнать её **после** правок):

```
python3 - <<'PY'
import json,re
d=json.load(open('contract/registry/warnings.json',encoding='utf-8'))
ph=re.compile(r'\{([a-z_0-9]+)\}'); implicit=set(d['text_params_implicit'])
for code,e in d['warnings'].items():
    params=set(e.get('params') or [])
    tt=' '.join([e['title_en'],e['title_ru'],e['text_en'],e['text_ru']])
    cf=' '.join([e['cause_en'],e['cause_ru']]+e['fix_en']+e['fix_ru'])
    used=set(ph.findall(tt)); incf=set(ph.findall(cf))
    if params-used or used-params-implicit or incf:
        print(code, 'unused=',sorted(params-used),
              'undeclared=',sorted(used-params-implicit),
              'in_cause_fix=',sorted(incf))
PY
```

### 3.5 Кандидаты по содержанию — таблица с конкретным замечанием

Тексты в целом хорошего качества: у подавляющего большинства кодов есть и
последствие, и совет. Ниже — только то, к чему есть **конкретная** претензия.
**Тексты не переписаны намеренно** — это диагноз, формулировки за
исполнителем.

**А. Обобщённый заголовок, а конкретика только в тексте.** Помнить §3.3:
в списке узлов видно **один заголовок**.

| code | строка | замечание |
|------|--------|-----------|
| `uri_param_unknown` | 1150 | `Ссылка: параметр не прочитан` — имя параметра (`{query_name}`) только в тексте. В списке узел с пятью такими кодами покажет пять одинаковых строк |
| `json_field_unknown` | 1175 | То же: `Конфигурация: поле не прочитано` |
| `wgconf_param_unknown` | 1125 | То же: `WireGuard: неизвестный ключ в конфигурации` |
| `naive_extra_headers_invalid` | 657 | `naive: заголовок отброшен` — **какой** заголовок (`{entry}`) только в тексте |

**Б. В текст подставляется машинный токен.** Проверить **фактом** (прогнать
код и посмотреть, что реально приезжает в параметр), а не по имени.

| code | строка | замечание |
|------|--------|-----------|
| `core_rejected` | 194 | `{reason}` — сырая строка ядра вида `initialize outbound[0] vless[proxy-de-1]: …`. Осознанное решение (норма — `contract/docs/CANON.md` §9), но текст вокруг обязан подготовить читателя к техническому куску |
| `chain_invalid` | 1526 | `{reason}` — проверить, человеческая ли это фраза или идентификатор правила |
| `dialer_proxy_unusable` | 1620 | `{cause}` — то же; если это токен (`not_found`, `cycle`), в UI он читается как мусор |
| `awg3_core_unsupported` | 1007 | `{reason}` — проверить |
| `tailscale_core_unsupported` | 1644 | `{reason}` — проверить |
| `xhttp_param_reset` | 269 | `{reason}` — проверить, что подставляется имя режима, а не внутренний код |

**В. Термин остался непереведённым в русском заголовке.** Спорная группа:
часть терминов — это **имена полей и значений**, которые человек увидит в
конфиге, и переводить их нельзя. Решение по каждому — за исполнителем,
критерий: «человек это слово где-то ещё увидит своими глазами?»

| code | строка | замечание |
|------|--------|-----------|
| `detour_with_listen_port` | 1294 | `Цепочка не применена: у узла listen_port` — имя поля в заголовке; в тексте уже есть человеческое «слушает собственный порт» |
| `ws_early_data_converted` | 1688 | `WebSocket: early data преобразован` — калька, и род сказуемого от английского термина |
| `selector_as_auto` | 474 | `Ручной selector импортирован как автовыбор` — `selector` это тип группы sing-box; проверить, видит ли человек это слово в UI |
| `xhttp_mode_forced_packet_up` | 294 | `Режим XHTTP доопределён в packet-up` — `packet-up` это значение поля, скорее всего законно; сверить с соседями |
| `vmess_security_unknown` | 612 | `заменён на auto` — `auto` значение поля, законно; сверить тон с соседними «Поле снято: …» |
| `masque_vhttp_invalid` | 819 | Заголовок называет только исход (`приведена к h3`), исходное значение — только в тексте |
| `chain_strip_utls_on_reality` | 1549 | `ClientHello` в причине — термин без пояснения |

**Г. Единство тона.** Массив кодов «Поле снято: …» / «Field removed: …»
(`packet_encoding_unknown` 589, `tuic_congestion_invalid` 750,
`tuic_udp_relay_mode_invalid` 773, `anytls_min_idle_invalid` 796,
`unknown_key` 1709, `type_invalid` 1734, `field_conflict` 1782,
`field_requires` 1806) задаёт образцовый шаблон:
**что снято → почему ядро иначе упадёт → узел жив**. Прочие коды сверять с
ним, а не изобретать новый тон.

## 4. Ловушки

1. **Плейсхолдер в `cause`/`fix` не раскроется.** Подстановка живёт только в
   `WarningText`. Соблазн «дописать `{value}` в совет» даёт пользователю
   буквальные фигурные скобки. Сегодня нарушений нет — не завести.
2. **Параметр, не объявленный в `params`, до текста не доедет.**
   `declaredParams` в `core/config/nodeflow/sanitize.go` фильтрует при записи
   кода в состояние. Добавляете плейсхолдер — добавляйте имя в `params`.
   Исключение — `path` и `value`: они неявные, объявлять **не надо** (и у
   `ss_method_legacy` текст именно ими и пользуется).
3. **`path` и `value` иногда объявляют явно, и это не всегда ошибка.** У
   `wg_key_invalid` явное объявление `value` связано с маскировкой секрета.
   Прежде чем «чинить», прочитать `desc` записи.
4. **Заголовок читается в отрыве от текста** (`nodewarn.Subtitle`). Правило:
   заголовок обязан быть самодостаточным настолько, чтобы строка в списке
   что-то значила.
5. **Тексты общие с мобильным приложением.** Нельзя опираться на реалии
   десктопа («нажмите правой кнопкой», «откройте вкладку Local») — на
   телефоне таких вещей нет. Формулировать про **сущности**, а не про
   поверхности.
6. **Не ломать корпус.** У каждого кода есть кейсы в корпусе контракта.
   Тексты в ожиданиях корпуса не сверяются (там коды и пути), но **`params`
   сверяются**. Снятие параметра из `params` — изменение поведения, гоняйте
   раннер корпуса.
7. **Не менять `severity`.** Уровень решает, попадёт ли код в подстроку и
   каким значком. Это не редактура.
8. **Русский — не подстрочник.** У пары EN/RU одна мысль, а не одинаковый
   порядок слов. Но и не расходиться по смыслу: обе стороны читают один
   реестр.
9. **Не «улучшать» то, что уже хорошо.** Восемьдесят процентов кодов в
   порядке. Каждая лишняя правка — строка в диффе контракта, которую кто-то
   будет сверять глазами.

## 6. Ритуал правки реестра (обязателен, без него CI красный)

## 7. Как проверить

Локально:

```
go build ./...
go generate ./contract/...
git status --porcelain contract/docs/generated
```

Последняя команда после коммита генерации обязана молчать.

Именованные тесты — только свои и только по имени. Релевантные существующие
раннеры (гонять, **если** менялись `params`):

```
go test ./core/config/... -run 'TestRegistryWarningsHaveCauseAndFix' -count=1
```

(тест живёт в `core/config/registry_body_test.go` и требует у каждого кода
непустых `cause`/`fix` на обоих языках). Раннер корпуса контракта — тоже по
имени; имя взять из `core/config/registry_body_test.go`.

**Новых тестов не писать.** Тестов на формат и тексты UI в проекте нет
принципиально. Единственное исключение, которое **стоит предложить в отчёте,
но не внедрять без спроса**: линтера «плейсхолдеры текста ⊆ `params` ∪
неявные, и ни одного в `cause`/`fix`» сегодня нет — расхождения из §3.4
дожили именно поэтому.

**Запрещено локально:** `go test ./...`, прогон пакета целиком «на всякий
случай», `go vet ./...` по репозиторию, Win7-сборка с `go.win7.mod`.

**Запрещено вообще:** запускать `sing-box run`, убивать процессы sing-box
(`pkill`, `killall`) — на машине живой VPN.

Полный прогон — в CI, после захода:

```
gh workflow run ci.yml --ref develop -f run_mode=tests
```

### Смежная находка — **в объём не входит**

Служебное поле `go` у девяти записей указывает на **удалённые** файлы:
строки 78, 357, 771, 794, 817, 840, 861, 912, 1052 ведут в

другая правка и другой параграф changelog), а записать в отчёт.
