# ТЗ 1 · Хвосты страховки «ядро отвергло узел»

**Цель одной фразой:** довести до конца четыре недоделанных куска механизма,
который автоматически выключает узел, забракованный ядром, — петлю на
последнем шаге Конфигуратора, второй источник сигнала у демона, тот же цикл
для удалённых машин и перенос причины выключения через бэкап.

---

## 0. Что вообще происходит (контекст для того, кто репозиторий видит впервые)

Приложение — десктопный лаунчер VPN-ядра `sing-box` (форк `sing-box-lx`).
Пользователь добавляет «источники» (подписки, ссылки, JSON), из них собирается
один файл `config.json`, и ядро с ним стартует.

Беда, которую лечит механизм: **ядро проверяет конфиг целиком и падает на
первом же узле, который не принимает.** Одна битая строка в одном узле
подписки из сотни оставляла человека вообще без связи.

Лечение (SPEC 132, волны 1–5 уже сделаны): перед записью `config.json`
собирается **кандидат**, по нему гоняется `sing-box check`, из текста ошибки
вынимается тег отвергнутого узла, узел выключается с причиной, конфиг
пересобирается — и так по кругу, пока ядро не примет. Заменяется `config.json`
**только** принятым конфигом.

Читать перед работой (обязательно, там обоснования решений владельца):

- `SPECS/132-F-N-CORE_REJECTED_NODE_AUTO_DISABLE/SPEC.md` — §5 (два источника
  сигнала), §5А (кандидат), §5В (Конфигуратор), §10 (что реализовано),
  §11 (остатки, строки 884–894);
- `SPECS/132-F-N-CORE_REJECTED_NODE_AUTO_DISABLE/TASKS.md` — волны 6, 6А, 7;
- `SPECS/132-F-N-CORE_REJECTED_NODE_AUTO_DISABLE/IMPLEMENTATION_REPORT.md` —
  раздел «Что осталось и почему».

## 1. Границы

### Входит

Четыре хвоста, каждый закрывается независимым коммитом:

| # | Хвост | Файлы правки |
|---|-------|--------------|
| 1.1 | Петля на шаге **Final** Конфигуратора до разблокировки Save | `ui/configurator/tabs/final_tab.go`, новый адаптер-выключатель поверх черновика |
| 1.2 | Второй источник сигнала — **отказ демона на реальном старте** | `core/backend_daemon_darwin.go` |

### НЕ трогать

- **Визуальные изменения UI не проектировать.** Если по ходу выяснится, что
  нужна новая плашка, новая кнопка, другой текст на кнопке или другая
  раскладка — **остановиться и пометить в отчёте «требует решения
  владельца»**, свой вариант не выдумывать и не внедрять. Существующие
  поверхности переиспользовать как есть.
- `core/config/linkmap/**`, `contract/registry/**`,
  `core/config/subscription/shareuri_*.go` — **только чтение**, там работает
  другой исполнитель.
- `core/corereject/parse.go` — разборщик строки ошибки уже готов и покрыт
  тестами; менять его не надо, надо звать.
- Движок **classic** (обычный спавн `sing-box run`) второго источника сигнала
  **не получает** — сознательное решение владельца (SPEC 132 §5): лаунчер
  stdout/stderr ядра не читает вовсе. Не пытаться это «починить».
- Никаких новых полей в модели состояния: причина живёт записью в
  существующем списке `Node.Warnings` (решение владельца 19.09.2026).

адаптер черновика из хвоста 1.1. Делать 1.3 **после** 1.1.

подписки остаётся выключенным **без объяснения** — визуально неотличим от
выключенного рукой.

## 3. Ловушки

1. **Поверхностная копия слайса на Save.** `presenter_state.go:113` кладёт в
   состояние `append([]wizardmodels.Source(nil), p.model.Sources...)`. Если
   выключать узлы в **сохранённом** состоянии, а не в черновике, Save затрёт
   отметки. Поэтому у хвоста 1.1 выключение обязано идти в черновик
   (`FindNodeByLink` по `ui/configurator/models/node_rule_ref.go:216`), а не
   через `savedStateDisabler`.
2. **`setNodeEnabled` из `tabs` — ложный друг.**
   `ui/configurator/tabs/source_edit_window.go:99` правит deep-copy источника.
   Взять её «потому что похоже называется» — значит потерять правку.
3. **Поток Fyne.** Всё, что трогает виджеты, — только через `fyne.Do`
   (`final_tab.go:377`, `:396`). Сам цикл блокирующий (зовёт `sing-box check`
   подпроцессом) — держать его в горутине. Диалог предела уже сделан
   неблокирующим: показ через `fyne.Do`, ответ каналом.
4. **Не заводить второй гейт на Save.** `SaveGateAllows` (`final_tab.go:197`)
   уже функция состояния (норма SPEC 115 §1). Цикл должен просто держать
   существующий предикат закрытым, а не добавлять свой флаг рядом.
5. **`Stop` в диалоге предела на Final оставляет Save ДОСТУПНОЙ** — решение
   владельца (SPEC 132 §5В.5, вариант А): правки не теряются, выключенные
   остаются выключенными, первый Connect продолжит цикл с того места.
   Не «защищать» пользователя, блокируя Save.
6. **После Save не гонять цикл второй раз впустую.** Кандидат уже чист —
   достаточно одного `check`.
7. **Пересчёт `warnings` стирает список целиком.** Есть шесть мест пересчёта;
   все обязаны идти через `Node.ReplaceDerivedWarnings`
   (`core/state/node_enabled.go:218`), которая бережёт авторитетные коды.
   Прямое присваивание `n.Warnings = …` в новом коде — ошибка.
8. **Демон (1.2): FATAL приходит асинхронно, потоком статусов.** Момент
   получения сигнала не совпадает с моментом сборки. Выключение узла обязано
   вести к **пересборке и повторному применению**, иначе демон снова получит
   тот же конфиг. Продумать защиту от бесконечной пары «применили → FATAL →
   выключили → применили»: у цикла для этого уже есть жёсткий потолок
   (`coreRejectHardCap`), у асинхронного пути его нет — нужен свой счётчик на
   один заход старта.
9. **Демон живёт под тегом `darwin`.** `core/backend_daemon_darwin.go` не
   компилируется на Windows/Linux — проверить, что общий код не сломал их
   сборку (`go build ./...` на своей ОС покрывает только свою; полный
   кросс — CI).
10. **Бэкап (1.4): формат карты `disabled{}` — часть контракта обмена с
    мобильным приложением.** Нельзя молча заменить карту на массив объектов.
    Расширение должно быть **аддитивным** и совместимым в обе стороны:
    старый импортёр обязан продолжать читать новый файл, новый — старый.
    Если аддитивно не выходит — **остановиться, пометить «требует решения
    владельца»** и описать варианты в отчёте.
11. **Remote (1.3): не поднимать локальные dirty-маркеры.** См.
    `presenter_save.go:350–353` — remote-Save локального `config.json` не
    касается, и это намеренно.

## 4. Шаги

### Хвост 1.1 — петля на Final

1. Написать адаптер черновика под существующий интерфейс
   `nodeDisabler` (`core/rebuild_corereject.go:102`): `Disable(link, reason)`
   → `FindNodeByLink(m, link).SetCoreRejected(reason)`, `Commit()` — no-op
   (черновик сохранит Save), `Label(link)` — имя источника для списка.
   Место файла — рядом с презентером Конфигуратора; в `core` его тащить не
   надо, интерфейс для того и заведён.
2. На входе в Final (там уже собирается конфиг для предпросмотра) пустить
   цикл: кандидат → `check` → выключение названных в черновике → пересборка.
3. Держать `SaveGateAllows` закрытым, пока цикл идёт; по окончании —
   отпустить. Ход показывать существующей строкой статуса, список
   выключенных — существующим окном «Показать».
4. Диалог предела подключить тем же колбэком, что и у локальной сборки;
   `Stop` → Save остаётся доступной.
5. Убедиться, что после Save повторного цикла нет.

### Хвост 1.2 — сигнал демона

1. В ветке FATAL (`core/backend_daemon_darwin.go:515`, `:530–532`) и на
   `ApplyError` c `Rejected() == true` прогнать текст через
   `corereject.Parse` с множеством тегов текущего собранного конфига.
2. Тег сопоставлен → выключить узел в сохранённом состоянии
   (`savedStateDisabler` уже есть), пересобрать и применить заново.
3. Завести счётчик попыток на один заход старта, чтобы не зациклиться.
4. Тег не сопоставлен / ошибка не про узел → поведение как сейчас (лог,
   сообщение пользователю), ничего не выключать.

### Хвост 1.3 — удалённые машины

1. Перевести `writeRemoteConfig` (`presenter_save.go:373`) на «кандидат →
   `check` → атомарная замена» по образцу локального Step 5
   (`core/rebuild.go:218`). Заодно уходит неатомарная запись на `:414`.
2. Подключить цикл с адаптером черновика из 1.1.
3. Локальные dirty-маркеры не поднимать.
4. Отказ демона на доставке (`ApplyError.Rejected`) — второй источник
   сигнала и здесь, по той же схеме, что в 1.2.

### Хвост 1.4 — зазор бэкапа

1. Решить, как аддитивно донести причину рядом с картой `disabled{}`
   (`core/backup/convert_v7.go:59–80`). Если совместимого способа нет —
   **остановиться и вынести владельцу**.
2. Экспорт: класть причину вместе с отметкой выключения.
3. Импорт (`core/backup/import10.go:168–170`, `:306–312`): читать причину и
   восстанавливать её записью `core_rejected` в `warnings[]` узла после того,
   как `PendingDisabled` сматчится с реальным узлом.
4. Старый бэкап без причины читается как сегодня — просто выключенный узел.

## 5. Как проверить

Локально — **только это**:

```
go build ./...
```

Если написан новый тест (нужен максимум **один** на весь заход, комплексный и
по данным, а не россыпь юнитов) — запустить только его, по имени:

```
go test ./core/... -run 'TestИмяВашегоТеста' -count=1
```

Кандидаты, куда дописать существующим таблицам, а не плодить файлы:
`core/rebuild_corereject_test.go` (таблица сценариев цикла),
`core/state/node_enabled_test.go` (жизненный цикл вердикта).

**Запрещено локально:** `go test ./...`, прогон пакета целиком «на всякий
случай», `go vet ./...` по репозиторию, Win7-сборка с `go.win7.mod`.

**Запрещено вообще:** запускать `sing-box run`, убивать процессы sing-box
(`pkill`, `killall`) — на машине живой VPN; трогать бинарь ядра в бандле.
Вызов `sing-box check` подпроцессом — это как раз то, что делает сам
механизм, и он безопасен.

Полный прогон — в CI, **после** законченного захода:

```
gh workflow run ci.yml --ref develop -f run_mode=tests
```

(на push в `develop` `ci.yml` сам не стартует). Упавшее разбирать отдельным
заходом: `gh run view <ID> --log-failed`.

Тестов на форматирование строк, тексты UI и вёрстку **не писать**.

## 6. Как коммитить

Ветка **только `develop`**. Запрещены `git checkout`/`switch`, `stash`,
`reset`, `rebase`, `clean`, `git add -A`, `git commit -a`. Рабочая копия
разделяемая — чужие незакоммиченные правки не трогать.

Коммитить **явным списком путей**, по одному коммиту на хвост:

```
git commit -m "feat(spec132): петля страховки на шаге Final Конфигуратора" -- \
  ui/configurator/tabs/final_tab.go \
  ui/configurator/presentation/<новый_адаптер>.go \
  docs/release_notes/upcoming.md
git push origin develop
```

Перед закрытием обновить:

- `docs/release_notes/upcoming.md` — пункт EN в `### Highlights` или
  `### Fixes`, зеркальный RU в `### Основное` / `### Исправления`;
- `docs/ARCHITECTURE.md` — если менялись потоки данных;
- `RELEASE_NOTES.md` — при заметном для пользователя изменении UX;
- отметить `[x]` закрытые пункты в
  `SPECS/132-F-N-CORE_REJECTED_NODE_AUTO_DISABLE/TASKS.md` (волны 6, 6А).
