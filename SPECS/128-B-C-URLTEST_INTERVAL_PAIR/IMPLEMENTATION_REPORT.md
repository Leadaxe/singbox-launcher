# IMPLEMENTATION REPORT 128 · Пара interval/idle_timeout

Дата: 15.09.2026. Ветка: develop. Статус: Complete.
Issue: [#118](https://github.com/Leadaxe/singbox-launcher/issues/118).

## Что сделано

Правило 6 графового санитайзера: urltest-группа, у которой `interval` больше
`idle_timeout` (в том числе дефолтного 30m, когда `idle_timeout` не задан),
получает `idle_timeout` = `interval`. Сам `interval` не меняется никогда.

## Изменённые файлы

| Файл | Что |
|------|-----|
| `core/build/outbound_graph_urltest.go` | **новый** — правило, разбор длительностей ядра (суффикс `d`) |
| `core/build/outbound_graph_sanitize.go` | правило 6 в шапку; вызов в `sanitizeEntryRefs`, ветка `isGroup()`, до разбора состава |
| `core/build/outbound_graph_urltest_test.go` | **новый** — 6 тестов |
| `docs/release_notes/upcoming.md` | EN + RU |

Четыре входа `interval` в конфиг (`singbox_groups.go`, `xray_balancer.go`,
`direction_twins.go`, `adapter_source.go`) НЕ трогались — они продолжают
переносить провайдерские значения как есть, санитайзер обезвреживает результат
в единственной точке.

## Ключевые решения

1. **Тянуть вверх `idle_timeout`, а не урезать `interval`.** `interval` — период
   перепроверки всех узлов группы; замена `3h` → `5m` (как просила issue) дала бы
   серверу в 36 раз больше проб. `idle_timeout` же — таймер засыпания цикла
   проверок, его удлинение стоит одной лишней проверки у неактивной группы.
2. **Коэффициент ×1**, решение владельца. ×2 обсуждался и отклонён ради
   прослеживаемости: при ×1 в конфиге стоит ровно провайдерское число.
3. **Одна точка вместо четырёх** — санитайзер, по принципу
   «новое ребро идёт в санитайзер, а не новой частной проверкой».
4. **Мусорный `interval` не подменяется** — ядро отвергнет его с внятным
   сообщением про сам ключ; тихая подстановка спрятала бы ошибку конфига.
5. **Свой разбор длительностей** — ядро понимает суффикс `d`, `time.ParseDuration`
   нет. Дни разворачиваются в часы, остальное отдаётся stdlib: вторая полная
   копия парсера разошлась бы с ядром по крайним случаям.

## Находка шире issue

Штатный вариант `1h` у `urltest_interval` (`bin/wizard_template.json:486-494`)
ломал старт ТОЧНО ТАК ЖЕ, без всякой подписки: `idle_timeout` шаблон не задаёт
нигде, `1h > 30m`. Тем же правилом закрыто.

| Проверка | Результат |
|----------|-----------|
| `go build ./...` | чисто |
| `go vet ./core/build/` | чисто |
| `go test ./core/build/` | ok (пакет целиком) |
| Живое ядро 1.14.0-lx.33, конфиг из issue | «до»: `check` exit=0, `run` → `FATAL ... interval must be less or equal than idle_timeout`; «после»: `run` стартует и держится |

Проверка живым ядром здесь обязательна: `sing-box check` этот класс ошибок
пропускает, пара валидируется в конструкторе группы на старте. Тестовое ядро
гасилось по захваченному PID, рабочий процесс не затрагивался.
