## Волна 2 · Причина = запись `core_rejected` в `warnings[]` — ЗАКРЫТА

**Решение владельца 19.09.2026 отменило отдельное поле.** `disabled_reason` не
заводится нигде; причина живёт записью существующего списка предупреждений
узла. Обоснование и цена — SPEC.md §4.4.

- [x] Хранение: `{code: "core_rejected", params: {reason}}` в `Node.Warnings`.
      Модель не меняется вовсе — ни поля, ни структуры.
      `core/state/node_enabled.go`: `SetCoreRejected` / `CoreRejectedReason` /
      `ClearCoreRejected`.
- [x] **Одно место-правило пересчёта** — `Node.ReplaceDerivedWarnings(fresh)`
      вместо прямого присваивания списка. Переведены ВСЕ шесть точек
      пересчёта (таблица в SPEC.md §4.4): миграция при загрузке state,
      миграция masque, правка тела, regen из исходника, форма AmneziaWG,
      вставка записи. Новый авторитетный код вносится в
      `authoritativeWarningCodes` одной строкой.
- [x] Ловушка `recountOneNode`: условие «коды уже считали» было
      `Warnings != nil`, и узел с ОДНОЙ записью вердикта навсегда остался бы
      без кодов своего тела — а они и объясняют, за что ядро его не приняло.
      Заменено на `hasDerivedWarnings` (список из одних авторитетных записей
      = «не считали»).
- [x] **Вердикт привязан к ТЕЛУ** (норма CANON §9.4):
      `CarryCoreVerdict(old)` при refetch (то же тело — держится, другое —
      снят, узел включён обратно) и
      `RevalidateCoreVerdictAfterBodyChange(before)` в трёх точках правки
      тела. Сравнение — `state.BodiesEquivalent` (семантическое, не
      побайтовое). Оживает только узел, выключенный СТРАХОВКОЙ.
- [x] **Единый сеттер включения** `Node.SetNodeEnabled(bool)`; переведены все
      четыре точки UI, включая «включить все» drilldown'а. Включение и
      выключение рукой стирают вердикт.
- [x] Бэкап: правок не потребовалось — `warnings[]` уже едут в оба конца.
      Схема: `disabled_reason` снят из обоих `$defs`, описание `warnings[]`
      получило оговорку про авторитетность `core_rejected` (контракт 1.1.10).
- [x] Миграция: не нужна, запись аддитивная.

**Тесты:** `core/state/node_enabled_test.go` — жизненный цикл вердикта
(выключение, замещение дубля, порядок в списке, `kind=unsupported`), пересчёт
производных кодов его не стирает, смена тела снимает и включает узел, то же
тело в другом написании держит, refetch во всех трёх ветках, round-trip
`state.json` + миграция при загрузке.

**Хвост (владелец не заказывал, записано):** у ПОДПИСКИ состав в бэкап не
едет вовсе — вместо `nodes[]` экспортируется карта `disabled: {tag: 0}`
(`core/backup/convert_v7.go` ↔ `core/backup/import10.go`). Причина
выключения узла подписки через бэкап поэтому не переносится. У папок и ручных
серверов состав едет целиком, и запись переносится.

## Волна 4 · Цикл страховки в ОБЩЕЙ функции сборки — ЗАКРЫТА

Один механизм на все входы. Живёт в `coreRejectLoop.run`
(`core/rebuild_corereject.go`), зовётся из `RebuildConfigIfDirty`.

- [x] Цикл: кандидат → `check` → назван узел → выключить + причина →
      пересобрать из ТОГО ЖЕ состояния в памяти → круг; чисто → замена.
- [x] Прерывание: ошибка не про узел / без тега / тег не сопоставлен / тот же
      тег назван повторно / круг не выключил ничего нового.
- [x] Предел `coreRejectAskAfter = 10` → колбэк
      `decide(disabled int) bool`; `true` снимает предел до конца прохода,

- [x] **Адаптер выключателя** — интерфейс `nodeDisabler`

      `savedStateDisabler` над сохранённым state: правки копятся в памяти,

      Конфигуратора оставлен — волна 6.
- [x] Итог прохода — `events.ConfigBuiltPayload.DisabledNodes`

- [x] Входы, получившие цикл БЕЗ своего кода: pre-start обоих движков, кнопка

## Волна 6А · Remote-цели: тот же цикл (SPEC 097/098)

**Решение владельца 19.09.2026: страховка действует на remote ТАК ЖЕ, как
локально** — узлы выключаются по вердикту `check`. Оговорка принята
сознательно: конфиг чужой машины проверяет ЛОКАЛЬНЫЙ бинарь, и его версия
может отличаться от ядра той машины («обновят»).

Зависит от волны 6: путь сохранения remote собирает из ЧЕРНОВИКА
(`BuildRemoteConfig(p.model)`), а не из сохранённого состояния, — значит
выключать надо в черновике, тем же адаптером.

- [ ] `writeRemoteConfig`
      (`ui/configurator/presentation/presenter_save.go:373-421`) — перевести
      на «кандидат → `check` → замена». Сегодня там простой `os.WriteFile`,
      **даже не атомарный**, и `sing-box check` не зовётся вовсе: отвергнутый
      узел всплывает только на `Deploy`, ответом демона
      `ApplyError.Rejected()` (`core/services/lxd_remote_deploy.go:46-77`).
- [ ] Цикл с адаптером черновика (волна 6).
- [ ] Не ломать текущую доставку: локальные dirty-маркеры по-прежнему НЕ
      поднимаются (`:350-353`) — remote-Save локального `config.json` не
      касается.
- [ ] Отказ демона на `Deploy` — второй источник сигнала и здесь; разбор
      строки (волна 1) к `ApplyError.Message` применим.
