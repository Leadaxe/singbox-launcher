# SPEC 109 — Полный конфигуратор DNS

Статус: **ТЗ к реализации**. Продолжает линию SPEC 104/108: сущность
настраивается формой, а не написанием JSON руками.

## Проблема

**DNS-сервер добавляется написанием JSON.** `showDNSServerDialog`
(`ui/configurator/tabs/dns_tab.go:630`) открывает пустое multiline-поле с
одной из двух заготовок — `udp` или `group`. Всё остальное пользователь
пишет по памяти: тип, порт, путь DoH, `tls.server_name`, `domain_resolver`,
`detour`. Ядро поддерживает **двенадцать** типов (`constant/dns.go:18-30`),
из них осмысленных для пользователя пять; форм нет ни для одного.

Это то же, от чего ушли Направления в SPEC 104 — только там JSON остался
запасным путём на отдельной вкладке, а здесь он единственный.

**Детур DNS-запроса не выбирается.** Через какой канал уходит запрос —
решающий вопрос: DoH через VPN и DoH напрямую дают разные ответы и разную
наблюдаемость. В правилах цель выбирается списком, здесь — вписывается
строкой `"detour": "proxy-out"`, если пользователь знает, что такое поле
есть.

**Шаблон беднее мобильного.** У нас шесть плоских серверов
(`bin/wizard_template.json` → `dns_options.servers`), у LxBox — десять, и
они **параметризованы**: `vars` с типами `outbound` (детур), `enum` (выбор
IP провайдера), `dns_servers` (резолвер имени самого сервера). У них же
есть **DNS Shield** — группа из девяти провайдеров с `mode: fastest`,
которой у нас нет вовсе.

**Правила перетаскиваются, источники и Направления — нет.** Механизм D&D
уже вынесен в переиспользуемый `internal/fynewidget/drag_reorder.go` и
подключён только на Rules и DNS.

## Решения (согласовано)

| # | решение |
|---|---|
| D1 | Форма на каждый тип DNS-сервера: UDP, DoT (`tls`), DoH (`https`), Group. Добавление — кнопкой `+`, как в других списках |
| D2 | Детур выбирается списком Направлений — тем же механизмом, что цель правила |
| D3 | На вкладке DNS появляется выбор Направления (детур) для сервера |
| D4 | DNS Shield переносится из LxBox: группа провайдеров с `mode: fastest` |
| D5 | Серверы шаблона переносятся из LxBox — они полнее и параметризованы |
| D6 | D&D из Rules подключается на Sources и Directions |
| D7 | На вкладке Rules «outbound» переименовывается в «Направление» |

## Модель

### Тип сервера

Пять форм вместо одного JSON-поля. Поля берутся из опций ядра
(`option/dns.go`), а не выдумываются:

| Тип | Ключ ядра | Поля формы |
|---|---|---|
| UDP | `udp` | адрес, порт (53), детур, резолвер имени |
| TCP | `tcp` | то же |
| DoT | `tls` | адрес, порт (853), SNI, детур, резолвер имени |
| DoH | `https` | адрес, порт (443), путь (`/dns-query`), SNI, детур, резолвер имени |
| Группа | `group` | состав (теги серверов), режим, `error_ttl`, `win_ttl` |

Прочие типы ядра (`quic`, `h3`, `local`, `hosts`, `fakeip`, `dhcp`,
`tailscale`, `legacy*`) формы не получают: `local` уже есть в шаблоне
записью без параметров, остальные — либо нишевые, либо служебные.
Правка их JSON остаётся доступной (см. ниже).

**JSON остаётся запасным путём**, как у Направления: форма покрывает
обычные случаи, а вкладка JSON — то, что в неё не помещается. Убрать её
нельзя — иначе типы без формы станут ненастраиваемыми.

### Детур (D2, D3)

Поле `detour` сервера — тег Направления. Список берётся из того же
источника, что цель правила (`business.GetAvailableOutbounds`), поэтому:

- в списке нет групп подписок (SPEC 108, S3);
- нет парных auto-групп (SPEC 104, D-9А);
- есть `direct-out` и `block-out` из шаблона.

**Ловушка:** у `type: group` детура быть НЕ должно — LxBox отдельно чинил
это (`docs/spec/tasks/319-dns-group-must-not-have-detour.md`). Группа сама
не ходит в сеть, ходят её участники; `detour` на ней ядро либо игнорирует,
либо отвергает. Форма группы поля детура не показывает.

### Перенос из LxBox (D4, D5)

`app/assets/wizard_template.json` → `dns_options.servers`, десять записей.
Формат **не копируется дословно**: у LxBox старая схема шаблона
(`selectable_rules`, `default_channels`), у нас — SPEC 053/056.

Переносится:

| Что | Наше состояние |
|---|---|
| `google_udp`, `google_dot`, `google_doh` | нет (есть только `google_doh` без параметров) |
| `cloudflare_udp`, `cloudflare_dot` | `cloudflare_udp` есть, `cloudflare_dot` нет |
| `opendns_udp`, `quad9_doh`, `yandex_udp`, `yandex_dot` | нет |
| `safe_dns_dot` (Quad9 / AdGuard / AdGuard Family) | нет |
| `dns_shield` (группа из девяти, `mode: fastest`) | нет |

Параметризация серверов (`vars` внутри записи сервера) — главное, что
переносится вместе с содержимым: без неё пользователь опять правит JSON,
чтобы сменить IP провайдера или канал.

**Расхождение имён типов:** у LxBox переменная резолвера объявлена как
`type: "dns_servers"`, у нас поддерживается `dns_server`
(`core/template/preset_types.go:424`). Свести к одному имени, второе
принимать как синоним бессрочно — иначе перенесённый шаблон не прочитается.

### D&D (D6)

`internal/fynewidget/drag_reorder.go` уже переиспользуем:
`NewDragReorderGroup` + `NewDragHandle(group, slotIdx, rowGetter)`.
Подключение на Sources и Directions — это регистрация ручки в строке и
обработчик коммита, а не новый механизм.

**Ловушка:** порядок Направлений значим (нижние ссылаются на верхние через
`addOutbounds`), а порядок источников — нет. Для Directions перестановка
обязана проверять, что ссылка не уехала вперёд своей цели.

### Переименование (D7)

`wizard.rules.label_outbound` («Outbound:») и
`wizard.add_rule.label_outbound` → «Направление». Тег в конфиге не
меняется — это подпись.

## Ловушки

| # | что |
|---|---|
| T1 | `type: group` не принимает `detour` — форма группы не показывает поле |
| T2 | Порядок Направлений значим (`addOutbounds` вверх), порядок источников — нет |
| T3 | `dns_servers` vs `dns_server` — принимать оба, писать одно |
| T4 | Серверы шаблона (`kind=template`) переносят только `enabled`; тело живёт в шаблоне (SPEC 056) — форма правит USER-патч, а не тело |
| T5 | `domain_resolver` не должен ссылаться сам на себя и образовывать цикл: сервер, резолвящий своё же имя, вешает старт |
| T6 | Контракт: типы серверов и их поля — общие с LxBox, класть в `contract/registry` |
| T7 | Win7 (`go1.20`): без `min`/`max`/`slices`/`maps` в не-test коде |

## Открытое (решить до реализации)

**Объём переноса шаблона.** Перенести все десять серверов LxBox или только
недостающие? Полный перенос даёт паритет и закрывает расхождение, но
меняет умолчания у существующих пользователей (например, `google_doh` у
нас включён и без параметров, у LxBox — параметризован и с другим
детуром). Предлагаю: перенести все, включёнными оставить только те, что
включены сейчас у нас.
