# SPEC 178 — Окна Конфигуратора и Профайлера: по одному на цель, с именем цели в заголовке

## 1. Проблема

Сценарий: одновременно работают локальное ядро и ядро на роутере (удалённая машина под lxd). Пользователю нужны **одновременно** Профайлер и Конфигуратор и для Local, и для машины — например, чтобы сравнить трафик и поправить правила на обеих сторонах, не закрывая окна по очереди.

Что сломано сегодня:

1. **Конфигуратор — глобальный синглтон, не зависящий от цели.** `UIService.WizardWindow` хранит одно окно. `showConfigWizardFor` при любом вызове (Local или `Configure` у машины) просто фокусирует уже открытое окно, даже если оно открыто для другой цели. Открыть Конфигуратор Local и Конфигуратор роутера рядом невозможно — вторая кнопка молча поднимает первое окно (для другой цели!), что ещё и вводит в заблуждение: кажется, что открылся Конфигуратор машины.
2. **Заголовки окон не называют цель.** Окно Конфигуратора всегда называется «Config Wizard», окно Профайлера — «Traffic Profiler» (и этот заголовок каждую секунду перерисовывается `FormatRecordingTitle`, так что любой одноразовый `SetTitle` затёрся бы). Профайлеры уже умеют жить параллельно (локальный — синглтон `trafficManager`, машинные — `machineProfilers[id]`), но два окна «Traffic Profiler» на экране неразличимы.
3. **Скрытая зависимость через глобал.** `showConfigWizardFor` при открытии ставит `config.SetTailscaleRemoteStateDirRoot(target.TailscaleStateDir)` и никогда не снимает. Пока окно одно, это «работает» (следующее открытие перезапишет). С двумя окнами последний открытый диктует корень состояния tailnet **обеим** сборкам: Save локального окна, открытого раньше окна роутера, унесёт в локальный `config.json` путь роутера. Это уже латентный баг и сегодня: после закрытия окна роутера глобал остаётся выставленным, и локальная пересборка по Update/Restart (вне Мастера) получает чужой корень.

## 2. Цель

- Конфигуратор: **по одному окну на цель** — `local` и `machine:<id>`. Повторный вызов для той же цели фокусирует её окно; вызов для другой цели открывает новое окно рядом.
- Профайлер: поведение открытия не меняется (локальный синглтон + по одному на машину), меняется только заголовок.
- Заголовки обоих окон несут имя цели:
  - Конфигуратор: `Config Wizard — Local` / `Config Wizard — <Name машины>`;
  - Профайлер: `Traffic Profiler — Local` / `Traffic Profiler — <Name машины>`, а при записи — `Traffic Profiler — <цель> ⚡ Recording · mm:ss` (цель остаётся в заголовке и во время записи).
- Корень состояния tailnet машины не живёт в глобале «с момента открытия окна»: он действует только на время разбора/сборки конфига этой цели и не протекает в сборку другой.

## 3. Требования

### 3.1 Конфигуратор

- R1. Ключ окна: `local` для локальной цели, `machine:<RemoteDaemon.ID>` для машины. Реестр открытых окон лежит в `UIService` вместо одиночного поля `WizardWindow`.
- R2. `showConfigWizardFor` ищет окно по ключу цели; найдено → `RequestFocus` и выход; нет → строит новое. Окна разных целей сосуществуют.
- R3. Всё, что сегодня читает `UIService.WizardWindow`, переводится на осмысленный вопрос:
  - `core/elevation.go` (`switchToProxyAction`): блокировать «Switch to proxy mode» только пока открыт **локальный** Конфигуратор — его Save пишет локальный state; окно машины к локальному tun отношения не имеет.
  - `ui/wizard_overlay.go` (overlay-перехват кликов по главному окну) и `ui/components/click_redirect.go`: overlay показан, пока открыт **хотя бы один** Конфигуратор; клик поднимает окно (если открыто несколько — локальное, иначе любое) и его дочерние окна.
  - `FocusOpenChildWindows` становится принадлежностью окна (per-window), а не одиночным полем `UIService`.
- R4. Заголовок окна: `locale.Tf("Config Wizard — %s", subject)`, где subject — `locale.T("Local")` либо `RemoteDaemon.Name`. Имя машины берётся из записи реестра, переданной в `ShowConfigWizardForMachine` (не из state).
- R5. `watchExternalStateChanges` уже фильтрует события по `(Target, MachineID)` презентера — ничего менять; но проверить, что попап при внешней правке приходит только в окно той цели, чей state поменяли.
- R6. На закрытие окна из реестра удаляется только его ключ; `OnStateChange` зовётся как и раньше.
- R7. `SwitchConfigTarget` (SPEC 097) вызовов в коде не имеет — не трогать и не опираться на него.

### 3.2 Профайлер

- R8. `traffic.WindowDeps` получает поле `Subject string` (имя цели для заголовка). `trafficWindowManager` (локальный) передаёт `locale.T("Local")`, `OpenMachineProfiler` — `d.Name`.
- R9. `tprof.FormatRecordingTitle` принимает subject (или появляется обёртка в `ui/traffic`), чтобы заголовок с записью и без неё содержал цель. Фраза «Traffic Profiler» и «Recording» — через locale как сейчас (проверить, что сейчас строка английская и без locale — тогда ключи добавить вместе с переводом в `bin/locale/ru.json`).
- R10. Поиск родительского окна по заголовку (см. комментарий в `ui/traffic/window.go` про `buildByClientView(deps, win)`) не должен сломаться: окна получают явную ссылку, как и сейчас.

### 3.3 Корень состояния tailnet

- R11. Убрать `config.SetTailscaleRemoteStateDirRoot(...)` из `showConfigWizardFor`. Корень машины действует только внутри операций разбора/сборки конфига цели: `writeRemoteConfig` (Save/Close→Save/`RebuildMachineConfig`) и тот путь разбора узлов, который порождает `GeneratedEndpoints` для окна машины (`parseOutboundsForSave` и вызов парсера при заходе на Rules/Preview). Предпочтительно — протащить корень параметром до `applyTailscaleStateDirectory` (через `ParserConfig`/опции разбора или `TargetSpec` модели), чтобы глобала не осталось вовсе. Если протяжка требует правки десятков сигнатур — допустим scoped set/restore под отдельным `sync.Mutex` вокруг разбора+сборки одной цели, с явным комментарием почему; `RebuildMachineConfig` уже делает set/defer-restore — унифицировать с ним.
- R12. Локальная сборка (Save локального окна и пересборка вне Мастера) обязана идти с пустым удалённым корнем, независимо от того, какие окна открыты.

## 4. Критерии приёмки

- A1. Открыть Конфигуратор Local и затем `Configure` у подключённой машины → два окна рядом; заголовки «Config Wizard — Local» и «Config Wizard — <имя машины>». Повторные нажатия фокусируют соответствующее окно.
- A2. Закрыть одно — второе живёт; overlay главного окна гаснет только после закрытия последнего.
- A3. Профайлер Local и профайлер машины открыты одновременно; заголовки различимы; во время записи в заголовке есть и цель, и таймер.
- A4. С открытым окном роутера Save локального окна (с узлом tailscale) не содержит `TailscaleStateDir` роутера; Save окна роутера — содержит. Проверяется грепом `state_directory` в обоих `config.json`.
- A5. «Switch to proxy mode» в диалоге прав TUN заблокирован только при открытом локальном Конфигураторе.
- A6. `go build ./...` зелёный; CI (`run_mode=tests`) зелёный.

## 5. Вне рамок

- Переключение цели внутри одного окна (вкладка Target SPEC 097) — не трогаем.
- Внутренняя «шапка» (баннер) внутри окна — не делаем; достаточно заголовка окна. Если Саша после показа решит, что нужен баннер, — отдельная правка.
- Профайлер: архитектура открытия не меняется.
