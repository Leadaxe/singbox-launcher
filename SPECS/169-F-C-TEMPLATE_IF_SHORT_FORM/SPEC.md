# SPEC 169 — Короткая форма `#if`: тернарный массив `[cond, V, E]`, `#if` на операции `#do`

Статус: **C** (закрыта 15.10.2026). Тип: Feature. Контракт: бамп `contract/VERSION` → **1.1.125**, норма `contract/docs/TEMPLATE_LANG.md` §4.1–4.5, §4.5.1, §4.6, §6.7.1, решение **D-133**, LxBox — `contract/TASKS_LXBOX.md` §122.

Решения владельца приняты 15.10.2026 в обсуждении пресета «Tunnel ingress» (SPEC 170, следующая): пресету нужны условные операции `#do`, а писать `{"#if": {"#and": ["@x"], "#value": …}}` ради одного предиката — шум, который язык терпел только по инерции.

---

## 1. Проблема

1. **Длинная форма на один предикат.** §4.1 требует ровно один из `#and`/`#or` с непустым списком даже для одиночного условия: `{"#if": {"#and": ["@ipv6_enabled"], "#value": {…}}}`. В шаблоне лаунчера 20 конструкций `#if`, почти все с одним предикатом.
2. **Две конвенции на одно и то же условие.** `#filter` обхода узлов (§6.5) уже принимает голое `cond` — предикат или `#and`/`#or` без обёртки, — а `#if` в той же спеке обёртку требует. Автор шаблона держит в голове, где какая форма.
3. **Операция `#do` не умеет условий.** Объект операции — ровно один глагол (§6.7.1, `parseNodeDo`). Собрать теги узлов с флагом в одну переменную, а без флага — в другую, одним обходом нельзя: нужен либо второй пресет на каждый список, либо условие на операции.

## 2. Решение — язык

### 2.1 Три формы `#if` по типу значения (D-133)

| Значение ключа `#if…` | Форма | Статус |
|---|---|---|
| **массив** `[cond, V]` или `[cond, V, E]` | короткая тернарная | **канон** |
| **объект** с ключом `#value` (или легаси `value`) | длинная `{"#and"\|"#or": […], "#value": V, "#else": E}` (§4.1) | читается бессрочно |
| что-либо иное (строка, число, bool, null, объект без `#value`) | — | ошибка загрузки; толерантный рантайм — ветка не выбрана + `template_unknown_directive {key}`, как сегодня для объекта без `#and`/`#or` |

- `cond` — условие §4.1–4.2 **без обёртки для одиночного предиката**: `"@flag"` (P1), `{"@x": "#notEmpty"}` и прочие P2–P5, `{"#not": cond}`, `{"#and": [cond…]}`, `{"#or": [cond…]}`, вложение любой глубины. Это ровно грамматика `#filter` (§6.5) и тела `#enable` (§4.6); легаси-ключи `and`/`or` внутри `cond` читаются, как везде (D-073).
- **`cond` никогда не массив.** Сахар-список `["@a", "@b"]` (= and), допустимый у `#enable`, в позиции условия массива `#if` **запрещён**: `{"#if": [["@a", "@b"], V]}` — ошибка загрузки. Иначе первый элемент нельзя было бы отличить от значения по форме. Несколько условий — только `{"#and": […]}` / `{"#or": […]}`.
- Чтение позиционное и единственное: **первый элемент — условие, второй — значение, третий — иначе.** `{"#if": ["@a", "@b"]}` значит «если `a`, то строка `"@b"`» (подстановка `@b` по §3), а не «a и b». Это не ловушка, а грамматика; кейс корпуса фиксирует чтение.
- Длина массива: 2 или 3. Один элемент, четыре и более — ошибка загрузки. `V` или `E` равные `null` — ошибка загрузки (как `#value: null` / `#else: null` сегодня).
- Семантика **полностью равна длинной форме**: `[cond, V]` ≡ `{"#and": [cond], "#value": V}` с тем лишь отличием, что `cond` не оборачивается; `[cond, V, E]` ≡ `… "#else": E`. Ленивое вычисление, Dropped-каскад §5.1, сплайс ветки-массива на один уровень (§4.4, D-123), merge/last-wins map-spread (§4.3), именованные ключи `#if…` с суффиксом (§4.3, D-045) — всё без изменений. Корпус проверяет равенство парными кейсами.

### 2.2 Где действует

| Позиция | Норма | Сегодня | Короткая форма |
|---|---|---|---|
| map-spread: `#if…` среди полей объекта | §4.3 | `{"type": "tun", "#if": {"#and": ["@a"], "#value": {"x": 1}, "#else": {"x": 2}}}` | `{"type": "tun", "#if": ["@a", {"x": 1}, {"x": 2}]}` |
| array-element: объект ровно с одним ключом `#if…` | §4.4 | `["@addr", {"#if": {"#and": ["@v6"], "#value": "@addr6"}}]` | `["@addr", {"#if": ["@v6", "@addr6"]}]` |
| фрагмент пресета целиком (rule_set[] / rules[] / dns_servers[] / dns_rules[] / outbounds[]) — частный случай array-element | §4.4, §6.1 | `{"#enable": ["@geoip_enabled"], "tag": "geoip-ru", …}` | `{"#if": ["@geoip_enabled", {"tag": "geoip-ru", …}]}` |
| `default_value` переменной: верхний уровень и per-platform | §7.4, `vars_default.go` | `{"#if": {"#and": [{"@runtime.platform": "windows"}], "#value": "a", "#else": "b"}}` | `{"#if": [{"@runtime.platform": "windows"}, "a", "b"]}` |
| `on_change.set` → цель (`EvalIfScalar`) | §4.5, §4.7 | `{"@dns_strategy": {"#if": {"#and": ["@ipv6_enabled"], "#value": "prefer_ipv4", "#else": "ipv4_only"}}}` | `{"@dns_strategy": {"#if": ["@ipv6_enabled", "prefer_ipv4", "ipv4_only"]}}` |
| **операция `#do`** (новое) | §6.7.1 | — | `"@tags": {"#if": ["@node.allow_lan", {"#append": "@node"}]}` |

Не меняется:

- **D-044** (§4.3): `#if` значением скалярного поля внутри дерева `config` по-прежнему не поддерживается — ни длинной, ни короткой формой. Скалярное значение по условию ведётся через `on_change`.
- **`#enable`** (§4.6): плоский гейт `{"#if": cond, …поля…}` **отвергнут** владельцем (форма гейта остаётся `#enable`, D-065 в силе). У объявлений переменных и `params[]` `#enable` означает «неактивно», а не «отсутствует», — тернарной формой это не выразить, и `#enable` там незаменим. На фрагментах пресета `#enable` остаётся законным; канон для «фрагмент есть при условии» — array-element `{"#if": [cond, фрагмент]}`.
- **`#filter`** (§6.5) — уже голое `cond`, без изменений.
- Именованные ключи `#if1`, `#if tun-only` (D-045) работают с массивом так же.

### 2.3 Операция `#do` с условием

Значение ключа `"@имя"` в `#do` — **объект операции**, к которому на каждом узле применяется обычный map-spread `#if` (любой из двух форм) с пространством узла (`@node`, `@node.<поле записи>`, `@node.body.<путь>`, переменные пресета, глобальные, `@runtime.*` на desktop):

```json
"#do": {
  "@all_nodes":   { "#append": "@node" },
  "@lan_nodes":   { "#if": ["@node.allow_lan", { "#append": "@node" }] },
  "@other_nodes": { "#if": [{ "#not": "@node.allow_lan" }, { "#append": "@node" }] },
  "@named":       { "#if": ["@node.body.server", { "#append": "@node.body.server" }, { "#append": "@node" }] }
}
```

- Результат вычисления на узле обязан быть **объектом ровно с одним глаголом** (операция выполняется) или **пустым объектом** (`#if` ложен без `#else` — узел пропущен молча, без предупреждения, как пустое значение `#append` сегодня).
- Валидатор загрузки проверяет глаголы **внутри обеих веток**: неизвестный глагол, два глагола, ветка не-объект, ветка с ключами кроме глагола — ошибка загрузки. Правая часть `#append` в ветке — по прежней норме (ссылка, строка, `#tpl`).
- Один ключ `#if…` на операцию (объект операции — не место для нескольких условий; второй `#if…`-ключ — ошибка загрузки). Рядом с `#if…` в объекте операции других ключей быть не должно: `{"#if": […], "#append": …}` — ошибка загрузки (смешение гейта и значения, которое владелец отверг).
- `#do` без `#if` — как раньше. `#final`, `unique`, `wizard_ui: internal`, порядок шагов сборки §6.7.3 — без изменений.

### 2.4 Что НЕ вводится (решения владельца)

- Плоский гейт `{"#if": cond, …}` — отвергнут (§2.2).
- Переименование или снятие `#enable` — нет.
- `#if` значением скалярного поля в `config` (снятие D-044) — нет, отдельный вопрос.
- Сахар-список в позиции `cond` массива — нет (§2.1).
- Условие на уровне `#append` (`{"#append": {"#if": …}}`, условие внутри значения) — отвергнуто как спрятанный гейт.

## 4. Шаблон лаунчера

Движок читает обе формы, поэтому шаблон можно не трогать. Решение этой SPEC: **переписать `bin/wizard_template.json` на короткую форму** последним этапом (20 конструкций `#if`; `#enable` не трогать) — это и есть лучшая проверка эквивалентности: golden-конфиги `core/build/testdata/wizard_template_config/*.json` и `core/build/testdata/golden/*` обязаны остаться **байт в байт** прежними. Если владелец решит отложить переписывание до паритета LxBox — этап снимается без последствий для остального.
