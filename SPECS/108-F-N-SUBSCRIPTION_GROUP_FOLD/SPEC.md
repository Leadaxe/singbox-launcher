# SPEC 108 — Свёртка подписки в группу: одна галка вместо четырёх

Статус: **ТЗ к реализации**. Продолжение SPEC 104 (Направления): та же мысль —
одна сущность вместо двух, настройка формой, а не набором флагов.

## Проблема

У подписки четыре галки, и пользователь обязан знать, как они складываются:

| Галка | Что делает сейчас |
|---|---|
| `Local auto (urltest)` | создаёт `<PFX>:auto` — urltest по узлам ЭТОЙ подписки |
| `Local select` | создаёт `<PFX>:select` — selector по её узлам, `default` = её `:auto` (включает `Local auto` сам) |
| `Exclude from global outbounds` | узлы подписки НЕ попадают в глобальные Направления |
| `Expose local group tags to global outbounds` | сами группы `:auto`/`:select` становятся кандидатами в Направления |

Полезный сценарий один: «подписка на полсотни узлов, в общий список тащить всё
не хочу — пусть приедет одной строкой». Он требует **трёх** галок разом
(`Exclude` + `Local auto`/`select` + `Expose`), и ни одна из них по отдельности
этого не говорит. Остальные семь комбинаций либо бессмысленны, либо ничего не
меняют в конфиге — включённая `Local auto` без `Expose` создаёт группу, которую
никто не видит.

Вторая проблема: локальные группы попадают в цели правил
(`ui/configurator/business/outbound.go`, ветка «Add local outbounds from all
ProxySource»). Правило может сослаться на `AL:select`, хотя это не Направление,
а группировка — и такая ссылка живёт по чужим правилам жизненного цикла
(исчезает вместе с подпиской, переименовывается вместе с префиксом).

## Решение

**Одна галка** — «свернуть подписку в группу». Отвечает ровно на «сворачивать
ли». Чем именно заменить — на **отдельной вкладке** внутри окна подписки.

Выключена — как сейчас: узлы подписки попадают в Направления по отдельности.

Включена — узлы подписки **заменяются** одной записью: в `proxy-out` приезжает
одна строка вместо пятидесяти, отдельных узлов там нет.

### Три расклада (вкладка «Группа»)

| Расклад | Что уезжает в конфиг |
|---|---|
| **селектор** | `<PFX>:select` — ручной выбор среди узлов подписки |
| **автогруппа** | `<PFX>:auto` — urltest по узлам подписки |
| **селектор с автогруппой** | `<PFX>:select` + парный `<PFX>:auto` первой опцией и умолчанием |

Третий — ровно `Direction{Auto: …}` из SPEC 104, только на уровне подписки:
селектор с автогруппой, которая стоит первой и становится `default`.
Настройки автогруппы те же (режим `least_test` \| `round_robin`, `url`,
`interval`, `tolerance`, `pool`, `pool_tolerance`, `sticky_hash`) — виджеты
переиспользуются с вкладки «Автовыбор» окна Направления.

Расклад **автогруппа** заодно закрывает нынешнее состояние «`Local auto` без
`select`»: оно перестаёт быть невыразимым.

## Решения (согласовано)

| # | решение |
|---|---|
| S1 | Одна галка вместо четырёх. Выбора «все узлы + селектор» нет: галка включена → узлы **заменяются** группой |
| S2 | Расклад выбирается на вкладке настроек группы, не рядом с галкой: галка — «сворачивать ли», вкладка — «во что» |
| S3 | Локальные группы **не цели правил**. Это группировка и сахар к Направлениям |
| S4 | В списке Направлений локальные группы не показываются вовсе (секция «Группы подписок» из SPEC 104 убирается) |
| S5 | Правило, ссылающееся на локальную группу — и вообще на что-либо, не являющееся Направлением, — **при загрузке состояния** сбрасывается на `direct`, с записью в лог |
| S6 | Схема тегов (`<PFX>:auto` / `<PFX>:select` из префикса подписки) не меняется — она работает, и её смена сломала бы ссылки |
| S7 | Третий расклад — именно «селектор с автогруппой», а не две независимые группы: автогруппа первой опцией и умолчанием |

## Модель

### Состояние

`core/state/connections.go` — `Source`:

```go
// Fold — свёртка подписки в группу (SPEC 108). nil = не свёрнута.
Fold *SourceFold `json:"fold,omitempty"`

type SourceFold struct {
    // Mode — во что заменяются узлы: "select" | "auto" | "select_auto".
    Mode string `json:"mode"`
    // Auto — параметры автогруппы; используется при mode = auto | select_auto.
    // Форма та же, что у Направления (SPEC 104).
    Auto *configtypes.DirectionAuto `json:"auto,omitempty"`
}
```

Старые поля `ExcludeFromGlobal` и `ExposeGroupTagsToGlobal`
(`connections.go:75,82` и `configtypes/types.go:101,103`) **читаются
бессрочно, не пишутся**: при загрузке разворачиваются в `Fold` (см. §Миграция).

### Миграция состояния (одноразовая, на загрузке)

Правило одно: встретили старую комбинацию — привели к новой, обратно не
сохраняем.

| Было | Стало |
|---|---|
| `Exclude` + группы + `Expose` | `Fold{Mode}` по наличию групп: select+auto → `select_auto`, только select → `select`, только auto → `auto` |
| группы + `Expose`, без `Exclude` | то же самое: узлы и так дублировались, свёртка — то, что имелось в виду |
| группы без `Expose` | `Fold` не создаётся, группы удаляются: они не доезжали до конфига |
| `Exclude` без групп | `Fold` не создаётся; `ExcludeFromGlobal` сохраняется как есть — см. §Открытое |

### Материализация

Свёрнутая подписка эмитит группу вместо узлов:

- узлы подписки по-прежнему попадают в `outbounds[]` конфига (их нужно, чтобы
  группа на них ссылалась), но **исключаются из пула глобальных Направлений** —
  это существующий механизм `FilterNodesExcludeFromGlobal`
  (`core/config/outbound_filter.go:17`);
- тег группы добавляется в кандидаты Направлений — существующий
  `collectExposeTagCandidates` (`core/config/outbound_validity.go:46`);
- при `mode = select_auto` автогруппа разворачивается тем же проходом 0, что и
  двойник Направления (`core/config/direction_twins.go`): у записи `:select`
  ставится `Auto`, дальше конвейер общий.

То есть новых механизмов эмиссии не заводим — переиспользуем три существующих,
меняется только то, кто и когда их включает.

### Правила → direct (S5)

`core/state/load_v6.go`, после разбора: правило с `Outbound`, не входящим в
множество тегов Направлений (`connections.direction_outbounds[].tag` +
литералы `direct`/`reject`/`drop`/`block-out`), получает `Outbound = "direct"`.
В лог — `WarnLog` с именем правила и прежней целью.

**Почему direct, а не выключение правила:** выключенное правило пользователь не
заметит и решит, что маршрутизация сломалась молча; правило на `direct` работает
предсказуемо и видно в списке.

**Почему на загрузке, а не на сборке:** пользователь должен видеть новое
состояние в списке правил сразу, а не гадать, почему конфиг ведёт себя иначе,
чем показывает интерфейс.

## UI

### Окно подписки

`ui/configurator/tabs/source_edit_window.go:332-335` — четыре галки заменяются
одной. Ключи локали `wizard.source.local_auto`, `local_select`,
`exclude_global`, `expose_tags`, `expose_tags_tooltip` удаляются, добавляется
одна пара (галка + подсказка).

Новая вкладка рядом с `Settings / Preview / Overview / JSON` (`:1137-1141`) —
**«Группа»**: видна только при включённой галке (как вкладка «Автовыбор» у
Направления, SPEC 104). Содержимое:

- выбор расклада (три пункта);
- при раскладах с автогруппой — её настройки: режим, интервал, tolerance, URL,
  и для `round_robin` размер пула, tolerance пула, липкость.

Разметка — как на вкладке «Автовыбор»: подпись фиксированной ширины слева
(`Border`, не `GridWithColumns`), подсказка с переносом, чекбоксы липкости в два
ряда.

### Список Направлений

`ui/configurator/outbounds_configurator/configurator.go` — заголовки секций и
показ локальных строк убираются: в списке только Направления. Ключи
`wizard.outbound.section_service`, `section_directions` удаляются.

### Цели правил

`ui/configurator/business/outbound.go` — ветка «Add local outbounds from all
ProxySource» удаляется целиком: локальные группы больше не предлагаются.

## Открытое (решить в реализации)

**`Exclude from global` без локальных групп.** Сейчас это выразимо: «узлы
подписки не идут в общий список, и групп у неё нет» — подписка фактически
отключена от Направлений, но её узлы есть в конфиге и доступны как цели правил
поимённо. Новая модель этого не покрывает: галка свёртки всегда создаёт группу.

Варианты: (а) оставить `ExcludeFromGlobal` как отдельное поле состояния без UI —
читается, но не выставляется; (б) при миграции считать это раскладом
`select` (появится группа, которой не было); (в) считать подписку выключенной.

Склоняюсь к **(а)**: не ломает существующие конфиги и не выдумывает за
пользователя того, чего он не просил. Решение подтвердить перед фазой 1.
