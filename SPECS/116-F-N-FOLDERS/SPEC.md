Папка **уже существует** как сущность модели и полностью работает на

**Чего нет: пользователь не может создать папку и не может положить в неё
ни одного узла.** Ровно одна дырка, но она делает всю готовую механику
недостижимой: `NewFolderSource` не вызван ни из одного UI-пути, у окна
источника нет ветки настроек папки, у узла нет операций «в папку».

Этап 3 = **только UI-создание/наполнение папок и операции над узлами**
плюс дыры, которые вскроются по дороге (§4). Модель, эмиссия, резолв,
гард, свёртка — не проектируются заново и не трогаются, кроме мест,
названных в §4 поимённо.

## 2. Требования пользователя (согласованы, пересмотру не подлежат)

Перенесены дословно по смыслу из прежней редакции и уточнений:

- **П1.** Папка — контейнер узлов в списке Sources: одна строка, одно имя,
  один переключатель, одна тег-политика, один общий detour; каждый узел
  внутри включается и выключается отдельно.
- **П2.** Правый клик по узлу подписки → **move to** / **copy to** папку,
  с **авторазыменованием Origin** (`origin.subUrl → null`) там, где узел
  становится свободным.
- **П3.** **«Взять всю папку → JSON её узлов»** — операция выгрузки
  содержимого папки одним JSON-документом.
- **П4.** **Заливка подписки в папку** — merge по **сырому тегу**
  (не по URL, не по позиции, не по содержимому).
- **П5.** **Drag-n-drop только внутри списка**: узлы таскаются внутри
  своего контейнера, папки — в общем списке источников; перетаскивания
  через границу контейнера нет. Перенос между контейнерами — командой
  меню.
- **П6.** `FolderReplace.mode` = **manual | auto | both**, с **явным
  тегом** (не позиционным деривативом).

Требования П1, П6 в модели уже выполнены (§1) — этап 3 даёт им UI.
П2, П3, П4 — работа этого этапа целиком.

## 3. Цели и не-цели

**Цели.**

1. Создать папку из UI, назвать, переименовать, удалить.
2. Наполнить папку всеми путями `features/sources.md` §«Наполнение папки»:
   создание руками, вставка URI/wg-INI/JSON, импорт файлов, Add WARP,
   copy to, move to, заливка подписки целиком.
3. Операции над узлом в списке узлов контейнера: включить/выключить
   (есть), переименовать, удалить, move to, copy to, порядок drag-n-drop.
4. Настройки папки в окне источника: имя, тег-политика, общий detour,
   свёртка (Replace — есть), без полей подписки.
5. Выгрузка «вся папка → JSON её узлов» (П3).
6. Заливка подписки в папку merge-правилом папки (П4): совпал — освежить,
   новый — добавить, исчезнувший — **разыменовать**, не удалить.

**Не-цели** (и почему).

- Вложенных папок нет — `features/sources.md`.
- Авто-обновления папки и кнопки «обновить папку» нет: у папки нет URL;
  освежение копий = повторная заливка той же подписки.
- Списка «подписок папки» нет: связь только `origin.subUrl` в узле.
- Move из подписки нет — только copy (состав подписки принадлежит
  провайдеру, `features/sources.md` §«Наполнение папки» п.4).
- Правки body/тега узла ВНУТРИ подписки нет (узлы подписки несвободны).
- Вкладки JSON у окна папки, дающей правку состава документом, нет:
  выгрузка (П3) односторонняя, обратной заливки JSON в папку в этом
  этапе не делаем (§O3).
- Новых виджетов и глифов не изобретаем: используем существующие —
  `theme.MoreVerticalIcon()` (⋮ overflow, `source_tab.go:270`),
  `theme.DocumentCreateIcon()` (правка), `theme.ContentCopyIcon()`,
  `fynewidget.NewSecondaryTapWrap` (правый клик, `source_edit_window.go:1084`),
  `fynewidget.NewDragReorderGroup` (`drag_reorder.go:103`),
  `fyne.NewMenu`/`ShowPopUpMenuAtPosition` (`preview_node_info.go:44`).

## 4. Дыры, которые вскроются (данные, не косметика)

Найдены чтением кода по адресам CODEMAP. Каждая обязана быть закрыта в
этом этапе — иначе операция П2/П4 теряет данные молча.

**Д1. Merge в папку не существует.** `MergeSubscriptionNodes`
(`subscription_merge.go:50`) первой же строкой отсекает
`sub.Kind != SourceKindSubscription`. Политика «исчезнувшего» там —
**удалить**; у папки она обязана быть **разыменовать** (`features/sources.md`
§«Merge-заливка папки»). Значит нужен второй вход с ключом
`(subUrl, сырой tag)` и своей политикой исчезновения, разделяющий с
подписочным merge всё остальное (сохранение `enabled`/`detour`, запрет
удаления при `truncated`). Это **data-критичное место — тесты
обязательны** (§7).

**Д2. Экспорт бэкапа выбрасывает папку.** `core/backup/export.go:98` —
`SourceKindFolder` уходит в warning `WarnBackupSourceKindUnsupported`:
контракт 0.11 папок не знает. До этого этапа это было безобидно (папок
не существовало). После — пользователь создаст папку и потеряет её при
первом же restore. **Открытый вопрос §O1** (contract/** менять нельзя без
согласования сторон).

**Д3. Окно источника считает «не server» = «подписка».**
`source_edit_window.go:779` и `rebuildSettingsLayout:776` — бинарная
развилка `isServer`. Папка получит поле «Subscription URL», отсутствующий
`meta`, и заголовок окна из ветки `default` (`:416` — `switch` без
`SourceKindFolder`). Нужна третья ветка настроек, без URL/интервала/skip.

**Д4. Список узлов контейнера — read-only текстовый блоб.**
`nodeOriginList` (`source_edit_overview.go:289`) склеивает узлы в
`MultiLineEntry` с откатом ввода. Операций над узлом там нет в принципе.
Единственное место с построчным узлом и правым кликом — вкладка Preview
(`source_edit_window.go:1084`, меню `preview_node_info.go:44`), и она
работает на `*config.ParsedNode` — эмитированной проекции, а не на
`corestate.Node`. Операции П2 адресуют **сырой тег** узла (идентичность),
и он в Preview уже известен (`identities[id]`, `:1120`) — значит меню
расширяется там, а не заводится новое место.

**Д5. Авторазыменование не реализовано нигде.** Грепом по
`origin.subUrl`/`SubURL` в UI — ни одной записи, обнуляющей поле.
Правило `features/sources.md` §«Авторазыменование» («любой ручной чих по
копии узла подписки — правка body, raw или тега — немедленно
разыменовывает её с уведомлением») сейчас держится только на том, что
править узлы папки нечем. Как только появится правка узла в папке (цель 3)
и copy to (П2) — правило обязано быть выполнено кодом.

**Д6. `AppendURLsToSources` умеет добавлять только в корень.**
`sources.go:33` — все три ветки (`subs`/`conns`/`jsonNodes`) делают
`append(model.Sources, ...)`. Наполнение папки (цель 2) требует того же
разбора и материализации с целью «узел кладётся в `Source.Nodes` папки»,
а не «новый Source в корень». Пути обязаны быть одни: второй разбор
разъедется с первым (ловушка «эмиттер и парсер ходят парой»).

**Д7. Перенос узла меняет финальный тег → нужен реестр переписи.**
`features/directions.md` §9: перенос между контейнерами — это
переименование, и оно идёт через реестр ссылок, с предупреждением о
протухшем выборе в кэше ядра. В UI уже есть обе половины:
`resetRefsAfterNodeRename` (`source_edit_window.go:1571`) и
`showStaleSelectionDialog:1638`. Операции move/copy обязаны их звать, а не
заводить свои.

## 5. Сценарии

**С1. Создать папку и положить туда десять конфигов.**
Sources → ⋮ → «Add folder» → в списке появляется строка папки («Folder 1»,
0 узлов). Правка → Settings: имя «Proton», префикс `proton-`.
Preview → «Add nodes…» → мультивыбор десяти файлов → десять узлов в папке,
тег каждого — из `#fragment`, а при его отсутствии из имени файла.
Строка списка: «Proton · 10 nodes». Переключатель папки гасит все десять
разом; галка узла в Preview гасит один. Направление с фильтром `^proton-`
забирает ровно эти узлы.

**С2. Скопировать узел подписки в папку (П2).**
Окно подписки → Preview → правый клик по узлу → «Copy to folder…» →
выбор папки → узел появляется в папке. Origin копии **сохраняет** `subUrl`
(она участвует в будущей заливке — `features/sources.md` §«Наполнение
папки» п.3). Финальный тег копии другой (политика новой папки):
пользователь получает предупреждение о протухшем выборе в селекторах
(Д7). Оригинал в подписке не тронут.

**С3. Перенести узел между папками (П2).**
Правый клик → «Move to folder…». Узел уходит из исходного контейнера,
приходит в целевой, `enabled` и личный detour едут с ним. Ссылки на его
прежнюю идентичность переписываются через реестр (Д7). Из **подписки**
пункта «Move to» нет — только «Copy to» (не-цель §3).

**С4. Ручная правка копии → авторазыменование (Д5).**
Узел в папке, у которого `origin.subUrl != ""`, правится (тег, body или
Regen raw) → `subUrl` обнуляется, пользователь уведомлён: «узел отвязан от
подписки — обновление больше не перетрёт вашу правку». Следующая заливка
той же подписки его не тронет и не удалит.

**С5. Залить подписку в папку (П4, Д1).**
Окно папки → «Fill from subscription…» → выбор подписки из списка
существующих → узлы подписки вливаются merge-правилом по паре
(`subUrl`, сырой тег):
совпал — body и `origin.raw` освежены, `enabled`/`detour`/позиция целы;
новый — добавлен включённым; исчезнувший у провайдера — **остался в папке**
с `subUrl = null` и пометкой «исчез у провайдера». Если разбор подписки
был `truncated` — разыменование не выполняется вовсе.
Повторная заливка той же подписки — тот же путь (отдельного «обновить
папку» нет).

**С6. Взять всю папку → JSON (П3).**
Окно папки → «Copy nodes as JSON» → в буфер уходит массив outbound'ов
её узлов — ровно то, что уедет в config.json (та же точка эмиссии
`EmitNodeJSONs`, что у сборки; см. §O2 про финальные теги).

**С7. Удалить папку.**
Диалог с двумя исходами: **удалить вместе с узлами** / **вынести узлы в
корень** (каждый узел становится верхним Source, порядок и личные
`enabled` сохранены; тег теряет политику папки → перепись ссылок, Д7).

**С8. Порядок (П5).**
Узлы таскаются внутри списка узлов контейнера; папки — в общем списке
Sources. Перетащить узел из окна в список источников нельзя — граница
контейнера drag'ом не пересекается.

## 6. Критерии приёмки

Комплексные, по сценариям. Каждый проверяется целиком, от клика до
собранного `config.json`.

**A1 (С1).** Пустая папка создаётся из ⋮-меню Sources; строка списка
показывает имя и «0 nodes» без пометки «источник не дал узлов» (пусто по
воле пользователя — не сбой). После добавления десяти узлов строка
показывает «10 nodes», после выключения двух — «8 of 10 nodes»
(формат существующий, `source_tab.go:422`). Перезапуск лаунчера
сохраняет всё это без сети.

**A2 (С1).** Префикс папки `proton-` даёт в собранном конфиге десять
outbound'ов с тегами `proton-*`; Направление с фильтром `^proton-`
берёт ровно их. Правка префикса не сбрасывает ни одну галку `enabled`,
ни одну ссылку NodeLink (они на сыром теге — `features/sources.md`
§«Тег и идентичность»).

**A3 (С2/С3).** Copy to сохраняет `origin.subUrl`; move to между папками
переносит `enabled` и detour; move из подписки в меню отсутствует.
После обеих операций сборка не теряет ни одного узла молча: всякая
ссылка, чья цель сменила финальный тег, либо переписана реестром, либо
названа в предупреждении.

**A4 (С4, Д5).** Правка тега, body или Regen узла с непустым `subUrl`
обнуляет `subUrl` и показывает уведомление. Следующая заливка той же
подписки этот узел не трогает.

**A5 (С5, Д1) — data-критично.** Заливка подписки в папку:
совпавший узел сохраняет `enabled=false` и личный detour;
исчезнувший у провайдера остаётся в папке с `subUrl=null`;
при `truncated` ни один узел не разыменован;
недостоверный ответ (ошибка/пусто) не трогает `nodes[]` папки вообще.

**A6 (С6).** «Copy nodes as JSON» даёт валидный массив outbound'ов,
который `sing-box check` принимает как фрагмент конфига, с тегами по
решению §O2.

**A7 (С7).** «Вынести узлы в корень» не теряет ни одного узла: число
верхних Source растёт ровно на число узлов папки, порядок и `enabled`
сохранены; «удалить вместе с узлами» требует подтверждения.

**A8 (Д3).** Окно папки не показывает ни поля URL, ни интервала, ни
skip; заголовок окна — имя папки, а не «Source — ».

**A9 (Д2).** Экспорт бэкапа с папкой ведёт себя по решению §O1 и
**никогда не отдаёт успешный файл, молча потерявший папку**.

**A10 (общий, го1.20-гард).** Ни одна новая строка не использует
`min`/`max`/`clear`/`slices.`/`maps.`/`errors.Join`/`PathValue`
(Win7-джоба CI собирает модуль тулчейном go1.20).

## 7. Тесты — минимум по политике

Пишем **только data-критичное**. Форматирование строк и вёрстку тестами
не покрываем (правило `no-ui-format-tests`).

Обязательные:

1. **Merge заливки в папку** (Д1, A5) — таблица: совпал / новый /
   исчез / исчез при truncated / недостоверный ответ. Проверяются
   `enabled`, `detour`, `origin.subUrl`, порядок `nodes[]`.
2. **Авторазыменование** (Д5, A4) — правка тега/body/Regen узла с
   `subUrl` обнуляет поле; узел без `subUrl` не меняется.
3. **Move/copy между контейнерами** (A3) — узел уходит/остаётся,
   `enabled` и detour едут, ссылки на прежний финальный тег собраны в
   список переписи (не проверяем текст диалога — проверяем список).
4. **Вынос узлов папки в корень** (A7) — число и состав сохранены.

Не пишем: тесты на подписи меню, на ширины колонок, на текст
уведомлений.

## §O. Открытые вопросы

Каждый — с вариантами и рекомендацией. Требуют решения пользователя до
соответствующей волны PLAN.

### O1. Папка в бэкапе: контракт 0.11 папок не знает

`core/backup/export.go:98` сейчас роняет папку в warning. `contract/**`
трогать нельзя без согласования обеих сторон, а `features/state.md` прямо
называет `folders[]` «отдельным будущим треком».

Пользователь, создавший папку и сделавший бэкап, обязан узнать о потере
**до** restore, а не после.

- **Вариант А (рекомендуется). Оставить warning, поднять его в UI.**
  Экспорт продолжает не писать папку, но окно отчёта бэкапа
  (`settings_backup_report_window.go`) показывает потерю первой строкой,
  явным текстом «папка N и её M узлов в файл не попали». Контракт не
  тронут, обещание «молчаливых потерь нет» выполнено. Цена: бэкап папки
  реально невозможен до согласования трека `folders[]`.
- **Вариант Б. Экспортировать узлы папки как одиночные `servers[]`,
  политику папки — в предупреждение.** Restore вернёт узлы, но плоско:
  папка развалится, тег-политика и свёртка потеряются, теги в конфиге

  закрывали в SPEC 118.
- **Вариант В. Открыть трек `folders[]` в контракте сейчас.** Правильно
  по существу, но выходит за границы этапа 3 и требует согласования с
  LxBox-стороной (запрет задачи на `contract/**`).

**Рекомендация: А**, с заведением В отдельной задачей.
