# SPEC 104 — Каналы в лаунчере: «правила → каналы → узлы»

Часть программы SPEC 103 (цель 7 пользователя). Активирует spec-only задел 087
(«CHANNELS_MODEL — порт LxBox §125/§267; Channels как отдельное top-level
state-поле, материализация на build-time. XL, нужен live-GUI + миграции»).

## Проблема

Правила лаунчера ссылаются на глобальные outbounds шаблона; правила LxBox — на
каналы `vpn-1..10` (selector + urltest-двойник `vpn-N-auto`, фильтры нод,
include_direct/block, auto-режим). Из-за разных неймспейсов целей правил бэкапы
переносятся только с деградацией (SPEC 103 PLAN §9.D9): правило с телефона на
десктопе указывает на несуществующий тег.

## Цель

Ввести в лаунчер модель каналов LxBox: пользователь настраивает каналы
(имя, фильтр нод, авто-режим), правила ссылаются на каналы, каналы
материализуются в selector/urltest-группы на build-time. После этого:

- цепочка «правила → каналы → узлы» идентична на обоих платформах;
- `rules[].outbound` и `route.final` в LX Backup становятся полностью
  переносимыми (bump схемы бэкапа до v1.1, снятие политики
  «импорт выключенным» для канальных ссылок);
- шаблоны и пресеты могут ссылаться на каналы одинаково.

## Рамки

- Эталон модели — LxBox: `app/lib/models/channel.dart` (§125/§208),
  `group_templates`/`default_channels` (§267), `_buildChannelGroups`
  в `build_config.dart`. Перед портом — архитектурное ревью обеих реализаций
  (цели 9–10 программы), вердикт в DECISIONS.md 103.
- Существующие глобальные outbounds шаблона не ломаются: миграция
  `connections.outbounds[]` → каналы с сохранением тегов, старые state
  читаются (v6 → v7 или совместимое расширение v6 — решить в PLAN).
- Live-GUI (список каналов, фильтры) — в объёме задачи; drag-and-drop и
  тонкости UI — по остаточному принципу.

## Статус

(нужен конформанс-корпус, чтобы порт не разошёлся с LxBox молча).
