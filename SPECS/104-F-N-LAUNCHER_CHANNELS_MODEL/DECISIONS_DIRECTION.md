# SPEC 104 — решения по модели Direction (согласовано 2026-08-22)

Статус: **утверждено, к реализации ещё не приступали** («пока не кодим»).
Эта дискуссия заменяет первую реализацию SPEC 104 (модель `Channel` как
отдельная сущность) — она признана дублем `OutboundConfig` и подлежит сносу.

## Почему переделка
`OutboundConfig` (лаунчер) уже умел то же, что мой `Channel`: фильтр
(`Filters`), default (`PreferredDefault`), direct/block (`AddOutbounds`),
auto (второй urltest), имя (`Comment`). Нужна была не вторая модель, а
выравнивание существующей с LxBox + форма вместо JSON.

## Решения

| # | решение |
|---|---|
| 1 | Термин **Direction** / «Направление». Тип `Direction`, ключ на диске `direction_outbounds[]` (snake_case как все v6-ключи). Отвергнуты: Channel (занято в сети), Exit (по-русски слабее), Route (секция sing-box), Pipe/Tube |
| 2 | Заменяет `OutboundConfig` (лаунчер) и `Channel` (LxBox + моя реализация). Старые ключи JSON читаем бессрочно, пишем только новый |
| 3 | Тег `vpn-N` неизменяем — цель правил. Имя `label` появляется в лаунчере впервые; дефолт `VPN ①…` одинаков на обеих сторонах (`group_templates`/`default_channels` шаблона) |
| 4 | Потолка числа направлений в лаунчере нет (LxBox свои 10 оставляет) |
| 5 | Состав — **одна регулярка** по итоговому тегу узла + знак инверсии; пусто = все узлы всех подписок; подписка отбирается через префикс (`AL:`). Галок по подпискам/серверам **нет** |
| 6 | Регулярка: только тело (без `/…/i`); компилируется **без учёта регистра** на обеих сторонах (Go `(?i)`, Dart `caseSensitive:false`); эмодзи поддерживаются (проверено); рядом с полем — ссылка на справку с примерами |
| 7 | Default — регулярка, первый совпавший, без регистра |
| 8 | Опции состава — `+direct`, `+block`, **направления, стоящие выше по списку** (порядок = разрешённые ссылки вниз, циклов нет по построению) |
| 9 | Автогруппа — парный `<tag>-auto`; режим `least_test` \| `round_robin` (`pool`, `pool_tolerance`, `sticky_hash[]`); поля `url/interval/tolerance/idle_timeout/interrupt_exist_connections`. **`<tag>-auto` — исключительно опция внутри своего направления** (вариант А): в состав другого направления и в цели правил не попадает |
| 10 | Слоёный пирог `шаблон → патчи пресетов → патч пользователя` — **обе платформы**. Пресет может: фильтр, вкл/выкл, переименовать, **создать** направление. Механизм `Ref`/`Updates` лаунчера переносится в LxBox |
| 11 | Направление, созданное пресетом (`russian` → `ru VPN 🇷🇺`), встаёт **в конец** списка; **правится только мутацией (патчем пользователя), не удаляется** |
| 12 | `proxy-out`, `auto-proxy-out`, ручные `vpn ①`/`vpn ②` — **не мигрируем, не переименовываем**, остаются в шаблоне как возможные имена |
| 13 | Локальные группы подписок (`AL:select`, `AL:auto`) — служебные, не направления. Отличить направление от группы подписки можно только по **state**, не по конфигу → UI строится от state |
| 14 | Вкладка Outbounds → **только список направлений + Add**. Общий JSON-редактор `ParserConfig` убираем (proxies правятся на Sources, `parser.reload` в defaults). JSON остаётся внутри окна направления |
| 15 | Редактор — текущий `OutboundEditWindow` (полноценное окно, не попап), **дорабатываем**: имя, режим автогруппы с полями пула, превью «что попадёт» |
| 16 | Перенос между платформами — на импорте/экспорте создаём направления под новыми именами; heal старых тегов не нужен. Бэкап → v1.1: ссылки на направления переносимы |
| 17 | Снести мою отдельную модель: `core/state/channel_types.go`, `channel_seed.go`, секцию `channels[]`, `ui/.../channels_section.go`. Переиспользовать: материализацию `core/build/channels.go` с частностями LxBox (пустая группа → `[block,direct]` default=block; auto подписки не вкладывается в auto направления; предупреждение только когда виноват фильтр; битый regex = пустой фильтр), `group_templates`, тесты |
| 18 | Контракт: схема направления в `contract/schema/`, фикстуры материализации `corpus/direction/` — гоняют обе стороны |
