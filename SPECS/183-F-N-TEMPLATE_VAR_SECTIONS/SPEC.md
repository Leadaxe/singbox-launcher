# SPEC 183 — Разделы объявлений переменных шаблона: `sections[]` общим контейнером

Статус: **N** (21.11.2026, постановка; не реализовано). Тип: Feature. Контракт: следующая версия после **1.1.173** (на день постановки — 1.1.174; номер взять по `contract/VERSION` в день реализации), решение D-151; норма — `contract/docs/TEMPLATE_LANG.md` §1, §2 (новый подраздел), §7, §8.1, §9 (разрыв C9); корпус `contract/corpus/template/grammar/`; LxBox — параграф `TASKS_LXBOX.md` §176.

## Проблема

На вкладке Settings Конфигуратора у групп настроек нет заголовков. Шаблон лаунчера объявляет переменные плоским списком `vars[]`, группы разделяет запись `{"separator": true}` — линия без подписи, которой валидатор запрещает `title` и любые другие поля. Группа «Sniff guard» держится на префиксе в подписи каждой строки («Sniff guard: TLS», «Sniff guard: QUIC», …), остальные группы не названы вовсе.

У LxBox та же задача решена контейнером `sections[]`: раздел несёт `id`, `name`, `description` и свой список `vars[]`. Контракт сегодня называет контейнер «расширением каждой стороны» (TEMPLATE_LANG §1, разрыв C9), поэтому две стороны описывают одно и то же двумя формами.

## Решение (решения владельца 21.11.2026)

Контейнер объявлений становится общим, в форме LxBox. В контракт входит **форма** контейнера; **состав и порядок** разделов остаются своими у каждой стороны — наборы переменных у сторон разные.

### 1. Норма контракта

1. **Контейнер.** Объявления переменных шаблона лежат в корневом `sections[]`. Раздел — объект:

   | Поле | Обязательность | Смысл |
   |---|---|---|
   | `id` | обязательно | стабильный машинный идентификатор, kebab-case, уникален в шаблоне |
   | `name` | обязательно | заголовок раздела в интерфейсе |
   | `description` | опционально | пояснение под заголовком |
   | `chapter` | опционально, по умолчанию `core` | экран-владелец раздела; сторона, у которой экран один, поле не использует |
   | `vars` | обязательно | список объявлений переменных (грамматика §2 без изменений) |

   Неизвестное поле раздела читатель пропускает — то же правило терпимости, что у объявления переменной (C9).
2. **Порядок объявлений** — разделы по порядку, внутри раздела переменные по порядку. Однопроходное разрешение умолчаний сверху вниз идёт по этому порядку. Имена переменных уникальны по всему шаблону, а не внутри раздела.
3. **Плоский `vars[]` в корне** — форма чтения: фрагменты корпуса (`<case>.template.json`) и шаблоны лаунчера, выпущенные до этой версии. Равен одному разделу без заголовка. Корпус остаётся в плоской форме.
4. **Обе формы в одном шаблоне** (`sections` и корневой `vars` вместе) — ошибка загрузки.
5. **Общие идентификаторы.** Раздел с тем же смыслом на обеих сторонах носит один `id`: `general`, `network`, `tun`, `dns`, `auto-proxy`, `dpi-bypass`, `sniff-guard`, `quic`. Разделы одной стороны (`vpn-mode`, `wireguard`, `internal` у LxBox; `proxy-in`, `clash-api` у лаунчера) носят свои. Состав раздела с общим `id` не нормируется.
6. **Запись `{"separator": true}`** — расширение лаунчера, действует только в плоской форме. Внутри `sections[].vars[]` — ошибка загрузки: границу группы задаёт сам раздел.

### 2. Лаунчер

1. **Загрузчик** читает обе формы. Разделы разворачиваются в прежний плоский `TemplateData.Vars`; каждая переменная знает `id` своего раздела, список разделов (`id`, `name`, `description`, `chapter`) лежит рядом. Плоская форма читается как раньше, вместе с разделителями. Читатель корневого `vars` в `core/config/varsubst.go` переводится на тот же разбор — второго места, знающего форму контейнера, не остаётся.
2. **Settings.** Перед первой видимой строкой раздела — линия (как сейчас у разделителя), под ней заголовок `name` и, если задано, `description` приглушённым текстом с переносом строк. Раздел, в котором для текущей цели и платформы не осталось ни одной видимой строки, не рисуется целиком. Тексты разделов приходят из шаблона и не переводятся — как подписи и подсказки переменных. Шаблон в плоской форме рисуется как раньше.
3. **Шаблон `bin/wizard_template.json`** переложен в `sections[]`, разделителей в нём нет. Предлагаемая раскладка (порядок на экране прежний; итог — после показа владельцу):

   | `id` | `name` | Переменные |
   |---|---|---|
   | `tun` | TUN | `tun` … `tun_stack` (13, как сейчас) |
   | `proxy-in` | Local proxy | `enable_proxy_in` … `proxy_in_password` (7) |
   | `network` | Network | `resolve_strategy`, `auto_detect_interface`, `bind_interface`, `mtu_align`, `route_final` (скрытая) |
   | `dpi-bypass` | TLS Fragmentation | `tls_fragment`, `tls_record_fragment`, `tls_fragment_fallback_delay`, `tls_mixed_case_sni` |
   | `sniff-guard` | Sniff guard | `sniff_guard_tls`, `sniff_guard_quic`, `sniff_guard_sni_mismatch`, `sniff_guard_persist` |
   | `quic` | QUIC | `masque_idle_timeout` |
   | `auto-proxy` | Auto Proxy | `urltest_url`, `urltest_interval`, `urltest_tolerance` |
   | `general` | General | `log_level`, `cert_store` |
   | `clash-api` | Clash API | `clash_api`, `clash_secret` |
   | `dns` | DNS | `dns_strategy` … `dns_store_cache` (7) |

   Тексты `description` — из шаблона LxBox там, где раздел общий и текст верен для десктопа; иначе свои.
4. **Подписи строк Sniff guard** теряют префикс и совпадают с LxBox: «TLS method», «QUIC method», «Only nodes with a masked SNI», «Remember relays across restarts». Раздел в `docs/TROUBLESHOOTING.md` / `.ru.md` «Узел через `detour` не работает…» переписывается под новые названия (раздел Sniff guard → TLS method).

### 3. Совместимость

- Шаблон в папке данных может быть старым (плоским) — он читается без ограничения по сроку.
- Старый лаунчер новый шаблон не получает: каждый релиз качает шаблон по закреплённому коммиту (`RequiredTemplateRef`).
- Состояние, бэкап и сборка конфига не меняются: значения переменных хранятся по именам, набор имён, типы и умолчания прежние. Реестр `registry/vars.json` не меняется.

## Не входит

Сворачивание разделов, экраны-`chapter` на десктопе, перевод названий разделов, сведение состава разделов между сторонами, перенос DNS-переменных на вкладку DNS, переименование `id` у LxBox, заголовки внутри форм пресетов и шаблонных DNS-серверов.

## Критерии приёмки

1. Settings показывает заголовки разделов с пояснениями; строки Sniff guard стоят под своим заголовком без префикса.
2. Раздел без видимых строк (другая платформа, удалённая цель) не оставляет ни линии, ни заголовка.
3. Конфиг, собранный из переложенного шаблона, совпадает с конфигом из прежнего при тех же значениях: существующие эталонные тесты шаблона зелёные без правки эталонов.
4. Плоский шаблон прошлого релиза загружается и рисуется как раньше.
5. Шаблон с `sections` и корневым `vars` одновременно, а также с `{"separator": true}` внутри раздела — отказ загрузки с понятным текстом.
6. Кейсы корпуса `template/grammar/sections_*` проходят у лаунчера; LxBox подтверждает их у себя.
