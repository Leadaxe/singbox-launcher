## Отступления от первой редакции SPEC (SPEC приведена к факту)

1. Тег `.json`-набора несёт расширение — иначе расширение пришлось бы тащить
   отдельным параметром через все функции, принимающие один тег.
2. Режим local — у правила целиком, а не по ссылке: карта закэшированных
   путей правила не различает ссылки, а правило и так одна единица.
3. Проверка содержимого строгая только для копии `.json`; копия `.srs`
   принимает и JSON, как раньше.
4. Пропавший исходник для цикла — обычная неудача (лог, пауза час), отдельной
   ветки нет.

## Не проверено

- Живое ядро: `format: source` в конфиге и подхват заменённой копии — sing-box
  агент не запускает.
- Windows: нативный диалог и путь с буквой диска на настоящей машине (логика
  путей покрыта тестом как строковая).
- Deploy `.json`-набора на удалённую машину: демон `lxd` имена с любым
  расширением принимает (проверено чтением `lxd/resources.go` форка), вживую
  не гонялось.

## Вне задачи (замечено)

- «Custom JSON» не может объявить собственный `rule_set` с `path` — путь к
  файлу на удалённой машине остаётся неподдержанным.
