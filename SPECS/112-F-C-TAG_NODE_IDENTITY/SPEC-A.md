# SPEC 112-A — ссылки на узлы как объекты (source_id + tag), резолв в тег при сборке

Продолжение SPEC 112 (реализован, не закоммичен). Решение пользователя:
внешняя ссылка на узел в состоянии — НЕ финальный конфиговый тег, а объект

    { "source_id": "<ULID источника>", "tag": "<identity-тег узла>" }

Финальный тег из него ВЫЧИСЛЯЕТСЯ при каждой сборке (семантика getConfigTag):
хранимый финальный тег — это кэш, который протухает при смене tag_prefix/mask,
переименовании источника или node_tag; вычисление не протухает.

## Модель

NodeRef (концептуально): source_id + tag.
- source_id — ULID источника (ProxySource.ID).
- tag — identity-тег узла ВНУТРИ источника (ParsedNode.IdentityTag, SPEC 112).

Резолв при сборке (в generator, где известны все финальные теги):
1. source_id найден:
   - источник типа server/chain (даёт один узел) → финальный тег этого узла;
     поле tag при расхождении НЕ рвёт ссылку (id главнее — лечит переименование
     node_tag), но расхождение логируется Debug и tag обновляется в ссылке
     в памяти;
   - источник типа subscription → узел с IdentityTag == tag → его финальный тег.
2. source_id пуст (legacy/переходные стейты) → глобальный поиск по финальному
   тегу, как в текущем resolveNodeTagDetours.
3. Не разрешилось → fail-closed, warning — дословно текущая семантика.

## Дополнения (от пользователя, нормативно)

### Двухпроходность — инвариант

Сборка строго в два прохода:
1. **Проход 1**: все узлы всех источников получают финальный configTag
   (prefix/mask/uniquify). Никакая ссылка на этом проходе не резолвится.
2. **Проход 2**: все ссылки материализуются (NodeRef → configTag) — когда
   полная карта «источник+identity-тег → финальный тег» уже построена.

resolveNodeTagDetours уже живёт после загрузки всех источников — оформить
это как явный инвариант: построить карту резолва одним местом и запретить
(комментарием на карте + структурой кода) резолв ссылок из тела прохода 1.
Любой будущий вид ссылок обязан ходить через эту же карту (родственно
build-graph-sanitizer: одно место для рёбер).

### Понятные ошибки

Тексты ошибок резолва обязаны называть обе стороны — где искали и что:
- цель в подписке не нашлась:
  «Detour: в подписке "AL: Liberty" не нашлось узла "🇳🇱 Amsterdam-1" —
  источник "Proton NL" исключён из конфига (fail-closed)»
- источник-цель удалён:
  «Detour: источник ссылки (id 01KX…) не найден — источник "Proton NL"
  исключён из конфига (fail-closed)»
Идентифицировать источники в тексте по подписи (label), при её отсутствии —
по тегу/URL. Хэши и ULID в текст не выносить, кроме случая, когда другого
имени нет. Тот же стандарт — для сообщения миграции и tag-only fallback.

### Смена идентичности узла = сброс ссылок с предупреждением (от пользователя)

ОТМЕНЯЕТ послабление из раздела «Модель» п.1 («id главнее, tag при
расхождении не рвёт ссылку»). Правильно так:

- Резолв при сборке — СТРОГИЙ: ссылка жива только при совпадении обеих
  частей (source_id найден И узел с таким identity-тегом в нём есть).
  Расхождение = не разрешилось = fail-closed с понятной ошибкой
  (стандарт текстов выше).
- Честность обеспечивает UI в момент операции: любая правка, меняющая
  идентичность узла — переименование node_tag ручного сервера,
  перенос узла/сервера в другой источник-папку — находит ВСЕ ссылки
  на этот узел (detour_node refs), СБРАСЫВАЕТ их (в «нет detour») и
  показывает окно-предупреждение со списком затронутых источников:
  «Ссылки на узел "X" сброшены: Proton NL, …». Отмена в окне не нужна —
  оно информирующее (сброс уже применён вместе с сохранением формы).
- Окно строить на существующих диалоговых компонентах; помнить
  fyne-ловушку: длинные Label без Wrapping задают min-width окна —
  списку имён обязателен Wrapping или усечение.
- Тест: переименование node_tag при существующей ссылке → ссылка
  сброшена в состоянии; сборка проходит без fail-closed предупреждений
  (узел-источник просто без detour). Формулировки окна тестами
  не фиксировать.
