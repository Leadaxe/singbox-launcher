# SPEC 112-B — parse-дедуп по кредам сервера + видимость fail-closed в UI

Два решения пользователя (26.08.2026), реализуются одним заходом.

## Часть A — дедуп возвращается parse-слоем (регресс v1.5.2)

### Факты
- SPEC 112 снёс контент-дедуп вместе с контент-хешем. Регресс: подписка
  https://sub.darklineapp.com/dR1r-CnfbP8hf4uD — 39 записей, из них 32
  байт-одинаковые ss:// (один пароль, сервер DARK-BOT:443), различие только
  в #fragment («Хорватия», «Финляндия», «LTE 1..7»). v1.5.1 схлопывал в 1,
  v1.5.2 показывает 32. Проверено на реальном стейте
  (~/Downloads/Telegram Desktop/state (3).json, preview_nodes, НЕ трогать
  этот файл — только как справка).

### Решение (нормативно, слово пользователя)
Дедуп — НЕ идентичность. Ключ = креды сервера:

    scheme | server | port | credential

то же семейство, что xrayServerKey (xray_json_array.go:340 — cred из UUID,
иначе первый из password/uuid/private_key/auth_str) и что LxBox
nodeIdentityKey (contract/docs/IDENTITY.md §4). Живёт ОДИН разбор источника,
в стейт не пишется, на отметки/ссылки/идентичность не влияет.

ЗАФИКСИРОВАННОЕ СЛЕДСТВИЕ (решение пользователя, запиновать тестом): ключ
жёстче старого хеша — один сервер + один пароль с РАЗНЫМИ SNI/транспортом
теперь схлопывается в один узел (v1.5.1 держал оба; LxBox всегда схлопывал —
семантики двух приложений сходятся).

### Реализация
1. Обобщить ключ: пакетная функция serverConnKey(node) в subscription
   (переиспользовать логику xrayServerKey; сам xrayServerKey перевести на
   неё, поведение xray-ownership не менять — тесты это докажут).
2. Per-source дедуп в LoadNodesFromSource: проверка ДО простановки тегов
   (SPEC 094 D3 — иначе дубль получает «X-2» и уезжает под чужим именем).
   Точки: четыре applyURINodeTags (source_loader.go:682,714,737,784) +
   цикл vpn:// (~528) + цикл sing-box-импорта (~578). Остаётся ПЕРВАЯ
   запись; Debug-лог на каждый пропуск + один INFO-итог «N duplicate
   entries collapsed» на источник (если N>0).
3. Пустой ключ (нет server или cred) — НЕ схлопывать.
4. Превью обязано совпадать с боевым разбором (память
   lazy-cache-vs-lost-state): найти путь подсчёта узлов из preview_nodes
   (ui/configurator/business/source_node_counts.go и рядом) и применить тот
   же дедуп — на darkline-источнике счётчик должен показать 8, не 39.
5. Тесты: 32 копии с разными подписями → 1 узел (первая подпись побеждает);
   один сервер+cred, разные SNI → 1 (пин решения); разные cred → 2;
   пустой ключ не схлопывается; поднять из git пригодные кейсы
   `git show 6ebab9e~1:core/config/subscription/dedup_test.go` и
   адаптировать; xray-ownership не изменился.
6. Контракт: IDENTITY.md §1.2 (абзац «контент-дедуп упразднён» переписать:
   дедуп есть, parse-слой, ключ по кредам) и §4 (различие с LxBox по дедупу
   СХЛОПНУЛОСЬ — отметить сближение и что per-app override корпуса может
   уйти при ревью); docs/release_notes/upcoming.md — пункт про фикс регресса.

## Часть B — fail-closed виден в UI (варианты 1+2, выбор пользователя)

Сейчас исключение источника (detour-хоп не найден) видно только в логе;
в UI источник выглядит здоровым («галка + N nodes») — ровно парадокс
Proton NL. Делаем два экрана:

1. **Строка источника в Wizard → Sources**: постоянная пометка у
   исключённого источника — существующий глиф ⚠ + текст причины по
   стандарту SPEC 112-A («в подписке "X" не найден узел "Y"» /
   «источник ссылки удалён»). Wrapping обязателен (fyne-ловушка: Label без
   Wrapping задаёт min-width окна). Пометка живёт, пока причина не ушла
   (следующая сборка без исключения её снимает).
2. **Тост после сборки на вкладке Local** — тем же механизмом, что
   «Subscriptions partially refreshed: 9/11» (найти его канал и
   переиспользовать, ничего нового не изобретать): «Источник "Proton NL"
   исключён из конфига: хоп не найден. Подробности в Wizard → Sources.»
   Несколько источников — перечислить через запятую.

### Реализация
- Генератор (resolveNodeDetours / migrate, core/config/outbound_generator.go)
  при fail-closed drop дополнительно ЗАПИСЫВАЕТ исключение
  {source_id, source_label, reason} в результат сборки; протащить до
  AppController (in-memory реестр последней сборки, НЕ в state.json);
  чистится при каждой сборке.
- Wizard Sources рендерит пометку по реестру (匹id источника).
- Тост шлётся после rebuild, если реестр непуст.
- l10n: новые строки в bin/locale/ru.json (и другие каталоги, если есть).
- Тесты: сборка с висячей ссылкой → реестр содержит запись с верным
  source_id и человекочитаемой причиной; чистая сборка очищает реестр.
  Формулировки строк тестами НЕ фиксировать (память no-ui-format-tests).
