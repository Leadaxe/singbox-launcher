# SPEC 143 — Единый канонический обходчик шаблона: подстановка, `options`, `@runtime.*` в значениях, коды в отчёт сборки

Статус: **N** (решения владельца приняты 2026-09-25, реализация не начата).
Тип: Feature. Контракт: бамп `contract/VERSION` → **1.1.68**, параграф **§64** в `contract/TASKS_LXBOX.md`.

Документ показывается LxBox: раздел **§7** описывает, что обязана повторить mobile-сторона,
чтобы один шаблон давал одинаковый конфиг на обеих платформах.

---

## 1. Проблема

В Go живут два обходчика подстановки шаблона:

| Обходчик | Где используется | Политика unresolved |
|---|---|---|
| Старый `SubstituteVarsInJSON` (lenient) | главный конфиг (`ApplyTemplateWithVarsFor`), `on_change.set` (`EvalIfScalar`) | `""` + строка в лог |
| Старый `SubstituteVarsInJSONStrict` | тела пресетов (`substitutePresetBody`), тела шаблонных DNS-серверов (`substituteTemplateDNSServer`) | ошибка → фрагмент выпадает целиком, запись только в лог |
| Канон `SubstituteVarsInJSONCanon` (`substitute_canon.go`, D-054) | **только тесты корпуса** | Dropped-каскад §5.1 TEMPLATE_LANG, коды предупреждений |

Разведка **[RECON.md](RECON.md)** (2026-09-25) сравнила все три на `bin/wizard_template.json`
(36 прогонов главного конфига, 954 вызова пресетов, 117 DNS-серверов) и на 25 краевых случаях:

- на живом шаблоне значения **побайтно совпадают**; расходятся только диагностика и краевые случаи;
- два расхождения по значению **не покрыты корпусом** и стражем `knownWalkerDivergences`:
  одноэлементный массив `["@text"]` (RECON строка 17) и литеральный массив в ветке условного элемента (строка 19);
- канон уже умеет отдавать коды `template_var_undeclared`, `template_unknown_directive`,
  `template_int_clamped`, `template_int_invalid`, тексты на двух языках в `contract/registry/warnings.json` есть,
  но в сборке они никуда не попадают: пользователь узнаёт о мусоре в MTU только из отказа ядра;
- каст в число держится на **зашитом списке имён** (`isIntCastVar` + вторая копия `intCastVarNames` в
  `core/config/varsubst.go`), потому что ни одна из трёх живых переменных не объявлена `int`,
  а `urltest_tolerance` с объектными `options` резолвер насильно превращает в `enum` (разрыв N5);
- ловушка пресетов: `VarValuesFor` выкидывает глобали с пустым значением, обходчику пресета их не объявляют,
  и при переводе на канон литерал `"@resolve_strategy"` уедет в конфиг.

## 2. Решения владельца (2026-09-25)

| # | Решение |
|---|---|
| R1 | **Объём: полный сразу.** Главный конфиг, `on_change.set`, тела пресетов и шаблонных DNS-серверов переходят на канон одной задачей. Старые обходчики, Strict-режим, `UnresolvedVarError` и `dropUnsetServerPlaceholders` удаляются. |
| R2 | **Массив в ветке условного элемента вливается на один уровень (сплайс).** `{"#if": {…, "value": ["a","b"]}}` в позиции элемента даёт `…, "a", "b", …`. Вложение выражается двойными скобками: `"value": [["a","b"]]` даёт один элемент `["a","b"]`. Правило одинаково для литерала и для ссылки на `text_list`. Норматив §4.4 правится под это. |
| R3 | **Одноэлементный коллапс `["@text"]` → скаляр хороним.** Скобки автора сохраняются: `"address": ["@tun_address"]` даёт `["172.16.0.1/30"]`. Ссылка всегда в кавычках, потому что шаблон это JSON; что получится на месте ссылки, решает только объявленный `type`. |
| R4 | **`type` и `options` ортогональны.** `type` говорит, что уедет в JSON; `options` даёт закрытый список допустимых значений для любого типа; новый флаг `options_open: true` разрешает своё значение помимо списка. `enum` остаётся синонимом `text` + закрытые `options`. Насильное `type→enum` при объектных `options` снимается (N5). Разрешено и для `text_list` (множественный выбор). |
| R5 | **Коды шаблона в «Итог» сборки.** Новый вид записи `template_degraded`, идёт первым в порядке `finalReportLines`. Save при `template_int_invalid` **не блокируется**: ядро отвергнет конфиг само, блокировка вне задачи. |
| R6 | **`@runtime.*` разрешён в позиции значения** в любой секции шаблона (`config`, `params`, тела пресетов) как desktop-расширение §7.2. |

## 3. Требования

### 3.1 Один обходчик

- **Т1.** Все вызовы подстановки в сборке идут через `SubstituteVarsInJSONCanon` (или его вариант с возвратом предупреждений). Функции `SubstituteVarsInJSON`, `SubstituteVarsInJSONStrict`, тип `UnresolvedVarError`, `dropUnsetServerPlaceholders` удаляются. `EvalIfScalar` для `on_change.set` переводится на канонический walker.
- **Т2.** Пресеты: обходчику объявляются **все** переменные шаблона (`td.Vars`) плюс переменные пресета, а не только имена из `varsMap`. Пустая глобаль тогда даёт Dropped ключа (§5.1), а не литерал `"@name"` и не выпадение фрагмента.
- **Т3.** Гейты валидности фрагмента после Dropped-каскада (§5.1 TEMPLATE_LANG): правило маршрутизации без `outbound` и без `action` выпадает; `dns_rule` без `server` и без `action` выпадает; `rule_set` без `url`/`path` выпадает; DNS-сервер без адреса выпадает. Каждое выпадение даёт запись `ExpandWarning` **и** запись в отчёт сборки (сейчас только лог). Список гейтов уточняется по SPEC 106 §5.1 при реализации, но не короче этого.
- **Т4.** Страж `walker_parity_test.go` перестаёт сравнивать два обходчика (второго нет). Вместо него корпус `contract/corpus/template` гоняется через **боевой** путь сборки (`ApplyTemplateWithVarsFor`), и список `knownWalkerDivergences` удаляется: расхождений между прод-путём и каноном быть не должно.

### 3.2 Грамматика: сплайс и скобки (R2, R3)

- **Т5.** Условный элемент массива (§4.4): если выбранная ветка после подстановки является массивом, его элементы вливаются в родительский массив (**один** уровень). Не массив встаёт одним элементом. Правило не зависит от того, литерал это или ссылка на `text_list`. Функция `isSpliceable` и проверка типа `text_list` у канона снимаются.
- **Т6.** Голая ссылка на `text_list` в позиции элемента массива (`["@list", …]`) вливается, как сегодня. Голая ссылка на `text_list` в позиции значения ключа даёт массив. Ничего нового, фиксируется в корпусе.
- **Т7.** Одноэлементный массив `["@name"]` не сворачивается: канон уже так делает, из старого обходчика ветка коллапса уходит вместе с ним. Абзац «legacy-форма» в §3 TEMPLATE_LANG заменяется прямым запретом коллапса.

Примеры (нормативные, идут фикстурами корпуса):

```json
"servers": ["1.1.1.1", {"#if": {"and": ["@ipv6"], "value": ["2606:4700::1111", "2606:4700::1001"]}}]
→ ["1.1.1.1", "2606:4700::1111", "2606:4700::1001"]

"servers": ["1.1.1.1", {"#if": {"and": ["@ipv6"], "value": [["2606:4700::1111", "2606:4700::1001"]]}}]
→ ["1.1.1.1", ["2606:4700::1111", "2606:4700::1001"]]

"address": ["@tun_address"]            // tun_address: text = "172.16.0.1/30"
→ ["172.16.0.1/30"]

"address": ["@tun_address", {"#if": {"and": ["@ipv6_enabled"], "value": "@tun_address6"}}]
                                        // tun_address6: text_list = ["fd00::1/126"]
→ ["172.16.0.1/30", "fd00::1/126"]
```

### 3.3 `type`, `options`, `options_open` (R4)

- **Т8.** Объявление переменной принимает `options` (строковая или объектная форма, формы равноправны) при **любом** типе из §2.2, кроме `bool`. Объектная форма **не меняет** `type`. Валидатор загрузки отвергает `options` у `bool`.
- **Т9.** Семантика `options`: закрытое множество допустимых значений. Новый необязательный флаг `options_open: true` разрешает значение вне списка; введённое значение проходит приведение по `type` (для `int` парс и кламп, для `text_list` построчный сплит). Без флага UI не даёт ввести своё, а загрузка состояния с чужим значением ведёт себя как сегодня у `enum` (движок не enforce'ит, забота UI).
- **Т10.** `enum` остаётся допустимым типом и означает `text` + закрытые `options`. Эмитить в новых объявлениях следует `text` с `options`; `enum` читается как синоним.
- **Т11.** `text_list` + `options`: грамматика и валидатор принимают, движок подставляет массив выбранных строк. Рендер множественного выбора в UI Settings **выносится в подзадачу 143.1**; до неё такое объявление рисуется многострочным полем, как `text_list` без `options`.
- **Т12.** UI: наличие `options` рисует выпадающий список независимо от `type`; `options_open` добавляет свободный ввод (комбобокс). Для `int` с `options_open` ввод проверяется как число.
- **Т13.** `bin/wizard_template.json`: `tun_mtu` и `proxy_in_listen_port` получают `type: "int"`; `urltest_tolerance` получает `type: "int"` с прежними объектными `options`; результат в `config.json` не меняется (число, как и сегодня через каст по имени).
- **Т14.** Зашитые списки имён `isIntCastVar` (`core/template/substitute.go`) и `intCastVarNames` (`core/config/varsubst.go`) удаляются. `varsubst.go` берёт тип из объявления шаблона (он уже читает типы для `bool`) и клампит так же, как канон. Имя `mixed_listen_port` исчезает из кода вовсе.

### 3.4 `@runtime.*` в значениях (R6)

- **Т15.** `"@runtime.platform"`, `"@runtime.arch"`, `"@runtime.target"` допустимы в позиции значения (ключ объекта, элемент массива) в `config`, `params[].value`, телах пресетов и DNS-серверов, `on_change.set`. Подставляется строка. Неизвестное поле после `@runtime.` даёт `template_var_undeclared` и остаётся плейсхолдером (§5.2).
- **Т16.** Валидатор загрузки (`ValidateWizardTemplate`) перестаёт отвергать такие ссылки в `config`; в `params` он их уже пропускает. Bare-форма в предикатах по-прежнему запрещена (§7.2).

### 3.5 Коды в отчёт сборки (R5)

- **Т17.** Канон накапливает предупреждения с параметрами: `TemplateWarning{Code, Params}`, дедуп по паре (код, параметры). Параметры по реестру: `template_var_undeclared {name}`, `template_unknown_directive {key}`, `template_int_clamped {name, value}`, `template_int_invalid {name, value}`. Сегодняшний `[]string` кодов без параметров уходит.
- **Т18.** Предупреждения из главного конфига, `on_change.set`, пресетов и DNS-серверов доходят до `build.Result` и оттуда в `BuildReportEntry{Kind: template_degraded, Subject: имя переменной или директивы, Code, Params}`. Подача рядом с `FeedBuildReportFromSanitizer` в обоих местах сборки (`core/rebuild.go`, `ui/configurator/business/create_config.go`).
- **Т19.** `template_degraded` стоит **первым** в порядке `finalReportLines`: причина в шаблоне или настройках объясняет всё ниже. Текст записи берётся из реестра по коду на языке интерфейса; новых ключей `locale.T` не добавлять без необходимости. Выпадение фрагмента пресета по Т3 тоже становится записью этого вида.
- **Т20.** Save не блокируется ни одним кодом шаблона. Поле `go` у четырёх кодов в `warnings.json` переписывается на реальные точки постановки.

### 3.6 Контракт

- **Т21.** `contract/docs/TEMPLATE_LANG.md`: §2.1 (`options`, `options_open`, `bool` без `options`), §2.2 (`enum` как синоним; фраза про fallback-список имён снимается), §3 (коллапс запрещён), §4.4 (сплайс на один уровень, двойные скобки), §7.2 (`@runtime.*` в значениях), §9 (C5 закрыт полностью, N5 закрыт, новая строка про сплайс и `options_open` для Dart).
- **Т22.** `contract/registry/vars.json`: пометки «desktop сегодня text/enum + каст по имени» у `urltest_tolerance`, `tun_mtu`, `proxy_in_listen_port` снимаются.
- **Т23.** Корпус `contract/corpus/template`: новые фикстуры (§5). Ожидаемые значения одинаковы для обеих сторон, кроме `@runtime.*` в значениях: на mobile окружения нет, ссылка считается unresolved и даёт Dropped (§5.2), фикстура помечается как desktop-расширение по правилам README корпуса.
- **Т24.** `contract/VERSION` → 1.1.68, changelog, `TASKS_LXBOX.md` §64 с содержимым §7 этого документа. Решения R2–R6 вносятся в `SPECS/103-F-O-LX_SHARED_CONTRACT/DECISIONS.md` следующими номерами.

## 4. Что меняется для пользователя

- **Главный конфиг на штатном шаблоне:** по значению ничего (36/36 в разведке). В «Итоге» появляются строки, когда в MTU, порт или tolerance введён мусор или значение вне [0, 65535], либо когда шаблон новее приложения (`template_unknown_directive`).
- **Пресеты и DNS:** вместо «фрагмент выпал, строка в логе» будет «выпал ключ» с записью в «Итоге»; невалидный после этого фрагмент выпадает целиком и тоже виден в «Итоге».
- **Пользовательские шаблоны:** `["@text"]` даёт массив, а не строку; литеральный массив в ветке условного элемента продолжает вливаться (как в проде сегодня); `@runtime.*` в значениях начинает подставляться вместо пустой строки.
- **Settings:** визуально без изменений. Список у `urltest_tolerance` остаётся, MTU и порт остаются текстовыми полями (ветка `default` рендера), для `int` желательна числовая проверка ввода, как у `number` в редакторе пресета.

## 6. Критерии приёмки

1. В `core/` нет символов `SubstituteVarsInJSON`, `SubstituteVarsInJSONStrict`, `UnresolvedVarError`, `dropUnsetServerPlaceholders`, `isIntCastVar`, `intCastVarNames`, `isSpliceable`, `knownWalkerDivergences`, строки `mixed_listen_port`.
2. Корпус `contract/corpus/template` целиком проходит через боевой путь сборки, включая новые фикстуры §5.
3. `bin/wizard_template.json` даёт тот же `config.json`, что до задачи, на наборах разведки (RECON §2), при этом переменные объявлены по типу и без зашитых имён.
4. Ввод `abc` в MTU даёт в «Итоге» первой строкой запись `template_degraded` с текстом реестра и именем переменной; Save доступен.
5. Пустая глобаль, на которую ссылается тело пресета, даёт правило без этого ключа, а не отсутствие правила и не литерал `"@name"`.
6. Загрузка шаблона с `"@runtime.platform"` в значении внутри `config` проходит валидатор и подставляет платформу цели.
7. Контракт 1.1.68 опубликован: VERSION, changelog, TEMPLATE_LANG, vars.json, TASKS_LXBOX §64, DECISIONS.

## 7. Для LxBox: что повторить на mobile

Один шаблон обязан давать одинаковый конфиг на обеих сторонах. После этой задачи desktop ведёт себя так:

1. **Сплайс на один уровень** (§4.4). Ветка условного элемента массива, если она массив, вливается в родительский массив. Вложение пишется двойными скобками. Литерал и ссылка на `text_list` не различаются.
2. **Никакого коллапса** `["@name"]` в скаляр. Скобки автора сохраняются, тип значения задаёт только `type`.
3. **`options` при любом типе, кроме `bool`,** не меняет `type`; это закрытый список допустимых значений; `options_open: true` разрешает своё значение с приведением по `type`. `enum` = `text` + закрытые `options`. `text_list` + `options` = множественный выбор.
4. **`@runtime.*` в позиции значения** на desktop подставляет строку. На mobile имена `runtime.platform`, `runtime.arch`, `runtime.target` считаются **объявленными со значением null**, и ключ или элемент выпадает (Dropped, §5.1), а не остаётся плейсхолдером как необъявленное имя. Неизвестное поле после `@runtime.` на обеих сторонах даёт `template_var_undeclared {name}` и плейсхолдер (Т15). В предикатах, как раньше, `false`.
5. **Предупреждения с параметрами:** `template_var_undeclared {name}`, `template_unknown_directive {key}`, `template_int_clamped {name, value}`, `template_int_invalid {name, value}`; дедуп по паре (код, параметры). Они показываются пользователю в итоге сборки, не блокируют сохранение.
6. **Пресеты:** телу пресета видны все переменные шаблона; пустое значение даёт Dropped ключа; после каскада фрагмент без обязательных полей (правило без `outbound`/`action`, DNS-правило без `server`/`action`) выпадает с предупреждением.
7. Каст в число только по объявленному `type`; никаких списков имён.

| 5 предупреждения с параметрами | два кода, один не ставится, `int_*` нет, без дедупа, только в тесте корпуса | отдельная задача в той же спеке LxBox |
| 6 пресеты | глобали видны, пустое → Dropped, гейты rule/dns_rule/rule_set есть | DNS-сервер без адреса проверят; коды на выпадение фрагмента после п.5 |
| 7 корпус | подхватывается по дереву каталогов | новые фикстуры подтянутся без правок теста |

Реализацию на mobile начинают после выхода контракта 1.1.68 с фикстурами. Просьба LxBox учтена в п.4 выше и обязана
дословно попасть в §64 TASKS_LXBOX и §7.2 TEMPLATE_LANG: на mobile `runtime.*` = «объявлено, null» (Dropped), а не
«не объявлено» (плейсхолдер).

## 8. Вне задачи

- Блокировка Save по кодам шаблона.
- UI множественного выбора для `text_list` + `options` (подзадача **143.1**).
- Числовая валидация поля ввода для `int` в Settings (желательно, но не блокирует; можно в 143.1).
- Интерполяция `"prefix @var"` внутри строки (§3, в ядро v1 не входит).
