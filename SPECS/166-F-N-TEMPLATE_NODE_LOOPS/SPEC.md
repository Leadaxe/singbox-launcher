# SPEC 166 — Обход узлов в пресете: `for_each_node`, `for_each_node_do`, `#do`/`#final`, `unique` и `internal` у переменной

Статус: **N**. Тип: Feature. Контракт: бамп `contract/VERSION` → **1.1.119**, норма `contract/docs/TEMPLATE_LANG.md` §6.5–6.7 (переписать), параграф **§116** в `contract/TASKS_LXBOX.md`, корпус `corpus/template/for_each_node/` и `corpus/template/for_each_node_do/`.

Решения владельца приняты 13.10.2026. Первый потребитель — пресет «свежий DNS для доменов узлов» (§4).

---

## 1. Проблема

1. **Потребность.** Нужны правила, которые строятся из полей узлов конфига: например, одно DNS-правило со списком доменов всех узлов. Список обязан собираться сборкой из состояния, а не руками в шаблоне.
2. **Язык шаблона это почти умеет, но криво.** `for_each` (контракт 1.1.86, LxBox §578) повторяет тело пресета по узлам, но:
   - `node_type` обязателен и одиночен — эрзац фильтра, хотя `filter` уже выражает то же (`{"@node.body.type": "vless"}`, `#in`);
   - `as` — свободное имя узла, которое ничего не выбирает (вложенных обходов нет) и не защищено от коллизии с переменными;
   - `filter` без `#` нарушает D-073 («`#` — слово движка»);
   - нет агрегации: «по правилу на узел» для двух десятков доменов — шумный конфиг, а одно правило с массивом язык собрать не может.

## 2. Решение — язык шаблона

### 2.1 Два ключа пресета вместо `for_each`

| Ключ | Тело пресета | Назначение |
|---|---|---|
| `for_each_node` | повторяется для каждого прошедшего узла, с `@node` в scope | как прежний `for_each` |
| `for_each_node_do` | раскрывается **один раз после обхода**, без `@node` | обход ради сбора значений в переменные пресета |

- В одном пресете допустим только один из двух; оба — ошибка загрузки.
- `for_each` — ошибка загрузки (нет легаси-чтения; клиент качает шаблон по пину своей версии `RequiredTemplateRef`, LxBox везёт свой).
- Имя узла фиксировано: `@node`, `@node.skip_presets`, `@node.body.<путь>` — семантика §6.6 нормы без изменений. Имена `node` и `node.*` зарезервированы: переменная пресета или глобальная с таким именем — ошибка загрузки.
- Ключи `node_type` и `as` — ошибка загрузки. Любой ключ внутри `for_each_node*` сверх перечисленных в §2.2–2.4 — ошибка загрузки.
- Обходятся те же узлы, что у `for_each` сегодня: включённые, попавшие в конфиг (не снятые гейтами, деградацией, граф-санитайзером), в порядке конфига. `"for_each_node": {}` и `"for_each_node_do": {"#do": …}` без фильтра — все узлы.

### 2.2 `#filter`

- Значение — `cond` языка `#if` (§4.1–4.2 нормы) целиком, без обёртки `#if`/`#value`. Необязателен; нет ключа — истина.
- Видны: имена узла, переменные пресета, глобальные переменные, `@runtime.*`. Отсутствующее значение — ложь, без предупреждения (как сегодня).
- Допустим в обоих ключах.

### 2.3 `#do` (только `for_each_node_do`, обязателен)

```json
"#do": {
  "@domains": { "#append": "@node.body.server" },
  "@tags":    { "#append": "@node" }
}
```

- Объект «`"@имя"` → операция». Имя обязано быть объявлено в `vars` **этого** пресета; глобальная, чужая или необъявленная — ошибка загрузки. Ключ без `@` — ошибка загрузки.
- Операция — объект ровно с одним глаголом. Единственный глагол этой волны — `#append`, допустим только для `text_list`; другой тип переменной — ошибка загрузки. `#set` для скаляров не вводится (нет потребителя; потребует правила «кто побеждает»).
- Правая часть `#append` — то, что умеет тело: ссылка `"@node…"`/`"@var"` или `{"#tpl": "…"}`. Пустое значение у узла (нет пути, null, `""`) — узел пропускается молча, как Dropped в теле. Объект или массив в правой части — ошибка загрузки.
- Один глагол на переменную в одном `#do` (дубли ключей JSON невалидны и так).
- `#do` в `for_each_node` — ошибка загрузки: там тело видит `@node` напрямую.
- `#append` — чистое добавление **без дедупа**: уникальность — явное решение автора (`#final` §2.4 или `unique` §2.5).

### 2.4 `#final` (только `for_each_node_do`, необязателен)

```json
"#final": { "@domains": { "#unique": true, "#sort": true, "#limit": 200 } }
```

- Объект «`"@имя"` → набор глаголов», применяется один раз после обхода к собранному списку. Имя обязано присутствовать в `#do` этого пресета, иначе ошибка загрузки. `@node` не виден, условий нет.
- Глаголы — закрытый список чистых преобразований `text_list`: `#unique` (bool; дедуп, порядок первого появления), `#sort` (bool; по строке, байтовый порядок), `#limit` (int > 0; первые N). Другой ключ или не тот тип значения — ошибка загрузки.
- Порядок применения фиксирован нормой, **не** порядком ключей JSON: `#unique` → `#sort` → `#limit`.
- `#final` в `for_each_node` — ошибка загрузки.

### 2.5 Объявление переменной: `unique` и `wizard_ui: "internal"`

| Поле | Тип | Семантика |
|---|---|---|
| `unique` | bool, только `text_list` | значение переменной всегда без дубликатов, порядок первого появления: применяется к вводу пользователя (UI убирает дубли при сохранении, хранимое значение с дублями нормализуется при чтении), к `default_value` и к результату `#append`. С `#final.#unique` совместимо (идемпотентно). У другого типа — ошибка загрузки |
| `wizard_ui: "internal"` | новое значение | переменная **только для сборки**: в формах не показывается, значение из состояния и бэкапа **игнорируется** при сборке (берётся `default_value`, затем `#do`), в state не пишется, в LX Backup не экспортируется; при импорте значение снимается с `backup_var_skipped` (новая причина `internal`). Единственный способ записать такую переменную — `#do` |

- Переменная без `internal` (например `domains` первого потребителя) остаётся пользовательской: введённое пользователем — база, `#append` добавляет к ней на время сборки. **Собранное не персистится:** сбор идёт в копию значения на время сборки; в state и бэкап уходит только ввод пользователя (норма BACKUP.md «`vars` у `preset`» без изменений).

### 2.6 Сборка

- `for_each_node_do`: порядок шагов — переменные пресета поверх глобалей → обход с `#filter` → `#do` → `#final` → `unique` объявления → раскрытие тела один раз с итоговыми значениями.
- Пустой итоговый список не подставляется как `[]`: пустой `text_list` в позиции значения ключа снимает ключ (Dropped §5.1, как сегодня). Правило маршрута или DNS, оставшееся без единого условия, снимается целиком с существующим кодом `logical_sub_rule_conditions_lost_dropped` (норма §5, кейс `for_each/logical_sub_rule_conditions_lost_dropped`); распространить его на тело `for_each_node_do`.
- Проба (тестовый конфиг узла) оба обхода не раскрывает — как у `for_each` сегодня.

### 2.7 Что НЕ вводится (решения владельца)

- `#init` — объявление есть в `vars`; второе место для объявления не нужно.
- Выражения внутри ссылок (`@nodes.filter(…).domains`), доступ к произвольным множествам, `#set`, операции «до/после» сверх `#final`. Принцип: язык декларативный, есть «что собрать» и «при каком условии», нет «когда».

## 4. Первый потребитель — пресет «Node hostnames: fresh DNS»

```json
{
  "id": "node-domains-fresh-dns",
  "label": "Node hostnames: fresh DNS",
  "description": "Resolve the hostnames of your nodes through a chosen resolver and never serve a stale answer for them.",
  "default_enabled": true,
  "vars": [
    { "name": "resolver", "type": "dns_server", "default": "direct_dns_resolver", "title": "Resolver",
      "tooltip": "Which DNS server resolves node hostnames. Must not go through the proxy itself." },
    { "name": "domains", "type": "text_list", "unique": true, "title": "Extra domains",
      "tooltip": "Hostnames of every node are collected automatically; add your own here." }
  ],
  "for_each_node_do": {
    "#filter": { "#and": [
      { "@node.body.server": "#notEmpty" },
      { "#not": { "@node.body.server": { "#matches": "^[0-9.]+$" } } },
      { "#not": { "@node.body.server": { "#matches": ":" } } }
    ] },
    "#do": { "@domains": { "#append": "@node.body.server" } }
  },
  "dns_rules": [
    { "domain": "@domains", "server": "@resolver", "disable_optimistic_cache": true }
  ],
  "num": 10
}
```

- Фильтра по типу узла нет: нужны все узлы с доменным сервером; у Tailscale и WireGuard-пиров поля `server` нет — отпадают сами.
- Полный `disable_cache` не по умолчанию: он отключает кэш целиком и даёт DNS-запрос на каждое соединение.
- Место — голова DNS-правил (`num: 10`), чтобы пользовательские правила его не перекрывали; точное значение `num` — по соседям в шаблоне при реализации.
- Tailscale-пресет переводится на `for_each_node` с `#filter: {"#and": [{"@node.body.type": "tailscale"}, {"#not": "@node.skip_presets"}]}`.

## 5. UI

- Форма пресета: `text_list` с `unique` — дубли убираются при сохранении; `wizard_ui: internal` — строки нет.
- Диалог Edit Rule, вкладка JSON (эмитнутые фрагменты): у `for_each_node_do` показывает одно правило с собранным массивом; `PresetServedTags`/`preset_nodes_view` (SPEC 145 §7) для `for_each_node_do` показывают узлы, прошедшие `#filter`, как сегодня для `for_each`.
- `source_skip_presets.go` сопоставляет пресеты узлу по `node_type` — переписать на «пресет обслуживает узел ⇔ узел проходит `#filter`» (общая функция `PresetForEachNodes`).

## 6. Вне scope

- `#set`, обход по группам/источникам, выражения в ссылках.
- Автоматический перевод чужих шаблонов с `for_each` (их нет: шаблон у каждого приложения свой).
- Глобальное поведение `dns.optimistic` и дефолты резолверов шаблона.
