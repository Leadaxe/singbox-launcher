# SPEC 111 — Локализация на естественных ключах

Статус: **новая**. Преемник [SPEC 013 LOCALIZATION](../013-F-C-LOCALIZATION/SPEC.md),
который ввёл текущую схему с искусственными ключами. Переносит в лаунчер
механику, обкатанную в LxBox (§285): **английский текст в коде и есть ключ
перевода**.

## Проблема

Сегодня строка живёт в трёх местах одновременно:

```go
// ui/clash_api_tab_render.go:70
ShowErrorText(win, locale.T("app.tab.servers"), …)
```
```jsonc
// internal/locale/en.json   (вшит в бинарь)
"app.tab.servers": "🖥️ Servers",
// bin/locale/ru.json        (внешний файл)
"app.tab.servers": "🖥️ Серверы",
```

Отсюда три следствия, которые мы платим каждый день:

1. **Правка каталога в каждом коммите.** Из последних 200 коммитов
   **124 (62%)** трогают `internal/locale/en.json`. Добавить кнопку — значит
   придумать ключ, открыть два JSON, вписать в оба, не опечататься.
2. **Код нечитаем без словаря.** По `locale.T("wizard.source.detour_hint")`
   не видно, что покажет экран. Чтобы прочитать диалог, надо держать
   `en.json` открытым во второй вкладке.
3. **Каталог копит мусор.** Ключ, переставший использоваться, ничем не
   помечен. Сейчас в каталоге **130 ключей из 1194** не встречаются в коде
   литерально.

Дублирование при этом бессмысленно: `en.json` — это ровно то, что и так
должно было бы стоять в коде. Мы поддерживаем отдельный файл, чтобы хранить
английский язык в приложении, у которого английский — базовый (CONSTITUTION
8.3).

## Решение

Ключ — сам английский текст. Английского каталога нет: он живёт в коде.

```go
ShowErrorText(win, locale.T("🖥️ Servers"), …)
```
```jsonc
// bin/locale/ru.json — единственный каталог
"🖥️ Servers": { "value": "🖥️ Серверы" }
```

Промах на любом уровне (нет каталога, нет ключа, нет формы) деградирует в
сам ключ — то есть в корректный английский текст. Сломать UI отсутствием
перевода нельзя.

Экстрактора **нет намеренно** — как и в LxBox. Ключ в `ru.json` добавляется
руками; от расхождения кода и каталога защищает не генератор, а CI-чекер.
Генератор пришлось бы запускать перед каждым коммитом и он всё равно не
сказал бы, что перевод неверен по смыслу.

## Что это даёт

| | сейчас | после |
|---|---|---|
| Новая строка | придумать ключ + 2 файла | написать текст в коде |
| Читаемость call-site | нужен словарь | текст виден на месте |
| Английский | отдельный файл, 1194 записи | код |
| Мёртвый ключ | невидим | `orphan` → CI падает |
| Забытый перевод | невидим | `missing` → CI падает |
| Хардкод в обход слоя | невидим | ratchet → CI падает |

## Замеры (факт на develop)

| Метрика | Значение |
|---|---|
| Ключей в каталоге | 1194, `en`/`ru` синхронны (0 расхождений) |
| Call-sites `locale.T` / `locale.Tf` | 1234 литеральных + 7 динамических |
| Уникальных ключей в коде | 1057 |
| Мёртвых ключей в каталоге | 130 |
| `locale.Tf` (с плейсхолдерами) | 156 вызовов / 140 ключей |
| Русского хардкода в `ui/` | **0** |
| User-facing русских строк в `core/` | ~20 |

**Дубли значений.** 51 английское значение повторяется под разными ключами
(`Close` ×13, `Cancel` ×13, `Save` ×11, `Add` ×5). При natural-key они
схлопываются: 1194 ключа → **~1091**. Из этих 51 только **13** переведены
на русский по-разному:

```
Copy    → Копировать / Скопировать      Reset   → Сброс / Сбросить
Start   → Запустить / Старт             Discard → Отбросить / Отменить
Stop    → Остановить / Стоп             Edit    → Изменить / Редакт.
Info    → Инфо / Информация             Used    → Занято / Использовано
Error   → Ошибка / Ошибки               Preview → Превью / Просмотр
Regex   → Регулярное выражение / Регулярные выражения
Restart the core → Перезапуск ядра / Перезапустить ядро
Deploy config    → Отправить конфиг / Отправка конфига
```

Только они требуют разведения через special-формы (§ Коллизии). Остальные 38
переводятся одинаково и схлопываются без потерь.

**Почему момент удачный:** языков ровно два (`RemoteLanguages = ["ru"]`,
восемь машинных переводов сняты ранее), `ui/` целиком уже ходит через слой,
каталоги синхронны. Миграция инвалидирует все внешние `bin/locale/*.json` —
при одном языке цена нулевая. С восемью языками она была бы неподъёмной.

## Требования

### 1. Формат каталога

`bin/locale/<tag>.json` — плоская карта `английский текст → запись`. Три вида
записи:

```jsonc
{
  "_display_name": "Русский",

  // обычная строка
  "Save": { "value": "Сохранить" },

  // множественное число: value — объект со всеми формами резолвера языка
  "%d nodes": {
    "value": {
      "one":   "%d узел",
      "few":   "%d узла",
      "many":  "%d узлов",
      "other": "%d узла"
    }
  },

  // коллизия: один английский текст → разные переводы по контексту
  "Copy": {
    "value": "Копировать",
    "special": { "1": { "value": "Скопировать" } }
  }
}
```

- `_display_name` остаётся как есть — это имя языка для селектора.
- Отдельного `en.json` **нет**. Английский — база, живёт в коде, он же
  fallback. `internal/locale/en.json` удаляется вместе с `//go:embed`.

### 2. API слоя

```go
locale.T("Save")                        // → "Сохранить"
locale.Tf("Connected to %s", host)      // подстановка
locale.TN(1, "Copy")                    // special-форма №1
locale.TfN(1, "%s available", tag)      // special-форма + подстановка
locale.Plural("%d nodes", n)            // множественное число
locale.PluralN(1, "%d nodes", n)        // special-форма + множественное
```

Порядок деградации: активный язык → форма 0 → **сам ключ** (английский
текст) с подставленными аргументами. Паники нет ни при каком промахе.

Сигнатура `T`/`Tf` не меняется — меняется смысл аргумента. Это позволяет
мигрировать call-sites механически.

### 3. Коллизии — special-формы

Когда один английский текст обязан переводиться по-разному, различающийся
call-site получает индекс формы **первым аргументом**:

```go
locale.T("Copy")      // «Копировать» — форма 0, корневой value
locale.TN(1, "Copy")  // «Скопировать» — special["1"].value
```

Не выбираем путь «дописать контекст в ключ» (`"Copy|button"`) — он засоряет
английский текст служебной разметкой, и её пришлось бы вырезать при
fallback. Индекс формы держит ключ чистым.

Чекер следит в обе стороны: индекс N в коде без `special["N"]` — ошибка
`shape`; `special["N"]` без вызова с индексом N — `orphan-special`.

### 4. Множественное число

В лаунчере сейчас плюрализации нет вообще — строки вида `"%d nodes"`
переведены одной формой и в русском звучат криво на «1 узлов». Вводим
резолверы:

- `RuPluralResolver` — CLDR one/few/many/other;
- `EnPluralResolver` — one/other (для fallback и будущих языков).

Число — всегда первый подставляемый аргумент. Набор форм диктует резолвер
языка; чекер требует полный набор.

Плюрализация — **добавление**, а не условие миграции: на первом этапе можно
не переводить ни одной строки в plural и включить механизм позже. Отдельный
подпункт в TASKS.

### 5. Плейсхолдеры

`printf`-стиль, как сейчас: `%s`, `%d` по порядку, `%[1]s` / `%[2]d` с явной
позицией, `%%` — литерал. ICU и `{named}` не вводим: у нас `fmt.Sprintf` под
капотом и 156 существующих вызовов уже в этом стиле.

Набор плейсхолдеров в ключе обязан совпадать с набором в переводе и в
**каждой** plural-форме — иначе `arity`-ошибка (тест `TestPlaceholderCount`
уже делает это для старой схемы, логика переезжает в чекер).

### 6. Чекер `l10n_check` — обязателен

Без него схема разваливается: ничто не заставит добавить перевод. Чекер —
Go-программа в `tools/l10n/`, AST-скан пакетов проекта, сверка с каталогом.
Находки:

| Находка | Что значит | Режим |
|---|---|---|
| `missing` | ключ есть в коде, нет в `ru.json` | warn, `--strict` → fail |
| `orphan` | ключ есть в `ru.json`, нет в коде | warn, `--strict` → fail |
| `orphan-special` | `special["N"]` не вызывается с индексом N | warn, `--strict` → fail |
| `usage-conflict` | один ключ зовут и `T`, и `Plural` | **fail всегда** |
| `shape` | `T` на plural-объекте; `Plural` без полного набора форм; использованный индекс N отсутствует | **fail всегда** |
| `arity` | наборы плейсхолдеров ключа и перевода расходятся | **fail всегда** |

Динамические ключи (`locale.T(someVar)`, 7 штук) валидировать нельзя — они
только считаются, и их число печатается в отчёте. Чтобы записи таких ключей
в каталоге не падали как `orphan`, константы, используемые как ключи
опосредованно (через переменную или функцию), помечаются `// l10n-key` на
строке объявления — сканер считает помеченную константу использованным
ключом. Немаркированная динамика + неиспользуемая запись = честный orphan.

### 7. Ratchet на хардкод — `hardcoded_check`

Ловит `widget.NewLabel("Save")` в обход слоя. Скан display-позиций Fyne;
список конструкторов конечен и известен:

```
widget.NewLabel, NewLabelWithStyle, NewButton, NewButtonWithIcon,
NewCheck, NewFormItem, NewHyperlink, NewRadioGroup, NewSelect,
NewSelectEntry, NewHoverForwardButtonWithIcon,
SetText, SetTitle, SetPlaceHolder, SetToolTip,
dialogs.ShowError, ShowErrorText, ShowInformation, ShowConfirm
```

Спускается в ветки `if`/`switch`/тернарных выражений в display-позиции —
каждая строковая ветка отдельный сайт. Легально: `widget.NewLabel(locale.T("…"))`
(литерал — аргумент `locale.T`, а не виджета).

Baseline (`tools/l10n/hardcoded_baseline.json`) заводится **пустым**: в `ui/`
сейчас 0 русского хардкода, а английский хардкод в display-позициях
вычищается в рамках этой задачи. Пустой baseline = любой новый хардкод
роняет CI.

Точечное исключение — `// l10n-exempt: <причина>` на строке литерала или
строкой выше. Легитимно: wire-теги (`direct-out`), единицы (`ms`, `Mbps`),
эндонимы в селекторе языка, имена протоколов. Нелегитимно: «переведём
потом».

### 8. Что не переводится никогда

Фиксируем явно, чтобы чекер не воевал с легитимным английским:

- логи (`debuglog.*`), ответы Debug API, `/state/full`, `/debug/snapshot`;
- wire-значения и теги outbound'ов, имена типов sing-box, имена полей JSON;
- имена файлов, пути, URL;
- пользовательские данные (метки узлов, имена подписок);
- сквозные сообщения ядра и ОС (diagnostic passthrough);
- единицы `B/KB/MB/GB`, `Mbps`, `ms` и суффиксы длительности `d/h/m/s` —
  остаются латиницей во всех локалях;
- эндонимы языков в селекторе (каждый язык подписан на себе).

### 9. Русский в `core/`

~20 user-facing русских строк в `core/` (валидация цепочек
`chain_generator.go`, бэкап `backup/*.go`, `core_chain_capability.go`,
`direction_twins.go`) всплывают в UI как текст ошибки. Это нарушение
CONSTITUTION 8.2 («язык технических сообщений только английский»), которое
существует и сейчас. В рамках задачи они переводятся на английский в коде и
**не локализуются** — это diagnostic passthrough из §8. Переводить их в
точке отображения нельзя логически: параметризованное сообщение
(`fmt.Sprintf("position %d is empty", 5)`) даёт строку, которая никогда не
совпадёт с ключом `"position %d is empty"`. Честная локализация таких
сообщений требует типизированной ошибки (ключ + аргументы, рендер в UI —
аналог `UiMsg` в LxBox) — это осознанно выносится в отдельную задачу.
Следствие: валидация цепочек, ошибки бэкапа и т.п. будут английскими и для
русской локали. Сегодня они русские для всех — то и другое неидеально, но
английский соответствует конституции.

`internal/platform/glprobe_windows.go` — особый случай: там двуязычный текст
в нативном MessageBox **до** инициализации GUI и слоя локали. Остаётся как
есть, помечается `// l10n-exempt: pre-init native dialog`.

### 10. Совместимость

- `bin/settings.json` (`"lang": "ru"`) — формат не меняется.
- `LoadExternalLocales` / `DownloadAllRemoteLocales` / `GetLocaleURL` —
  сигнатуры не меняются, меняется парсер записи.
- Старые `bin/locale/*.json` со схемой `ключ → строка` после обновления не
  подойдут: значения не найдутся, UI покажет английский. Это **приемлемая
  деградация** (не падение), а свежий `ru.json` приезжает вместе с релизом и
  докачивается кнопкой в Settings. Отдельная миграция старых файлов не
  пишется.
- Обратный skew: стабильные релизы качают локаль с ветки `main`
  (`GetMyBranch`). Когда новый формат попадёт на `main`, **старые**
  установленные лаунчеры кнопкой «Download translations» получат файл,
  который их валидация `map[string]string` отвергнет: кнопка покажет ошибку,
  локальный старый `ru.json` останется нетронутым, UI не пострадает.
  Приемлемо; в release notes упомянуть.
- `_display_name` остаётся простой строкой, не `{"value": …}`. Механизм:
  парсер записи принимает голую строку как эквивалент `{"value": строка}`.
  Побочный бонус — старый формат (`ключ → строка`) разбирается без ошибок
  и деградирует мягко: ключи просто не находятся.

## Критерии приёмки

1. `internal/locale/en.json` удалён; `//go:embed` из `locale.go` убран.
2. `bin/locale/ru.json` — в новом формате, ключи = английские тексты,
   13 коллизий разведены через `special`.
3. Все 1234 литеральных call-site переведены на английский ключ; 7
   динамических разобраны индивидуально.
4. `go run ./tools/l10n/l10n_check --strict` — 0 находок.
5. `go run ./tools/l10n/hardcoded_check --strict` — 0 находок, baseline пуст.
6. Оба чекера — шаг в job `Test` в `.github/workflows/ci.yml`, безусловно
   `--strict`.
7. Запуск с `lang=ru` — интерфейс русский, кроме diagnostic passthrough
   (§8–9: технические ошибки `core/` — английские by design); с `lang=en` —
   полностью английский; ни одного «сырого ключа» на экране.
8. Запуск с намеренно испорченным `ru.json` (битый JSON, отсутствующий файл)
   — приложение стартует и показывает английский, в лог уходит warn.
9. `go build ./...`, `go test ./...`, `go vet ./...` — зелёные.
10. Легаси-джоба Win7 не сломана: она собирает модуль тулчейном
    **go 1.20.14** (`-modfile=go.win7.mod`), а её `go get ./...` обходит
    все пакеты модуля — включая `tools/`. Поэтому чекеры: только stdlib
    (`go/ast`, `go/parser`, `encoding/json`), без go1.21+ синтаксиса
    (`min`/`max`, `slices` и т.п.).

## Оценка

| Этап | Дней |
|---|---|
| 1. Движок `internal/locale` (формат, `TN`, plural, fallback) | 1 |
| 2. Миграция каталога скриптом + 13 коллизий руками | 0.5 |
| 3. Переписывание 1234 call-sites скриптом + вычитка | 1 |
| 4. Чекер `l10n_check` + self-тесты | 1–1.5 |
| 5. Ratchet `hardcoded_check` + self-тесты | 1 |
| 6. Английский в `core/` (~20 строк) | 0.5 |
| **Итого** | **5–6** |

Без этапа 5 — 4–5 дней, но тогда схема протекает: ничто не помешает
написать `widget.NewLabel("Save")` мимо слоя.

## Риски

| Риск | Митигация |
|---|---|
| Огромный механический дифф по всей кодовой базе плохо мержится | Отдельная ветка, влить одним коммитом сразу после закрытия текущих задач по цепочкам (110); не начинать при незакрытом рабочем дереве |
| Длинные ключи в коде: 62 значения >120 символов (макс. 419), 31 многострочное | Такие тексты выносятся в `const` рядом с местом использования — `locale.T(chainHintText)`; чекер видит константу и резолвит её значение |
| 193 значения содержат эмодзи (`🖥️ Servers`) — эмодзи попадает в ключ | Оставляем как есть: ключ = ровно то, что на экране. Альтернатива (вынести эмодзи из строки) — отдельная задача, не смешиваем |
| Скрипт миграции испортит перевод на коллизиях | Скрипт **падает** на любом значении с неодинаковыми переводами; 13 известных случаев разводятся руками до прогона |
| Правка английского текста молча ломает перевод | Это by design: смена текста = смена ключа. Старая запись становится `orphan`, новая — `missing`, `--strict` роняет CI. Переводчик обязан перечитать строку — ровно то поведение, которого мы хотим |
