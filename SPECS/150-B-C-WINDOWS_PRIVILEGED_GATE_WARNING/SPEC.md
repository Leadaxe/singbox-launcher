# SPEC 150 — Windows: проверки прав повышенного старта предупреждают, а не запрещают

Статус: **C** (решение владельца 2026-09-28, реализовано 2026-09-28).
Тип: Bug. Issue [#137](https://github.com/Leadaxe/singbox-launcher/issues/137).
Связь: SPEC 141 §8, §13 п. 1.

## 1. Проблема

Лаунчер с правами администратора стартует classic-ядро только из защищённой
копии `C:\Program Files\sing-box-lxd\sing-box-lxd.exe` и пишет его вывод в
`C:\ProgramData\sing-box-lxd\logs\classic.log` (SPEC 141 §8). Каталог лога
проверялся по инварианту §6.1 от корня тома, включая системную папку
`C:\ProgramData`. Если у группы «Все» (S-1-1-0) есть запись в
`C:\ProgramData`, старт VPN блокировался ошибкой вида
`C:\ProgramData: Все (S-1-1-0) is granted 0xd0040, must not be writable by a
non-administrative account`, и пользователь оставался без запуска.

## 2. Решение (владелец)

Проверки прав не оставляют пользователя без запуска. Отказ — предупреждение
с причиной, риском, командой исправления и кнопкой «Run anyway».

## 3. Поведение

1. **Каталог лога.** Проверяются только `<ProgramData>\sing-box-lxd` и
   `logs\` по правилу нашей папки §6.1. Предки выше (`ProgramData`, корень
   тома) не проверяются — как в ядре. Копия в `Program Files` проверяется
   по §6.1 целиком, как раньше.
2. **Причина нарушения** — типизированная ошибка `platform.ProtectionError`:
   путь звена, английский текст, команда исправления, признак предка.
   В тексте — имена прав (`GENERIC_ALL`, `WRITE_DAC`, `FILE_ADD_FILE`, …)
   вместо hex, как в `lxd/aclcheck.go` ядра; у каталога биты записи
   называются `FILE_ADD_FILE` / `FILE_ADD_SUBDIRECTORY`.
3. **Команда исправления** (консоль администратора):
   - владелец не из списка — `icacls "<путь>" /setowner *S-1-5-32-544`;
   - разрешающая запись чужому SID — `icacls "<путь>" /remove:g *<SID>`,
     у унаследованной записи — `icacls "<путь>" /inheritance:d /remove:g *<SID>`;
   - reparse point, NULL DACL, неразбираемый тип записи — команды нет.
4. **Диалог отказа** (копия: missing, outdated, unsafe; лог: нет `logs\`,
   нарушены права, файл не открылся): причина, фраза о риске, команда,
   кнопки Run as administrator (где команда copy/install), Copy the
   command, Retry, Run anyway; слева Close. Нарушение на предке с командой
   `icacls` — показывается она, без Run as administrator; иначе — команда
   copy/install SPEC 141 §8. Заголовки лога — «Core log folder is missing»
   и «Core log folder is not protected».
5. **Run anyway.** Флаг в памяти `ProcessService` до закрытия лаунчера, в
   файлы не сохраняется. Старт повторяется тем же путём, что Retry.
   - Копия не прошла проверку — ядро `bin\sing-box.exe` (`FileService.SingboxPath`).
   - Каталог лога не прошёл проверку — вывод ядра в лог лаунчера
     (`ChildLogFile`), `CoreLogPath` отдаёт его.
   - Проверки деградируют независимо: копия в порядке, лог нет — копия и
     лог лаунчера.
   - На следующих стартах сессии диалога нет, в лог пишется WARN с причиной.
6. Без UI поведение прежнее: отказ без старта.
7. macOS не меняется: гейт SPEC 137 общий, «Run anyway» на darwin нет.

## 4. Риск

«Run anyway» исполняет с правами администратора файл или пишет в каталог,
которые может подменить любая программа под учётной записью пользователя.
Диалог говорит об этом одной фразой; выбор не переживает перезапуск
лаунчера.
