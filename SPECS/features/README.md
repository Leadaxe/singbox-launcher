# SPECS/features — живые документы логики

Здесь живёт **текущая истина поведения** — обещания пользователю и правила
логики, без кода, без file:line, без статусов «сделано/не сделано».
Настоящее время: фича описывает, как система себя ведёт, а не как к этому
пришли.

Отличие от задач (`SPECS/NNN-T-S-NAME/`): задача смертна — описывает дельту,
реализацию и закрывается; фича бессмертна — правится при каждом изменении
логики и никогда не «завершается».

## Правило синхронизации (жёсткое)

**Задача, меняющая логику, обязана в том же коммите поправить фичу.**
Иначе фичи начинают врать — ровно как врали note-поля контракта, писанные
в будущем времени и не переписанные после реализации.

## Состав

| Файл | Блок | Обещания |
|---|---|---|
| `sources.md` | Источники | узлы (Server/Chain/Auto), папки, подписки, свобода и несвобода, происхождение, copy/move, merge-заливка, Regen, теги и идентичность |
| `directions.md` | Направления | пулы и фильтры, что попадает в пул, свёртка папки (replace), NodeLink-резолв, fail-closed |
| `subscriptions.md` | Подписки | классификация тела, три вида записи состава (server/comment/unsupported), признак комментария по форматам, метаданные подписки, диалекты |
| `state.md` | Хранение | схема состояния, «память = диск», материализация, миграции, бэкап и граница контракта с LxBox |

Решения принимаются в обсуждении (или капитаном при мандате) и фиксируются
здесь; история решений — в git log и задачах.
