## 1. Проблема

В обоих приложениях язык шаблонов имеет **две разные грамматики условий**:

| Где | Форма | Что умеет |
|---|---|---|
| внутри дерева конфига | `"#if": {"and"/"or": [predicates], "value": …, "else": …}` | полная таблица предикатов P1–P6, but **один уровень** and/or (D-018) |
| на носителях (переменные, фрагменты пресетов, `params`) | Go: `"if": ["@a"]`, `"if_or": [...]`; Dart: `"enabled": "@var"` | только bool-переменные (Go ещё — JSON-предикат строкой, SPEC 097) |

Последствия:

- непомеченная управляющая конструкция (`if`) лежит **внутри тела правила
  вперемешку с полями sing-box** — нарушение конвенции пометок (`@` = значение,
  `#` = директива); движок вырезает её перед эмиссией отдельной строкой;
- в Dart ключ `enabled` **коллидирует с настоящим полем sing-box** (`tls.enabled`,
  `cache_file.enabled`) и с UI-дефолтом DNS-сервера шаблона — три смысла у
  одного слова (см. §11.2);
- гейты носителей не умеют ни платформу, ни равенство, ни отрицание, ни
  вложенность — приходится либо дублировать условия, либо обходить;
- на каждое изменение переменной UI обеих сторон перерисовывает **всю** вкладку
  Settings (Go: `box.RemoveAll()` + пересборка; Dart: `setState` экрана).

## 2. Решения владельца (не пересматривать)

1. **`#enable`** — плоский помеченный ключ среди полей носителя, заменяет
   `if`/`if_or`/`enabled:`. Форма плоская (полная `#if`-обёртка отвергнута как
   тяжеловесная — «выворачивает объект ради одного условия»).
2. **Одна грамматика условий на весь язык.** Значение `#enable` — то же условие,
   что и тело `#if` без `value`/`else`. Никаких параллельных грамматик.
3. **Вложенность and/or — разрешена на любую глубину** (снимается запрет D-018):
   `"or": ["@tun", {"and": [{"@runtime.platform": "windows"}, "@enable_proxy_in"]}]`.
4. **Сахар**: `"#enable": ["@a", "@b"]` ≡ `{"and": ["@a", "@b"]}`; строка ≡ список
   из одного.
5. **Реактивный пересчёт** в UI: каждый вычисляемый узел знает множество
   переменных, от которых зависит, и пересчитывается **только** при их
   изменении — не «все `#enable` на любой чих». Зависимости извлекаются
   **статически** при загрузке шаблона (язык декларативен и полностью
   анализируем; динамический трекинг не нужен).
6. Генерация конфига реактивности не использует: один проход сверху вниз,
   без состояний и присвоений, порядок узлов безразличен.
7. Легаси-формы `if`, `if_or`, `enabled: "@var"` читаются **бессрочно** как алиасы.
8. Контракт (общий для обоих приложений) фиксирует **семантику условий и
   извлечение зависимостей** (проверяется корпусом). Способ доставки
   уведомлений виджетам — деталь реализации каждого UI.

## 3. Цели

- G1. Единый вычислитель условий (далее **движок условий**) в Go и Dart с
  рекурсивными `and`/`or`, полной таблицей предикатов P1–P6, `#not`, сахаром.
- G2. `#enable` на всех носителях: объекты дерева конфига, фрагменты пресета
  (`rule_set[]`, `rules[]`, `dns_servers[]`, `dns_rule`, `dns_rules[]`,
  `outbounds[]`), переменные пресета, объявления переменных шаблона
  (Settings), `params[]`.
- G3. Статическая компиляция условий → множество зависимостей; инвертированный
  индекс `переменная → узлы`; точечный пересчёт и точечное обновление UI.
- G4. Легаси-алиасы читаются; шаблоны обоих приложений переведены на `#enable`.
- G5. Корпус: рекурсия, `#enable` по носителям, зависимости — 100 % на обеих
  сторонах; все существующие 72 фикстуры остаются зелёными.
- G6. Документация и release notes (EN+RU) обновлены.

## 4. Не-цели

- Менять семантику `#if` (`value`/`else`, merge, array-element) — не трогать.
- Вводить суффиксные `#enable1`, `#enable x` — **нет**: один `#enable` на узел,
  композиция через `and`/`or`. (Суффиксы у `#if` остаются, D-045.)
- Хранить индекс зависимостей в state/бэкапе — нет, он производный.
- Оптимизировать CPU: на десятках узлов выигрыш нулевой; цель реактивности —
  точечное обновление UI (без перерисовки вкладки, потери фокуса, мерцания).
- Переносить на движок `if`-гейты вне шаблона (Go `PresetOutbound`
  `mode/filters` — не условия).

## 5. Грамматика (нормативно)

### 5.1 Условие (`cond`)

```
cond      := pred-list | cond-obj | pred
pred-list := [ pred | cond-obj, ... ]          // сахар: ≡ {"and": [...]}
cond-obj  := {"and": [cond, ...]} | {"or": [cond, ...]}   // РОВНО один ключ
pred      := "@var"                              // P1: bool-var истинна
           | {"@var": "literal"}                 // P2: равенство (RHS проходит @-подстановку)
           | {"@var": "#notEmpty" | "#isEmpty"}  // P3: по объявленному типу
           | {"@var": {"#in": [..] | "@list"}}   // P4
           | {"@var": {"#notIn": ...}}           // P4
           | {"@var": {"#matches": "re"}}        // P5: паттерн проходит @-подстановку
           | {"#not": cond}                      // P6: отрицание ЛЮБОГО cond (в т.ч. and/or)
```

- Элемент списка `and`/`or` — **либо предикат, либо вложенный `cond-obj`**.
  Глубина не ограничена.
- Пустой `and` → true; пустой `or` → false (как сейчас, §4.1).
- `cond-obj` с обоими ключами или без обоих, предикат неизвестной формы,
  не-список в `and`/`or` — **невалидно** → на load ошибка, в толерантном
  рантайме **false + warning** (fail-closed; принцип D-058: опечатка не должна
  молча включить узел).
- `@runtime.*` в bare-форме запрещён (как сейчас); в `{"@runtime.x": "..."}` —
  разрешён.

### 5.2 `#if` (без изменений формы)

```
{"#if…": {<cond-obj-ключи and|or>, "value": …, "else": …}}
```
Тело `#if` = `cond-obj` + `value`/`else`. После снятия D-018 вложенные `and`/`or`
внутри списков работают автоматически — тот же движок.

### 5.3 `#enable`

```
{ ...поля узла..., "#enable": cond }
```
- Значение — любой `cond` (§5.1), включая сахар-список.
- **Ровно один** ключ `#enable` на узел.
- Ключ всегда вырезается из результата (как `#if`).

## 6. Семантика `#enable` по носителям

| Носитель | false означает | Где сегодня легаси |
|---|---|---|
| объект внутри дерева конфига (элемент массива или значение ключа) | узел **Dropped**: удаляется из родительского массива / ключ удаляется из родительского объекта (каскад §5.1 TEMPLATE_LANG) | — (новая возможность) |
| фрагмент пресета: `rule_set[i]`, `rules[i]`, `dns_servers[i]`, `dns_rule`, `dns_rules[i]`, `outbounds[i]` | фрагмент не эмитится | Go `if`/`if_or` на каждом; Dart `enabled: "@var"` только на `rule_set` |
| переменная пресета (`presets[].vars[i]`) | переменная **неактивна**: поле в диалоге пресета заблокировано; имя **удаляется из varsMap** → фрагменты, ссылающиеся на неё, выпадают (как сейчас `filterActiveVars`) | Go `if`/`if_or` |
| объявление переменной шаблона (`vars[i]`, Settings) | строка Settings **неактивна** (приглушена, заблокирована); **значение сохраняется и по-прежнему подставляется в конфиг** — UI-гейт ≠ emit-гейт (см. §11.7) | Go `if`/`if_or`; Dart — **нет механизма вовсе** (новая возможность для мобилы) |
| `params[i]` | блок не применяется | Go `if`/`if_or` |

Порядок внутри одного узла (нормативно):
1. `#enable` вычисляется **первым**, до любых `#if…` того же узла и до обхода
   детей;
2. false → узел Dropped, **ничего внутри не вычисляется** (никаких warnings из
   детей, никаких побочных эффектов);
3. true → ключ удаляется, далее обычный обход (`#if…` в отсортированном
   порядке, потом поля).

`#enable` внутри ветки `value`/`else` чужого `#if` — работает штатно (ветка
обходится как обычное поддерево).

## 7. Легаси-алиасы (читать бессрочно)

Нормализация на **входе** (при декодировании носителя) в единый `cond`, чтобы ни
одна точка применения не знала о старых формах:

| Легаси | Эквивалент |
|---|---|
| Go `"if": [e1, e2]` | `{"and": [e1, e2]}` |
| Go `"if_or": [e1, e2]` | `{"or": [e1, e2]}` |
| Go `if` + `if_or` на одном носителе | `{"and": [ {"and": if…}, {"or": if_or…} ]}` |
| Go элемент `if[]` — строка-JSON `"{\"@runtime.target\":\"local\"}"` (SPEC 097, `template_validate.go:40-50`) | **распарсить строку как JSON** → предикат. Не забыть! |
| Dart `"enabled": "@var"` на `rule_set[]` (`preset_expand.dart:171-190`) | `{"and": ["@var"]}` |
| Dart `"enabled": true/false` | **НЕ гейт** — см. §11.2 (поле sing-box либо UI-дефолт DNS-сервера); не трогать |
| легаси + `#enable` на одном носителе | `{"and": [legacy, #enable]}`; в документации — не смешивать |

## 8. Компиляция и зависимости

### 8.1 Извлечение зависимостей (контракт, проверяется корпусом)

`deps(cond) → отсортированное множество имён`, статически, по **всему** дереву:

- bare `"@x"` → `x`;
- `{"@x": rhs}` → `x` **плюс** имена из RHS: литерал-строка `"@y"` (C8) → `y`;
  `#in` со строкой `"@list"` → `list`; элементы списка `#in`/`#notIn` вида
  `"@y"` → `y`; `#matches` с паттерном `"@p"` → `p`;
- `#not`, `and`, `or` — рекурсивно;
- **невычисленные ветки тоже входят** (short-circuit не влияет на deps: завтра
  `@a` станет false и результат зависит от `@b`);
- `@runtime.platform`/`arch`/`target` → имена `runtime.platform` и т. д. —
  **псевдо-переменные индекса**: на вкладке Target удалённой машины платформа
  меняется селектором, узлы обязаны реагировать.

### 8.2 Узлы и индекс

При загрузке шаблона (фаза компиляции):

```
узел := { id, cond, deps }
индекс: имя → [id узлов]
```

Стабильные `id` (нужны UI, чтобы найти виджет):
- объявление переменной шаблона → `var:<name>`;
- переменная пресета → `preset:<preset_id>:var:<name>`;
- фрагмент пресета → `preset:<preset_id>:<секция>:<index>`;
- `params` → `param:<index>`;
- узлы дерева конфига в UI не реактивны (считаются только при генерации) —
  в индекс не попадают.

Индекс — производная. Не сериализуется, не попадает в state/бэкап,
пересобирается при каждой загрузке шаблона.

### 8.3 Поток изменения (UI-драйвер)

```
set(@a, v)
  → каскад on_change (существующий fixpoint, Go core/template/on_change.go;
    Dart settings_screen.dart:_applyOnChange)
  → БАТЧ всех изменившихся имён за этот ход (a + цели on_change)
  → индекс: объединение затронутых узлов (без дублей)
  → пересчёт каждого: чистая функция (снимок переменных → bool)
  → сравнение с кэшем результата: не изменилось → виджет не трогаем
  → изменилось → точечное обновление ОДНОГО виджета (enable/disable строки,
    приглушение подписи — см. D-063)
```

Один батч = одно уведомление. Узел, зависящий от двух переменных каскада, не
должен пересчитываться дважды.

### 8.4 Build-драйвер

Генерация конфига: индекс не используется, один проход по дереву, каждый
`#enable`/`#if` вычисляется ровно раз. Тот же движок условий.

### 8.5 on_change-драйвер

`EvalIfScalar` (Go, `substitute.go`) / `evalIfScalar` (Dart) — обязаны идти
через **тот же** движок; после снятия D-018 рекурсия в `on_change.set` работает
автоматически. Проверить, что Go `EvalIfScalar` вызывает общий `selectIfBranch`/
`evaluateIfCondition`, а не свою копию.

## 11. НЕ ПРОПУСТИТЬ — ловушки (каждая стоила времени или является багом)

1. **Неизвестный `#`-ключ выбрасывается обходчиками — молча включая узел.**
   Go `substitute.go:217`, `substitute_canon.go:75`, Dart `if_engine.dart:171-178`.
   Если `#enable` не распознан **до** этой ветки, ключ исчезнет с warning, а
   узел **всегда эмитится** — противоположность задуманному, и никто не заметит.
   Тест обязателен: `#enable` с false внутри `config` → узла нет.

2. **Dart `enabled` — три разных смысла.** `enabled: true` у `tls`, у
   `experimental.cache_file` — **настоящие поля sing-box**; у
   `dns_options.servers[]` — UI-дефолт (включён ли сервер); гейт — только
   строковая форма `"@var"` на `rule_set`. Нельзя трактовать любой `enabled`
   как гейт и нельзя удалять bool-`enabled` из результата. Это и есть главный
   аргумент за помеченное имя `#enable`.

3. **Легаси `if[]` в Go несёт не только имена**: элемент может быть **строкой с
   JSON-предикатом** (`"{\"@runtime.target\":\"local\"}"`, SPEC 097,
   `template_validate.go:40-50`). Нормализация алиасов обязана парсить такие
   строки, иначе гейты Settings по таргету сломаются молча.

4. **Вложенный `and`/`or` сегодня = false/ошибка в обоих движках** (D-018): Go
   `evaluatePredicate` «unknown key → false» (~L567), Dart `TemplateIfError` на
   load. Снимать **и в вычислителе, и в валидаторе**, на обеих сторонах, с
   фикстурами глубины ≥ 3.

5. **Fail-closed везде.** Неразобранное условие → false + warning. Никогда
   true. Прецедент D-058: невалидный `#if` в Go считался истинным и втаскивал
   в конфиг блок, которого автор не просил.

6. **`#enable` вычисляется первым, лениво.** При false — ничего внутри узла не
   трогать: ни `#if`, ни подстановки, ни warnings. Не полагаться на
   алфавитную сортировку (`#enable` < `#if`) — порядок явный.

7. **UI-гейт ≠ emit-гейт у переменных шаблона.** `#enable` на `vars[i]` блокирует
   строку Settings, но значение **продолжает подставляться в конфиг** — это
   существующая семантика `if` (см. `VarUISatisfiedFor`), не «чинить» её молча.
   У переменных **пресета** — иначе: неактивная переменная удаляется из
   `varsMap`, и фрагменты с ней выпадают (`filterActiveVars`). Обе семантики
   сохранить и задокументировать рядом.

8. **`@runtime.*` — зависимости, а не константы.** Платформу удалённой машины
   меняют селектором на вкладке Target → узлы с `{"@runtime.platform": …}`
   обязаны пересчитаться. В индекс как псевдо-переменные.

9. **Deps — по всему дереву**, включая RHS (`{"@a": "@b"}` → `a`, `b`), строку
   `#in` `"@list"`, паттерн `#matches`, невычисленные ветки.

10. **Батч после on_change.** Каскад меняет несколько переменных за клик —
    одно уведомление объединённым множеством, иначе двойные пересчёты.

11. **Два обходчика в Go.** Боевой путь конфига — legacy `SubstituteVarsInJSON`
    (`substitute.go`); канонический `SubstituteVarsInJSONCanon`
    (`substitute_canon.go`) — в корпусе и для D-011. `#enable` и рекурсию — в
    **оба**. Унификация обходчиков — отдельная задача, здесь не делать.

12. **`#enable` в map-фрагменте пресета надо удалить из копии после
    `deepCopyMap` и до `substitutePresetBody`** (`preset_expand.go` rules-loop
    ~L216+), иначе обходчик выбросит его с warning-шумом на каждое правило.

13. **Черновик в `core/template/ifexpr.go`** (`ParseEnableGate`,
    `splitEnableOperator`, `EvalEnable`, `EnableGateSatisfied`,
    `MergeEnableGateJSON`) — форма `["or", …]` **отвергнута**. Переписать, не
    достраивать.

14. **Win7-сборка = go1.20** (`go.win7.mod`, CI legacy-job): в не-`_test.go`
    коде **никаких** `min`/`max`/`slices`/`maps`/`PathValue`. Перед финалом —
    грепнуть.

15. **Тесты на формат UI не писать** (правило проекта): проверяем
    семантику/enable-состояние, не подписи и не вёрстку.

16. **Не задавать вопросов через виджет AskUserQuestion** — решать самому и
