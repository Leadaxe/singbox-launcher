# SPEC 179 — Настройки Tailscale живут в записи узла, каталог отвязан от тега

Владелец 04.11.2026: «почему хранится все в settings.json это же настройки
узла!»; «по умолчанию если разрешен taildrop то и все остальное разрешено
(сохранение в downloads и команды); при миграции старые перестать читать а
новые дефолт сделать по умолчанию»; «а может нам развязать каталог и тег?».
Опора: контракт 1.1.159 (`SERVICE_FILES.md` §5, `BACKUP.md`), SPEC 175–177.

## 1. Умолчания

Если на узле разрешён Taildrop (галка Allow Taildrop, `disable_taildrop: false`
в теле), включены и приём буфера и ссылок, и сохранение файлов в Downloads.
Отключение — исключение: поля записи `disable_taildrop_commands`,
`disable_taildrop_autosave`. Они уже хранятся и переносятся бэкапом (1.1.159),
эта задача начинает их применять.

Удалённая машина: приём буфера и ссылок, автосохранение и двойное копирование
относятся к этому компьютеру, поэтому у её узлов этих пунктов нет (решение
владельца 04.11.2026). Лаунчер не подписывается на её входящие: служебные файлы
не разбираются, файлы забирают кнопкой Save в окне узла. Поля, уже лежащие в
записи такого узла, не применяются и не стираются.

## 2. Команды

Разрешения по устройствам убираются вместе с пунктами «Accept clipboard» и
«Accept links» меню устройства. Отправитель проверяется по норме §5: пир
находится по `senderID` в статусе узла; если у него `shareeNode`, он не найден
или `senderID` пуст, команды не выполняются.

Пропуск из-за `disable_taildrop_commands` даёт уведомление с именем устройства
и местом, где включить приём. Текст и адрес в уведомление не идут.

## 3. Интерфейс

Настройки Taildrop — на вкладке Settings узла Tailscale, под Allow Taildrop,
недоступны при выключенном Allow:

- «Accept clipboard and links from my devices», включена по умолчанию;
- «Save received files to Downloads», включена по умолчанию;
- «Send double copy to»: выбор одного устройства, по умолчанию не выбрано (§5).

Применяются по Apply и Save конфигуратора, как `allow_lan`, и без пересборки
ядра: в конфиг поля не идут. Галка автосохранения из окна узла и «Send double
copy here» из меню устройства убираются.

## 4. Старые настройки

Миграции нет. Поля `TaildropServicePermissions`, `TaildropAutoSave`,
`TaildropDoubleCopy` удаляются из `locale.Settings`; `SaveSettings` пишет файл из
структуры, поэтому ключи пропадают из `settings.json` при первом сохранении.

## 5. Двойное копирование

Владелец 04.11.2026: «не по умолчанию никуда не уходит. выбрать надо явно в
настройках узла»; «одно устройство не группа».

По умолчанию текст никуда не уходит. Текст, скопированный дважды подряд, уходит
на одно устройство, выбранное в настройках Taildrop узла, если оно в сети и
принимает файлы. Устройства sharee в выборе не показываются. Содержимое с
пометкой чувствительности ОС, как и раньше, не отправляется.

Варианты выбора берутся из статуса узла, поэтому без работающего ядра виден
только уже выбранный.

Поле записи стороны лаунчера `taildrop_double_copy` (объект `{peer_id,
peer_name?}`, ключ — stable ID пира), контракт 1.1.160: LxBox пропускает молча,
в бэкап входит. Не выбрано — поля нет. Старые отметки по §4 не читаются.

## 6. Каталог состояния

Имя каталога становится параметром узла: новое поле записи `state_dir_id`
(строка, контракт 1.1.160, обе стороны, входит в бэкап). Имя каталога:

1. `state_directory` в теле, если задан руками, — как сейчас;
2. иначе `state_dir_id`, пропущенный через `sanitizeStateDirName`: строка
   приходит из бэкапа, путь за пределы корня невозможен;
3. иначе, как сейчас, `TailscaleStateDirName(финальный тег)`.

Когда поле ставится:

- новый узел: случайное `ts-xxxxxx`;
- копия узла: новое значение, тот же каталог двум узлам нельзя;
- переименование узла без поля: поле получает имя каталога по старому тегу,
  каталог не двигается, устройство в tailnet остаётся тем же;
- остальные существующие узлы поля не получают, их каталоги не меняются;
- узел подписки записи не имеет: каталог по тегу, как сейчас.

`RenameTailscaleStateDir` и его вызовы удаляются. GC и `CollectTailscaleStateDirNames`
считают имя той же функцией. Ручка lxd для переноса каталога не нужна.

## 7. Вне задачи

Уборка каталогов удалённого узла и узла в режиме daemon на macOS (`bin/tailscale`
принадлежит root): остаётся как сейчас.
