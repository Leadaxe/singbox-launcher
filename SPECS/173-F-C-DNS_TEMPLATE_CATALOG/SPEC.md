# SPEC 173 — Каталог шаблонных DNS-серверов: посев один раз, удаление, бэкап по `template_catalog`

Статус: **C** (написана 23.10.2026 по решению владельца, переданному LxBox: спека LxBox 681; принята владельцем 23.10.2026). Тип: Feature. Контракт: **1.1.135**, решение **D-139**, норма — `contract/docs/BACKUP.md` §9 п. 5 (блок «Состав шаблонных серверов — каталог источника»), поле `dns.template_catalog` (§2, `schema/backup.schema.json`), коды `backup_dns_entry_kept`, `backup_dns_resolver_reset`, `backup_dns_group_empty` (`registry/backup_warnings.json`). LxBox — `contract/TASKS_LXBOX.md` §132.

---

## 1. Проблема

1. **Модели у сторон разные.** У LxBox (§680) секция `dns_options.servers` шаблона — каталог: засевается в список один раз, шаблонный сервер можно удалить и вернуть из каталога. У лаунчера библиотека шаблона эмитится целиком всегда (`core/build/resolve_dns.go`, «TEMPLATE LIBRARY»), запись `kind: template` в состоянии несёт только `enabled` и `vars`, удалить шаблонный сервер нельзя (`DNSTagFromTemplate` блокирует удаление, `reconcileDNSServers` дописывает каждый тег шаблона обратно).
2. **«Нет записи» значит разное.** У LxBox — «удалён», у лаунчера — «по умолчанию шаблона». Записи `kind: template` в состоянии лаунчера появляются только после первого сохранения Конфигуратора, поэтому файл лаунчера не полный список.
3. **Контракт 1.1.135 сделал модель однородной** (D-139): каталог на обеих сторонах, файл несёт `template_catalog` источника, правило снятия одно. До этой SPEC лаунчер только терпит `template_catalog` (`core/backup/file_keys_10.go`), импорт у него — слияние без снятия.

## 2. Решение

### 2.1 Модель

- **Каталог** — `dns_options.servers` шаблона. **Список** — `state.DNS.Servers`. Запись `kind: template` в списке = сервер каталога, который пользователь держит; нет записи = удалён.
- **Посев один раз.** При первой загрузке состояния без признака посева в список дописываются все серверы каталога: `{kind: template, tag, enabled: <default шаблона>}` в порядке шаблона. После посева `reconcileDNSServers` теги каталога **не дописывает**.
- **Сборка** эмитит шаблонный сервер, только если в списке есть его запись (кроме `required: true` — эмитится всегда, запись при отсутствии создаётся). Порядок — по списку.
- **Новый сервер шаблона** (обновился шаблон, тега в каталоге раньше не было) — дописывается в список один раз. Для этого рядом с признаком посева хранится множество тегов каталога, которые уже предлагались. Тег, который пользователь удалил, не возвращается.

### 2.2 Миграция (одноразовая)

Состояние без признака посева: для каждого тега каталога без записи `kind: template` создаётся запись с `enabled` из шаблона; признак посева и множество предложенных тегов выставляются. Без миграции первый экспорт новой версии читался бы как «пользователь удалил всё нетронутое». Миграция — шаг загрузки состояния по образцу `migration_v7_to_v8.go` (бамп версии формата состояния) либо идемпотентный шаг с признаком; выбор — в PLAN.

### 2.3 UI вкладки DNS

- У шаблонного сервера — Delete (как у своего), кроме `required: true` и удерживаемых ссылкой (локи, §2.5): кнопка недоступна, подсказка «Used by …».
- Кнопка «Add from template» — список серверов каталога, которых нет в списке; выбор дописывает запись с `enabled` и `vars` по умолчанию шаблона. «Add all defaults» — все такие сразу.
- Строки и подсказки — через `locale.T` с переводом в `bin/locale/ru.json`.

### 2.4 Бэкап

- **Экспорт** (`core/backup/export10.go`): `dns.servers` — весь список; `dns.template_catalog` — теги каталога в порядке шаблона (`opts.RecordVars` уже знает теги; порядок добавить).
- **Импорт** (`core/backup/import.go`, `importDNS`): после слияния — снятие по `BACKUP.md` §9 п. 5. Условия: тег в `template_catalog` файла, нет записи `kind: template` в файле, нет удерживающей ссылки после импорта (§2.5) → иначе `backup_dns_entry_kept`. Файл без `template_catalog` — слияние без снятия (в паре с лаунчером-приёмником снятия без каталога нет вовсе). Файл без серверов в `dns.servers` — без снятия.
- **Ссылки на неизвестные теги**: `final` / `default_domain_resolver` на тег не из списка или выключенный → умолчание шаблона, `backup_dns_resolver_reset {field, value}`; сервер-группа (`body.type: group`) без единого члена из списка → `enabled: false`, `backup_dns_group_empty {tag}`.
- Коды снять со списка `pending` в `core/backup/schema_test.go` (`TestBackupWarningCodesAreActuallySet`), заведя константы.

### 2.5 Удерживающие ссылки — одна функция

Одна функция «кто держит тег» на вкладку (локи и подписи «Used by») и на импорт (снятие). Закрытый перечень контракта: `final`, `default_domain_resolver`, DNS-правило списка `dns.rules` (`server`; правила шаблона не считаются), `rules[].dns` с непустым `serverTag` независимо от `enabled` (контракт 1.1.136), сервер-группа, `domain_resolver` другого сервера, сервер или DNS-правило включённого пресета, `required: true`. `used_by` — первая удерживающая ссылка в формате контракта.

## 3. Критерии

1. Новая установка: все серверы каталога в списке, включённость как в шаблоне; конфиг тот же, что до SPEC.
2. Обновление со старого состояния: после миграции список = каталог + свои; конфиг тот же.
3. Удалённый шаблонный сервер не возвращается ни перезапуском, ни открытием Конфигуратора; возвращается через «Add from template».
4. Экспорт → импорт в пустое состояние воспроизводит список, удалённое не появляется.
5. Файл LxBox с `template_catalog` без `direct_dns_resolver`: у лаунчера сервер остаётся (тег вне каталога файла). Файл LxBox, где удалён `google_doh`, а у приёмника на него указывает `final`: запись остаётся, `backup_dns_entry_kept {entry: "template:google_doh", used_by: "final"}`.
6. Старый файл лаунчера (без каталога) → слияние, ничего не снято.

## 4. Не входит

- Правка репозитория LxBox (их часть — `TASKS_LXBOX.md` §132).
- Изменение формы самих шаблонных серверов, переменных записи (SPEC 129) и DNS-правил.
