# SPEC 095 — Подзаголовок узла, иконки групп и экран информации

**Тип:** Feature · **Статус:** New

Перенос из LxBox трёх связанных вещей списка серверов: подзаголовок под тегом,
значки пула у групп и пункт «Info» в контекстном меню с полной карточкой узла.

---

## 1. Проблема

Список серверов на вкладке Servers показывает только **тег и пинг**. Всё, что
описывает узел — протокол, транспорт, TLS/Reality, версия AmneziaWG, состав
группы, цепочка detour — не видно нигде, кроме сырого `config.json`.

Практические следствия:

1. Два узла с одинаковым именем от провайдера неразличимы: `vless·ws·Reality` и
   `vless·tcp·TLS` выглядят одинаково.
2. У импортированных групп (SPEC 094) не видно ни режима, ни состава — только
   имя. Пользователь не понимает, что это группа, а не сервер.
3. Чтобы посмотреть, что реально уехало в конфиг, приходится открывать
   `config.json` текстом.

В LxBox это решено давно и, по оценке пользователя, работает хорошо — переносим
оттуда, а не выдумываем своё.

---

## 2. Ключевое ограничение — источник данных

`api.ProxyInfo` (`api/clash_proxy.go:17`), которым живёт список, приходит из
Clash API и несёт только `Name`, `ClashType`, `Delay`, `Traffic`.

**Транспорта, TLS, сервера, состава группы там нет.** Всё это лежит в
`config.json`, который лаунчер сам сгенерировал.

Поэтому основная часть задачи — не UI, а **слой чтения `config.json`**,
отдающий по тегу разобранные поля. В LxBox эту роль играет
`ParsedConfig`/`ConfigNode` (`app/lib/models/config_node.dart`).

Слоя чтения `config.json` для UI в проекте сейчас нет.

## 3. Требования

### 3.1 Слой данных

**D1. Разбор `config.json` по тегу.** Новый пакет читает актуальный
`config.json` и отдаёт по тегу узла:

| Поле | Источник |
|---|---|
| `Type` | `type` outbound'а |
| `Kind` | `outbound` или `endpoint` (WireGuard живёт в `endpoints`) |
| `Server`, `ServerPort` | одноимённые поля |
| `Transport` | `transport.type`; для masque — `network`; см. D2 |
| `Security` | TLS/Reality/Vision, для WireGuard — версия AWG; см. D3 |
| `Detour` | поле `detour` |
| `GroupMembers` | `outbounds[]` у selector/urltest |
| `Raw` | исходный JSON-объект целиком (для экрана Info) |

**D2. Метка транспорта** — правила LxBox (`_deriveTransport`):
- `transport.type`, при этом `http` показывается как `h2`;
- `masque` → `network`, пусто → `h3` (дефолт ядра);
- `vless`/`vmess`/`trojan`/`anytls` без `transport` → `tcp`;
- иначе — пусто.

**D3. Метка security** — правила LxBox (`_deriveSecurity`):
- `tls.enabled` + `reality.enabled` → `Reality`, иначе `TLS`;
- плюс `+Vision`, если `flow` начинается с `xtls-rprx-vision`;
- WireGuard — уровень AmneziaWG по наличию полей:
  - `awg2` — ranged-заголовки `h1`–`h4` вида `"N-M"` либо `s3`/`s4`;
  - `awg1.5` — signature-пакеты `i1`–`i5`;
  - `awg` — базовые `jc`/`jmin`/`jmax`/`s1`/`s2`/одиночные `h1`–`h4`;
  - суффикс `+` при masquerade-полях `ip`/`id`/`ib` (`awg2+`, `awg1.5+`);
- иначе — пусто.

**D4. Кэш и инвалидация.** Конфиг читается один раз и кэшируется; кэш
сбрасывается при перегенерации конфига. Список серверов перерисовывается часто —
читать файл на каждую строку нельзя.

### 3.2 Подзаголовок

**S1. Формат.** Под тегом — строка `протокол·транспорт·security`, пустые части
опускаются: `vless·ws·Reality`, `vless·tcp·TLS+Vision`, `masque·h3`,
`wireguard·awg2+`.

**S2. Группы.** У selector/urltest вместо протокола — метка режима с размером
пула: `🔀 [15/7]` (round robin: всего/активных) либо `🎯 [3]` (least test).

**S3. Пинг** остаётся справа, прижатым к краю строки; подзаголовок не должен
его смещать или конкурировать за ширину.

**S4. Длинные значения** обрезаются многоточием, строка не переносится и не
растягивает окно (см. память проекта: длинный `Label` без `Wrapping` задаёт
min-width и ломает layout).

**S5. Узел без данных** (нет в конфиге, конфиг не читается) показывается как
сейчас — только тег. Отсутствие подзаголовка не считается ошибкой.

### 3.3 Иконки групп

**G1.** Рядом с меткой режима группы — значки её живых членов (флаги из тегов).
Ограничение по количеству, чтобы строка не расползалась.

**G2.** Значки берутся из тегов членов; если извлечь нечего — метка режима
показывается без них.

### 3.4 Экран информации

**I1. Вход** — пункт «Info» в контекстном меню узла (правый клик). Отдельной
кнопки в строке не будет: строка и так плотная.

**I2. Содержимое** — всё, что известно об узле:
- тег, тип, kind (outbound/endpoint);
- сервер и порт;
- транспорт и его параметры (path, host, service_name);
- TLS: SNI, ALPN, fingerprint, reality public_key/short_id, insecure;
- detour-цепочка;
- для групп — тип, состав, url/interval;
- источник (из какой подписки узел);
- полный JSON узла с возможностью копирования.

**I3. Копирование.** JSON и отдельные поля можно скопировать в буфер.

**I4. Окно.** Отдельное окно приложения, не модальный попап — форма высокая
(см. память: для высоких форм `Application.NewWindow`, иначе Fyne раздувает
диалог).

## 4. Критерии приёмки

1. Узел `vless` с ws-транспортом и reality показывает `vless·ws·Reality`.
2. Узел `vless` на голом TCP с vision показывает `vless·tcp·TLS+Vision`.
3. MASQUE-узел без `network` показывает `masque·h3`.
4. WireGuard с ranged-заголовками и masquerade показывает `wireguard·awg2+`.
5. Импортированная группа urltest из 15 членов показывает метку режима с
   размером пула, а не протокол.
6. Пинг остаётся у правого края при любой длине подзаголовка.
7. Узел, которого нет в `config.json`, показывается без подзаголовка и не
   роняет список.
8. «Info» в контекстном меню открывает окно с JSON узла; JSON копируется.
9. Для группы «Info» показывает состав и параметры проверки.
10. Список из 500+ узлов не тормозит: конфиг читается один раз, не на строку.
11. Окно приложения не раздувается по ширине из-за длинных подзаголовков.
12. `go build ./...`, `go test ./...`, `go vet ./...` — чисто.

---

## 5. Риски

| Риск | Митигация |
|---|---|
| Длинный подзаголовок растягивает окно | Truncation на всех Label; критерий 11 |
| Чтение конфига на каждую перерисовку тормозит список | Кэш с инвалидацией (D4); критерий 10 |
| Рассинхрон конфига и списка после перегенерации | Сброс кэша в той же точке, где помечается config dirty |
| Тег в Clash API не совпадает с тегом в конфиге | Сопоставление по точному тегу; несовпадение → узел без подзаголовка (S5) |

## 6. Не-цели

- Редактирование узла из окна Info — только просмотр.
- Перенос всей карточки узла LxBox с вкладками Source/JSON: показываем JSON
  конфига, исходный фрагмент подписки — отдельная задача.
- Изменение самого списка (сортировка, фильтры) — не трогаем.
