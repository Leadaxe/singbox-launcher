# SPEC 116 — Папки серверов (server folders)

> **СТАТУС: NEW.** Решения по трём развилкам приняты пользователем
> (сценарии 1/2/3 → А/А/А + уточнение по drag-n-drop). Зеркало §234/§236/§237
> LxBox — модель переносится полем в поле, чтобы бэкап сходился.

## 1. Зачем

Сегодня набор из десяти отдельных конфигов провайдера (типовой случай — по
одному файлу на сервер) превращается в десять записей на вкладке Sources.
Их нельзя ни выключить одним движением, ни назвать общим именем, ни задать
им общую тег-политику и общий detour: каждая запись несёт свои настройки.

**Папка** — контейнер ручных серверов: одно имя, один переключатель, одна
тег-политика и один detour на всех, но каждый сервер внутри включается и
выключается отдельно.

Папка НЕ подписка. У неё нет URL, нет метаданных провайдера, нет интервала
и статуса обновления, нет счётчика неудач — она не ходит в сеть **никогда**.
Состав папки принадлежит пользователю, а не источнику: он не может измениться
у пользователя за спиной.

## 2. Терминология (жёстко)

- Сущность зовётся **папка** / `folder` — в UI, в коде, в JSON.
- Элемент папки — **член** / `member`. Не «узел»: узел это то, что член
  даёт после разбора, и у битого члена узла нет.
- «Группа» — занятое слово (selector/urltest ядра, свёртки SPEC 108).
  Папку группой не называть нигде.

## 3. Решения по развилкам

| № | Развилка | Решение | Почему |
|---|---|---|---|
| 1 | Как папка хранит серверов | **Список фрагментов** `members[]`: `raw` + `enabled` + `detour` | Контейнер существующих источников оставил бы каждому свою тег-политику и свой detour — это ровно то, что папка отменяет. Плюс узел оказался бы в двух источниках сразу, что рвёт SPEC 112 («идентичность — тег в рамках источника») |
| 2 | Как выключается член | **Булев `enabled` на члене** | `disabled_nodes` (карта идентичность→время + TTL + GC) решает задачу подписки: состав перезаписывается провайдером, и отметка обязана пережить обновление. У папки состав неизменен — чистить нечего, TTL пустой |
| 3 | Список Sources | **Плоский**: папка — одна строка, состав только внутри её окна | Раскрытие в списке сломало бы drag-reorder источников, который работает по плоскому индексу |
| 3а | Drag-n-drop | **Два независимых контура**: члены таскаются внутри окна папки, папки — в общем списке источников. **Перетаскивания через границу нет** | Уточнение пользователя. Перенос члена наружу и в другую папку — командой меню, не перетаскиванием |

## 4. Модель

### 4.1 Четвёртый тип источника

`core/state/connections.go` — новое значение дискриминатора:

```go
SourceTypeFolder SourceType = "folder"
```

Папка живёт в том же `connections.sources[]`, что подписка, сервер и цепочка.
Отдельной секции состояния нет.

### 4.2 Поля папки

Живые поля для `type: "folder"`:

| Поле | JSON | Смысл |
|---|---|---|
| `ID` | `id` | ULID, цель ссылок `detour_node_source_id` |
| `Type` | `type` | `"folder"` |
| `Enabled` | `enabled` | переключатель всей папки |
| `Label` | `label` | имя папки (отображение) |
| `Tag` | `tag` | `TagSpec` — общая тег-политика на всех членов |
| `Members` | `members` | **новое**: массив членов, порядок = порядок в UI |
| `CreatedAt` | `created_at` | RFC3339, момент создания |
| `ExcludeFromGlobal` | `exclude_from_global` | как у прочих источников |
| `DetourTag` / `DetourNode*` | | общий detour папки |
| `Fold` | `fold` | свёртка в группу (SPEC 108) — папка её поддерживает |

**Мёртвые для папки** (не пишутся, не читаются): `URL`, `URI`, `ConfigJSON`,
`Chain`, `Skip`, `Update`, `Meta`, `MaxNodes`, `DisabledNodes`, `NodeTag`.

`NodeTag` мёртв намеренно: у папки нет одного узла, тегом которого она
представлена — она даёт N узлов, и их теги строятся из `Tag` + голого тега
члена, как у подписки.

### 4.3 Член папки

```go
// FolderMember — один сервер внутри папки.
type FolderMember struct {
    Raw       string `json:"raw"`
    Enabled   bool   `json:"enabled"`
    DetourTag string `json:"detour,omitempty"`
}
```

- `Raw` — **самодостаточный разбираемый фрагмент**: одна URI-строка, либо
  целый WG/AWG-INI (многострочный), либо sing-box outbound JSON. Именно
  поэтому у папки массив фрагментов, а не одно общее тело: построчная
  вставка и удаление сломали бы INI.
- `Enabled` — по умолчанию `true`, пишется всегда (не omitempty): у члена
  `false` — рабочее состояние, и omitempty сделал бы его неотличимым от
  «поле не записано».
- `DetourTag` — личный detour члена, пишется только непустой. Взаимодействие
  с общим detour папки — §6.4.
- **У члена нет id.** Идентификация позиционная (индекс в `members[]`).
  Осознанно: ссылок на члена как на объект нет, а стабильная идентичность
  узла берётся из тега (SPEC 112).

### 4.4 Инвариант: один член = один узел

Фрагмент, разбирающийся в N узлов (многострочная вставка, файл с несколькими
URI), **расщепляется на N членов в момент импорта**. Инвариант держит всё
остальное простым: переключатель, порядок, отображение, счётчик.

Если после расщепления `raw` всё же даёт больше одного узла — берётся первый.

### 4.5 Битый член

`raw`, который не разбирается, — **штатное состояние, а не ошибка импорта**.
Такой член виден в окне папки (показывается началом `raw`), правится и
удаляется. В конфиг он не идёт.

Правка члена, после которой `raw` перестал разбираться, **откатывается** с
сообщением: молча превратить рабочий сервер в битый — потерять данные.

### 4.6 Узлы папки

Узлы папки не хранятся в состоянии. Они восстанавливаются разбором каждого
включённого `raw` — локально, без сети, при каждой сборке.

**Выключенный член до разбора не доходит.** Фильтрация по `Enabled` — на
входе в конвейер, а не внутри него: тогда весь остальной лаунчер (генератор,
Направления, санитайзер) о папках вообще ничего не знает.

## 5. Наполнение папки

Пять путей, все — через общее ядро с расщеплением (§4.4):

| Путь | Поведение |
|---|---|
| **Вставка текста** | share-URI, несколько строк, WG-INI, sing-box JSON |
| **Импорт файлов** | мультивыбор; имя члена без собственного `#fragment` берётся из имени файла без расширения |
| **По ссылке — разовый снимок** | fetch → разбор → статичные члены. **URL не сохраняется, метаданных нет, автообновления нет.** В диалоге обязана стоять явная пометка: «Загружается один раз — серверы добавятся снимком и обновляться не будут. Нужны обновления — добавьте подписку» |
| **WARP** | регистрация кладётся членом папки |
| **Перенос одиночного сервера** | `URI`/`ConfigJSON` источника становится `raw` члена, запись источника удаляется |

### 5.1 Цена переноса одиночного сервера в папку

Личные `Tag` и `DetourTag` переносимого источника **отбрасываются** —
действуют папочные. Это осознанный размен («настроил один раз на всех»), а
не потеря: пользователь обязан быть предупреждён в диалоге переноса, если
у источника были непустые личные настройки.

Исключение: личный detour источника переезжает в `member.detour` — он
описывает не политику, а конкретный маршрут этого сервера.

### 5.2 Дедупликации членов нет

Два одинаковых сервера в папке — законно, ровно как сегодня законны два
одинаковых одиночных источника. Дедуп внутри одного источника при разборе
(`newSourceDedup`) работает как у всех, но записи в `members[]` не трогает.

## 6. Сборка конфига

### 6.1 Общий конвейер, без ветвлений

Папка попадает в сборочную форму (`configtypes.ProxySource`) уже
**отфильтрованной**: `Connections` содержит `raw` только включённых членов.
Дальше генератор, тег-политика, Направления и санитайзер работают с ней как
с любым другим источником.

### 6.2 Теги и идентичность

Идентичность узла — **голый тег члена, уникализированный в рамках папки**,
снятый до применения `Tag` (SPEC 112 писался с прямым расчётом на папки:
«тег, уникальный в рамках источника — подписки **или папки**»).

Финальный тег = `Tag` (prefix/postfix/mask) поверх голого. Коллизии с узлами
других источников снимаются общим `MakeTagUnique`, отдельного механизма нет.

### 6.3 Ссылки на узлы папки

Папка — полноценный адресат ссылок: `detour_node_source_id` = ULID папки,
`detour_node_tag` = identity-тег члена внутри неё. Резолв — через общий
индекс `buildNodeRefIndex`, отдельного пути **не заводить**.

### 6.4 Detour: личный члена поверх общего папки

- Член без личного detour дозванивается через общий detour папки.
- Член с личным detour — через свой; общий папочный к нему **не
  применяется** (иначе получилась бы неявная двухзвенная цепочка, которую
  пользователь не просил).
- Личный detour, указывающий на другого члена **этой же** папки, хранится
  **голым тегом** — тогда он переживает смену префикса папки. Внешняя цель
  хранится в финальной форме, как везде.
- Отвергаются: ссылка на самого себя и ребро, замыкающее цикл внутри папки.
- Недоступная цель — **fail-closed**, общим правилом: носитель выбрасывается
  с ⚠, detour никогда не снимается (снять — отправить трафик напрямую вопреки
  настройке).

### 6.5 Достоверность разбора

Папка — локальный источник, сети не касается: её разбор **всегда
достоверен** (в терминах SPEC 113-A). Пустая папка и папка с полностью
выключенными членами дают ноль узлов **без** пометки «источник не дал узлов»:
это не сбой, а состояние, заданное пользователем.

Отдельная строка отчёта нужна другая: **папка, у которой все члены битые** —
это уже потеря, и она обязана быть видна.

## 7. Операции

| Операция | Семантика |
|---|---|
| Создать папку | пустая, из меню добавления Sources |
| Переименовать | правка `Label` |
| Переключить папку | `Enabled` — гасит/зажигает всех членов разом |
| **Удалить папку** | диалог с двумя исходами: **удалить вместе с серверами** / **вынести серверы** (каждый член становится одиночным источником на месте папки, порядок и личные `enabled` сохраняются) |
| Добавить членов | пять путей §5 |
| Переключить члена | `member.Enabled` |
| Править члена | правка `raw`; неразбираемый результат откатывается (§4.5) |
| Удалить члена | с подтверждением при непустом составе |
| Порядок членов | drag внутри окна папки |
| **Вынести члена наружу** | член → одиночный источник; личный detour переезжает в его настройки |
| **Перенести члена в другую папку** | целиком, вместе с `enabled` и личным detour; папочные настройки — новой папки |
| Порядок папок | общий drag списка источников, как сейчас |

**Переноса узла из подписки в папку нет.** Составом подписки владеет
провайдер; вынуть оттуда узел — значит сделать его копию, которая разойдётся
с оригиналом при первом же обновлении. Нужен такой сервер отдельно — есть
копирование его ссылки.

## 8. UI

### 8.1 Строка в списке Sources

```
📁 Mullvad · 10 серверов (2 выкл)
```

- Подпись — `Label`; при пустом — «Папка N».
- Счётчик — по составу `members[]`, **не** по разобранным узлам: он обязан
  работать до всякой сборки.
- Пустая папка — «Пустая папка».
- Битые члены — отдельным довеском: `· 1 не читается`.

Кнопки строки: переключатель, правка (открывает окно папки), удаление,
ручка перетаскивания. **Кнопки обновления у папки нет** — обновлять нечего;
её присутствие было бы обещанием, которого папка не выполняет.

### 8.2 Окно папки

Зеркалит окно источника: **Обзор**, **Серверы**, **Настройки**.

- **Обзор** — тип, id, имя, количество членов, дата создания. Блока
  метаданных провайдера нет (их не существует).
- **Серверы** — список членов: переключатель, подпись (тег узла или начало
  `raw` у битого), меню члена (Править / Перенести в папку… / Вынести наружу /
  Удалить), перетаскивание. Кнопка добавления с пятью путями §5.
- **Настройки** — тег-политика, общий detour, `exclude_from_global`,
  свёртка. Те же виджеты, что у подписки.

### 8.3 Пустая папка

Показывает подсказку, как добавить серверы, а не пустой список.

## 9. Бэкап и контракт

Папка едет в бэкап **целиком, вместе с составом**: `raw` членов — это и есть
её содержимое, без них восстанавливать нечего.

- Новая корневая секция `folders[]` в `contract/docs/BACKUP.md` и схеме.
- Поддержка — **обе стороны**: у LxBox папка уже есть (§234), поля сходятся
  один в один (`raw` / `enabled` / `detour`).
- Слияние по `id`; при его отсутствии — по имени.
- `contract/VERSION` — бамп минора (новая секция, обратно совместимо:
  старая сторона её отбросит с warning по общему правилу П3).
- Секреты: `raw` членов содержит ключи и пароли — это ровно то же, что уже
  едет в `servers[].uri`, и той же политикой (локальная машина = граница
  доверия) покрыто. Ничего нового не открывается.

## 10. Ловушки реализации

Три системных места, где новый тип **не упадёт, а молча исчезнет**:

1. **`core/state/adapter_source.go:24-84`** — `switch s.Type` с
   `return configtypes.ProxySource{}` на дефолте. Папка без своей ветки
   станет пустым источником. Добавить ветку **и** явную диагностику в
   дефолт — чтобы следующий тип упал громко.

2. **`core/state/sync_to_connections.go:59-206`** — обратный синк
   дискриминирует **не по `Type`, а по заполненности полей**:
   `Chain != nil` → `Source != ""` → `Connections`/`ConfigJSON`. У папки
   `Connections` непустой — **она слипнется с одиночным сервером**. Нужен
   явный признак папки в сборочной форме и ветка **раньше** серверной.

3. **`core/state/sync_to_connections.go:41-77`** — матчинг старой записи:
   у каждого типа свой ключ (URL / URI / тег цепочки / ID). Без своего ключа
   папка получит **новый ULID на каждом сохранении**, и из-под неё уедут все
   ссылки `detour_node_source_id`. Ключ папки — `ID`, запасной — имя.

Плюс `core/state/sync_to_legacy.go:19-77` и `core/backup/export.go:77-83` —
`switch` без `default`, та же болезнь.

**Сборочная форма (`configtypes.ProxySource`) не имеет поля `Type`** — тип
выводится по заполненности. Это две несогласованные системы дискриминации;
папка обязана нести явный признак, а не полагаться на форму полей.

## 11. Критерий приёмки

Сценарий с форума, дословно:

1. Десять файлов, по одному конфигу Proton в каждом → мультивыбор → папка
   «Proton» с десятью членами, имена взяты из имён файлов.
2. Переключатель папки гасит все десять разом.
3. Префикс `proton-` в настройках папки → Направление с фильтром
   `^proton-` забирает ровно её серверы.
4. Выключение двух членов → в конфиге восемь узлов, строка показывает
   «10 серверов (2 выкл)».
5. Битый файл среди десяти → девять рабочих членов и один видимый битый;
   сборка не падает, отчёт «Итога» его называет.
6. Экспорт бэкапа → импорт на чистом состоянии → папка восстановлена
   с составом, порядком и личными переключателями.

## 12. Что НЕ делаем

- Вложенных папок нет. Один уровень.
- Подписки в папку не кладутся, смешанных папок нет.
- Автообновления содержимого папки нет ни в каком виде.
- Дедупликации членов нет.
- Персональной тег-политики у члена нет (личный detour — есть).
- Переноса узла из подписки в папку нет (§7).
- Тестирования членов (аналог §236 LxBox) в этой задаче нет — отдельная
  работа поверх готовой папки.

## 13. Связанные

- SPEC 110 — цепочки: ближайший прецедент добавления типа источника.
- SPEC 112 — идентичность узла тегом; писался с расчётом на папки.
- SPEC 108 — свёртка источника в группу; папка её поддерживает.
- SPEC 113-A — достоверность разбора (§6.5), 113-B — fail-closed detour.
- SPEC 115 — отчёт сборки: папка с битыми членами обязана в нём звучать.
- LxBox §234 (папки), §237 (личный detour члена), §284 (WARP-генератор).
