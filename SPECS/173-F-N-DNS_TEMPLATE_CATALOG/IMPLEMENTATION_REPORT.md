# IMPLEMENTATION REPORT 173

**Итог:** секция `dns_options.servers` шаблона у лаунчера стала каталогом, как у LxBox (D-139, контракт 1.1.135–1.1.136). Список засевается каталогом один раз (это же миграция старых состояний), шаблонный сервер удаляется на вкладке DNS и не возвращается сам; «Add from template» / «Add all defaults» возвращают удалённые. Бэкап несёт `dns.template_catalog` и полный список, импорт снимает удалённое источником по норме `BACKUP.md` §9 п. 5. Кейс корпуса `v10_dns_template_catalog` — контракт 1.1.137, LxBox — `TASKS_LXBOX.md` §133.

## Что сделано

- **Данные** (`core/state`). `DNSOptions.TemplateCatalog` (`json:"template_catalog,omitempty"`) — одно поле на состояние и бэкап 1.0 (у бэкапа `dns` и есть `state.DNSOptions`): в состоянии — каталог, которым список засеян (nil — посева не было), в файле — каталог источника. `SeedDNSTemplateCatalog(dns, decls, skip)`: тегу каталога, которого `TemplateCatalog` ещё не видел, и `required` без записи — запись `{kind: template, tag, enabled: умолчание шаблона}` на место в порядке каталога; затем `TemplateCatalog` = каталог. `ApplyRecordVars` = посев + `NormalizeRecordVars` (прежнее тело) — посев идёт во всех точках встречи состояния с шаблоном: загрузка и сохранение Конфигуратора, сборка из файла, экспорт, debug API. `FindTemplateServer`. `DNSServerHolders(state, decls)` — одна функция удерживающих ссылок: тег → `used_by` словаря контракта (`final`, `default_domain_resolver`, `dns_rule:<server>`, `rule:<name>`, `group:<tag>`, `server:<tag>`, `preset:<id>`, `required`), первая по порядку словаря.
- **Мост шаблона** (`core/template/record_var_decls.go`). `RecordVarDecls` получил `DNSServerOrder` (порядок каталога; nil — секции нет), `DNSServerRequired`, `DNSServerLinks` (`domain_resolver` и члены группы тела сервера, `@имя` — переменная записи) и `PresetDNSRuleServers` (`server` DNS-правил пресета на любой глубине `#if`).
- **Сборка** (`core/build/resolve_dns.go`). Шаблонный сервер эмитится, только если у тега есть запись `kind: template` в списке; `required` — всегда. Состояние без посева (`TemplateCatalog == nil`) — прежнее правило «нет записи = умолчание шаблона».
- **Конфигуратор.** `model.DNSTemplateListed` — теги шаблонных записей загруженного состояния (`restoreDNS`); `reconcileDNSServers` строит строку сервера каталога, только если он в списке или `required` (nil — состояния нет, каталог целиком). `syncDNSServersOnly` пишет ровно строки модели — доливка записей по `explicitOverrides` снята; `TemplateCatalog` списка — все теги шаблона (порядок выставит посев). Вкладка DNS: Del у шаблонного сервера (выбор записи — включённость, значения переменных — снимается, `ForgetDNSTemplateServer`); недоступен у `required` и удерживаемого ссылкой, подсказка и строка описания называют, кто держит (`presenter.DNSServerHolders` — лёгкое состояние из модели → `state.DNSServerHolders`). «Add from template» — меню серверов каталога, которых нет в списке (`DNSTemplateServersMissing`, `AddDNSTemplateServer`: тело и включённость шаблона, место по каталогу); «Add all defaults» — все сразу; кнопки недоступны, когда возвращать нечего. Свой сервер с тегом каталога не заводится (иначе сохранился бы шаблонным). 18 ключей `locale.T` с переводом в `bin/locale/ru.json`.
- **Бэкап.** Экспорт: `dns.template_catalog` = поле состояния копии, засеянной каталогом (`stateWithRecordVars10`), `servers` — полный список. Разбор 1.0: ключ из рефлексии `state.DNSOptions`, ручной `withKeys` для `template_catalog` снят; `decodedDNS.TemplateCatalog`. Импорт (`importDNS`): снятие удалённого источником (тег в каталоге файла, записи в файле нет, нет удерживающей ссылки после импорта — иначе `backup_dns_entry_kept {entry, used_by}` с `used_by` в `Warning.Reason`); файл без каталога или без серверов — без снятия; `backup_dns_resolver_reset` (`final` / `default_domain_resolver` файла — поле секции и переменная `dns_final` / `dns_default_domain_resolver` — на тег вне списка или выключенный: значение снимается с обоих каналов, действует умолчание шаблона; поле — `Warning.Reason`); `backup_dns_group_empty` (ввезённая группа без членов из списка — выключена). Три константы, три фразы отчёта импорта (`settings_backup.go`), коды сняты с `pending` в `schema_test.go` (список убран).
- **Корпус** (контракт 1.1.137). `v10_dns_template_catalog` (фикстура шаблона из четырёх серверов, предсостояние — файл лаунчера, кейс — файл LxBox): снятие `google_udp`, удержание `google_dot` (`dns.final`) и `cloudflare_dot` (DNS-правило), `quad9_doh` вне каталога файла, сброс `default_domain_resolver`, пустая группа выключена. Конвенция раннера в `corpus/backup/README.md`: у кейса с фикстурой пустое состояние — пустой список при засеянном каталоге; Go-раннер помечает каталог фикстуры засеянным до импорта. Прогон: `go test ./core/backup/ -run 'TestBackupCorpus|TestBackupWarningCodesAreActuallySet'` — ok.
- **Доки.** `docs/ARCHITECTURE.md` (каталог → список → сборка, удерживающие ссылки, импорт), `docs/release_notes/upcoming.md` (EN/RU), `RELEASE_NOTES.md` (черновик).

## Отступления от SPEC/PLAN и решения по умолчанию

- **Порядок эмиссии шаблонных серверов — каталога, а не списка** (SPEC §2.1 «Порядок — по списку»). Ядро адресует серверы тегом, вкладка DNS показывает шаблонные в порядке каталога, а порядок по списку менял бы `config.json` после миграции (записи дописываются посевом) — против критериев §3 п. 1–2 «конфиг тот же».
- **Посев на импорте — после слияния, не до.** Засеянная до слияния запись была бы «своей» и по правилу «своё сильнее» перебила бы включённость из файла: импорт в пустое состояние (`ImportBackupFile(fresh)`) снова уводил бы DNS мимо VPN — тот самый случай, ради которого fresh-импорт идёт в пустое состояние. Поэтому импорт зовёт `NormalizeRecordVars`, а посев — в `importDNS` с исключением серверов, удалённых источником (удерживаемый всё же засевается с `backup_dns_entry_kept`).
- **Миграция без бампа версии формата состояния:** признак посева — само поле `TemplateCatalog`, посев идемпотентен (PLAN допускал). Состояние на диске получает поле при первом сохранении (Конфигуратор, импорт, debug API); до этого каждый читатель засевает свою копию одинаково.
- **Удерживающие ссылки пресета** — только `server` DNS-правил пресета (литерал или `@переменная`); у DNS-серверов пресета лаунчера нет `domain_resolver` и групп. Полного раскрытия пресета, как у LxBox, нет — в `core/state` шаблона нет, данные приходят мостом.
- **`used_by` и поле сброса едут `Warning.Reason`** (`Detail` — `template:<tag>` / значение): так же отдаёт их debug API.
- **Группа без членов** выключается только у ввезённой этим импортом группы («ввозится выключенной»); локальные группы импорт не трогает.
- **Контракт 1.1.137** — сверх SPEC: кейс корпуса подхватывает раннер LxBox, и конвенцию «пустого состояния» пришлось записать в README корпуса.
