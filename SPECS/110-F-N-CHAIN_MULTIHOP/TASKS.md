# TASKS 110 — Цепочка хопов (`chain`)

Нормативка: [`SPEC.md`](SPEC.md). Порядок фаз обязателен: модель → проба →
UI → валидация → контракт. Каждая фаза заканчивается зелёной сборкой.

## Фаза 0 — подтвердить открытый вопрос
- [ ] Ядро без `with_lx_chain` (текущий бандл): вариант (а) — делаем с
      деградацией, не дожидаясь сборки ядра с тегом

## Фаза 1 — модель и эмиссия
- [ ] `DirectionChain{Hops, IdleTimeout, StripEvasion, Strip, Rewrite}`
- [ ] `Direction.Chain *DirectionChain`, json-ключ `chain`
- [ ] Эмиссия `{"type":"chain","tag":…,"outbounds":[…]}` — поле ядра
      называется `outbounds`, наше `Hops` (T3: порядок = порядок пакета)
- [ ] Цепочка не получает состав селектора и парную auto-группу

## Фаза 2 — проба ядра и деградация (T1)
- [ ] `ChainSupportProbe` по образцу `NaiveSupportProbe`
- [ ] Без поддержки: запись не эмитится, правила на неё → `direct`,
      предупреждение в лог с версией ядра и нужным тегом
- [ ] Пометка неработающей записи в списке Направлений

## Фаза 3 — UI
- [ ] Тип записи в редакторе Направления: селектор | цепочка
- [ ] Вкладка «Цепочка»: список позиций, `+` с выбором, перетаскивание
- [ ] Подпись направления пакета над списком (T3)
- [ ] Настройки: `idle_timeout`, `strip_evasion`, четыре ключа `strip`
- [ ] При типе «цепочка» вкладка «Автовыбор» скрыта

## Фаза 4 — валидация (T2, T4, T5, T6, T7)
- [ ] Минимум две позиции
- [ ] `tls.utls` нельзя снять, если на пути узел с `reality`
- [ ] Вложенная цепочка — только на позиции 0
- [ ] Внутренние теги `<tag>#<i>` не попадают в цели правил
- [ ] Цепочка и `detour` подписки не смешиваются
