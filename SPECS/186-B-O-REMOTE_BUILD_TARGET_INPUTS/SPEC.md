# SPEC 186 — Сборка конфига машины берёт входы от цели, а не от компьютера лаунчера

## Проблема

Конфиг удалённой машины (роутер, VPS) собирается на компьютере лаунчера.
Три входа сборки при этом берутся с этого компьютера, а не с машины-цели:

| № | Что | Где | Симптом в конфиге машины |
|---|-----|-----|--------------------------|
| 1 | Пресеты шаблона отбираются по ОС лаунчера | `core/template/loader.go` (`filterPresetsByPlatform(…, runtime.GOOS)`) | Пресет «только linux» при сборке на macOS/Windows пропал бы из конфига роутера; пресет «только darwin» попал бы туда. В текущем шаблоне платформы есть только у `messengers` (windows/darwin/linux) — ошибка спящая. |
| 2 | Гейт узлов смотрит на локальное ядро | `core/config/node_build_gate.go` (`CoreVersionProbe`, `runtime.GOOS`, `CoreBuildTagsProbe`), `ChainSupportProbe` | `tls.kernel_tx` / `tls.kernel_rx` (kTLS, платформа linux) молча срезаются; поля с `min_core` (REALITY `key_share`, XHTTP) режутся или остаются по версии ядра лаунчера; узлы naive/tailscale и цепочки снимаются по тегам сборки локального ядра. |
| 3 | `@vars` в `parser_config.outbounds` читаются из локального состояния | `core/config/varsubst.go` (`BuildVarSubstituterFromDisk` → `wizard_states/state.json`) | URLTest URL / interval / tolerance из Settings машины не действуют на её auto-группы — подставляются значения профиля этого компьютера. |

Проверено и отклонено:

- **params шаблона** — пересчитываются от цели в `core/build/build.go` (`effectiveConfig` → `GetEffectiveConfigForWarnings(…, target)`); вызов с `runtime.GOOS` в загрузчике — прекэш умолчаний.
- **наличие `.srs` legacy-правил в `bin/rule-sets`** (`core/build/route_merge.go`, `convertRuleSetToLocalRequired`) — для машины ветка недостижима: любое пользовательское правило даёт запись v6, и `ctx.Route.Rules` обнуляется (`ui/configurator/business/create_config.go`).

## Требования

1. Сборка для машины отбирает пресеты по `TargetSpec.GOOS` цели.
2. Гейт узлов для машины считает по её ядру: ОС — `TargetSpec.GOOS`, версия — кэш паспорта демона (`build.CoreVersionForTarget`). Теги сборки ядра машины лаунчеру неизвестны (паспорт их не несёт) — гейт по тегу и проба цепочек для машины не применяются: не деградируем по догадке, та же политика, что при неизвестной версии.
3. `@vars` для машины берутся из её Settings (`model.SettingsVars`), затем умолчание шаблона.
4. Локальная сборка не меняется: при пустой цели работают прежние пробы и прежний файл состояния.
5. Никаких глобалов «текущая цель»: окна Конфигуратора разных целей открыты одновременно (SPEC 178).

## Критерии приёмки

- Именованный тест: при цели linux (на любой ОС запуска) kTLS-ключ узла остаётся, при цели darwin — снимается; `@urltest_interval` берётся из переменных цели, а не из локального `state.json`; пресет с `platforms` цели остаётся, чужой — отфильтрован.
- `go build ./...` проходит.

## Вне задачи

- Теги сборки ядра в паспорте демона (`/admin/info` форка) — тогда гейт по тегу для машины станет точным.
- Превью узла во вкладке JSON источника (`TailscaleBuildAdditions`, `EmitNodeJSONsFor` из окна) — показывает гейт локального ядра.
