# SPEC 177 — Двойное копирование: буфер на телефон без окна

Владелец 03.11.2026: «Send text…» — сложно; «команд + с 2 раза и все».
Опора — SPEC 176 (служебные файлы), контракт `docs/SERVICE_FILES.md` §7.

## 1. Жест

Текст, скопированный дважды подряд (Cmd+C на macOS, Ctrl+C на Windows) —
два изменения системного буфера с одним и тем же текстом не дальше 1 с друг от
друга — уходит служебным файлом `clipboard` на отмеченные устройства. Третье
копирование подряд жест не повторяет: нужна новая пара.

Лаунчер опрашивает счётчик изменений буфера (macOS `NSPasteboard.changeCount`,
Windows `GetClipboardSequenceNumber`) раз в 150 мс, только пока есть отмеченные
устройства и своё ядро с Taildrop работает. Оба копирования между опросами —
счётчик вырос на 2 и больше — тоже жест. Linux — без жеста (счётчика нет).

## 2. Чувствительное

Окна показа нет, поэтому содержимое с пометкой чувствительности ОС не
отправляется никогда: macOS — типы `org.nspasteboard.ConcealedType` /
`TransientType` (менеджеры паролей, Связка ключей), Windows — формат
`ExcludeClipboardContentFromMonitorProcessing`. Контракт 1.1.156, §7 п.3.

## 3. Куда

Галка «Send double copy here» в меню `…` устройства (там же, где «Send
text…»; только своё ядро). Отмеченных устройств может быть несколько — текст
уходит на каждое, что сейчас в сети и принимает файлы. Хранится в
`settings.json` (`taildrop_double_copy`: тег узла, stable ID пира, имя), в
бэкап не идёт.

Итог — уведомлением: «Clipboard sent — Copied text sent to <устройство>» или
«Not sent — <причина>». Текст в журнал и уведомление не пишется.

Приём на телефоне — по его разрешению «буфер от <ПК>» (SERVICE_FILES §5).
