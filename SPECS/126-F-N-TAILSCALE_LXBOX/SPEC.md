# SPEC 126 · Tailscale и секции узла в LxBox: контракт на обе стороны

Статус: задачи лаунчера (§2) закрыты; приёмка §4 — за владельцем.
Ветка develop. Кросс-проектная задача: норма — `contract/docs/NODE_SECTIONS.md`
(**норма**, черновик снят волной 3 SPEC 127), задача мобильной стороне —
`contract/TASKS_LXBOX.md` `## 13` (**закрыта** релизом LxBox v2.23.2),
решения — D-101 → D-102 → D-103, форма записей приведена к общей D-107/D-109.
Здесь — что делает **лаунчер**, чтобы контракт стал общим, и чего он ждёт от
LxBox.

## 1. Что меняется

SPEC 121/122 сделали `servers[].sections` и Tailscale полем и поведением
**лаунчера** (BACKUP.md §2: «Поддержка: launcher», LxBox игнорирует молча).
Решение владельца 2026-09-13: Tailscale нужен и в LxBox, а значит секции
узла становятся **общей** конструкцией контракта, и обе стороны обязаны
одинаково их хранить, экспортировать, импортировать и собирать.

Предпосылка вне обоих приложений: **libbox AAR форка собран без tailscale**
(`sing-box-lx/cmd/internal/build_libbox/main.go:121-127`, блок
`// lx:begin no-tailscale`, решение владельца 2026-06-09 «tailscale =
клиенту не нужен»). Без пересборки AAR с `with_tailscale` (+ `ts_omit_*`,
как в апстримном `sharedTags`) узел на телефоне доедет только до гейта
`tailscale_core_unsupported`. Это решение по форку; цена — размер APK
(tailscale — самая тяжёлая зависимость libbox).

## 3. Чего ждём от LxBox (кратко; полностью — TASKS_LXBOX `## 13`)

Модель `sections` у свободных узлов; инъекция при сборке с `@self`/`@{self}`;
экспорт/импорт по NODE_SECTIONS.md §4–5 (в `rules[]` узловых правил нет,
слияние «файл замещает», перенумерация всей оси); Tailscale: приём
безадресного endpoint'а, `state_directory` в каталоге приложения при
эмиссии, гейт по сборке libbox, узел без `exit_node` вне Направлений, тип
`tailscale` в редакторе DNS-сервера, режим Tailscale в Add Server Wizard,
строки узловых правил на оси; корпус зелёный. Ответы на три вопроса
(TASKS `## 13` §«Вопросы»): AAR с tailscale — да/нет; форма — как в
документе или правки; версия 0.13.0.

## 4. Приёмка (обе стороны, один сценарий)

Бэкап с десктопа с узлом Tailscale и его связкой импортируется на телефон:
узел появляется с секциями, правило `@{self} network` встаёт на ось в том же
относительном месте, DNS-сервер и правило на `.ts.net` видны в списке DNS;
обратный экспорт с телефона и импорт на десктоп даёт узел с теми же
секциями. На стороне с ядром без тега узел не собирается, но состояние его
хранит и после обновления ядра он оживает без переимпорта.

## 5. Ответ LxBox (13.09.2026, сессия lxbox-f8)

- **А (AAR с `with_tailscale`)** — ждёт владельца форка. Два факта против
  немедленного «да»: F-Droid собирает libbox из исходников на своём
  buildserver с потолком джоба 3 ч (сборку x86_64 уже сняли 06.09 из-за
  него), tailscale — самая тяжёлая зависимость по времени сборки и размеру
  APK. Хранение, провоз и UI (13.2–13.7) от А не зависят и делаются при
  любом исходе.
- **Б (форма)** — правки приняты: форма секций = корневая форма бэкапа
  (D-102), см. L9 и NODE_SECTIONS.md §1. Остальная семантика §4–§5 принята
  без правок. Код `backup_section_record_dropped` покрывает два случая.
- **В (версия)** — да, 0.13.0 после реализации LxBox.
- Ведущая сессия LxBox назначится после решения по А.
- **Ведёт LxBox: сессия `lxbox-3d`** (13.09.2026; ответ от lxbox-f8 пришёл
  по ошибке маршрутизации, по содержанию в силе). Контракт забран их
  sync_contract.sh с develop на `b8a0682c`. Факты по AAR для владельца:
  два ABI собираются 73 мин, три ABI были 2 ч 45 мин (x86_64 снят 06.09),
  `libbox.aar` 116 МБ на все ABI, замера сборки с `with_tailscale` нет.
  Ждут от лаунчера: L9 (корневая форма в экспорте) и кейсы корпуса §8 —
  прогонят своим раннером.
- **А решён: ДА** (13.09.2026, по сообщению lxbox-3d — решение владельца
  форка): libbox AAR собирается с `with_tailscale` + `ts_omit_*`
  (восстановление апстримного append из блока `lx:no-tailscale` в
  `build_libbox`). Замер времени сборки под потолок F-Droid и прирост AAR
  снимут при первом пересборе. Tailscale на телефоне — полноценный, не
  провоз. D-103.
