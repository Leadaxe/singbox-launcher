## 1. Цель

Состояние переезжает на схему v7: плоский корень
`sources[] / directions[] / rules[] / dns_options / vars / warp_accounts / meta`,
полиморфное дерево источников (Server / Chain / Auto / Folder / Subscription),
материализованные узлы подписок (`nodes[]` с body + origin). Разбор тела
подписки происходит один раз — при fetch; сборка конфига подписки не парсит:
эмиссия из body, тег-политика на эмиссии, единый резолв NodeLink, единый гард
тегов, правило пула Направлений. Старое состояние v6 переносится миграцией
строго по `features/state.md` §«Миграция v6 → v7» — с единым отчётом потерь,
без молчаливых.

## 3. Требования

### Т1. Схема диска v7

- Корень плоский: `sources[]`, `directions[]`, `rules[]`, `vars[]`,
  `dns_options`, `warp_accounts`, `meta`. Обёртки `connections` нет.
  `meta.version = 7`. Легаси-ключи (`connections`, `outbounds` источника,
  `defaults`, `disabled_nodes`, `fold`, `exclude_from_global`,
  `expose_group_tags_to_global`, `tag.mask`, `preview_nodes`) система
  только читает — в миграции; писать их некуда.
- `directions[]` — сегодняшние `configtypes.Direction` без изменений
  формы записи (глобальные Направления SPEC 104); локальных Направлений
  источника в схеме нет.
- `warp_accounts` — независимая корневая секция, переносится как есть;
  удаление WARP-узла кеш не трогает (правило модели, не сирота).
- Roundtrip: `Load(f) → Save(p1) → Load(p1) → Save(p2)` даёт `p1 == p2`
  побайтно на любом v7-состоянии.
- `Defaults{Reload,MaxNodes}` в state не существуют: умолчания живут в
  настройках приложения (`bin/settings.json`). Резолв: у `max_nodes` —
  настройка подписки → дефолт настроек (двухступенчатый: заголовка
  провайдера не существует); у интервала обновления — настройка подписки →
  заголовок провайдера (`profile-update-interval`) → дефолт настроек.

### Т2. Типы дерева источников

- `Source` — элемент `sources[]`, дискриминатор
  `kind ∈ {server, chain, auto, folder, subscription}`; всякий Source несёт
  `enabled`. Точная Go-форма — PLAN §1; инварианты формы (какие поля у
  какого kind легальны) валидируются на Load: лишние поля отбрасываются с
  warning, неизвестный `kind` — внятный отказ загрузки.
- `Node.tag` — СЫРОЙ тег, идентичность в рамках контейнера, снятый до
  тег-политики. На нём живут merge-ключ, `enabled`, `detour`, ссылки
  NodeLink. Финальный конфиг-тег = `prefix + tag + postfix` вычисляется на
  эмиссии; у корневых узлов политики нет — финальный тег = сырой; сырой тег
  корневого узла уникален в корневом пространстве тегов.
- `Server{body json.RawMessage, detour *NodeLink}` — эмиссия отдаёт body;
  body чист от detour (никакого запекания `Outbound["detour"]`).
- `Chain{hops []NodeLink}` — ближний хоп первым; detour у Chain НЕ
  существует (типом).
- `Auto{groupType selector|urltest, default?, members []NodeLink,
  strategy AutoStrategy}` — detour у Auto НЕ существует (типом);
  импортированный selector остаётся selector'ом; `default` только у
  selector, обязан входить в состав. `AutoStrategy` — перенос сегодняшнего
  `configtypes.DirectionAuto` (9 полей, включая TemplateInt-tolerance и
  трёхзначный interrupt; strategy-К1) без изобретательства.
- `Folder{id, name, tagPolicy, detour?, nodes []Node, replace?}` —
  `id` — единственная идентификация папки; вложенных папок нет.
  Общий detour папки применяется к Server-узлам без личного и
  ПРОПУСКАЕТ Chain и Auto.
- `Subscription` — папка с внешним владельцем состава: `url`, `skip[]`,
  `max_nodes`, `update` (расписание), `meta` (SubMeta: заголовки
  провайдера, userinfo, announce), `updateStatus` (диагностика fetch:
  последняя ошибка, даты попыток/успехов, статусы достоверности,
  truncated). UI и отчёт сборки читают диагностику из состояния — ничего
  не перепарсивается.
- `TagPolicy{prefix, postfix}` — маски нет; переменные
  `{$tag} {$scheme} {$protocol} {$server} {$port} {$label} {$comment} {$num}`
  в prefix/postfix живут (RECON).
- `Origin{kind uri|wgIni|json, raw, subUrl?}` — kind `warp` НЕ заводится
  (warp-К1); raw — байт в байт, правится только явным Regen и освежением
  merge. У узлов ВНУТРИ своей подписки `subUrl` не хранится (контейнер и
  есть связь); `subUrl` штампуется при копировании узла наружу (механика
  копий — этап 3, но правило формы фиксируется сейчас). Origin у Auto
  допустим (kind=json, диагностика; синтезированные Xray-группы —
  origin=null), Regen для Auto отключён.
- `NodeLink{folderId?, tag}` — folderId задан → узел папки по сырому тегу;
  folderId пуст → корневое пространство финальных тегов.

### Т3. Fetch: скачать → разобрать → слить

- Fetch — единственное место разбора тела подписки. Стадии в порядке
  применения к каждой записи (features/sources.md «Подписка: fetch»):
  1. `skip[]` — отсечка до рождения узла; правка skip действует со
     следующего обновления;
  2. дедуп по подписи полной эмиссии (без тега и detour) — `dedupSignature`
     остаётся fetch-стадией ДО merge (регресс v1.5.2 не возвращается);
     члены групп перепривязываются на выжившего (`collapsedInto`);
  3. уникализация сырых тегов внутри тела (`X`, `X-2`);
  кап `max_nodes` ограничивает число ПРИНЯТЫХ узлов по ходу стадий 1–3 —
  реальный предел парса, не бейдж; резолв: настройка подписки → дефолт
  настроек приложения; аварийный потолок-константа
  (`MaxNodesPerSubscription = 3000`) остаётся сверху; достижение капа =
  `truncated` в updateStatus.
- Merge в `nodes[]` по сырому (уникализированному) тегу: совпавший —
  body/origin освежаются, `enabled`/`detour` живут; новый — добавляется
  включённым; исчезнувший — удаляется (цена задекларирована). Порядок
  `nodes[]` после merge = порядок свежего тела провайдера.
- Fetch НЕ штампует detour в body (`ApplySourceDetour`-запекание умирает);
  исключения (wireguard+listen_port, Xray Jump) переезжают в
  эмиттер/резолв.
- Auto-члены при fetch резолвятся в NodeLink на узлы той же подписки по
  сырым тегам; вложенная группа-член теряется с warning (не молча);
  группа без тега — skip; пустая группа не рождается.
- Битая запись тела — деградация записи с warning, не подписки.
- Охрана SPEC 113-A: недостоверный ответ (ошибка сети, пустое тело,
  оборванный разбор) не трогает `nodes[]` вообще. Truncated-разбор
  достоверен В ПРЕДЕЛАХ капа: обновить и добавить можно, удалять
  «исчезнувших» — запрещено.
- Подписка, ни разу не сфетченная (`nodes[]` пуст, успехов нет) — warning
  в отчёте сборки, не отказ; `ErrRawCacheIncomplete`-строгость умирает.
  Свежедобавленная подписка авто-фетчится сразу (как сегодня).
- Per-record деградации fetch (skip-статистика, битые записи, потерянные
  группы-члены) персистятся в `updateStatus` — отчёт сборки и UI читают
  их из состояния (замена parse-стадии двухфазного отчёта «Итога»,
  jsontab-К4).

### Т4. Дирти-модель

- «Конфиг устарел» (любая правка модели → нужна пересборка, без сети) и
  «пора обновить подписку» (расписание/ручной запрос → fetch) —
  независимые признаки. Правка модели никогда не запускает fetch;
  пересборка никогда не требует сети.

### Т5. Эмиссия, резолв, гард, пул

- Сборка не читает тел подписок и не зовёт парсеры по подпискам: эмиссия
  узла = body (Server), построение по hops (Chain), selector/urltest по
  members (Auto). Эмиттеры per-scheme остаются для Regen/превью
  фрагментов — но не в конвейере сборки подписок.
- Тег-политика применяется на эмиссии; глобальная уникализация финальных
  тегов между источниками (`MakeTagUnique`) — на эмиссии, в состоянии не
  хранится.
- Единый резолв NodeLink, топологический (цель раньше ссылающегося):
  - detour и хопы — fail-closed: нерезолвящаяся/выключенная/недоступная
    цель = деградация носителя с ⚠, кольца fail-closed;
  - члены Auto — prune с warning; эмиссия Auto сама фильтрует выключенных;
    Auto без членов не эмитится + warning; `default` вне состава снимается
    с warning;
  - резолв видит replace-теги наравне с узлами.
- Detour: только у Server; папочный общий detour — Server-узлам без
  личного, пропуская Chain/Auto; исключение ядра — detour не применяется
  к WireGuard-узлам (правило модели).
- FolderReplace: `{mode manual|auto|both, tag явный, strategy?}`;
  `both` = селектор + авто-двойник `<tag>-auto` (переиспользование
  buildTwin); пул замены — вся папка; авто-состав исключает Auto-узлы
  папки (dropGroupNodes); селекторная половина наследует опции
  `group_templates.channel` (в т.ч. interrupt), default = двойник при
  both; собственных селекторных полей у replace нет.
- Пул кандидатов Направлений: верхние узлы + узлы папок без replace (под
  финальными тегами) + replace-теги папок с replace — и ничего кроме.
  Механизмы WIZARD-маркеров и `ExposeGroupTagsToGlobal` умирают. Твины
  Направлений исключают групповые кандидаты (Auto-узлы и replace-теги).
- Единый гард занятости тегов на сборку и операции именования: теги
  Направлений + твины + replace-теги + `-auto`-двойники + верхние узлы +
  системные теги шаблона. `rule_target_reset` включает все эти виды в
  known (иначе первая загрузка сбрасывает живые правила на direct).
- `dns.detour` — полноправное ребро граф-санитайзера и known-реестра
  (правило build-graph-sanitizer: новое ребро — в общий проход).
- Валидация в форме остаётся рубежом (`sing-box check` старт-ошибок не
  ловит — chain-check-misses-start-errors).

### Т7. Миграция v6 → v7

Строго 8 шагов `features/state.md` §«Миграция», один раз при первой
загрузке старого состояния, пока raw-кэш жив:

1. материализация `nodes[]` из raw-кэша (кэша нет → `nodes[]` пуст, карты
   отбрасываются с warning);
2. карта выключенных → `enabled=false` по identity-ключам (legacy-64hex
   докручиваются тем же проходом; несматченные — warning);
3. `NodeTagOrLabel`/mask server/chain → `Node.tag`; маска-шаблон подписки —
   warning;
4. `Chain.Hops []string` → `[]NodeLink` через живой индекс узлов;
   нерезолвящийся хоп → `NodeLink{null, старый-тег}` (fail-closed) +
   warning;
5. detour-тройня → NodeLink (источник-папка → folderId; верхний узел →
   голый тег); коллизии тегов верхних узлов: уникализация + перепись
   ссылок + warning;
6. fold → `replace` с МАТЕРИАЛИЗАЦИЕЙ вычисленного тега (включая
   позиционный дериватив `<index+1>:auto`/`:select` при пустом префиксе);
   локальные Направления: fold-производные → replace, произвольные —
   warning;
7. одиночный `exclude_from_global` — warning + запись в отчёт (узлы
   живут);
8. снос легаси (raw-кэш, карты, `connections`-обёртка, `defaults` → в
   настройки приложения) — только после успеха шагов 1–7.

Все потери — в один список предупреждений, показанный пользователю
(диалог отчёта миграции); молчаливых потерь нет. Миграция идемпотентна
(повторная загрузка v7 — no-op). Шаблонный сид легаси-формы
конвертируется тем же путём. Перед миграцией пишется бэкап-копия
исходного state-файла рядом (страховка необратимого шага 8).

### Т8. UI-компенсация (ровно объём)

- Превью узлов и счётчики источников читаются из материализованных
  `nodes[]` напрямую (три состояния ленивого кэша схлопываются — данные
  всегда есть); «not fetched yet» остаётся только как честное «nodes
  пуст и успехов не было» из updateStatus.
- Окно источника: вкладка JSON server-узла = прямой редактор body;
  «Reset to URI» → «Regen from raw» (разбор origin.raw пересоздаёт body;
  неразбираемый raw = ошибка и откат, узел не портится). Вкладка JSON
  подписки — синхронный показ body из nodes[] (read-only: узлы подписки
  несвободны).
- Overview: блок «raw body» умирает; вместо него счёт узлов + per-node
  origin.raw. Блок «Storage record» показывает canonical v7-запись.
- Пул хопов цепочек строится из материализованных `nodes[]` (не из
  PreviewNodes); кандидаты отдаются парами (folderId, сырой тег) /
  финальными тегами корня — под `[]NodeLink`.
- Вкладка Settings приложения: два поля умолчаний (reload-интервал,
  max_nodes), персист в `bin/settings.json`.
- Никакого нового UI папок; правило ui-visuals-approve-first: новые
  подписи/иконки не вводить, переиспользовать существующие.

### Т9. Бэкап — эмуляция 0.11 на границе

- Экспорт: v7 → форма 0.11: `node.enabled` → карта `sub.Disabled` по
  identity-ключам (сырым тегам); `replace` → `fold`; `NodeLink` detour →
  тройня; `hops []NodeLink` → строковые финальные теги; `TagPolicy` →
  `tag{prefix,postfix}` (mask не пишется); `Server.NodeTag` = `Node.tag`.
  Материализованные nodes[] в бэкап НЕ уезжают (0.11 их не несёт) — после
  импорта подписка фетчится заново.
- Импорт: обратные конвертации; mask: server/chain → `Node.tag`,
  подписка — warning; локальные Направления: fold-производные → replace,
  прочие — warning (бэкапы v1.5.x восстанавливаются без молчаливой потери
  маршрутизации); хопы-строки резолвятся по живому индексу, нерезолвящиеся
  → `NodeLink{null, тег}` fail-closed + warning; disabled-карта импорта —
  см. открытый вопрос O2.
- Контракт `contract/**` (0.11, корпус backup — 14 кейсов) не меняется;
  corpus_test остаётся зелёным без правки фикстур.
- `warp[]` бэкапа — как есть (однослотная перезапись — известная цена).

### Т10. Внешние поверхности

- Debug API отдаёт v7-форму (локальный интерфейс, не контракт).
- Remote: `/profile/copy-from`, `PATCH /state/rules`, `PATCH /state/dns`
  (локальные `state_endpoints.go` и remote-близнецы
  `remote_endpoints.go`) гейтуются по мажорной версии схемы состояния
  (= `meta.version`); несовпадение — внятный отказ с объяснением, не
  тихий рассинхрон.
- Секреты в состоянии — by design; не маскировать (memory:
  secrets-in-state-by-design).

### Т11. Совместимость сборки

go1.20 (win7-джоба): без `min`/`max`/`clear`/`slices`/`maps`/`PathValue`/
`errors.Join`; греп по диффу перед приёмкой.

## 4. Критерии приёмки (проверяемые)

### A. Grep-инварианты (прод-код, `*_test.go` исключены; читатели миграции v6→v7 — единственное исключение, помечены)

| disabled-карта снесена | `grep -rn "DisabledNodes\|GCDisabledNodes\|filterDisabledNodes" core ui` → 0 вне миграции и бэкап-конвертеров |

| exclude/expose снесены | `grep -rn "ExcludeFromGlobal\|ExposeGroupTagsToGlobal" core ui` → 0 вне миграции |
| mask снесён | `grep -rn "TagMask\|\.Mask\b" core ui --include=*.go` → 0 вне миграции и бэкап-конвертеров |
| локальных Направлений нет | у v7 `Source` нет поля Outbounds; `grep -rn "Sources\[i\].Outbounds\|localSubscriptionGroupTags" ui core` → 0 |

| сборка не парсит подписки | build-конвейер не вызывает `LoadNodesFromSourceEx`/классификацию тел для подписок (вызовы остаются только в fetch-сервисе, Regen и превью фрагмента) |
| обёртки connections нет | `grep -rn "ConnectionsSection\|\"connections\"" core/state` → только миграция |

### B. Миграционные сценарии (на реальных фикстурах)

Фикстуры: `core/state/testdata/v6_roundtrip.json` (существующая),
golden-state `real-v088`, плюс синтетические v6-фикстуры, покрывающие:
fold всех трёх режимов (в т.ч. с пустым префиксом — позиционный тег),
локальные Направления (fold-производные и произвольные с фильтрами),
disabled-карту с legacy-64hex ключами, mask у подписки и NodeTag у
server/chain, detour-тройню (на подписку и на верхний узел, включая
переходную форму без source_id), chain c хопами на узлы подписки и на
Направление, `exclude_from_global` без fold, state без raw-кэша.

1. **Материализация**: после миграции у подписки с raw-кэшем `nodes[]`
   непуст, body каждого узла эквивалентен эмиссии старого парса; у
   подписки без кэша `nodes[]` пуст + warning в отчёте.
2. **Отметки**: выключенные узлы получили `enabled=false` (в т.ч. по
   legacy-hex-ключам); несматченные ключи — в отчёте.
3. **Теги**: `NodeTag`/mask server/chain → `Node.tag`; mask-шаблон
   подписки — warning; переменные prefix/postfix сохранены.
4. **Хопы**: резолвнутые → корректные NodeLink (folderId узлов подписки);
   нерезолвнутый → `NodeLink{null, тег}` + warning + fail-closed на
   сборке.
5. **Detour**: тройня → NodeLink обоих видов; коллизия тегов верхних
   узлов уникализирована с переписью ссылок + warning.
6. **Fold → replace**: режимы 1:1; `replace.tag` = материализованный
   сегодняшний дериватив (включая `1:auto` при пустом префиксе);
   правила, ссылавшиеся на `1:select`, живут (не сброшены на direct).
7. **Потери**: `exclude_from_global` и произвольные локальные Направления
   — в едином списке предупреждений; список показан один раз.
8. **Снос и идемпотентность**: после успешной миграции raw-файлы и
   легаси-ключи отсутствуют; повторный Load v7 — no-op (Save байт-в-байт);
   при ошибке на шагах 1–7 исходный файл не тронут; бэкап-копия исходного
   state существует.
9. **Сид**: легаси-сид шаблона проходит тем же путём и даёт валидную
   v7-модель.
10. **Rule-reset не стреляет**: на мигрированном состоянии
    `resetForeignRuleTargets` не сбрасывает цели на replace-теги и верхние
    узлы (known расширен).

### C. Байт-эквивалентность конфига (golden)

- На golden `real-v088` (и `v6_roundtrip.json`): config.json, собранный
  текущим develop-движком из v6-состояния, побайтно равен config.json,
  собранному новым движком из мигрированного v7-состояния той же
  фикстуры. Любое расхождение — блокер: либо чинится, либо поимённо
  выносится капитану на утверждение (см. O3) с обоснованием в
  IMPLEMENTATION_REPORT.
- Golden-снимок `real-v088` перезафиксирован (state — v7-форма) и тест
  больше не SKIPPED по умолчанию.

### D. Fetch (поведенческие, unit/integration уровня fetch-сервиса)

1. skip-фильтр отсекает до рождения узла; отсечённый выпадает на merge как
   исчезнувший; правка skip без fetch не меняет `nodes[]`.
2. Дедуп по подписи схлопывает узлы, различающиеся только фрагментом
   (регресс-кейс v1.5.2: 32 ss:// → 1 узел); члены Auto перепривязаны на
   выжившего.
3. Дубли тегов `X, X-2, X` — оба узла живут (`X`, `X-2`, `X-3`).
4. `max_nodes=N` реально останавливает разбор на N принятых узлах;
   `truncated=true`; аварийный потолок 3000 сверху.
5. Merge: совпавший тег сохранил `enabled=false` и `detour` при свежем
   body; новый — enabled; исчезнувший — удалён.
6. 113-A: ошибка сети / пустое тело / обрыв разбора → `nodes[]`
   неизменны, ошибка в updateStatus. Truncated: удаления нет, обновление
   и добавление есть.
7. Никогда не фетчилось → сборка идёт, warning в отчёте.
8. Body материализованного узла не содержит ключа detour при наличии
   detour у источника.
9. Auto: члены-NodeLink на узлы своей подписки; вложенная группа — потеря
   с warning; selector сохранил type и default.

### E. Эмиссия и резолв (поведенческие)

1. Тег-политика: правка prefix папки меняет финальные теги БЕЗ смены
   merge-ключей, `enabled`, `detour`, ссылок hops/members (сырые теги
   нетронуты).
2. Detour fail-closed: висячий/выключенный/кольцевой — носитель
   деградирует с ⚠, не идёт напрямую; WireGuard-узел detour не получает.
3. Chain: хоп на replace-тег и на верхний узел легален; висячий хоп —
   fail-closed.
4. Auto: выключенный член отфильтрован эмиссией; пустой Auto не эмитится
   + warning; detour на Auto не существует типом (битый config из
   groups-К1 невозможен).
5. FolderReplace: manual → селектор по всей папке; auto → авто-группа;
   both → пара с `-auto`-двойником-умолчанием; Auto-узлы папки исключены
   из авто-состава; узлы свёрнутой папки эмитятся в outbounds и легальны
   целями ссылок.
6. Пул Направлений: свёрнутая папка представлена только replace-тегами;
   несвёрнутая — узлами под финальными тегами; верхние узлы — все.
   Твины исключают Auto-узлы и replace-теги.
7. Гард: Направление `x` + replace-тег `x` (или `x-auto`) — отказ
   операции/сборки с внятным сообщением, а не два `x-auto`.
8. dns.detour на несуществующий тег ловится санитайзером на сборке (не
   падением ядра).
9. Выключенное Направление не эмитится, его тег в known — правила не
   сброшены.

### F. Бэкап (roundtrip)

1. Экспорт v7 → файл 0.11 проходит контрактную схему; corpus-тесты
   зелёные без правки фикстур.
2. Экспорт→импорт на этой же машине: модель эквивалентна (enabled,
   replace, detour-NodeLink, hops; с точностью до задокументированных
   потерь конвертации).
3. Импорт бэкапа v1.5.x (фикстура с fold, локальными Направлениями,
   disabled-картой, mask): fold-производные → replace; произвольные
   Направления — warning; mask server/chain → tag; ни одна потеря не
   молчалива.

### G. Remote-гейт

`/profile/copy-from` и `PATCH /state/*` (обе стороны) при несовпадении
мажора схемы возвращают отказ с версиями в сообщении; при совпадении
работают как раньше.

### H. Roundtrip и ревизия

- v7 Load→Save→Load→Save байт-в-байт; `meta.updated_at` — единственная
  разница с исходником при пересохранении.
- ULID папок/подписок стабильны через циклы мутаций и Save/Load; узлы
  идентифицируются тегом (id у узлов нет).
- Ревизия модели (этап 1) продолжает расти на мутациях нового дерева;
  fetch-merge поднимает «конфиг устарел», не наоборот.

## 5. Открытые вопросы (капитану) — РЕШЕНЫ

Вердикты капитана (2026-08-30): **O1 = А** (корпус не трогаем, раннер
маппит fold-фикстуры на FolderReplace-эквивалент; правка корпуса — трек
folders[] с LxBox). **O2 = А** (`pending_disabled` у Subscription —
одноразовое поле, применяется по сырым тегам на первом достоверном fetch
и стирается; features/state.md дополнен — restore не теряет отметки).
**O3** — как сформулировано: любое расхождение golden — блокер до
поимённого вердикта капитана в IMPLEMENTATION_REPORT; классов
«допустимого» заранее не объявляется.

Исходные формулировки:

- **O1. Fold-фикстуры общего корпуса Направлений**
  (`contract/corpus/direction`: `auto_twin_excludes_group_nodes` и др. —
  нормативны для LxBox). Этап 2 убивает fold-механику в лаунчере;
  корпус трогать в одиночку нельзя. Варианты: (А) оставить фикстуры,
  раннер лаунчера маппит их на FolderReplace-эквивалент; (Б) согласовать
  правку корпуса с LxBox-стороной отдельным треком. Рекомендация: А на
  этап 2, Б — в трек folders[].
- **O2. Disabled-отметки при ИМПОРТЕ бэкапа**: nodes[] пусты до первого
  fetch — применять карту не к чему. (А) одноразовое поле
  `pending_disabled` у Subscription: применяется по сырым тегам на первом
  достоверном fetch и стирается (не TTL-карта, но новое хранимое поле —
  формально не описано в features/state.md); (Б) терять с warning, как в
  миграции без кэша (конвертер enabled↔disabled тогда работает только на
  экспорт). Рекомендация: А — иначе каждый restore теряет все отметки.
- **O3. Порог расхождений golden**: если байт-эквивалентность C упрётся в
  неустранимое порядкозависимое расхождение (глобальная уникализация,
  порядок опций групп) — нужен вердикт по каждому пункту списка;
  пустой список — цель.
