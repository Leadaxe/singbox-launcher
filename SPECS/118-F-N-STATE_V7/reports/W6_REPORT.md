# SPEC 118 · W6 «UI-компенсация» — отчёт

Волна закрывает Т8 полностью и три хвоста ревью предыдущих волн. Формальный
итог: интерфейс больше нигде не разбирает тела подписок и нигде не хранит
позицию цепочки строкой. Обе эти вещи в W5 остались наполовину — вторая
реализация разбора жила в окне источника, а хоп на узел папки терял папку на
первом же сохранении.

## 1. Что изменилось по существу

### 1.1 Вторая реализация разбора тел снесена

`ui/configurator/tabs/source_edit_window.go` держал СВОЙ парсер тела
подписки: `parseNodePoolFromBody` / `parseNodePoolFromBodyEx` /
`uniquifyPreviewTags` / `capNodePool` — ~120 строк, воспроизводивших
классификацию тела, дедуп, стемпинг идентичности и уникализацию сырых тегов.
После W5 вкладка Preview его уже не звала (она читает `nodes[]`), но код
остался и звался тестами — то есть выглядел живым.

Это ровно ловушка `emitter-parser-pairing` в обратную сторону: два разбора
одного тела расходятся на первой правке любого из них, и расходятся молча.
Снесён вместе с `preview_singbox_body_test.go` (предмет — чужой парсер, дом
которого `core/config/subscription/parse_body.go`; там же и покрытие:
`parse_body_test.go`, `singbox_import_test.go`, `xray_json_array_test.go`).

**Следствие, которое пришлось починить.** Вместе с парсером вкладка Preview
теряла ПРИЧИНЫ отбраковки (SPEC 115): «половина подписки протухла» она
получала из собственного разбора. Причины эти уже персистятся — Т3 требует
их в `updateStatus.warnings`, и fetch их туда пишет, — но вкладка их не
читала. Добавлен `fetchWarningTexts` (`source_meta_format.go`) в том же
формате, что у отчёта сборки (`build_report_feed.go`): адресация тегом узла,
счётчик у агрегируемых видов. Разъехаться этим двум поверхностям нельзя —
пользователь читает про одно событие в двух местах.

### 1.2 Позиция цепочки стала ссылкой

**Это был баг, а не недоделка.** `applyChainFormToSource` складывала позиции
так:

```go
hops = append(hops, wizardmodels.NodeLink{Tag: h})  // h — ФИНАЛЬНЫЙ тег
```

То есть любое сохранение окна цепочки превращало ссылку на узел папки
`{FolderID: "SUB1", Tag: "n1"}` в корневую `{"", "[NL] n1"}` — тег, за
которым в корневом пространстве никого нет. Цепочка деградировала
fail-closed на первой же пересборке, а форма при этом показывала её
здоровой. Мигрированные состояния (шаг 4 переносит хопы именно папочными
ссылками) ломались первым же открытием окна.

Переделано целиком:

| Было | Стало |
|---|---|
| `chainForm.hops []string` | `[]corestate.NodeLink` |
| `chainHopCandidate{Tag, Kind}` | `+ Link corestate.NodeLink`; `Tag` = финальный тег для показа |
| `lookup` по тегу | по `hopLinkKey(link)` = `folderID + "\x00" + tag` |
| `Collect() *SourceChain` (позиции = хранение) | `CollectLinks()` — для модели; `Collect()` — форма ЯДРА с развёрнутыми финальными тегами (для эмиттера/валидатора/превью JSON) |
| `chainFormFromSource` | `chainFormSettings` (только `body`) + `chainFormHops` (ссылки) |

Кандидаты собираются по правилу пула из features/directions.md: верхние узлы
(корневой ссылкой), узлы НЕсвёрнутых папок (парой `folderId` + сырой тег),
replace-теги свёрнутых (корневой), Направления, системные теги, другие
цепочки. Узлы свёрнутой папки не предлагаются вовсе — конфиг их тегов не
знает, и предложить их значило бы вести к fail-closed.

`chainReplaceTags` делегирует `config.FolderReplaceTags`, а не повторяет
формулу `<tag>` / `<tag>-auto`: разойдись они — форма предлагала бы позицией
тег, которого в конфиге нет.

Вкладка JSON (там позиция — строка `outbounds[i]`, другой адресации форма
ядра не знает) разворачивает теги обратно в ссылки через
`chainLinksFromTags` по кандидатам. Тег без кандидата остаётся корневой
ссылкой: пользователь вправе вписать цель, которой ещё нет.

### 1.3 Хвост W3 — write-back one-shot fetch

Ручное обновление подписки работает на снимке: снимок → горутина → запись
обратно. Обе точки (`triggerOneShotFetch` в окне источника,
`refreshOneSourceFromUI` в списке) писали `m.Sources[i] = snapshot` —
снимок ЦЕЛИКОМ. Пока горутина летит, пользователь вправе править ту же
запись: переименовать, сменить тег-политику, включить свёртку, нажать Save.
Запись снимка откатывала всё это к состоянию на момент старта fetch'а —
через две секунды после нажатия правка исчезала, и повода связать это с
обновлением подписки у пользователя не было.

`business/fetch_writeback.go` → `ApplyFetchSnapshot(m, snapshot, revAtStart)`:

- ревизия не менялась → снимок пишется целиком, как раньше (это ещё и
  сохраняет поля, о которых fetch-слой знать не обязан);
- ревизия выросла → заносятся ТОЛЬКО поля, которые fetch производит:
  `Nodes`, `UpdateStatus`, `Meta`, `PendingDisabled`. Остальное —
  собственность пользователя;
- источника больше нет → запись не выполняется вовсе (удаление осознанно,
  воскрешать его снимком нельзя).

Поиск по ID, а не по индексу: слайс мог реаллоцироваться.

Логика та же, что уже держит Save окна источника
(`mergeEditedSourceIntoModel`) — у fetch'а есть свои поля, и только их он
вправе занести.

### 1.4 Хвост W2 — отчёт миграции на диск

Отчёт жил только в памяти `State`, и до пользователя не доезжал в самом
частом сценарии: мигрирует ПЕРВЫЙ, кто откроет состояние, а на старте
лаунчера это фоновая загрузка без единого окна. К моменту открытия
конфигуратора файл уже v7 — миграции для него не существует, отчёта нет ни
у кого, а потери уже произошли.

- `Load` зовёт `PersistMigrationReport(lc.BinDir, s.Migration, path)` →
  `bin/migration_report.txt`;
- запись ДОПИСЫВАЕТ: за один запуск мигрируют локальное состояние и профили
  удалённых машин, перезапись показала бы только последний. Каждый отчёт со
  своим заголовком-путём и версией схемы;
- `maybeShowMigrationReport` показывает ОБА источника в одном диалоге (из
  памяти — если миграция случилась прямо на этой загрузке; с диска — если
  раньше) и снимает файл после показа;
- ошибка записи не фатальна: строки уже в логе.

`features/state.md` §«Миграция» дополнен той же правкой.

### 1.5 Хвост W3 — мостовая Meta

Проверено: противоречие «Meta штампует `ok` при недостоверном теле, а
`UpdateStatus=err`» умерло вместе с мостовой Meta.

- статус пишется ТОЛЬКО в `SubUpdateStatus` и только двумя функциями:
  `successSubStatus` (зовётся на достоверном merge) и `failedSubStatus`;
  третьего писателя `LastStatus` в прод-коде нет;
- заголовки провайдера живут в `SubMeta` и статуса не несут;
- `sourceDiag` (`source_meta_format.go`) держит обе половины раздельными
  указателями — склеить их обратно нечем.

Добивать нечего.

### 1.6 Настройки приложения: два умолчания

`ui/settings_tab.go` → `buildSubscriptionDefaultsBlock`: поля Default update
interval и Default max nodes, персист в `bin/settings.json` через
`locale.LoadSettings`/`SaveSettings` (load-mutate-save — не «свежая
структура», которая вытирала бы соседние поля). Резолв в W3 уже был; здесь
только UI.

Ступенчатость показана подсказками, а не новыми виджетами: у интервала три
ступени (своя настройка → заголовок `profile-update-interval` → это поле),
у капа две (провайдерского заголовка не существует). Разница не
косметическая — она объясняет, почему подписка может обновляться не так, как
здесь написано, а количество узлов — ровно так. Плейсхолдеры несут встроенные
умолчания (`1h`, `3000`), чтобы «пусто» не читалось как «ноль».

Дебаунс 500 мс (тот же приём, что у поля User-Agent): без него «4h» дало бы
две атомарные перезаписи, из которых первая ещё и с невалидным «4». Ошибка
ввода — строкой под полями, не диалогом: модальное окно на каждый
недописанный символ поперёк ввода. `setErr` обёрнут в `fyne.Do` — таймер
дебаунса работает на своей горутине.

### 1.7 Предупреждение о протухании cache.db

`source_tag_shift_warning.go` — снимок формы тегов на открытии окна
(`tagShapeOf`), сравнение на сохранении (`staleSelectionAfterEdit`):

- сменились `prefix`/`postfix` → переименован КАЖДЫЙ узел контейнера:
  протухает выбор члена в любой группе, куда они входят;
- сменился состав replace-тегов (тег, режим, появление/исчезновение
  свёртки) → протухает выбор в самой группе, при `both` — и у
  `-auto`-двойника.

Названы теги СТАРОЙ формы: именно их помнит кэш. Включение свёртки с нуля
предупреждения не даёт — кэш этих тегов ещё не видел.

Показ — существующим механизмом: тот же информирующий диалог, что у сброса
detour-ссылок при переименовании узла (`showDetourRefsResetDialog`).
Отменять нечего: правка сохранена, а выбор в cache.db не наша
собственность — у Remote-машины он вообще на другой машине, о чём текст и
говорит.

Правки, не трогающие финальные теги (URL, skip, подпись, галки узлов),
предупреждения не дают: диалог на каждое сохранение приучают закрывать не
читая.

### 1.8 Прочая компенсация Т8

- **Overview.** Ранний выход был по `Kind == server`, поэтому цепочка, папка
  и Auto попадали в подписочную ветку и получали «No meta yet — press
  Refresh to fetch this subscription» — подпись, отправляющую искать кнопку,
  которой у них нет. Теперь выход по `Kind != subscription`, и этим видам
  показывается их состав (счёт узлов + per-node `origin.raw`). Строка Type
  берёт подпись из `sourceKindLabel` — видов пять, и называть цепочку
  подпиской нельзя. Комментарий блока Storage record («canonical v5») —
  на v7.
- **Мёртвое поле маски.** W5 оставил `maskEntry` с пометкой «удаление —
  предмет W6»: поле создавалось, дизейблилось и НИ В ОДИН layout не
  добавлялось. Снесено. Заодно снят комментарий, утверждавший, что
  `exclude_from_global` «остаётся в состоянии и читается» — поля нет с W5.
- **Мёртвый raw-код.** `source_edit_raw.go` (константа `rawBodyMaxDisplay`)
  и `readRawBodySmart` / `rawBodyFullReadLimit` / `wrapLongLines` /
  `openInFileManager` из Overview — остатки чтения `bin/subscriptions/*.raw`.
  Кэша нет с W5; ни один вызов не жил.
- **Кап вкладки JSON стал честным.** `previewNodeCap` после сноса парсера
  ни на что не влиял, но статус-строка продолжала обещать «(showing first
  200)». Теперь `renderUnpackedNodes` реально обрезает ВЫВОД (не состав) и
  говорит об этом, только когда обрезала; счёт узлов — полный. Вкладка
  Preview кап не получает: она рисует `widget.List` с виртуализацией, и
  обрезка прятала бы от пользователя половину его собственных галок.
- **Правка тела вынесена из Fyne-замыканий.** `source_body_edit.go`:
  `applyServerBodyJSON` и `regenServerBodyFromRaw`. Обе ничего не мутируют
  до успеха — ошибка это ОТКАТ, — и обе идут через единственную точку
  материализации `config.MaterializeServerNode` (ту же, что зовут fetch и
  миграция).

## 5. Замечания следующим волнам

- **W7.** Позиции цепочек теперь честные `NodeLink` на обеих сторонах формы —
  конвертер бэкапа «хопы ↔ строковые финальные теги» (Т9) обязан
  разворачивать папочные ссылки через живой индекс узлов, а не брать
  `hop.Tag` как есть: у узла папки это СЫРОЙ тег, и в контракт 0.11 он уедет
  под именем, которого в конфиге нет.
- **W7.** `pending_disabled` теперь переносится write-back'ом fetch'а
  (`applyFetchResultFields`) — импортный сценарий O2 сквозной.
- **Этап 3 (UI папок).** `chainFolderIDsBySourceIndex` уже различает
  свёрнутую папку (узлы не адресуются) и обычную; пикер хопов готов
  показывать узлы папок, как только папки появятся в UI.
- **Открыто (капитану), не блокер.** `defaultReplaceTag` при пустом префиксе
  даёт позиционный `<index+1>:select` — тот же дериватив, что материализовала
  миграция. Позиция берётся из индекса источника В МОДЕЛИ, поэтому у НОВОЙ
  свёртки после перестановки источников тег будет другим. Для мигрированных
  это не важно (у них тег уже материализован явно), но как формула умолчания
  для новых свёрток позиционность — наследие упразднённой механики. Стоит
  обсудить замену на имя источника; правка тривиальная, но это изменение
  видимого пользователю умолчания, и решать его в одиночку я не стал.
