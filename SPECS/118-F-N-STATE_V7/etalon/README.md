# Эталоны старого движка (SPEC 118, сняты в W2 — ДО W4)

Назначение: приёмка W8 §4.C — байт-эквивалентность сборки нового движка
(эмиссия из материализованных `nodes[]`) сборке текущего develop-движка
(парс raw-кэша на каждой сборке). Сняты в волне W2, пока старый движок жив.
Любое расхождение при сверке в W8 — блокер: поимённый список на вердикт
капитана (открытый вопрос O3), не подгонять молча. **O3 закрыт вердиктом
капитана 2026-08-29** — расхождения разобраны поимённо ниже (real-v088) и
в разделе `v6mig/` (Р2).

## real-v088.config.json

Полный config.json сценария `core/build/testdata/golden/real-v088/`,
собранный текущим движком (`GOLDEN_RUN_REAL=1 go test ./core/build -run
TestGoldenScenarios`, снят 2026-08-29, HEAD develop до правок W2; той
переменной окружения больше нет — real-сценарии прогоняются всегда, см.
вердикт ниже).
Отличается от закоммиченного `expected.config.json` сценария ровно двумя
известными классами: снятый `dns.independent_cache` (deprecation sing-box
1.14; раннером НЕ нормализуется — на нём падала и сверка с тогдашним
`expected.config.json`, предсуществующее) и косметические `// комментарии`
перед узлами
(эти раннер нормализует). Для W8 эталон — ЭТОТ файл (сырой выхлоп
движка), сравнение без нормализаций; расхождение со старым
expected.config.json — не предмет W8.

### Известные расхождения real-v088 — вердикт капитана (2026-08-29, O3 закрыт)

Сверка эталона с выхлопом нового движка дала два расхождения секции `dns`
(разбор — `IMPLEMENTATION_REPORT.md` §7.3). Вердикт по каждому:

**Р-DNS-1 — порядок `dns.servers`. ПРИНЯТ. Расхождение остаётся.**
Тот же набор из пяти серверов в другом порядке:
`[local, direct, cloudflare_udp, google_doh, yandex_doh]` в эталоне против
`[direct, google_doh, yandex_doh, local, cloudflare_udp]` у прод-пути.
Множества совпадают полностью — 0 лишних, 0 недостающих; потери нет,
порядок `dns.servers` sing-box не трактует. Причина — раннерный артефакт
снятия эталона: эталон снимался легаси-путём v5, где `MergeDNSSection`
перезаписывает `dns.servers` списком из состояния и тем сохраняет его
порядок; боевой путь v6+ дописывает серверы состояния через
`MergePresetsIntoDNS` после шаблонных. Это разница ДВУХ ПУТЕЙ СНЯТИЯ, а не
разница движков: при неизменённом раннере сборка нового движка из
v4-фикстуры совпадает с эталоном байт-в-байт.
**Следствие:** сверять real-v088 с этим эталоном как есть — значит вечно
видеть эту дельту. Живой рубеж регрессии — golden-сценарий
`core/build/testdata/golden/real-v088/`, чей `expected.config.json`
перезафиксирован честным выхлопом прод-пути (W8, после вердикта) и
сравнивается строго, без исключений и без переменной окружения.

**Р-DNS-2 — снятый `rule_set: "ru-domains"` у DNS-правила. ПОЧИНЕН.
Расхождения больше нет.**
Предсуществующий прод-баг, не регрессия кампании: чистка висячих
`rule_set`-ссылок судила по НЕПОЛНОМУ множеству известных тегов —
`collectRuleSetTagsFromPresets` обходила только правила `RuleKindPreset`,
а `ru-domains` объявлен прямо в `route.rule_set` шаблона. Ссылка живая,
просто не увиденная — и DNS-правило молча теряло ограничение по
российским доменам, начиная матчить весь трафик. Чинён в
`core/build/preset_merge.go`: `collectRuleSetTagsFromPresets` заменена на
`CollectEmittedRouteRuleSetTags`, которая перечисляет ВСЕ источники
`route.rule_set` (теги шаблонной route-секции, легаси-путь
`RouteConfig.Rules`, и всё, что эмитит `ResolveRouteWithGlobals` — любого
kind'а, по тем же условиям, что и `MergePresetsIntoRoute`). Множество
считается один раз до обхода секций (`core/build/build.go`,
`buildOrderedSections`), потому что секция `dns` собирается раньше
`route`. Чистка при этом сохранена: действительно висячая ссылка снимается
по-прежнему — иначе ядро падает на
`initialize DNS rule[N]: rule-set not found`. Обе стороны держит
`core/build/dns_ruleset_dangling_test.go`.

## v6mig/

Фикстура «v6-состояние с raw-кэшем» (v6_roundtrip-подобная: подписка с
префиксом/постфиксом/skip/fold select_auto/disabled-картой, server с
detour-тройней на узел подписки, chain с хопами на верхний узел и узел
подписки, правила на fold-теги `[P]select`/`[P]auto`, defaults):

- `state.json` — входное v6-состояние;
- `01J00000000000000000000SUB.raw` — raw-тело подписки (URI-список:
  дубль тега `NL-1` → уникализация, байтовый дубль ss → дедуп по подписи,
  `RU-1` → skip-фильтр);
- `outbounds.snapshot.json` — ЭТАЛОН: outbounds/endpoints, эмитированные
  текущим движком из raw-кэша (`buildSnapshotFromRawCache`, без сети, без
  шаблона).

Снимается/сверяется тестом `core/etalon_v6mig_capture_test.go`:
`ETALON_V6MIG=1` — сверка (W8), `ETALON_V6MIG=capture` — перезапись
(использована один раз в W2; после W4 не перезапускать — это сравнило бы
новый движок с самим собой).

Почему уровень эмиссии, а не целый config.json: SPEC 118 меняет ровно слой
«тело подписки → outbound-объекты»; слой BuildConfig (шаблон/route/dns)
кампания не трогает, и он закрыт полноформатным эталоном real-v088.
Байт-равенство снимка эмиссии + нетронутый BuildConfig ⇒ байт-равенство
config.json.

### Известное расхождение, внесённое самой W2 — Р2, ПРИНЯТО (вердикт O3)

Миграция fold mode=both материализует пару тегов как
`<selectTag>` + `<selectTag>-auto` вместо прежней `<PFX>select` + `<PFX>auto`
(модель `<tag>-auto` не выражает старую пару; PLAN §5 шаг 6, риск Р2) — со
переписью всех ссылок и предупреждением пользователю. Поэтому сверка
`ETALON_V6MIG=1` на этой фикстуре уже с W2 даёт ровно ОДНО расхождение:
`[P]auto` → `[P]select-auto` (тег авто-группы; состав и опции идентичны).
Это задекларированная цена Р2. **Вердикт капитана 2026-08-29: ПРИНЯТ**
(принят ещё в W2, подтверждён при закрытии O3) — эталон НЕ
перезафиксирован, расхождение остаётся ожидаемым и задекларированным.
Других расхождений быть не должно: `ETALON_V6MIG=1` обязан давать ровно
эти три строки (сам тег и две ссылки на него — `default` селектора и
запись в его `outbounds[]`), любое четвёртое — регрессия.
