# SPEC 113 — Фиксы аудита v1.5.0→develop

Статус: решения приняты пользователем 27.08.2026, пофразовый разбор в сессии
аудита. Аудит: 6 критических, 7 серьёзных, 14 мелких находок (артефакт
«Аудит v1.5.0 → develop»). Этот SPEC покрывает блоки A/B/C/E. Блок D
(бэкап = сериализация стейта, контракт 0.11.0) — отдельный SPEC 114.

## Принятые решения (нормативно)

1. **Единственный ключ дедупа во всём парсере** — подпись содержимого:
   sha256(канонизированная эмиссия узла БЕЗ полей tag/detour). Эмиттер
   получает режим «голый JSON» (без комментария-имени и запятой) — хирургия
   строк с поиском `{` удаляется. Xray-ownership переезжает на эту же
   подпись; ключ по кредам (`схема|сервер|порт|креденшл`) умирает совсем.
   Хеши для узлов, где подпись считалась раньше, обязаны совпасть байт в
   байт (миграция legacy-ключей).
2. **Нет достоверного ответа от подписки — состояние не меняем.** Формулировка
   пользователя. Любые выбрасывания (миграция disabled-ключей, GC, будущие
   чистки) — только по разбору, которому верим: успешный сетевой фетч,
   непустой список узлов. Перепись совпавших ключей безопасна всегда.
3. **Detour = управление анонимностью, не балансировка. Всегда: ⚠ и носитель
   недоступного перехода скипается.** Единая строгость для всех видов целей
   (узел, селектор шаблона, группа); мягкое правило SPEC 077 УПРАЗДНЕНО.
   Гранулярность = носитель: source-detour → выпадает источник;
   node-detour → скипается узел; хоп цепочки → выпадает цепочка.
   Резолв — в топологическом порядке (цель раньше ссылающегося), выпадение
   каскадирует, кольцо = fail-closed всех участников с причиной.
   Санитайзеру запрещено «спасать» detour снятием ключа.
4. **Массив правил в файле всегда отсортирован по оси.** Двойной порядок
   (файловый vs ось) упраздняется как источник багов: очередь безымянных
   строится в порядке оси; после любой перенумерации массив
   пересортировывается; сохранение поддерживает инвариант.

## Части

- SPEC-A: парсер и дедуп (критические 2, 3, 5; серьёзные M1, M2).
- SPEC-B: граф detour (критическая 4; серьёзная M3).
- SPEC-C: ось порядка правил (критическая 6; серьёзная M7; минор movedPos==0).
- SPEC-E: UI (серьёзные M4, M5, M6; миноры).

Критическая 1 (импорт бэкапа затирает тег цепочки) НЕ чинится точечно:
она умирает вместе с механизмом extensions в SPEC 114.
