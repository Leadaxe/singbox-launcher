# SPEC 113-A — Парсер и дедуп

Закрывает находки аудита: C2 (Xray-транспорты), C3 (`{` в имени), C5
(миграция отметок при пустом разборе), M1 (группа теряет членов), M2
(коллизия identity `X-2`).

## 1. Эмиттер: режим «голый JSON»

`GenerateNodeJSON` / `GenerateEndpointJSON` (core/config) получают вариант,
возвращающий ЧИСТЫЙ JSON-объект узла: без строки-комментария с именем, без
хвостовой запятой, без табов обёртки. Сборка config.json зовёт как раньше;
подпись и миграция — голый режим.

- `decodeEmittedOutbound` (core/config/node_hash.go:147) удаляется целиком —
  вместе с классом бага «первая `{` найдена внутри имени».
- `LegacyNodeIdentityHash` переходит на голый режим: канонизация
  (существующая `marshalCanonicalJSON` — рекурсивная сортировка ключей,
  значения и порядок массивов не трогаем) → вырезать `tag`/`detour` → sha256.
- **Ловушка: стабильность хешей.** Для всех узлов, где подпись считалась
  раньше, sha256 обязан совпасть байт в байт (старые disabled-ключи и
  detour_node_hash находят свои узлы). Пин:
  `TestLegacyNodeIdentityHashStillReproducible` остаётся зелёным БЕЗ правок
  ожидаемых значений. Новое поведение только у имён со скобками: раньше
  «подписи нет», теперь честный хеш — запиновать отдельным тестом
  (имена `SG {премиум} 1`, `}{`, `{"json":1}`), с комментарием, что их
  старые отметки не находятся by design (старые версии на них ломались
  так же).

## 2. Xray-ownership на подпись содержимого

`xrayServerKey` (core/config/subscription/xray_json_array.go:325) →
подпись содержимого (та же `dedupSignature`). `buildServerConnKey`
(server_conn_key.go:49) удаляется — потребителей не остаётся.

- Семантика восстанавливается к v1.5.0: «страна» и пул «Авто» с
  байт-идентичным сервером схлопываются; grpc/xhttp одного сервера
  выживают оба.
- Тесты: (а) двухэлементный массив, один сервер+uuid, network grpc/xhttp →
  2 узла; (б) страна+пул с байт-копией → узел у страны, пул ссылается;
  (в) `TestXrayServerKeyPicksCredential` переписать/удалить по новой
  семантике.
- **Ловушка:** подпись зовёт эмиттер через хук
  `LegacyNodeIdentityHashFunc` — в тестах пакета subscription без импорта
  config хук nil (подпись пустая, ownership выключен). Тесты ownership
  обязаны ставить хук (см. dedup_test.go, `withContentSignatureHook`) или
  жить в пакете, где config импортирован.

## 3. Мутации состояния — только по достоверному разбору

Правило (пользователь, 27.08): «нет достоверного ответа (не прочитали
подписку) — не меняем состояние».

- `migrateLegacyDisabledKeys` (source_loader.go:232): ВЫБРАСЫВАТЬ
  несовпавшие legacy-ключи можно только когда разбору верим — успешный
  сетевой фетч (или полное чтение живого кэша) И len(nodes) > 0 И ни один
  узел не отброшен капом `MaxNodesPerSubscription`. Иначе: переписать
  совпавшие (безопасно всегда), несовпавшие ОСТАВИТЬ КАК ЕСТЬ до
  следующего честного разбора; `DisabledMigrated` при этом не должен
  провоцировать персист урезанной карты.
- Признак «разбор достоверен» вычисляется там, где известен источник тела
  (фетч/кэш) — прокинуть в filterDisabledNodes/миграцию явным параметром,
  не глобальным флагом.
- GC (`GCDisabledNodes`) уже под этим правилом — свести оба под один
  комментарий-закон, чтобы будущие чистки его наследовали.
- Тесты: пустой разбор → legacy-ключи нетронуты; разбор с капом →
  нетронуты; честный разбор → мигрируют/выбрасываются как раньше.

## 4. M1: группа не теряет схлопнутых членов

`rebindImportedGroupNodes` (source_loader.go:972): член группы, выброшенный
дедупом, перепривязывается на тег ВЫЖИВШЕЙ копии — `sourceDedup.seen`
хранит `подпись → тег первой записи`, надо отдать эту карту в перепривязку
(final-тег выжившего после штамповки: связка «оригинальный тег дубля →
тег выжившего»). Группа остаётся жить с дедуплицированным составом
(повторы члена схлопнуть).
Тест: узлы a,b + байт-копии a2,b2 + urltest {a2,b2} → группа жива,
состав {a,b}.

## 5. M2: уникализация без коллизий

`makeIdentityUnique` (source_loader.go:88) и `MakeTagUnique`: сгенерированное
имя `X-2` может быть занято настоящим тегом из подписки. Генерация обязана
пропускать занятые: проверять кандидата по счётчику/множеству и
инкрементировать до свободного. Чинить ОБЕ функции (у MakeTagUnique тот же
изъян с v1.5.0 — дубль тега в outbounds ядро отвергает).
Тест: подписка `X, X-2, X` → идентичности `X, X-2, X-3`; отметка на `X-2`
гасит только второй узел.

## Запреты

- Идентичность узла (SPEC 112 — тег в рамках источника) НЕ трогать: этот
  SPEC про parse-слой.
- Никакого нового дедупа по кредам нигде — вердикт «разные транспорты =
  разные узлы» распространяется на весь парсер.
