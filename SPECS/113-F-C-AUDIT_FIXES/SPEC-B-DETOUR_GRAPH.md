# SPEC 113-B — Граф detour: единая строгость, топологический резолв

Закрывает находки аудита: C4 (каскад fail-closed → тихий direct), M3
(preview не переписывает реестр исключений). Упраздняет мягкое правило
SPEC 077 для dangling DetourTag.

## Принцип (нормативная формулировка пользователя)

«Detour — это управление анонимностью, а не балансировка. Пользователь
настроил переход; если переход недоступен — это проблема, о которой
говорят». Всегда: **⚠ и носитель недоступного перехода скипается.**
Молчаливый фолбэк (снятие detour, direct dial) запрещён на всех уровнях.

## 1. Топологический порядок резолва

`resolveNodeDetours` (core/config/outbound_generator.go:1401):

- Построить граф зависимостей источников: ребро «ссылающийся → цель».
  У источника не больше одной исходящей node-ссылки → граф из цепочек и
  колец, сортировка тривиальна. Для tag-only ссылок (без source_id)
  источник-цель определяется предварительным запросом к nodeRefIndex
  (без штамповки!) только ради ребра.
- Обрабатывать источники в топологическом порядке: цель раньше
  ссылающегося. При резолве проверять: источник-цель уже в dropSource →
  выпадение с причиной вида «хоп находился в источнике "X", который
  исключён из конфига» (человеческий текст, локализуемый).
- Кольцо (обнаруживается при сортировке) → ВСЕ участники fail-closed,
  причина «циклическая ссылка A ↔ B». Сегодня кольцо доезжает до
  санитайзера и рвётся снятием detour — это запрещённый тихий direct.
- Групповые рёбра (DetourTag на группу другого источника, свёртки) — в тот
  же граф. Двухпроходность SPEC 112-A не трогается: меняется только порядок
  обхода ссылок внутри прохода 2.

## 2. Единая строгость для ВСЕХ целей detour

- **Source-detour на узел** — как было: не разрешился → источник выпадает
  (fail-closed) + SourceExclusion.
- **Source-detour на группу/тег (бывший SPEC 077, fail-open)** — теперь
  ТО ЖЕ САМОЕ: тег не существует в финальном конфиге → источник выпадает
  с ⚠ «цель detour "vpn ①" не существует». Особенность: существование
  селекторов шаблона известно там, где известен полный набор финальных
  тегов (build-слой, finalTags) — проверка встаёт туда, но исход
  одинаковый: запись в реестр исключений + выброс узлов источника, а не
  зачистка санитайзером.
- **Node-detour** (ручной config_json со своим `detour`): цель не
  существует → скипается УЗЕЛ, с warning и причиной.
- **Хоп цепочки** — уже fail-closed («маршрут без хопа — другой маршрут»),
  не трогать.
- Санитайзер графа (core/build/outbound_graph_sanitize.go) остаётся
  последним рубежом для прочего мусора, но правило 1 «снять detour → узел
  ходит напрямую» ЗАМЕНЯЕТСЯ на «выбросить носителя + запись причины»:
  если сюда что-то дошло с висячим detour — это баг выше по конвейеру,
  и спасать его переходом в direct запрещено. WarnLog обязателен.

## 3. M3: реестр исключений — у каждой сборки

`config.SetExcludedSources` зовут два пути из трёх; путь Мастера
(`ConfigService.GenerateOutboundsFromParserConfig`, core/config_service.go:190,
вызов из ui/configurator/business/parser.go:146) результат выбрасывает.
Инвариант «реестр переписывается каждой сборкой, включая пустую»
восстановить: этот путь тоже пишет реестр. ⚠ в списке источников
обновляется после preview-сборки; протухшая пометка после починки хопа
исчезает без полной пересборки.

## Заметность (release notes)

Смена поведения: переключение настроек шаблона (например, выключение
мульти-VPN) теперь ИСКЛЮЧАЕТ источники, задетуренные на исчезнувший
селектор, с ⚠ — раньше они молча ехали напрямую. У пользователей с уже
протухшими групповыми detour после обновления «пропадут» источники — ⚠ и
тост обязаны называть цель по имени, чтобы починка была очевидной.

## Тесты (обязательные, каждый должен падать на старом коде)

1. A битый, B → узел в A: B выпадает, в реестре ДВЕ записи с причинами;
   в конфиге нет ни одного узла B; detour нигде не снят.
2. Цепочка A←B←C: выпадают все три, порядок причин честный.
3. Кольцо A↔B: оба fail-closed, причина про цикл.
4. DetourTag на несуществующий селектор: источник выпадает (старый тест
   fail-open поведения — удалить/инвертировать).
5. Node-detour в config_json на несуществующий тег: скип узла, warning.
6. Preview-путь Мастера: после сборки реестр соответствует её результату.
