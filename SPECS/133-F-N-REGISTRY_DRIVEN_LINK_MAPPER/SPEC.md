# SPEC 133 · Маппер источников строится ОТ реестра

Статус: **N — ТЗ**. Решение владельца 19.09.2026, **блокер релиза**.
Ветка develop от `5170a169` (контракт `1.1.10`, ядро `1.14.1-lx.4`).

Продолжает **SPEC 131** (`SPECS/131-F-O-UNIFIED_NODE_PIPELINE/`): тот перевёл
в реестр правила **значений** и поставил `nodeflow.Sanitize`/`Emit`.
Здесь — **вход**: последнее место, где решения живут в коде.

**Расширение области 19.09.2026 (решение владельца).** Изначально кампания
бралась за ссылки. Владелец расширил её до ВСЕХ источников узла:

> «Разрешаю по необходимости доработать структуры реестра, чтобы они полностью
> отражали потребности. Итог: управляем структурой превращения ссылок/JSON и
> прочих источников в целевые узлы через реестр ПОЛНОСТЬЮ. Учти, что маппер из
> ссылок, из xray и из sing-box могут быть разные».

Отсюда — **несколько мапперов по виду источника** (§3), а не один на всё:
`mappers.uri`, `mappers.xray`, `mappers.singbox`, `mappers.conf`. Таблицы у
них РАЗНЫЕ, движок — ОДИН.

Это ровно то, что `contract/docs/CANON.md` §8 уже объявляет нормой («любой
вход — share-URI, sing-box/Xray JSON, wg-conf, ручное тело — проходит три

«маппер» существует как ЧЕТЫРЕ независимых рукописных парсера.

Спутники: `PRIMITIVES.md` (инвентаризация с адресами и выражение примитивами;

## 1. Зачем

### 1.1. Четыре входа, четыре рукописных маппера

Узел рождается из внешнего текста четырьмя путями. Ни один не читает реестр
как таблицу перевода:

| Вход | Код | Объём | Реестр читает? |
|---|---|---|---|
| share-ссылка | `node_parser_*.go` ×16, `shareuri_*.go` ×14 | ~4500 строк | только `QueryAliases` |
| Xray-JSON | `xray_outbound_convert.go`, `xray_protocols.go`, `xray_hysteria.go` | ~2100, из них ~530 per-scheme развилка | **нет ни одного импорта** |
| sing-box JSON | `singbox_import.go`, `singbox_sanitize.go` | ~700 | только `singboxTypeToScheme` |
| wg-quick `.conf` / `awg://base64` | `wgconf_text.go`, `wgConfToURI` (`node_parser_amnezia.go:508`) | ~350 | нет |

Дефект одного класса — **реестр знает, код не читает** — возможен в каждом
из четырёх, и в каждом он уже случился (§1.2, §1.3).

**Вход «ручное тело» (sing-box JSON) почти identity** — тело копируется как
есть и судится санитайзером (`singbox_import.go:322-385`). Но «почти»: три
per-type ветки в `singbox_sanitize.go` (`masque` legacy-ключи `:84`,
форма `tls` `:109`, `hysteria.obfs` объект→строка `:147`) — это перевод
диалекта, живущий в коде и не объявленный нигде. Именно поэтому
`mappers.singbox` не пустой.

### 1.2. Дефекты ссылочного входа

Таблица реестра `uri.*` (имя, `aliases`, `maps_to`, `emit.param_order`)
**не читается кодом вообще**:

- `Registry.MapsTo` (`core/config/registry/registry.go:951`) — заполняется,
  экспонируется и **не вызывается ниоткуда**;
- секции `uri.*`, `mapper`, `emit`, `xray_dialect` в рантайме не участвуют —
  их читает только докогенератор (`contract/tools/gendocs/`);
- `emit.param_order` не читает никто: порядок задаёт `q.Encode()`, то есть
  алфавит `net/url`;
- из всего реестра ссылочный путь берёт ровно одно — `QueryAliases`
  (`uri_params.go:59`).

Отсюда дефекты одного класса — **реестр знает, код не читает**:

| Дефект | Реестр объявляет | Код |
|---|---|---|
| ss `plugin`/`plugin_opts` (SIP003) | `shadowsocks.json:40-52` — и прямо пишет «Go молча теряет query целиком» | слова `plugin` нет во всём `core/` |
| `disable_sni` у tuic и masque | обе схемы, `ext: mobile` | не читает ни одна |
| SS2022 открытый userinfo | кейс корпуса живёт случайно (ключ оказался валидным base64) | безусловный base64-декод |
| `socks4://` | (добавлено в 1.1.x) | раньше не существовало |
| `fp` у hysteria/hy2/tuic | (исправлено в 1.1.4) | раньше не читался |

Последние две строки — уже починенные вручную экземпляры **того же класса**.
Пока таблица не исполняется, каждый следующий параметр повторит их судьбу.

### 1.3. Дефекты прочих входов — тот же класс

| Вход | Дефект | Адрес |
|---|---|---|
| Xray | неизвестный `network` (kcp/quic) возвращает `nil` **молча** — транспорт теряется без предупреждения, хотя код `transport_unsupported` объявлен | `xray_outbound_convert.go:326-337`, и это прямо записано в `warnings.json` как РАЗРЫВ |
| Xray | ни один из пяти файлов не импортирует `core/config/registry` — `aliases`, `maps_to`, allowlists догоняют узел только ниже, в `node_materialize.go:56` | все `xray_*.go` |
| Xray | написания ключей (`serverName`/`server_name`, `publicKey`/`public_key`, `shortId`/`short_id`, `xhttpSettings`/`splithttpSettings`) зашиты литералами в `xrayFirstString`, а не взяты из `aliases` | `:236-283`, `:391` |
| sing-box | `masque`: плоские `network`/`sni`/`skip_cert_verify` **стрипаются без кода** — пользователь не узнаёт, что поле выброшено | `singbox_sanitize.go:84-96` |
| sing-box | `hysteria.obfs` объект→строка и три ветки отбрасывания — **только `WarnLog`**, ни одного кода на узел | `:147-175` |
| `.conf` | ini переводится в **текст ссылки** `wireguard://` и разбирается заново; `q.Encode()` на этом стыке превращает `+` в `%2B`, а `AllowedIPs` без пробелов теряет форму | `node_parser_amnezia.go:508-599` |
| `.conf` | honored только ПЕРВАЯ секция `[Peer]`, прочие отбрасываются молча | `node_parser_amnezia.go:466-501` |

**`.conf` — самый наглядный случай «крючок вместо примитива»:** ini не
переводится в тело, он переводится в ДРУГОЙ ИСТОЧНИК (в ссылку), чтобы
переиспользовать чужой парсер. Один источник ходит через второй, набирая
дефекты обоих. В целевой архитектуре `mappers.conf` адресует `ini.*` напрямую и стык
исчезает вместе с `wgConfToURI`.

## 2. Решение владельца (19.09.2026)

> «Дать реестру нужное количество примитивов, в коде остаётся только движок,
> общий для всех схем».

Именованные per-scheme крючки в коде — **не** целевая архитектура. Целевое:

| | |
|---|---|
| Реестр | несёт декларативные **примитивы** (13 групп, `SCHEMES.md` §12) |
| Код | **один движок**: `parse` + `emit`, без единого `if scheme ==` и без функций под схему |
| Критерий конца кампании | §2.1 |
| Значения | судит только `nodeflow.Sanitize` — маппер переводит диалект и не судит |
| Норма | общая с LxBox: раскладка уходит в контракт, обе стороны читают одну таблицу |

### 2.1. Критерий конца кампании (в редакции 19.09.2026)

**Ни одной рукописной функции превращения источника в тело узла по
протоколу/схеме.** Развёрнуто:

1. в пакете маппера нет ни одной функции, названной по схеме, протоколу или
   виду транспорта, и ни одного `if scheme ==` / `case "vless"`;
2. удалены `node_parser_*.go` (16), `shareuri_*.go` (14),
   `xray_outbound_convert.go`, `xray_protocols.go`, `xray_hysteria.go`,
   `wgConfToURI`/`parseWGConfSections`, три per-type ветки
   `singbox_sanitize.go`;
3. остаются и НЕ переводятся (§12): сборка документа Xray
   (`xray_json_array.go`, `xray_balancer.go`), распаковщик Amnezia `vpn://`,
   классификатор тела (`body_classify.go`), разбор тела подписки;
4. греп-страж §7 зелёный (решение владельца 19.09, вопрос 4 = Б).

## 3. Мапперы по виду источника

**Решение владельца 19.09.2026:** «маппер из ссылок, из xray и из sing-box
могут быть разные». Так и делается: **четыре независимые секции, один движок**.

### 3.1. Почему разные секции, а не одна с `when`

Источники отличаются не значениями, а **пространством адресации и формой
оболочки**. Одна таблица с ветвлением по виду источника воспроизвела бы в
данных ту самую развилку, которую кампания убирает из кода.

| | `uri` | `xray` | `singbox` | `conf` |
|---|---|---|---|---|
| адресация | `query.X`, `userinfo`, `host`, `port_raw`, `fragment` | `json.<path>` | `json.<path>` | `ini.<Section>.<Key>` |
| оболочка | схема + формы (base64/legacy) | объект outbound | объект outbound | ini-текст |
| имена | диалект панелей (`pbk`, `sid`, `obfs-password`) | camelCase Xray (`publicKey`, `serviceName`) | канон sing-box (`public_key`) | ключи wg-quick (`PublicKey`) |
| перевод | плотный | плотный | почти identity | плотный |
| эмит | да (share-URI) | нет | да (тело) | нет |

`mappers.singbox` **не** «почти identity» (уточнение владельца 19.09.2026):
sing-box существует в форках, и одно и то же поле они оформляют по-разному.
Это полноценный маппер с **диалектами** — §3.4.

### 3.2. Единообразие структуры

Секции разные, **форма записи одна**. У каждого маппера:

```jsonc
"mappers": {
  "<kind>": {
    "detect":  { … },        // когда эта секция применима (§3.6)
    "forms":   [ … ],        // оболочка → пространство источников (P1)
    "userinfo":{ … },        // только там, где userinfo есть
    "params":  { "<имя>": {"source": …, "maps_to": …, …} },
    "emit":    { … }         // только там, где обратный ход существует
  }
}
```

Различаются **только** `detect`, `forms` и написание `source`. Примитивы
(§4, `PRIMITIVES.md` §1) общие: `value_map`, `selector`, `sets`, `implies`,
`extract`, `list`, `default_from`, `normalize` работают одинаково в любой
секции. Движок, умеющий исполнить одну, исполняет все четыре.

### 3.3. Переиспользуемые блоки (`$ref`) — чтобы не дублировать

TLS, транспорты и multiplex общие для многих протоколов, но **у каждого
диалекта свои имена ключей**. Поэтому блок выносится один раз и адресуется
ссылкой, а диалектных вариантов у него столько, сколько диалектов:

```jsonc
// registry/transports.json
"blocks": {
  "ws": {
    "uri":  { "path": {"source": "query.path", …}, "host": {"source": "query.host",
              "maps_to": "transport.headers.Host"} },
    "xray": { "path": {"source": "json.wsSettings.path", …},
              "host": {"source": "json.wsSettings.host",
                       "maps_to": "transport.headers.Host"} }
  }
}
// у протокола:
"mappers": { "uri":  { "include": ["transports.ws#uri",  "tls#uri"] },
             "xray": { "include": ["transports.xray",    "tls#xray"] } }
```

`include` разворачивается загрузчиком до исполнения; конфликт имён —
ошибка линтера, а не молчаливое перекрытие. Так `?ed=N`, живший в четырёх
слоях (память проекта `ws-early-data-ed-param`), объявлен **один раз для
uri** и **один раз для xray** — и оба написания видны рядом.

**Что доказывает необходимость диалектных вариантов блока** (из
инвентаризации Xray):

- `host` у одного и того же ws в трёх формах: `headers{"Host":…}` (ws),
  `[]string` (http/h2), скаляр (httpupgrade) — форма обязана быть
  **атрибутом записи**, а не выводиться из имени транспорта;
- `serverName`/`server_name`, `publicKey`/`public_key`, `shortId`/`short_id`
  читаются двумя написаниями только в TLS-ветке, а транспортные ключи — одним
  (`xray_outbound_convert.go:236-283` против `:347-402`): это `aliases`
  внутри xray-блока, а не общее правило;
- `xray_hysteria.go:227` читает **только** `server_name`, расходясь с `:270`
  того же файла — расхождение исчезает, когда написание объявлено один раз.

### 3.4. `mappers.singbox` — ДИАЛЕКТЫ форков

**Уточнение владельца 19.09.2026** (отменяет прежнюю формулировку «почти
identity»):

> «Бывают разные форки sing-box, и они по-разному оформляют одно и то же:
> имена и вложенность полей xhttp/AWG/amnezia, endpoint vs outbound у
> wireguard, legacy-поля разных версий ядра, типы-синонимы, расширения
> форков (hiddify / nekobox / sing-box-extended / amnezia-box и наш lx)».

Поэтому `mappers.singbox` — **полноценный маппер**, а не пропуск тела
насквозь. Целевое тело всегда одно: канон нашего реестра (`body.fields`),
дальше санитайзер.

#### Чем доказано, что диалекты реальны

| Свидетельство | Где |
|---|---|
| Реестр **уже** объявляет двойные написания xmux: `max_concurrency`/`maxConcurrency`, `c_max_reuse_times`/`cMaxReuseTimes`, `h_max_request_times`/`hMaxRequestTimes` | `transports.json`, запись `xmux.impl` |
| Реестр **уже** объявляет `extra.xmux (вложенный объект)` как алиас — та же величина на ДРУГОМ УРОВНЕ вложенности | там же, `xmux.aliases` |
| Живое состояние владельца: 186 узлов, `origin=json`, `xmux.max_concurrency = "16-32"` — строка-диапазон, которой у канона нет | `SPECS/131…/tools/realstate_probe_2026-09-18.out.txt` |
| `splithttpSettings` ∥ `xhttpSettings` — один транспорт под двумя именами | `transports.json` `impl`, `xray_outbound_convert.go:394-397` |
| `wireguard` живёт и в `outbounds[]`, и в `endpoints[]` (sing-box ≥ 1.11) | `singbox_import.go:296-316` |
| masque: плоские `network`/`sni`/`skip_cert_verify` против вложенного `tls` — два поколения одного поля | `singbox_sanitize.go:84-96` |
| hysteria v1 `obfs` строкой против v2-формы объектом `{type,password}` | `singbox_sanitize.go:147-173` |
| `type: "shadowsocks"` ↔ схема `ss` — тип-синоним уже отображается таблицей | `singbox_import.go:390-409` |

Сегодня всё это разбросано: часть — в `impl`-прозе реестра (не исполняется),
часть — в трёх `if obType ==` (`singbox_sanitize.go`), часть — нигде.

#### Форма секции

```jsonc
"mappers": { "singbox": {
  "forms": [
    { "id": "endpoint", "detect": {"in_array": "endpoints"},
      "space": "json", "level": "endpoint" },
    { "id": "outbound", "detect": {"default": true},
      "space": "json", "level": "outbound" }
  ],
  "type_synonyms": {"shadowsocks": "ss"},        // тип-синоним → схема
  "unknown_key": {"action": "keep", "code": "json_field_unknown"},
  "params": {
    "max_concurrency": {
      "source": ["json.transport.xmux.max_concurrency",
                 "json.transport.xmux.maxConcurrency",
                 "json.transport.extra.xmux.max_concurrency"],
      "maps_to": "transport.xmux.max_concurrency" },
    "obfs": { "source": "json.obfs", "maps_to": "obfs",
              "coerce": {"object_to_scalar": "password"},
              "when": {"$type": "hysteria"} },
    "$masque_flat": { "source": ["json.network","json.sni",
                                 "json.skip_cert_verify"],
                      "maps_to": null, "since": "0.8.0",
                      "on_present": {"action": "drop",
                                     "code": "singbox_legacy_key_dropped"} }
  }
} }
```

Три механизма, закрывающие весь список форков:

1. **`forms` с `detect` по признакам тела** — уровень (`outbounds` против
   `endpoints`), характерные ключи, форма вложенности;
2. **`source` списком** — альтернативные пути/написания одного поля;
   первый найденный выигрывает, порядок = приоритет;
3. **`level`/перенос между уровнями** — `outbound ↔ endpoint`,
   `peers[] ↔ плоские поля` (примитив `lift`, §4 и `PRIMITIVES.md` §15).

#### Неизвестный ключ — код, а не тишина и не слепая копия

`unknown_key: {action, code}` объявляется **у секции**. Для `singbox`
действие — `keep` (тело уже каноническое, чужой ключ может быть расширением
форка, и выбрасывать его нельзя), но **с info-кодом `json_field_unknown`**
(path = путь ключа). Это парный к `uri_param_unknown` (решение владельца 1,
вопрос §13) ответ для JSON-входов: сегодня неизвестный ключ уезжает в тело
слепой копией и всплывает лишь тогда, когда ядро отвергнет весь конфиг.

Три сегодняшние per-type ветки (`singbox_sanitize.go:84/109/147`) ложатся
сюда целиком, и каждая **получает код** — сегодня две из трёх молчат (§1.3).

### 3.4a. `mappers.xray` — те же диалекты (Xray / v2ray / v2fly)

Проверка по требованию владельца: диалекты есть и здесь, механизм тот же.

| Вариант | Сегодня | Примитив |
|---|---|---|
| `settings.vnext[]` (vless/vmess) против `settings.servers[]` (trojan/ss/hy2) против плоского `settings.{address,port}` (hysteria) | три рукописные выемки, две из них — дословный дубль (`xray_outbound_convert.go:104-131` ≡ `xray_protocols.go:117-144`) | три `forms` с `detect` |
| `xhttpSettings` ∥ `splithttpSettings` | fallback в коде `:394-397` | `source` списком |
| `serverName`/`server_name`, `publicKey`/`public_key`, `shortId`/`short_id` | `xrayFirstString`, только в TLS-ветке | `aliases` внутри xray-блока |
| `network: "h2"` ∥ `"http"`; `"splithttp"` ∥ `"xhttp"` | `case "http", "h2"` | `value_map` |
| `hysteriaSettings.version` 1/2 → два разных типа тела | `if version == 2` (`xray_hysteria.go:54-57`) | `selector` + `sets` |
| auth под четырьмя именами (`auth`/`auth_str`/`authStr`/`password`), полоса под четырьмя | литеральные списки `xray_hysteria.go:163,188-200` | `source` списком |
| `xmux` вложенный ∥ плоский в `extra` | `xrayFlattenScalars` разворачивает `xmux` вручную (`:42-71`) | `lift` |

Неизвестный ключ у `xray`: `action: "drop"` + `json_field_unknown` — в
отличие от `singbox`, чужой ключ Xray в тело sing-box не годится по
построению.

#### Сверка с LxBox по xray-входу (проверено по нашему коду)

**Новый примитив — `materialize_default`.** Даже там, где дефекта у нас нет,
различие важно: `default` в `body.fields` — это правило САНИТАЙЗЕРА (чем
заполнить, если ключа нет), а «маппер обязан ЗАПИСАТЬ значение в тело» —
свойство МАППЕРА. Сегодня оно выражено кодом (`outbound["security"] = …`
безусловно). В грамматике: `"materialize_default": true` у записи секции —
значение попадает в тело даже когда источник молчал. Ср. `emit_when:
"always"` — то же самое для обратного направления.

#### Источник тела для санитайзера — объявляется секцией

`except_sources` в правилах реестра (`wireguard.json:388`,
`max_when.except_sources: ["singbox"]`) опирается на то, каким **входом**
приехало тело. У нас пять значений, а не два:

```
NodeSourceURI "uri" · NodeSourceSingbox "singbox" · NodeSourceXray "xray"
NodeSourceWGConf "wgconf" · NodeSourceAmnezia "amnezia"
```
(`core/config/configtypes/types.go:648-652`)

У LxBox `BodySource` двузначен (`singbox` / `other`), и Xray у них идёт как
`other` — то есть правило `except_sources: ["singbox"]` у обеих сторон
совпадает случайно, а любое правило, различающее `xray` и `uri`, разъедется.

**Норма:** каждая секция-маппер **объявляет**, каким `source` её тела
приходят в санитайзер:

```jsonc
"mappers": {
  "uri":     { "body_source": "uri" },
  "xray":    { "body_source": "xray" },
  "singbox": { "body_source": "singbox" },
  "conf":    { "body_source": "wgconf" }     // vpn:// → "amnezia"
}
```

Линтер проверяет, что каждое значение, встречающееся в `except_sources`,
объявлено хотя бы одной секцией.

**Молчаливые потери, которые становятся кодами** (сегодня их нет вовсе):
`network` вне набора (kcp/quic/ds) → `transport_unsupported` (код уже
объявлен, но из Xray не ставится); `security: "xtls"` → тот же класс;
`vnext[1..]`/`servers[1..]`/`users[1..]` отбрасываются — код о том, что
элементов было больше одного.

### 3.5. `mappers.conf`

`conf` — таблица `ini.<Section>.<Key>`, **общая с `uri` по `maps_to`** и
отдельная по `source` (`SCHEMES.md` §9 уже записан в этой форме). Стык
«ini → текст ссылки → парсер» (`wgConfToURI`) исчезает вместе с потерей
`Interface.DNS` и молчаливым отбрасыванием второй секции `[Peer]` (§1.3).

## 3A. `detect` — реестр сам говорит, что есть что

**Требование владельца 19.09.2026 (обязательное):**

> «Каждая секция-маппер в реестре содержит собственный декларативный признак
> „этот контент — мой“: регулярку и/или схему проверки. Реестр сам
> показывает, как отличить ссылку от ini, от Xray JSON и от sing-box JSON —
> в коде нет ни одного рукописного сниффера формата».

Сегодня сниффер рукописный и живёт в двух местах: `ClassifySubscriptionBody`
(`body_classify.go:90-124`) и каскад `HasPrefix(uri, "<scheme>://")` из 25
схем, продублированный switch-диспетчером (`node_parser_core.go:21-45` и
`:118-330`). Оба переезжают в данные.

### 3A.1. Два уровня, один словарь примитивов

| Уровень | Что решает | Где объявлен |
|---|---|---|
| **документ** | вид источника целиком: что это за текст | `registry/sources.json` (новый) |
| **элемент** | к какому протоколу И диалекту относится запись | `mappers.<kind>.detect` у протокола, `forms[].detect` у формы |

Примитивы `detect` **одни и те же на обоих уровнях**, движок исполняет их
одинаково — отдельного «документного» языка нет.

### 3A.2. Словарь предикатов `detect`

```jsonc
"detect": {
  "regex":   "^(?i)vpn://",            // RE2 ∩ ECMAScript, как pattern у полей
  "json":    { "required_keys": ["protocol"],      // все обязаны быть
               "any_keys":      ["outbounds"],     // хотя бы один
               "key_absent":    ["type"],          // ни одного
               "type_of":       {"outbounds": "array"} },
  "ini":     { "sections": ["Interface"],          // регистронезависимо
               "keys":     ["Jc", "Jmin"] },
  "text":    { "line_fold": "[interface]",         // строка целиком, fold-case
               "prefix_fold": "vpn://" },
  "not":     { … },                                 // отрицание любого предиката
  "all":     [ … ],  "any": [ … ],                  // композиция
  "default": true                                   // ветка «всё остальное»
}
```

Предикаты внутри одного объекта — конъюнкция. `regex` — общее подмножество
RE2 ∩ ECMAScript (без backreference и lookaround), тот же диалект, что у
существующего `pattern` у полей: **регулярка обязана компилироваться обеими
сторонами** (Go и Dart), это проверяет линтер.

### 3A.3. Уровень документа — `registry/sources.json`

```jsonc
{ "v": 1,
  "document": {
    "max_unwrap_depth": 2,
    "on_unrecognized": {"code": "source_unrecognized", "severity": "warning",
                        "include_fragment": 120},
    "sources": [
      { "kind": "vpn_link", "priority": 10, "mapper": null,
        "unwrap": "amnezia_vpn",
        "detect": {"text": {"prefix_fold": "vpn://"}} },

      { "kind": "base64", "priority": 20, "mapper": null,
        "unwrap": "base64", "redetect": true,
        "detect": {"regex": "^[A-Za-z0-9+/_-]+={0,2}\\s*$"} },

      { "kind": "xray_config", "priority": 30, "mapper": "xray",
        "detect": {"json": {"type_of": {"outbounds": "array"},
                            "array_elem_any_keys": ["protocol"]}} },

      { "kind": "singbox_outbound", "priority": 40, "mapper": "singbox",
        "detect": {"json": {"required_keys": ["type"]}} },

      { "kind": "singbox_config", "priority": 50, "mapper": "singbox",
        "detect": {"json": {"any_keys": ["outbounds", "endpoints"],
                            "key_absent": ["type"]}} },

      { "kind": "wgconf", "priority": 60, "mapper": "conf",
        "detect": {"ini": {"sections": ["Interface"]}} },

      { "kind": "uri_list", "priority": 90, "mapper": "uri",
        "split": "lines", "detect": {"default": true} }
    ]
  } }
```

**Правило неоднозначности.** Совпало несколько — побеждает меньший
`priority` (порядок в файле = порядок проверки, `priority` делает его явным
и устойчивым к перестановке строк). Не совпало ничего и нет ветки
`default` — код `source_unrecognized` уровня warning с фрагментом текста.

Порядок сохраняет сегодняшние обоснования дословно: `vpn://` раньше
base64-эвристики (`:` не входит в алфавит base64); Xray раньше sing-box-массивов
(элемент Xray-конфига тоже несёт `outbounds`); `type` раньше `outbounds`
(одиночный selector несёт оба). Всё это — докстрока
`ClassifySubscriptionBody:76-89`, переведённая в данные.

**Оболочка-декодер и рекурсия.** `unwrap` распаковывает (base64, zlib+base64
у Amnezia), `redetect: true` отправляет результат на повторный детект;
глубина ограничена `max_unwrap_depth` — сегодня этот предел в коде
отсутствует, и это единственное новое ограничение (base64-подписка, внутри
которой снова base64, сегодня раскрывается неограниченно).

**Clash-YAML.** Проверено: поддержки нет ни в каком виде — ни парсера, ни
зависимости (все вхождения `clash` в коде относятся к Clash API ядра). В
`sources.json` он **не объявляется**; появится — станет ещё одной записью
без единой строки кода.

### 3A.4. Уровень элемента

У каждой секции-маппера и у каждой её формы — свой `detect`:

```jsonc
// uri: схема + форма (awg://<base64 .conf> против awg://key@host)
"mappers": { "uri": {
  "detect": {"scheme_in": ["wireguard", "wg", "awg"]},
  "forms": [
    { "id": "conf_b64",
      "detect": {"all": [{"regex": "^[A-Za-z0-9+/_-]+={0,2}$"},
                         {"not": {"regex": "[@:?]"}}]},
      "decode": ["base64", "ini"], "space": "ini" },
    { "id": "url", "detect": {"default": true},
      "decode": ["url"], "space": "url" }
  ] } }

// conf: род узла по ключам ini
"mappers": { "conf": { "forms": [
  { "id": "awg3", "detect": {"ini": {"keys_any": ["H1","I1","HeaderProtectionKey"]}} },
  { "id": "awg",  "detect": {"ini": {"keys_any": ["Jc","Jmin","Jmax","S1"]}} },
  { "id": "wg",   "detect": {"default": true} } ] } }

// xray: протокол + форма эндпоинта
"mappers": { "xray": {
  "detect": {"json": {"required_keys": ["protocol"]}, "value_of": {"protocol": "vless"}},
  "forms": [
    { "id": "vnext",  "detect": {"json": {"type_of": {"settings.vnext": "array"}}} },
    { "id": "servers","detect": {"json": {"type_of": {"settings.servers": "array"}}} },
    { "id": "flat",   "detect": {"json": {"any_keys": ["settings.address"]}} } ] } }

// singbox: тип (+синонимы) и диалект форка
"mappers": { "singbox": {
  "detect": {"json": {"value_in": {"type": ["shadowsocks", "ss"]}}},
  "forms": [
    { "id": "endpoint", "detect": {"in_array": "endpoints"} },
    { "id": "outbound", "detect": {"default": true} } ] } }
```

Род узла AWG сегодня определяется функцией `hasAWGParams`
(`node_parser_wireguard.go:406-415`) — она становится `detect` формы.

### 3A.5. Что проверяет линтер (в W0)

| Проверка | Что ловит |
|---|---|
| у каждой секции-маппера и каждой формы есть `detect` (или `default: true`) | «секция, которую невозможно выбрать» |
| `detect`-ы одного уровня **не пересекаются на корпусе**: каждый кейс опознаётся ровно ОДНОЙ секцией | тихое перекрытие форм; **иначе красное** |
| ровно одна ветка `default` на уровень | две ветки «всё остальное» |
| `regex` компилируется в RE2 **и** валиден как ECMAScript | разъезд Go/Dart |
| `priority` уникальны в пределах уровня | неустойчивый порядок |
| каждый `kind` ссылается на существующий `mapper` (или `null`) | висячая ссылка |

Проверка непересечения гоняется по всему корпусу `contract/corpus/**`
(334 URI-кейса + 94 body-кейса): если кейс опознан двумя секциями сразу или
ни одной — тест падает.

### 3A.6. Документация

`contract/tools/gendocs` выводит из этих `detect` таблицу **«как
распознаётся источник»** — по одной строке на вид источника и на форму, с
человекочитаемым условием. Сегодня такой таблицы нет нигде: порядок проверок
живёт в докстроке одной Go-функции и в контракт не попадает.

### 3.6. Выбор секции: порядок значим

Порядок значим и сохраняется дословно: `type` раньше `outbounds` (одиночный
selector несёт оба), Xray-массив раньше sing-box-массивов, `vpn://` раньше
base64-эвристики. Основание каждого — в докстроке `ClassifySubscriptionBody`.

`mapper: null` у `vpn://` — это распаковщик, а не маппер: он отдаёт `.conf`
секции `conf` (§12).

**Эмит выбирает секцию обратно** по своему назначению, а не по входу:
share-URI ⇒ `mappers.uri` наоборот (`emit_form`, `param_order`), тело ⇒
`body.order` через `nodeflow.Emit`. У `xray` и `conf` обратного хода нет —
и это объявляется (`"emit": null`), чтобы линтер не требовал `param_order`.

## 3B. Примитивы по сверке с LxBox (G1–G8)

Сверка LxBox по `bfe65293` дала восемь мест, не ложащихся на черновик
грамматики. Каждое проверено **по нашему коду** и закрывается общим
примитивом — ни одного крючка.

| № | Что | Как у НАС | Примитив |
|---|---|---|---|
| G1 | род AWG объявляет **вход**, а не тело: при негодных значениях в теле не остаётся ни одного awg-ключа, а mtu обязан стать 1280 | `hasAWGParams(q url.Values)` читает **query**, не тело (`node_parser_wireguard.go:400-410`); `any_set` по телу здесь пуст по построению | **`when.source_has`** / `when.form` — условие по ИСТОЧНИКУ и ФОРМЕ наравне с условием по телу |
| G2 | `sets` обязан уметь **снимать** путь | tuic `disable_sni=1` должен убирать `tls.server_name` | `sets` со значением **`null` = удалить путь** (сегодня `null` означает «не писать»; различаются как `"unset"` и отсутствие записи) |
| G3 | приоритет двух записей в один путь | `flow=…-udp443` пишет `packet_encoding=xudp` (`node_parser_core.go:752-755`), затем `packetEncoding` может перезаписать (`:759-768`). Корпус `packet_encoding_udp443_quirk_wins`: `packetEncoding=none` → `xudp` УЦЕЛЕЛ — но лишь потому, что `none` отображается в null и записи не делает | **`priority` у записи** (меньше = раньше) + **`merge: "keep_first" \| "overwrite"`**. Правило «sets побеждает» неверно: побеждает не источник, а явный порядок |
| G4 | `sort_keys` у `type: "object"` | заголовки http/naive: **сортировки в коде нет** (`grep sort` пуст), порядок ключей даёт Go-map → в JSON сериализуется отсортированным; identity держится на этом неявно | **`sort_keys: true`** у `type: object` — делает явным то, что сегодня случайность реализации |
| G5 | `flatten` | `extra.xmux.{…}` разворачивается вручную (`xrayFlattenScalars`, `xray_outbound_convert.go:42-71`) | **`flatten`** — общий примитив (нужен и `mappers.singbox` для форков, §3.4) |
| G6 | SS `plugin` SIP003: резка по первому `;` на `plugin` + `plugin_opts`, алиас `pluginOpts` | не читается вовсе (§1.2) | `extract` `^(?P<plugin>[^;]+)(?:;(?P<opts>.*))?$` + `aliases` |
| G7 | ini: источник `$comment` (имя из комментария под `[Peer]`); `Endpoint` с голым IPv6 | комментарий — `wgPeerNameComment` (`wgconf_text.go:82-107`); хост — `LastIndex(":")` + `Trim("[]")` (`:111-118`), то есть голый IPv6 **уже** обрабатывается, но регуляркой из черновика не матчится | источник **`ini.$comment.<Section>`**; `extract` для Endpoint с веткой «несколько `:` без скобок = IPv6, порт 51820» |
| G8 | нормализация НЕПУСТОЙ метки | `normalizeFlagTag` (🇪🇳→🇬🇧, `node_parser_core.go:635-637`) + trim; strip control-символов — фикстура `vless/fragment_control_chars` | **`label.normalize`**: `strip_control`, `trim`, `value_map` — метка входит в identity |

**Норма: authority разбирает лексер ДВИЖКА, не платформенный парсер.**
`host:443,20000-30000` (multi-port hysteria) `Uri.tryParse` у Dart отвергает
целиком. Движок обязан резать authority сам и класть в `port_raw` сырую
строку (§0.1 `SCHEMES.md`). У нас это уже так: `hysteria2_ports.go` работает
с сырым authority через хук `node_parser_core.go:383-388`.

### 3B.1. Противоречие alpn/path — снято

Черновик `SCHEMES.md` писал `{"percent": 2}` обоим. **Это ошибка черновика**,
и она сдвинула бы identity. По коду:

| | Сегодня | Норма |
|---|---|---|
| `alpn` | `normalizePercentDecodeLoop` — `QueryUnescape` **до стабилизации, без предела** (`node_parser_transport.go:24-33`) | `{"mode": "query", "passes": "until_stable", "max": 16}` |
| `path` | `decodeResidualPercent` — ровно **2** прохода `PathUnescape` (`:755-776`) | `{"mode": "path", "passes": 2}` |

Фикстура `contract/corpus/uri/vless/alpn_multiply_encoded.uri` несёт
`http%2525252F1.1` — **три** уровня кодирования, ожидание `["http/1.1"]`.
При `passes: 2` кейс покраснел бы. Предел 16 вводится как страховка от
неограниченного цикла (§9.2) и на корпусе не достигается.

Семантика различается **намеренно**: `path` декодируется `PathUnescape`,
потому что литеральный `+` в пути легален, а `QueryUnescape` превращал
`/ws+v2` в `/ws v2` → 404 (комментарий `:766-769`).

### 3B.2. Оговорки к `uri_param_unknown`

Приняты (иначе код зашумит на ровном месте):

1. **«Объявленными» считаются и параметры общих блоков** — `tls.json`,
   `transports.json`, `dialer.json`. Иначе `tcp_keep_alive*` дали бы по три
   info на каждый узел;
2. **содержимое `extra` у xhttp — не параметры ссылки**: это вложенный слой
   чужого диалекта, он адресуется `source`-ом, а не перечисляется;
3. код ставится **только при загруженном реестре** — без реестра «неизвестно
   всё», и молчание правильнее шума.

## 4. Грамматика

Полный словарь примитивов — `PRIMITIVES.md` §1, черновики по схемам —
`SCHEMES.md`. Здесь — принципы.

**Минимализм.** Ничего не изобретается заново: `when`, `any_set`, `aliases`,
`normalize`, `default_when`, `on_invalid`, `format`, `values` — существующие
атрибуты (`registry.go:24-225`), они переиспользуются. `when` расширяется
предикатом `in` и равенством по источнику. Вариантность транспортов уже
разложена в `transports.json` по типам — движок читает её как есть.

**Пространство источников.** Форма (`uri.forms[]`) распаковывает текст в
одно плоское пространство: `scheme`, `authority`, `userinfo[.user|.pass]`,
`host`, `port`, `port_raw`, `path`, `fragment`, `query.X`, `json.X`,
`ini.S.K`. Параметр адресует источник атрибутом `source` — и **это
единственный способ** получить значение.

**13 групп примитивов** (`SCHEMES.md` §12): `forms/decode/reparse`,
`source`, `userinfo`, `value_map`, `selector`+`when`, `sets`/`implies`,
`extract`/`compose`/`split_into`, `list`, `default_from`, `label_fallback`,
`decode_extra`, `emit_*`, расширение `normalize`. Ни одна не названа по
схеме; каждая используется минимум двумя схемами.

## 5. Движок: порядок фаз

Порядок **нормативен** и уходит в `contract/docs/CANON.md` (§10).
Он же — ответ на вопрос LxBox о порядке применения.

```
0. сырой ТЕКСТ ссылки                    ← движок принимает текст, не url.Parse
1. выбор формы (uri.forms[], по порядку, первая сработавшая)
2. decode формы: percent ОДИН РАЗ, base64/json/ini/reparse
   → пространство источников
3. проход A: параметры с selector: true (в порядке объявления)
4. проход B: остальные параметры — source → decode_extra → value_map →
   приведение типа → when по УЖЕ ПОСТРОЕННОМУ телу → maps_to / sets /
   implies / extract
5. label: fragment → path → label_fallback
6. тело (карта sing-box) + Origin
   ↓
7. nodeflow.Sanitize  ← значения судит ТОЛЬКО он
8. nodeflow.Emit      ← порядок ключей тела = body.order
```

**Порядок ключей тела задаёт `body.order` через `Emit`, а не порядок
примитивов.** Это снимает вопрос LxBox (1) целиком: у нас голдены тела уже
не зависят от порядка разбора — так же, как `warnings[]` упорядочены по
`body.order`, а не по порядку обнаружения (W2D_CHANGES §8 п.6).

**Два прохода, а не один** — потому что `when` у зависимого параметра
ссылается на тело, построенное селектором (`transport.type`, `tls.enabled`).
Внутри прохода порядок объявления значим только для селекторов.

**Отказы движка — ровно два**: «форма не распознана» и «синтаксис не
разобрать». Оба — узел в `dropped` с кодом. Молча ронять узел движок не
может; всё прочее — деградация поля санитайзером с кодом.

## 6. Пустое значение

**По умолчанию: пусто = отсутствует.** Это сегодняшнее поведение
(`uri_params.go:36`: `if v != ""`), и корпус на него опирается.
Исключение объявляется **у параметра** (`"empty": "significant"`) — нужно
там, где ядро различает «ключа нет» и «пустая строка» (tristate-поля,
`vless.packet_encoding *string`).

Ответ на вопрос LxBox (3): не «зависит от параметра» в смысле произвола, а
единый дефолт с явным опт-аутом в данных.

## 7. Эмит — та же таблица наоборот

`maps_to⁻¹`, `value_map⁻¹`, `sets` сопоставлением, `compose`, `into⁻¹` у
userinfo, `emit_form`/`form_from`, `param_order`, `emit_when`/`omit_default`.

Эмит — **отдельный осторожный этап** (W7), после того как разбор доказан на
всех схемах. Причины осторожности — оговорки LxBox, у нас подтверждённые:

- их `toUri` — ещё и форма хранения ручных узлов (`origin.raw`);
- корпус знает не-round-trip случаи; у нас они уже перечислены в раннере
  (`contract_emit_test.go:190-217`: D-028 путь с `%2F`, ws-Host из sni);
- лимит длины на выходе **сегодня не проверяется** вовсе
  (`max_uri_length` применяется только на входе, `node_parser_core.go:130-132`).

Эти случаи становятся **данными** (`round_trip: false` с причиной), не кодом.

Известная асимметрия, которую эмит обязан пережить без изменения тел:
`fp=random` не пишется у vless, но пишется у trojan/vmess
(`shareuri_vless.go:49-51` против `shareuri_trojan.go:31-33`);
vmess `httpupgrade → net:"ws"` (`shareuri_vmess.go:70-73`) — неинъективный
`value_map`, ловится линтером; vmess xhttp теряет весь набор полей
(`:74-83`).

## 8. Линтеры (W0, обязательны)

| Линтер | Что ловит |
|---|---|
| у каждого `uri`-параметра есть `source` | «объявлен, но не читается» — весь класс §1 |
| `source` разрешим в пространстве своей формы | опечатка в пути |
| `maps_to` существует в `body.fields` | разъезд с телом |
| `when`/`sets`/`implies` ссылаются на объявленные пути | висячее условие |
| `extract.re` компилируется в RE2 **и** ECMAScript; группы покрыты `into` | разъезд Go/Dart на регулярках |
| `value_map` инъективен у эмитируемой схемы | vmess `httpupgrade→ws` |
| `param_order` покрывает все эмитируемые параметры | молчаливая потеря при эмите |

**«Движок читает только объявленное» обеспечено конструктивно**, а не
грепом: значение доступно лишь через `source`, сырого `url.Values` у движка
нет. Дополнительный греп-страж «нет литералов имён схем в пакете маппера» —
вопрос владельцу (§13, вопрос 4): он раньше отменял сторожевой тест «на
остатки», и формулировку надо согласовать.

## 9. Критерий приёмки схемы

Схема считается переведённой, когда **в одном коммите**:

1. корпус зелёный **без единого изменённого ожидания** — `TestContractCorpusURI`
   и `TestContractCorpusEmitRoundTrip` (334 кейса, из них vless 103,
   wireguard 55, trojan 33);
2. identity живых узлов не сдвинулась — сверка с фикстурами W0.5 (§9.1);
3. рукописный парсер схемы **удалён** (не «оставлен до лучших времён»);
4. `TestCorpusBodiesPassSingboxCheck` зелёный.

Изменение `expected` корпуса **запрещено по умолчанию**, даже когда
рукописный парсер делал заведомую ошибку (ss `plugin`, SS2022, `disable_sni`):
такие исправления меняют тела живых узлов и выносятся **отдельным решением
владельца** (§13, вопрос 2).

## 10. Риски и ловушки

### 10.1. Страховка кампании — фикстуры identity ДО переезда (W0.5)

Предложение стороны LxBox, принимается: снять по всем схемам фикстуры
**старым путём** до первого перевода — тело, tag, label, `origin.raw`,
share-URI, warnings, хеш. Корпус (334 кейса) сравнивает `entry`+`label`, но
**не** сравнивает tag, warnings и round-trip одновременно на одном кейсе;
фикстуры закрывают этот зазор. Это и есть главная страховка: любой сдвиг
identity виден сразу, а не на живой подписке пользователя.

### 10.2. Порядок percent-декодирования

Один раз, до всего. Два узаконенных исключения становятся свойством
параметра, а не поведением кода: `alpn` — декод **до стабилизации, без
ограничения проходов** (`node_parser_transport.go:24-33`); `path` — ровно
2 прохода `PathUnescape` (`:759-776`, D-028). Первое — потенциально
неограниченный цикл; в грамматике он получает явный предел.

### 10.3. `+` в query — риск identity (вопрос LxBox (к))

`url.ParseQuery` превращает `+` в пробел, ломая base64. Сегодня обойдено
**четырьмя точечными заплатами** в трёх файлах (`PRIMITIVES.md` §2), и
покрыты ими ровно четыре параметра: WG `publickey`/`presharedkey`/`privatekey`,
AWG3 `header_protection_key`, masque `publickey`. **Везде остальном — в том
числе у `pbk`, `password`, `obfs-password` — `+` сегодня становится пробелом.**

Единый декодер без замены — правильное поведение и просьба LxBox, но он
меняет значения там, где заплат не стояло. Порядок действий:

1. W0: прогнать корпус с временным флагом «не заменять `+`» и выписать
   кейсы, где меняется тело;
2. если меняются только кейсы с заведомо битым сегодня значением — переход
   идёт как исправление, с фикстурой на каждый;
3. если меняется тело узла, который сегодня рабочий, — стоп и вопрос
   владельцу (это уже не грамматика, а поведение).

Решение не принимать до данных прогона.

### 10.4. Память проекта

| Ловушка | Где отражена |
|---|---|
| ws `?ed=N` жил в 4 слоях (3 парсера + allowlist-эмиттер) | `SCHEMES.md` §11 — одна запись, `extract`+`compose` |
| JSON-карта несёт `float64`/`[]interface{}`; `.(int)`-ассерты теряли поля | приведение типов делает движок по `type`, ассертов в маппере нет |
| эмиттер и парсер ходят парой (masque/anytls/ssh теряли поля) | одна таблица на оба направления; линтер `param_order` |
| Win7 = go1.20 | движок пишется без `slices`/`maps`/`min`/`max` |
| регистр enum-ов ядра case-sensitive | `normalize` только по явному флагу — правило SPEC 131 не меняется |

### 10.5. Прочее

- **Дубли параметров** в query (`?fp=a&fp=b`): сегодня берётся первый
  (`queryGetFold` возвращает `vs[0]`). Норма — фиксируется явно.
- **Регистр имён**: сегодня регистронезависимо (`queryGetFold`), и корпус на
  это опирается (`AllowInsecure=1`, `SNI=` — живые формы). Сохраняется.
- **Приоритет первого распознанного значения**: `fp=qwerty` не должен
  перебивать `fingerprint=firefox` (D-029, `node_parser_transport.go:132-152`)
  — выражается порядком в `source`-списке.
- **`label` из userinfo не берётся никогда** (там секрет,
  `node_parser_core.go:518-530`): в грамматике это не запрет, а факт —
  `label_fallback` не содержит такого источника.

## 11. Норма для LxBox (в CANON)

В `contract/docs/CANON.md` новым разделом — **только то, что обе стороны
обязаны соблюдать одинаково**:

1. порядок фаз движка (§4) и что порядок ключей тела задаёт `body.order`;
2. percent-декод один раз, до всего; `+` не заменяется на пробел (§9.3);
3. «пусто = отсутствует» по умолчанию, опт-аут у параметра (§5);
4. движок принимает сырой **текст**, не разобранный URL-объект;
5. маппер не судит значения — только перевод диалекта;
6. источник метки — `fragment`; фолбэк — по **типу тела** (§13 вопрос 3);
7. семантика `when` (по уже построенному телу), `sets`, `implies`;
8. словарь примитивов и их атрибуты.

Внутренним остаётся: устройство самого движка, имена Go-функций, кэширование
реестра, форма фикстур identity.

## 12. Xray-JSON

Тот же движок: форма без схемы, `space: json`, параметры с
`source: "json.<path>"`. Таблица соответствий — `PRIMITIVES.md` §10.

**Рекомендация: в объёме, но последней волной (W8).** Причины: диалект
изолирован, реестр его уже описывает (`sources: [… "xray"]` у семи схем,
секция `xray_dialect` в `hysteria.json`), а грамматика к тому моменту
проверена на 16 схемах. Вне маппера остаётся не перевод, а **сборка
документа**: `dialerProxy`→цепочки с разрывом колец, два прохода владения,
`balancers[0]`→группа, дедуп и slug тегов (`xray_json_array.go`) — это
работа над массивом узлов и связями, а не над одним узлом.

Так же и распаковщик Amnezia `vpn://` (zlib+base64, выбор контейнера,
плейсхолдеры DNS, `node_parser_amnezia.go:50-460`): остаётся обёрткой над
текстом, выдающей `.conf` тому же движку.

## 13. Вне области

- Правила **значений** — они уже в реестре (SPEC 131), кампания их не трогает.
- MTU-политика WireGuard — перенесена в реестр волной W2d, выражена по телу.
- Дропы узла за негодное значение (битый WG-ключ, пересечение h1–h4,
  AWG3-паддинг) — правила тела, не маппера.
- Изменение формата ссылок и дефолтов — не предмет кампании.

## 14. Решения владельца (19.09.2026) — ПРИНЯТЫ

Все четыре развилки закрыты владельцем в день постановки. Записаны как

### 14.1. Вопрос 1 — неизвестный параметр: **Б, принято**

Неизвестный параметр источника даёт **info-код `uri_param_unknown`**
(`path`/`value` = имя параметра). Код заводится в `registry/warnings.json`
с `cause`/`fix` на en+ru. Движок выдаёт его для всего, что не объявлено в
секции маппера.

Парный код для JSON-входов — **`json_field_unknown`** (§3.4): у `singbox`
действие `keep` (расширение форка выбрасывать нельзя), у `xray` — `drop`.

Оговорки, снимающие ложный шум, — §3B.2 (общие блоки считаются
объявленными; `extra` у xhttp не перечисляется; без реестра код молчит).

### 14.2. Вопрос 2 — заведомые ошибки парсера: **Б, ПРОТИВ прежней рекомендации**

Спека рекомендовала А (не трогать поведение в ходе кампании). Владелец
решил **Б: чинить сразу**.

Чтобы не потерять различие «движок сломал» против «движок починил»:

1. identity-фикстуры всё равно снимаются **старым путём** (W0.5) — база
   сравнения не зависит от решения;
2. каждое место оформляется **явно перечисленной разрешённой дельтой** в
   `DELTAS.md` (кейс, поле, было→стало у обеих сторон, почему старое —
   ошибка);
3. `expected` корпуса по дельте меняется **отдельным коммитом на каждое
   место**;
4. **любое расхождение вне списка = красное.**

Это сохраняет критерий приёмки (§9) в силе: «корпус зелёный без изменённых
ожиданий» превращается в «без изменённых ожиданий, кроме перечисленных в
`DELTAS.md`, и ровно в тех полях, которые дельта называет».

### 14.3. Вопрос 3 — фолбэк тега: **Б, по типу тела** (решено позже в тот же день)

`label_fallback.scheme_source: "singbox_type"`. `hy2://` и `hysteria2://` →
`hysteria2-…`; `socks5://` → `socks-…`. Правило живёт в реестре и общее с
LxBox (у них уже так).

**Это шестая разрешённая дельта** — она переименует живые узлы.

#### Что именно меняется (посчитано по корпусу)

Затронуто **12 написаний из 26**, 52 кейса корпуса. Не только hy2/socks5:

| Схема | → тег | кейсов |
|---|---|---|
| `naive+https` / `naive+quic` | `naive-…` | 17 |
| `ss` | `shadowsocks-…` | 9 |
| `socks5` / `socks4` / `socks4a` | `socks-…` | 10 |
| `proxy-http` / `proxy-https` / `proxy+http` / `proxy+https` | `http-…` | 10 |
| `awg` | `wireguard-…` | 4 |
| `hy2` / `hy` | `hysteria2-…` / `hysteria-…` | 3 |

**Xray-вход — исключение.** LxBox сообщает, что у них Xray держит
историческое написание (`tagScheme`). У нас Xray-ветка пишет тег сама, и
написание там **уже расходится с типом тела**: `xrayTagOrDefault(ob, "ss")`
при `type: "shadowsocks"` (`xray_protocols.go:295` против `:303-304`).
Правило фиксируется в реестре явно, отдельной записью для `mappers.xray`,
а не выводится из общего.

#### Новый риск, которого не было у hy2/socks5

`socks4://`, `socks4a://` и `socks5://` на одном `host:port` дают **один и
тот же** тег `socks-host-port`. Сегодня они различались написанием. Итог —
коллизия, которую `MakeTagUnique` разрешит суффиксом `-2`/`-3`, причём
**порядок суффиксов зависит от порядка узлов в подписке**, то есть
нестабилен между обновлениями. Дельта обязана это назвать.

#### Смягчение для живых пользователей — ОЦЕНКА, реализация ждёт ответа

Что порвётся у узла, чей автотег изменился:

| Класс | Ссылки | Переписывает |
|---|---|---|
| A — `NodeLink {folder_id, tag}` | `detour`, `hops[]`, состав Auto-группы, `default` селектора | `editNodeLinks` (`ui/configurator/business/node_move.go:516-548`) |
| B — по имени (только КОРНЕВЫЕ узлы) | цели правил, `route.final`, Направления (тело + USER-патч), outbound-переменные пресетов, `detour` DNS-серверов, переменные шаблонных DNS | `editRootNameRefs` (`root_name_refs.go:89-217`) |
| — | `Source.Skip[]` фильтры по `tag` | **никто** |
| — | `PendingDisabled[]` (сырые теги) | **никто** |
| — | каталог состояния Tailscale (имя производно от тега) | `RenameTailscaleStateDirForNode` (`tailscale_state_dir.go:149-166`) |

Аналог «переименования Направления, переписывающего 6 видов ссылок»
**существует и для узла**: `RenameRootNodeRefs` (`root_name_refs.go:478-487`)
— тот же `editRootNameRefs`, тот же список мест. Для узла контейнера есть
`RepointContainerNodeLinks` (`node_move.go:410-419`), но он покрывает
**только класс A**.

Три препятствия, из-за которых миграция не делается без явного «да»:

1. **Нет признака «тег сгенерирован автоматически».** В состоянии у узла
   одно имя — `Tag` (`core/state/sources_v7.go:196-199`); `Label` снят
   намеренно (SPEC 112). Различить автотег от совпавшего пользовательского
   постфактум нельзя. Единственный способ восстановить признак — перепарсить
   `Origin.Raw` старым правилом и сверить с `Tag` (с учётом суффикса `-N`).
2. **Расхождение state и генератора откатит миграцию.** Merge подписки идёт
   **по сырому тегу** (`core/state/subscription_merge.go:116-146`): узел с
   новым тегом — новый (включённый), со старым — отсутствует и **удаляется**
   вместе с `Enabled`, `Detour` и вердиктом ядра. Поэтому правка генератора
   и миграция state обязаны ехать **одним релизом**.
3. **Ручное переименование узла подписки разыменовывает origin**
   (`source_edit_window.go:2443-2451`) — для массовой миграции неприемлемо,
   оторвало бы узлы от подписки. Нужен отдельный проход, а не переиспользование
   UI-пути.

Механизм для этого есть: разовая внутрисхемная миграция при загрузке, без
подъёма мажора (прецеденты — `masque_uri_migration.go:30-62` и
`node_warnings_migration.go`, вызовы `load_router.go:75-93`; идемпотентность
обязательна). Ближайший шаблон переписывания — `applyRenames`
(`migration_v6_to_v7.go:724-830`), но его список мест **уже устарел**
относительно `editRootNameRefs`.

### 14.4. Вопрос 4 — греп-страж: **Б, принято**

## 15. Открытые вопросы владельцу

Прежние четыре закрыты (§14). Новые — из расширения области.

**5. Миграция тегов под дельту §14.3.**
Правило `singbox_type` меняет автотег у 12 написаний схем. Без миграции
у пользователя рвутся `detour`, цепочки, состав групп, цели правил и
`Source.Skip`-фильтры; узлы пересоздаются как новые, теряя `Enabled` и
вердикт ядра.
**А.** Правило + разовая миграция состояния одним релизом: признак автотега
восстанавливается перепарсом `Origin.Raw` старым правилом, ссылки
переписываются обоими классами (A через `editNodeLinks`, B через
`editRootNameRefs`), плюс `Source.Skip`, `PendingDisabled` и каталоги
Tailscale. Дороже, но живые конфигурации переживают обновление.
**Б.** Правило без миграции: identity сдвигается разово, пользователь
чинит связи руками.
*Рекомендация — А.* Цена Б — молчаливый разрыв связей у всех, кто добавлял
узлы по `ss://`, `naive+https://`, `proxy-http://`, `socks5://`, `awg://`,
а это большинство написаний. Отдельно: коллизия `socks4`/`socks5` на одном
`host:port` даёт нестабильный суффикс `-2` — в обоих вариантах её надо
назвать в `DELTAS.md`.

**6. Политика «+» в query — ждёт данных прогона.**
Норма «`+` не пробел» правильна и её просит LxBox, но она меняет значения
там, где заплат не стояло (`pbk`, `password`, `obfs-password`). У LxBox
заплата вообще одна. Решение не принимается до прогона корпуса в двух
режимах (W0, §10.3); в `DELTAS.md` запись стоит как **кандидат**.
**А.** Включить после прогона, если меняются только заведомо битые сегодня
значения.
**Б.** Включить безусловно как дельту с фикстурами «до».
*Рекомендация — А*, и она же порядок работ: сначала цифры, потом решение.

**7. Кандидаты в дельты со стороны LxBox** (меняют тела у НИХ, не у нас):
регистронезависимость имён параметров (у них CI только `packetEncoding`);
набор написаний `insecure` (у них 4, в реестре 9); `pinSHA256` по запятой;
**trojan `password`** — черновик режет по `:` (у нас так и есть,
`node_parser_core.go:462-466`), LxBox просит НЕ резать и брать весь
userinfo; `ss` userinfo try-decode; vmess legacy cleartext с IPv6 в скобках.
Все перечислены в `DELTAS.md` с пометкой стороны.
**А.** Принять поштучно, каждый — своей дельтой с фикстурой.
**Б.** Принять пакетом в волне своей схемы.
*Рекомендация — А:* дельта на кейс — единственное, что отличает «починили»
от «сломали» (§14.2).

**8. QUIC и utls/reality на xray-входе — норма нужна общая.**
LxBox предлагает правило: QUIC-протоколы (hysteria2/tuic) на xray-входе
**не получают** `utls`/`reality` вовсе — маппер не пишет эти пути (`when` по
типу тела), чтобы не порождать код `tls_not_applicable_quic` там, где вход
молчал. У нас **иначе**: hysteria2 идёт через общий `xrayStreamParts`, `tls`
пишется, а срез делает РЕЕСТР кодом `tls_not_applicable_quic` (контракт
1.1.4, `forbidden_for`). Результат расходится: у них кода нет, у нас есть.
**А.** Принять их правило: маппер не пишет — кода нет. Тише, но правило
«срез QUIC» уезжает из реестра обратно в таблицу маппера, раздваивая место
решения.
**Б.** Оставить наше: маппер переводит, реестр судит и ставит код.
*Рекомендация — Б:* это ровно граница «маппер не судит значения» (§2), и
код здесь полезен — он сообщает, что подписка прислала неприменимое поле.
Цена — info-код на узлах, где вход молчал; лечится `when` на СТОРОНЕ ИСТОЧНИКА
(не писать путь, если ключа во входе не было), а не отменой правила реестра.
