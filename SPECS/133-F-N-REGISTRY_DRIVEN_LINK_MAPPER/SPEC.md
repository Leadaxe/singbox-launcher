# SPEC 133 · Маппер ссылок строится ОТ реестра

Статус: **N — ТЗ**. Решение владельца 19.09.2026, **блокер релиза**.
Ветка develop от `5170a169` (контракт `1.1.10`, ядро `1.14.1-lx.4`).

Продолжает **SPEC 131** (`SPECS/131-F-O-UNIFIED_NODE_PIPELINE/`): тот перевёл
в реестр правила **значений** и поставил `nodeflow.Sanitize`/`Emit`.
Здесь — вход **ссылки**: последнее место, где решения живут в коде.

Спутники: `PRIMITIVES.md` (инвентаризация с адресами и выражение примитивами),
`SCHEMES.md` (черновики секций `uri` по схемам — артефакт сверки с LxBox),
`TASKS.md` (волны). Встречная кампания LxBox — их фича 480.

## 1. Зачем

Вход **JSON** идёт картой через реестр: дефект «поле знаем, но не читаем»
там невозможен по построению. Вход **ссылки** — 16 рукописных парсеров
(`node_parser_*.go`) плюс Xray-конвертер (~2100 строк, ~530 из них — чистая
per-scheme развилка), и таблица реестра `uri.*` (имя, `aliases`, `maps_to`,
`emit.param_order`) **не читается кодом вообще**:

- `Registry.MapsTo` (`core/config/registry/registry.go:951`) — заполняется,
  экспонируется и **не вызывается ниоткуда**;
- секции `uri.*`, `mapper`, `emit`, `xray_dialect` в рантайме не участвуют —
  их читает только докогенератор (`contract/tools/gendocs/`);
- `emit.param_order` не читает никто: порядок задаёт `q.Encode()`, то есть
  алфавит `net/url`;
- из всего реестра ссылочный путь берёт ровно одно — `QueryAliases`
  (`uri_params.go:59`).

Отсюда дефекты одного класса — **реестр знает, код не читает**:

| Дефект | Реестр объявляет | Код |
|---|---|---|
| ss `plugin`/`plugin_opts` (SIP003) | `shadowsocks.json:40-52` — и прямо пишет «Go молча теряет query целиком» | слова `plugin` нет во всём `core/` |
| `disable_sni` у tuic и masque | обе схемы, `ext: mobile` | не читает ни одна |
| SS2022 открытый userinfo | кейс корпуса живёт случайно (ключ оказался валидным base64) | безусловный base64-декод |
| `socks4://` | (добавлено в 1.1.x) | раньше не существовало |
| `fp` у hysteria/hy2/tuic | (исправлено в 1.1.4) | раньше не читался |

Последние две строки — уже починенные вручную экземпляры **того же класса**.
Пока таблица не исполняется, каждый следующий параметр повторит их судьбу.

## 2. Решение владельца (19.09.2026)

> «Дать реестру нужное количество примитивов, в коде остаётся только движок,
> общий для всех схем».

Именованные per-scheme крючки в коде — **не** целевая архитектура. Целевое:

| | |
|---|---|
| Реестр | несёт декларативные **примитивы** (13 групп, `SCHEMES.md` §12) |
| Код | **один движок**: `parse` + `emit`, без единого `if scheme ==` и без функций под схему |
| Критерий конца кампании | в пакете маппера нет ни одной схемной функции; все `node_parser_*.go` и `shareuri_*.go` удалены |
| Значения | судит только `nodeflow.Sanitize` — маппер переводит диалект и не судит |
| Норма | общая с LxBox: раскладка уходит в контракт, обе стороны читают одну таблицу |

## 3. Грамматика

Полный словарь примитивов — `PRIMITIVES.md` §1, черновики по схемам —
`SCHEMES.md`. Здесь — принципы.

**Минимализм.** Ничего не изобретается заново: `when`, `any_set`, `aliases`,
`normalize`, `default_when`, `on_invalid`, `format`, `values` — существующие
атрибуты (`registry.go:24-225`), они переиспользуются. `when` расширяется
предикатом `in` и равенством по источнику. Вариантность транспортов уже
разложена в `transports.json` по типам — движок читает её как есть.

**Пространство источников.** Форма (`uri.forms[]`) распаковывает текст в
одно плоское пространство: `scheme`, `authority`, `userinfo[.user|.pass]`,
`host`, `port`, `port_raw`, `path`, `fragment`, `query.X`, `json.X`,
`ini.S.K`. Параметр адресует источник атрибутом `source` — и **это
единственный способ** получить значение.

**13 групп примитивов** (`SCHEMES.md` §12): `forms/decode/reparse`,
`source`, `userinfo`, `value_map`, `selector`+`when`, `sets`/`implies`,
`extract`/`compose`/`split_into`, `list`, `default_from`, `label_fallback`,
`decode_extra`, `emit_*`, расширение `normalize`. Ни одна не названа по
схеме; каждая используется минимум двумя схемами.

## 4. Движок: порядок фаз

Порядок **нормативен** и уходит в `contract/docs/CANON.md` (§10).
Он же — ответ на вопрос LxBox о порядке применения.

```
0. сырой ТЕКСТ ссылки                    ← движок принимает текст, не url.Parse
1. выбор формы (uri.forms[], по порядку, первая сработавшая)
2. decode формы: percent ОДИН РАЗ, base64/json/ini/reparse
   → пространство источников
3. проход A: параметры с selector: true (в порядке объявления)
4. проход B: остальные параметры — source → decode_extra → value_map →
   приведение типа → when по УЖЕ ПОСТРОЕННОМУ телу → maps_to / sets /
   implies / extract
5. label: fragment → path → label_fallback
6. тело (карта sing-box) + Origin
   ↓
7. nodeflow.Sanitize  ← значения судит ТОЛЬКО он
8. nodeflow.Emit      ← порядок ключей тела = body.order
```

**Порядок ключей тела задаёт `body.order` через `Emit`, а не порядок
примитивов.** Это снимает вопрос LxBox (1) целиком: у нас голдены тела уже
не зависят от порядка разбора — так же, как `warnings[]` упорядочены по
`body.order`, а не по порядку обнаружения (W2D_CHANGES §8 п.6).

**Два прохода, а не один** — потому что `when` у зависимого параметра
ссылается на тело, построенное селектором (`transport.type`, `tls.enabled`).
Внутри прохода порядок объявления значим только для селекторов.

**Отказы движка — ровно два**: «форма не распознана» и «синтаксис не
разобрать». Оба — узел в `dropped` с кодом. Молча ронять узел движок не
может; всё прочее — деградация поля санитайзером с кодом.

## 5. Пустое значение

**По умолчанию: пусто = отсутствует.** Это сегодняшнее поведение
(`uri_params.go:36`: `if v != ""`), и корпус на него опирается.
Исключение объявляется **у параметра** (`"empty": "significant"`) — нужно
там, где ядро различает «ключа нет» и «пустая строка» (tristate-поля,
`vless.packet_encoding *string`).

Ответ на вопрос LxBox (3): не «зависит от параметра» в смысле произвола, а
единый дефолт с явным опт-аутом в данных.

## 6. Эмит — та же таблица наоборот

`maps_to⁻¹`, `value_map⁻¹`, `sets` сопоставлением, `compose`, `into⁻¹` у
userinfo, `emit_form`/`form_from`, `param_order`, `emit_when`/`omit_default`.

Эмит — **отдельный осторожный этап** (W7), после того как разбор доказан на
всех схемах. Причины осторожности — оговорки LxBox, у нас подтверждённые:

- их `toUri` — ещё и форма хранения ручных узлов (`origin.raw`);
- корпус знает не-round-trip случаи; у нас они уже перечислены в раннере
  (`contract_emit_test.go:190-217`: D-028 путь с `%2F`, ws-Host из sni);
- лимит длины на выходе **сегодня не проверяется** вовсе
  (`max_uri_length` применяется только на входе, `node_parser_core.go:130-132`).

Эти случаи становятся **данными** (`round_trip: false` с причиной), не кодом.

Известная асимметрия, которую эмит обязан пережить без изменения тел:
`fp=random` не пишется у vless, но пишется у trojan/vmess
(`shareuri_vless.go:49-51` против `shareuri_trojan.go:31-33`);
vmess `httpupgrade → net:"ws"` (`shareuri_vmess.go:70-73`) — неинъективный
`value_map`, ловится линтером; vmess xhttp теряет весь набор полей
(`:74-83`).

## 7. Линтеры (W0, обязательны)

| Линтер | Что ловит |
|---|---|
| у каждого `uri`-параметра есть `source` | «объявлен, но не читается» — весь класс §1 |
| `source` разрешим в пространстве своей формы | опечатка в пути |
| `maps_to` существует в `body.fields` | разъезд с телом |
| `when`/`sets`/`implies` ссылаются на объявленные пути | висячее условие |
| `extract.re` компилируется в RE2 **и** ECMAScript; группы покрыты `into` | разъезд Go/Dart на регулярках |
| `value_map` инъективен у эмитируемой схемы | vmess `httpupgrade→ws` |
| `param_order` покрывает все эмитируемые параметры | молчаливая потеря при эмите |

**«Движок читает только объявленное» обеспечено конструктивно**, а не
грепом: значение доступно лишь через `source`, сырого `url.Values` у движка
нет. Дополнительный греп-страж «нет литералов имён схем в пакете маппера» —
вопрос владельцу (§13, вопрос 4): он раньше отменял сторожевой тест «на
остатки», и формулировку надо согласовать.

## 8. Критерий приёмки схемы

Схема считается переведённой, когда **в одном коммите**:

1. корпус зелёный **без единого изменённого ожидания** — `TestContractCorpusURI`
   и `TestContractCorpusEmitRoundTrip` (334 кейса, из них vless 103,
   wireguard 55, trojan 33);
2. identity живых узлов не сдвинулась — сверка с фикстурами W0.5 (§9.1);
3. рукописный парсер схемы **удалён** (не «оставлен до лучших времён»);
4. `TestCorpusBodiesPassSingboxCheck` зелёный.

Изменение `expected` корпуса **запрещено по умолчанию**, даже когда
рукописный парсер делал заведомую ошибку (ss `plugin`, SS2022, `disable_sni`):
такие исправления меняют тела живых узлов и выносятся **отдельным решением
владельца** (§13, вопрос 2).

## 9. Риски и ловушки

### 9.1. Страховка кампании — фикстуры identity ДО переезда (W0.5)

Предложение стороны LxBox, принимается: снять по всем схемам фикстуры
**старым путём** до первого перевода — тело, tag, label, `origin.raw`,
share-URI, warnings, хеш. Корпус (334 кейса) сравнивает `entry`+`label`, но
**не** сравнивает tag, warnings и round-trip одновременно на одном кейсе;
фикстуры закрывают этот зазор. Это и есть главная страховка: любой сдвиг
identity виден сразу, а не на живой подписке пользователя.

### 9.2. Порядок percent-декодирования

Один раз, до всего. Два узаконенных исключения становятся свойством
параметра, а не поведением кода: `alpn` — декод **до стабилизации, без
ограничения проходов** (`node_parser_transport.go:24-33`); `path` — ровно
2 прохода `PathUnescape` (`:759-776`, D-028). Первое — потенциально
неограниченный цикл; в грамматике он получает явный предел.

### 9.3. `+` в query — риск identity (вопрос LxBox (к))

`url.ParseQuery` превращает `+` в пробел, ломая base64. Сегодня обойдено
**четырьмя точечными заплатами** в трёх файлах (`PRIMITIVES.md` §2), и
покрыты ими ровно четыре параметра: WG `publickey`/`presharedkey`/`privatekey`,
AWG3 `header_protection_key`, masque `publickey`. **Везде остальном — в том
числе у `pbk`, `password`, `obfs-password` — `+` сегодня становится пробелом.**

Единый декодер без замены — правильное поведение и просьба LxBox, но он
меняет значения там, где заплат не стояло. Порядок действий:

1. W0: прогнать корпус с временным флагом «не заменять `+`» и выписать
   кейсы, где меняется тело;
2. если меняются только кейсы с заведомо битым сегодня значением — переход
   идёт как исправление, с фикстурой на каждый;
3. если меняется тело узла, который сегодня рабочий, — стоп и вопрос
   владельцу (это уже не грамматика, а поведение).

Решение не принимать до данных прогона.

### 9.4. Память проекта

| Ловушка | Где отражена |
|---|---|
| ws `?ed=N` жил в 4 слоях (3 парсера + allowlist-эмиттер) | `SCHEMES.md` §11 — одна запись, `extract`+`compose` |
| JSON-карта несёт `float64`/`[]interface{}`; `.(int)`-ассерты теряли поля | приведение типов делает движок по `type`, ассертов в маппере нет |
| эмиттер и парсер ходят парой (masque/anytls/ssh теряли поля) | одна таблица на оба направления; линтер `param_order` |
| Win7 = go1.20 | движок пишется без `slices`/`maps`/`min`/`max` |
| регистр enum-ов ядра case-sensitive | `normalize` только по явному флагу — правило SPEC 131 не меняется |

### 9.5. Прочее

- **Дубли параметров** в query (`?fp=a&fp=b`): сегодня берётся первый
  (`queryGetFold` возвращает `vs[0]`). Норма — фиксируется явно.
- **Регистр имён**: сегодня регистронезависимо (`queryGetFold`), и корпус на
  это опирается (`AllowInsecure=1`, `SNI=` — живые формы). Сохраняется.
- **Приоритет первого распознанного значения**: `fp=qwerty` не должен
  перебивать `fingerprint=firefox` (D-029, `node_parser_transport.go:132-152`)
  — выражается порядком в `source`-списке.
- **`label` из userinfo не берётся никогда** (там секрет,
  `node_parser_core.go:518-530`): в грамматике это не запрет, а факт —
  `label_fallback` не содержит такого источника.

## 10. Норма для LxBox (в CANON)

В `contract/docs/CANON.md` новым разделом — **только то, что обе стороны
обязаны соблюдать одинаково**:

1. порядок фаз движка (§4) и что порядок ключей тела задаёт `body.order`;
2. percent-декод один раз, до всего; `+` не заменяется на пробел (§9.3);
3. «пусто = отсутствует» по умолчанию, опт-аут у параметра (§5);
4. движок принимает сырой **текст**, не разобранный URL-объект;
5. маппер не судит значения — только перевод диалекта;
6. источник метки — `fragment`; фолбэк — по **типу тела** (§13 вопрос 3);
7. семантика `when` (по уже построенному телу), `sets`, `implies`;
8. словарь примитивов и их атрибуты.

Внутренним остаётся: устройство самого движка, имена Go-функций, кэширование
реестра, форма фикстур identity.

## 11. Xray-JSON

Тот же движок: форма без схемы, `space: json`, параметры с
`source: "json.<path>"`. Таблица соответствий — `PRIMITIVES.md` §10.

**Рекомендация: в объёме, но последней волной (W8).** Причины: диалект
изолирован, реестр его уже описывает (`sources: [… "xray"]` у семи схем,
секция `xray_dialect` в `hysteria.json`), а грамматика к тому моменту
проверена на 16 схемах. Вне маппера остаётся не перевод, а **сборка
документа**: `dialerProxy`→цепочки с разрывом колец, два прохода владения,
`balancers[0]`→группа, дедуп и slug тегов (`xray_json_array.go`) — это
работа над массивом узлов и связями, а не над одним узлом.

Так же и распаковщик Amnezia `vpn://` (zlib+base64, выбор контейнера,
плейсхолдеры DNS, `node_parser_amnezia.go:50-460`): остаётся обёрткой над
текстом, выдающей `.conf` тому же движку.

## 12. Вне области

- Правила **значений** — они уже в реестре (SPEC 131), кампания их не трогает.
- MTU-политика WireGuard — перенесена в реестр волной W2d, выражена по телу.
- Дропы узла за негодное значение (битый WG-ключ, пересечение h1–h4,
  AWG3-паддинг) — правила тела, не маппера.
- Изменение формата ссылок и дефолтов — не предмет кампании.

## 13. Вопросы владельцу

**1. Неизвестные параметры ссылки.**
Сегодня молча игнорируются (исключения — `padding` у naive и `ech=`, оба с
кодом). С общим циклом «неизвестный» становится точно определимым.
**А.** Оставить как есть — игнор без кода. Тише, но дефект «панель шлёт
параметр, которого мы не знаем» остаётся невидимым.
**Б.** Info-код `uri_param_unknown` (в UI не показывается, виден в карточке
и диагностике).
*Рекомендация — Б:* именно этот класс мы и чиним, а info-код ничего не
ломает. Цена — шум на подписках с нестандартными параметрами.

**2. Менять ли `expected` корпуса там, где парсер делал заведомую ошибку.**
Найдено пять таких мест (ss `plugin`/`plugin_opts`, SS2022, `disable_sni` у
tuic и masque, masque `insecure=yes`, masque `sni` без алиасов). Исправление
меняет тела живых узлов.
**А.** По умолчанию — нет: кампания переносит решения в данные, поведение не
меняет; каждое исправление едет **отдельным** решением после неё.
**Б.** Чинить сразу, в волне своей схемы, с фикстурой на каждый случай.
*Рекомендация — А:* иначе не отличить «движок сломал» от «движок починил», и
критерий приёмки (§8) теряет смысл.

**3. Фолбэк тега: по схеме или по типу тела.**
Сегодня `generateDefaultTag(scheme, …)` — по **написанию схемы**:
`hy2-…` ≠ `hysteria2-…`, `socks5-…` ≠ `socks-…`. LxBox просит по типу тела.
**А.** Оставить `as_written` — identity живых узлов не двигается.
**Б.** Перейти на `singbox_type` — **переименует существующие узлы** у всех,
кто добавлял ноды по `hy2://`/`socks5://`.
*Рекомендация — А*, с записью нормы в CANON; переход — отдельной задачей с
миграцией, если владелец захочет.

**4. Греп-страж «в пакете маппера нет имён схем».**
Инвариант обеспечен конструктивно (§7), греп — дополнительная страховка.
**А.** Не заводить: владелец раньше отменял сторожевой тест «на остатки».
**Б.** Завести один тест, проверяющий только пакет маппера.
*Рекомендация — Б* в этой кампании: «ни одной схемной функции» — её критерий
конца, и без стража он проверяется глазами на каждом ревью.
