# DELTAS — разрешённые изменения поведения кампании SPEC 133

Единый список. **Любое расхождение с фикстурами identity вне этого файла =
красное** (решение владельца 19.09.2026, вопрос 2 = Б).

Правила работы со списком:

1. фикстуры identity снимаются **старым путём** до первой дельты (W0.5) —
   база сравнения от решения не зависит;
2. `expected` корпуса меняется **отдельным коммитом на каждую дельту**, и
   только в полях, которые дельта называет;
3. дельта без кейса корпуса не принимается: «было→стало» обязано быть
   проверяемым;
4. статус **кандидат** = в код не едет, ждёт решения владельца.

Стороны: **Л** — лаунчер (Go), **X** — LxBox (Dart).

одном `host:port` дают один тег `socks-host-port`. Коллизию разрешит
`MakeTagUnique` суффиксом `-2`/`-3`, но порядок суффиксов зависит от порядка
узлов в подписке — **нестабилен между обновлениями**.

**Миграция состояния (§14.5 SPEC.md) — НЕ НУЖНА, проверено прогоном
19.09.2026.** Вывод обратный тому, что предполагала таблица «Что меняется»
выше: она описывала правило реестра, а не фактический выход парсера.

Проверка — один и тот же набор из 22 ссылок (все 12 «расходящихся»
написаний плюс контроль) прогнан через `subscription.ParseNode` на двух
деревьях: рабочем (`438d5eb6`, движок) и **до кампании** (`28780ce6~1` =
`4a3dbf3f`, рукописные парсеры). Теги совпали **во всех 22 случаях**,
посимвольно. Прогон делался во временном `git worktree` в scratchpad,
рабочая копия не трогалась.

Причина: **старые рукописные парсеры уже строили тег по типу тела**, а не
по написанию ссылки — нормализация написания стояла ДО вызова
`generateDefaultTag`, в самом диспетчере:

| Написание | где нормализовалось (до кампании) | тег тогда и сейчас |
|---|---|---|
| `hy2` → `hysteria2` | `node_parser_core.go:252-253` (`scheme = "hysteria2"`) | `hysteria2-…` |
| `hy` → `hysteria` | `node_parser_core.go:282-287` (`scheme = "hysteria"`) | `hysteria-…` |
| `naive+https` / `naive+quic` → `naive` | `node_parser_core.go:348-351` (`scheme = "naive"`) | `naive-…` |
| `proxy-http(s)` / `proxy+http(s)` → `http` | `node_parser_http.go:92,142` (`generateDefaultTag("http", …)`) | `http-…` |
| `awg` → `wireguard` | `node_parser_wireguard.go:246,253` (`generateDefaultTag("wireguard", …)`) | `wireguard-…` |
| `masque` | `node_parser_masque.go:167` | `masque-…` |

Расходились бы только `ss` и `socks4/4a/5/socks` — и **именно у них
`scheme_source` остался `as_written`** (`shadowsocks.json:325` и `:436`,
`socks.json:216`), сознательно и по той же причине (identity живых узлов).
Полный скан реестра: `as_written` ровно в этих трёх фолбэках, остальные 15
— `singbox_type`, и для них написание = тип тела и до кампании.
`mappers.conf` у wireguard фолбэка со схемой не имеет вовсе (литерал
`WireGuard`).

Следствия:
* **миграция состояния не пишется** — переименовывать нечего, ни один
  сохранённый тег-фолбэк не сдвинулся; `detour`, цепочки, состав групп,
  цели правил, `Source.Skip`, `PendingDisabled` и каталоги Tailscale целы;
* **риск коллизии `socks4`/`socks5` на одном `host:port` не наступил** —
  он возникал бы только при переводе socks на `singbox_type`, а тот
  остался `as_written`. Риск остаётся записанным здесь как цена
  **будущего** снятия per-app override (отдельное решение владельца);
* три `as_written` — не долг и не недоделка волны, а норма: снятие любого
  из них сдвинет identity и потребует той самой миграции.

**Ловушка для читателя реестра:** `impl`-заметка у
`shadowsocks.json:327` начинается словами «scheme_source: singbox_type —
тег безымянного узла `shadowsocks-host-8388`», хотя поле рядом стоит
`as_written`. Первая фраза описывает **отклонённый** вариант, а не
действующий; читать надо со второго предложения. Именно она и породила
таблицу «Что меняется» в этой записи.

### D133-7 · base64-поля читают `+` буквально — **ПРИНЯТО** (рабочее решение 19.09.2026)

Норма **не меняется**: `+` в query = пробел (form-encoding). Так же наш эмит и
**пишет** — все 11 эмиттеров идут через `q.Encode()` (`shareuri_*.go`), а он
кодирует пробел как `+`. Прогон «в двух режимах» и флаг режима **отменены**.

Исключение — **декларативно от реестра**, одно правило вместо четырёх заплат:
у поля с base64-форматом (`format: base64`, `base64_32`) движок читает `+`
буквально. Атрибут `decode.plus_literal`, **выводимый из `format`**, с
возможностью явного указания.

| | |
|---|---|
| Поле | всё с `format: base64*`: WG `privatekey`/`publickey`/`presharedkey`, AWG3 `header_protection_key`, masque `publickey`, REALITY `pbk` |
| Было Л | заплаты покрывают **четыре** параметра (`queryParamPreservePlus` ×2, `queryParamPreservePlusOrGet`, обратная замена `ReplaceAll(v," ","+")`). **`pbk` заплаты не имеет**: `+` в нём становится пробелом → реестр снимает поле по `format` → REALITY деградирует молча |
| Стало Л | `plus_literal` из формата; заплаты удаляются при переходе схемы на движок |
| Было X | заплата **одна** (`headerprotectionkey`); WG/masque-узел с сырым `+` **молча пропадал**, `pbk` снимался |
| Стало X | то же правило из реестра |
| `password` / `obfs-password` / `host` | `+` = пробел, **как сейчас** — тела рабочих узлов не меняются |

Критерий владельца соблюдён: чиним сегодня сломанное (`pbk`, пропадающие
WG/masque-узлы), тела рабочих узлов не трогаем.

### D133-14 · `path` с сырым `+` — **ПРИНЯТО, чинится у ОБЕИХ сторон**

**Проверено запуском, а не чтением кода.** Утверждение «у лаунчера без
изменений» **не подтвердилось**: у нас та же поломка, что у LxBox.

| | |
|---|---|
| Кейс | `uri/trojan/ws_path_plus_literal` — **нужно завести** |
| Вход | `trojan://pw@example.com:443?type=ws&path=/a+b&…` |
| Было Л | `transport.path = "/a b"` — **пробел** |
| Стало Л | `/a+b` |
| Было X | `/a b` |
| Стало X | `/a+b` |

**Почему у нас так, хотя `decodeResidualPercent` использует `PathUnescape`:**
две ступени, и ломает первая. Значение приходит из `url.ParseQuery`
(form-encoding: `+` → пробел) **до** того, как его увидит
`decodeResidualPercent`; тот честно сохраняет `+`, но сохранять уже нечего.
Проверка: `ParseQuery("path=/a+b")` даёт `/a b`, а
`decodeResidualPercent("/a+b")` даёт `/a+b`.

В движке ступени нет: `ParseQueryOrdered` не заменяет `+` на уровне
пространства, а форм-семантику применяет ЗАПИСЬ (`PlusToSpace`) — и только
там, где `plus_literal` не объявлен. Для `path` объявлен `mode: "path"`,
то есть `+` литерален. Норма (D133-7) при этом не меняется: в query `+` —
по-прежнему пробел.

### Открытый пункт · эвристика SNI у trojan — **НЕ снимать, вопрос владельцу**

LxBox просит **не включать** в норму фолбэк `server → tls.server_name` при
отсутствии `sni`. **У нас он есть** (`node_parser_transport.go:1042-1045`) и
**корпус на нём стоит**: `uri/trojan/basic_password` не несёт `sni=`, а
ожидание — `tls.server_name: "example-1.com"` (= `server`). То же
`default_port_443` и другие.

Снятие изменило бы тела **рабочих** узлов → критерий владельца нарушен.
`default_from: "host"` в секции **сохраняет наше поведение**; LxBox тогда
расходится.

**Решение владельца требуется** — вынесено вопросом `SPEC.md` §15.9.

### D133-15 · ssh `private_key`: PEM читается форматом, а не флагом — **ПРИНЯТО**

Находка 2 LxBox. `plus_literal` на всё поле негоден: `+` в PEM несёт **два
смысла** — пробел в заголовочных строках `-----BEGIN …-----` и литерал в
base64-теле. Примитив — `format: "pem"` (`PRIMITIVES.md` §0.4a).

| | |
|---|---|
| Кейс | `uri/ssh/pem_percent_encoded` — **нужно завести**, сегодня такого нет |
| Вход | `ssh://u@h:22?private_key=-----BEGIN+OPENSSH+PRIVATE+KEY-----%0Ab3Blb…+A/B%0A-----END+OPENSSH+PRIVATE+KEY-----` |
| Было Л | `+` → **пробел везде**: заголовок случайно верен, **тело ключа испорчено**. Заплаты у ssh нет — значение идёт из `parsedURL.Query()` (`node_parser_ssh.go:32`, `node_parser_core.go:415`) |
| Стало Л | заголовок с пробелами, тело с литеральными `+` |
| Было X | та же поломка (их фикстура `pem_percent_encoded` ждёт заголовок с пробелами) |
| Стало X | то же правило из реестра |

Почему дыра не видна сегодня: round-trip зелёный, потому что наш эмиттер
пишет `+` как `%2B` (`shareuri_ssh.go:125` → `q.Encode()`); ломается только
**чужая** ссылка с сырым `+`. Критерий соблюдён — чиним молча теряемое.

### D133-26 · `dialer#uri` у vless/trojan + голые секунды судит ТЕЛО — **ПРИНЯТО**

Две половины одной пачки: дочитать то, что молча игнорировалось, и увести
нормализацию написания туда, где она действует на всех входах.

**1. `include dialer#uri` у vless и trojan.** Записи `tcp_keep_alive`,
`tcp_keep_alive_interval`, `disable_tcp_keep_alive` объявлены в
`dialer#uri` с D133-19 и подключены у семи схем (anytls, http, naive,
shadowsocks, socks, ssh, vmess). У **vless и trojan** блок не подключался —
у самой частой пары схем параметры ссылки уезжали в никуда. Это «чтение
ранее молча игнорируемого»: тело узла без этих параметров не меняется,
узел с ними получает три новых поля. Единообразно с LxBox.

**2. `normalize: duration_bare_seconds` переезжает из маппера в
`body.fields`** — следом за `cidr_prefix` и `base64_std` (D133-22) и по той
же причине: это правило **значения**, а не построения тела, и живя в
маппере оно действовало на одном входе из трёх. Голые секунды приезжают

- со **ссылки** (`heartbeat=10`, `idle_session_timeout=30`),
- из **Xray-sockopt** (`tcpKeepAliveIdle: 30` — ЧИСЛОМ, не строкой),
- из **тела в форме ядра** (вход `singbox`, чужой конфиг).

Перенесено у пяти полей: `dialer.body` `tcp_keep_alive` /
`tcp_keep_alive_interval`, `tuic.heartbeat`, `anytls`
`idle_session_check_interval` / `idle_session_timeout`. В маппере имя
осталось только как legacy в описании схемы.

**Негодное ПОСЛЕ нормализации снимается с кодом `type_invalid`** — общим
правилом `duration`, отдельного правила не заводится. У LxBox сегодня такое
значение уходит молча; дельту «молча → с кодом» они принимают (§24.33).

**Голое число из JSON** (`float64`) нормализуется только у поля, объявившего
`duration_bare_seconds`: без объявления число у `duration` по-прежнему
негодно, иначе единица измерения угадывалась бы за источник.

Корпус: `uri/vless/dialer_keepalive`, `uri/trojan/dialer_keepalive_disabled`,
`uri/anytls/idle_session_bare_seconds`. У keep-alive корпусного покрытия не
было вовсе — D133-19 влили без единого кейса.

### D133-27 · Вход Xray на движке: keep-alive из sockopt, `alter_id: 0`, массив `host` — **ПРИНЯТО**

- порядок чтения версии — сперва `streamSettings.hysteriaSettings.version`,
  и ЛИШЬ при его отсутствии `settings.version`;
- отсутствие версии в обоих местах = v1;
- версия, написанная СТРОКОЙ (`"2"`), двойкой не считается и ведёт в v1:
  `xrayJSONInt` строк не читал, и предикат теперь тоже не приводит типы
  (расширение `value_of`, TASKS_LXBOX §26 п.1).

**Расхождение с LxBox — не дельта, а разная поддержка.** Их черновик
роняет `version: 1` кодом `protocol_unsupported`: своего Spec под v1 у них
нет. У лаунчера v1 живой (`auth_str`, `up_mbps`, `down_mbps`), и секция
заведена под наше поведение — принять их ветку значило бы потерять
рабочие узлы.

### D133-29 · Порт `ss` по умолчанию 443 → 8388 — **РЕШЕНИЕ ВЛАДЕЛЬЦА**

**Что меняется:** `mappers.uri.defaults.server_port` у shadowsocks:
`443` → `8388` (канонический порт shadowsocks).

**Откуда взялось 443:** не из решения, а из общего умолчания старого
кода: `node_parser_core.go:145` ставил 443 ВСЕМ схемам, и ss-ветка его не
переопределяла — в отличие от socks и ssh, где это сделано явно. То есть
наш дефект, а не диалект.

**Почему не ловилось:** ни одна из девяти фикстур `uri/shadowsocks` порт
не опускает. Дефолт не исполнялся НИГДЕ, и разойтись с ожиданием было не
с чем — ровно «данные без исполнителя» (Q133-59) в третий раз за кампанию.

**Что сделано вместе со сменой:** заведён кейс
`uri/shadowsocks/no_port_default_8388` — ссылка без порта. Проверено
фактом: возврат дефолта на 443 роняет корпус (5 подтестов), возврат на
8388 — зелено. Теперь у решения есть сторож.

**Влияние на живые узлы:** нулевое для существующих. Тег и тело меняются
только у узла, чья ссылка порт НЕ несёт; такие узлы прежде молча получали
443 и не соединялись никуда — 443 у ss-сервера означает совпадение,
а не норму.

**Встречная сторона:** у LxBox дефолт проверить отдельно; если там 8388
стоял всегда, это расхождение закрывается нашей правкой.

### D133-30 · Необъявленный ключ даёт код НА КАЖДОЕ имя, а не один на узел — **ПРИНЯТО**

**Что меняется:** ссылка с двумя необъявленными параметрами получает два
`uri_param_unknown` вместо одного; имя параметра едет в `path`, порядок —
появления в источнике.

**Почему это дефект, а не ужесточение:** дедуп деградаций узла идёт по
паре (`Code`, `Path`) — `ParsedNode.addWarning`. Код движка ставился с
пустым путём, поэтому ВТОРОЙ и все последующие незнакомые параметры той же
ссылки схлопывались в первый и исчезали без следа. Код заведён ровно
против молчаливой потери — и терял молча сам.

**Кто это видел:** корпус. `uri/naive/unknown_query_ignored` несёт
`?unknown=42&also_unknown=foo`, а ожидание фиксировало ОДИН код —
то есть зелёный прогон подтверждал дефект как норму.

**Влияние на живые узлы:** тела не меняются (необъявленный параметр в
тело не едет по построению). Меняется число деградаций у узла и их `path`.

**Встречная сторона:** норма согласована с LxBox до правки.

### D133-31 · `json_field_unknown` начал ставиться — **ПРИНЯТО**

**Что меняется:** элемент JSON-тела (Xray, sing-box) с ключом верхнего

### D133-32 · Коды с `maps_to: null` несут `path` — **ПРИНЯТО**

### D133-33 · Негодный ЭЛЕМЕНТ списка выбрасывается сам, не забирая соседей — **ПРИНЯТО**

### D133-34 · `public_key` REALITY канонизируется в RawURL — **ПРИНЯТО**

**Где:** `ini.first_section_fold: "interface"` у вида `wireguard_conf`.

**Что меняется:** `looksLikeWGConf` (`body_classify.go:131`) требовал НАЛИЧИЯ

(например, инструкция провайдера со ссылками сверху), больше не объявляется

**Наблюдаемо:** кейсы «wg-quick .conf», «комментарий над [Interface] не
мешает», «заготовка .conf без [Peer]» раннера `TestSourceKinds`.
**ДОСНЯТО позже (волна эмита):** тем же прогоном `-update` дописан `path` в
восьми ожиданиях, до которых обновление не дошло в свой заход —
`uri/naive/canonical_full`, `fragment_utf8_escaped`,
`https_anonymous_padding_true`, `https_userpass_padding_false`
(`naive_padding_ignored` → `path: "padding"`),
`uri/trojan/ech_bare_name_ignored`, `ech_name_resolver_ignored`,
`uri/vless/ech_ignored_reality_kept` (`ech_ignored` → `path: "ech"`),
`uri/masque/legacy_params_ignored` (`uri_param_unknown`). Поведение не
менялось — код `path` ставил и тогда; расхождение просто не было снято
прогоном, и ожидания описывали мир до D133-32. Урок тот же, что в
«Рекомендациях» §5: ожидания снимаются прогоном, а не дописываются руками
по списку затронутых файлов — список забывается.

## Обратный ход: отличия движка от рукописного эмита

Машинный список — `core/config/linkmap/testdata/emit_deltas_allowed.json`
(отличия от снимка) и `emit_round_trip_deltas_allowed.json` (отличия на
круге). Оба судятся **в обе стороны**: объявленный кейс обязан отличаться.

Списки раздельные потому, что кейс бывает ровно одним из двух — ссылка
совпала, а круг разошёлся, или наоборот. Один список требовал бы от такого
кейса отличаться там, где он совпадает.

### D133-E1 · `security` пишется явно — **ПРИНЯТО**

**Что меняется:** vless/trojan/anytls пишут `security=tls` (`=none`,
`=reality` — см. ниже) там, где рукописный эмиттер молчал.

**Зачем:** у Xray-клиентов умолчание `security` у vless — `none`, и узел без
явного параметра прочтётся БЕЗ TLS. Норма: вид ссылки есть де-факто формат
схемы для ЧУЖИХ клиентов, а не симметрия таблицы (решение владельца).

**Исключение:** `security=reality` у vless НЕ пишется
(`omit_default: ["security:reality"]`) — REALITY-ветку в ссылке объявляет
наличие `pbk`, и второе имя того же факта только путает.

**Кейсов:** 42.

### D133-E2 · Имя флага insecure — свойство СХЕМЫ — **ПРИНЯТО**

**Что меняется:** `allowInsecure` у vless/trojan/http, `allow_insecure` у
tuic (было единое `insecure`).

**Зачем:** единое `insecure` читают не все клиенты; написание принадлежит
схеме, а не общему блоку `tls#uri`. Оверлей LxBox, принят как есть.

**Кейсов:** 5.

### D133-E3 · Пробел на выходе — `%20` — **ПРИНЯТО**

**Зачем:** норма PRIMITIVES §0.6. В ПУТИ чужой клиент читает `+`
буквально, и `/ws+v2` уезжает сервером как есть — 404 при живом узле.

**Кейсов:** 14 (ssh `host_key`, naive `extra-headers`, http `headers`,
vless `encryption`, wireguard `i1`…`i5`).

### D133-E4 · ПОЧИНКА: keep-alive не писался вовсе — **ПРИНЯТО**

### D133-E5 · ПОЧИНКА: имена xhttp — написание Xray — **ПРИНЯТО**

**Зачем:** `zero_rtt_handshake` — имя ТЕЛА, а не ссылки; ссылочное имя

### D133-39 · Порядок `warnings[]`: маппер впереди санитайзера — **ПРИНЯТО**

**Что меняется:** норма закреплена в CANON §6: коды записей маппера с

### D133-40 · `wgconf_dns_ignored` и `xray_extra_entries_dropped` несут `value` — **ПРИНЯТО**

**Что меняется:** раннер конверта переносит `params.value` маппера в поле
`value` ожидания (`on_present` / `on_len_gt`). Ожидания дополнены:
`uri/wireguard/amnezia_vpn_awg*`, `awg_conf_base64*`, `body/wgconf/ini_basic`,
`body/vpn/multi_container`, `body/xray/vless_extra_vnext`.

**Кейсов:** 7.

### D133-41 · `merge: append`/`prepend` действительно сливает списки — **ПРИНЯТО**

**Что меняется:** `merge` у занятого пути исполняется движком, а не только
разрешает запись. `append`/`prepend` конкатенируют СПИСКИ (у скаляра и у
пути другой формы побеждает пришедшее — как при `overwrite`: merge решает
спор за путь, а не меняет его тип). До правки обе формы вели себя как
`overwrite`: у hysteria/hysteria2 запись `mport` вытесняла диапазоны,
записанные селектором `$multiport` из authority, и `host:443,20000-30000`
вместе с `?mport=` терял половину port-hopping'а молча, без кода.

**Кейсов:** 1 (`uri/hysteria2/mport_and_authority_range` — заведён;
круг `parse(emit(body)) == body` на нём сходится: эмит пишет весь список
в `mport`, authority остаётся одним портом — у `$multiport` объявлен
`round_trip: false`).

### D133-42 · Двойная base64-обёртка раскрывается до `max_unwrap_depth` — **ПРИНЯТО**

**Что меняется:** `requires_after_unwrap` больше не гасит цикл `redetect`
на ПРОМЕЖУТОЧНОМ слое. Промежуточный слой двойной обёртки — чистый алфавит
base64: в нём нет ни `://`, ни `{`, ни `[Interface]`, и правдоподобие
проваливается, хотя документа мы ещё просто не достигли. Отличает этот
случай от «обёртки не было» повторный детект: распакованное снова выиграл
ТОТ ЖЕ вид — значит, оболочка не кончилась, и цикл продолжается. Предел
`max_unwrap_depth` (D133-35) впервые достижим: на третьей обёртке
классификация отказывает тихо, `UnwrapFailed` = имя распаковщика,
элементов нет — ни паники, ни рекурсии. До правки двойная подписка
уезжала в `uri_lines` одним элементом-блобом (ноль узлов).

**Кейсов:** 2 в раннере `TestSourceKinds` (двойная обёртка, тройная).

### D133-43 · BOM снимается на входе определения вида — **ПРИНЯТО**

**Что меняется:** `NewContent` срезает `U+FEFF` в начале текста. BOM —
мусор кодировки файла, а не признак формата: невидимый префикс сдвигает
первый значащий символ, и документ, начинающийся с `{` или `[Interface]`,
переставал быть таковым сразу для ВСЕХ предикатов (`prefix_trim`,
`first_section_fold`) — JSON и `.conf` уезжали в построчную ветку. Старый
`body_classify.go` болел тем же, так что это не регрессия, а общая дыра;
место снятия одно, потому что признак общий.

**Кейсов:** 2 в раннере `TestSourceKinds` (BOM перед JSON, BOM перед `.conf`).

### D133-44 · Детерминизм и латентные дефекты исполнителя — **ПРИНЯТО**

**Что меняется:** три правки без наблюдаемого сегодня эффекта, каждая —
закрытая дыра нормы, а не поведение.

1. `applyLabel`: замены `label.value_map` шли обходом Go-карты — при
   пересекающихся ключах исход зависел от запуска. Порядок теперь тот же,
   что у префиксов `value_map`: длинный ключ раньше короткого, равные
   длины — алфавитом. Норма §7 «Детерминированность» этого требовала, в
   реестре сегодня одна запись (`🇪🇳→🇬🇧` у hysteria2).
2. `applyOnLenGt`: `return` вместо `continue` обрывал цепочку
   АЛЬТЕРНАТИВНЫХ источников на первом существующем — следующее имя могло
   оказаться тем самым длинным массивом. Сегодня у всех записей
   `on_len_gt` источник один.
3. `decodeOnce`: параметр `mode` был мёртв (обе ветки возвращали одно и
   то же) — снят вместе с комментарием, описывавшим несуществующее
   различие. Разницу «путь против query» несёт `plus_literal`:
   percent-декод к `+` не прикасается вовсе, и знак решается ОДИН раз,
   декодером формы.

### D133-45 · Xray dialerProxy → freedom с fragment — не хоп — **ПРИНЯТО**

**Что меняется:** цель `streamSettings.sockopt.dialerProxy` с протоколом
`freedom` и `settings.fragment` больше не трактуется звеном цепочки.
Узел-владелец остаётся прямым; при `tls.enabled` включается

Прочие служебные цели (blackhole, dns, loopback) — отбраковка как раньше.

### D133-46 · Xray dialerProxy → freedom: код `xray_fragment_mapped` снят — **ПРИНЯТО**

**Что меняется:** норма D133-45 без изменений (`tls.fragment=true` молча при
`settings.fragment` и включённом TLS). Код `xray_fragment_mapped` снят
решением владельца: Xray режет ClientHello вслепую по length и ждёт
фиксированный interval; sing-box парсит ClientHello, режет каждую метку SNI
(public suffix не трогается), включает TCP_NODELAY, ждёт ACK или
`fragment_fallback_delay` (500 мс по умолчанию); `record_fragment` — тот же
разрез на уровне TLS-записей. Механика ядра строго лучше, потери поведения
нет — предупреждать не о чем.

**Кейсов:** 1 (тот же `body/xray/dialer_proxy_freedom_fragment`, ожидания без
warnings).

### D133-47 · XHTTP `extra`: proto-имена Xray как алиасы канона — **ПРИНЯТО**

**Что меняется:** записи `sessionPlacement` и `sessionKey` читают в `source`
дополнительно написание Xray-прото — `sessionIDPlacement` и `sessionIDKey` —
во всех трёх входах: URI `extra`, URI `query` и Xray-JSON `extra`
(`xhttpSettings` и `splithttpSettings`). Канон sing-box перечислен ПЕРВЫМ:
когда рядом лежат оба написания, побеждает канон. До правки идентификатор
сессии живой ссылки уходил в дефолт ядра `path`, хотя сервер ждал cookie
с кастомным ключом; `seqPlacement`/`seqKey` доезжали и раньше — у них имена

означает «не задано», а протащить одно поле пары без второго — отказ ядра

читается только там, где канона нет.
