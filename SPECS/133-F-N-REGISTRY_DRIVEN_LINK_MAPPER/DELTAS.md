# DELTAS — разрешённые изменения поведения кампании SPEC 133

Единый список. **Любое расхождение с фикстурами identity вне этого файла =
красное** (решение владельца 19.09.2026, вопрос 2 = Б).

Правила работы со списком:

1. фикстуры identity снимаются **старым путём** до первой дельты (W0.5) —
   база сравнения от решения не зависит;
2. `expected` корпуса меняется **отдельным коммитом на каждую дельту**, и
   только в полях, которые дельта называет;
3. дельта без кейса корпуса не принимается: «было→стало» обязано быть
   проверяемым;
4. статус **кандидат** = в код не едет, ждёт решения владельца.

Стороны: **Л** — лаунчер (Go), **X** — LxBox (Dart).

## Принятые (рабочие решения 19.09.2026, вечер)

### D133-7 · base64-поля читают `+` буквально — **ПРИНЯТО** (рабочее решение 19.09.2026)

Норма **не меняется**: `+` в query = пробел (form-encoding). Так же наш эмит и
**пишет** — все 11 эмиттеров идут через `q.Encode()` (`shareuri_*.go`), а он
кодирует пробел как `+`. Прогон «в двух режимах» и флаг режима **отменены**.

Исключение — **декларативно от реестра**, одно правило вместо четырёх заплат:
у поля с base64-форматом (`format: base64`, `base64_32`) движок читает `+`
буквально. Атрибут `decode.plus_literal`, **выводимый из `format`**, с
возможностью явного указания.

| | |
|---|---|
| Поле | всё с `format: base64*`: WG `privatekey`/`publickey`/`presharedkey`, AWG3 `header_protection_key`, masque `publickey`, REALITY `pbk` |
| Было Л | заплаты покрывают **четыре** параметра (`queryParamPreservePlus` ×2, `queryParamPreservePlusOrGet`, обратная замена `ReplaceAll(v," ","+")`). **`pbk` заплаты не имеет**: `+` в нём становится пробелом → реестр снимает поле по `format` → REALITY деградирует молча |
| Стало Л | `plus_literal` из формата; заплаты удаляются при переходе схемы на движок |
| Было X | заплата **одна** (`headerprotectionkey`); WG/masque-узел с сырым `+` **молча пропадал**, `pbk` снимался |
| Стало X | то же правило из реестра |
| `password` / `obfs-password` / `host` | `+` = пробел, **как сейчас** — тела рабочих узлов не меняются |

Критерий владельца соблюдён: чиним сегодня сломанное (`pbk`, пропадающие
WG/masque-узлы), тела рабочих узлов не трогаем.

### D133-14 · `path` с сырым `+` — **ПРИНЯТО, чинится у ОБЕИХ сторон**

**Проверено запуском, а не чтением кода.** Утверждение «у лаунчера без
изменений» **не подтвердилось**: у нас та же поломка, что у LxBox.

| | |
|---|---|
| Кейс | `uri/trojan/ws_path_plus_literal` — **нужно завести** |
| Вход | `trojan://pw@example.com:443?type=ws&path=/a+b&…` |
| Было Л | `transport.path = "/a b"` — **пробел** |
| Стало Л | `/a+b` |
| Было X | `/a b` |
| Стало X | `/a+b` |

**Почему у нас так, хотя `decodeResidualPercent` использует `PathUnescape`:**
две ступени, и ломает первая. Значение приходит из `url.ParseQuery`
(form-encoding: `+` → пробел) **до** того, как его увидит
`decodeResidualPercent`; тот честно сохраняет `+`, но сохранять уже нечего.
Проверка: `ParseQuery("path=/a+b")` даёт `/a b`, а
`decodeResidualPercent("/a+b")` даёт `/a+b`.

В движке ступени нет: `ParseQueryOrdered` не заменяет `+` на уровне
пространства, а форм-семантику применяет ЗАПИСЬ (`PlusToSpace`) — и только
там, где `plus_literal` не объявлен. Для `path` объявлен `mode: "path"`,
то есть `+` литерален. Норма (D133-7) при этом не меняется: в query `+` —
по-прежнему пробел.

### Открытый пункт · эвристика SNI у trojan — **НЕ снимать, вопрос владельцу**

LxBox просит **не включать** в норму фолбэк `server → tls.server_name` при
отсутствии `sni`. **У нас он есть** (`node_parser_transport.go:1042-1045`) и
**корпус на нём стоит**: `uri/trojan/basic_password` не несёт `sni=`, а
ожидание — `tls.server_name: "example-1.com"` (= `server`). То же
`default_port_443` и другие.

Снятие изменило бы тела **рабочих** узлов → критерий владельца нарушен.
`default_from: "host"` в секции **сохраняет наше поведение**; LxBox тогда
расходится.

**Решение владельца требуется** — вынесено вопросом `SPEC.md` §15.9.

### D133-15 · ssh `private_key`: PEM читается форматом, а не флагом — **ПРИНЯТО**

Находка 2 LxBox. `plus_literal` на всё поле негоден: `+` в PEM несёт **два
смысла** — пробел в заголовочных строках `-----BEGIN …-----` и литерал в

| | |
|---|---|
| Кейс | `uri/ssh/pem_percent_encoded` — **нужно завести**, сегодня такого нет |
| Вход | `ssh://u@h:22?private_key=-----BEGIN+OPENSSH+PRIVATE+KEY-----%0Ab3Blb…+A/B%0A-----END+OPENSSH+PRIVATE+KEY-----` |
| Было Л | `+` → **пробел везде**: заголовок случайно верен, **тело ключа испорчено**. Заплаты у ssh нет — значение идёт из `parsedURL.Query()` (`node_parser_ssh.go:32`, `node_parser_core.go:415`) |
| Стало Л | заголовок с пробелами, тело с литеральными `+` |
| Было X | та же поломка (их фикстура `pem_percent_encoded` ждёт заголовок с пробелами) |
| Стало X | то же правило из реестра |

Почему дыра не видна сегодня: round-trip зелёный, потому что наш эмиттер
пишет `+` как `%2B` (`shareuri_ssh.go:125` → `q.Encode()`); ломается только
**чужая** ссылка с сырым `+`. Критерий соблюдён — чиним молча теряемое.

### D133-16 · vmess: истинность `tls` разведена по формам — **ПРИНЯТО, односторонняя**

Находка 3. У нас формы **уже разные**, и это надо сохранить, а не свести:

| Форма | Истина `tls` | Адрес |
|---|---|---|
| v2rayN JSON | **строго строка `"tls"`**; `"1"`, `"true"`, `"TLS"`, булев `true` TLS **не включают** | `node_parser_vmess.go:288` |

**`SCHEMES.md` сводить эти две в одну таблицу не должен** — проверено,

### D133-18 · http: `extra-headers` — алиас `headers` — **ПРИНЯТО**

Находка 5. У нас теряется так же, но иначе, чем описал LxBox:

| Схема | Читаемое имя | Адрес |
|---|---|---|
| `proxy-http(s)://` | **только `headers`** | `node_parser_http.go:115` |
| `naive://` | **только `extra-headers`** | `node_parser_naive.go:137` |

Разбор у обеих схем **общий** (`parseNaiveExtraHeaders`, вызов из http на
`node_parser_http.go:119`) — расходятся только имена. Ссылка с
`?extra-headers=` на http-прокси теряет заголовки молча, и код сюда
намеренно не ставится (`node_parser_http.go:116-118`).

Дельта: `extra-headers` становится **алиасом** `headers` у http.
Каноническое имя (для эмита) — `headers`, первое в `aliases`: тела рабочих
узлов не меняются, добавляется только принимаемое написание.

**Уточнение к формулировке LxBox:** наш корпус
`uri/http/proxy_http_path_headers` шлёт именно `headers=` и заголовки **не**
теряет — «теряются целиком на обеих фикстурах» относится к их b480-кейсам,
не к общей норме.

### D133-19 · общие блоки: цепочки SNI, `fp` у anytls, keep-alive у dialer — **ПРИНЯТО**

Находка 6. Правки **добавлением** в `tls.json` / `transports.json` /
`dialer.json`, существующие записи не трогаются:

- **цепочка SNI — вариантами блока**, а не одной записью: `tls#uri`
  остаётся `sni → peer` (как сейчас), добавляется `tls#uri_with_host`
  (`sni → peer → host`) для http. Причина различия не стилистическая: у
  vmess/anytls `host` адресует **транспорт**, а не TLS
  (`node_parser_core.go:866-873`), и общая цепочка с `host` увела бы
  transport-host в `server_name`;
- **`fp` у anytls**: алиас `fingerprint` и дефолт — из `tls#uri`, отдельной
  записи у протокола не заводится;
- **`dialer#uri` / `dialer#xray`**: добавляются `tcp_keep_alive`,
  `tcp_keep_alive_interval`, `disable_tcp_keep_alive`. Поля у ядра есть и в
  `dialer.json` `body` уже описаны (контракт 1.1.6) — не хватало только
  **исполняемых** записей. Лаунчер их сегодня не читает ни из одной ссылки:
  дельта односторонняя, тела рабочих узлов не меняются.

### D133-20 · `uri_param_unknown` начинает звучать — **ПРИНЯТО** (SPEC §14.1, вопрос 1 = Б)

Код был решён владельцем ещё при постановке, но до перевода схемы на движок
его **некому было ставить**: рукописный путь неизвестные параметры ссылки
молча игнорировал. Первый узел, где он зазвучал, — `naive` с
`?unknown=42&also_unknown=foo`.

| | |
|---|---|
| Было Л | неизвестный параметр ссылки теряется молча, узел выходит без кодов |
| Стало Л | **info**-код `uri_param_unknown` с `query_name` параметра |
| Тела узлов | **не меняются** — код это деградация, а не поле |
| Корпус | `uri/naive/unknown_query_ignored` — ожидание пересниято |

Оговорки §3B.2 работают и снимают ложный шум: параметры общих блоков
считаются объявленными, `extra` у xhttp объявлен своим `overlay`, записи со
значением `null` (`spx`, `echfq`) — «знаем, читать нечего». Без них код
звучал бы на каждом втором узле, и первый прогон продакшен-пути это показал
(13 кейсов из 19 красных были ровно им).

### D133-21 · снятые написания masque ЗВУЧАТ — **ПРИНЯТО** (следствие D133-20)

Контракт 0.8.0 (D-078) снял у masque приём legacy-написаний `?network=` и
`?server_name=`: `network=h2` рядом с `vhttp` уронило бы ядро fail-fast'ом.
Снятие было правильным, а вот МОЛЧАНИЕ при нём — нет: параметр исчезал, и
человек не узнавал, что написанное им в ссылке не доехало.

Секция LxBox объявляет их записью `$legacy_flat` с
`on_present: {action: note, code: uri_param_unknown}` — то есть ровно тем же
кодом, что и любой другой нечитаемый параметр. Это честно: написание снято,
значит параметр нам и вправду неизвестен.

| | |
|---|---|
| Было Л | `?network=`/`?server_name=` исчезают молча |
| Стало Л | **info**-код `uri_param_unknown` |
| Тела узлов | **не меняются** — код это деградация, а не поле |
| Корпус | `uri/masque/legacy_params_ignored` — ожидание переснято |

### D133-22 · `base64_std` и `cidr_prefix` переезжают в ТЕЛО — **ПРИНЯТО**

Обе операции правят ЗНАЧЕНИЕ, а не написание ссылки, и потому принадлежат
реестру тела, а не мапперу (`SPEC 133` §6.0, `GRAMMAR_SYNC` §9 п. 3–4). До
сих пор они жили рукописными `normalizeWGKey` и `normalizeWGPrefixes` в
парсере ССЫЛКИ — то есть не работали на входе `singbox`. Это ровно
расхождение входов из находок №4/№5 `LEGACY_AUDIT`, только не пойманное
раньше.

После переезда обе действуют на ВСЕХ входах:

| | |
|---|---|
| Было Л | ключ url-safe/без паддинга канонизируется **только** из ссылки; голый адрес достраивается **только** из ссылки |
| Стало Л | то же на всех входах, включая тело `singbox` и `.conf` |
| Тела узлов | **меняются** у узлов, приехавших телом sing-box с неканоническим ключом либо адресом без префикса |

**Про identity.** Идентичность узла сегодня — **тег** (`SPEC 112`, память
`node-identity-is-tag`), и его канонизация ключа не трогает.
`LegacyNodeIdentityHash` хеширует тело и потому у таких узлов сдвинется —
но это УПРАЗДНЁННАЯ идентичность, живущая только ради разового
сопоставления отметок при миграции состояния старой схемы, и её расхождение
у «здоровых узлов, приведённых конвейером иначе» владелец уже принял
(`node_hash.go:109-124`, 74 узла из 305 на корпусе). Новых оснований для
решения здесь нет: класс тот же.

Адрес без префикса ядро не принимает вовсе (`netip.ParsePrefix: no '/'` —
фатал на весь конфиг), так что для `cidr_prefix` альтернатива переезду —
оставить вход `singbox` заведомо нерабочим.

### D133-23 · `preshared_key` у wireguard читался только Dart — **ПРИНЯТО**

Реестр объявлял алиас (`uri.query.presharedkey.aliases`), а парсер Go читал
только `presharedkey` слитно. Ссылка с `?preshared_key=…` отдавала узел
**без PSK, молча**: туннель поднимается, сервер ждёт общий ключ, данные не
идут. Секция объявляет оба написания.

| | |
|---|---|
| Было Л | `preshared_key` игнорируется, PSK теряется без кода |
| Стало Л | читается, как у LxBox |
| Тела узлов | **меняются** у узлов из ссылок с этим написанием (появляется `peers[].pre_shared_key`) |
| Кейс | `uri/wireguard/uri_psk_keepalive` — ожидание перегенерировано |

### D133-24 · Хост `Endpoint` в цепочке метки `.conf` — **PER-APP**

Норма общей секции: `label.source = ["ini.$comment.Peer", "hint",
<звено хоста Endpoint>]`, `fallback: "WireGuard"`.

Первые два звена у сторон совпадают. Источник **`hint`** (имя от
вызывающего — файл, импорт, сохранённый тег) принят в грамматику как
**НЕОБЯЗАТЕЛЬНЫЙ**: не передан или пуст после нормализации — звено
пропускается. Лаунчер его не передаёт.

Третье звено, **хост `Endpoint`**, у нас исполняется, у LxBox снимается
оверлеем: их безымянный `.conf` становится литералом «WireGuard», наш —
адресом сервера. Корпус ждёт наш (`awg_conf_base64_no_label` → метка
`91.247.235.94`), и включать литерал значило бы переименовать живые узлы.
Класс тот же, что у `socks5` и `ws_ed`.

Читается звено из **тела** (`peers[].address`), а не из входа: во входе
`Endpoint` лежит целиком, «91.247.235.94:51821», и сырое звено дало бы узлу
имя вместе с портом. Хост из него уже выделен выемкой, и резать значение
второй раз своим правилом незачем.

### D133-25 · Коды, объявленные и никогда не ставившиеся, заработали — **ПРИНЯТО**

Не новые правила, а включение уже написанных: оба кода объявлены в
`warnings.json` с полным человеческим текстом, и ни один не ставился.

| Код | Где теперь ставится | Что изменилось в конверте |
|---|---|---|
| `wgconf_dns_ignored` | запись `dns` секции, `on_present` | `.conf`, `awg://<base64>` и `vpn://`-профиль — 7 ожиданий корпуса |
| `awg3_random_trailers_wide_headers` | связь `cooccurrence` + `$range_width` | на ВСЕХ входах, включая `singbox`; прежде рукописное правило работало только на ссылке |

Тела узлов не меняются ни у одного: оба кода информационные и ничего не
снимают. Заведён кейс `uri/wireguard/awg3_random_trailers_wide_headers` —
прежде у правила не было корпусного покрытия вовсе.

Дельта **D133-6** (фолбэк тега) — единственная, меняющая **identity** (тег);
остальные меняют только содержимое тела.

**Проверено по коду, вошло в решения:**
`q.Encode()` во всех 11 эмиттерах — алфавит и `+` за пробел;
`insecure=1` пишем везде (tuic — сознательно канон, парсер принимает
`allow_insecure`); identity узла = **тег**, а `LegacyNodeIdentityHash`
хеширует **тело**, не текст ссылки — значит вид ссылки (`+` → `%20`) можно
менять без сдвига identity;
`queryGetFold` обходит Go-map, поэтому при ДВУХ написаниях одного имени в
одной ссылке победитель сегодня **недетерминирован** — норма «точное
совпадение с каноном, иначе первое по порядку» это чинит.
