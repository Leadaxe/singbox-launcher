# SPEC 114 — Бэкап = сериализация стейта (контракт 0.11.0)

Решения пользователя 27.08.2026. Нормативные идеи — в
contract/docs/BACKUP_PRINCIPLES.md (П1–П7); этот SPEC — их реализация в
лаунчере. Закрывает находку аудита C1 (импорт затирал тег цепочки — класс
умирает вместе с extensions) и миноры бэкап-зоны.

## 1. Схема 0.11.0

- `contract/VERSION` → 0.11.0 (мажор смысла: формат без extensions).
- Все поля из `extensions.launcher` растворяются в схеме сущностей
  НЕОБЯЗАТЕЛЬНЫМИ полями: `id`, `skip`, `outbounds` (локальные),
  `detour_tag`, `detour_node_source_id` + `detour_node_tag`, `node_tag`
  (server-источники), `fold`, `exclude_from_global`,
  `expose_group_tags_to_global`. Проверить по export.go полный список —
  ничего не забыть; legacy-поле `detour_node_hash` в новую схему НЕ входит
  (П4: старые файлы читаются общим правилом, хеш-ссылки теряются с warning).
- BACKUP.md переписывается: таблица полей с колонкой поддержки
  (обе / only launcher / only LxBox), ссылка на BACKUP_PRINCIPLES.md,
  раздел «Что изменилось против 0.10.x» с ценой разрыва.
- `schema/backup.schema.json` обновить; `additionalProperties` политика:
  неизвестные ключи допустимы на ЛЮБОМ уровне, но импортёр обязан их
  отбросить с warning (П3) — схема не должна валить чужой файл с лишним
  полем.

## 2. Экспорт

- `launcherSourceExtensions` и вся ветка `extensions` удаляются; поля
  пишутся напрямую в записи сущностей (пустые/нулевые — опускаются).
- Экспорт — чистая функция состояния (П1): тест «два экспорта одного
  состояния байт-идентичны», тест «export не зависит от того, было ли
  состояние импортировано или настроено руками».

## 3. Импорт

- Чтение `extensions` удаляется ЦЕЛИКОМ (вместе с
  `applyLauncherSourceExtensions` — смерть C1). Старый файл: общие поля
  читаются, `extensions` отбрасывается ОДНИМ warning'ом на файл с
  перечнем затронутых записей (П3/П4).
- `keepForeignEntityExtensions`, `ForeignExtensions` в state.Source,
  `_backup_fields` — удалить: состояние после импорта неотличимо от
  настроенного руками (П1). Миграцию существующих state.json с
  ForeignExtensions не писать: поле просто перестаёт читаться и писаться
  (json-ключ в старых файлах игнорируется штатно).
- Неизвестные ключи любого уровня → warning с именем ключа и сущности,
  продолжаем импорт (П3, П6).
- Миноры аудита закрыть по пути:
  - legacy-развилка `importLauncherChains` УДАЛЯЕТСЯ (П4) — вместе с
    минором «дедуп молча» (предупреждение `backup_chain_exists` остаётся
    в единственном пути chains[]);
  - `directions[].label` чужой стороны: неизвестный ключ → warning (П3),
    ничего не провозим;
  - `renumberImportedRules`: после перенумерации СОРТИРОВАТЬ слайс
    (инвариант SPEC 113-C «файл = ось»); ImportMerge либо чинится тем же
    инвариантом (якоря не перенумеровывать — только пользовательскую
    зону), либо, если merge-путь мёртв в UI, удаляется с фиксацией в
    BACKUP.md;
  - `core/state/sync_to_connections.go:177` — NodeTag не размазывать по
    всем connections legacy multi-connection источника (per-connection
    fallback восстановить).

## 4. Тесты и корпус

- Roundtrip-тесты по П1 на все сущности, включая цепочку С id и подписью:
  `export → import → export` байт-идентичен, тег цепочки жив (тест-ловушка
  C1 — обязан падать на старом коде).
- Импорт файла 0.10.x (с extensions): общие поля применились, warning
  выдан, ничего не упало. Тест на файл с НЕИЗВЕСТНЫМИ ключами → warning,
  импорт продолжен.
- contract/corpus/backup: фикстуры перегенерировать в новую схему; старые
  файлы с extensions оставить как вход теста «старый файл читается общим
  правилом» (это НЕ legacy-путь кода — только фикстура).
- Заметка LxBox-стороне: обновить handover (таблица «Статус зеркала» в
  BACKUP_PRINCIPLES.md, IDENTITY.md не трогать).

## Запреты

- Ветки не переключать; чужие незакоммиченные файлы не трогать.
- win7 = go1.20: без min/max/slices/maps/PathValue.
- Секреты/URL реальных провайдеров в фикстуры не класть — только моки.
